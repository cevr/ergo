# work

An Ergo module of this repository (`modules/`, MK0): `work`, copy-on-write workspaces of any Git repository (SEMWS WS0, WG0). A workspace is a folder that holds a full clone of its base, the tracked files, the Git folder and every untracked file (installed packages and build output included), with a name, an id, a branch and a lifecycle. It replaces Rift. The binary is `examples/work/cmd/work` (a module has no `cmd/`); `ergo work ARGS` runs `work` from `PATH`, and a repository with no `ergo.mod` needs only `work`. The npm package `@cevr/work` installs the binary.

```
/workspaces/ergo/                         the base
/workspaces/.work/ergo/<name>/       a workspace (beside the base, on its file system: work.toml's storage)
/workspaces/.work/ergo/<name>/.git/work-id   its id (the marker: in Git's folder, never in the tree)
/workspaces/.work/ergo/.registry     the registry: one journal file
/workspaces/.work/ergo/.trusted      the digest of the work.toml commands work trust allowed
/workspaces/.work/ergo/.work-trash/  removed workspaces, until gc
~/.local/share/work/bases            every base init registered (XDG_DATA_HOME/work)
```

| Package | What |
| --- | --- |
| `work` | The domain. `Workspace`, `State`, `Signal` and the `Lifecycle` machine; the contracts `Cloner`, `Registry` and `Vcs` with their laws; the contracts `Lock` (the registry's mutation lock) and `Hooks` (work.toml's hook commands); `Config` (`work.toml`); `Api`, the commands, and `Tool`, the Api over the contracts |
| `work/workcli` | The command line of `work.Api`, generated by `ergo gen cli ./work.Api` |
| `classes` | The merge by the unit of a file's class (SEMWS §2.6): a line merge first (diff3), then `rows` (a JSON list of objects by `name`: mutant ledgers), `measured` (numbers by key path: gate durations; two numbers measured apart keep ours and mark the file to be measured again), `lines` (a set of lines: allowlists) and `derived` (generated: one side whole, never merged) |
| `memory` | `Cloner` (a copy-on-write disk model: trees of blocks, volumes, mounts), `Registry`, `Vcs` (with a count of index writes and of stale stats), `Lock` (a table of holders, shared by the processes of a test), `Hooks` (a recorder) and an `exec.Runner` that counts, in memory: the tests' providers and the laws' reference |
| `journal` | `Registry` by a journal file: a tab-separated, Go-quoted line per put or drop, replayed at each read; `Lock` by kernel file locks (`.lock` for mutations, `.lock-<id>` per reservation), across processes |
| `sh` | `Hooks` by `sh -c`, in the hook's folder, with `WORK_SOURCE`, `WORK_DESTINATION`, `WORK_ID` and `WORK_PARENT_ID` |
| `system` | The tree commands every host `Cloner` shares (`test`, `mkdir`, `mv`, `rm`, `du`, `btrfs filesystem du`), through std `exec` |
| `btrfs` | `Cloner` by `btrfs subvolume snapshot`: one call for the tree, when the base is a subvolume |
| `reflink` | `Cloner` by `cp -a --reflink=always`: a `FICLONE` per file (btrfs, XFS) |
| `clonefile` | `Cloner` by macOS `cp -c` (`clonefile(2)` on APFS) |
| `copy` | `Cloner` by `cp -a`: shares nothing, made only when asked |
| `git` | `Vcs` by the git command: a reading call with `--no-optional-locks`; a snapshot in an index file of its own (`GIT_INDEX_FILE`), as `git stash create` builds one |

## Commands

`work init` (in the base), `new [-copy] [-from REV] [-branch B] [-on WS] [-token T] NAME`, `adopt DIR [-name N]`, `list`, `rm NAME [-abandon] [-expect ID] [-tree]`, `gc [-older AGE] [-id ID] [-idle AGE]`, `du`, `ready [-name N]`, `sync [-name N]`, `env [-name N]`, `deps [-name N]`, `trust`, `doctor`, `refresh`, `bases`, `shell-init`, `import-rift [-file F]`; a command with no `-name` takes the workspace the working folder is in; `--json` before the command (`work --json list`) prints the answer as JSON. A failure prints its tag and its JSON on stderr with status 1; a usage error has status 2.

- `new` runs the `precreate` hook in the parent, records the workspace as `Creating` (under the lock), clones its parent with no lock held (the base, or with `-on WS` the workspace WS as it is now, uncommitted files included: a stack), leaves out the `leave_out` folders of `work.toml` (none by default: the clone carries everything), writes the marker `.git/work-id`, starts its branch (`-branch`, else the name; at the parent's head by two ref writes, so the index is not rewritten), sets `core.checkStat=minimal` and `core.trustctime=false` in a clone made file by file (every inode is new), records it `Active`, installs when `[deps]` says so, and runs the `postcreate` hook in it. It answers `{name, id, path, branch, deps, hooks}`: a failed hook or install is in the answer, and the workspace stays active. The branch starts where the parent's branch of that name is, when it has one (a `-from` it does not contain is `Diverged`), else at `-from`, else at the parent's head, as `lane-rift.sh create` does; the record keeps that commit as the workspace's base. The clone's origin gets a push URL that refuses every push (`no-push:workspaces-never-push-origin`). The first `Cloner` the file system supports makes the clone (btrfs, then reflink, then clonefile), and the record keeps its name. Where none can share blocks, `new` refuses with `CopyRefused` and the bytes a copy would take; `-copy`, or `copy = true` in `work.toml`, allows the plain copy. A workspaces folder on another file system than its base is `NotSameVolume`.
- `rm` runs the `preremove` hook in the workspace, then, under the lock, records the intent (the record `Trashed` with its old folder as `Moving`), moves it to `.work-trash/` beside it (a rename) and clears the intent, then runs `postremove` in the parent. It answers a list of `{name, id, trash, already}`. It refuses (`NotHeld`) a workspace whose work is not in its parent, unless `-abandon`: one that is not clean or whose head no branch of the parent holds, and whose snapshot is not the one `ready` last handed. `-expect ID` removes only the workspace of that id: when the name holds another, `IdMismatch` names both, and when that id was removed already (trashed, or purged: its tomb), the answer is `already` and nothing changes, so a retry is safe. A workspace that another is made on, or is being made on, is `HasDescendants` with their folders; `-tree` removes it and every descendant, the leaves first.
- Every command that writes takes the registry's lock (`<storage>/.lock`, a kernel `flock` through std `fs.LockFile`, waited for 10 s, then `Locked`) and first finishes what a stopped writer left: an intent's move is done. A clone runs with no registry lock: `new` reserves the name (a `Creating` record and the reservation's own lock `.lock-<id>`), clones, and activates under the lock again; `-token T` makes a retry of the same `new` answer the workspace the first made. A reservation whose maker is gone (its lock is free) is gc's.
- `ready` is `lane-rift.sh push`: it snapshots the workspace (a Git tree of every file that is not ignored, untracked ones included; no branch, index or file moves), keeps it as a commit at `refs/work/latest`, and pushes, all or none, the branch (fast-forward only: `NotFastForward` when the parent's moved) and the snapshot (`refs/work/snapshots/NAME`) into the parent's repository, never to origin. It prints the branch, the commit the parent's branch now holds and the snapshot tree.
- `sync` merges the parent's branch into the workspace's (Git's merge, a fast-forward when it can) and records the parent's commit as the base; a workspace with changes is `Dirty`, and a conflict is `Conflicted` with its files (the merge is left in progress, as git leaves it).
- `merge-file [-path P] CLASS BASE OURS THEIRS` is a Git merge driver: it merges the three files by the class's units, writes the merge into OURS and prints the answer; a conflict (a unit both sides changed apart, a removal against a change, a side that does not read as the class) leaves Git's markers there and ends with status 1, so Git keeps the file conflicted. The repository's `.gitattributes` names each file's class and the git config lines that register the drivers (`merge.ergo-CLASS.driver = ergo work merge-file -path %P CLASS %O %A %B >&2`; standard output goes to stderr so that `git merge-tree` output stays Git's). Without that config, Git merges those files as text. Class `json` merges a JSON or JSONC object by key path, member by member in OURS' bytes (an untouched member keeps its text, comments stay); a list is one value, and a list whose key path a class line names in `sets` merges as a set. Class `auto` takes the class of `-path` from `work.toml`'s `[[class]]` lines: the first whose `match` (a glob; a pattern with no slash is a name at any depth, as in `.gitattributes`) takes the path; a `driver` line runs its command (`%O %A %B %P`; after `trust`), whose status other than 0 is a conflict; a path no line takes merges by lines. `init` registers the driver `work` (`merge.work.driver = work merge-file -path %P auto %O %A %B`) and writes the lines' patterns to `.git/info/attributes`, so nothing is written into the tree.
- `derive [-name N]` runs each `derived` line's `by` command (after `trust`) in the workspace, or the base, after a merge: a lock from the merged manifests. A lock file at the base's root that no line takes is a preset: `bun.lock`, `package-lock.json`, `pnpm-lock.yaml` or `yarn.lock` is derived by its package manager's lockfile-only command, and `package.json` merges as `json`. A merge-file keeps OURS for a derived file and says `regenerate`.
- `env` prints the `env` lines of `work.toml`, `{workspace}` replaced by the workspace's folder, for `eval "$(work env)"`: this repository's are `lane.env`'s.
- `deps` runs `[deps]`'s install in the workspace when its lock file's digest is not the one it last installed from (a new clone carries its parent's packages and records the parent's digest), and starts no process when it is. `sync` runs it after the merge.
- `trust` allows the commands `work.toml` runs (its install, hooks, and class lines' `by` and `driver`): their digest is kept in the base's storage. No hook and no install runs for a digest not allowed; the answer says `Untrusted` with the digest and the commands. `init` allows the commands of the work.toml it finds.
- `doctor` reports the Cloners in order and the last one used, the file system and whether a btrfs purge is one call (`user_subvol_rm_allowed`), the index entries with a stale stat, and the trust. `refresh` refreshes the base's index (`git update-index --refresh`) and prints how many entries were stale.
- `bases` lists the bases `init` registered; `shell-init` prints a shell function for `eval "$(work shell-init)"` with which `work new` changes to the new workspace; `import-rift` prints the `work.toml` of a `.rift.toml` (its four hooks, and Rift's default copy as `leave_out = ["rift-filtered"]`) and writes nothing.
- `gc` deletes the trashed workspaces of this base's registry older than `-older` (0s when absent), and the reservations whose maker is gone; `-id ID` takes that entry only. It picks them under the lock, deletes their folders with none, and under the lock again drops their records and keeps a tomb of each id for 30 days, so an `rm -expect` retry still answers `already`. It reads only its own registry (`WORK_BASE` picks another), so another base's trash is never touched. `-idle AGE` first removes, as `rm` with no `-abandon` does, each active workspace no `new`, `ready` or `sync` touched for AGE (the record's `since`), the last made first, so the same gc deletes the ones whose work is held; one `rm` refuses (`NotHeld`, `HasDescendants`, `Busy`) stays. gc answers `{purged, idle}`: the names it deleted, and each idle workspace with `removed` and, when kept, `why`. The lanes' `work gc -idle 48h` is the Rift-era `workrift prune` without its archive: what it removes is held already.
- `du` is `Cloner.Usage` per live workspace: the bytes only it holds and the bytes it shares (btrfs's count of shared extents).

`work.toml`, at the root of the base, is the one checked-in configuration (TOML; every key has a default, and a table it does not know is skipped):

```toml
[work]
storage = "../.work/<base>"      # the workspaces' folder, relative to the base
leave_out = []                   # ["rift-filtered"] is Rift's default list
copy = false                     # allow a plain copy
env = []                         # lines work env prints

[deps]
lock = "bun.lock"
install = "bun install --frozen-lockfile"

[hooks]                          # each a list of sh commands, outside the lock
precreate = []
postcreate = []
preremove = []
postremove = []

[[class]]                        # how a path merges; the first that matches wins
match = "tsconfig.json"
kind = "json"                    # json, derived, rows, measured, lines, driver
sets = ["files"]                 # json: key paths merged as sets
# by = "..."                     # derived: the command that makes it again
# driver = "cmd %O %A %B %P"     # driver: writes its merge into %A
```

`init` writes a starter one, all comments.

## Laws

- The Tool on the memory providers, each law beside the provider it reads: `memory/cloner.ergo`: `CloneCarriesEverything` (tracked, untracked and ignored files, the base unchanged), `LeaveOutLeavesOnlyThose`; `memory/hooks.ergo`: `HooksRunInOrder`, `NoHookUnderTheLock` (the lock's hold count is 0 at each hook's start), `UnallowedConfigRunsNothing`, `FailedPostcreateLeavesActive`, `InstallOnlyWhenTheLockDiffers` (the memory Runner's count); `memory/vcs.ergo`: `BranchAtHeadWritesNoIndex` (the memory Vcs's count of index writes), `InitRefreshesTheIndex`; `work/config.ergo`: `ConfigStarterReads`. `Hooks`: `ExitIsAFailure` (memory's "exit N" is sh's, and sh for real under sh's `onHost`); `Lock`: `HoldExcludes` (memory, and journal's kernel lock under its `onHost`).
- `Cloner`: `CloneMakesTheTree`, `SecondCloneIsExists`, `FailedCloneLeavesNothing`, `FreshCloneSharesItsBlocks` (a sharing clone holds no block of its own, a copy shares none), `MoveMoves`, `DiscardDiscards`. They run against `memory.Cloner`, and against the host Cloners (btrfs, reflink, copy) under each package's `onHost` context: `context needs TestAmbient { work.Cloner: New(exec.NewTestHost()) }`, so every case runs the real commands in a fresh folder of its own (rows.md, Test's ambient). A generated host Cloner stays a skip (`expected-skips`: no generator builds an `exec.Runner`). git's `Vcs` law runs the same way, and `copy`'s and `git`'s tests clone a tree and commit in that folder. The `work` cases still run them through the binary.
- `memory`: `CloneEqualsBase`, `WritesStayPrivate` (both ways), `CloneOfCloneEqualsBase`, `UsageSplitsTheBlocks`, `CloneAcrossVolumesIsRefused`, on trees the law plants; and `ToolAgreesWithTheReference`, the model property, on a generated tree that is not an Ergo module (random names, an ignored `node_modules` and build output that every clone must carry): random sequences of new, new -on, rm, ready, sync, edits, lands, commits on the base, crashes between the record and the clone, gc (with and without `-idle`) and waits, on one or no sharing Cloner, against a reference written apart from the Tool, with a second base's trash that must survive; and `UseKeepsAWorkspace`: a ready or a sync is a use, so `gc -idle` leaves that workspace.
- `Vcs`: `OwnBranchHoldsItsHead`, `SnapshotChangesNoBranch` (a snapshot leaves the head, the branch and what is uncommitted), `CompareAndSetIsAtomic` (two writers against one register), on the checkout `.` the provider was built over: `memory.NewVcs()`, a checkout with an uncommitted change, an untracked file and an ignored one. git's run under `git/checkout`'s `onHost` (each case's folder made a checkout with a commit and an untracked file; a package of the module's `full-tier` file, so only the gate's full tier runs it: git starts in every case) and under git's `onShell` (an empty folder, with its `exec.Runner` and `os.Process`, where they hold by their failure cases). git's tests hold each law's fact on a repository they make: `OwnBranchHoldsItsHeadInARepository`, `SnapshotLeavesTheIndex` (its status is unchanged: the snapshot has an index of its own), `StaleSetIsMoved` (the second of two writers that read the same value is `Moved`) and `NonFastForwardIsRefused`; and copy's `CloneStatusEqualsBaseStatus` (git's status in a copy of a checkout with a mode, a link, staged, unstaged, untracked and ignored files is the base's). `memory`: `SnapshotIsTheFiles` (a snapshot read back is the working files) and `ParityWithLaneRift`: a lane made and driven as `lane-rift.sh` does (clone and branch, push, fetch and merge of main) and a workspace driven by new, ready and sync leave the base's two branches at the same files.
- `classes`: `RowsAreTheReference`, `RowsByUnitsAreTheReference`, `MeasuredIsTheReference`, `LinesAreTheReference` (seeded properties: a base and two edit scripts against the reference "apply both scripts to the base", unit by unit with `Choose`), `RowsCommute`, `MergeOfEqualIsOne` (with `MergeWithBaseIsOther`), `DerivedIsNeverMerged`, `TextIsDiff3`, `JsonIsTheReference` (a JSONC manifest with nested keys and a set, two edit scripts, against the reference by key path; the comment and an untouched member's bytes stay); `memory`: `MergeFileWritesTheMerge` (the Tool's merge-file on a memory disk), `LockIsTheManifests` (`memory/lockmodel.ergo`: MergeTree of three trees of a manifest and its lock, with a model package manager, ends with the lock of the merged manifest, or a conflict on the manifest); `work/merge.ergo`: `PresetPicksTheLockThatExists`, `GlobTakesAnyDepth`, `AttributesKeepOtherLines`.
- `Registry`: `PutIsRead`, `LastPutWins`, `DropForgets`, `BuryKeepsTheId`, `CompactKeepsTheRecords`, run against `memory.Registry` and `journal.Registry`; `journal`: `TornWriteIsDropped`, `ReplayIsTheMemoryRegistry`.
- The registry protocol (`memory/protocol.ergo`): `RemovingIsIdempotent` (a retry, before and after gc), `RemovingSparesTheReplacement`, `ReservingWithATokenTwiceIsOnce`, `PurgingTouchesOneEntry`, `NoCopyUnderTheLock`, `ClaimReadsTheParentAgain` (new -on claims nothing when an rm took, or a gc and a new replaced, the parent after it looked: rift#56); and `SchedulesKeepTheInvariants` (`memory/schedule.ergo`): two or three callers of new (look, begin, claim, clone, activate), rm, gc and replace interleaved step by step from a seed, eight schedules a case, any stopped after any step, then a gc recovers; no new failed with Git's error on a parent an rm took (it is `NoWorkspace`) or a failed clone, each claim found its parent live; no intent or reservation is left, the trees are the live records' folders, no record outlives its parent (a reservation counts as a child), an intent a stopped rm left is finished, an `rm -expect` trashed only its id, and with none stopped the records are a serial run's in the order the calls took the lock. `models/registry` is the protocol's model (the same invariants, and the mutants of the protocol it rules out). `Lock`: `HoldExcludes` (memory; the host lock by `TestFSLockFileExcludes` and `scripts/workrace`).
- `Lifecycle`: `EveryWorkspaceCanBeRemoved` (always), `SomeWorkspaceLands` (sometimes), and `LandedIsFinal`, `OnlyActiveLands`, `StateNamesRoundTrip`.
- The rows `CopyRefusedSaysTheBytes` and `NotSameVolumeNamesBoth` hold the two refusals' text, and `IdMismatchNamesBothIds`, `HasDescendantsNamesThePaths` and `LockedNamesTheRegistry` the registry's; `UntrustedHookSaysTheDigest` and `FailedHookIsInCreated` hold the hooks' answers.

## Decided

- The host Cloners run the system's own commands through std `exec`, not `import go` of `syscall`: the same calls Rift makes, no Go in the module, and a test can replay the commands. Reverse by: an `import go` provider beside them.
- The lifecycle's states carry no data (the record does), so `ergo test` decides the machine's laws on the whole graph.
- The registry takes one append per record, under a kernel file lock (std `fs.LockFile`, `flock`): the host gives back a dead holder's lock, so no stale lock file is left to clear. A line a crash cut short has no newline and is dropped; gc compacts the file (tombs older than 30 days go). Reverse by: an `import go` lock provider.
- `gc` has no `--of BASE`: `WORK_BASE` picks the base; `gc ID` is `-id ID` (a generated command has no optional argument).
- `init` registers the base it runs in (no DIR: a generated command has no optional argument); `adopt DIR` reads DIR relative to the base.
- A snapshot is a Git tree, kept by a commit no branch holds (`refs/work/latest`), since a push carries commits: Git's object store is the snapshot store.
- `ready` does not refuse uncommitted work, as `lane-rift.sh push` does: the snapshot holds it, and `rm` takes the workspace while the snapshot stands.
- The memory `Vcs` merges file by file and changes nothing on a conflict; git leaves the merge in progress. Both are `Conflicted`.

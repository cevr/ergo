# work

An Ergo module of this repository (`modules/`, MK0): `ergo work`, copy-on-write workspaces of one base checkout (SEMWS WS0). A workspace is a folder that holds a full clone of its base, the tracked files, the Git folder and every untracked build product, with a name, a branch and a lifecycle. It replaces Rift for Ergo work. The binary is `examples/ergo-work` (a module has no `cmd/`); `ergo work ARGS` runs it from `PATH`.

```
/workspaces/ergo/                         the base
/workspaces/.ergo-work/ergo/<name>/       a workspace (beside the base, on its file system)
/workspaces/.ergo-work/ergo/.registry     the registry: one journal file
/workspaces/.ergo-work/ergo/.ergo-trash/  removed workspaces, until gc
```

| Package | What |
| --- | --- |
| `work` | The domain. `Workspace`, `State`, `Signal` and the `Lifecycle` machine; the contracts `Cloner`, `Registry` and `Vcs` with their laws; `Config` (`ergo.work`); `Api`, the commands, and `Tool`, the Api over the contracts |
| `work/workcli` | The command line of `work.Api`, generated by `ergo gen cli ./work.Api` |
| `memory` | `Cloner` (a copy-on-write disk model: trees of blocks, volumes, mounts), `Registry` and `Vcs` in memory: the tests' providers and the laws' reference |
| `journal` | `Registry` by a journal file: a tab-separated, Go-quoted line per put or drop, replayed at each read |
| `system` | The tree commands every host `Cloner` shares (`test`, `mkdir`, `mv`, `rm`, `du`, `btrfs filesystem du`), through std `exec` |
| `btrfs` | `Cloner` by `btrfs subvolume snapshot`: one call for the tree, when the base is a subvolume |
| `reflink` | `Cloner` by `cp -a --reflink=always`: a `FICLONE` per file (btrfs, XFS) |
| `clonefile` | `Cloner` by macOS `cp -c` (`clonefile(2)` on APFS) |
| `copy` | `Cloner` by `cp -a`: shares nothing, made only when asked |
| `git` | `Vcs` by the git command: a reading call with `--no-optional-locks`; a snapshot in an index file of its own (`GIT_INDEX_FILE`), as `git stash create` builds one |

## Commands

`ergo work init` (in the base), `new [-copy] [-from REV] [-branch B] [-on WS] NAME`, `adopt DIR [-name N]`, `list`, `rm NAME [-abandon]`, `gc [-older AGE]`, `du`, `ready [-name N]`, `sync [-name N]`, `env [-name N]`; a command with no `-name` takes the workspace the working folder is in; `--json` before the command (`ergo work --json list`) prints the answer as JSON. A failure prints its tag and its JSON on stderr with status 1; a usage error has status 2.

- `new` records the workspace as `Creating`, clones its parent (the base, or with `-on WS` the workspace WS as it is now, uncommitted files included: a stack), leaves out the `leave-out` folders of `ergo.work`, starts its branch (`-branch`, else the name) and records it `Active` and runs the `warm` command in it. The branch starts where the parent's branch of that name is, when it has one (a `-from` it does not contain is `Diverged`), else at `-from`, else at the parent's head, as `lane-rift.sh create` does; the record keeps that commit as the workspace's base. The clone's origin gets a push URL that refuses every push (`no-push:workspaces-never-push-origin`). The first `Cloner` the file system supports makes the clone (btrfs, then reflink, then clonefile), and the record keeps its name. Where none can share blocks, `new` refuses with `CopyRefused` and the bytes a copy would take; `-copy`, or a `copy` line in `ergo.work`, allows the plain copy. A workspaces folder on another file system than its base is `NotSameVolume`.
- `rm` moves the workspace to `.ergo-trash/` beside it (a rename) and records it `Trashed`. It refuses (`NotHeld`) a workspace whose work is not in its parent, unless `-abandon`: one that is not clean or whose head no branch of the parent holds, and whose snapshot is not the one `ready` last handed.
- `ready` is `lane-rift.sh push`: it snapshots the workspace (a Git tree of every file that is not ignored, untracked ones included; no branch, index or file moves), keeps it as a commit at `refs/work/latest`, and pushes, all or none, the branch (fast-forward only: `NotFastForward` when the parent's moved) and the snapshot (`refs/work/snapshots/NAME`) into the parent's repository, never to origin. It prints the branch, the commit the parent's branch now holds and the snapshot tree.
- `sync` merges the parent's branch into the workspace's (Git's merge, a fast-forward when it can) and records the parent's commit as the base; a workspace with changes is `Dirty`, and a conflict is `Conflicted` with its files (the merge is left in progress, as git leaves it).
- `env` prints the `env` lines of `ergo.work`, `{workspace}` replaced by the workspace's folder, for `eval "$(ergo work env)"`: this repository's are `lane.env`'s.
- `gc` deletes the trashed workspaces of this base's registry older than `-older` (0s when absent), and the workspaces whose clone never ended once they are an hour old (or `-older`, when longer). It reads only its own registry, so another base's trash is never touched.
- `du` is `Cloner.Usage` per live workspace: the bytes only it holds and the bytes it shares (btrfs's count of shared extents).

`ergo.work`, at the root of the base, is the one checked-in configuration: `module DIR`, `leave-out DIR`, `warm COMMAND`, `copy` and `env LINE`, one a line; `#` starts a comment. `init` writes a starter one.

## Laws

- `Cloner`: `CloneMakesTheTree`, `SecondCloneIsExists`, `FailedCloneLeavesNothing`, `FreshCloneSharesItsBlocks` (a sharing clone holds no block of its own, a copy shares none), `MoveMoves`, `DiscardDiscards`. They run against `memory.Cloner`; the host Cloners' values need a host `exec.Runner`, which no test may hold (`expected-skips`), so the examples cases of `ergo-work` run them on the host.
- `memory`: `CloneEqualsBase`, `WritesStayPrivate` (both ways), `CloneOfCloneEqualsBase`, `UsageSplitsTheBlocks`, `CloneAcrossVolumesIsRefused`, on trees the law plants; and `ToolAgreesWithTheReference`, the model property: random sequences of new, new -on, rm, ready, sync, edits, lands, commits on the base, crashes between the record and the clone, gc and waits, on one or no sharing Cloner, against a reference written apart from the Tool, with a second base's trash that must survive.
- `Vcs`: `OwnBranchHoldsItsHead`, `SnapshotChangesNoBranch` (a snapshot leaves the head, the branch and what is uncommitted), `CompareAndSetIsAtomic` (two writers against one register), on the checkout `.` the provider was built over: `memory.NewVcs()`, a checkout with an uncommitted change, an untracked file and an ignored one. git's runs wait for a test-host capability (unit TH1, `expected-skips` until then). `memory`: `SnapshotIsTheFiles` (a snapshot read back is the working files) and `ParityWithLaneRift`: a lane made and driven as `lane-rift.sh` does (clone and branch, push, fetch and merge of main) and a workspace driven by new, ready and sync leave the base's two branches at the same files.
- `Registry`: `PutIsRead`, `LastPutWins`, `DropForgets`, run against `memory.Registry` and `journal.Registry`; `journal`: `TornWriteIsDropped`, `ReplayIsTheMemoryRegistry`.
- `Lifecycle`: `EveryWorkspaceCanBeRemoved` (always), `SomeWorkspaceLands` (sometimes), and `LandedIsFinal`, `OnlyActiveLands`, `StateNamesRoundTrip`.
- The rows `CopyRefusedSaysTheBytes` and `NotSameVolumeNamesBoth` hold the two refusals' text.

## Decided

- The host Cloners run the system's own commands through std `exec`, not `import go` of `syscall`: the same calls Rift makes, no Go in the module, and a test can replay the commands. Reverse by: an `import go` provider beside them.
- The lifecycle's states carry no data (the record does), so `ergo test` decides the machine's laws on the whole graph.
- The registry takes one append per record and no lock file: std `fs` has no exclusive create, and an append of one line does not interleave with another's on a local file system. A line a crash cut short has no newline and is dropped.
- `init` registers the base it runs in (no DIR: a generated command has no optional argument); `adopt DIR` reads DIR relative to the base.
- A snapshot is a Git tree, kept by a commit no branch holds (`refs/work/latest`), since a push carries commits: Git's object store is the snapshot store.
- `ready` does not refuse uncommitted work, as `lane-rift.sh push` does: the snapshot holds it, and `rm` takes the workspace while the snapshot stands.
- The memory `Vcs` merges file by file and changes nothing on a conflict; git leaves the merge in progress. Both are `Conflicted`.

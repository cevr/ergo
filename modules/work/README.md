# work

An Ergo module of this repository (`modules/`, MK0): `work`, copy-on-write workspaces of any Git repository (SEMWS WS0, WG0). A workspace is a folder that holds a full clone of its base, the tracked files, the Git folder and every untracked file (installed packages and build output included), with a name, an id, a branch and a lifecycle. It replaces Rift. The binary is `examples/work/cmd/work` (a module has no `cmd/`); `ergo work ARGS` runs `work` from `PATH`, and a repository with no `ergo.mod` needs only `work`. The npm package `@cvr/work` installs the binary.

```
/workspaces/ergo/                         the base
/workspaces/.work/ergo/<name>/       a workspace (beside the base, on its file system: work.toml's storage)
/workspaces/.work/ergo/<name>/.git/work-id   its id (the marker: in Git's folder, never in the tree)
/workspaces/.work/ergo/.creating/<id>   a clone new is making, until its one rename into place
/workspaces/.work/ergo/.registry     the registry: one journal file
/workspaces/.work/ergo/.trusted      the digest of the work.toml commands work trust allowed
/workspaces/.work/ergo/.work-trash/  removed workspaces, until gc
~/.local/share/work/bases            every base init registered (XDG_DATA_HOME/work)
```

| Package | What |
| --- | --- |
| `work` | The domain. `Workspace`, `State`, `Signal` and the `Lifecycle` machine; the contracts `Cloner`, `Registry` and `Vcs` with their laws; the contracts `Lock` (the registry's mutation lock) and `Hooks` (work.toml's hook commands); `Config` (`work.toml`); `Api`, the commands, and `Tool`, the Api over the contracts |
| `work/workcli` | The command line of `work.Api`, generated by `ergo gen cli ./work.Api` |
| `classes` | The merge by the unit of a file's class (SEMWS §2.6): a line merge first (diff3), then `rows` (a JSON list of objects by `name`: mutant ledgers), `measured` (numbers by key path: gate durations; two numbers measured apart keep ours and mark the file to be measured again), `lines` (a set of lines: allowlists) and `derived` (generated: one side whole, never merged; a merge either class marks to be made again is a conflict in merge-file) |
| `memory` | `Cloner` (a copy-on-write disk model: trees of blocks, volumes, mounts), `Registry`, `Vcs` (with a count of index writes and of stale stats), `Lock` (a table of holders, shared by the processes of a test), `Hooks` (a recorder) and an `exec.Runner` that counts, in memory: the tests' providers and the laws' reference |
| `journal` | `Registry` by a journal file: a tab-separated, Go-quoted line per put or drop, replayed at each read; `Lock` by kernel file locks (`.lock` for mutations, `.lock-<id>` per reservation), across processes |
| `sh` | `Hooks` by `sh -c`, in the hook's folder, with `WORK_SOURCE`, `WORK_DESTINATION`, `WORK_ID` and `WORK_PARENT_ID` |
| `system` | The tree commands every host `Cloner` shares (`test`, `mkdir`, `mv`, `rm`, `du`, `btrfs filesystem du`), through std `exec` |
| `btrfs` | `Cloner` by `btrfs subvolume snapshot`: one call for the tree, when the base is a subvolume |
| `reflink` | `Cloner` by `cp -a --reflink=always`: a `FICLONE` per file (btrfs, XFS) |
| `clonefile` | `Cloner` by macOS `cp -c` (`clonefile(2)`); only on APFS: elsewhere `cp -c` copies each file silently, so it is `Unsupported` |
| `copy` | `Cloner` by `cp -a`: shares nothing, made only when asked |
| `git` | `Vcs` by the git command: a reading call with `--no-optional-locks`; a snapshot in an index file of its own (`GIT_INDEX_FILE`), as `git stash create` builds one, kept between snapshots and filled from HEAD by `read-tree -m`, so only the files changed since the last are hashed (`docs/receipts/work-snapshot.md`) |

## Commands

`--json` (before the command or after it) prints every answer as JSON. `work init` (in the base), `new [-copy] [-from REV] [-branch B] [-on WS] [-token T] NAME`, `adopt DIR [-name N]`, `list`, `rm NAME [-abandon] [-expect ID] [-tree]`, `gc [-older AGE] [-id ID] [-idle AGE] [-archive]`, `pin NAME`, `unpin NAME`, `du`, `ready [-name N]`, `sync [-name N]`, `env [-name N]`, `deps [-name N]`, `trust`, `doctor`, `refresh`, `bases`, `forget-base DIR`, `prune-bases`, `shell-init`, `import-rift [-file F]`; a command with no `-name` takes the workspace the working folder is in; the base is `WORK_BASE`, else the repository the working folder is in, or, when that is a workspace (an adopted copy among them), the base whose registry holds it; `--json` before the command (`work --json list`) prints the answer as JSON. A failure prints its tag and its JSON on stderr with status 1; a usage error has status 2.

- `new` runs the `precreate` hook in the parent, records the workspace as `Creating` (under the lock), clones its parent with no lock held (the base, or with `-on WS` the workspace WS as it is now, uncommitted files included: a stack), leaves out the `leave_out` folders of `work.toml` (none by default: the clone carries everything) and Rift's marker `.rift` (it names the copy it is in), writes the marker `.git/work-id`, starts its branch (`-branch`, else the name; at the parent's head by two ref writes, so the index is not rewritten), turns on `core.untrackedCache` (a `git status` after the first, rm's held check among them, walks only the folders that changed), writes work's merge drivers into the clone's own Git config (below, `merge-file`; one `git config` read when the clone has them from its parent already), sets `core.checkStat=minimal` and `core.trustctime=false` in a clone made file by file (every inode is new), records it `Active`, installs when `[deps]` says so, and runs the `postcreate` hook in it. It answers `{name, id, path, branch, deps, hooks}`: a failed hook or install is in the answer, and the workspace stays active. The branch starts where the parent's branch of that name is, when it has one (a `-from` it does not contain is `Diverged`), else at `-from`, else at the parent's head, as `lane-rift.sh create` does; the record keeps that commit as the workspace's base. Every remote of the clone gets a push URL that refuses every push (`no-push:workspaces-never-push-origin`), unless `work.toml` says `push = "origin"`. `adopt` and `adopt-rift` write no guard: an adopted copy was its owner's before work took it, and its pushes stay theirs (an older work guarded them; `doctor -unguard` drops that). The guard is a push URL, so it stops `git push REMOTE` but not a push to a URL given on the command line (`git push https://… main`); the refusal reads as Git failing to reach the host `no-push`. The first `Cloner` the file system supports makes the clone (btrfs, then reflink, then clonefile), and the record keeps its name. Where none can share blocks, `new` refuses with `CopyRefused` and the bytes a copy would take; `-copy`, or `copy = true` in `work.toml`, allows the plain copy. A workspaces folder on another file system than its base is `NotSameVolume`.
- `rm` runs the `preremove` hook in the workspace, then, under the lock, records the intent (the record `Trashed` with its old folder as `Moving`), moves it to `.work-trash/NAME.SECOND.ID` beside it (a rename) and clears the intent, then runs `postremove` in the parent. It answers a list of `{name, id, trash, already}`. It refuses (`NotHeld`) a workspace whose work is not in its parent, unless `-abandon`: one with a local branch or a stash entry whose commit is not held, or one that is not clean or whose head is not held, and whose snapshot is not the one `ready` last handed. A commit is held when a branch of the parent contains it or a remote-tracking ref of the workspace does (it is on a remote already). The name is free again at once: a later `new` of it works before any gc, and the trash stays listed as `NAME~ID` (its id kept) until gc purges it. `-expect ID` removes only the workspace of that id: when the name holds another, `IdMismatch` names both, and when that id was removed already (trashed, or purged: its tomb), the answer is `already` and nothing changes, so a retry is safe. Where `work.toml` says `trash = false` (the workbox's bases: no trash), rm, after the same refusals, then deletes that workspace for good at once, as `gc -id ID` would, by its record's one id (never a target from a listing or a glob): its trash folder is deleted, its record leaves a tomb, the answer's `trash` is empty, and `gc -idle` keeps no day of trash. A workspace that another is made on, or is being made on, is `HasDescendants` with their folders; `-tree` removes it and every descendant, the leaves first.
- Every command that writes takes the registry's lock (`<storage>/.lock`, a kernel `flock` through std `fs.LockFile`, waited for 10 s, then `Locked`) and first finishes what a stopped writer left: an intent's move is done. A clone runs with no registry lock: `new` reserves the name (a `Creating` record and the reservation's own lock `.lock-<id>`), clones, and activates under the lock again; `-token T` makes a retry of the same `new` answer the workspace the first made. The clone is staged: it is made whole in `<storage>/.creating/<id>` (its leave-outs, its branch, its settings, its marker), then renamed into its folder by one rename (`mv --no-copy -T`, both folders synced after), so a workspace's folder is never half made. `.creating` sits in the storage beside the workspaces, and a `.creating` on another file system (or btrfs subvolume) than the storage is refused as `NotSameVolume` before any copy. A `work new` stopped at any point (a TERM, a KILL, an OOM, a power cut) leaves its `Creating` record, which `list` shows; the next command that writes (`new`, `rm`, `gc`, `pin`, `unpin`, `ready`, `sync`, `deps`, `adopt`, `adopt-rift`, `doctor -repair`) settles it under the lock once its maker is gone, which only the kernel tells (its `.lock-<id>` is free; no pid or time is trusted): a clone placed and marked becomes `Active`, as `new` would have made it; otherwise its staging folder is renamed under the lock to `.creating/<id>.gone`, deleted for good (never trashed) with the lock free, so a large copy's delete never makes another command wait and answer `Locked`, and only then its record is dropped, under the lock again. A delete that fails (a killed maker's `cp` may still write there) leaves the record, and `gc` and `rm` leave it too (`rm` answers `Busy`), for the next command. A live maker's reservation is never touched. A record left by an older work (which cloned in place: a folder at its path with no marker) keeps gc's and `doctor -repair`'s rules.
- `ready` is `lane-rift.sh push`: it snapshots the workspace (a Git tree of every file that is not ignored, untracked ones included; no branch, index or file moves), keeps it as a commit at `refs/work/latest`, and pushes, all or none, the branch (fast-forward only: `NotFastForward` when the parent's moved) and the snapshot (`refs/work/snapshots/NAME`) into the parent's repository, never to origin. It prints the branch, the commit the parent's branch now holds and the snapshot tree.
- `sync` merges the parent's branch into the workspace's (Git's merge, a fast-forward when it can) and records the parent's commit as the base; a workspace with changes is `Dirty`, and a conflict is `Conflicted` with its files (the merge is left in progress, as git leaves it).
- `merge-file [-path P] CLASS BASE OURS THEIRS` is a Git merge driver: it merges the three files by the class's units, writes the merge into OURS and prints the answer; a conflict (a unit both sides changed apart, a removal against a change, a side that does not read as the class) leaves Git's markers there and ends with status 1, so Git keeps the file conflicted. The repository's `.gitattributes` names each file's class and the git config lines that register the drivers (`merge.ergo-CLASS.driver = work merge-file -path %P CLASS %O %A %B >&2`; standard output goes to stderr so that `git merge-tree` output stays Git's). Without that config, Git merges those files as text, silently: so `init` (the base), `new` (each workspace) and `doctor -fix` write these lines for every class, `merge.work` (class `auto`) and `work.drivers`, the digest of the lines, by which a checkout that has them already is not written again. Class `json` merges a JSON or JSONC object by key path, member by member in OURS' bytes (an untouched member keeps its text, comments stay); a list is one value, and a list whose key path a class line names in `sets` merges as a set. Class `auto` takes the class of `-path` from `work.toml`'s `[[class]]` lines: the first whose `match` (a glob; a pattern with no slash is a name at any depth, as in `.gitattributes`) takes the path; a `driver` line runs its command (`%O %A %B %P`; after `trust`), whose status other than 0 is a conflict; a `candidate` driver line is never worse than Git: where Git's line merge is clean that is the merge and the driver never runs; where it conflicts, the driver's merge is kept (class `candidate`) only when its tool answers the pinned `version`, it ends with status 0, leaves no conflict marker and its `check` (a command on `%A`, allowed by `trust` as the driver is) ends with status 0 and prints nothing; its own conflict keeps its text, conflicted; a tool missing (status 127) or of another version, a marker or a failed check withdraws it, and the file is Git's line merge, conflicted, with the reason (this repository's `*.go` line: Mergiraf, checked by `gofmt -l`); a path no line takes merges by lines. `init` registers the driver `work` (`merge.work.driver = work merge-file -path %P auto %O %A %B >&2`) and writes the lines' patterns to `.git/info/attributes`, so nothing is written into the tree.
- `merge-folders BASE OURS THEIRS OUT` merges the files under three folders (each a tree) into OUT, each path as `merge-file auto` takes it, then derives when nothing conflicts; it answers `{conflicts, ran}`. A `[language.NAME]`'s files start its plugin twice for the whole merge (every file's three sides in one run, every merge cut again in one more), where Git's driver starts `merge-file` once a file, which starts it twice for that file.
- `derive [-name N]` runs each `derived` line's `by` command (after `trust`) in the workspace, or the base, after a merge: a lock from the merged manifests. A lock file at the base's root that no line takes is a preset: `bun.lock`, `package-lock.json`, `pnpm-lock.yaml` or `yarn.lock` is derived by its package manager's lockfile-only command, and `package.json` merges as `json`. A merge that must be made again (a derived file both sides changed, a number both sides measured apart) is never a clean merge-file: Git runs merge-file as its driver and nothing regenerates after it, so it ends as a conflict (status 1) whose why says `both sides changed PATH, a derived file: run BY, then git add`. The file keeps the class's merge, which reads: ours whole for a derived file (the package manager can still read it), every entry with ours' value for a measured one. `work sync` then fails `Conflicted` with that file. A tree merge (land, `merge-folders`) makes it again instead.
- `env` prints the `env` lines of `work.toml`, `{workspace}` replaced by the workspace's folder, for `eval "$(work env)"`: this repository's are `lane.env`'s.
- `deps` runs `[deps]`'s install in the workspace when its lock file's digest is not the one it last installed from (a new clone carries its parent's packages and records the parent's digest), and starts no process when it is. `sync` runs it after the merge.
- `trust` allows the commands `work.toml` runs (its install, hooks, and class lines' `by` and `driver`): their digest is kept in the base's storage. No hook and no install runs for a digest not allowed; the answer says `Untrusted` with the digest and the commands. `init` allows the commands of the work.toml it finds.
- `adopt-rift [-registry FILE]` takes over the base's Rift copies: it reads Rift's registry (SQLite, by `sqlite3 -readonly`; it never writes it) and registers each copy made from the base's Rift root, directly or on another copy, as `adopt` does: the folder's name is the workspace's, the copy it was made from is its parent (the base for the root's), each parent first. It moves no file and writes none in a copy it adopts (`.git/config` included). A copy is left, with why, when a workspace holds its folder already (a second run adopts nothing), its folder is gone, its `.rift` marker names another id, its name is taken or cannot name a workspace, or its parent was left. It answers `{adopted, skipped}`.
- `doctor` reports the Cloners in order and the last one used, the file system (from `/proc/mounts`, or on macOS from `mount`'s list: `apfs`) and whether a btrfs purge is one call (`user_subvol_rm_allowed`), the index entries with a stale stat, and the trust; its first note is the trash rule in force and where it came from (`trash: false (git config work.trash)`, `trash: true (work.toml)`, `trash: true (default)`: the base's Git setting `work.trash` wins over `work.toml`'s `[work] trash`, which wins over the default). It names each record left `Creating` over a whole clone (the folder holds a checkout whose head resolves, with no marker or its own) whose maker is gone: a `work new` killed after its clone and before its marker, which gc and rm keep; `-repair` records each `Active` under the lock, as gc activates a marked one, and writes no file. `refresh` refreshes the base's index (`git update-index --refresh`) and prints how many entries were stale. `-rift` adds `rift`: the folders of the base's Rift copies that no workspace holds (Rift's registry, `-registry FILE` or `$XDG_DATA_HOME/rift/rift.sqlite`, and on macOS, when that file is not there, `~/Library/Application Support/rift/rift.sqlite`), none once `adopt-rift` took them. It notes the adopted workspaces whose remotes carry the push guard an older `adopt` wrote; `-unguard` drops that guard from each (only that push URL: one the owner set stays, and a workspace `new` made keeps its guard). It notes each checkout, the base or an active workspace, whose attributes (its `.gitattributes` and `.git/info/attributes`) give a file a merge driver its Git config lacks (Git merges that file as text), and each merge line of the base that takes no file; `-fix` writes work's merge drivers into each such checkout (an adopted copy, a base made before work wrote them). `-here` narrows both to the one checkout that holds the folder doctor runs in, so a lane's gate fixes its own clone and no other; run from no checkout of the base, it says so and fixes nothing. A fix writes the drivers and nothing else: `rerere.enabled`, which replays recorded resolutions into later merges, stays as the checkout's owner set it. `adopt` and `adopt-rift` write no driver into a copy themselves, as they write no guard: `doctor -fix` is the owner's step.
- `bases` lists the bases `init` registered whose folder is there (one whose folder is gone, a test's scratch or a removed repository, is skipped); `forget-base DIR` drops a base from the list (its folder and workspaces stay), and `prune-bases` forgets every base whose folder is gone and prints them; `shell-init` prints a shell function for `eval "$(work shell-init)"` with which `work new` changes to the new workspace; `import-rift` prints the `work.toml` of a `.rift.toml` (its four hooks, and Rift's default copy as `leave_out = ["rift-filtered"]`) and writes nothing.
- `gc` deletes the trashed workspaces of this base's registry older than `-older` (0s when absent), and the reservations whose maker is gone; `-id ID` takes that entry only. It picks them under the lock, deletes their folders with none, and under the lock again drops their records and keeps a tomb of each id for 30 days, so an `rm -expect` retry still answers `already`. It reads only its own registry (`WORK_BASE` picks another), so another base's trash is never touched. `-idle AGE` first removes, as `rm` with no `-abandon` does, each active workspace that is idle for AGE, the last made first; its trash is kept a day (`until`) before a gc purges it, so never in the same run. Idle means all of: no `new`, `ready` or `sync` touched it for AGE (the record's `since`); no file under its folder, `.git` included, changed in the last AGE on work's clock (`find -newer` a stamp file); no process has its working folder inside it (`/proc/N/cwd`, else `lsof -d cwd`); and it is not pinned. Its work must be held as for `rm`, except that a remote-tracking ref holds a commit only when it is a remote's default branch (the ref `refs/remotes/R/HEAD` names), as `workrift prune` rules: another may be stale, its branch deleted on the remote since the last fetch, so with `-archive` such a branch is archived and without it the workspace stays `NotHeld`. A host where work cannot tell keeps it (`InUse`, with why). `pin NAME` keeps a workspace from `gc -idle` (`Pinned`) until `unpin NAME`. One `rm` refuses (`NotHeld`, `HasDescendants`, `Busy`) stays. gc answers `{purged, idle}`: the names it deleted, and each idle workspace with `removed` and, when kept, `why` (`Pinned`, `InUse`, `NotKept` or rm's refusal) and `detail`. The lanes' `work gc -idle 48h` is the Rift-era `workrift prune` without its archive: what it removes is held already. `-archive` (with `-idle`) also removes an idle workspace whose work is not held, after it keeps that work in the base under `refs/work/archive/NAME/ID`: `…/work`, a snapshot of every file that is not ignored as a commit on its HEAD; `…/heads/B` for each local branch B and `…/stash/N` for each stash entry (0 the newest) that is not held. It reads each ref back in the base, and a ref that does not hold its commit keeps the workspace (`NotKept`, with why). Rift's prune with its archive, in the base's repository, since a parent workspace may be removed next. The idle entry names the snapshot's ref (`archived`). The daily timer is `work gc -idle 48h -archive`.
- `clone [-leave-out PATH]... SRC DST` is the Cloner without the registry. It needs no base and touches no registry, lock, hook, trash, `work.toml` or trust.
  - It clones the folder SRC to DST, which must be absent with its parent present. It never makes DST's parent, which would write outside DST.
  - It tries the sharing Cloners in order, then the plain copy. In clone, a copy is an answer: also across file systems, where `new` refuses one.
  - A copy is measured first (`Cloner.Usage` of SRC against `Cloner.Free`, `df -Pk`, of DST's parent). With too little room it is `NoSpace{path, need, free}` and nothing is written.
  - Links are copied as links with their text, so a link out of SRC is never followed. Each `-leave-out` entry, relative to SRC and inside it, is deleted from the clone.
  - The answer is `{"cloner", "shared", "entries", "bytesCopied", "ms"}`: entries are DST's files, folders and links; bytesCopied is 0 when shared; ms is the clone without the count.
  - A failure work sees leaves no DST. A cut (a kill) can leave a partial DST that the caller may delete; exit 0 is the only proof DST is whole.
- `du` is `Cloner.Usage` per live workspace: the bytes only it holds and the bytes it shares (btrfs's count of shared extents). On another file system it is `Unsupported` with the reason: APFS (macOS) and XFS do not report the blocks a clone shares, so `du` cannot tell them.
- `plugin-test [-files PATTERNS] [-max N] [-seed N] COMMAND` is the admission test of a language plugin (`work/language.ergo`): it runs COMMAND (its words, split at white space), or the command of the `[language.COMMAND]` it names (only once `work trust` allowed it), on up to N of the base's files that match the patterns (comma-separated, as a `[[class]]` matches; the language's `files`; every UTF-8 file when there are none), and holds it to the laws of the three contracts: `UnitsAreTheFile`, `KeysAreUnique` and `EditStaysInItsUnit` (a space added after a space inside a unit) for a `Splitter`; `ChangesOfSameIsEmpty` and `CommentEditIsNoChange` (the plugin's own comment added at a file's end) for an `Indexer`; `CheckIsPure` and `EmptyLayerIsTheBase` for a `Checker`. A plugin that breaks one is refused (`PluginRefused`) with the law's name, the file and why; one that does not start, dies or answers what is no answer is refused by law `Answers`. It answers `{command, level, files, unreadable, laws}`: level 1 has only a Splitter (it answers `NotProvided` to the rest), level 2 an Indexer or a Checker too.

A path no `[[class]]` takes but a `[language.NAME]`'s `files` do merges by that language's units (`work/units.ergo`, class NAME; `merge-file NAME` names it too, and the merge of three trees takes it), only once `work trust` allowed its command: the plugin cuts base, ours and theirs into units keyed by the names each declares, and a unit one side changed takes that side; a unit both changed apart merges by lines within it, then by its members (a class's, an import's specifiers); a unit one side renamed in place (most of its lines kept, the units around it the same) takes the other side's change; units one side moved, the other keeping the base's order, are in the moving side's order; a unit theirs added goes after the unit before it in theirs and after what ours added there. What still clashes is a conflict named by its overlap: `SameDeclaration KEY` (both changed it, or one removed what the other changed), `SameNewHandle KEY` (both added one name apart), `SameMember KEY.MEMBER`. The merged text is cut again: one the language cannot read is the line merge, conflict `Unparsed`. A side the plugin cannot read, or a plugin that gives no answer, leaves the file to the line merge. `plugins/typescript` is the TypeScript plugin (level 1, by oxc-parser; its README).

A plugin is a child process: it reads one request a line on its standard input (`{"_tag":"UnitsOf","file","text"}`, `ChangesOf{base, head}`, `SitesOf{snap, of}`, `CheckOf{base, layer}`, `CommentOf{text}`; a snapshot is `{root, layer}`, a layer's file `{path, text}` with `text` an Option) and writes one answer a line, in order, then ends with status 0: `UnitsAre{units}` (each `{key, kind, text, exported, members}`), `ChangesAre{changes}` (`{key, file, kind}`, kind one of added, removed, body, contract), `SitesAre{sites}`, `CheckIs{diagnostics}`, `CommentIs{text}`, or a failure as its tagged record: `Unreadable{file, why}`, `NotProvided{op}`, `ToolMissing{why}`, `Unanswered{command, why}`. One run carries every request of a batch. A plugin written in Ergo prints `work.Serve(stdin, splitter, indexer, checker)`; `work.Absent` is the Indexer and Checker of a level-1 language. Units that do not join to the file are `Unanswered` before any caller uses them.

`work.toml`, at the root of the base, is the one checked-in configuration (TOML; every key has a default, and a table it does not know is skipped):

```toml
[work]
storage = "../.work/<base>"      # the workspaces' folder, relative to the base
leave_out = []                   # ["rift-filtered"] is Rift's default list
copy = false                     # allow a plain copy
trash = true                     # false: rm and gc -idle delete for good at once; a host's own rule goes in
                                 # `git config --local work.trash false` in the base instead (never committed),
                                 # which wins over this key; doctor notes `trash: V (SOURCE)`
push = "refuse"                  # "origin": a workspace may push to its remotes
env = []                         # lines work env prints

[deps]
lock = "bun.lock"
install = "bun install --frozen-lockfile"

[hooks]                          # each a list of sh commands, outside the lock
precreate = []
postcreate = []
preremove = []
postremove = []

[[class]]                        # how a path merges; the first that matches wins
match = "tsconfig.json"
kind = "json"                    # json, derived, rows, measured, lines, driver
sets = ["files"]                 # json: key paths merged as sets
# by = "..."                     # derived: the command that makes it again
# driver = "cmd %O %A %B %P"     # driver: writes its merge into %A
# candidate = true               # driver: only where Git's line merge conflicts
# check = "gofmt -l %A"          # candidate: kept only when this prints nothing, status 0
# version = "mergiraf 0.20.0"    # candidate: `TOOL --version` must print it

[language.typescript]            # a language plugin: run only after work trust
command = "bun plugins/typescript/main.js"
files = ["*.ts", "*.tsx", "*.mts", "*.cts"]
```

`init` writes a starter one, all comments. An untracked `work.toml` would make every clone's status dirty (so every `rm` `NotHeld`), so `init` adds `/work.toml` to `.git/info/exclude`; commit it with `git add -f work.toml`.

## Decided

- The host Cloners run the system's own commands through std `exec`, not `import go` of `syscall`: the same calls Rift makes, no Go in the module, and a test can replay the commands. Reverse by: an `import go` provider beside them.
- The lifecycle's states carry no data (the record does), so `ergo test` decides the machine's laws on the whole graph.
- The registry takes one append per record, under a kernel file lock (std `fs.LockFile`, `flock`): the host gives back a dead holder's lock, so no stale lock file is left to clear. A line a crash cut short has no newline and is dropped; gc compacts the file (tombs older than 30 days go). Reverse by: an `import go` lock provider.
- `gc` has no `--of BASE`: `WORK_BASE` picks the base; `gc ID` is `-id ID` (a generated command has no optional argument).
- `init` registers the base it runs in (no DIR: a generated command has no optional argument); `adopt DIR` reads DIR relative to the base.
- A snapshot is a Git tree, kept by a commit no branch holds (`refs/work/latest`), since a push carries commits: Git's object store is the snapshot store.
- `ready` does not refuse uncommitted work, as `lane-rift.sh push` does: the snapshot holds it, and `rm` takes the workspace while the snapshot stands.
- The memory `Vcs` merges file by file and changes nothing on a conflict; git leaves the merge in progress. Both are `Conflicted`.

# orchestrate

An Ergo module (`modules/`) holding the pure event-sourced ledger of an orchestration run, its in-memory reference store and its transactional SQLite store. The binary that serves it over MCP stdio and the command line is `examples/orchestrate`.

| Package | What |
| --- | --- |
| `orchestrate` | Domain types keyed by the unit triple (repo, run, id), the machines `UnitLifecycle` (open, accepted, landed, closed), `QuestionLifecycle`, and `ReadinessMachine` (edge-triggered `Ready \| Backpressure \| Unhealthy` with hysteresis and backoff), progressive-disclosure ledger types (`RunMeta`, `RunOverview`, `UnitSummary`/`UnitPage`, `Decision`/`DecisionPage`, `Landing`/`LandingPage`, `LedgerEvent`/`EventPage`, `ImportReport`), host telemetry & event-stream types (`HostStatusInput`, `HostStatusReport`, `HostReadinessInput`, `HostReadinessReport`, `HostMetrics`, `ReadinessPolicy`, `ReadinessChanged`, `EventsSinceInput`, `EventStreamEntry`/`EventStreamPage`, `UnifiedEvent`), `ParsePlanLines`, `Command`/`Envelope`/`Event`, `Decide`/`Apply`/`Fold`, `Scope`, the `Store` contract (`ListEventLogSince`) and its laws, and the `Api` contract (`HostReadiness`, `EventsSince`) with its `Service` |
| `orchestrate/orchestrateapi`, `orchestratecli`, `orchestratemcp` | Generated by `ergo gen api|cli|mcp orchestrate.Api` |
| `orchestrate/memory` | In-memory reference provider of `orchestrate.Store`, running the `Store` and `Api` laws, a model-based path check and a linearizability check |
| `orchestrate/sqlite` | Single-transaction SQLite provider of `orchestrate.Store` over `modules/sqlite` (`BEGIN IMMEDIATE` WAL, `schema_version` fence at 4 with non-destructive v1/v2/v3->v4 migration (owners from the opening command's actor; the landing lease in `run_meta`), `events` + `commands` + projection tables updated in one `sql.Tx`); each command loads only its scope |

## Laws

- The verdict: `AcceptNeedsGreenReceiptsAtHead` (accepted exactly when the latest receipt of every required kind at the head, of the same unit, exited 0; else `Unverified` naming the missing and red kinds), `LandNeedsTheAcceptedHead` (`NotAcceptedHead` otherwise) and, through the Api, `ApiVerdictFollowsReceipts`.
- `UnitKeysAreTriples`: units that differ in repo, run or id are different units.
- Tandem orchestrators: `LaneHeldAtMostOneLive` (an open on a lane a live unit of the repo holds is `LaneHeld`; at most one live unit per repo and lane), `NoMutationByNonOwner` (receipt, accept, land, close and transfer by a non-owner are `NotOwner` and change no unit; `unit-transfer` is the one hand-over, and a unit of `unknown` owner is claimed once), `LandingHeadMovesOnlyByLeaseHolder` (exhaustive over every four-step interleaving of two actors: the run head moves only by `landing-end` of the live lease holder from the lease's base head, or by the first `landing-begin` of an empty run; `LandingBusy` during another's live lease, `StaleHead` from an old head, a land only inside the lander's lease, a takeover of an expired lease recorded as `LandingLeaseTakenOver`).
- `DecideReadsOnlyItsScope`: `Decide(Scope(state, env), env) == Decide(state, env)`, so a store may load only the scope.
- `ReplayMatchesIncremental`, `IdempotentCommandID`, `ReceiptRecordedReadable`, `CommitmentLandedMonotone`, `QueueUpsertRemoveRoundTrip`, `QuestionAnsweredOnce`, `DecisionSupersedesMarksTargetSuperseded`, `IngestPlanDeduplicatesEvents`, `UnitListPaginationAndFilterLaw`, `ParsePlanExtractsStructuredRecords`, `HostStatusReportPreservesMeasurements`, `HostProcessesFilterInvariants`, `ReadinessHysteresisPreventsFlapping`, `ReadinessBackpressureExitRequiresExitThreshold`, `ReadinessReplayIsDeterministic`, `ReadinessBackoffMonotonicAndBounded`, `EventCursorMonotonicAndDeduplicated`, `ProjectStoredEventCoversDomainTransitions`, `ApiProgressiveDisclosureRoundTrips`, `ApiImportPlanIsIdempotent`, `ApiHostStatusAgreesWithSystem`, `ApiHostProcessesAgreesWithSystem`, `ApiHostReadinessAndEventsSince`, and the machine laws checked by `ergo test`.
- `Store` laws: `StoreReplayMatchesSnapshot`, `StoreIdempotentExecute`, `StoreRefusedLeavesStateUnchanged`, `StoreQueriesMatchSnapshot` over `memory.Store`, `sqlite.Store` and `sqlite.WALStore`.
- SQLite checks (`PersistenceChecks`): `SqliteAgreesWithMemory` (across close and reopen), `SchemaVersionFenceRefusesFutureVersion`, `RollbackAtomicityPreservesConsistency`, `ConcurrentMultiWriterWAL`, `MigrationV2ToV3PreservesExistingData`, `MigrationV1ToV3PreservesExistingData`.

# orchestrate

An Ergo module (`modules/`) holding the pure event-sourced ledger of an orchestration run, its in-memory reference store and its transactional SQLite store. The binary that serves it over MCP stdio and the command line is `examples/orchestrate`.

| Package | What |
| --- | --- |
| `orchestrate` | Domain types keyed by the unit triple (repo, run, id), the machines `UnitLifecycle` (open, accepted, landed, closed) and `QuestionLifecycle`, `Command`/`Envelope`/`Event`, `Decide`/`Apply`/`Fold`, `Scope` (the slice of state `Decide` reads), the `Store` contract and its laws, and the `Api` contract (`unit-*`, `receipt-record`, `commitment-*`, `queue-*`, `question-*`) with its `Service` |
| `orchestrate/orchestrateapi`, `orchestratecli`, `orchestratemcp` | Generated by `ergo gen api|cli|mcp orchestrate.Api` |
| `orchestrate/memory` | In-memory reference provider of `orchestrate.Store`, running the `Store` and `Api` laws, a model-based path check and a linearizability check |
| `orchestrate/sqlite` | Single-transaction SQLite provider of `orchestrate.Store` over `modules/sqlite` (`BEGIN IMMEDIATE` WAL, `schema_version` fence at 2, `events` + `commands` + projection tables updated in one `sql.Tx`); each command loads only its scope |

## Laws

- The verdict: `AcceptNeedsGreenReceiptsAtHead` (accepted exactly when the latest receipt of every required kind at the head, of the same unit, exited 0; else `Unverified` naming the missing and red kinds), `LandNeedsTheAcceptedHead` (`NotAcceptedHead` otherwise) and, through the Api, `ApiVerdictFollowsReceipts`.
- `UnitKeysAreTriples`: units that differ in repo, run or id are different units.
- `DecideReadsOnlyItsScope`: `Decide(Scope(state, env), env) == Decide(state, env)`, so a store may load only the scope.
- `ReplayMatchesIncremental`, `IdempotentCommandID`, `ReceiptRecordedReadable`, `CommitmentLandedMonotone`, `QueueUpsertRemoveRoundTrip`, `QuestionAnsweredOnce`, and the machine laws checked by `ergo test`.
- `Store` laws: `StoreReplayMatchesSnapshot`, `StoreIdempotentExecute`, `StoreRefusedLeavesStateUnchanged`, `StoreQueriesMatchSnapshot` over `memory.Store`, `sqlite.Store` and `sqlite.WALStore`.
- SQLite checks (`PersistenceChecks`): `SqliteAgreesWithMemory` (across close and reopen), `SchemaVersionFenceRefusesFutureVersion`, `RollbackAtomicityPreservesConsistency`, `ConcurrentMultiWriterWAL`.

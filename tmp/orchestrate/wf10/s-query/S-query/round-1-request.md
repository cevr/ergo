## Effect intent and what Ergo takes (inferred)

The purpose of Effect `HttpServerRequest.schemaSearchParams` / `HttpRouter.schemaParams`: a handler gets typed search params, and a cardinality or parse error is a typed issue, not a silent first value. Ergo takes this purpose. It leaves out:
- the Schema value: the record type is the schema (W7);
- the ParseError tagged union: QueryRepeated and the codec's Wire* failures are nominal rows (W5);
- the service-tag access to the request (W4): the caller passes `r.Query`.

The repeated-key rule is stricter than Go's `url.Values.Get` (first value) and Plug's query parser (last value unless the key ends in `[]`). It matches Effect's string-or-array record decoded by a String schema. Gleam's wisp gives a list of pairs and leaves the choice to the handler.

Lowering: the decode is the derived codec's one Go function per type over the Reader interface. There is no reflection. The Reader is an Ergo provider over sync.Refs. No speed is claimed. The hand-written Go control would be `url.Values` plus a per-field `len(v[k]) != 1` check. No measurement was made.

## Known gaps

- An absent list key is WireMissingField: the codec has no default value. A list that may be empty is `json.Optional[[]T]`. A query-specific "absent list is empty" rule would be a construct-local rule (q39). If the owner wants it, the codec needs a field-default rule language-wide.
- The law does not reach `Number`, `Peek`, `TakeNull` and `Tag` of queryReader. The derived decode of a record of scalars and lists never calls them: they serve json.Num, json.Value and union types. `BeginObject` on a field (a record field) has no law row. These lines have no mutant.
- ParseQuery keeps Go's rule: a pair with a malformed escape (`n=%zz`) is dropped, as Serve dropped it before. This is unchanged behaviour, now stated.
- The Go typecheck of the lowered DecodeQuery is exercised only through the stdhttp table program (TestStdHTTPLawsRun builds it).

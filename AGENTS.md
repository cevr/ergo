# Ergo

Claude orchestrates. Opus native subagents implement, one writer per isolated lane, running in parallel as far as the work DAG allows. After each implementation, one verifier from the other model family verifies the round in a clean checkout, through the codex mod: `mcp__codex__start` with model `sol`, the verifier role (the bridge still accepts the old name `reviewer`), and "verify directly" in the prompt; follow up with `mcp__codex__send`. It proves that the change does what the spec says and that it follows the written rules, and files nothing else (orchestrate, 2026-11-03). Continue past two rounds while findings remain. Older handoffs naming `okra counsel`, other models, Herdr panes or Codex panes are superseded. Every verify includes a prior-art section: how Gleam, ReScript, Elixir and the other compile-to-host languages in PRIOR_ART.md handle the same problem, and which optimizations and lowering paths they use (owner, 2026-10-07: "remember to look at lang prior arts as well as part of the review, gleam, rescript, elixir - they all compile downto another language, what optimizations and paths have they used?").

Work runs in waves (owner, 2026-11-03: "batching the implementation work and then batching the verification work"). A lane builds up to four units back to back on stacked branches. Each unit still has its red acceptance check, its mutants and the gate. At the end of the wave, one verifier per unit starts at the same time. Nothing reaches main unverified. A wave ends with non-trivial programs in `examples/`, one per folder, that use its features: ports of the owner's CLIs, a TUI, a GUI and a small game (owner, 2026-11-03: "as kind of a verification round as well"; "in an example within the repo"). A gap a program finds becomes a unit. Examples show what makes Ergo different: machines, laws, exhaustive `match`, rows and typed failures (owner, 2026-11-04: "let's make sure we use machines, laws, matching"). They model their domain as the effect and alchemy-domain skills do, on the path Ergo provides, and they are the worked source of the Ergo skill (#220). They use a Go layout, not kind-suffixed files (owner, 2026-11-04: "more go idiomatic layout but with more effect domain modeling"): a package per responsibility with files named by concept; the domain package declares the contracts it needs (operation types with laws); implementations live in packages named after their dependency (`memory`, a file store, a server); each binary's `cmd/<name>/main.ergo` binds them in a context and is the only place that chooses them. If a construct is not built yet, the unit that builds it upgrades the example when it lands.

## Tests

**Tests.** Before you add a test, name the mutant it catches that no existing law, property, example or test catches, and put that mutant in the package's mutant ledger and in the request. If you cannot, do not add the test (owner, 2026-11-08; [decisions](docs/decisions.md#owner-direction-2026-11-08)).

- Prefer, in order: a law on an operation type or machine; a seeded property against a reference model (a failing seed prints the Ergo source, both outputs and the replay command); an example program under `examples/`. Write a concrete row only for a diagnostic's text or position, or as the smallest repro of a fixed bug (name the bug).
- Check in process. Use the checker's result, the lowered Go text, or `go/types` on the lowered Go (`typecheckGo`) when the question is "does it compile". A test that builds or runs a Go binary states in its doc comment why the in-process check is not enough, builds with the one-binary helper, and calls `needsBuild(t)` (full tier only). Every program it runs has a memory bound the kernel enforces (the 2026-11-08 OOM: one generated test program reached 46.7 GB).
- No fixed time limits: wait for an event, a channel or a process exit; a deadline only stops a hung test and names it. No wall-clock bounds or ratios.
- No pinned counts or digests of generated corpora; the split harness checks that the parts run every case once.
- No golden of the lowered Go's shape, unless the shape is the spec (a speed lowering's promised form, such as "no `env` parameter"); then check the one promised fact.
- When a rule change flips old rows, delete the rows that only restated the old rule if a property or law covers the new rule; do not rewrite them.
- A growth or complexity guard counts work (a counter the code exposes) at small sizes; it never times.
- A unit that deletes tests runs the package's mutant ledger (`go run ./scripts/mutants <pkg>`): every mutant is still killed.

`internal/residue` holds the rules it can read from the source: no fixed waits (`TestTestsWaitNoFixedTime`), no wall-clock comparisons, and none at all in `internal/sketch` (`TestTestsCompareNoWallClock`), no split pins (`TestSplitsPinNoDomain`), and a "builds Go because" line in the doc comment of each `internal/sketch` declaration that builds Go (`TestSketchBuildsSayWhy`). Until the test-speed units land, `typecheckGo` (T1), the one-binary helper (T2), `needsBuild` (T3) and `scripts/mutants` (T0) are planned names.

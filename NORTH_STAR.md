# North star

Ergo is becoming a general application language, for servers and front-ends, that preserves Go-like simplicity and fast native builds, makes Effect-style contracts and owned lifetimes explicit, and adds algebraic data types and useful abstractions in the spirit of Borgo. Straightforward host interop and compiler-backed inspection serve both humans and agents. `.ef` is its source format; `ergo` is its command.

The owner reaffirmed this balance on 2026-10-06. Simplicity means a small set of regular concepts, readable local control flow and predictable costs; it does not mean removing abstractions and making every application repeat their implementation. Effect-grade guarantees require executable evidence for typed failures, dependencies, cancellation and completed cleanup, with unsupported and foreign behavior clearly distinguished.

Dated owner decisions, which apply these principles to one feature, construct, stage or tool, are recorded in [docs/decisions.md](docs/decisions.md).

## Go is the only target (owner, 2026-10-26)

Owner, 2026-10-26: "we're removing the js interop id say". And: "this will be effect for Go with this kind of new language as well. So we'll have a standard library and all the things that Effect does kind of more but more tailored to this new language and the new idioms". Go is therefore Ergo's only target. Effect stays prior art for the guarantees (pillar 2 below). It is no longer a runtime, an ABI or a conformance dependency: the JavaScript emitter, the pinned Effect checkout and the Node toolchain are removed, and `--target js` is the EF110 diagnostic. The standard library covers what Effect does, restated in Ergo's idioms rather than ported API for API.

## North-star pillars (owner, 2026-10-26)

Owner, 2026-10-26: "what I want as a North Star is traceability, you know, observability. The core guarantees of effect and simplicity of go, laws and proofs for sure. The same kind of error and dependency tracking that effect gives, and also really strong focus on agent interpretability, like that they can really understand the code and interact with it that's different than languages that have come before it."

Owner, 2026-10-26, on performance: "zero cost subtractions [abstractions] is very important and being able to compile down to optimized code that's even faster than hand optimized Go code".

1. Traceability and observability.
2. Effect's core guarantees.
3. Go simplicity.
4. Laws and proofs.
5. Error and dependency tracking.
6. Agent interpretability.
7. Performance: every construct lowers to code no slower than hand-written Go, and a feature that is not used costs nothing. Beat hand-optimized Go where the language knows facts Go cannot. Claims need measured evidence.

Score every construct and spike against all seven pillars. Observability and agent interpretability are language concerns, not tooling afterthoughts. Pillar 4 names proofs, so the earlier "no proofs" position on laws is re-opened rather than closed. The proof tier is now designed in outline (change (b) of the [2026-11-02 direction](docs/decisions.md#owner-direction-2026-11-02)): an SMT solver at check time, within a fixed time budget, proves only decidable facts, and reports "proved" only when it discharges the obligation. Everything outside that tier, including a passing finite law suite, is still reported as tested, never as proved.

## Tiebreaks

- **Structural correctness** beats **fast move-in-place** (owner AGENTS.md, 2026-10-05): deliver coherent changes in compiling units; reject shortcuts that hide ownership or duplicate authoritative semantics.
- **Explicit contracts** beat **terse syntax** (drafted 2026-10-05): reject shorter syntax that hides a requirement, target restriction, or foreign trust assertion.
- **Truthful target limits** beat **feature parity** (drafted 2026-10-05): diagnose unsupported operations until an adapter proves their contract.
- **Completed owned cleanup** beats **deadline punctuality** (drafted 2026-10-05): a managed timeout may exceed its deadline while waiting for cooperative shutdown; early return requires an explicit surviving owner.
- **A small regular language with deep libraries** beats **one-to-one API syntax** (owner direction applied 2026-10-06): adopt shared type/function/module mechanisms before adding a special compiler operation for each Effect combinator. Shorter source is useful when control flow and contracts stay visible.
- **Measured implementation evidence** beats **familiar API names** (owner direction applied 2026-10-06): upstream tests guide behavior, but copied tests and similarly named functions cannot establish parity. Preserve slower results and unsupported cases in receipts.
- **Strong abstractions with visible zero-cost obligations** beat **repeated hand-written ceremony** (owner direction applied 2026-10-08): compare the same validation, ownership, cancellation and cleanup in an Ergo candidate and an optimized idiomatic Go control (the TypeScript/Effect control went with the JavaScript target, 2026-10-26). Erasure or direct lowering is valuable only when residual allocation, dispatch, checks, retention, executable size and runtime cost are measured; a failed or unmeasured candidate remains unresolved.
- **Contract guardrails** beat **zero-cost slogans** (owner direction applied 2026-10-08): never remove a check, row, owner or cleanup step to make an abstraction appear free. Rust iterator examples, C++ Per.7 design-for-optimization, Per.11 compile-time lowering, P.9 safety-cost and Per.6 measurement guidance, and Go escape analysis are primary comparisons, not universal Ergo proof.
- **Measured target parity** beats **a convenient weak baseline** (owner direction applied 2026-10-08): native Go uses optimized idiomatic Go with the same contract, and Go lowering investigates static match lowering, direct dispatch and generated/specialized effect runtime paths. A possible many-times speedup is a testable ambition, and losing candidates remain visible.
- **One inspectable contract** beats **duplicated declarations** (owner direction applied 2026-10-06): derive structural codecs from checked data and project machine graphs from checked transitions; retain explicit representation, transformation and lifecycle policies. Automatic derivation does not prove a transformation reversible, host data valid, or a machine durable.
- **Go-like local readability** beats **framework API fidelity** (owner clarification, 2026-10-06): use ordinary statements, typed functions and explicit execution for behavior; keep declarative additions small and inspection rich. Adopt proven guarantees without reproducing every upstream combinator, builder or configuration concept in source syntax.
- **Go idioms** beat **novel notation** as the default lens (owner, 2026-10-08: "go idioms are key in terms of simple yet expressive"): start from the Go spelling and shape, and depart only when a recorded decision shows the departure serves a north star better. The owner may override a Go spelling decision by decision.
- **Reconsidering a prior** beats **consistency with it** when the change better serves these north stars (owner, 2026-10-08: "always reconsider priors if it better serves our north stars"): a settled spelling, admission or design reopens on new evidence; record the superseded choice and the reason.
- **Syntax for compiler-known constructs** beats **special-cased library items** (owner direction 2026-10-09: "syntax is preferred over special cased library constructs ... all of our langauge constructs"): first try to make an item ordinary library through a general mechanism. Where the compiler must still know its meaning, spell it as syntax or a predeclared language identifier. Ordinary library stays library, including capability services. A library intrinsic may swap an implementation without changing checking and is documented. The failure mode is a bundled type, method or service that the checker recognises by identity to grant it language semantics, for example `.catch` moved into an `ergo/effect` method the checker still special-cases, or a machine rule keyed on a bundled `Step` enum. This refines **A small regular language with deep libraries**: it decides how compiler knowledge is spelled, not whether to add it. The [2026-10-12 construct bar](docs/decisions.md#owner-construct-bar-2026-10-12) narrows which syntax qualifies.
- **A primitive function plus library** beats **a construct that fails the guardrail or portability test** (owner construct bar, 2026-10-12: "we'd have to think about a good way to make them primitive rather than blocks"; the two tests are the recorded synthesis, not owner words): a construct must pass the [guardrail and portability tests](GLOSSARY.md). Otherwise the behavior is a primitive function with honest rows and library on top, as in Effect. [#134](https://github.com/cevr/ergo/issues/134) decides provide and timeout by this rule.
- **Visually distinct constructs** beat **method-shaped syntax** (owner, 2026-10-12: "they should be distinct from other already possible constructs. Like normal dot chaining and whatnot"; "I think the else block is overloading if else"): a construct must not look like ordinary dot chaining, and a well-known keyword such as `else` is not reused with a new meaning. The recorded synthesis, not owner words, sharpens this: a construct uses a keyword or block form, and a dot or pipe form is always ordinary library. Postfix constructs are therefore no longer an admissible construct spelling; existing ones stay until [#134](https://github.com/cevr/ergo/issues/134) decides, per form, between a keyword or block construct and ordinary library.
- **Composability** beats **a locally convenient construct** (owner, 2026-10-12: "the primitives have to be able to be stacked on top of each other and grow together"): a candidate that fails a [composability check](GLOSSARY.md) is redesigned or stays library, however short its source. The checks are the recorded elaboration of the owner's direction, not owner words.
- **Laws** beat **API resemblance** for provider admission (owner, 2026-10-12: "it doesn't have to have the same contract … it would be the same laws"): the RS1 suite ([#124](https://github.com/cevr/ergo/issues/124)), together with the Ergo conformance corpus, admits an effect runtime provider. Effect's own suite ([#123](https://github.com/cevr/ergo/issues/123)) is approximation evidence on the Effect surface a provider claims.
- **Go-simple signatures** beat **TypeScript-style expressiveness** (owner, 2026-10-11 and 2026-10-12: "[Go's] simplicity is the goal"; "I'm not sure if they look simple"): simplify what users write, not what the compiler checks. Elide only pass-through rows, never declared requirements, and measure each simplification against a corpus ([#135](https://github.com/cevr/ergo/issues/135)).
- **Capabilities as layers** beat **compiler-builtin providers** (owner, 2026-10-08: "layers define the impl so http is just an impl of a servicve layer"): HTTP, files, clocks and other capabilities are ordinary services whose implementations a layer provides; the compiler checks rows and ownership but does not hard-code a provider.

## Owner rules

- Go is the only target (owner, 2026-10-26: "we're removing the js interop id say"). Ergo is Effect for Go: its standard library covers what Effect does, in Ergo's idioms (owner, 2026-10-26). A lighter or generated runtime provider joins only through the RS1 laws ([#124](https://github.com/cevr/ergo/issues/124)) together with the Ergo conformance corpus.
- The language is named Ergo (owner, 2026-10-27: "I just pick Ergo for now. This is a private project, so if it becomes big we can try to make a whole work or whatever, but for now let's just call it Ergo"; [#218](https://github.com/cevr/ergo/issues/218)). Text written before the rename, and quoted owner text, keep the name Effra. The `.ef` extension stays until [#205](https://github.com/cevr/ergo/issues/205) decides `.ergo` ([preview](docs/previews/2026-10-27-ergo.md)).
- Score every construct and spike against the seven north-star pillars above (owner, 2026-10-26).
- Ergo has no `nil` or `null` language value, nullable ordinary type or observable uninitialized field. Absence is an explicit closed alternative, with bundled `Option<T>` supplied by the generic-data contract ([decision](docs/decisions.md#owner-data-constraint-2026-10-06)).
- Every construct proposal answers the owner's construct bar and composability direction of 2026-10-12. Under the recorded synthesis, not owner words, it states its guardrail and portability tests, its outcome (a keyword or block construct, or a primitive function plus library) and its composability checks ([GLOSSARY](GLOSSARY.md); [#134](https://github.com/cevr/ergo/issues/134)).
- Preserve unrelated work and use isolated Rifts. Implementers never push. The orchestrator integrates accepted, reviewed and gated heads into local `main` and may fast-forward `origin/main` to them (owner, 2026-10-07: "as these things come in we can push straight to main"). Other publishing still requires an explicit owner request (owner AGENTS.md, 2026-10-05).
- Run the full repository gate between logical units and before handoff. Performance claims require measured evidence (repository AGENTS.md).
- Keep Wayfinder's HITL decisions open until owner feedback; artifact completion is not decision closure (repository AGENTS.md).
- Keep `.ef` text authoritative and CLI/MCP on the compiler's semantic model (repository AGENTS.md; architecture direction, drafted 2026-10-05).
- Local fixtures and scratch artifacts are the default for live checks. Paid services, deployment, and production data are outside routine checks (drafted 2026-10-05).
- Continue the authorized Wayfinder and loop work autonomously, extending finite implementation specs with evidence-backed ergonomic, guarantee and performance improvements (owner, 2026-10-06). Follow the standing principles before a genuine question; reversible implementation choices do not require a checkpoint.
- Use Effect's behavior, recorded with upstream provenance in `conformance/effect-cases.json`, plus real usage, to guide the bundled library (owner, 2026-10-06). The pinned Effect checkout is removed (owner, 2026-10-26: "also the effect requirement as well"). Public examples and application-pattern notes stay generic. Agent roles, models and independent review are set only in [AGENTS.md](AGENTS.md).
- Compare Elixir (with Erlang/OTP) and MoonBit alongside Go, TypeScript/Effect, Gleam and ReScript in every language decision where they have a relevant construct; [PRIOR_ART.md](PRIOR_ART.md#standing-comparison-languages-elixir-with-erlangotp-and-moonbit-2026-10-09) holds the pinned rows (owner, 2026-10-07, 2026-10-08 and 2026-10-09).

- Drive: `./scripts/gate.sh` builds `bin/ergo` and exercises native Go execution through the CLI process tests (`TestSketchExampleBuildsAndRuns`, `cmd/ergo/sketch_process_test.go`).
- State: `./bin/ergo check examples/editions/sketch/main.ef` and `./bin/ergo diagnostics --json examples/editions/sketch/main.ef`. `ergo inspect`, `ergo explain` and MCP are unavailable until [#203](https://github.com/cevr/ergo/issues/203); there is no out-of-process runtime endpoint yet.
- Stop: the process tests wait for their processes to exit. Longer-lived server checks must record shutdown and scratch cleanup.

## Rejected

| Candidate | Why it stays rejected |
| --- | --- |
| Kernel or hard real-time execution profile | Outside the owner's revised server scope, 2026-10-05; [Wayfinder map](https://github.com/cevr/ergo/issues/1), "Out of scope". The 2026-10-11 application direction widens the scope to front-end code and does not revisit this exclusion. |
| Reusing a well-known keyword, such as `else`, with a new construct meaning | Owner, 2026-10-12: "I think the else block is overloading if else, since that's already a well-known programming concept." [#134](https://github.com/cevr/ergo/issues/134) decides the replacement. |
| A language construct that looks like ordinary dot chaining | Owner, 2026-10-12: constructs "should be distinct from other already possible constructs. Like normal dot chaining and whatnot." Today's postfix constructs remain until [#134](https://github.com/cevr/ergo/issues/134) decides each form; this replaces [#95](https://github.com/cevr/ergo/issues/95)'s reservation plan. The wider rule that every dot or pipe form is ordinary library is the recorded synthesis in the [construct bar](docs/decisions.md#owner-construct-bar-2026-10-12), not owner words. |
| Requiring a lighter effect runtime to share Effect's API contract | Owner, 2026-10-12: "it doesn't have to have the same contract … it would be the same laws". Admission is by the RS1 laws ([#124](https://github.com/cevr/ergo/issues/124)) together with the Ergo conformance corpus; Effect's suite ([#123](https://github.com/cevr/ergo/issues/123)) is secondary approximation evidence. |
| Treat host type declarations as proof of foreign behavior | Breaks **Explicit contracts and clear guardrails**; [interop trust distinction](docs/interop.md#behavior-contracts-without-signature-duplication). |
| A platform that owns every capability | Capabilities stay separate services provided by a context; owner direction, 2026-11-02. |
| Replace `.ef` with an authoritative graph database | Conflicts with the repository's source-authority rule; borrow focused semantic queries/edits instead ([design](docs/design.md#compiler-backed-mcp-and-semantic-editing)). |

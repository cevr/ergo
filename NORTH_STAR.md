# North star

Ergo is becoming a general application language — for servers, shared libraries, CLI tools, and browser/edge front-ends — that preserves Go-like simplicity and fast native builds, makes Effect-style contracts and owned lifetimes explicit, and adds algebraic data types and useful abstractions in the spirit of Borgo. Straightforward host interop and compiler-backed inspection serve both humans and agents. `.ergo` is its source format; `ergo` is its command.

The owner reaffirmed this balance on 2026-10-06. Simplicity means a small set of regular concepts, readable local control flow and predictable costs; it does not mean removing abstractions and making every application repeat their implementation. Effect-grade guarantees require executable evidence for typed failures, dependencies, cancellation and completed cleanup, with unsupported and foreign behavior clearly distinguished.

Dated owner decisions, which apply these principles to one feature, construct, stage or tool, are recorded in [docs/decisions.md](docs/decisions.md).

## Native backend pivot (owner, 2026-11-27)

Owner, 2026-11-27: Go is **Stage-0 bootstrap only**; Ergo owns its native backend end-to-end (ELF64 on Linux, Mach-O64 on macOS, `.wasm` for browser/edge, and standard C ABI everywhere):

1. **Go is Stage-0 bootstrap only.** The Go backend, `toolchain/ir` Go fork patches, `goobj` emission, `internal/gobind`, `runtime/v1` Go shims, `runtime/rt`, and `go.Ref`/`go.New`/`go.Zero`/`go.Any` are frozen as disposable Stage-0 bootstrap and scheduled for deletion once Stage-1 self-hosted Ergo compiles itself natively (`Stage-1 -> Stage-2` identical native bootstrap).
2. **Two-tier native execution model.** The Dev/Test Tier (`compiler/objfmt/` emitting standard ELF64/Mach-O64 + `compiler/nativelower/` lowering with zero `goobj`, zero Go stack-maps/write-barriers, and zero `GOCACHE`) pairs with `compiler/eval` for `<50ms` incremental tests, laws, and mutants. The Release Tier optimizes Ergo's typed SSA IR (SIMD, LTO, whole-program DCE) targeting Linux, macOS, and `.wasm`.
3. **Zero-GC native memory and concurrency (`runtime/native/`).** Perceus reference counting with compile-time `own` unique in-place reuse (`rc == 1`), scoped O(1) bump arenas for frame/request temporaries, BEAM/OTP per-actor isolated bounded heaps (`Limits.Bytes` exact accounting, O(1) crash reclamation on defect/`OverBytes`/`OverSteps`, zero cross-actor pauses or write barriers), and a cooperative M:N fiber scheduler over `io_uring` (Linux) / `kqueue` (macOS) with native reduction counting (`Limits.Steps`).
4. **One clean FFI and interop surface.** Outbound `extern c` lowers directly through `compiler/bindc/` to platform C ABI calls. Inbound `ergo build --lib` emits compact `.so`/`.dylib` libraries (C ABI, zero Go runtime or signal-handler conflicts) plus auto-generated `bun:ffi` / Node N-API TypeScript bindings and `.d.ts` directly from checked contracts, alongside tiny `.wasm` builds and `tsproj` RPC for network boundaries.
5. **Spec and language surface diet.** Hard target `<250 KB` core language spec outside `docs/spec/stdlib.md` once Go-interop surface is retired after Stage-1 cutover, paired with language surface simplification.

Effect remains prior art for guarantees (pillar 2 below), never a runtime dependency or ABI; the superseded 2026-10-26 Go-only stage is recorded in [docs/decisions.md](docs/decisions.md#native-backend-pivot-elfmach-o-perceusarenas-c--bun-ffi-2026-11-27). Architecture and execution slices live in [native backend architecture](docs/specs/native-backend/architecture.md) and [native backend units](docs/specs/native-backend/units.md).

## North-star pillars (owner, 2026-10-26)

Owner, 2026-10-26: "what I want as a North Star is traceability, you know, observability. The core guarantees of effect and simplicity of go, laws and proofs for sure. The same kind of error and dependency tracking that effect gives, and also really strong focus on agent interpretability, like that they can really understand the code and interact with it that's different than languages that have come before it."

Owner, 2026-10-26, on performance: "zero cost subtractions [abstractions] is very important and being able to compile down to optimized code that's even faster than hand optimized Go code".

1. Traceability and observability.
2. Effect's core guarantees.
3. Go simplicity.
4. Laws and proofs.
5. Error and dependency tracking.
6. Agent interpretability.
7. Performance: reach the native floor, then lower it. Every construct lowers to zero-GC native code competitive with or faster than hand-optimized native systems code (C, Rust, Go), and a feature that is not used costs nothing. Perceus RC with compile-time `own` unique reuse, scoped O(1) bump arenas, per-actor bounded heaps, direct ELF64/Mach-O64 emission, and typed SSA release optimization (SIMD, LTO) are the native performance levers; Stage-0 Go (`toolchain/ir` fork and `runtime/v1`) remains a transitional bootstrap baseline until Stage-1 cutover. A lever never changes a result, and each lever rests on proved laws or validated evidence with matched receipts against honest controls. (Supersedes the Go-runtime-only formulation of 2026-11-20: "reach the floor ... via the fork or the IR path".)

Score every construct and spike against all seven pillars. Observability and agent interpretability are language concerns, not tooling afterthoughts. Pillar 4 names proofs, so the earlier "no proofs" position on laws is re-opened rather than closed. A passing finite law suite is reported as tested, never as proved, and never acted on (q115).

## Composability and consistency (owner, 2026-11-20)

Owner, 2026-11-20: "we want our language to be as composable as possible. So composability, performance, guarantee, simplicity, no ceremony, like these are the keywords that we want for our language, and consistency". The two paragraphs below come from the composability audit (COMPOSE-AUDIT). They are the recorded elaboration of these words, not owner words, and the order of the six keywords heads **Tiebreaks** ([decision](docs/decisions.md#owner-direction-2026-11-20)).

**Composability (owner, 2026-11-20: "we want our language to be as composable as possible").** A feature composes when a value of it can be named, passed, returned, stored, made generic, nested and combined with another of its kind, by the same rules everywhere, and when doing so loses no row, no owner, no law and no instruction. A declaration form (a context, a machine, a union, a law, an operation type) is sugar for a value an ordinary function could build, and whatever the declaration can say, a function that returns the value can say. A refusal is a guarantee or it is a gap: each "is only called", "is closed", "takes no type parameter" in the specification names the guarantee it protects, or it is listed as a gap with its owner. The test of a feature is the matrix in docs/spec (features × name, pass, return, generic, nest, combine, tweak at a leaf): every cell works, or is refused by a diagnostic that names the guarantee. This sharpens **Composable primitives** and the five composability checks: lossless wrapping now includes speed facts, so wrapping a construct in an ordinary function costs no instruction the direct form does not pay.

**Consistency (owner, 2026-11-20; q39, 2026-11-09: "a language hole gets one consistent rule across the language, not a construct-local fix").** One idea has one spelling and one rule set. Where two forms stay (a capability and a value of its type, `Option` and a failure, a member law and a top-level law), the specification states the rule that chooses between them and the conversion between them is one call. A rule that holds for one kind of row, parameter, declaration or built-in type holds for the others, or the difference is a stated guarantee. Std and the prelude follow the rules a user package follows. Consistency is with the language as it should be, not with what was built first: **Reconsidering a prior** still beats consistency with it.

## Tiebreaks

**The order of the six keywords** (owner, 2026-11-20, q256: "Yes, that order"). When two of them pull apart, the higher one wins. The pairwise tiebreaks below apply this order to particular cases; each one names the keywords it sets against each other, and none of them reverses the order.

1. **Guarantees.** A guarantee is never removed to gain anything below it (**Contract guardrails** beat **zero-cost slogans**; **Explicit contracts** beat **terse syntax**).
2. **Composability.** **Composability** beats **a locally convenient construct**.
3. **Consistency.** One rule across the language (q39). It ranks below guarantees, and **Reconsidering a prior** beats consistency with it.
4. **Simplicity.** **A small regular language with deep libraries**; **Go-simple signatures**. It ranks below composability: simplicity does not mean removing abstractions and making every application repeat their implementation.
5. **Performance at the native floor.** Every unit must deliver it (pillar 7), and it is never bought with 1 to 3: a lowering keeps its reference and its agreement property (while Stage-0 Go exists, Stage-0 comparisons keep Go controls alongside native controls).
6. **No ceremony.** Last where the ceremony is a written contract (**Explicit local signatures** beat **inference**: a clause is never elided). First where the ceremony carries no contract: a closure that only forwards, a restated law, a written type argument the checker could infer.

- **Structural correctness** beats **fast move-in-place** (owner AGENTS.md, 2026-10-05): deliver coherent changes in compiling units; reject shortcuts that hide ownership or duplicate authoritative semantics.
- **Explicit contracts** beat **terse syntax** (drafted 2026-10-05): reject shorter syntax that hides a requirement, target restriction, or foreign trust assertion.
- **Truthful target limits** beat **feature parity** (drafted 2026-10-05): diagnose unsupported operations until an adapter proves their contract.
- **Completed owned cleanup** beats **deadline punctuality** (drafted 2026-10-05): a managed timeout may exceed its deadline while waiting for cooperative shutdown; early return requires an explicit surviving owner.
- **A small regular language with deep libraries** beats **one-to-one API syntax** (owner direction applied 2026-10-06): adopt shared type/function/module mechanisms before adding a special compiler operation for each Effect combinator. Shorter source is useful when control flow and contracts stay visible.
- **Measured implementation evidence** beats **familiar API names** (owner direction applied 2026-10-06): upstream tests guide behavior, but copied tests and similarly named functions cannot establish parity. Preserve slower results and unsupported cases in receipts.
- **Strong abstractions with visible zero-cost obligations** beat **repeated hand-written ceremony** (owner direction applied 2026-10-08): compare the same validation, ownership, cancellation and cleanup in an Ergo candidate and an optimized native control (C, Rust, or Stage-0 Go where applicable). Erasure or direct lowering is valuable only when residual allocation, dispatch, checks, retention, executable size and runtime cost are measured; a failed or unmeasured candidate remains unresolved.
- **Contract guardrails** beat **zero-cost slogans** (owner direction applied 2026-10-08): never remove a check, row, owner or cleanup step to make an abstraction appear free. Rust ownership/iterator examples, Koka Perceus reuse, C++ Per.7/Per.11/P.9/Per.6 guidance, and Go escape analysis are primary comparisons, not universal Ergo proof.
- **Measured target parity** beats **a convenient weak baseline** (owner direction applied 2026-10-08): native lowering targets performance matching or beating hand-optimized native systems controls with the same contract, using static match lowering, direct dispatch, Perceus `own` reuse, scoped arenas, and specialized effect runtime paths. A possible many-times speedup is a testable ambition, and losing candidates remain visible.
- **One inspectable contract** beats **duplicated declarations** (owner direction applied 2026-10-06): derive structural codecs, C/TypeScript FFI bindings, and machine graphs from checked declarations; retain explicit representation, transformation and lifecycle policies. Automatic derivation does not prove a transformation reversible, host data valid, or a machine durable.
- **Go-like local readability** beats **framework API fidelity** (owner clarification, 2026-10-06): use ordinary statements, typed functions and explicit execution for behavior; keep declarative additions small and inspection rich. Adopt proven guarantees without reproducing every upstream combinator, builder or configuration concept in source syntax.
- **Go idioms** beat **novel notation** as the default lens (owner, 2026-10-08: "go idioms are key in terms of simple yet expressive"): start from the Go spelling and shape, and depart only when a recorded decision shows the departure serves a north star better. The owner may override a Go spelling decision by decision.
- **Reconsidering a prior** beats **consistency with it** when the change better serves these north stars (owner, 2026-10-08: "always reconsider priors if it better serves our north stars"): a settled spelling, admission or design reopens on new evidence; record the superseded choice and the reason. It bounds rank 3 (consistency) of the order above: consistency is with the language as it should be.
- **Syntax for compiler-known constructs** beats **special-cased library items** (owner direction 2026-10-09: "syntax is preferred over special cased library constructs ... all of our langauge constructs"): first try to make an item ordinary library through a general mechanism. Where the compiler must still know its meaning, spell it as syntax or a predeclared language identifier. Ordinary library stays library, including capability services. A library intrinsic may swap an implementation without changing checking and is documented. The failure mode is a bundled type, method or service that the checker recognises by identity to grant it language semantics, for example `.catch` moved into an `ergo/effect` method the checker still special-cases, or a machine rule keyed on a bundled `Step` enum. This refines **A small regular language with deep libraries**: it decides how compiler knowledge is spelled, not whether to add it. The [2026-10-12 construct bar](docs/decisions.md#owner-construct-bar-2026-10-12) narrows which syntax qualifies. Since 2026-11-12 the failure mode also covers emission, optimization, evidence and tooling keyed on a std item or on std membership, not only checking (owner: std gets no special treatment).
- **A primitive function plus library** beats **a construct that fails the guardrail or portability test** (owner construct bar, 2026-10-12: "we'd have to think about a good way to make them primitive rather than blocks"; the two tests are the recorded synthesis, not owner words): a construct must pass the [guardrail and portability tests](GLOSSARY.md). Otherwise the behavior is a primitive function with honest rows and library on top, as in Effect.
- **Visually distinct constructs** beat **method-shaped syntax** (owner, 2026-10-12: "they should be distinct from other already possible constructs. Like normal dot chaining and whatnot"; "I think the else block is overloading if else"): a construct must not look like ordinary dot chaining, and a well-known keyword such as `else` is not reused with a new meaning. The recorded synthesis, not owner words, sharpens this: a construct uses a keyword or block form, and a dot or pipe form is always ordinary library. Postfix constructs are therefore no longer an admissible construct spelling.
- **Composability** beats **a locally convenient construct** (owner, 2026-10-12: "the primitives have to be able to be stacked on top of each other and grow together"): a candidate that fails a [composability check](GLOSSARY.md) is redesigned or stays library, however short its source. The checks are the recorded elaboration of the owner's direction, not owner words. This is rank 2 of the order above, and the **Composability** paragraph (2026-11-20) adds the feature matrix as its test.
- **Laws** beat **API resemblance** for provider admission (owner, 2026-10-12: "it doesn't have to have the same contract … it would be the same laws"): the RS1 suite, together with the Ergo conformance corpus, admits an effect runtime provider. Effect's own suite is approximation evidence on the Effect surface a provider claims.
- **Go-simple signatures** beat **TypeScript-style expressiveness** (owner, 2026-10-11 and 2026-10-12: "[Go's] simplicity is the goal"; "I'm not sure if they look simple"): simplify what users write, not what the compiler checks. A clause is never elided: an unwritten clause is the empty clause (**Explicit local signatures**), and a left-out trailing row argument is the empty row. Simplification comes from fewer concepts and from derivations declared at one site, never from a clause computed from a body or a call graph, and is measured against a corpus. Pass-through elision is dropped (owner, 2026-11-12, q140).
- **Explicit local signatures** beat **inference** (owner, 2026-11-12: "maybe it's just better to be explicit at all times - We're entering an age where now agents really do the writing. Inference works well for humans since we're lazy, but agents tend to work better with explicitness"; and: "we can also make this a North Star"): every function states its needs, errors and given/gives/keeps clauses; the checker checks a body against its own signature and never infers a clause; tooling (`ergo fix`) writes missing clauses. Refines pillar 6 (agent interpretability) and **Explicit contracts** beat **terse syntax** ([decision](docs/decisions.md#owner-direction-2026-11-12)). It is why no ceremony is last in the order above where the ceremony is a written clause.
- **Better-than-system std** (evolved from "Better-than-Go std", owner, 2026-11-12 and 2026-11-27): std names and conventions stay as they are (Effect's intent, Go's conventions); each implementation uses Ergo's guarantees (the value rule, Perceus `own` reuse, borrows, scoped arenas, proved laws, typed failures, closed unions, explicit rows) to be faster and safer than C/Go system libraries, measured against matched native controls, with Go/standard semantics as the behavioral oracle where the semantics match. Never an optimizer keyed on a std name: the compiler gains general facts, and std uses them ([decision](docs/decisions.md#owner-direction-2026-11-12)).
- **Capabilities as context-provided services** beat **compiler-builtin providers** (owner, 2026-10-08: "layers define the impl so http is just an impl of a servicve layer"): HTTP, files, clocks and other capabilities are ordinary services whose implementations a context provides; the compiler checks rows and ownership but does not hard-code a provider.

- The standard library takes Effect's guarantees and Go's names: Go's package and function names where Go has them, Effect's operations where it does not, laws on every operation type and pure family, typed failures and `Option` in place of `error` and `(v, ok)`, and a named native/Go control with a benchmark for every package. `unsafe` lives only in listed, reviewed runtime/FFI boundaries (`runtime/native/` C ABI and transitional Stage-0 `runtime/v1` bodies), each with its invariant, a test and a measured gain (owner, 2026-11-06; [decision](docs/decisions.md#owner-direction-2026-11-06)).
- The standard library takes Effect's behaviour and guarantees, never an Effect API shape that exists only to work around TypeScript (generators, `pipe`, dual signatures, service tags and layers, `_tag` strings, `Match`, schema classes, runtime `Equal` and `Hash`, brands). It uses Ergo's constructs instead (rows and `try`, operation types with laws, `context` and `with`, unions with exhaustive `match`, construction authority, derivation), and each package states its lowering against hand-optimized native/Go controls, at least as fast or with the loss and its compiler follow-up recorded (owner, 2026-11-08; [decision](docs/decisions.md#owner-direction-2026-11-08)).
- The standard library gets no special treatment (owner, 2026-11-12: "even our standard library should not be able to get any special treatment"). Std is an ordinary set of packages. Anything std can do (a fast path, an extern, a law the optimizer uses, a codec format, a lint pack), any module can do through the same written mechanism: a declaration in its source that the compiler reads. No checker rule, lowering, optimizer, cache or tool decides by a std name or by std membership. Two things stay, and both are written lists: the predeclared names of the language, and the seam by which the toolchain finds, ships, caches and names std, which changes no meaning. The test: a std package copied into a user module checks, lowers and counts the same ([decision](docs/decisions.md#owner-direction-2026-11-12)).
- Compare Elixir (with Erlang/OTP) and MoonBit alongside Go, TypeScript/Effect, Gleam and ReScript in every language decision where they have a relevant construct; [PRIOR_ART.md](PRIOR_ART.md#standing-comparison-languages-elixir-with-erlangotp-and-moonbit-2026-10-09) holds the pinned rows (owner, 2026-10-07, 2026-10-08 and 2026-10-09).
- Nothing is hard (owner, 2026-11-22: "By the way, as a standing rule, nothing is hard. We live in a new age. You're more capable than you realize"; "Let's put it in the North Star"). Difficulty is never a reason to defer or refuse work, split the real design off as "later", narrow its acceptance, recommend the lesser option, take a workaround or hand back blocked. Only three reasons order or rule out a candidate, and each is named: a **guarantee** it would break (the guarantee and the failure it prevents), a **dependency** that must land first (the prerequisite and what it enables), or a **measured cost** (the receipt and what it counts). When two options differ only in effort, the better one is built; when the owner must choose, both outcomes and their tradeoffs are described, and neither is recommended for its effort. *Example:* live upgrade. "Hot code loading: not planned" became a hand-over between binaries, in which the new binary takes the old one's state and open connections. A stream passes across the upgrade rather than making its client reconnect, with no event dropped or duplicated (q344, owner: "Let's try passing live connections first"). A transport that cannot hand its state over is refused only after the refusal names the state that must move and the guarantee it protects.

## Rejected

| Candidate | Why it stays rejected |
| --- | --- |
| Kernel or hard real-time execution profile | Outside the owner's revised server, library, and front-end scope. Zero-GC Perceus/arenas/per-actor heaps deliver predictable low latency for applications, `--lib` libraries, and `.wasm`, while kernel-mode and hard real-time execution remain outside the destination. |
| Reusing a well-known keyword, such as `else`, with a new construct meaning | Owner, 2026-10-12: "I think the else block is overloading if else, since that's already a well-known programming concept." |
| A language construct that looks like ordinary dot chaining | Owner, 2026-10-12: constructs "should be distinct from other already possible constructs. Like normal dot chaining and whatnot." The wider rule that every dot or pipe form is ordinary library is the recorded synthesis in the [construct bar](docs/decisions.md#owner-construct-bar-2026-10-12), not owner words. |
| Requiring a lighter effect runtime to share Effect's API contract | Owner, 2026-10-12: "it doesn't have to have the same contract … it would be the same laws". Admission is by the RS1 laws together with the Ergo conformance corpus; Effect's suite is secondary approximation evidence. |
| Treat host type declarations as proof of foreign behavior | Breaks **Explicit contracts and clear guardrails**; [foreign facts](docs/spec/interop.md#foreign-facts). |
| A platform that owns every capability | Capabilities stay separate services provided by a context; owner direction, 2026-11-02. |
| Replace `.ergo` source with an authoritative graph database | Conflicts with the repository's source-authority rule; borrow focused semantic queries/edits instead ([design](docs/design.md#compiler-backed-mcp-and-semantic-editing)). |

# Prior Art for `atlas`

This document records the prior art reviewed when designing `atlas`: what `atlas` adopts, what it leaves behind, and why. Facts verified from source or repository files on disk are cited by repo-relative path or commit; uninspected upstream code from public documentation is explicitly tagged `[not checked]` / `[inferred from public docs]`.

## Detailed Notes by System

### 1. T3 Code (`pingdotgg/t3code`)
Inspected thoroughly in [t3-decisions.md](t3-decisions.md) (decisions D1–D68). T3 Code proved the exact server/adapter architecture required to tame Claude Code (`claude-agent-sdk.query`), Codex (`codex app-server`), and Antigravity (`agy acp`) under one typed server:
- **What transfers unchanged:** server-owned processes (D1), capability-driven orchestration with zero adapter-name branching above the seam and zero fake capability emulation (D2, D4), Thread/Session/Turn separation (D6), terminal settlement of open children/requests (D7), structured `usage_limit` + single-armed auto-resume (D8–D9), per-thread scoped `/mcp` tokens (D11), and Antigravity's strict process/profile boundary (D20–D35: no proxy, no rotation, `SSH_CONNECTION` isolation for keyring avoidance, SQLite session error classification).
- **What `atlas` simplifies:** no browser/Electron clients, no T3 Connect public relay, no Git hidden-ref checkpoints, no per-peer OAuth login over tailnet (our tailnet authenticates host peers), and adding a first-class `Direct` adapter path so `atlas` is not limited to subprocess CLIs.

### 2. OpenCode (`anomalyco/opencode`, `prime-look`, and dotfiles mods)
Inspected directly on disk (`prime-look` commit `24dca3c14f` and dotfiles `opencode/mods/*`). Over months of real multi-agent orchestration, critical behavior had to be bolted onto OpenCode via TypeScript plugins:
- **`mods/pool`:** Fleet-wide weekly pace line (99% weekly target + 5% leeway across all accounts and hosts), soonest-resetting under-line account placement, unsettled fleet-start accounting, door refusals naming exact `retryAt` openings, held-turn/subagent single-wake delivery with immutable `wakeDeliveryId`, automatic measured limit resets, and owner-approved time-boxed pushes. All of this moves natively into `atlas`'s pool subsystem.
- **`mods/kernel` + `mods/wake` + `mods/questions`:** Bounded persistent cell kernel (2 min wait / 30 s compute / 10 min asking cut), `DELIVERS` single-deliverer handle registry (`call`/`land` via registry; `timer`/`job`/`subagent`/`shell`/`question` via owners), `Unfinished` / `Handed` separation, async-only `ask_user_async`, and `Executing · Ns` live status. Moves natively into `atlas`'s `KernelEngine` + wake service.
- **`mods/queue` + `mods/orchestrate`:** Input message queueing moves into `atlas`; commitment tracking (`modules/orchestrate`, already in this repo) stays anchored in `modules/orchestrate` rather than a dotfiles plugin.
- **`mods/guard`:** Safety refusals (`Destructive` `rm`/`git reset --hard`/`git clean`, kill-by-pattern protecting server PID, `git worktree add` where CoW workspaces apply, `work gc` during workspace creation, subagent long foreground `sleep`, Chrome mock-keychain flag enforcement) move natively into `atlas`'s shell tool gate. The removed heavy-command queue (`host-admit` / `light.sh` / `nice`) is deliberately **rejected**; host load and memory capacity come from `std/host`.
- **Upstream `codemode/` & `prime-look`:** Upstream OpenCode explored confined `psychoscript` execution and moved toward ephemeral `execute` scripts with suspension; our fork carried hold/restart budget recovery (`2cfd486367`), held `Step` send history (`284de1d65c`), model selection `origin` provenance (`d28605ebad`), and Prime-styled transcript/tool formatting.

### 3. Vercel / `fx` (`vercel-labs/fx`)
`[not checked]` on disk; characteristics observed from public documentation `[inferred from public docs]` plus local transcript components (`mods/prime/tui/transcript.tsx`, `mods/prime/tui/tools.tsx`) built from its look:
- **Core architecture (`[inferred from public docs]`):** Zig native single binary with sub-millisecond startup, embeddable engine (`libfx`), ACP agent support, native search/read/modify/shell tools, and explicit `ask` / `auto` / `yolo` permission modes.
- **Visual transcript grammar (checked in local TUI adaptations):** `fx` replaces noisy bordered boxes around every step with clean typographic hierarchy: a thick left rail (`┃`) for user messages, a solid header glyph (`●`) on assistant steps, and crisp tree connectors (`├` / `└`) grouping `thinking` and tool calls together with paired outputs. `atlas`'s TUI adopts this transcript grammar directly inside the Prime layout shell.

### 4. Pi (`badlogic/pi-mono` and `@earendil-works/pi-durable`)
`[not checked]` on disk `[inferred from public docs]`:
- **Layered loop:** Separates provider gateway (`pi-ai`), event-driven core loop (`pi-agent-core`), surgical built-in tools (`read`, `write`, `edit`, `bash`), lightweight TUI (`pi-tui`), and non-linear session trees (`/fork`, `/tree`).
- **Session tree topology (`id` / `parentId`):** Stores entries as an append-only tree rather than a flat chat array, maintaining strict structural validity (`assistant toolUse -> toolResult -> user`) on resume and compaction.
- **Crash & server-upgrade durability (`pi-durable` + subagent resilience `[inferred from public docs]`):** Commits conversation turns, intents, and tool states *before* side effects execute ("effect sandwich"), and settles mid-flight interrupted calls on restart according to idempotency (`replay: "safe"` vs `"unsafe"` -> explicit *"may have partially run"* rather than silent duplicate replay or dropped work). Paired with background subagents surviving restarts and rate-limit holds without losing parent-child links.
- **`atlas` synthesis:** Because `atlas` restarts frequently during self-updates/upgrades, `atlas` adopts Pi's crash/restart settlement philosophy in Ergo + SQLite (`modules/sqlite`): intent/handles/tree links commit first, surviving async work (`job`, `subagent`, `pool` hold, `question`, detached handles) resumes automatically with single-wake delivery, and process-bound work that cannot survive a binary restart (`call`) settles honestly once as `"may have run"` rather than silently disappearing or replaying blindly.

### 5. Tardigrade (`clavia-labs/tardigrade`)
Checked locally (`README.md`, `docs/introduction.mdx`, `docs/agent.mdx`):
- Models durable execution via pure state atoms (`durableAtom`) and side-effectful `act` boundaries backed by persistent actors (`Actor.make`), alongside a direct `Agent` abstraction (`Agent.tools`, `Agent.compact`, `localWorkspace` / `virtualWorkspace`).
- Reinforces two invariants in `atlas`: (1) separate pure decision state from external I/O effects (already native to Ergo's machines and `modules/orchestrate`), and (2) keep workspace access virtualizable behind explicit interfaces so tests and remote/local execution share one semantics.

### 6. Prime Agent (`PrimeIntellect-ai/prime-agent` & local `mods/prime`)
- **Upstream RLM concept (`[not checked]` `[inferred from public docs]`):** Treats prompts and intermediate data as variables inside a persistent Python/IPython REPL where subagents act like recursive function calls, plus background sessions surviving terminal disconnects with an Agents View.
- **Local `mods/prime` (checked on disk):** Proved the operator TUI ergonomics `atlas` keeps: violet-accented dark palette (`#7c6faf`), status diamonds (`◆` running, `◈` question/permission wait, `◇` idle), single top breadcrumb bar showing parent -> subagent lineage, dock line (`agents`, `questions`, `jobs`), compact 6-row live subagent strip, composer view tabs, and mouse-clickable file/session/question/link targets.
- **`atlas` synthesis:** Keep the persistent state-across-cells ergonomics and Prime TUI layout, drop IPython/blocking REPL execution in favor of bounded wake-driven cells (`KERNEL-ENGINE-PROBE` picks between `psychoscript`, `Luau`, and an `ergoscript` spike, keeping Bun only as a later measured benchmark).

### 7. Gent (Our Effect / TypeScript Harness & Ergo `examples/gent`)
Inspected directly on disk across the TypeScript/Effect `gent` repository (`NORTH_STAR.md`, `ARCHITECTURE.md`, `docs/architecture/{lanes,machines}.md`, `packages/core/src/runtime/{agent-loop,turn}.ts`, `packages/extensions/src/*`) alongside Ergo's native port at [`examples/gent/README.md`](../../../examples/gent/README.md):

- **What `atlas` adopts directly from Effect/TS Gent:**
  - **Actor-per-session runtime (`packages/core/src/runtime/agent-loop.ts`, `turn.ts`):** Every session mutation crosses one mailbox in order; callers wake on completions rather than blocking on locks (`NORTH_STAR.md`: *"Children wake, never block"*). Translates directly to Ergo's `std/actor` + `std/machines`.
  - **Durable transactional consistency (`ARCHITECTURE.md` Rules 5–8):** Events and projections commit in one SQLite transaction (`Rule 5`); resumed turns replay stored tool bindings instead of re-executing side effects blindly (`Rule 6`); approvals are one-shot and fail closed (`Rule 7`); each model step classifies once (`StepOutcome`).
  - **Cross-host quota lanes (`docs/architecture/lanes.md` & `extensions/src/lanes`):** Multi-host peer synchronization adding peer active runs (`peerLoad`) and fuel spend per model onto local admission, plus bounded silent-peer backpressure (`min(C - peer runs, C / (1 + N))`)—shaping `atlas`'s cross-host `pool` sync.
  - **Cost & prefix stability (`NORTH_STAR.md`):** Byte-stable prompt prefixes with explicit model-change notices, 8,000-char inline tool-result cap with output spill to storage, and 429 limit auto-resume 30 s after reset (`README.md`).
  - **Safety & transcript (`packages/extensions/src/guard.ts`, `NORTH_STAR.md`):** Unconditional `@gent/guard` destructive floor (`rm`, `git reset --hard`, forced `git clean`) and transcript visual hierarchy (`fx` tool/thinking tree + semantic styling).
  - **Native Ergo proof (`examples/gent/`):** Already proves `std/llm` + `modules/sqlite` event-sourced turns, `NoRetryAfterFirstDelta`, tool dispatch, and compaction in pure Ergo.

- **What `atlas` replaces or improves over Effect/TS Gent:**
  - **Ergo runtime over Bun + Effect-TS:** Replaces Effect-TS `Context.Service` / `Layer` runtime overhead, dynamic extension loading, and Bun heap weight with statically checked Ergo capability rows, `std/actor` supervision trees, `std/machines` finite-state proofs, and a single native binary.
  - **Bounded wake-driven `KernelEngine` over full-Bun cells (`Rule 13`):** Gent deliberately ran `"in full Bun. No sandbox, no interpreter"`; `atlas` puts cells behind `KernelEngine` (`KERNEL-ENGINE-PROBE` testing `psychoscript`, `Luau`, and `ergoscript` spike) with 2 min wait / 30 s compute cuts and `DELIVERS` wakes so neither roots nor subagents stall threads.
  - **`Meta` + `Direct` parity:** Gent focused on its own direct loop and thin `opencode` extension; `atlas` manages Claude Code, Codex app-server, Antigravity ACP, AND its built-in `Direct` loop under one Thread/Turn model.
  - **Zero-downtime server cutover & mouse-clickable `std/ui`:** Adds BEAM-inspired live FD/PTY handover (`models/cutover/cutover.ergo`) and `std/ui` + `hosts/opentui` mouse-click parity (`models/tui/tui.ergo`), avoiding manual restart waits or keyboard-only divergence.

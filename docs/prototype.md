# Implemented prototype

> **Status:** describes the retired `.ef` language, removed 2026-10-28 by [#205](https://github.com/cevr/ergo/issues/205); kept as design reference. The [retirement record](receipts/retire-ef.md) lists what was removed.

This is a single-file compiler experiment, not the full design in design.md. The source is authoritative; unsupported syntax produces diagnostics rather than being passed through to the host.

## Supported surface

- Immutable local bindings, string/bool/void and i64 values, managed File handles, string concatenation, signed i64 `+`, `-`, `*`, unary `-`, `/` and `%` (the divisor must be proven nonzero, EF150), ordered comparisons and primitive equality, and `if` expressions with two branches. Signed i64 literals are range checked, including the minimum value. Decimal text conversion is the bundled `ergo/i64` module (`format`, and `parse` raising `I64ParseFailure`); other numeric widths remain unsupported. See [portable i64 arithmetic](research/numeric-arithmetic.md).
- Ordinary `fn` and lazy `effect fn`, with explicit parameter, result, failure, and service contracts.
- Nominal records and closed enums with typed fields: `record User { id: string }`, `enum State { Ready Waiting { reason: string } }`, constructors, field access and exhaustive `match` arms. Constructor payloads accept `{ field }` shorthand; in a control position such as `match State.Ready { value } { ... }`, the following arm brace disambiguates that constructor from the control body. Static data does not decode or validate external wire values.
- Nominal errors may carry typed fields: `error NotFound { id: string }`; `fail NotFound { id: "missing" }` preserves the payload. Error declarations are failure payload types, not ordinary success values or nested record fields.
- Nominal services and implementations, including configured providers that capture declared services: `impl MemoryUsers for Users` and `impl Prefixed(prefix: string) for Greeting uses {Names}`. Construction is effectful and explicit; fallible acquisition and general memoized sharing are unsupported.
- Calls bind arguments by position or by parameter name. In `card(body: "b", title: "t")` each label binds the parameter it names, whatever the order. Positional arguments fill parameters from the left and must come before labelled ones, as in `pair("m", second: "n")`. An unknown label, a repeated label, a label naming a parameter that a positional argument already fills, and a parameter with no argument are EF106 errors on the label or the call name. Arguments always run in the order they are written, not parameter order. The rule covers functions, effect functions, service operations and configured provider constructors. Parameter names are therefore public API: renaming a parameter breaks every caller that labels it. Callable values and Go functions declare no parameter names, so a label there is an EF106 error. Record and enum constructors keep their own rule: all fields named or all positional (EF122). Static layer configuration stays positional (EF135).
- `run` to execute a deferred effect within an effect body.
- `x |> f(args)` is the call `f(x, args)`, rewritten by the parser: the piped value is positional argument 1, pipes associate left, the postfix chain continues after the call and `run` takes the whole chain. An unparenthesised pipe chain beside `+`, `-`, `*`, `/`, `%`, `<`, `<=`, `>`, `>=` or `==`, a bare `x |> f` and a non-call right side are EF002; a label naming the first parameter is EF106. See the [pipe operator](specs/language-abstractions.md#pipe-operator) and [examples/pipe.ef](https://github.com/cevr/ergo/blob/dbf135bff09901e85385945593113f35b300199c/examples/pipe.ef).
- `.provide<Service>(Provider)` removes that service requirement.
- `.catch<Failure>(pureFallback)` removes exactly that failure. This prototype deliberately accepts a pure replacement value rather than a lambda or effectful handler.
- Built-in Console/Stdout, Clock/LiveClock, Env/LiveEnv and Http/LiveHttp; Go additionally supplies Files/LiveFiles and Runtime/RuntimeLive. See [runtime.md](runtime.md) for contracts and foreign adapters.
- `scope { ... }`, `fork effectCall()`, inferred fiber `join()` / `cancel()` / `interrupt()`, and lazy `.timeout(milliseconds)` adding Timeout. The checker conservatively retains child failure rows even when a child is not joined.

- `import go alias "module/package"` loads primitive native function declarations; `.orFail()` adapts returned Go errors explicitly. See [interop](interop.md).
- `Http.listen(address, HttpLimits, handler)` is the only builtin HTTP server operation: a bounded managed transport over builtin `HttpRequest`/`HttpReply` records whose native provider owns requests and shutdown. The raw `Http.serve` was removed (EF102). See [HTTP contract](runtime.md#http-server).

Rows are normalized sets; declarations are upper bounds. Service calls use the service's declared contract even if one provider admits fewer failures. A library may retain requirements; the executable entry is an effect function named `main`, takes no parameters, and requires no remaining services. Its admitted typed failures are reported as runtime failures with nonzero exit status.

The last expression is a block's value. Use semicolons where adjacent expressions could parse as one call; newlines are whitespace. Strings use JSON escapes. Identifiers are ASCII; source offsets and columns are UTF-8 bytes. Empty blocks and blocks ending in a `let` produce `void`. The explicit no-value expression is bare `void`; `()` remains the required spelling for empty parameter and argument lists, and is rejected in type and expression positions.

## Execution and inspection

The frontend is Go with no third-party Go dependencies. The Go target, the only target since 2026-10-26, lowers checked IR to typed lazy closures, explicit Exit propagation, nominal provider structs, and a standalone executable through `go build`. No JavaScript runtime is involved in the native artifact.

Until 2026-10-26 an optional JavaScript target lowered to pinned Effect 4.0.1. The owner removed it ("we're removing the js interop id say"); `--target js` is now the EF110 diagnostic.

`ergo check` returns revisioned JSON including diagnostics, contracts, canonical type references, bounded ownership/capture facts, nominal declarations, used host bindings, and separate import/parse/check timings. `ergo inspect FILE SYMBOL` and `ergo explain FILE SYMBOL` return the same semantic symbol and direct executed-call/failure contributions; passing a record, enum or error name inspects its declaration fields/variants. Explanations are currently local contributions, not a transitive proof or provision history. JSON schema version 9 is experimental.

`ergo build FILE` publishes a complete generated Go module under `dist/go/apps/<application-id>/generations/` and produces the standalone executable `dist/<name>`. `-o PATH` selects its output path. `ergo run FILE` builds and executes the native artifact. Each source origin, target, and ordinary/test mode has a stable application identity; unchanged snapshots reuse their immutable generation.

Generated Go is trusted compiler output and should be regenerated after source edits.

## Limits

The finite supported profile includes named callback row parameters, compiler-distributed first-order record templates and initialized conversion witnesses, structural JSON codec derivation through `ergo/json`, decimal `i64` text conversion through `ergo/i64`, pure static layer plans, and an LSP diagnostics/full-document lifecycle subset. See [bundled interfaces](specs/bundled-interfaces.md), [layers](specs/layers.md), and the [LSP contract](lsp.md) for their boundaries.

 General user generic declarations, nested template data arguments, open rows, first-class polymorphic functions, anonymous closures and capture checking remain unsupported. Planned constructs not yet supported (anonymous closures, loops, assignment, the `?` operator and module-level `let`) and the familiar TypeScript/Go constructs Ergo leaves out (`null`, `throw`, `try`/`catch`, `as`, `async`, `!`, `&&`, dynamic `import(...)`) report `EF003` with construct-specific help; see [diagnostic codes](https://github.com/cevr/ergo/blob/dbf135bff09901e85385945593113f35b300199c/docs/tooling.md#diagnostic-codes-and-absent-constructs). Managed layer acquisition, fallible/startup construction, parameterized or inherited plans, and complete layer tooling/adoption remain future work. Retry, source maps, persistent/package caching, LSP range/on-type formatting, references and rename, content mapper, semantic edits, codecs for arrays, decoding failure witnesses, endpoint path parameters, query and headers are also unsupported. Recursive data layouts receive an explicit diagnostic, as do unknown generic type spellings. Go scope snapshots exist, but there is no process-wide runtime endpoint or instrumented wait-reason tree. Lifecycle conformance covers owned cleanup, unobserved child failures and deadline cleanup defects. Service/type identities remain local to this single-file experiment.

Inspection revisions hash source bytes and, when imported, Go export archives and normalized behavior contracts. Compiler/runtime/schema versions are separate metadata; this is not a complete build-cache key. Construction of an unused recipe may retain requirements in the recipe type without adding them to the enclosing executed body. The requirements row tracks managed service access, not a proof of complete purity or race freedom.

## Baseline

Measured 2026-10-05 on Apple M4 Pro, darwin/arm64, Go 1.27.1. `BenchmarkCompile10KLines` checks 2,000 five-line independent effect functions (114,890 bytes): three runs averaged 3.15–3.23 ms/op, approximately 14 MB allocated and 16,144 allocations per compile. This is an in-process parse/check measurement; it excludes CLI startup, JSON output, emission, dependency loading, and backend execution. It contains no imports or adverse row-polymorphism cases. No claimed speed budget has been established.

Reproduce: `go test ./internal/compiler -run '^$' -bench BenchmarkCompile10KLines -benchmem -count=3`.

After managed-runtime integration, the same command on the same M4 Pro/Go 1.27.1 environment measured 3.30–3.35 ms/op, approximately 14.05 MB and 16,176 allocations. It still excludes imports, generation, Go compilation and linking; it establishes no matched end-to-end ratio.

## Validation receipt

The gate verifies formatting, Go vet, compiler diagnostics/contracts, both backends' sequential laziness/replay/recovery, provider isolation, nested execution, emitted library imports, nonzero host failure exits, and MCP initialization/query behavior. The generated Go conformance probe uses the race detector. Go runtime tests additionally exercise acquisition-close races, concurrent close, child-before-parent cleanup, LIFO release, composite failure/defect preservation, cancellation hooks, timeout shutdown, native partial results, and closed File handles. The public smoke harness runs the portable concurrency example, imported Go functions, and [`examples/lifecycle.ef`](https://github.com/cevr/ergo/blob/dbf135bff09901e85385945593113f35b300199c/examples/lifecycle.ef) (whose Files/Runtime capabilities remain Go-only). The HTTP harness runs a real generated server and checks routes, failure responses, deadlines, file scopes and SIGTERM shutdown. The transport harness drives [`examples/http-transport.ef`](https://github.com/cevr/ergo/blob/dbf135bff09901e85385945593113f35b300199c/examples/http-transport.ef) over raw sockets: exact statuses, body limits, stalled bodies, admission, disconnect and shutdown. Use `go test -race ./...` for the full race check.

A prior short parser/checker/emitter fuzz run completed over 1.2 million inputs without a crash before the explicit nesting bound was added. This is limited historical fuzz evidence, not a correctness proof or fresh lifecycle fuzz coverage. The compiler rejects parser nesting beyond 256.

## Native Go lowering boundaries

Go success values are typed primitives/handles, not boxed interpreter values. Effects are lazy `func(efContext) efExit[A]` closures; `run` emits ordinary calls and explicit Exit propagation. Failure/service rows remain frontend checks and are erased in generated Go. Context copies implement lexical provider binding. Ordinary sequencing stays on the current goroutine; managed fork creates a goroutine with an owning scope.

Generated programs imported the reusable managed runtime bundled from `runtime/ergo` into each immutable generation's `runtime/` directory (`runtime/ergo` was removed in batch 14; the rest of this section describes the retired language in the present tense). Each generation contains only the runtime modules its checked application plan selects, always including the core ownership and scheduler sources, and its generated main emits only the declarations that plan retains. They use exactly the tested runtime source, not a second handwritten scheduler prelude. Managed effect/finalizer panics become defects; arbitrary unmanaged goroutine panics and fatal process/runtime failures remain outside that guarantee. Native entry points forward interrupt/SIGTERM through context and wait for owned cleanup before reporting failure. Legacy shared `dist/go` files are preserved and are not adopted by a new generation. Retained generations and interrupted staging or temporary commit entries remain available for inspection. Each `dist/go/apps/<application-id>/commits/<generation-id>.commit` marker's JSON `directory` field names its completed folder under that application's `generations/`; folders without a referring marker are retained orphans. Publication uses an exclusive same-filesystem regular-file hard link, so filesystems without hard-link support are unsupported. Tests cover failed publication, cooperating publication and orphan recovery; there is no SIGKILL or power-loss durability claim.

Native builds rely on the installed Go toolchain and its normal compiler/build cache. Generated source is deterministic and unchanged bytes are not rewritten. Ergo does not yet cache its own parsing/checking or interface summaries. Automatic imports invoke go list on each check and have separately reported loading cost. Backend build/link time must be measured separately from the frontend microbenchmark.

Historical warm native build sample, before managed runtime integration: on the same Apple M4 Pro/Go 1.27.1 setup, five unchanged `ergo build examples/main.ef` invocations took 40.44–42.26 ms, median 42.08 ms after one warm-up. This includes CLI startup, source checking/emission, and cached Go compilation. It is a tiny no-op fixture; no cold-build, private-edit, public-edit, or matched-Go ratio has been established.

### Imports and lifecycle update (2026-10-05)

On the same Apple M4 Pro / Go 1.27.1 setup, the 10k-line no-import fixture measured 3.65 ms/op, 14.06 MB and 16,184 allocations in one run. This is about 9% above the previous 3.30–3.35 ms sample; no matched repeated regression attribution was performed.

Four warm public CLI checks of [`examples/main.ef`](https://github.com/cevr/ergo/blob/dbf135bff09901e85385945593113f35b300199c/examples/main.ef) took 4.01–5.33 ms, with no import work. Four checks of [`examples/imports.ef`](https://github.com/cevr/ergo/blob/dbf135bff09901e85385945593113f35b300199c/examples/imports.ef) took 50.66–51.81 ms; reported import loading took 45.67–47.08 ms. Four unchanged native builds of the imported example, after one warm-up, took 154.90–157.46 ms. These are distinct tiny fixtures, not matched Go/Ergo comparisons. Go toolchain process/export loading dominates the imported check; persistent normalized import summaries remain a priority. Cold builds, edit invalidation regimes and linking attribution remain unmeasured.

Reproduce by timing `./bin/ergo check examples/imports.ef` and `./bin/ergo build examples/imports.ef` after warm-up; inspect the JSON `timings.importMicros` separately from wall time.

## Default tooling and tests

`lint`, `lint rules`, `query` and `graph` use the same checked model as symbol inspection. MCP adds `project.lint`, `lint.rules`, `code.typeAt`, `project.graph` and `project.tests`; all tools remain read-only. Queries use expression diagnostic anchors, not full source ranges. Graphs describe provider recipes, materialized values and declared provision edges; fallible acquisition and general dependent-layer sharing remain unsupported.

`ergo test` discovers checked `test_` effects and supplies `Assert`. Each case owns a fresh scope, with captured suite output and structured failure reasons. Live host/time capabilities require `--live`; the real process watchdog reports unconfirmed cleanup on forced termination. See [tooling](tooling.md), [testing](testing.md) and [runnable testing example](https://github.com/cevr/ergo/blob/dbf135bff09901e85385945593113f35b300199c/examples/testing.ef).

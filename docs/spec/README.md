# Ergo language specification, v0

Version 0, 2026-10-27. Ticket the sketch specification, part of the compiler track the main compiler.

This directory is the normative specification of the Go-shaped Ergo language: Effect's guarantees with Go's spelling, compiled to Go (owner, 2026-10-26: "this will be effect for Go with this kind of new language as well"). `.ergo` source is authoritative: a source file ends in `.ergo`, and every other extension, the earlier `.ef` included, is refused with "source file must have .ergo extension". The parser, the checker and the linearity pass implement this text.

## Scope

- **In scope.** Lexical rules and grammar, types, error and capability rows, resources, the runtime rules, the standard-library outline and the diagnostics of the core.
- **Sources.** The design sketches of 2026-10-26, numbered 8, 9 and 10, and their two independent reviews.
- **Out of scope.** The earlier `.ef` language, which the .ef migration retired with its compiler ([retirement record](../receipts/retire-ef.md)). Its documents stay as design reference. [`docs/design.md`](../design.md) marks each section this specification supersedes.
- **One language.** There are no editions and no manifest: every `.ergo` file is this language.
- **Terms.** Every domain term is defined only in the [glossary](../../GLOSSARY.md). These files state rules and link to it.
- **Direction.** [NORTH_STAR.md](../../NORTH_STAR.md) holds the pillars P1 to P7 and the tiebreaks. [PRIOR_ART.md](../../PRIOR_ART.md) holds the source comparisons.

## Conventions

- "Must", "must not" and "is an error" are normative. An error has a diagnostic code from [diagnostics.md](diagnostics.md).
- Each construct carries one status label:
  - **Checked; runs**: the checker `internal/sketch/check` checks it, and `ergo build`, `ergo run` and `ergo test` lower it to Go from the checker's output (`internal/sketch/lower`).
  - **Checked; build refused (S109 naming its owner)**: the checker checks it, and the build stops at it with S109, whose message names the open owner that will lower it.
  - **Designed, not yet implemented**: decided in the sketches or by the owner, with no compiler support yet.
  - The [support table](support.md) gives the exact support of the build, one row per family of construct with its status and owner. A test generates it from the lowering's inventory, so it cannot drift.
  - Since the parser and formatter, the parser `internal/sketch/syntax` parses and formats every construct of every label. A parsed construct that another ticket owns is S109 naming that ticket ([diagnostics](diagnostics.md#s109-owned-by-another-ticket)).
- A design choice between options cites prior art in one line. The standing comparison set is Go, Gleam, ReScript, Elixir/OTP, MoonBit, Rust, Swift, Effect and OCaml/Koka.
- Examples are fenced as `go` because the surface is Go-shaped. They are Ergo source, not Go.

## Gaps

The prototype's behaviour and the sketches leave the points below unstated or in conflict. Each has a recommendation. A rule in another file that settles a gap says so.

1. **Total-catch default arm.** The sketches say a total `catch` has no default arm. The prototype's emitter adds one that passes `rt.Interrupted` on, because interruption is not a typed error. *Recommendation:* adopted as the rule in [rows.md](rows.md#catch): a `catch` covers the typed row only, and interruption and defects always pass through it. Lowering must keep that path.
2. **Interruption in a function with no error row.** The prototype panics with `rt.Interrupted` through `t.Check()`, and the nearest task boundary recovers it; `main` exits with status 130. *Recommendation:* adopted in [runtime.md](runtime.md#exit-causes): interruption is part of the exit cause, never of the error row. The lowering is free to choose the carrier.
3. **Type-switch totality.** The prototype accepts a type switch that omits a variant when the function needs no value after it (measured: a two-variant switch with one `case` checks with exit 0). The sketches say switches are checked for totality. *Recommendation:* a `match` over a union must name every variant or have a `case _` arm, as Gleam, Rust and Swift require. The rule is in [rows.md](rows.md#totality); the checker enforces it (S103).
4. **`main` with an error row.** The prototype rejects it (S109). The sketches write `func main() fails ConnectFailed needs Console`. *Recommendation:* allow it. The entry prints each cause and exits 1, or 130 when every cause is an interruption, as the current entry failure report does. *Status:* the checker allows it; a value result is S113.
5. **Host capabilities for `main`.** The prototype gives `main` only `Console`. Decision the Foreign protocol makes `Clock`, `Scheduler`, `Random` and `Console` ordinary interfaces bound by `context`. *Recommendation:* the entry supplies a predeclared host context with these four live providers. A test replaces any of them with `with`. The exact host set is open. *Status:* the checker does not restrict `main`'s capability row; the build refuses what the host cannot supply.
6. **Closed top-level contexts.** The prototype requires a named `context` to need no capability from its caller and to let no failure escape. The sketches give a named context constructors whose rows join the `with` site. *Recommendation:* the closed rule is a prototype limit. The designed rule is in [rows.md](rows.md#context). *Status:* **needs closed** (CTX-ROWS-1; owner q254 "Context carries its failure row", q266 "Written header, as designed"): a named context's header `needs` row is checked, and each `with`, embedding or conversion charges it where it builds ([rows.md](rows.md#context) Context 4). **Failures open:** a named context still lets no failure escape its build until its header can write a `fails` row (CTX-ROWS-1b). Constructor entries are context construction's.
7. **Context entries as provider literals only.** The prototype rejects a constructor entry (S109). *Recommendation:* constructors are designed ([rows.md](rows.md#context)). The parser takes both forms; the checker refuses a constructor entry with S109 naming context construction.
8. **Visibility (closed 2026-10-27).** Every sketch since the fourth relies on Go's capitalised export, for example an unexported field that makes `ParseQuantity` the only constructor. The owner chose explicit `pub` on 2026-10-08. Asked again with the recommendation "Go's capitalisation", the owner answered on 2026-10-27: "Yeah, let's go with your [recommendations]". *Decision:* a name is exported when it starts with an upper-case letter, and `pub` is superseded. The rule is in [grammar.md](grammar.md#visibility); the [NORTH_STAR tiebreak](../../NORTH_STAR.md#tiebreaks) records the change.
9. **Integer types.** The prototype has one integer type, `int64`, and the sketches use `int` and `int64`. *Recommendation:* Go numeric types decides the numeric types. *Status:* the checker types every Go numeric type with Go's rules (Q5), `complex64` and `complex128` included (arithmetic and `==`, no ordering; no imaginary literal and no `complex`, `real` or `imag` builtin), and a typed floating-point or complex constant holds its type's rounded value; Go numeric types keeps the overflow policy, checked runtime conversions and floating-point literals.
10. **Short-circuit operators.** The prototype rejects `&&` and `||` (S109) because hoisted calls would run out of order. *Recommendation:* allow them with Go's short-circuit order. The lowering must not hoist a right operand above the left. *Status:* the checker accepts them with Go's typing; the build lowers them ([support](support.md), `BinaryExpr`).
11. **Bindings and statements in arms.** The prototype's arms are single expressions with no binding. The sketches bind the error in an arm and use `return` in an arm. *Recommendation:* adopt both, as in [rows.md](rows.md#catch): an arm binds with `case E as e:`, and an arm is a statement list whose last statement yields the arm's value when the catch is an expression. *Status:* statements in arms are checked; `as` bindings are check-v1's (196p).
12. **Multi-subject type switch.** The sketches write `match (s, sig)` with tuple cases and `_`. *Recommendation:* adopt it as the machine-step form, with totality over the product. *Status:* the checker checks it, with totality decided by a usefulness check over the case matrix; the build lowers it ([support](support.md)).
13. **Automatic release versus checked `defer`.** The 2026-10-26 sketch 9 made a resource linear with a checked `defer` and `build.Scope.Acquire`. The owner's later direction of the same day ("make it simpler so that defers are automatic") replaced that with automatic release. *Resolved 2026-10-27:* [resources.md](resources.md) follows automatic release. `defer` stays for statements that are not releases. `build.Scope` becomes a library for dynamic registration. The std scope and resources body and the standard library table now say the same.
14. **Resources behind interfaces.** Review 9 (M2) showed that converting a resource to an interface without `Close` loses release authority. *Recommendation:* adopted in [resources.md](resources.md#conversions): that conversion is an error.
15. **Moves into aggregates.** The owner's rule lists four moves. Building a struct whose field is a resource also transfers ownership, as the `Postgres` example does. *Recommendation:* adopted in [resources.md](resources.md#moves) as a fifth move.
16. **Reserved names of the prototype's output.** The prototype reserves Go's predeclared identifiers, `rt`, `time`, `fmt`, `init`, `Error`, `timeout`, `duration`, names with `__` and names ending in `_` (S109). *Recommendation:* these are prototype limits. The main compiler mangles generated names, so only the language's own reserved words stay reserved ([grammar.md](grammar.md#reserved-names)). *Status:* the checker reserves none of them, and universe names may be shadowed.
17. **Capabilities in provider methods.** The prototype rejects a `needs` clause on a method and a capability call inside a provider method (S109). *Recommendation:* a provider method may use the capabilities its constructor captured, as Effect's layers capture their dependencies. A method signature still cannot widen the capability's row. *Status:* a method may write a capability row and is charged at its call; such a method cannot implement a capability method (S106) or an interface method (S108), because its row is wider. The captured form exists for go.Foreign (STD-NOPRIV NP4e): a provider whose operations need go.Foreign beyond the operation type's row becomes a value of the operation type, or a context entry, where it is built, and that site is charged go.Foreign, as any call of Go is ([types](types.md#capabilities) Capabilities 4). go.Foreign has no provider value, so nothing is stored. A law case of the test binary holds go.Foreign, so a law runs natively on such a provider (owner q277; [types](types.md#laws) Laws 10). A type parameter's constraint captures nothing, and every other capability stays with context construction.
18. **Diagnostic codes.** The prototype's codes (S001, S101 to S110) are not in the main compiler's EF registry. *Recommendation:* the main compiler gives each rule in [diagnostics.md](diagnostics.md) an EF code, and keeps the rule text and fixture links.
19. **No fixture file for S107.** The missing-return rule is pinned only by a table test in `sketch/sketch_test.go`. *Closed:* the checker's fixture `missing-return` pins S107.
20. **Codec discovery by name.** The sketches find a type's codec by the names `ParseX` and `Wire`, as Go finds `TestX`. A rule keyed on a name risks the special-cased-library pattern the owner rejected. *Recommendation:* state it as a general method-set convention with laws in std codecs and I/O, so that a userland codec family can use the same rule.
21. **Go interop.** The 2026-10-26 sketch 9 first dropped user-level Go interop and then restored `import go` at the owner's request. Decision Go and TypeScript bindings maps Go imports automatically. *Recommendation:* `import go "path"` with the `go.Foreign` capability, as in [grammar.md](grammar.md#declarations). The mapping rules stay with Go interop.
22. **`Layer.fresh`.** There is no form for an independent build of one node inside a build. *Recommendation:* a contextual `fresh` inside `context`, decided with context construction.
23. **Generic surface.** The sketches use single capital letters as implicit type parameters (`func Map(xs []A, …)`). No rule says which names are parameters. *Recommendation:* row elision and named constraints decides. The spelling in [types.md](types.md#generics) is provisional. *Status:* the checker implements rows-and-constraints §7 amendment 2: a name of one upper-case letter, optionally followed by digits, that names no declaration is an implicit parameter, and its kind follows its position.
24. **Purity of function values.** Review 9 (M3) withdrew "an empty-row function type is pure". *Recommendation:* adopted in [rows.md](rows.md#footprints): a function type carries requirements only, and an unknown function value counts as impure. *Status:* the checker converts a function value to a function type whose rows are supersets of its own, never the reverse.
25. **`duration` in signatures.** The prototype types duration literals and the `timeout.After` argument, but `func delay(d duration)` is S104, because `duration` is not one of its basic type names. *Recommendation:* `duration` is a basic type usable in every type position ([types.md](types.md#basic-types)). *Prior art:* Go's `time.Duration` is an ordinary named `int64` type, usable in every type position. *Status:* the checker types `duration` in every type position; the build lowers it ([support](support.md)).
26. **Equality on `duration`.** `1s == 1s` is S109 in the prototype. *Recommendation:* `==` applies to every basic type, `duration` included ([types.md](types.md#operators)). *Prior art:* Go compares `time.Duration` values with `==`, as every integer-based type. *Status:* checked.
27. **Method calls on values.** The prototype calls a method only through a capability. A direct call such as `S{}.M()` or `v.M()` is S109. *Recommendation:* Go's method calls on values, including on a composite literal ([types.md](types.md#methods)). *Prior art:* Go method values and calls; Gleam has no methods and calls module functions instead. *Status:* checked; the build lowers such a call ([support](support.md)).
28. **Repeated capability entry in one context.** The prototype accepts two entries for one capability in one context, and the later one wins (measured: `context{ Store = Mem{V: "first"}; Store = Mem{V: "second"} }` prints `second`). *Recommendation:* a second entry for a capability in one context is an error, S111, unless it is a `replace` of an embedded entry ([rows.md](rows.md#context)). *Status:* implemented by the checker. *Prior art:* Google Context rejects two providers of one type in a set; Effect's `Layer.merge` lets the later layer win silently, which Ergo does not copy.
29. **Capabilities as values.** The prototype accepts a capability interface as a parameter and result type (`func identity(c Store) Store { return c }` checks), but a method call on such a value is S109, and assigning a struct value to an interface type (`func NewStore() Store { return Mem{} }`) is S108, because the prototype's assignability is identity plus the variant-to-union rule. Both are prototype limits. *Recommendation:* interface assignability by method-row compatibility ([types.md](types.md#interface-assignability)), and distinguish the capability from the interface type ([types.md](types.md#capabilities)). A capability name used as an expression, other than as the receiver of a method call, is an error: the bound provider cannot be passed, returned or stored. The same interface used in a type position is an ordinary interface type, and its values are provider values whose method calls carry the methods' declared rows. This keeps the decision on the Foreign protocol (capabilities are ordinary interfaces bound by `context`) and keeps ambient authority out of values. *Prior art:* Effect separates a service's tag (the requirement) from a service value; Scala 3 capture checking tracks capabilities apart from their types. *Status:* checked.
30. **Channels of resources.** v0 makes a channel whose element type is a resource an error ([resources.md](resources.md#channels)). *Recommendation for a later version:* a send moves the value; the channel's buffer owns values in flight; releasing a channel releases its buffered values; a failed or interrupted send leaves ownership with the sender. *Prior art:* Rust `mpsc` moves values into the channel and drops buffered values with the receiver; Go channels copy and leave cleanup to the programmer.
31. **`timeout.After` as a name-keyed prototype exception.** The prototype recognises `timeout.After` by its imported name: the parser gives it a trailing block, and the checker charges `Scheduler`, adds `timeout.Expired` and makes its block a failure target. That is the special-cased-library pattern the owner rejected. *Recommendation:* `timeout.After` is an ordinary library function over kernel primitives ([runtime.md](runtime.md#timeouts)): a trailing block is a function-literal argument ([grammar.md](grammar.md#expressions)), and a row-generic signature gives the same rows. *Status:* the checker checks `timeout.After` as an ordinary bodiless declaration of the package `timeout` in `internal/sketch/std`; the prototype's special casing stays inside the build path only, until direct-Go lowering.
32. **Resource map keys.** v0 makes a map whose key type is a resource an error (R40 in [resources.md](resources.md#containers); S112, designed), because a key has no release owner under R34 to R37. *Recommendation for a later version:* a map with a resource key type is itself a resource and owns its keys; inserting moves the key in; a delete-and-return moves the key and value out together; replacing the value for an existing key releases the old value and keeps the old key, releasing the new key argument; releasing the map releases every key and value. *Prior art:* Rust's `HashMap` owns its keys and drops them with the map, and `HashMap::insert` on an existing key keeps the old key.
33. **A context header clause: exposure or requirements.** The corpus (`sketch-eval-8/five/layers`, both `context-effects` files) wrote `context App uses Account, Invoice { … }`, where the clause meant the capabilities the context exposes ("Store stays hidden"), while `uses` on a signature meant requirements ([rows-and-constraints.md](../research/rows-and-constraints.md) §7 item 9). *Resolved 2026-10-27*: two keywords, one meaning each. `provides A | B` lists what a named context exposes, and the entries it does not list stay private to its build; `needs C | D` lists what its providers require from the `with` site, joined into that site's row, as Effect's `Layer<ROut, E, RIn>` keeps provided and required services apart. *Retired 2026-11-27* (RSI-SURFACE-DIET, owner q225): a context exposes every entry it binds, so `provides` is gone (S001), and the corpus copies drop it; `needs` stays ([rows.md](rows.md#context) rule 8).
34. **One provider for several capabilities: `Clock, Scheduler = testing.VirtualClock{}`.** The corpus binds one value to several capability rows in one context entry. The parser of the parser and formatter admits several keys before `=`, as Go's `var a, b = …` admits several names ([grammar.md](grammar.md#extensions-beyond-the-written-productions)), and the bridge refuses it with S109. Its meaning (one value shared by several rows, or one value per row) is the checker's to define. *Status:* the checker reads it as one shared value that must implement each listed capability. *Prior art:* Effect's `Layer.mergeAll` builds one layer that provides several services.

Gaps 35 to 47 come from the [actor library spike](../research/actor-library.md) (A1 to A13 there). The `actor` package is library code only if these general rules exist. Each also serves tasks in containers and channels, queues, `tasks.Set`, RPC replies and batch waiters.

35. **Consuming parameters and receivers (A1).** R19 names the consuming calls: `Close`, `Task.Wait`, `Task.Stop` and an actor's `Stop`. A library type such as `actor.Reply` needs its own consuming method (`Send`). *Recommendation:* a parameter or receiver whose body consumes or moves it is consuming, and a call moves the argument. The checker infers it and records it in the exported interface summary, as it does for concurrent parameters. R19's list becomes a consequence of the rule. *Prior art:* Rust by-value `self`; Swift `consuming` methods.
36. **Resource unions (A2).** No rule says whether a union with a resource variant is a resource. *Recommendation:* it is (R1 extended); a type switch on an owned union moves the variant into the case binding.
37. **Channels of resources (A3).** Gap 30's later rule is needed now: an actor's mailbox holds messages with a reply. *Recommendation:* adopt Gap 30's recommendation. A send moves the value, the buffer owns values in flight, and a failed send leaves ownership with the sending function, whose scope releases it. The receiving half is the same rule: when the last owner of a channel releases it, its buffered values are released. A value nobody can receive is therefore released exactly once. A reply slot is a channel that the asker and the reply share, so a late answer to a detached asker is released by whichever share is released last; the Go lowering implements this with a one-shot `slot` state. *Prior art:* Tokio `oneshot`: dropping the receiver makes `send` return the value to the sender, and dropping the channel drops a value in flight.
38. **Consuming a resource field in place (A4).** A handler answers `m.Reply.Send(v)`, which consumes one field of an owned message; R39 forbids moving a field out. *Recommendation:* consuming a field in place is allowed on an owned aggregate; the field is then consumed, and the generated `Close` (R3) skips it. Moving the field out stays an error. *Prior art:* Rust partial moves.
39. **Owned parameters in function types (A5).** A handler `func(S, M)` must own `m` to consume the reply in it, and a function type has no body to infer A1 from. *Recommendation:* a function type marks an owned resource parameter; a call through it moves the argument. The spelling is open. *Prior art:* Swift `(consuming T) -> U`.
40. **Generic types with row parameters (A6).** `actor.Reply[T, E]` and `actor.Actor[M, E]` carry an error row as a type parameter, and `Reply[int64]` should mean an empty row. *Recommendation:* a generic type may take row parameters, and an omitted trailing row argument is the empty row. [types.md](types.md#generics) rule 3 covers only rows that pass through.
41. **Failures as values (A7).** A library that carries a typed failure from one task to another, as a reply does, needs a value form of an outcome. *Recommendation:* a prelude `Exit[T, E]` with `Succeed(v)`, `Fail(e)` and `x.Get() T fails E`. *Prior art:* Effect `Exit`; Gleam `Result`. A function literal that returns the failure works under the current rules, at one closure per value.
42. **Release of a value typed by a type parameter (A8, lowering performance).** Generic code that owns a value of type `M` must release it when `M`'s instantiation is a resource. *Recommendation:* the checker treats such a value as possibly a resource. The lowering may test for `Close` on cold paths; a hot path needs per-type release passed through the generic dictionary or an argument, measured under lowering performance. A `Close` test finds only a value that implements `Close` itself, so the same gap covers general drop glue: a struct with a resource field (R1) and a slice, array or map of resources (R34, R37) are resources with no `Close` of their own, and the compiler must generate their release, each field in reverse declaration order and each element, with every remaining release run after a defect, under the releasing task's masked boundary. The Actor projection prototype hand-writes it only for its own message envelopes and pins the other shapes as unreleased (the note's Q2). Status (L8 B2): the generated release of structs, tuples, unions, `Option`, slices and `Map`s is **implemented**; the release of a value typed by a type parameter is not, so a generic body that drops a value of its own type parameter (`[T own]`) is S108 at the drop.
43. **The result of `Task.Stop` (A9).** [runtime.md](runtime.md#tasks) Tasks rule 4 does not say what `Stop` returns. `runtime/rt` returns defects only and drops the typed failure of a task that ended before the stop, which `actor.Actor.Stop() fails E` needs. *Recommendation:* `Stop` returns the task's typed failure when the task ended with one before the stop, and its defects; the interruption it caused is dropped. *Status:* closed as built (decision D9): `actor.Actor.Stop() fails F` returns the typed failure of a runner that ended with one before the stop (batch 13); `Task.Stop` keeps [runtime](runtime.md#tasks) Tasks 10.
44. **Escaping function parameters and shared handles by structure (A10).** [types.md](types.md#function-values) rule 2 says a function parameter is non-escaping "unless its type says otherwise", with no spelling; `actor.Start` and `tasks.Set.Go` keep their function. [runtime.md](runtime.md#tasks) Tasks rule 6 and R1 name "actor handles" among shared handles and resources. *Recommendation:* spell the escaping mark in the function type, and make sharing structural: a value whose fields are all synchronised handles copies into tasks. An actor's owner handle is a resource because it holds a `Task`, with no name in the rule.
45. **The copy at a task boundary (A11).** [runtime.md](runtime.md#tasks) Tasks rule 6 says values copy into a task, and [types.md](types.md#structs) Structs rule 6 says a copy is a snapshot. Neither says what the Go lowering emits for a slice or a map, which Go shares by reference, or where the copy happens when a value leaves a task through a channel, a reply or a callback result. *Recommendation:* every value that crosses a task boundary (a capture into `go`, a channel send, an actor message, a reply, an agent result, a machine snapshot) is a copy that shares no mutable storage: the lowering clones each reachable slice and map, per static type, and emits nothing for a type with none. Move on last use skips the clone. A resource moves and is not copied. The historical actor library spike applied the rule at run time with a cached per-type plan; its measured cost is in the note's Q8.
46. **The type of a machine value (A12).** *Status: implemented as recommended (V2 machine-run): the prelude `Machine[S, E, O, F, R, W]` record with `Initial` and `Step`, an implicit conversion from a machine declaration's value ([types.md](types.md#assignability) Assignability 6), and std `machines` ([runtime.md](runtime.md#machines-and-actors) 8). A generic record with row parameters already checks and lowers, which covers the Gap 40 part this needs.* [runtime.md](runtime.md#machines-and-actors) item 1 declares `type X machine[S, E] { initial: v, step: f }` with two type parameters, so a function that takes any machine cannot name the step's output `O`, failure row `F` or requirement row `R`. *Recommendation:* a machine declaration's value has the prelude type `Machine[S, E, O, F, R, W]`, a struct with `initial S` and `step func(S, E) Decision[S, O] fails F needs R`; `O`, `F` and `R` are read from `step`'s signature. This needs Gap 40 extended to `needs` row parameters, and a function-typed field whose `needs` row is charged where the value is built (Gap 17's constructor capture).
47. **A boundary releases a successful result it discards (A13, lowering performance).** *Status:* built for checked tasks and releasing combinators (L8 B3t, B4), and the explicit Go scope boundary (B5). A task keeps a value its body returned past stop-wins, and its owner's release or a `Wait` takes it exactly once (`Task.Drain`). `timeout.After`, `tasks.Race` (its losers) and `tasks.Transform` (finished results when another call fails) release dropped values through hidden result glue ([stdlib](stdlib.md) Hidden arguments 7). A function frame keeps a returned owned local until its exit succeeds (B1, `Returned`). `rt.Scoped(t, release, body)` releases a successful body's result when scope shutdown fails, masked, preserving release defects. No zero or candidate value from a failed body is released. Bare `rt.Run` and deferred `Scope.End` do not transport result glue: Go callers must retain ownership or use `Scoped`. The std machine actor refuses resource-bearing state, signal and decisions in v1 because retained decisions alias replies ([resources](resources.md) R44). Tests: `TestScopedResultReleaseModel` (runtime/rt), `TestStopWinsReleaseModel` (runtime/v1), `TestTaskOwnershipRunModel` (lower, mode 9), and `docs/research/ownership/main.ergo` (mutant `StopWinsDrops`).

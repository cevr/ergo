# Inserted operations

Status: **the inventory is normative; the rule is checked by a property for the rows marked "elaborated"** (G9, unit INS-ops, 2026-11-12). Owners of the open rows are named in the last column.

An [inserted operation](../../GLOSSARY.md) is one the compiler adds where the source names none: a release at a scope end, the adapter of a conversion, the by-name calls of a codec, the instance of a generic body. Each one stands for a [written form](../../GLOSSARY.md).

## The rule

1. **One rule for written and inserted forms.** An inserted operation carries every rule of the written form it stands for: its rows (`fails` and `needs`, charged to the frame where it runs), its ownership (moves, lends, takes, releases), its borrows (no escape, no overlap) and its task confinement. A program whose inserted operations are written out by hand gets the same verdict and the same rows from the checker. *Principle:* no side table may type an inserted operation more loosely than the checker types its written form (audit 3, G9: REL-needs, BORROW-conv, G3 and G4 were each an inserted operation typed by its own table).
2. **Elaboration.** Where a written form exists, the property `TestInsertedOpsAgree` (`internal/sketch/check/inserted_ops_test.go`) holds the rule. Each seed writes a program of sites, one inserted operation in each function `sN`. An elaboration rule (one per row marked "elaborated" below) writes the same site with the operation spelled out. The checker reads both programs; the set of diagnostic codes in each site's lines (the verdict: a refusal reported at two places of a written copy is one verdict) and the inferred rows of each `sN` must be equal. A disagreement that the property's gap list (`insertedGap`) does not name fails the test, with the seed, both forms and the replay command; a named gap that no longer occurs fails it too, so the unit that closes a hole removes its line. `-insops.survey` prints every disagreement and fails on none.
3. **No written form.** An inserted operation with no written form is listed below with the reason, and with the property or rule that holds it instead.
4. **A new inserted operation** gets a row here and, when it has a written form, an elaboration rule in the property, in the unit that adds it.

*Prior art:* Rust elaborates drops into MIR `Drop` terminators before the borrow checker runs, so inserted and written drops are checked alike; Koka's Perceus inserts `dup` and `drop` as ordinary core calls; Swift's SIL ownership verifier runs after inserted copies and destroys. Gleam's `use` and Elixir's macros expand to ordinary code before checking, and ReScript's `@spice` emits plain functions. Effect has no inserted operation: every finalizer is a value the program writes. Elaborate-then-check is the common answer; Ergo checks inserted operations by their own tables, so this property compares those tables with the checker's rule for the written form.

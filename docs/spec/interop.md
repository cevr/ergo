# Go interop: `import go`, bindings and adapters

This file is the v1 specification of Go imports. It replaces the retired pre-v1 interop design, now deleted. The plan with its owner answers (q32 to q38, 2026-11-08) is the wf10 import-go plan; the rules below are its §1 and §2. Terms (Go import, Host package, Ambient) are in the [glossary](../../GLOSSARY.md).

Status: **implemented** per section: **Binding files** and **Type mapping** are implemented by `ergo bind go` (`internal/gobind`, IG1), and the bindings of Go's standard library are embedded (`internal/sketch/std/gostd`). **Checking** is implemented (IG2): the checker reads the bindings, and a binding declaration in user source stays S109 (only a binding declares one). **Lowering** is implemented (IG3): Level 1 calls are direct Go calls. **Level 2 adapters** are implemented (IG4): a user extern names a binding's function and is checked against it. **Go modules** are implemented (IG7): go.mod and go.sum beside ergo.mod, stamped bindings under ergo.bind/. **Host calls** are implemented (IG10): a hidden `context.Context` that interruption cancels. **Go calls Ergo** is implemented (IG11): `ergo lib` exports a library's functions to Go, and an Ergo value converts to a Go interface.

## Two levels, one mechanism

1. **Level 1.** `import go net/url` makes every exported declaration of the Go package usable, with no declaration written by the user. The checker reads the package's **binding** (below): an Ergo file that `ergo bind go` generates from go/types.
2. **Level 2.** A user `extern go P.F func name(sig)` whose written signature is an **adapter** of the Level 1 signature, checked against the binding ([grammar.md](grammar.md#declarations), Declarations 2; IG4).
3. An ordinary Ergo function over Level 1 calls maps `go.Error` to a closed union with a `catch`. No construct is added for error mapping.

*Prior art:* Borgo writes committed declaration files from Go source; Swift's Clang importer imports headers automatically and reads API notes for the facts headers lack; Gleam and ReScript bind one host function at a time with a trusted, written type. Ergo imports automatically (Level 1) and checks a written type against the binding (Level 2), so neither level is trusted.

## Which Go declarations import

| Go declaration | Ergo form |
| --- | --- |
| exported function | `extern go P.F func F(sig)`; a call `url.QueryEscape(s)` |
| generic function, each constraint `any`, `comparable`, `cmp.Ordered` or a core type `~[]E` or `~map[K]V` | `func F[E ordered](…)`; a parameter with a core-type constraint is replaced by its core type (`slices.Sort[S ~[]E, E cmp.Ordered](x S)` is `func Sort[E ordered](x []E)`). Any other constraint is refused. An unconstrained type parameter before a constrained one is refused, because Ergo's `[A, B comparable]` constrains both. |
| variadic function `...T` | the parameter is `[]T` and the binding marks the function `// ergo:variadic`; the lowering spreads it (`xs...`) |
| function or method whose first parameter is `context.Context` (outside package `context`) | the parameter is hidden and the binding marks the declaration `// ergo:context`; the call passes the calling task's context and is foreign (Host calls) |
| method of a named non-interface type, promoted ones included | `extern go P.T.M func (r T) M(sig)` when the method is in the method set of `T`, `(r *T)` when only `*T` has it |
| exported named type | `extern go P.T type T …` (Type mapping) |
| constant | `extern go P.C let C T`: a typed constant keeps its type; an untyped one takes Go's default type when its value fits (`math.Pi` is `float64`), and is refused otherwise (`math.MaxUint64`): Ergo has no untyped constants (196u) |
| variable of type `error` (`io.EOF`) | `extern go P.V let V go.Error`, a sentinel for `go.Is` (IG5) |
| variable whose type has `Close()` or `Close() error` | a read-only, borrowed resource (Resources 4); a pointer variable is `Option[go.Ref[T]]`, since it may be nil |
| variable of `runtime/v1.GoReadOnlyVars` (`base64.StdEncoding`, `crc32.IEEETable`, `time.UTC`, `os.Args`) | `extern go P.V let V T`, read-only; a pointer is `go.Ref[T]`, never nil (Go package variables) |
| any other variable | refused: "a Go variable is host state; call a function" |
| generic named type | refused, except `iter.Seq[T]`, which is the prelude `Seq[T]` |
| alias declaration | refused; a use of the alias maps the type it stands for |
| unexported declaration, a package under `internal` or `vendor`, `unsafe`, `builtin`, `C` | not bound |

A declaration that does not map is listed in the binding with its reason, so the diagnostic comes at its **use**, never at the import: one unmappable function does not block its package.

## Type mapping

| Go type | Ergo type | Rule |
| --- | --- | --- |
| `bool`, `string`, the integer, float and complex types, `byte`, `rune` | the same basic type | direct |
| `time.Duration` | `duration` | direct; its methods bind as functions of the receiver, `time.DurationString(d)` (Methods of Ergo's own types) |
| `uintptr`, `unsafe.Pointer` | none | refused |
| named type defined over a basic type | the host type, nominal | `extern go io/fs.FileMode type FileMode uint32` |
| `[]T` | `[]T` | value rule (types.md Values): copied at the call unless fresh or dead (Lowering 2-3) |
| `map[K]V` | `Map[K, V]` | as `[]T` |
| `[N]T` | `[N]T` ([types.md](types.md#arrays)) | Go copies an array whole, so it crosses with no copy; an array whose elements hold a slice or a Map (`[2][]int`) is refused: v1 copies no element at the boundary (batch-14) |
| `*S`, `S` a named non-interface type, as a parameter | `*S` | a borrow (types.md Borrows); a `go.Ref[S]` is accepted too (q38) |
| `*S` as the one result beside a last `error`, proven non-nil | `go.Ref[S]` | `ergo bind go` proves from the Go source that every return gives a non-nil pointer or a non-nil error, through the helpers and methods it calls (`gobind/nonnil.go`; GOBIND-NIL, GOBIND-PROVE), by a forward flow over each body: a nil check that returns, a dereference (`x.f` panics on a nil `x`), a named result's last value, an error carried across branches (`time.LoadLocation`'s `firstErr`), loops and gotos (`gobind/nonnil_flow.go`; GOBIND-FLOW), a range over a slice, map or string `len(x) == 0` ruled out runs at least once (`template.ParseFiles`; GOBIND-LOOP). A non-nil error includes Go's typed nil: a value of a concrete type, `syscall.EINVAL`, `KeySizeError(k)`. Ergo writes no Go package variable, so a pointer variable no Go function assigns (`time.UTC`) counts as set once. |
| `*S` as the one result beside a last `error`, unproven (an interface method, a function value's call, `return nil, nil`) | `Option[go.Ref[S]]` | nil with a nil error is `None`: `http.ProxyFromEnvironment` returns `nil, nil` for a request that takes no proxy |
| `*S` as another result or a field | `Option[go.Ref[S]]` | nil is `None` |
| `*S` in an element, a Map value or a callback result; a pointer to an unnamed type or an interface | none | refused: a pointer there may be nil, and v1 maps a pointer only as a parameter, a result or a field |
| named struct `S` | `extern go P.S type S { Field T, … }` | the exported fields of mappable type, **read only** (q34); a field that does not map is listed refused |
| named interface `I` | `extern go P.I type I { M(sig), … }`, an operation type | its exported methods; an interface with no exported method, an empty one and a constraint interface are refused |
| `error` | `go.Error` | the native error crosses unchanged |
| last result `error` | the row `fails go.Error` | the other results are dropped on failure |
| `any`, `interface{}` | `go.Any` | [Go any](#go-any) (GB2): a value with a Go form goes in, `go.Any` keys no `Map` |
| an unnamed non-empty interface or struct | none | refused |
| `func(…) …` parameter, or a parameter of a named Go function type (`fs.WalkDirFunc`) | an Ergo function type without parameter names, of the underlying signature | a callback with one result at most: the call's rows when synchronous, else `own` ([Callbacks](#callbacks)) |
| `func` result, field or element; a function inside a callback | none | refused |
| `chan T` | none | refused: "Ergo has no channels (196c); wrap the Go channel in a Go function of your module, or use std queue" |
| several results without `error`, `(T, bool)` included | a tuple | `(T, bool)` stays a tuple: `strings.CutPrefix` returns a meaningful value when the flag is false |
| named type defined over an array | `extern go P.T type T [N]E` | as `[N]T` |
| named type defined over a function, a channel or a pointer | none | refused |

A Go pointer is never Ergo's `*T` outside a parameter: `*T` is a borrow everywhere, Go types included, and a stored or returned Go pointer is the distinct handle type `go.Ref[T]`, opaque and never nil (owner q32 and q38: "consistency is important").

### Go values by address

GBX1, 2026-11-16. `go.New[T]()` is Go's `new(T)`: a fresh zero `T`, held by its address as a `go.Ref[T]` (`check/gonew.go`). It is how Ergo source holds a Go value whose methods have pointer receivers and which Go forbids to copy once used:

```
import go sync
import go sync/atomic

type Counter { mu go.Ref[sync.Mutex], n go.Ref[atomic.Int64] }

func NewCounter() Counter needs go.Foreign {
	Counter{mu: go.New[sync.Mutex](), n: go.New[atomic.Int64]()}
}
```

1. **T** is a Go type of import go that is no interface (Go has no value of one) and no resource (a zero file or connection is not open, and its release would run on nothing; take a resource from the Go function that opens it). An Ergo type, a basic type, `go.Any` and a `go.Ref` are refused, S108 "go.New[T]: …".
2. **Sharing.** Copies of the `go.Ref` share the one Go value, as Go's pointers do: `c.n.Add(1)` through any copy writes the same `atomic.Int64`. A method with a pointer receiver is called on it as on any `go.Ref` (Checking 3), and lends it (Resources 5).
3. **Rows.** Its value has identity, which a pure frame may not create, since a pure call may be evaluated once for two uses: the call is opaque in its frame's footprint, as a memory-only call is. It charges `go.Foreign` when `T` reaches a Go type with a host-touching method, a method whose binding charges `go.Foreign` or any method of a Go interface, through the structure rule 8 walks (GBX1b, 2026-11-17; `goTouchesHost`). A `T` whose reachable methods are all memory-only rows ([Purity and authority](#purity-and-authority)), as `sync/atomic.Int64`'s and `Bool`'s are, or that has none, is made with no row, as its methods are called with none: std's `atomic.NewInt64` is called from laws and tests. `go.New[sync.Mutex]()` still charges `go.Foreign`, because `Lock` waits. A method promoted from an embedded field is bound with no row of its own, so it touches the host (follow-up: carry the row of the method it promotes). `TestGoNewChargesOnlyHostTouching` (check) is the property, over rule 8's seeded shapes against a reference model.
4. **Lowering.** `new(T)`, nothing else. `TestGoNew` (lower) is the property: each target admitted or refused as the rule says, the admitted ones called through a copy and a record field and type-checked as Go.

*Prior art:* Gleam and Elixir reach a mutable host cell only through the host (`:atomics.new`, an ETS table, a process), never as a language value; ReScript's `ref` and OCaml's `Atomic.make` are a heap cell with identity, as here. Effect's `Ref.make` is an effect for the same reason as the `go.Foreign` charge: allocation of identity is not pure. Each lowers to the host's own allocation.

**Set at construction** (GBX5b, 2026-11-16). `go.New(v)` is a `go.Ref[T]` to a new Go `T` holding a copy of `v`. It is how Ergo source sets a Go struct's fields, since they stay read-only after it (q34). `go.Zero[T]()` is Go's zero `T` as a value. It is the explicit base a literal of a Go struct spreads from, because a literal names every field (owner q44: every field value comes from a site that named it):

```
let sys = go.New(syscall.SysProcAttr{..go.Zero[syscall.SysProcAttr](), Setpgid: true})
let mut attr = os.ProcAttr{Dir: "", Env: []string{}, Sys: Some{Value: sys}}
let p = try os.StartProcess("/bin/sh", argv, &attr)
```

5. **T** follows rule 1, for both. `go.New(v)` also refuses a `T` that holds a slice or Map through its fields (S108 "go.New(v) of os.ProcAttr: its field Env holds a slice or Map that an Ergo value may share …"). Go could write such a slice through the `go.Ref`, and an Ergo value could share it. A `go.Ref` field is Go's memory already and is admitted.
6. **Rows.** `go.New(v)` charges as `go.New[T]()` does (rule 3). `go.Zero[T]()` is a value with no identity, and charges nothing.
7. **Lowering.** `n := v` and `&n` for `go.New(v)`, which is hand Go's `&T{…}`; `*new(T)` for `go.Zero[T]()`. A spread from it is a copy and one store per named field (types.md, Structs 3). `TestImportGoRuns` (lower) starts a child with `Setpgid` set and checks that it leads its own process group.
8. **One task** (GB-RACE, 2026-11-16). A memory-only method ([Purity and authority](#purity-and-authority)) needs no `go.Foreign`, so any task may call it, and `math/rand/v2.PCG.Uint64` writes its two state words with no lock. A Go type is therefore confined when it reaches a Go type with a memory-only method that `v1.GoConcurrentTypes` does not list (GB-RACE2): the type itself, or any field, embedded field, slice or array element, Map key or value, pointer (`Option[go.Ref[U]]`) or `go.Ref` reachable through its structure as its binding shows it. A listed type stops the walk, and a Go interface's methods are foreign. A `go.Ref` to a confined type, and a confined Go value itself, are confined to the task that holds them, by the provider cell's rules ([types.md](types.md), Interface assignability 6; `check/goconfined.go`): no escaping function literal or block (a `task.Go` body) captures a value that holds it, no type argument (a queue, a `sync.Ref`, a `Task`, a generic body) carries it, no package `let` holds it, and it converts to no Ergo operation type. Each is S108 "p holds go.Ref[rand.PCG], whose Go value's memory-only methods are not safe for concurrent use, so it is confined to the task that made it, …". Three cases are admitted. An `Option` or `Some` holds it where these rules still see it (`NewPCG`'s result is an `Option[go.Ref[PCG]]`). A Go interface argument (`rand.New(src)`) takes it, since only a `go.Foreign` call reaches it there. A type of the reviewed table `v1.GoConcurrentTypes` (`sync/atomic.Bool`, `Int64`), whose methods are safe for concurrent use, is not confined. `TestGoConfinedRefs` (check) holds each clause, and `TestGoConfinementReachesThroughShapes` is the property: seeded Go struct shapes (fields, pointers, slices, arrays, Maps, embedding), bound by `ergo bind go`'s own generator, against a reachability model. *Prior art:* Rust's `ThreadRng` is `!Send`, so `thread::spawn` refuses a closure that captures one, and `AtomicU64` is `Sync`. Swift refuses a non-`Sendable` class across an isolation boundary. Go documents `PCG` as unsafe for concurrent use and leaves the race to `go test -race`. Erlang's `:rand` keeps its state in each process's dictionary.

## Purity and authority

Each call's row comes from the reviewed tables of `runtime/v1`, never from the Go signature:

| tier | which Go | row |
| --- | --- | --- |
| reviewed pure | a package of `v1.PureImports`, minus the members of `v1.PureImportsExcept` | none; transparent in footprints (q35) |
| memory-only | a function or method of a row of `gofacts.Effects` whose guard line acts (GBX6) | none; not pure: opaque in footprints |
| host | a function of a row of `gofacts.Hosts` whose guard line acts (HOST-ROW) | `needs Ambient`; not pure |
| foreign | every other Go function, method and interface method | `needs go.Foreign` |

A memory-only call (np4f-plan GBX6) reads or writes memory its arguments reach and nothing else: an atomic cell (`sync/atomic.Int64.Add`, `Bool.CompareAndSwap`), a generator's state (`math/rand/v2.PCG.Uint64`, `NewPCG`, `PCG.Seed`). It reads no host state, needs no capability and never waits on another goroutine (its wait kind, in `ergo inspect`, is `none`; its tier is `memory`), so its binding has no row and a test may call it; it is not pure, so its call is opaque in a footprint and no pure frame or law treats it as a function of its arguments. `ergo bind go` writes it `// ergo:effect none (vouched: <reason>)` above the declaration, only on its row's guard line current and validated (Foreign facts 7); the checker reads the line back, and a missing, stale or refuted guard line is S108 at the binding ("math/rand/v2.PCG.Uint64 is bound as memory-only without a reviewed row that acts (…)"). A call that waits (`sync.Mutex.Lock`, `WaitGroup.Wait`) or reads the process (`os.Getpid`) stays foreign. A method Go promotes from an embedded field is the field's own method, so it takes the row of the type that declares it (GB): `type Counter struct{ atomic.Int64 }` binds `Counter.Add` with `// ergo:effect none from sync/atomic.Int64.Add (vouched: <reason>)`, and the checker reads the row of the `from` target, which must be a method of the same name (else S108 at the binding). A method of the outer type that hides the promoted one has no row and stays foreign.

A host call (HOST-ROW, from std-priv NP4f-6) reads the host process's own state and nothing else: its environment (`os.Getenv`, `os.LookupEnv`, `os.Environ`), its working directory (`os.Getwd`), its clock (`time.Now`), its files at a path it resolves against the working directory (HOST-ROW-2: `os.ReadFile`, `os.WriteFile`, `os.Mkdir`, `os.MkdirAll`, `os.Remove`, `os.RemoveAll`, `os.Rename`, `os.Readlink`, `os.Chmod`). It keeps nothing of its caller's, returns values the caller owns and no open file but the one it opens for its caller, leaves no goroutine and takes no callback. Open files are host rows too (HOST-ROW-3 slice 2): `os.Open`, `os.Create` and `os.OpenFile` return the new handle, a `go.Ref[os.File]` its owner closes, and the handle's `Read`, `ReadAt`, `Write`, `WriteString`, `Seek`, `Close`, `Name`, `Sync` and `Truncate` read or change the file of that handle only, so a read loop needs `Ambient` and no `go.Foreign`. So do `WriteAt`, `Chmod`, `Chown`, `Readdirnames` and the three deadlines (S2-FILE); `Chdir` changes the working directory, the host state `os.Getwd` reads, and so do their path forms `os.Chdir`, `os.Chown` and `os.Lchown` (host rows; the guard tells `Lchown` from `Chown` by a link to a missing file); `Fd` and `SyscallConn` stay refused, and `ReadFrom` and `WriteTo`, which call an `io.Reader` or `io.Writer`, stay `go.Foreign`; their guard (hostguard, handles.go) opens by relative path in each host state and checks a method on a handle opened by absolute path, reading the outcome back through other calls, and checks that `Read` and `ReadAt` write only `b[:n]` and keep no reference to `b`. A file row's guard runs each call with relative paths in each of the guard's two host states, whose working directories hold different fixtures, and reads the outcome back through Go calls other than the row's. A file's metadata is a value (HOST-ROW-3): Go's `os.Stat`, `os.Lstat` and `os.ReadDir` return `fs.FileInfo` and `fs.DirEntry`, interfaces any Go type may implement, so `ergo bind go` binds them to the toolchain's plain Go package `runtime/v1/hostfs` (`gobind.ValueResults`), whose `Stat`, `Lstat` and `ReadDir` call os's and copy the result's values, read once on the implementation os returns, into structs the caller owns: `hostfs.Info { Name, Size, Mode fs.FileMode, ModTime time.Time, IsDir }` and `hostfs.Entry { Name, IsDir, Type fs.FileMode }`. Reading one is a field access, so no row vouches for an interface method; the three are host rows of hostfs, reviewed and guarded as any Go function's are, with no trust line and no exception for the toolchain's own package, and std's binding of `os` and a user's are the same. An open file's metadata is the same value (S2-FILE-B): `(*os.File).Stat`, `ReadDir` and `Readdir` bind as the methods themselves, `func (f *File) Stat() hostfs.Info`, `ReadDir(n int) []hostfs.Entry` and `Readdir(n int) []hostfs.Info`, each `fails go.Error needs Ambient`, whose extern target is a Go function that takes the receiver first, not a method: `extern go ergo.local/prototype/runtime/v1/hostfs.FileStat func (f *File) Stat() …` is called as `hostfs.FileStat(f)`. hostfs's `FileStat`, `FileReadDir` and `FileReaddir` call the method once on the handle and copy its values, keep no handle (their receiver is lent, `v1.GoArgClauses`), and are host rows with guards as the three above. So an extern method's target in a binding is `path.Type.Method`, or `path.Func` of a Go function whose first parameter is the receiver. A `fs.FileInfo` that really is another Go type's (a zip archive's) stays an interface whose methods need `go.Foreign`. The values' own methods that compute on the value alone are memory-only rows (HOST-ROW-3b; Foreign facts 7): `fs.FileMode`'s `IsDir`, `IsRegular`, `Perm`, `Type` and `String`, and `time.Time`'s instant methods `Unix`, `UnixMilli`, `UnixNano`, `IsZero`, `Before`, `After`, `Equal`, `Compare`, `Sub`, `Add` and `UTC`, so reading them needs no capability. Their guard draws times in `time.Local`, whose zone the guard's two host states differ in, so a method that reads the zone (`Year`, `Hour`, `Format`, `In`) is not a row and still needs `go.Foreign`. A call that returns or keeps an open file (`os.Open`, `os.Create`), and a method of `fs.FileInfo` or `fs.DirEntry` (an interface method, which a row would vouch for in every implementation), stays `go.Foreign`. Ambient is the authority to choose the host ([stdlib](stdlib.md), Host packages), so its binding charges `needs Ambient` in place of `go.Foreign`: `ergo bind go` writes `// ergo:effect ambient (vouched: <reason>)` above it and `needs Ambient` as its row, only on its row's guard line current and validated (Foreign facts 7). The checker reads the line back; a missing, stale or refuted guard line is S108 at the binding ("os.Getenv is bound as a host call without a reviewed row that acts (…)"), and so is a binding that writes `needs Ambient` for a Go function with no host line ("os.Unsetenv is bound with needs Ambient and no host line: only a host row of internal/gofacts charges Ambient for a Go call (…)"). A provider whose operations call a host function captures Ambient where it is built, as one that calls other Go captures `go.Foreign` ([types.md](types.md#capabilities) Capabilities 4): `with context { Env: Real }` in a main that lists Ambient. The row is Go's function's, not std's: std's binding of `os` and a user's `ergo bind go os` write the same line, and a user's provider package that calls `os.LookupEnv` is checked exactly as std's `os.Host` would be. `go.Foreign` is given only by the entry, `func main() needs … | go.Foreign`; a test never gets it (q33). No user source asserts a trust fact in v1 (q36).

## Binding files

1. **Form.** A binding is an Ergo source file. The root of the tree `ergo bind go` writes (a module's `ergo.bind`, the embedded `gostd/src`) holds its marker `ergo.gen` (`kind bind`, the digest of every file under it; [api.md](api.md)), by which the formatter and the comment pass leave the tree to its generator. Its first line is `// Code generated by ergo bind go; DO NOT EDIT.`, its second `// ergo:bind <import path> <go1.N> <platforms>`. Then the imports of the Go packages its signatures name, by their Go package name: `import go io`, and an alias when the package name is a keyword or taken (`import go gocontext context`).
2. **Entries.** Each exported Go declaration is one entry, in name order, each type followed by its methods. An entry starts with `// ergo:go <Go declaration>`. A mapped entry follows with `// ergo:context` when its first Go parameter is a hidden `context.Context`, `// ergo:variadic` when the function is variadic, `// ergo:reads <binder>…` when it carries derived `reads` facts ([Foreign facts](#foreign-facts)), `// ergo:writes <binder>` when Go writes that slice in place ([Go writes in place](#go-writes-in-place)), then its declaration: `extern go <target> func …`, `extern go <target> func (r T) M…`, `extern go <target> type T …` or `extern go <target> let C T`. A refused entry follows with `// ergo:refused <Name>: <reason>`; `<Name>` is `T.M` for a method or a member. These comment lines are a fixed form the checker and `ergo inspect` read.
3. **Grammar.** The binding declarations extend `ExternDecl` ([grammar.md](grammar.md#declarations)): `"extern" "go" import_path "." identifier ( "func" [ "(" identifier Type ")" ] … | TypeDecl | LetDecl )`. Only a binding declares them; in a user package each is S109 until Go interop's checking reads them.
4. **Generator.** `ergo bind go [-o DIR] PACKAGE…` runs `go list -deps -export -json` and reads the export data with `go/importer`; it is the only code that runs Go tools for signatures. With `-o` it writes `DIR/<import path>/<last element>.ergo`. Inside an Ergo module, without `-o`, it writes them under the module's `ergo.bind/` (Go modules 2); outside one, it prints them.
5. **Platforms.** A generated binding holds for darwin/amd64, darwin/arm64, linux/amd64 and linux/arm64 with `CGO_ENABLED=0`, the target list of `ergo build` ([tooling](../tooling.md#platforms)). A declaration missing on one, or with another Go text or Ergo text there, is refused "platform-specific". The one exception is a struct that every platform declares but with different fields (GBX5, 2026-11-16: `syscall.SysProcAttr`, `Stat_t`, `Timeval`). It binds with the fields every platform maps to the same line, and each other field is a refused member: "platform-specific: Go declares it only on linux/amd64, linux/arm64" (`Pdeathsig`), or "its Go declaration differs by platform". A Go literal of such a struct leaves those fields at Go's zero, as it does any refused field. For each module binding the program imports, including through another package or binding, checking requires the selected target to be an exact platform in its `// ergo:bind` header. A missing header or an absent target is S104 at the import: the diagnostic names the Go package, its stated platforms (or none), the target and the repair command. The build stops before it emits or links anything. Until DIST1 the list was darwin/arm64 and linux/amd64 only, and 25 `syscall` constants (`SYS_OPEN`, `TCP_KEEPCNT` and others) that linux/arm64 does not declare checked and then failed the Go link there. An old two-platform binding still checks for either stated platform; `ergo bind go <package>` regenerates it in place for all four. The phone platforms of the target list (ios/arm64, android/arm64, android/amd64; `gobind.Phones`) have no bindings of their own. Each checks against the bindings of the platform that Go's build constraints read it as: GOOS=ios satisfies the `darwin` tag, so ios/arm64 checks against darwin/arm64, and GOOS=android satisfies `linux`, so android/arm64 and android/amd64 check against linux/arm64 and linux/amd64. Every file a binding's package builds for that platform also builds for the phone. A declaration that only a file constrained to `ios` or `android` (or to `!ios`, `!android`) holds or changes is not seen by the binding. The phone compile of the emitted module is the check for that (`TestPhoneModuleTypechecks`), not the binding. Bindings are not generated for the phones themselves: `go list -export` of a host's Go packages for a phone needs cgo there (MyGo's purego and phone glue), and a binding is typed with cgo off. A phone program is linked with cgo by its packager, which uses cgo builds of `net` and `os/user` whose exported API is the cgo-free one.
6. **Go's standard library.** The compiler embeds the bindings of every standard-library package outside `internal` and `vendor` (and outside `builtin`, `unsafe` and the cgo and sanitizer runtimes) at its toolchain `go1.N`, made by `go generate ./internal/sketch/std/gostd`. `TestGoStdBindingsMatchToolchain` regenerates them and compares. The checker reads them as files and runs no Go tool.
7. **Third-party and local packages** get committed bindings under `<module root>/ergo.bind/<import path>/` and a plain `go.mod`/`go.sum` beside `ergo.mod` (q37; IG7; see Go modules below). Such a binding has a third line, `// ergo:module <module> <version>`, with ` => <replacement> [<version>]` when go.mod replaces the module, or `// ergo:module <module>` for a package of go.mod's own module.

8. **Closed.** A declaration that names a refused type, of its package or another, is refused too ("it names the refused type syscall.RawConn"); a struct field or an interface method that names one is a refused member, and the type keeps its other members. A use of a prelude type (`Map`, `Seq`, `Option`) is refused in a package that declares a type of that name, which would hide it (`go/types.Map`). So every binding checks clean; `TestGoStdBindingsCheckClean` resolves every declaration of every embedded binding.

## Checking

1. **Import.** `import go P` reads P's binding: Go's standard library's (embedded; a standard-library path always names it), else the module's own at `ergo.bind/<P>/<last element>.ergo`. A path follows Go's rule (`module.CheckImportPath`): `github.com/0xAX/x` is a path. No binding is S104 at the path, with the `ergo bind go` command. The name the import binds is the Go package name: the last element, or the one before a major-version element (`math/rand/v2` binds `rand`). One program shares one set of Go packages, so a host type has one identity.
2. **Lazily, per declaration.** The import reads nothing. The first use of a member parses the binding and resolves that member only; a host type's underlying type resolves when it is first read. A program that imports no Go package reads no binding. The checker never runs a Go tool.
3. **Uses.** A call, a constant, a type, a method (Go's method set) and a read-only field check by the binding's declaration. A method in the method set of `*T` only is called on a `go.Ref[T]` or a borrow, not on a copy (S109). `go.Ref[T]` reaches T's fields and methods; a borrow `*T` is accepted where Go takes `*T`, and is never kept as a `go.Ref` (S108). A Go interface is a host type, not a capability. When a Go value is checked against a Go interface, a [written slice](#go-writes-in-place) returned to Ergo callers is not part of the Go method's results. The failure, capability and ownership checks still use the binding's contracts. A declaration the binding refuses is S109 at its use, with the binding's reason.
4. **Rows.** The binding's rows are the call's: `fails go.Error` when Go's last result is `error`, `needs go.Foreign` outside the reviewed pure list (Purity and authority). A field read through a `go.Ref` or a borrow, and a read of a borrowed resource package variable, charges `go.Foreign`, since Go code may write that memory. The exception is a **fresh handle** (NP4f-URL, 2026-11-18; `check/gofresh.go`): a `go.Ref` that a call of a pure-tier Go function or method (one whose binding needs nothing) returns, bound by an immutable `let` and used in its frame only as the operand of a field read or a method call, outside any function literal. No Go code but the pure-tier methods the frame calls on it can reach it, so a field read through it charges nothing: `let u = try url.Parse(raw)` then `u.Scheme`. Passing the handle on (an argument, a result, a stored or captured value), a `let mut`, or a handle from an Ergo function or a foreign Go call leaves every field read through it charged (`TestGoFreshRefFields`). Every function that charges `go.Foreign` writes it in its row (S102); only the entry provides it ([rows.md](rows.md), Entry 4), so a test never calls foreign Go.
5. **A wrong binding.** A binding that does not check (an edited or stale file) is S108 at the import, with the first diagnostic and the command that regenerates it.
6. **A carried package** (S-tz; owner q107). A Go package whose binding declares nothing has no name to use: its only effect is its initialization. Go's `time/tzdata` is one: it registers Go's copy of the zone database, which `time.LoadLocation` reads after the host's own sources. Its import is its use, so `import go time/tzdata` is not S110. It stands only in the package of `main`, which makes the binary: the program's entry decides what its binary carries, as it decides which providers it binds. Anywhere else it is S108 at the import, "Go package time/tzdata declares nothing; it is carried into the binary for its initialization, and only the package of main, which makes the binary, carries it", because the data would enter every binary that imports the package, unseen at its entry. This is not a general side-effect import: a package with any declaration still needs a use (S110), and an alias, `_` included, is still S108 ([grammar.md](grammar.md#declarations), Imports 1). The checker reads the binding only for an import no use marked, so the import stays lazy. `Info.Carries` lists the carried paths; [stdlib.md](stdlib.md#build-time-assets) 5 states the cost. *Prior art:* Go's blank import `import _ "time/tzdata"` and the `timetzdata` build tag, which a build sets outside the source; Gleam, ReScript and Elixir run on hosts (BEAM's `calendar`, JavaScript's `Intl`) whose zone data ships with the runtime, so none carries it in the program; Rust's `chrono-tz` compiles the database into a crate the program depends on, a use like any other.

*Prior art:* Kotlin/Native's cinterop writes a klib of stubs at build time; Swift caches imported modules; Borgo commits its generated `.brg` files. A committed binding keeps `ergo check` hermetic: it reads files, as `go.sum` is read.

## Lowering

1. **Direct calls.** A call of a Go function, a method (of a Go struct through a value, a `go.Ref` or a borrow, or of a Go interface) and a field read lower to Go's own: `url.Parse(raw)`, `u.Hostname()`, `u.Path`, with Go's import in the emitted file (named apart when its name clashes). No environment, no wrapper and no poll: a Go call is not an interruption point ([runtime.md](runtime.md)). `go.Ref[T]` is Go's `*T`; a Go value passed where a Go interface is expected is Go's implicit conversion. `go.Foreign` has no operation, so the environment holds nothing for it. A call into the reviewed pure tier that takes no function is transparent in footprints (owner q35, reversing [stdlib.md](stdlib.md) Pure bodies 3 for `import go`): a function that makes only such calls takes no environment and polls nothing, as hand Go; a user extern stays opaque.
2. **Values in.** An argument (or a receiver) that is a Map or a slice, or a Go type over one, goes where Go may write or keep it: it is copied unless it is fresh (a literal, a call's result) or a local dead after the call, the value rule of [types.md](types.md) (q26). `sort.Ints(xs)` on a live `xs` sorts a copy; on a dead one it sorts in place, as hand Go does. A live operand that Go only reads (a `reads` fact) is not copied ([Foreign facts](#foreign-facts) 6). The copy-always lowering is kept as the reference (`lower.SetHostCopyAlwaysForTest`), and a seeded property holds the two equal to the value model (`TestHostCopyElisionAgrees`).
3. **Values out.** A Map or slice result is copied unless a `fresh` row of the reviewed table `gofacts.Rows` says the function returns new memory (`strings.Split`, `regexp.Regexp.FindAllString`) and its guard line is current and validated (Foreign facts 7; `lower/factledger.go`, `goFresh`); a result such as `regexp.Regexp.SubexpNames`, which shares Go's state, is copied, so a write to it never reaches Go. **Go's memory stays Go's while only Go uses it** (G2, H4, H5; one rule, owner q39). Go's own Map or slice is a Go call's result or a field read through a `go.Ref` (`r.Header`). When only Go calls take it, it is never an Ergo value, so it is not copied on either side, and a write by a Go method reaches the map Go keeps, as in hand Go. Only Go calls take it when it is a whole operand of a Go call (a receiver or an argument: `w.Header().Set(k, v)`, `r.Header.Set(k, v)`), or when it is bound by an immutable `let` whose every use is such an operand (`let h = w.Header(); h.Set(k, v); h.Add(k, w2)`). A `let` that the program also uses in another way (`len(h)`, an index, an Ergo call, a return) is an Ergo value: it is copied where it is bound, by this rule, and a later Go write does not reach it. A field of a Go struct value (not a `go.Ref`) is part of an Ergo value and keeps the value rule. Both lowerings share this rule: it is the rule, not an elision, because a copy there would lose the write with no message (`TestImportGoHeaderWriteReachesGo`: the three forms reach an `httptest` recorder and request, and the mixed `let` keeps its value). *Prior art:* a Gleam external's foreign value is opaque and never copied, and ReScript's bindings pass the shared JS reference at no cost; Elixir copies at a NIF or port boundary only where the program asks. A Go method with no result called on such a copied `let` can only write the copy, and Go never sees the write: that call is S108 at its receiver, "h is a copy of the Map or slice Go gave it, because the program also uses h as an Ergo value; this Go method writes only the copy, …" (`check/gocopy.go`; `TestGoCopyWriteIsReported`). A Go method with a result (`h.Get`) reads and is allowed. Several Go results are a tuple; a last `error` is `fails go.Error` (`v1.GoErrorOf`, as G4 lowers an extern).
4. **Nil.** A nil pointer or interface whose Ergo type is `Option[T]` is `None`, else `Some`. A `go.Ref[S]` result beside an error is one `ergo bind go` proved non-nil when the error is nil, from the Go source (Type mapping; GOBIND-NIL), so the call takes no check: Go's convention that a nil error comes with a value is proven where the binding promises it, and an Option where it is not. A wrong proof is the binder's bug (`TestNonNilResultsProperty`). A user extern that asserts `go.Ref[S]` (Level 2, Non-nil) is checked: a nil there is the defect `Go returned nil without an error at <file:line:col>: <function>` (`v1.GoNilDefect`).
5. **Variadic.** The last argument of a `// ergo:variadic` function is spread: `filepath.Join(parts...)`.
6. **Panics.** A Go panic in an imported call is a defect; the call's `//line` directive names the Ergo call site in the report, and the task's existing recover catches it, with no recover per call.
7. **Callbacks** are lowered as [Callbacks](#callbacks) says.
8. **Go function values** (D2). A non-variadic Go function with a direct type is a value: each parameter and result is a basic type, a non-generic Go type or `go.Error`, or a parameter is a borrow of a Go type; at most one result, no type parameters, and no failure but `go.Error` (`check.GoDirectSig`). At a Go callback argument the function is passed in Go's own calling convention; elsewhere it is wrapped in Ergo's uniform function shape. Other Go functions are call-only (S108). Ergo callback arguments use the wider conversion and row rules of [Callbacks](#callbacks), not this direct-value restriction.
9. **Seq.** Go's `iter.Seq[T]` is the prelude `Seq[T]` (Type mapping), and the call converts at the boundary: a Seq result becomes an Ergo Seq that ranges over Go's and stops when the Ergo yield returns false, and an Ergo Seq argument becomes a Go `iter.Seq` whose Ergo yield calls Go's. A generic Go function's Seq (`maps.Keys`, `slices.Collect`) takes the call's checked type. *Prior art:* Gleam's and ReScript's externals pass the host's iterator unconverted, as an opaque value; Ergo converts, because its Seq is a function of its uniform shape (it takes the environment and returns an error), not Go's (inferred from their documentation).
10. **Imports a program does not write.** A Go type that a Go call's result names, at any depth (the `[]fs.DirEntry` of `os.ReadDir`), is Go's own, named through its package's import, which the emitted file adds although the program imports only `os`; a Go type takes no name of the program's package scope (FU-readdir). `TestEveryGoBoundFunctionLowers` lowers one program for each Go-bound function and method of the embedded bindings (a Go interface type's operations included), importing only what its parameters name, and type-checks the emitted Go.
11. **Go methods are called.** A Go method, of a Go struct or of a Go interface type, is an extern and is call-only (grammar.md, Extern): `let f = recv.ReadDir` is S108 "recv.ReadDir is an extern and is not a value; pass func(n int) []fs.DirEntry fails go.Error needs go.Foreign { recv.ReadDir(n) }", as `let f = os.ReadDir` is. Go's method value has Go's signature, not Ergo's function shape (the environment first, an error last), so it is never passed where an Ergo function value goes; the literal the diagnostic names is one, and it lowers (FU-readdir r2). `TestEveryGoBoundFunctionLowers` writes each method's value and steps to that literal at the S108. *Prior art:* Gleam and ReScript externals are values because their targets share the host's calling convention; Elixir makes a function value only by an explicit capture (`&:math.sqrt/1`), as the literal does.
12. **A carried package** (Checking 6) is Go's blank import in the emitted file of the package of `main`: `import _ "time/tzdata"`. Lowered tests of that package carry it too.
13. **Go builtins** (OPT4b; LR3). An `extern go` whose target has no package path names a builtin of Go's universe scope, and the call lowers to the builtin itself, with no function between (`check/builtin.go`): `append` at `[T](xs []T, x T) []T` or `(xs []byte, s string) []byte`, `len` and `cap` at `[T](xs []T) int`, `copy` at `[T](dst *[]T, src []T) int`, `clear` at `[T](xs *[]T)`, `min` and `max` at `(a T, b T) T` for an ordered `T`; any other signature is S108 with the shape it must take. A builtin has no function value. **`cap` is unspecified** (NB-CUT r2, 2026-11-20): it answers the room the build gave the slice, which no rule fixes beyond `MakeSlice[T](c)` having room for at least `c` elements. A lowering may reserve more (a literal later appended to), and a copy may round up, so two builds of one program may answer differently. A program may branch on `cap`, as a push written in Ergo does (`if n < cap(xs)` writes the room, else it copies to a larger array), but every branch must compute the same value. A program whose printed values depend on `cap` is not portable between builds, and a test does not compare such output across lowerings. TestCutAgrees runs its push programs with `cap` and with a `room` that is always 0, which forces the copy branch everywhere, and requires the same output. The string shape, `extern go append func appendString(out []byte, s string) []byte`, is Go's `append(out, s...)`: the check-time evaluator runs it, and a symbolic run ([types.md](types.md#laws) Laws 14, Symbolic runs) reads it as a concatenation, as `+` on strings, so `appendString(appendString(o, a), b)` and `appendString(o, a + b)` are one term. std json's `text` writes through it, which lets its laws join constant text be proved. A chain `p = appendString(appendString(p, a), b)` whose base is the target appends in place.

## Foreign facts

A foreign fact is a statement about what a Go function does with an operand, which the compiler may use to change emitted code (LAWFFI). Each fact has a level: **checked** when the pinned Go toolchain derives it, **vouched** when a reviewed row asserts it, and **validated** when a vouched fact's guard has a current, passing line in the ledger (item 7). A checked or validated fact changes code; a vouched one does not. A law is never the licence of a fact; it can only guard one.

1. **`reads p`.** The function does not write through `p`, keeps nothing of `p`, returns no part of `p` and does not call `p`. It is derived for a parameter, or a method's receiver, whose Go type is a slice (or a type over one) whose elements reach no map, interface, function, channel or unsafe pointer.
2. **Derivation.** `ergo bind go` compiles each package it binds with `-gcflags='-m -d=escapemutationscalls=1'` on each of the four platforms (Binding files 5), and reads one line form: `<file>:<line>:<col>: p does not escape, mutate, or call`, at the position of the parameter's name in the Go source. Any other verdict at that position, a line it cannot read, and the silence Go keeps about a parameter that moves to the heap are no fact. A fact holds only when every platform derives it, so a function with an assembly body on one platform has none. A generic function, or a method of a generic type, has none: Go prints its verdict per instance shape. A package a binding only names (not one `ergo bind go` was given) has none. The debug flag has no compatibility promise, so the bindings are regenerated with the toolchain (`TestGoStdBindingsMatchToolchain`), and `TestDerivedFactsSound` holds the derivation to a model on generated Go packages.
3. **Why the type limit.** At go1.27, Go's escape analysis does not count a write into a map as a mutation: `m[k] = v`, `delete(m, k)` and `m[k][0] = v` all print "m does not escape, mutate, or call"; only `clear(m)` mutates (measured, LF0). Go uses the verdict for its own `[]byte(s)` copy elision, where no map is involved. So a Map, and a slice whose elements reach one, gets no fact.
4. **In the binding.** The fact is the line `// ergo:reads <binder>…` above the declaration, naming the binders of the Ergo signature (a hidden `context.Context` and a renamed binder shift Go's index; the line names the binding's binder). The toolchain is the one the `// ergo:bind` line names. A line that names no binder of the declaration is S108 where the binding is read; one that names an operand that is not a slice is S108 when the binding is resolved whole (`ergo bind go`'s acceptance).
5. **Report.** `ergo inspect facts` prints a `fact-go-reads` row at each Go call operand a fact names: the Go function, `reads p`, its level and source, the law that guards it (none for a derived fact) and what the lowering did. `ergo build -report copies` prints a `COPY` line for each Map or slice operand of a Go call, with its form (`copy`, `no copy`, `shared`) and why, naming the facts on it.
6. **`reads` skips the copy** (LF1; the shortcut `host-reads`, `lower/gofacts.go`). Where Lowering 2 would copy a live slice operand, the run build passes it as it is when all of these hold: the operand's binding carries a `reads` fact; its elements are scalars or strings; it is a binding or a field path of one, in the frame that declares the binding (no task or kept function holds it); the call has no callback; and every other Map or slice operand of the call also carries a `reads` fact, so no operand Go writes shares its memory. `sort.SearchInts(xs, k)` on a live index then costs a search, not a copy of the index (`examples/gointerop find`). The test build takes no shortcut: it passes a copy and, after the call, compares it with the value Ergo holds element by element (`v1.GoReadsCheck`; two NaNs are equal, and a write of -0 over +0 is not seen). A difference is the defect `Go wrote <p>, which its binding says <function> only reads, at <file:line:col>` (`v1.GoReadsDefect`). The compare stays for derived facts, since Go does not report every write (3). A false fact gives a wrong value in memory-safe Go; it never corrupts memory. `TestHostCopyElisionAgrees` holds the run build, the copy-always reference and the value model equal on generated reads shapes and raises the defect on a planted false fact; `TestReadsCallTakesNoCopy` checks the promised form; `TestHandoverGrowsLinearly`'s `host-search` counts the work.
7. **Vouched `reads`** (LF2; `internal/gofacts`, `lower/factledger.go`). Where Go's analysis cannot see a body (assembly: `bytes.IndexByte`, `sha256.Sum256`; a function variable: `crc32.ChecksumIEEE`), a row of the reviewed table `gofacts.Rows` vouches for the fact: the function, the fact, the parameter, the reason, and the hash of the function's Go declaration at the pinned toolchain (`TestVouchedRowsReviewed` fails while a declaration's hash differs from its row's, until a reviewer looks again). `ergo bind go` writes it as `// ergo:reads <binder> (vouched: <reason>)`. Each row has a guard: the function is called on operands of the edge lengths of word, vector and block widths and on seeded drawn ones, and a call that leaves its operand changed refutes the row. `go run ./scripts/stdlaws` runs every guard and writes its line into std's ledger, `fact go bytes.IndexByte reads b validated by guard with go1.27.4 h1:…`, whose digest covers the row and the toolchain. The fact acts, as item 6 says, only on that line current and validated (`admitLevel`); a missing or stale line keeps the copy and the copy report says why. A current refuted line stops the build at the call: "bytes.IndexByte is vouched to only read b, and its guard refuted it". A keep with no later write is not seen by a guard; review holds it. Every test build still copies and compares (item 6), so each test that reaches the call checks the fact again on its own inputs. **The older reviewed tables are guarded too** (LF2c). A `fresh` row (they were `lower.freshGoResults`) is a row of `gofacts.Rows` with a guard of its own: the function is called, every string of its result is written, and a second call must give the first's value, so a result that shares memory Go keeps (`regexp.Regexp.SubexpNames`) refutes the row; it acts only on its ledger line, as `reads` does, and a refuted line stops the build ("strings.Split is vouched to return a new result, and its guard refuted it"). `v1.GoSyncCallbacks` stays in `runtime/v1`, which the checker and `ergo bind go` read; its guard (`internal/gofacts/hostguard`, `sync.go`) calls each row's function twice with callbacks that record their goroutine and whether the call has returned, and refutes a row whose callback runs on another goroutine, after the call, or not at all; a row with no guarded call is refuted. `v1.PureImports` minus `v1.PureImportsExcept` is guarded by the determinism guard (`hostguard/pure.go`): every exported function of those packages with no type parameter (`hostguard/members_gen.go`, generated from the pinned toolchain's source; `TestMembersCurrent`) whose parameters the guard can draw is called on the same drawn arguments under two host states (working directory, `HOME`, `TZ`, `time.Local`, `GOMAXPROCS`), and the results and the arguments after the call must agree; `filepath.Abs` would fail it. **Both tables act only on a guard line** (LF2d). `go run ./scripts/stdlaws` runs both guards and writes a line per row into std's ledger, `fact go sort.Search sync callbacks validated by guard with go1.27.4 h1:…` and `fact go strings pure members validated by guard with go1.27.4 h1:…`, whose digest covers the row (its reason; the package's excepted members) and the toolchain. The checker reads the shipped ledger as an input, as `ergo check`'s licence advice reads a module's (LF6c; `check.FactLedger`, `check/factguard.go`): a binding's non-escaping callback clause checks only on its row's line current and validated, and `ergo bind go` writes a package's members in the pure tier (with no `needs go.Foreign`) only on its line current and validated (`check.PureActs`). A missing or stale line is the diagnostic "sort.Search declares a non-escaping Go callback without a reviewed clause that acts (the guard line for go sort.Search sync callbacks is stale …)"; a refuted line is "… and its reviewed clause does not hold: its guard refuted it". The guards call `expvar`, `flag`, `go/ast` and change the process's working directory for a moment, so only `scripts/stdlaws` and tests link `hostguard`, never the compiler; `stdlaws` gives the checker its fresh lines before it checks std, so a stale shipped line never stops the run that refreshes it. A determinism guard cannot see every read of host state, so `pure` stays review-first. **The memory-only rows** (GBX6) are rows of `gofacts.Effects`: the target, the reason and the hash of its Go declaration, reviewed as a `reads` row is (`TestVouchedRowsReviewed`). Their guard (`hostguard/effect.go`) runs each row's seeded calls on the same drawn state under the determinism guard's two host states; the results and the state after must agree, and a row with no guarded call is refuted. `go run ./scripts/stdlaws` writes `fact go sync/atomic.Int64.Add effect none validated by guard with go1.27.4 h1:…`, whose digest covers the row and the toolchain. **The host rows** (HOST-ROW) are rows of `gofacts.Hosts`, reviewed as the memory-only rows are. Their guard (`hostguard/host.go`) runs each row's call under the same two host states: the call must follow each state (`Getenv` gives that state's `HOME`, `Getwd` its directory, `Now` its zone), a slice result must be the caller's (a write to it is not seen by the next call), and the call must leave no goroutine; three planted false rows are refuted (`TestHostRowsHold`). `go run ./scripts/stdlaws` writes `fact go os.Getenv effect ambient validated by guard with go1.27.4 h1:…`. `v1.GoArgClauses` (`lent`) has no guard: a resource's keep is review-only.
8. **The view** (LF2b; owner q193; the shortcut `host-view`, `lower/view.go`; `runtime/v1/view.go`, `guard.go`). `crc32.ChecksumIEEE(strings.Bytes(s))` copies `s`'s bytes for a function that only reads them. The run build passes `v1.BytesView(s)`, the string's own bytes (nil for the empty string, capacity equal to length), when all of these hold: the operand is, as a whole, a call whose body's contract names a view form (`//ergo:view BytesView` on `StringsBytes`; a std function whose body is one call of such a body on its parameter, as `strings.Bytes` is, reaches it); the parameter's `reads` fact is vouched by a row that allows a view (`gofacts.Row.View`: `crc32.ChecksumIEEE`, `crc32.Update`, `sha256.Sum256`) and validated (item 7; `admitView`, the one memory-class change a validated fact admits); the call has no callback and Go writes no other operand. A derived fact takes no view: Go drops a `[]byte(s)` copy itself where it derives the fact. The selection reads facts, never a name. Every test build passes a guarded copy instead (`v1.GuardBytes`): the bytes end at the last byte of read-only pages followed by an unmapped page, and after the call the pages become unreadable and join a ring of at most 64 copies. A write (even one the callee restores), a read past the end and a read through a kept slice after the call each fault at the access, and the fault is the defect `crc32.ChecksumIEEE wrote to its argument data, which its row vouches it only reads (main.ergo:13:15); remove the row` ("read past the end of" and "kept" are the other verbs). Where pages cannot be mapped, the copy is on the heap, compared after the call and poisoned. `ergo build -views=off` takes no view; `BytesView` and the guard's `mapPages` are lines of `internal/residue/testdata/unsafe.txt`.

9. **`total`** (GOBIND-TOTAL; `gobind/total.go`; the format is GO-NOPANIC's). A total function returns normally for every value of every operand: no `panic` of its own, no run-time panic (an index, a nil dereference, a zero divisor, an assertion, a closed channel, a negative shift). Out-of-memory, stack exhaustion and non-termination are outside the fact. `ergo bind go` derives it over go/types on the package's own source for each platform, keeps it only where all four prove it, and writes `// ergo:total` above the declaration. The rule is narrow, because a false line is a miscompile (the IR drops the call's panic edge). A body may use locals and parameters, basic package variables (read only), operators on basic operands, shifts by a constant or unsigned count, integer `/` and `%` by a non-zero constant, numeric conversions, `if`, `switch` on a basic value, `for`, a range over an integer, `min`, `max`, `len` of a string or array, and calls of total functions and value-receiver methods of its own package, to a least fixed point. Everything else proves nothing. 120 std functions and methods carry the line at go1.27.4, among them `math/bits` Mul64, Add64, Sub64, RotateLeft64 and ReverseBytes64; the table-indexing `Len8` and `OnesCount8`, and `Div64`, whose body panics, carry none.

*Prior art:* Go's own `[]byte(s)` copy elision rests on the same analysis, and `#cgo noescape` asserts the fact for C with no check; MoonBit's `#borrow` marks a C parameter only read; Gleam's and ReScript's externals assume nothing of a foreign call; Elixir's NIFs must not write a binary they are given, and nothing checks it.

## Resources

Status: **implemented** (IG9; `check/hostres.go`, `TestHostResourceVerdicts`, `TestHostResourceRun`).

1. **A Go resource.** A Go type whose binding declares `implements Closer` is a resource ([resources.md](resources.md) R1), and so is `go.Ref[T]` of one and a Go interface that includes `io.Closer` (`io.ReadCloser`); `io.Closer` stands for the prelude's `Closer`. `ergo bind go` writes the clause on a Go type whose method set has `Close()` or `Close() error` (the binding's `Close()` or `Close() fails go.Error`, value or pointer receiver), `implements io.Closer` in a package that declares its own `Closer`, and `..io.Closer` in a Go interface that lists it (EXC1). The name is read once, by the tool, and the result is text in the binding, so no user marks the type and no Go tool runs.
2. **Owned results.** A Go function's result of a resource type is owned by the caller (owner q62): `let f = try os.Open(p)` is released at its scope's end on every exit, last acquired first, with no `defer` to write. `try f.Close()` is the explicit take; it fails `go.Error` as any Go call with a last `error` does, and a later use of `f` is S108.
3. **The release.** An automatic release calls Go's `Close` inside the release boundary (`v1.Release`, masked, as a checked `Close` runs). A non-nil error of `Close() error` there is a defect in the exit cause, `release of the value acquired at <file:line:col>: <error>`, naming the acquisition (owner q61, `v1.CloseFailed`). Go's `defer f.Close()` drops that error by habit.
4. **Borrowed package variables.** A Go package variable is borrowed (owner q62): it is never released, and a take of it (`try P.V.Close()`, `let v = P.V`) is S108 "a Go package variable, borrowed from Go". `ergo bind go` admits a variable whose actual Go method set has `Close()` or `Close() error`, including a named interface, and keeps refusing other non-error variables. A pointer variable such as `os.Stdout` maps to `Option[go.Ref[os.File]]`: unlike a successful `(T, error)` call, a variable gives no non-nil promise. Match it to lend the contained handle; a `Close` or a hand-off through the match binding is S108 too. Reading the pointer snapshots it once and maps nil to `None`, otherwise `Some`. No write to the Go variable is admitted.
5. **Arguments default to kept** (ESC1 r2, 2026-11-11). A Go signature proves no lifetime. Resource-capable parameters are taken, including an interface such as `io.Reader` that may receive a resource without declaring `Close`. An incoming lent resource cannot be passed there; an owned one is handed over to Go and cannot be used or released by the caller afterwards. `bufio.NewReader(f)` takes `f`: its reader keeps the file but has no `Close`, so this is a foreign hand-off, not a scoped reader that Ergo will release. Use a reviewed scoped operation such as `io.ReadAll(f)` to keep automatic release in Ergo. Only the checked-in per-function/per-parameter table `v1.GoArgClauses`, with a nonempty source reason, grants a narrower lend. `gobind` writes the mode word `own` on each kept parameter, on a kept method receiver and before an interface operation that keeps its implicit receiver (`own Close() fails go.Error`) (q168), and the checker enforces the default even for an old or edited binding that omits it.

   **A receiver is lent** (GB1, 2026-11-15). A Go method, and a Go interface's operation, lends its receiver for the call, so one driver handle serves many calls: `c.Get(a)`, then `c.Get(b)`, then `c.Close()`. Go's memory is safe whatever Go keeps; what the owner of the receiver must know is that a result may still need it, which the keeps rule below states. Two receivers stay taken whatever the binding writes: the release (`Close() error`, R19), and, on a resource, a method whose result may hold the receiver itself (the type, a pointer to it, a Go interface, or a field of a Go struct that may; `gobind`'s `mayHold`, the checker's `hostTakesRecv`), since the caller would then own one Go value twice and release it twice: `let d = try c.Clone()` takes `c`.

   **Keeps.** A result of such a call that holds a `go.Ref`, a Go interface or a resource keeps the receiver's owner (`check/hostclauses.go`, `hostKeptLoans`; the structured lend of [resources](resources.md) R31 with the call as its keeper). It is used where it was made: a `let`, a match binding or a field of a value bound after the owner, released before it. The owner is not closed or handed off while the result is in scope, unless the result is a resource whose `Close` ran first (`try rows.Close(); try db.Close()`); the result is not returned, given to an Ergo function's parameter (other than a borrow), captured by a function value that outlives the owner, or stored past it. Each is S108, "this value comes from c.Get and keeps c: …" or "c cannot be released or handed off here: cmd, the result of c.Get, keeps it, …". A Go argument may take a kept result, since Go may keep what Go keeps. The fact is derived from the signature by the checker, so no binding text states it. `TestDriverHandleIsLent` (check) holds the rule to a model on generated bodies over a driver-shaped Go package. *Prior art:* Rust's `rows: Rows<'conn>` ties a result to its connection by a lifetime parameter; Swift's `~Escapable` results with `@lifetime(borrow self)` do the same without a written lifetime; Gleam, ReScript and Elixir hand a driver's connection to the host (a pid or a JS object), which the host closes, and check no order. Ergo has no lifetimes in signatures (types.md, Structs 3), so the kept result stays in the owner's frame.

   A match takes the payload of a fresh `Option[go.Ref[T]]` into an owned binding with a record pattern, `case Some{Value: c}:`; `case Some[go.Ref[T]] as s: let c = s.Value` stays S108 (R39) and names that pattern. A bound non-resource parameter's written own is inert (mode crossing), so the binding is not diagnosed for it. The table intentionally does not narrow `io.Copy`: its optional `WriterTo`/`ReaderFrom` delegation can hand one endpoint to another Go implementation.
6. **Generic Go functions** copy each type parameter (D-B): they are bodiless and the reviewed table (`v1.MovesOnly`) lists none, so a resource instantiation is S108 at the call.

   A Go pointer parameter can keep a borrow too, even when its referent is not a resource. It follows the conservative default. A borrow cannot be handed over: passing it to a kept argument or receiver is S108. A reviewed lend still admits it. The direct Go argument conversion uses the enclosing function's lifetime clause, not a second hand-off through the Go interface's receiver; interface parameter ownership and method rows still match. This boundary exception does not apply inside the argument's nested expressions or function literals.

*Prior art:* Rust's `File` closes on drop and drops the error; Swift's `~Copyable` `FileDescriptor` needs a written close; Go's vet has no check for a leaked `*os.File`. Gleam, Elixir and ReScript leave a host handle to the host (the BEAM closes a port with its process).

*Prior art:* Gleam's `@external` and ReScript's `@module` externals are direct calls with no adapter, as here when no Map or slice crosses shared; Kotlin/Native's cinterop and Swift's Clang importer map a nullable pointer to an optional the same way; Swift copies an `Array` passed to C only when its buffer is shared, as the value rule copies a live operand.

## Go modules

Implemented (IG7, owner q37). A module imports Go packages outside Go's standard library through the go command's own files and committed bindings; `ergo check` reads files only.

1. **Layout.** Beside `ergo.mod` stand a plain `go.mod` and `go.sum`, managed with the go command (`go mod init`, `go get example.com/x@v1.4.0`, `go mod edit -replace`). `ergo.mod` keeps its `module` line, and a `trust go MODULE` line for each required module whose Go the program admits ([grammar](grammar.md#source-files) rule 1, Trusted Go; MD3). The bindings are the root module's: a trusted dependency's `import go P` reads the root's `ergo.bind/P/…`, because the root's `go.mod` selects the version of each Go module the program links, so one Go package has one binding in a program; `ergo bind go P` in the root writes it. The bindings are committed under `ergo.bind/<import path>/<last element>.ergo`. A folder name with a `.` is no Ergo import path, so `ergo.bind` never loads as a package; `ergo fmt` of a folder and the examples runner skip it. `go mod tidy` sees no Go import in an Ergo module and drops the requirements: do not run it there.
2. **Binding.** Inside a module, `ergo bind go PACKAGE…` runs `go list` in the module root with `-mod=readonly` (it never edits go.mod or go.sum), writes each binding under `ergo.bind/`, and also writes the binding of every package outside the standard library that a written binding names, so the set checks on its own. A standard-library package, a `main` package and an `internal` or `vendor` package are refused: the first is embedded, the second is a program, and Go admits the others only inside the tree that holds them, which the emitted program never is.
3. **Stamp.** Each module binding carries the stamp of its Go module (Binding files 7), as `go list` reports it for the go.mod where it ran. The loader computes the same stamp from go.mod (the required version, then the replacement of that exact version, else of every version) and compares. A missing go.mod, a module go.mod does not require, or another stamp is S104 at the import: "the binding of Go package "example.com/x" is stale: it was made for example.com/x v1.4.0, and go.mod now names example.com/x v1.5.0; run ergo bind go example.com/x". `import go` of a path with an `internal` or `vendor` element is S109 at the import.
4. **Emitted module.** The emitted go.mod requires and replaces what go.mod requires and replaces, each relative local folder made absolute, and go.mod's own module, replaced by the module root; go.sum is copied as it is. It merges these with Ergo's own directives (the runtime's module `ergo.local/prototype`, required at v0.0.0 and replaced by the copied `ergo/` tree; the main module `ergo.local/program`) by one rule for every module path (`lower.MergeGoModules`, G1): one version per required module; equal directives once; for each required module, the replacement each source applies to that version (its exact one, else its version-less one) is the same in every source. Two replacements that differ conflict, unless one is the copied `ergo/` tree and the other a folder that holds the same bytes for each of its files (this repository at the compiler's revision): then that folder serves both. A conflict is a diagnostic at the later go.mod line that names both sources, such as "the Ergo runtime (ergo/) replaces ergo.local/prototype with ./ergo, and go.mod:7 replaces it with /src/ergo: /src/ergo holds another runtime/v1/text.go than this compiler emits". go.mod, go.sum and every module binding read are inputs of the build key. go build checks each emitted call at its `//line`: a binding edited to lie (another target, another type) checks, and fails the build at the Ergo line of the call.
5. **Proof.** `TestGoModuleImports` (cmd/ergo) binds, checks and runs a module that imports a Go module replaced by a local folder and one required from a `file://` module proxy (no network), and shows the stale, missing and internal diagnostics with only a stub `go` on PATH that would mark a start. `TestGoModMatchesGo` holds the loader's reading of go.mod and its stamps to `go mod edit -json` on seeded go.mod texts. `TestEmittedGoModMergesGoMod` holds the merge to `go list` on seeded modules (every admitted one resolves, every conflict is one diagnostic naming both sources); its "compiler repository" shape is the repro of a module that requires and replaces `ergo.local/prototype` by this repository.

Prior art: Borgo commits generated declaration files per package (`std/`) and regenerates them with a script; Kotlin/Native's cinterop writes a klib at build time; Swift caches precompiled Clang modules keyed by the headers. None checks the summary against the dependency's version; Ergo's stamp does, as go.sum checks a module's content.

## Host calls

Implemented (IG10; G8 host-call stage, outbound direction).

1. **Hidden context.** A Go function or method whose first parameter is `context.Context` is bound without it (Which Go declarations import; `// ergo:context`). Package `context` itself is exempt: its functions take a context as their subject (`context.Cause(ctx)`). Such a call is foreign (`needs go.Foreign`) whatever its package, because it needs the calling task.
2. **The task's context.** The call passes `rt.GoContext(task)`: the calling task as a `context.Context`. Its `Done` is the task's stop channel, made when Go first asks for it, and `Err` is `context.Canceled` once a stop is requested (an interruption, a timeout, a lost race, the end of a scope). It has no deadline and no values. It is one pointer in an interface: the call allocates nothing, and a call whose Go code never reads `Done` costs a mask test.
3. **Masks.** Inside a masked region (an exit action, an acquisition) the call gets `context.Background()`: the region runs to its end (runtime.md I2), so a Go wait there is not cancelled.
4. **Interruption wins.** Right after the call, the lowering writes the task's interruption point. A task whose stop ended the Go wait unwinds there: the `context.Canceled` error Go returned is never seen as a `go.Error`, no catch arm runs, and the task's exit actions run.
5. **Not claimed by shape.** A Go call that ignores its context (or takes none) is an uninterruptible host wait; nothing is assumed cooperative from its signature. `ergo inspect` lists those waits for each function ([tooling](../tooling.md#inspect)).
6. **Proof.** `TestGoContextInterrupts` (cmd/ergo) waits for Go to enter a context-aware wait, then calls the task's `Stop`. The catch arm never runs, the exit action runs masked with a context that cannot be cancelled, and its release has completed when `Stop` returns. It observes owned events, not a process-wide goroutine count. A Level 2 adapter of `runtime/trace.Log` passes the context too. `TestGoContextModel` (runtime/rt) holds the context to `context.Context`'s contract on every sequence of up to five interrupts and reads, from other goroutines, for a task and a child.

Prior art: Go itself passes `ctx` by hand to every call (the convention this lowering writes for the user). Effect's `Effect.tryPromise` gives the callback an `AbortSignal` that the fiber's interruption aborts; Kotlin's `suspendCancellableCoroutine` and Swift's `withTaskCancellationHandler` bridge a host wait to the task's cancellation in the same way. Gleam, ReScript and Elixir have no structured cancellation to pass: a BEAM process exit kills the process, and a NIF cannot be interrupted (dirty schedulers run it to the end), the uninterruptible host wait of item 5.

## Go writes in place

GBX2, 2026-11-16. A Go function that writes its slice argument in place and returns nothing (`slices.Sort`, `slices.SortFunc`, `slices.SortStableFunc`, `slices.Reverse`, `sort.Ints`, `sort.Float64s`, `sort.Strings`) returns that slice in Ergo: `let ys = slices.Sort(xs)`.

1. **Fact.** The reviewed table `runtime/v1.GoWrites` names each function and the parameter it writes, with its source reason (go1.27): it writes only the slice's elements, keeps no reference to it and returns nothing. `ergo bind go` writes `// ergo:writes <binder>` above the declaration and gives it that parameter's type as its one result (`extern go slices.Sort func Sort[E ordered](x own []E) []E`). A writes line on a parameter that is not a slice the function returns is S108 when the binding is resolved.
2. **Values.** Go gets the operand the value rule gives it (Lowering 2): a copy of a live slice, or the dead local or fresh literal itself, which it writes in place with no copy. The call's value is the slice Go wrote; the slice an Ergo binding holds never changes (`TestHostCopyElisionAgrees`, lower, against the value model and the copy-always reference).
3. **Calls only.** A user extern of such a function is S109 ("writes its slice argument in place; call it through import go"): no Level 2 adapter states the written result.
4. **Lowering.** `w := <operand>; slices.Sort(w)`, and the value is `w`.
5. **Methods and results.** HOST-ROW-3 slice 2. A method may write its slice parameter (`(*os.File).Read`, `ReadAt`; the table's index counts after the receiver, and a writes line never names the receiver), and a function with results of its own returns the written slice first: `extern go os.File.Read func (f *File) Read(b []byte) ([]byte, int) fails go.Error needs Ambient`, so a read is `let (b, n) = try f.Read(buf)`. On a failure the value rule's copy, or the dead local, holds what Go wrote; no Ergo binding sees it. In a loop, `buf = b` after the call ends the old buffer (types.md, Bindings 2), so the loop hands Go its buffer at each call with no copy, and Go keeps no reference to the written slice, so the operand is no escape (S2-COPY). An operand Go only reads (a reads fact) is no escape either, and a slice of a binding (`b[:n]`) takes its fact as the binding does: `File.Write` reads `b`.

*Prior art:* Gleam's `list.sort`, ReScript's `Array.toSorted` and Elixir's `Enum.sort` return a new sorted collection; ReScript's `Array.sort` sorts in place and returns unit, and Effect's `Array.sort` returns a new array. Ergo keeps the value form at the surface and gets the in-place speed from the value rule's handover, as Swift's copy-on-write `sort()` writes a uniquely held buffer in place and Koka's reuse analysis reuses a dead value.

## Go any

GB2, 2026-11-16. Go's empty interface (`any`, `interface{}`) is the predeclared host type `go.Any` (`check/goany.go`): `db.ExecContext(q, args []go.Any)`, `rdb.Set(key, v go.Any, ttl)`, `rows.Scan(dest []go.Any)`.

## Go errors

`go.Error { Text string }` keeps the Go error it was made from (IG5, Go interop: "with `errors.Is` and `errors.As` kept").

1. **Made.** A Go call whose last result is a non-nil `error` fails with the `go.Error` of that error; a typed nil (a nil `*T` in a non-nil `error`) is an error, as Go's `err != nil` says. A binding's error variable (`io.EOF`, `fs.ErrNotExist`) is the `go.Error` of Go's variable. A Go `error` read from a field or a non-last result is a `go.Error` too (`go.Error{}` when nil). `go.Error{Text: s}` written in Ergo makes a Go error of its own whose text is `s`; two of the same text are `go.Is` of each other.
2. **Text** is the Go error's `Error()` when the field is read, never a copy taken at the failure: a failure no code prints costs what hand Go's `return err` costs. `Text` is read-only (S108 "cannot assign"); `go.Error{..e, Text: s}` makes a new one.
3. **Passed to Go.** A `go.Error` argument for a Go `error` parameter (and each element of a `[]go.Error` for `...error`) is Go's own error, so `errors.Join` and Go code see the chain Go made; `go.Error{}` is `nil`.
4. **`go.Is(e go.Error, target go.Error) bool`** is `errors.Is` on the two Go errors: `go.Is(e, fs.ErrNotExist)`.
5. **`go.As[T](e go.Error) Option[T]`** is `errors.As`: `Some` of the first error in the chain that is a `T`. `T` is a type of a Go binding whose Go method set has `Error() string` (a value type whose method has a value receiver, or a `go.Ref[S]`), or a Go interface; any other `T` is S108 at the call, because `errors.As` panics on it. `go.As[go.Ref[fs.PathError]](e)`; `go.As[strconv.NumError](e)` is S108 ("implements error through a pointer receiver; write go.Ref[strconv.NumError]").
6. **Equality.** `==` on `go.Error` compares `Text` (G4's rule, kept). Go's `==` on errors compares identity and panics on an error type Go cannot compare, so `go.Error` is equatable but not comparable: it is no `Map` key and does not satisfy `comparable` (S108).
7. **Lowering.** `v1.GoError` holds the Go error; `Text` lowers to the method `Text()`, `go.Is` to `errors.Is`, `go.As[T]` to `errors.As` into a `T` and an `Option`. The eager form (the text computed at the failure, G4's) is kept as the reference lowering (`lower.SetGoErrorEagerForTest`); `TestGoErrorChainsAgree` runs generated chains under both against Go's own `errors` package, and `runtime/v1`'s `TestGoErrorChainsModel` covers chains only a Go package can build (custom `Unwrap`, a typed nil).

*Prior art:* Go's own `errors.Is`/`errors.As` are the semantics. Swift's `NSError **` convention keeps the `NSError` object behind `throws`, and Swift code casts it (`as? URLError`) as `go.As` does; Kotlin/JVM keeps the Java exception object and `is`-checks it. Gleam and Elixir keep the host's error term as data (`{error, enoent}`); ReScript's `Js.Exn.Error` keeps the JS exception. Effect's `Cause` keeps the original defect object for the same reason: a typed failure that drops the host value cannot be asked about it later.

`v1.GoSyncCallbacks` stores a source reason per function; only a nonempty reason grants the narrower clause. An unreviewed non-escaping annotation in an old or edited binding is a diagnostic, not a trust assertion (ESC1 r2).

A Go parameter of a function type takes an Ergo function value (IG6). One rule, Ergo's row generics (q39), covers what Go code between the call and the callback cannot carry by itself: a failure and a capability.

1. **Synchronous.** The reviewed table `v1.GoSyncCallbacks` (`runtime/v1/gocallback.go`) lists the Go functions and methods that call each callback only during the call, on the caller's goroutine, and keep none (`strings.Map`, `slices.SortFunc`, `path/filepath.WalkDir`, `regexp.Regexp.ReplaceAllStringFunc`, `sync.Once.Do`, …); trust facts come only from reviewed tables (owner q36). A listed function's binding takes row parameters `CE` and `CR`: its callback needs `CR`, and fails `CE` when Go's callback returns an error that the call returns, and the call fails `CE | go.Error` and needs `CR`: `extern go path/filepath.WalkDir func WalkDir[CE, CR](root string, fn func(string, fs.DirEntry, go.Error) fails CE needs CR) fails CE | go.Error needs CR | go.Foreign`. A callback literal fails `Hit` and reads `Tag`, so the call fails `Hit | go.Error` and needs `Tag`. A callback whose Go type returns an error the call does not return fails `go.Error`. A method takes no row parameters in v1: its synchronous callback needs nothing and fails `go.Error` when Go's returns an error.
2. **Escaping.** Any other callback may run after the call, on any goroutine: its parameter is `own func(…)` (q168), with no `needs` row, so it reads no capability (nothing `with`-bound escapes: [rows.md](rows.md), Footprints 5; a use is S102), and fails `go.Error` at most, Go's own error: `extern go time.AfterFunc func AfterFunc(d duration, f escaping func()) …`.
3. **Shape.** A callback has one result at most; a pointer result is refused (Go may return nil); a Go error parameter is a `go.Error`. Gobind writes a `fails` row exactly when Go's callback returns an error, so the lowering reads Go's function type from the binding.
4. **Lowering.** The argument becomes a Go function literal of Go's exact type (`func(string, fs.DirEntry, error) error`), bound once before the call: it calls the Ergo value in the environment of the code that makes the call, so the callback runs on its caller's task with its caller's capabilities, as hand Go's closure would. Go's arguments become Ergo values (a Go error the `go.Error` that keeps it; a slice or a Map a copy), and the result Go's (a `go.Error` its native error; a slice or a Map a copy). A defect in the callback is a Go panic that unwinds through the Go function to the task's recover, a defect of the outer call.
5. **Failures through Go.** A callback's `go.Error` failure is Go's own error (`v1.GoCallbackError`), so Go acts on it: `fs.SkipDir` skips, `fs.SkipAll` stops. Any other failure is wrapped in `*v1.GoTunnel` and returned to Go, and the outer call's error is `v1.GoUntunnel`: the tunnelled Ergo failure, typed again, when Go's error chain holds one (Go returns the callback's error as it is, or wrapped), else the `go.Error`. The eager go.Error reference has `v1.GoUntunnelEager`. `TestCallbackTunnelModel` runs generated walks of `filepath.WalkDir` and `filepath.Walk` over generated trees under both go.Error lowerings against Go's walker with a Go callback.

*Prior art:* Swift's `rethrows` is this rule: a function that takes a throwing closure throws exactly when the closure does, and a closure parameter is non-escaping unless written `@escaping`, which Ergo's `own` on a function parameter follows; Kotlin's `inline` lambdas may return from and throw through the caller, while `crossinline`/non-inline ones may not. Effect's `Effect.forEach` gives the callback's `E` and `R` to the whole call, as `CE` and `CR` do. Gleam and ReScript pass a host closure straight through, with no adapter, and leave a failure inside it to the host's exceptions; the tunnel is the typed form of that: an exception that carries the Ergo failure through the host frames and is caught at the call.

## Level 2 adapters

A user `extern go P.F func name(sig)` names a function of P's binding, and its written signature must be one adapter of the Level 1 signature the binding gives (IG4). The checker reads the binding and runs no Go tool, so an adapter is checked, not trusted ([grammar.md](grammar.md#declarations), Declarations 2):

| written | Level 1 (Go) | lowering |
| --- | --- | --- |
| the Level 1 signature, any names | any | as an `import go` call |
| `T` | `Option[T]`: a pointer or interface result that may be nil, with no error | a nil result is the defect `v1.GoNilDefect` naming the target and the Ergo call |
| `Option[T]` | `(T, bool)` | `Some(v)` when Go's bool is true, else `None` |
| `(R…, Option[go.Error])`, no `fails` row | `R… fails go.Error` (`(R…, error)`) | Go's values are kept beside the error; the error is `Some(go.Error)` when non-nil; refused when an `R` is a `go.Ref` |

1. **Parameters** are Level 1's, of identical types. A generic target binds its type parameters from the written parameters, as Go infers them, and each must satisfy its constraint; a written type parameter is refused.
2. **Rows.** `needs go.Foreign` exactly when the binding has it (the foreign tier); none on the reviewed pure tier. A target that returns an error writes `fails go.Error` or the Partial adapter. Adapters do not compose.
3. **Trust** facts no adapter can check (purity, a synchronous callback, a read-only slice argument, a fresh result) come only from reviewed tables in `runtime/v1` (owner q36); user source states none.
4. **Lowering.** An extern whose adapter is the Level 1 signature over predeclared basic types and G1's callbacks lowers as before, a direct call that go build also checks, and may be a function value. Any other is call-only and lowers by the rules of Lowering above (the copy rule, the spread, Go's results bound), then the adapter's check. An extern stays opaque in footprints, as before (stdlib.md, Pure bodies 3).

*Prior art:* Swift's API notes change an imported C signature (nullability, the `NSError **` convention, names) without touching the header, and the compiler applies them at the call; Kotlin's platform types are the opposite choice, an unchecked `T!`. Gleam and ReScript externals trust their written types; Borgo maps `(T, bool)` to `Option<T>` for every function, which loses `strings.CutPrefix`'s `after` when not found, so Ergo makes it an opt-in adapter.

## Trusted Go

Status: **implemented** for a module's own packages (STD-NOPRIV NP4e, NP4d; decision Q2 of the plan). The runtime's Go API (`ergo.local/prototype/runtime/v1`) is a public calling convention: a body takes hidden arguments that the lowering supplies (the frame, the call site, the task, the scheduler, the context package; [stdlib](stdlib.md), Hidden arguments), and the checker reads the body's facts from its declaration's target (`check.BodyOf`), never from the package that declares it. Such Go is not checked by Ergo, so someone vouches for it. What a body promises, fact by fact, and where each fact is written (a clause on the Ergo declaration or a mark on the Go body) is the body contract ([stdlib](stdlib.md#the-body-contract); STD-NOPRIV NP4a).

1. **The trust line.** `ergo.mod` holds `module NAME` and then lines `trust go MODULE`, each naming once a module whose Go the root vouches for (one trust line, the same as a required module's, [grammar](grammar.md#source-files) rule 1, Trusted Go; orchestrator ruling 2026-11-14). A module trusts its own Go with its own name:

   ```
   module app
   trust go app
   ```

   The toolchain vouches for what it ships: std and the prelude are trusted by the same rule, with no line. A `trust go` of a std path is S108 in `ergo.mod`.
2. **The door.** An `extern go` whose target is in the runtime module binds a body of `runtime/v1` when its package's module is trusted: `extern go ergo.local/prototype/runtime/v1.ContextBound func contextBound(key string) bool`. Its call is lowered as std's is, hidden arguments included, so a copy of a std package in a trusted module checks and lowers to the same Go (std `TestStdCopyAgrees`). In an untrusted package it is S108 naming the line to write; in a package with no module it is S108 that says no `ergo.mod` can trust it. A trusted target outside `runtime/v1` (`runtime/rt` is the prelude's) or a body the runtime's table lacks is S108 with its reason.
3. **A module's own Go bodies.** A package binds a function of a Go package of its own module (the module of the `go.mod` beside `ergo.mod`), with no trust line: `trust go` is only for another module's Go. An **effect-free** body needs no row and no mark (LAWFFI LF2m; owner, 2026-11-19: "least amount of ceremony"): its file imports only Go's pure packages (`v1.PureImports`), it names no function or variable of its package at top level, starts no goroutine, uses no channel, takes no hidden argument and no function, and it is written in Go, not assembly; these rules are read from its source, by the checker. Any other body shows its effects in its own signature, where its callers see them: its extern declares `needs go.Foreign` (LAWFFI LF2m r2; AGENTS.md, public effect contracts are explicit), which only main provides. Such a body may take hidden arguments, under the same convention ([stdlib](stdlib.md), Hidden arguments and Calling policy; STD-NOPRIV NP4d). Its file names v1's hidden types through its import of `runtime/v1` (`*v1.Scope`, `v1.Site`, `v1.Sleeper`, `v1.ContextPackage`) and the task as `*rt.Task`, and states its waiting policy with `//ergo:wait KIND`:

   ```go
   //ergo:wait caller
   func Poll(t *rt.Task, n int) int { t.Check(); return n + 1 }
   ```

   ```
   extern go example.com/app/gohost.Poll func poll(n int) int needs go.Foreign
   ```

   The checker reads the package's Go files that go build compiles for the target, never a Go tool: a file whose name ends in another GOOS or GOARCH, or whose `//go:build` line excludes the target's GOOS, GOARCH or the `goexperiment` tags of `GOEXPERIMENT` in the environment, is not read, so a body that a vector file and its stock twin both declare is read from the one that is built (U1 SIMD-SCAN, `TestModuleGoBodiesHonourBuildConstraints`). The lowering calls the body with its hidden arguments, by its policy, as it calls a `runtime/v1` body. The body is a plain exported function: no method and no type parameter, no `Releaser`, and no release route, bridge or owned form, which are the runtime's own. Its Ergo parameters are basic types or slices of them, and its one result at most a basic type, each spelled as the body spells it (`duration` is `time.Duration`; `[]byte` and `[]uint8` are one type), and the extern has no failure row. A slice argument is passed as a copy (Go's `slices.Clone`), since the module's Go may write or keep it. It is call-only. No review makes it pure: an effect-free body is pure only where a law against an Ergo reference admits it (5). Each refusal is S108 with its reason: a body that is not effect-free and declares no `go.Foreign` names its effect and the row to write, and such a body with no `//ergo:wait` names the mark (an effect-free one waits on nothing and needs none). The Go files join the program's analysed text, so a change to a body changes the build's key.
4. **Not yet.** A required module's trust (CORPUS MD3), a module body of other types than basic ones and slices of them, a slice passed to a body without its copy (a guarded test form, as Foreign facts 8's view), a licence driver for a body bound in another package than the law's, and `ergo inspect deps` showing the toolchain's line are follow-ups.
5. **Pure by a law** (LAWFFI LF2m; owner, 2026-11-19: "if we can make our laws prove unsafe then it should be available userspace as well"; STD HAS NO PRIVILEGES). A top-level rewrite law ([types.md](types.md), Laws 14) whose left side is an Ergo reference and whose right side calls the body, `law IndexByteIsRef(s []byte, c byte) { indexByteRef(s, c) } == { indexByte(s, c) }`, is in the rewrite's scope when the body is effect-free. `ergo test`'s licence run (runtime.md, Tests 7) runs the body itself: it compiles the package's effect-free bodies into a driver, with the toolchain the program builds with, and calls it, one process per ambient state, so the verdict is the body's own run. Only a current `validated` entry admits the rewrite, which then calls the Go kernel wherever the reference is called (the IR path); the entry's key holds the hash of the module's Go files (Foreign keys), so an edit of the body makes it stale until the next `ergo test`. A refuted law stops the build, and the shadow check of each test build compares the two sides at every rewritten site.
6. **A verdict's build** (LAW-BUILD-KEY; orchestrator ruling 2026-11-19). A law's ledger entry is keyed by the build it was given in exactly where the Go code it reaches may differ between builds, read from the files each build compiles ([runtime.md](runtime.md#tests) Tests 10, `under`). The line is drawn at the trust boundary. *Assumption:* a verdict over Go standard library code holds on every platform of the same Go version: std's exported behaviour is specified to be the same on every platform, and the toolchain that compiles every emitted program is trusted to keep it, so a std entry is keyed by the Go version and the toolchain alone and serves every platform. The runtime's Go (`runtime/v1`, `runtime/rt`) and a module's own packages have no such contract: their key names the platform and the experiments when another supported platform, or the stock build, compiles the reached declarations differently (`exchange_linux.go` and `exchange_darwin.go`; a vector kernel and its stock twin). A required module from `go.sum` is third-party Go the keys do not read: its entries always name the build.

*Prior art:* OCaml's `external` and Gleam's `@external` give any module the binding std has, with no vouching; Roc's platforms are the one place host code enters, chosen by the application; Go's `//go:linkname` into the runtime is refused for new code outside a list the toolchain keeps. Ergo keeps the binding open, as OCaml and Gleam do, and names the vouching in the root's file, as Roc names its platform.

## Go-backed providers

Status: **implemented** (STD-NOPRIV NP4e; GAP17). A provider of an Ergo operation type may call Go: `func Read(d Disk, path string) string fails Missing needs go.Foreign`. Its operation type writes no capability row, so `go.Foreign` is charged where the provider is built, the conversion to the operation type (a context entry, an argument, a binding, a return), and only there ([types.md](types.md) Capabilities 4; [rows.md](rows.md) Context 2). This is how host providers charge `Ambient` at `NewHost`. `with context { files.Files: disk.NewDisk(root) } { … }` needs `go.Foreign` in the enclosing row, and the calls inside need nothing more. A constraint `[P Files]` is not a build, and admits no such provider. The operation type's laws report the provider as a skip with that reason, because a law case never holds `go.Foreign` ([types.md](types.md) Laws 10). Any other capability that a provider method needs stays with context construction.

## Go calls Ergo

1. **An Ergo value as a Go interface.** A value of a type of the program converts to a Go interface type of `import go` when the type declares it, as for an operation type ([types.md](types.md#interface-assignability) 1, EXC1): `io.WriteString(w, s)` with an Ergo record `type W { … } implements io.Writer` that has `func Write(w W, p []byte) int fails go.Error needs go.Foreign`. A provider needs nothing but `go.Foreign`. The lowering wraps the value in an adapter, one Go type per Go interface, whose methods call one Go callback per operation, made at the conversion as a callback is ([Callbacks](#callbacks)): the method runs the Ergo function on the task of the code that converted it, Go's arguments and results cross as a callback's do (a `go.Error` is Go's own error, a slice a copy), a failure is Go's error, and a defect is a Go panic through Go's frames. A Go value converts to a Go interface by Go's own conversion. One rule covers every value whose operations come from Ergo: (a) a value of a type of the program that declares the interface and whose functions provide its operations (a record, a named type, a generic type's instance, whose generic functions are called at the instance, or a borrow of one, read at each call) converts through the adapter, and the function that converts it binds its task, so it is never a pure function; (b) a sealed std value (`json.Cursor`) converts where the member match admits it, as its runtime type; (c) a value of an Ergo operation type (a generic one's instance or a borrow included) or of a type parameter (whose operations are its witness's) does not convert to a Go interface with methods (S108, "the operations of S take Ergo's calling convention, not the Go methods of fmt.Stringer"): no function of the program provides them for an adapter, so the program converts the value whose functions provide them instead (batch-16b r3, r4). Go's `error` is `go.Error`, an error value, not an interface: no Ergo value converts to it (S108, "go.Error holds a Go error, which a Go call or go.Error{Text: s} makes"). `TestValuesIntoGoInterfaces` is the property of the rule: every value kind into `fmt.Stringer`, `io.Writer`, `io.Reader`, `sort.Interface`, `go.Error` and a Go interface of the user's own Go package is refused with its reason or lowers to Go that type-checks.
2. **A library.** `ergo lib FILE|DIR -o DIR` writes the program as a Go module at DIR whose module path and package name are the file's or folder's name, with no Go `main`. Each exported function of the root package whose signature Go can spell (the basic types, slices of them, and Go's own types: a type of `import go`, a `go.Ref` of one, a borrow of one), that is not generic, and that needs at most `Console`, `Ambient` and `go.Foreign` (what the host provides an entry, rows.md Entry 4), is a Go function of the same name with a `context.Context` first and an `error` last: `func Hello(ctx context.Context, name string) (string, error)`. Every other exported function is listed in the emitted file as `// Not exported to Go: F: <reason>.` A slice result crosses as a copy (Go may write it, and it may share an Ergo value); an argument crosses as is, since the Ergo call keeps nothing of it. The package-level lets run once, in the task of the first call. When they end in a defect (or the first call is interrupted while they run), that call fails with it, and every later call fails with the same panic value, raised again in its own task: the lets never run twice, and no call reads a let they did not set. Go's own package `init` panic stops the program, so no Go call sees such a let either. The library is lowered through the IR, the build path (LIB-ON-IR): the patched compile builds its IR bodies, and the emitted file holds them printed as Go text, so a Go program builds the module with a stock go. `TestGoCallsErgo` runs one Go host against the IR library and the source emitter's, with the same output, and `TestIRLibraryAgreesOnExamples` holds the two to the same Go API on every example package.
3. **The host entry.** An exported Go function runs the Ergo function as a new root task on the calling goroutine (`v1.Call`): a host that calls it from its locked main thread (a GUI loop) runs the Ergo code on that thread, and the tasks it starts end before the call returns. A typed failure returns as the error; a defect as the defect error that names the Ergo call sites; an interruption as `rt.Interrupted`.
4. **Inbound cancellation.** When the Go caller's `ctx` is done, the task is interrupted, as by a timeout (runtime.md I1): the Ergo code unwinds at its next interruption point, its releases run, masked, and the call returns `ctx.Err()`. A `ctx` that is never done costs nothing (no goroutine, no registration); the registration (`context.AfterFunc`) is removed before the call returns, so a `ctx` not done during the call leaves no goroutine, and one done during it interrupts from the goroutine `context.AfterFunc` starts; the call waits for that function to end before it returns, so no part of the call runs after it (control: a handler blocked in `Scheduler.Sleep` is interrupted when the Go request is cancelled; its release runs; nothing leaks).
5. **Limits.** An adapter's method runs on the converting task; a Go interface value that Go keeps and calls after that task ended runs on the ended task (as an escaping callback would; IG6). An exported function over an Ergo record, union, Map or function is not exported in v1. Two Ergo libraries in one Go program each carry the runtime under the one module path `ergo.local/prototype`, so they must be built by the same compiler.

*Prior art:* Gleam and ReScript export every public function in the host's module format (an Erlang function, a JS export) with no wrapper; cgo's `//export` and Kotlin/Native's framework export write a C-callable wrapper per function, as `ergo lib` writes a Go one; Effect's `runtime.runPromise` takes an `AbortSignal` that interrupts the fiber, as the `ctx` does here; Kotlin's `runBlocking` runs a coroutine on the calling thread. Elixir has no inbound case: Erlang calls Elixir as any module.

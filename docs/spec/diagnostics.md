# Diagnostics

Status: S001 is **implemented** by the parser `internal/sketch/syntax` ([#195](https://github.com/cevr/ergo/issues/195)). The other codes are **implemented** by the checker `internal/sketch/check` ([#196](https://github.com/cevr/ergo/issues/196)), which `ergo check` and `ergo diagnostics` run. The checker's code table (`internal/sketch/check/codes.go`) mirrors this page; a test keeps the table, the emitted codes and the rows below in step. `ergo build` and `ergo run` run the checker first, then lower the checked program from the checker's output (`internal/sketch/lower`, check-v1); a form the lowering does not lower yet is refused at build with S109 naming the ticket or stage that owns it, at its position, and nothing is written (`internal/sketchfront`). The checker's fixtures are in `internal/sketch/check/testdata/fixtures`; the prototype's fixtures (first line `// want CODE`) keep their outcome except the changes [the parity table](../../internal/sketch/check/testdata/parity.overrides) lists. The main compiler maps each rule to a code in its EF registry ([#79](https://github.com/cevr/ergo/issues/79); README Gap 18).

A diagnostic has a position, a code and a message: `file:line:col: CODE message`. A file with any diagnostic does not build. The checker reports every diagnostic, sorted by position; an invalid operand or type suppresses every diagnostic that would follow from it, so one mistake gives one diagnostic (D3). A refused binder is one such mistake: a read of its name in a value position adds nothing, and everywhere else (a type position, a later pattern, binder or type test) the name means what it means without the binder and gives the diagnostics it gives then ([rows: totality](rows.md#totality) 6). A type whose declaration is refused (an invalid underlying type, or a union that lost every variant) adds no diagnostic where it is used, as a case of a union that lost a variant adds none (S103). Prototype fixture paths are relative to [`prototypes/sketch9/testdata`](../../prototypes/sketch9/testdata); checker fixture names are files in `internal/sketch/check/testdata/fixtures/negative`.

## Rules by code

Each rule names a fixture where one exists.

### S001: syntax

The parser `internal/sketch/syntax` ([#196](https://github.com/cevr/ergo/issues/196)) reports S001 with a specific message ("expected X, found Y"), a byte offset and length, a line and a byte column. It reports the first error only. The formatter refuses a file with S001 on every surface, naming the code and position.

- An identifier is tested on decoded code points; a code point that cannot start or continue it, or invalid UTF-8, is S001 (`probes/nonletter-name.ergo`).
- A composite literal mixes keyed and positional elements (`probes/mixed-fields.ergo`).
- A Go habit outside the decided grammar: the message names the Ergo form, as `x := e` names `let x = e` and `defer f()` names `scope.OnExit` ([grammar: Old spellings](grammar.md#old-spellings) holds the whole table).
- An old Ergo-only spelling (`error[…]` rows, `wire Name { A = x }`, `catch e { … }`, `uses`, `try` in operand position): the plain S001, with no rename hint (#217).
- A keyword or reserved word used as a name (`let match = 1`), and a word that is not in the language (`enum`) where a declaration or statement starts.
- A context literal with `needs` before `provides`.
- A form the decided grammar does not admit: a local type declaration, a `~` constraint, a type parameter list on an operation, a trailing block without the call's parentheses (`task.Go { … }`), a statement-leading `if`, `match` or `for` continued by an operator, selector or call, `case limit + 1:` (a case lists patterns), a type that is not a type name in a `fails` row or a union (`fails []int`, `type U = []int | B`).
- A top-level law with type parameters, `law L[T](x T) { … }`: "a law has no type parameters; state it at concrete types, or as a member of the protocol's operation type", at the `[` (law-top; [grammar](grammar.md#declarations) rule 11). A token that starts no declaration at top level: "expected a declaration (type, func, extern, test, law or let), found …".
- A malformed construct: an unknown or duplicate machine entry, a machine without `step`, a capability row written with commas or parentheses (`needs A, B`, `needs (A | B)`; 196n).
- An unterminated string or block comment, a newline inside an interpreted string, an unknown number suffix (`5kg`), an unexpected character, an import after a declaration.
- A tree higher than 1000 levels, in any composition of chains, operators, parentheses, types, statements and blocks ([grammar](grammar.md#parser) rule 5).

A type that mixes fields with operations or laws is S108 from the parser ([grammar](grammar.md#declarations) rule 5). The fixtures are `sketchtest.MalformedTable` (`TestMalformed`) and `testdata/refuse` (`TestRefusedFixtures`) in `internal/sketch/syntax`.

### S101: undeclared error

- An error escapes through `try` and is not in the declared row (`reject/undeclared-error.ergo`, `undeclared-error`).
- A function returns a value of an error type, a type named in an error row of its package, and its row does not list it (`probes/error-as-value.ergo`).
- A partial `try … catch` leaves an undeclared error (`partial-catch-rest`).
- An inline context's provider expression can fail, and the enclosing function does not declare it (`probes/context-initializer-error.ergo`).
- A named context's provider can fail while it is built: a named context is closed (`probes/named-context-failure.ergo`; README Gap 6).
- The step of an exported machine type spells its rows (the export guard), so an error it does not list is S101 (`export-guard-machine-step`).

### S102: missing capability

- A body calls a capability its capability row does not list (`reject/missing-capability.ergo`, `missing-capability`).
- A callee needs a capability that no `with` provides (`reject/unprovided.ergo`, `unprovided-callee`).
- A provider expression of an inline context needs a capability of its own context (`probes/context-sibling.ergo`) or one the enclosing function lacks (`probes/context-initializer.ergo`).
- A named context needs a capability from its caller: a named context is closed (`probes/named-context-requirement.ergo`; README Gap 6).
- A provider expression of a local context needs a capability that neither a `with` around the `with` that builds it nor the function's written row provides: S102 at that `with` operand, once per such `with`, never at the `let` ([rows.md](rows.md#context) rule 9; `testdata/v1/Esub5-context-charge.neg.ergo`, `TestLocalContextChargeSite`).
- The with scopes of a package need more than its with budget to compute: "the with scopes of this package need more work than its with budget to find which with binds each capability; split this with or the contexts it names (D16)". The budget is 16 × the package's source bytes + 65536 steps of push work (a node of the scope read, split or merged), fixed by the source alone; each step is charged before it runs. The S102 is at the first `with` operand, in the order the bodies are checked, whose push would pass the budget, once per package; every later push that needs a step leaves its frame unknown, so no diagnostic cascades from those withs. Whether a package is refused does not depend on the order of its declarations ([rows: with](rows.md#with) 10; checker tests `TestWithBudgetRefuses`, `TestWithBudgetPrefixes`, `TestWithBudgetHeadroom`).
- `timeout.After` without `Scheduler`: `timeout.After` is an ordinary library function whose row lists `Scheduler` (`timeout-is-a-library-function`).
- An inferred capability reaches an exported function, which spells its row (`inferred-needs-reaches-exported`).
- A law calls a package function that charges a capability, or a capability operation such as `Store.Get()`, outside a `with` of the law that discharges it: "this call requires main.Store, which is not in the capability row of law Bare and no with provides it". A law needs no service; a call of an operation of its own type charges nothing ([types](types.md#laws) rules 6 and 7; `TestLawRules`, `TestLawDomain`).

The checker does not restrict `main`'s capability row; the build refuses what the host cannot supply (README Gap 5).

### S103: not total

- A `catch` without `try` omits an error of the caught row (`reject/catch-not-total.ergo`, `catch-not-total`).
- A `match` names neither every constructor nor `case _`: a union's variants, nested through record patterns, `bool`'s two constants, a tuple's product; constants of other types never cover ("constant patterns never cover int; add case _"). The message names one missing pattern (`type-switch-not-total`; check-v1 D-B4).
- A `let` or `for` pattern that does not cover its value's type: "this let pattern does not match main.Pending, a value of main.Payment: a let pattern matches every value; use match" (check-v1 D-B5).
- A multi-subject `match` leaves a tuple of variants unhandled; `_` matches any variant. Totality is decided by a usefulness check over the case matrix, never by enumerating the product (`product-not-total`). The message names one missing tuple.
- A `match` whose proof, or the resolution of its cases in the variant index, needs more than the source budget for proof work and allocations: "too many cases to prove this match total; split it or add case _", or, when the reachability of its cases needs more, "too many cases to prove which cases of this match are reachable; split it". The checker never accepts a match it has not proved. The solver is deterministic for a given source; reordering the subjects may change whether a switch near the budget is refused, never a proved verdict ([rows: totality](rows.md#totality) 5). A case of a union that lost a variant to a reported error adds no diagnostic of its own (D3). No missing-return diagnostic follows an S103 for the same switch (D3).

### S104: unknown name

- An unknown local, function, type, field, method, package or context (`reject/unknown-name.ergo`, `unknown-local`, `unknown-type`, `unknown-field`, `unknown-selector`, `unknown-context`).
- Outside its package, an unexported field read, written, named as a keyed literal's key or in a record pattern, "units is not an exported field of lib.Q", and an unexported operation called, "inner is not an exported operation of lib.Ops" ([grammar](grammar.md#visibility) Visibility 2; 196b Q6; `TestFieldVisibility`). A type of another package that would implement an operation type with an unexported operation is S108, "inner is an unexported operation of lib.Ops, so only a type of package lib implements it".
- A Go built-in function other than `len`: `make`, `new`, `cap`, `copy`, `close`, `print`, `println`, `append`, `delete`, `min`, `max`, `clear`, `panic`, `recover`, `complex`, `real` and `imag` are not predeclared. The message names the Ergo form: `xs.Append(x)`, `m.Delete(k)`, a literal, `Console.Println`, `if a < b { a } else { b }` (#196, fourth round, item 2).
- A bare call of a prelude function on slice and Map types, `Append(xs, x)`, `Get(m, k)` or `Delete(m, k)`, which is reached only by the dot form the message names (check-v1 D-D6, D-D8; `TestPreludeDotCallRefusals`).
- A dot call of a prelude function on slice and Map types on a defined type over a slice or Map, whose message names the assignment to the unnamed type: `let raw []int = xs; then raw.Append(…)`, choosing `raw2`, `raw3`, … when the earlier names are bound (check-v1 D-D8; `TestPreludeDotCallRefusals`, `TestRepairTextsCheck`).
- A capability name in an expression position other than a method call's receiver, such as `f(Orders)` (`capability-as-value`; README Gap 29).
- A local of the same name as a capability that the function's written row lists, in the same frame (`local-and-binding-one-frame`; rows-and-constraints §7 amendment 3). A binder in an inner scope that reuses the name is S108 (no shadowing, check-v1 D-D2).
- A capability row or a context entry key names a type that is not a capability (`needs-non-capability`, `context-entry-non-capability`).
- An error row names a type that is not a named struct type (`error-row-non-struct`).
- A law's name in any body, `RoundTrip(1)` ("unknown name RoundTrip"), or as a member, `Codec.RoundTrip`: law names have their own namespace and declare no value. A law parameter written as a lone name is a type, so `law L(v)` is "unknown type v", as `func f(v)` is ([types](types.md#laws) rules 2 and 4; `testdata/v1/E5-laws.neg.ergo`, `TestLawRules`).

### S105: unhandled failure

- A fallible call in a struct field value (`probes/composite-error.ergo`).
- A fallible `timeout.After` duration (`probes/fallible-duration.ergo`).
- A fallible expression as a `let` value, an expression statement, an operand, a selector receiver, a call argument, an `if` condition, a `match` subject or a `catch` arm value (`unhandled-define`, `unhandled-argument`, `unhandled-condition`).
- A call of an unexported helper whose inferred error row is not empty, in an exported function that does not handle it (`inferred-error-reaches-exported`).
- A fallible tail of a law, untried: a law's tail is a value, so `Decode(Encode(v)) == v` with a fallible `Decode` is written `try Decode(Encode(v)) == v` ([types](types.md#laws) rule 8; `TestLawDomain`).

### S106: bad provider

- A provider method's parameter types differ from the capability's (`probes/provider-parameter.ergo`).
- A provider without the capability's method, or whose method's error row is wider (`provider-missing-method`, `provider-wider-row`).
- A provider method that writes a capability row: its row is wider than the capability method's, which writes none (`provider-method-needs`; README Gap 17 stays with #37).

### S107: missing return

- A body that needs a value and whose path ends in a statement with no value (`missing-return`; check-v1 D-C1): a function or function literal with a result, a branch of a value `if` or `match`, a trailing block with a known result, a `catch` arm whose value is used (review m1). A body yields its last expression; a final `if` with an `else` and a total `match` yield through their branches (D-C2); a branch that ends in `return`, `break` or `continue` leaves. An `if` without `else` as a body's tail is S107 at the body's closing brace (`C1-tail-result.neg`). Other final statements terminate as in Go: a `for` without a condition or `break`.

### S110: unused

- A local is declared and never read (`unused-local`; `probes/same-local-as-cap.ergo`).
- An `as` binding is read in no case (`unused-type-switch-binding`).
- An expression statement is not a call, `try`, `catch` or `with` (`unused-expression`, `probes/unused-expression.ergo`).
- An import is not used (Go's rule).
- A `let mut` local is never reassigned: "n is never reassigned; write let n". An assignment through a field or an index, and a borrow, count, the implicit one of a call `x.f(…)` in every spelling (`(x.f)(…)`, `x.f[T](…)`) included, also inside a callback the checker could not type; a `let mut` read nowhere keeps only its unused diagnostic (check-v1 Q3; `D10-mut-reassigned.neg`, `TestLetMutNeverReassigned`).

*Prior art:* Go rejects unused locals, imports and unused expression values; Rust and Gleam warn instead. Ergo keeps Go's errors because its output is Go and because an unread value usually hides a dropped result.

### S111: duplicate context entry

- A context has two entries for one capability, and neither is a `replace` of an embedded entry (`duplicate-context-entry`; README Gap 28).
- Two embedded contexts bind one capability, and no `replace` entry of the embedding context overrides it (rows.md, Context 7).
- A context whose embedding graph needs more than the package's fixed context budget to check: "this context's embedding graph is too large to check for duplicate entries; split it". The budget is 128 × (context declarations and literals + entries + embeddings + capability names written in context entry keys and `needs` rows + 1) steps of repeatable work (set nodes, union elements, probes against a summary, sorts), shared by every context of the package and fixed by the source alone; each such step is charged before it runs, and the pass's single-pass reading of the context source is at most 12 × the same size. The S111 is at the context whose summary or body was being checked when the next step would pass the budget, or at each inline context of the declarations of one name, and no other context diagnostic follows from it. Neither the verdict nor the place of the S111 depends on the order of the declarations ([rows: context](rows.md#context) 5; checker tests `TestContextBudget`, `TestContextBudgetRefusal`, `TestContextBudgetPrefixes`, `TestContextBudgetOrder`).

*Prior art:* Google Context rejects two providers of one type; Effect's `Layer.merge` keeps the last silently, which Ergo refuses. For the budget: TypeScript stops instantiation past a fixed count (TS2589), and rustc refuses past `recursion_limit` (default 128). For the order: Elixir's typer sorts definitions before its recursive traversal (module/types.ex).

### S112: resource map key

Designed: a map's key type must not be a resource in v0 ([resources: containers](resources.md#containers), README Gap 32). It is emitted when [#197](https://github.com/cevr/ergo/issues/197) implements resources.

### S113: entry and test functions

- `main` takes parameters (`main-parameter`) or type parameters.
- `main` returns a value; only an error row is allowed, as Go's `main` returns nothing (`main-value-result`; README Gap 4).
- `main` is called (`main-called`, `probes/main-call.ergo`); only the host calls it.
- `main` is used as a value, such as `run := main` or `call(main)`: a value would let ordinary code call it.

*Prior art:* Go's `func main()` takes nothing and returns nothing (Go still allows a call of `main`; Ergo refuses it, so the host is its only caller); Gleam's `main` takes no arguments.

### S114: construction authority

Outside the package that declares it, a record with an unexported field, a defined type over one, and a type that holds one by value are built only by that package ([types](types.md#zero-values-and-definite-initialisation) Zero values 6; 196b Q7). Each message names the package and up to three of its exported functions whose result is the record: "lib.Q has an unexported field, so only package lib builds it; use lib.ParseQ" (`TestConstructionAuthority`, `TestConstructionAuthorityShapes`).

- A literal of the record or of a defined type over it, keyed, positional or empty: `lib.Q{N: 1}`, `lib.Q{}`, `M{}` with `type M lib.Q`. A key that names an unexported field is also S104.
- A record update of it, `lib.Q{..q, N: 2}`, even of exported fields only.
- An implicit zero value: `let q lib.Q` with no value, in a body or at package level, also in a tuple type or an instance (`let b Box[lib.Q]`), and a keyed literal of an enclosing record that leaves a field of such a type unset (`H{B: 1}` with `A lib.Q`).

Not S114: a value an exported function returns, a conversion between a defined type and its base, a pattern, a copy, and a literal or update of an enclosing record that sets the field. A record with a field of a non-defaultable type that is left unset stays S108 (Zero values 2), which comes first.

*Prior art:* Rust refuses a struct literal and a functional update with a private field outside its module (E0451); Gleam's `opaque` types hide their constructors; ReScript's abstract type in an interface file hides the representation; Elixir builds `%S{}` anywhere; Go builds `Q{}` from another package.

# Standard library outline

Status: **designed, not yet implemented**, except the prelude's `Console` (`Println`) and the `Sleep` of its live scheduler, which `ergo build` lowers ([runtime.md](runtime.md#host-and-lowering-notes)). `ergo build` lowers `timeout.After` to its `runtime/v1` body, which takes its deadline from the program's `Scheduler` ([runtime.md](runtime.md#timeouts); `TestTimeoutAfterLowers`, `TestTimeoutDeadlineIsTheProgramScheduler`). The four v1 packages `task`, `scope`, `queue` and `slices` (named `slice` until std-align S2a) have Ergo signatures, which the checker checks like user code, bound to Go bodies in `runtime/v1` ([v1 packages](#v1-packages-task-scope-queue-and-slice)); `ergo build` lowers their calls (check-v1 stage D3b; `TestTaskGoAndTaskResults`, `TestErgoRunQueueOperations`, `TestErgoRunSliceWithCapacity`). The context packages `trace` and `log` lower too (#199 stage 4a; [Context values](#v1-packages-task-scope-queue-and-slice)).

The standard library is the "Effect for Go" track, [#206](https://github.com/cevr/ergo/issues/206). Its module map is the contract: each family states the Effect modules it covers, the construct it uses and its tier. Modules are restated in Ergo's idioms, not ported API for API. Effect is prior art for the guarantees, not a dependency (owner, 2026-10-26). Go names are kept wherever Go has one. Definitions are in the [glossary](../../GLOSSARY.md).

**Tiers.**
- **kernel**: a checker or runtime rule the module needs.
- **library**: ordinary Ergo code over the kernel, with no compiler branch keyed on its identity.
- **host**: a host package, the only code that calls Go.

## Prelude

The prelude is in scope in every package without an import: `Option`, `Range`, `Seq`, `Task`, `Decision`, `Timeout`, `Machine`, `InputMachine`, `Scheduler`, `Random`, `Console` and `Ambient` (`Clock` is `time.Clock` since std-align S2b; [time](#time)). `Ambient` is the authority to choose the host, which only the entry provides ([Host packages](#host-packages)). The function `Unreachable(reason)` states that a path cannot run: its call has the bottom type, and it raises a defect, never a typed failure ([types.md, Unreachable](types.md#unreachable); owner q29). Its functions on slice and Map types, `Append`, `Get` and `Delete` (below, Slices and Maps), are in no scope: they are reached only by the dot form, `xs.Append(x)`, so a package may declare its own function of the same name (check-v1 D-D6, D-D8). The same holds for a prelude function on a prelude type, which is that type's operation (196m): `Sleep` is `LiveScheduler`'s, reached as `s.Sleep(d)` on a `LiveScheduler` value `s` or through a context that binds `Scheduler: NewLiveScheduler()`; `NewLiveScheduler` needs `Ambient` ([Host packages](#host-packages) 6). A bare `Sleep(…)` is S104 naming the dot form, and a program may declare its own Scheduler provider with its own `func Sleep(s Instant, d duration)` (checker-fixes prelude-scope S1). `check.IsPredeclared` reports the names the prelude and the universe predeclare, for tools such as bind-c. The capabilities are ordinary interfaces bound by `context` (decision #102), so a test replaces any of them ([#209](https://github.com/cevr/ergo/issues/209)).

## v1 packages: task, scope, queue and slice

Language v1 ([#196](https://github.com/cevr/ergo/issues/196)) has four small std packages beside the prelude. A file imports each one it uses; none is ambient (parse-v1 ruling 6). Each pairs ordinary Ergo signatures with a Go body in `runtime/v1`, bound by the identity of the declaration it implements, never by its target text ([runtime.md](runtime.md#host-and-lowering-notes), Extern bodies). The signatures are `extern go` declarations in `internal/sketch/std/task`, `scope`, `queue` and `slice`; the checker checks them, and a program that imports them, with the rules of user code. Their calls lower (check-v1 stage D3b), and their waits take the caller's task (#199 stage 2).

| Package | Signatures | Contract | Go body |
| --- | --- | --- | --- |
| `task` | `func Go[T, E, R](body func() T fails E needs R) Task[T, E] needs R`; the prelude's `Task[T, E]` has `Wait() T fails E` and `Stop()` | [runtime.md, Tasks](runtime.md#tasks) rules 7 to 12 | `Go(s *Scope, span Site, body func(*rt.Task) (T, error)) *Task[T]`; the methods `Wait`, `Stop` and `Move(dest *Scope)`, the return of a Task, which only the lowering calls (task.go) |
| `scope` | `func OnExit[R](body func() needs R) needs R` | [runtime.md, Exit actions](runtime.md#exit-actions) | `OnExit(s *Scope, body func())` (task.go) |
| `queue` | `type Closed {}`; `type Queue[T] { Push(v T) fails Closed takes v, Pop() T fails Closed, End(), Values() Seq[T], Poll() Option[T], Len() int }`; `func New[T](capacity int) Queue[T]` | [runtime.md, Queues](runtime.md#queues) | `New(capacity int) *Queue[T]`; the methods `Push(t *rt.Task, v T) error`, `Pop(t *rt.Task) (T, error)`, `Close()`, `Values(t *rt.Task) iter.Seq[T]`, `Poll() (T, bool)` and `Len() int`; `Closed` (queue.go) |
| `slices` | `func WithCapacity[T](n int) []T`, and the functions of [Slices and Maps](#slices-maps-and-cmp) | below | `WithCapacity(n int) []T` (data.go); the rest in collections.go |

**`Values`.** `q.Values()` returns the prelude's `Seq[T]` (lower-v1 Q1; [types.md, Loops and len](types.md#loops-and-len)): `for v in q.Values()` pops each value in turn, waiting like `Pop`, and ends when the queue is closed and empty; a `break` leaves the values not yet popped in the queue. Its Go body returns Go's `iter.Seq[T]`. A `for` over the queue is never an eagerly collected slice. The call evaluates its receiver once, where the Seq is made, and returns a Seq that calls the Go `Values` body each time it is iterated, with the task of the code that iterates it, so a stop of the iterating task ends a wait inside the loop, also when the Seq was made in another task (check-v1 stage D3b).

**Hidden arguments.** Some Go bodies need a value that the Ergo signature does not show and the lowering supplies at the call. The Go body names each one by its Go type, which no Ergo type lowers to, so the body's own signature is the binding; there is no attribute in the Ergo source:

1. `*Scope` is the **frame**: the frame scope of the innermost source function at the call ([Exit actions](runtime.md#exit-actions) 5). In an exit action's block, it is the scope of the function that registered the action; the scope itself routes to the action's frame. `task.Go` and `scope.OnExit` take it, and so does every function whose result holds a `Task`, as its hidden destination ([Tasks](runtime.md#tasks) rule 8): its return is `Task.Move(dest)`.
2. `Site` is the **site**: the call's Ergo identity, the calling function, the called declaration and the call's source position, such as `main calls task.Go at main.ergo:12:10`, the form of a call frame in a defect report. `task.Go` names the task by it, which a defect's task chain shows ([G2](runtime.md#g2-fork-tree-defects); [#230](https://github.com/cevr/ergo/issues/230)).
3. `*rt.Task` is the **task**: the task that runs the call. `Push`, `Pop` and `Values` take it, because a stop of that task ends their wait ([Queues](runtime.md#queues) rule 8). `ContextBound` and `ContextValue`, the bodies of the context reads in `trace` and `log` (below), take it because they read that task's context values.
4. `Sleeper` is the **scheduler**: the `Scheduler` capability of the caller's environment, which is the provider the program bound (`env.Scheduler`). `Sleeper` is a `runtime/v1` interface with the one method `Sleep(*rt.Task, time.Duration)`, so the program's own `Scheduler` interface satisfies it. Lowering supplies it to `After`, whose Ergo signature needs `Scheduler`, so the checker has bound it at the call. A body that takes it and whose signature needs no `Scheduler` is an internal compiler error (`TestStdExternsHaveBodies`). The deadline is time, and time is a capability (Q-S4-7): a test `Scheduler` controls it, as Effect's `TestClock` drives `Effect.timeout` and a Go test injects a clock.
5. `ContextPackage` is the **reading package**: the namespace of the package that declares the context-read extern, `std:` and its path (`std:log`; [runtime.md, G1](runtime.md#g1-context-through-with) 3). Lowering supplies it to `ContextBound` and `ContextValue`. Each binding is stored under the pair of its type's declaring package namespace and its protocol key, so a package reads only its own bindings. Std source does not spell a package prefix.

The hidden parameters come first, in this order, each at most once; a hidden type after an ordinary parameter breaks the convention. The parameters after them stand for the Ergo parameters, one each, in order. The Go results are the Ergo results, then `error` when the Ergo signature has an error row. A function parameter is a Go function under the same convention: the block of `task.Go` is `func(*rt.Task) (T, error)`, which receives the child's task, and the lowering adapts its function value to that shape (the block's providers are captured, never passed). An operation of a type that a std extern returns (`queue.Queue[T]`, the prelude's `Task[T, E]`) is the method of that name on the Go type the extern's body returns (`*Queue[T]`, `*Task[T]`), under the same convention, and the lowering calls that method directly (Types 3).

The lowering supplies these values from the caller's frame and the checked declaration:

1. **Every impure function takes the environment.** Every lowered function, method, function literal, function value, context builder and package initializer takes a hidden `env *Env` first, except a pure function; the environment holds one field per capability and the running task (`env.task`, a `*rt.Task`). `main` gets its task from `v1.Main`, and a `task.Go` block runs with a copy of the caller's environment that holds the child task. A pure function (no `fails`, no `needs`, no witnessed type parameter, no `Task` result (a row type parameter changes nothing: `flag.CommandUsage[C, E]` is pure; fu4b), an empty footprint, and only calls of pure functions of any package, of pure std bodies ([Pure bodies](#pure-bodies)), `len` and conversions; lower-v1 stage 5, fu-lower, batch-9 C3) takes no environment and is called with none. Purity is decided with each function's own package's facts, so a std function with an Ergo body (`strings.Cut`) and a function of an imported package are pure when their bodies are, and a caller of one is pure only when the callee is (`TestPureStdCallsKeepFunctionsPure`, `TestPurityAcrossPackages`). So `func Fold(n int) int` lowers to Go's `func Fold(n int) int`. Its function value keeps the one Go shape and discards the environment. No source name changes purity; the exception is decided from the Go method that the lowering emits. The host protocols are `Error() string`, `String() string`, `GoString() string` and every canonical method of go vet's stdmethods check (`ReadByte() (byte, error)`, `Seek(int64, int) (int64, error)` and the others). A pure function that lowers to a Go method whose name and Go signature meet a protocol exactly keeps the environment, so its type never joins the protocol by accident. A pure function that lowers to a Go method with a protocol's name and another signature stays pure, and its Go method name gets an underscore (`Seek_`, one more while a field or another function on the type has that name, as a renamed `Error` field does). A plain function, `func String(n int) string` included, is pure by the rule above. Kotlin draws the same line: it passes its hidden continuation only to `suspend` functions.
2. **A frame scope where one is needed.** A function that calls `task.Go`, `scope.OnExit` or a function whose result is a `Task` opens `fs := v1.NewScope(env.task)` and `defer fs.End(&err)` (`fs.End(nil)` when the function cannot fail), and passes `&fs` as the frame. The checker records per call whether the result holds a `Task` (`Info.Calls[x].TaskResult`, from the one owner of Task containment), for direct calls, calls through function values and function literals; the lowering never derives it again. A function whose result is a `Task` takes the caller's scope as a hidden destination after the environment, and its return is `v.Move(dest)`. A result that holds a `Task` inside another type (`Option[Task[T, E]]`) is refused with S109 naming check-v1 stage E, and so is a `Task` as a type argument.
3. **The site** of `task.Go` is `FUNC calls task.Go at FILE:LINE:COL`: the source function that makes the call, as the call table names it, and the position of the call.
4. **The task** of `Push`, `Pop` and `Values` is `env.task`.
5. **A hidden task is bound where the blocking happens, never where a value is made.** A std value that defers a runtime call takes its task from the environment it is called with, and evaluates its receiver and arguments once, where it is made, in source order:
   - The Seq of `q.Values()` calls `Values` with the iterating environment (above).
   - A method value of an operation, `q.Push` or `t.Wait` of a std operation type or `s.Area` of the program's operation type, is a function value of the uniform shape: it takes the caller's environment first, and calls the operation with that environment's task. One lowering writes every operation call, direct or through a method value. The checker still refuses `t.Wait` and `t.Stop` as values (a Task rule, [runtime.md, Tasks](runtime.md#tasks)), and `task.Go` and `scope.OnExit` as values: a generic function is only called or instantiated, and an explicit instantiation used as a value is S109 naming check-v1 stage E.
   - The block of `task.Go` is bound once, where `task.Go` is called: `let mut f = one; task.Go(f); f = two` runs `one`.
6. **A block with no value.** A type argument that stands for no value ([types.md, Generics](types.md#generics) 6) lowers to `struct{}`: `task.Go() { work() }` is a `*v1.Task[struct{}]`, and `t.Wait()` discards the `struct{}`. A declared generic function whose `T` is no value has its `func(…) T` parameters adapted to return `struct{}{}`, and its `T` result discarded. A `T` that is no value in any other position, such as the result of a nested function type or a type argument of a declared generic type, is refused with S109 naming check-v1 stage E.

`timeout.After` lowers to `v1.After(site, task, scheduler, d, body)` (lower-v1 stage 4, Q-S4-7). Its deadline is a second child of the caller's task that calls `Sleep(d)` on the scheduler argument; `rt.AfterSpan` races it against the body and drains both before it returns. So the deadline is the time the program's `Scheduler` gives: a test `Scheduler` decides when it passes, and the timeout test needs no real sleep. `v1.After` arms no host timer of its own. Its failure is `v1.Expired`, the `runtime/v1` struct that `timeout.Expired` binds (Types 4 below). A std extern that is neither an intrinsic nor a `runtime/v1` body is an internal compiler error, because `TestStdExternsHaveBodies` proves that none exists. `v1.BodyOf` (runtime/v1/files.go, compiler only) reads a body's shape from the embedded source, as the lowering reads it; `TestBodiesFollowTheHiddenConvention` pins each body's shape, and the test of `internal/sketch/std` ties each extern and operation to its body. *Prior art:* Gleam's `@external(erlang, "m", "f")` and ReScript's `external f: t = "f"` bind a host function by name with the signature the source states and pass nothing hidden; Go's own `iter.Seq` carries its stop through `yield`; Effect passes its fiber context implicitly through the runtime; Kotlin passes a hidden `Continuation` as the last parameter of a `suspend` function, the closest relative of the hidden task here.

**Types.** Each Ergo type in a std signature has one Go type, which the body writes and the lowering must use:

1. A basic type is its Go type (`int` is `int`), a type parameter keeps its name, and `[]T` is a Go slice.
2. A row parameter (`E`, `R` in `task.Go[T, E, R]`) has no Go type parameter: rows are erased (rows.md), so the body is `Go[T any]`, and `Task[T, E]` is `*Task[T]`. The type parameters left after erasure are the Go ones, with the same names in order and the same constraint (none or `any` is `any`, `comparable` is `comparable`, `ordered` is `runtime/v1`'s `ordered`, whose terms are Go's `cmp.Ordered`'s and the lowering's generated set's), so the checker admits a type argument exactly when the Go call compiles: `slices.WithCapacity[[]int](3)` is valid on both sides, and so is `slices.Sort` of a slice of a type parameter `T ordered`. An operation takes the type parameters of its type (`Queue[T]`, `Task[T, E]`). An error row is the last Go result `error`; a capability row is captured by the lowered block, never passed.
3. An operations type that a std extern returns (`queue.Queue[T]`, the prelude's `Task[T, E]`) is the runtime type that the extern's body returns, `*v1.Queue[T]` or `*v1.Task[T]`; the lowering emits no interface for it. A returned Task needs the concrete `*v1.Task[T]` to `Move`, and `Close`, `Wait` and `Stop` take no task, so one emitted shape would need an adapter per type. These are the sealed std protocols (`check.SealedStd`): a value of the program converted to such a type is refused with S109 naming [#206](https://github.com/cevr/ergo/issues/206) ("… it is a sealed std protocol; a program value implements it in #206"). An operations type of std that no std extern returns (the prelude's `Console`, `os.Process`) is open: a program value implements it, as for a Go interface ([os](#os) 5); a type defined over one and a pointer to one are S108 (types.md, Defined types 1 and Operation types).
4. A record type declared in a std package, which is not an operations type, is the exported `runtime/v1` struct that its row of the **binding table** names, with the same fields: `queue.Closed` is `v1.Closed`. The lowering never generates a struct for it, because `Push` and `Pop` return `v1.Closed{}`, and a `catch` arm `case queue.Closed:` must match that value. An error type's Go text is its Ergo name: `v1.Closed{}.Error()` is `queue.Closed`. The table (`v1.StdRecord(pkg, name)`, runtime/v1/files.go; std-align S3b) keys a row by the record's package and name, never by the name alone, so two packages may each declare a `NotFound` and bind two Go types; the Go names are unique because the table says so, not by a naming habit. A std record with no row, such as `strings.Halves`, is a declaration of the program. `TestStdRecordTable` holds each row to an exported record of its package and a struct with its fields, no struct to two rows, and every `runtime/v1` struct with an `Error` method to a row, so a `catch` arm can name each failure a body returns; lower `TestStdRecordsKeyedByPackage` lowers two std packages that each declare `NotFound` and catches each in its own arm. Extern bodies need no table: an extern names its Go body in its target (`v1.StringsSplit`), and Go needs that name to be unique in `runtime/v1`, so a body name carries its package (`Strings`, `Filepath`, `FS`).
5. The prelude's `Option[T]` as the result of an operation of a std type is Go's comma-ok `(T, bool)`: `queue.Queue[T]`'s `Poll() Option[T]` is `Poll() (T, bool)` (std-align S3d). `Option` is a union the program emits, so no `runtime/v1` body can name it; the lowering calls the method and adapts its results in place to `Some{Value: v}` when the bool is true and to `None{}` when it is false, through the helper that also lowers the prelude's `Get` (`optionReturn`), so a later change of `Option`'s Go form changes both. The `None` path allocates nothing (`TestQueuePollNoneAllocatesNothing`). A `(T, bool)` body for any other Ergo result is an internal compiler error. *Prior art:* Go's `v, ok := m[k]` and `v, ok := <-ch`; ReScript lowers `None` to JavaScript's `undefined` and `Some(v)` to `v` with no box, which Go has no general form of; Gleam lowers its `Option` as an ordinary custom type (on Erlang the atom `none` and the tuple `{some, V}`), and its Erlang externals return that form themselves.

The std test compares each Ergo type parameter, parameter and result type with its body's Go one under these rules (`TestEachExternHasItsGoBody`), and ties each record of a v1 package to its Go struct and text (`TestStdTypesBindRuntimeTypes`, through `v1.StructFields`).

**Slices and Maps.** `slices.WithCapacity[T](n)` is an empty slice with room for `n` elements; it makes no element, and a negative `n` is a defect, as Go's `make` panics. There is no `slices.Repeat`: not every type has a zero value (parse-v1 ruling 7). The prelude's `xs.Append(x)` returns the slice with `x` at the end, `m.Get(k)` returns `Option[V]` and `m.Delete(k)` returns the Map without `k` (check-v1 D-D6). They are prelude functions, `func Append[T](xs []T, x T) []T`, `func Get[K comparable, V](m Map[K, V], k K) Option[V]` and `func Delete[K comparable, V](m Map[K, V], k K) Map[K, V]`, reached by the dot form of a function on a type ([types.md, Methods](types.md#methods)) from a value whose type is exactly an unnamed slice or Map type; the bare call `Append(xs, x)` is S104 naming `xs.Append(x)`. `Append` takes one element. A defined type over a slice reaches `Append` after assignment ([types.md, Assignability](types.md#assignability) clause 2): `let raw []int = xs`, then `raw.Append(x)`; a defined Map uses `let raw Map[string, int] = m`, then `raw.Get(k)` or `raw.Delete(k)` (check-v1 D-D8). `Append` and `Delete` have Go bodies in data.go. `Get` builds the program's own `Option`, so its body is lowered in the program, as the comma-ok read `v1.Get` is. All three are pure ([Pure bodies](#pure-bodies) 5). A slice and a Map are values ([types.md, Bindings](types.md#bindings); owner q26, 2026-11-08): `xs.Append(x)` and `m.Delete(k)` leave `xs` and `m` unchanged. The lowering writes in place for `xs = xs.Append(x)` and `m = m.Delete(k)` on one place, and for a source that is dead after the call; elsewhere `Append` appends to a clipped slice, so Go's `append` makes a new array, and `Delete` deletes from a copy of the Map. *Prior art:* Go `make([]T, 0, n)` and `append`; Gleam's `list` module and Elixir's `Enum` keep collection functions out of the prelude.

**Context values: trace and log.** Two packages make and read the context values of [runtime.md, G1](runtime.md#g1-context-through-with) (#199 stage 4a). They are the first std packages with Ergo bodies; the lowering emits those bodies as it emits a user package's.

| Package | Exported declarations | Key | Go body of the read |
| --- | --- | --- | --- |
| `trace` | `func Span(name string) span`, the value `with trace.Span("checkout") { … }` binds; `func Current() Option[string]`, the innermost span's name or `None` | (`trace`, `span`) | `ContextBound(t *rt.Task, pkg ContextPackage, key string) bool` and `ContextValue(t *rt.Task, pkg ContextPackage, key string) string` (context.go), through unexported externs |
| `log` | `func Annotate(key string, text string) annotation`; `func Annotation(key string) Option[string]` | (`log`, the annotation's key) | the same |

Each value's type (`span`, `annotation`) is an unexported record with the protocol's unexported functions `contextKey` and `contextText` on it, so it binds by the rule every type uses and the packages export only the four declarations above. A read has empty rows and is effectful ([rows.md, Footprints](rows.md#footprints)). The rest of the trace and log APIs is [#206](https://github.com/cevr/ergo/issues/206). The lowering opens and ends a region with `Scope.OpenContext(pkg, key, text string) *Context` and `Context.End()` (context.go), which only the lowering calls. *Prior art:* OpenTelemetry's `Tracer.start_as_current_span` and Elixir's `Logger.metadata` set a value for the running process; Java's `ScopedValue` scopes it to a block, as `with` does.

## strings and strconv

Std `strings` and `strconv` work on text (wave std-1, unit G5a). They are pure functions: no operation type and no capability. Each export is an `extern go` of a `runtime/v1` body in `text.go` that calls the Go function of the same name, under the convention of [v1 packages](#v1-packages-task-scope-queue-and-slice): no hidden argument, a `runtime/v1` Go name with the std package as prefix (`StringsSplit`, `StrconvAtoi`), because Go needs each name of `runtime/v1` to be unique (Types 4), and one `runtimeBindings` row each, which neither waits nor releases. `TestStdTextRuns` runs each function.

| Package | Signatures |
| --- | --- |
| `strings` | `Split(s, sep string) []string`, `SplitN(s, sep string, n int) []string`, `Join(xs []string, sep string) string`, `HasPrefix`, `HasSuffix`, `Contains(s, x string) bool`, `ContainsRune(s string, r rune) bool`, `EqualFold(s, t string) bool`, `TrimSpace(s string) string`, `TrimPrefix`, `TrimSuffix(s, x string) string`, `Fields(s string) []string`, `Repeat(s string, n int) string`, `ReplaceAll(s, old, repl string) string`, `ToLower`, `ToUpper(s string) string`, `Index`, `LastIndex`, `Count(s, sub string) int`, `Slice(s string, i int, j int) string`, `Lines(s string) Seq[string]`; `type Halves { Before string, After string }`, `func Cut(s, sep string) Option[Halves]` |

1. Lengths and indexes are bytes, as `len(s)` is. Ergo has no substring syntax yet (`s[i..j]` is an index by a `Range`, S108), so `strings.Slice(s, i, j)` is Go's `s[i:j]`. A bound outside `0..len(s)`, or an `i` after `j`, is a defect, as an index out of range is; so is a negative `n` in `Repeat`.
2. `Cut` is Ergo over `Index` and `Slice`: `Some` of the text before and after the first `sep`, or `None` when `s` has no `sep`. A `sep` at index 0 gives an empty `Before`.
3. Go's one `*NumError` is two failures (std-align S1c): `Malformed` for a text the function cannot read (Go's `ErrSyntax`) and `OutOfRange` for a number that does not fit its type (Go's `ErrRange`), so a caller tells "not a number" from "too big" with a `match`. `Atoi`, `ParseInt` and `ParseFloat` fail either; `ParseBool` and `Unquote` fail `Malformed`. `ParseInt` takes Go's base rules (0 reads the prefix `0b`, `0o`, `0x` or `0` and allows `_`); a base outside 0 and 2..36, or a bit size outside 0..64, is a defect, as a negative `Repeat` count is. Both records are `runtime/v1` structs (`v1.Malformed`, `v1.OutOfRange`; Types 4), with the texts `strconv.Malformed{Text:…}` and `strconv.OutOfRange{Text:…}`.
4. Each call is transparent in footprints: every body in `text.go` is marked pure ([Pure bodies](#pure-bodies)).
5. `slices.SortFunc` and `SortStableFunc` (follow-up G5c) are in [Slices, maps and cmp](#slices-maps-and-cmp).
6. `Lines` is Go 1.24's `strings.Lines`: each line keeps its line feed. It is Ergo over `Index` and `Slice`, because a pure Go body cannot import `iter`. `SplitN` with `n == 0` gives an empty slice where Go gives nil. `utf8.RuneCount` counts each byte of an invalid sequence as one rune, as Go does.
7. The algebra of `strings`, `strconv` and `utf8` is in the [Std laws](#std-laws) ledger: split and join, count and split, cut, index, case and trim idempotence, repeat and replace lengths, lines, and the strconv round trips. Each Go-bodied law runs in runtime/v1 `TestStdTextLaws` on 10,000 seeded cases over an alphabet with separators, white space, case-changing and multi-byte runes and invalid bytes; the laws over Ergo bodies (`Cut`, `Lines`) run in lower `TestStdTextRuns2`. Two of the plan's laws are false and are stated in a true form: "ReplaceAll removes old" fails on `ReplaceAll("aabb", "ab", "")`, which is `"ab"`, so the law is `ReplaceAllLength`; "a text equals its case maps under folding" fails on `"İ"`, whose lower case `"i"` does not fold to it, so the law is `EqualFoldIsSymmetric`.
8. **Runes** (std-text-runes). `utf8.DecodeRuneInString(s)` is the first rune of `s` and its size, Go's two results as the record `Decoded`: an invalid byte is `Decoded{Rune: '\uFFFD', Size: 1}` and an empty text `Size` 0, so a loop that moves on by `Size` reads every byte once and ends (law `DecodeMovesOn`). `RuneText(r)` is Go's `string(r)`, `"\uFFFD"` for a rune that is not valid (a surrogate, a negative rune, one past U+10FFFF); `ValidRune`, `RuneLen` (-1 for an invalid rune), `ValidString` and `AppendRune` are Go's. `AppendRune` takes and gives Go's `[]byte`; Ergo has no conversion between `[]byte` and `string` yet, so a text is built with `RuneText` and `+`. `strings.ToValidUTF8(s, r)` replaces each run of invalid bytes with `r`, once per run, as Go's does. `strconv.FormatInt(n, base)` writes `n` in a base 2 to 36 with Go's digits; a base outside that is a defect, as Go's panics. The laws `DecodeInvertsRuneText`, `InvalidRuneTextIsReplacement`, `DecodeMovesOn`, `ToValidUTF8IsValid` and `ParseIntInvertsFormatInt` run in runtime/v1 `TestStdRunesLaws` over texts with every rune length, U+FFFD and invalid bytes (a lone continuation byte, cut 2-, 3- and 4-byte sequences, an overlong form, a surrogate's bytes, `0xff`, one past U+10FFFF) and runes of every class; `TestStdRunesMatchGo` holds each body to Go's function on 10,000 such cases; lower `TestStdRunesRuns` runs each function from an Ergo program.
9. **Padding and order** (std-strings-pad). `strings.PadLeft(s, width, pad)` is `s` after copies of the rune `pad`, so that it is `width` runes wide, and `PadRight` puts them after `s`; a text as wide as `width` or wider, and a negative width, pad nothing. Width counts runes as Go's `fmt` width does, so `PadRight(s, 8, ' ')` is `fmt.Sprintf("%-8s", s)` and `PadLeft(s, 8, ' ')` is `"%8s"`, for a multi-byte rune and an invalid byte (one rune each) too. A `pad` that is not a valid rune is written U+FFFD, as `utf8.RuneText` gives it. Interpolation has no width (`"\(x)"` takes no `%-8s`): that is a grammar change. `strings.Compare(a, b)` is Go's: 0, -1 or +1 by bytes. The laws `PadWidth`, `PadKeepsText` and `CompareIsAntisymmetric` run in runtime/v1 `TestStdPadLaws`, and `TestStdPadMatchesGo` holds the bodies to `fmt.Sprintf` and `strings.Compare` on 10,000 seeded cases. Effect's `String.padStart` and `padEnd` count UTF-16 code units, and Gleam's `string.pad_start` counts graphemes; Ergo counts runes, as Go's `fmt` does.

*Prior art:* Gleam's `gleam/string` and ReScript's `Js.String2` bind host text functions as direct externals with no wrapper; Elixir's `String` and `Integer.parse/1` (`{n, rest} | :error`) are plain BEAM calls. Ergo binds Go's `strings` and `strconv` the same way, and gives `Atoi` a typed failure in its row in place of Go's `error`.

## Slices, maps and cmp

Std `slices`, `maps` and `cmp` (std-align S2a) follow Go's packages of the same names for names, argument order and meaning, and Effect's `Array` and `Order` where Go has no function. The std package `slice` is now `slices`, with no alias. `TestStdSlicesRuns` runs each function; the laws are in `slices/laws.ergo`, `maps/maps.ergo` and `cmp/cmp.ergo`, with their rows in [Std laws](#std-laws).

| Package | Signatures | Go body |
| --- | --- | --- |

| `maps` | `Keys[K comparable, V](m Map[K, V]) Seq[K]`; `Values[K comparable, V](m Map[K, V]) Seq[V]`; `GetOr[K comparable, V](m Map[K, V], k K, def V) V`; `Update[K comparable, V, E, R](m Map[K, V], k K, f func(old Option[V]) V fails E needs R) Map[K, V] fails E needs R` | Ergo |

1. **A new slice, never a changed one.** `Sort`, `SortFunc`, `SortStableFunc` and `Reverse` return a new slice and leave their argument unchanged, where Go's change it in place: a `let` is immutable, and aliasing is visible (plan owner question 3; law `SortLeavesItsArgument`). The cost is one copy, which Go's in-place call does not make; a later lowering may sort in place when the argument is dead after the call.
2. **Option, never a panic or a second result.** `Max` and `Min` of an empty slice are `None`, where Go's panic. `BinarySearch` is `Some` of the index of the first `x`, or `None`, where Go returns `(int, bool)`. Each is an Ergo body over a `runtime/v1` body that the Ergo body calls only where Go's answer is defined.
3. **Callbacks.** `Transform`, `Filter`, `Fold` and `IndexFunc` take a function with a row and pass the row on, as `task.Go` does: an effectful or failing callback is allowed, and its first failure ends the call. `Transform` is Effect's `Array.map`: `Map` is the prelude's type, which no package may redeclare (#196), so the name is the one types.md, Generics, uses. The comparator of `SortFunc` and `SortStableFunc` has an empty row, as Go's has no error: the lowering adapts the Ergo function value to Go's `func(a, b T) int` (`lower/std.go`, `adaptPlainFunc`), and its error, which a value with no error row never returns, is dropped. A comparator must be a strict weak order, as Go's `SortFunc` needs; a comparator that is not one gives an unspecified order and no defect, as in Go.
4. **Order.** `ordered` is Ergo's constraint: the integer, float and string types, `duration`, and the types defined over them; its Go form is `runtime/v1`'s `ordered`, whose terms are Go's `cmp.Ordered`'s. `cmp.Compare` is a total order on floats too: a NaN is less than every other value and equal to a NaN, and `Sort` puts a NaN first, as Go does. collections.go restates `cmp.Compare` and `cmp.Less` rather than import `cmp`, which is not in `PureImports`; `TestStdCmpMatchesGo` holds them to Go's.
5. **Map order.** `maps.Keys` and `maps.Values` are Seqs in an unspecified order, as a `for` over a Map is ([types.md, Loops and len](types.md#loops-and-len) 1). `slices.Sorted(maps.Keys(m))` gives a fixed order, which a golden test needs.
6. **Purity.** The Go bodies of `Sort`, `Contains`, `Index`, `Reverse`, `Equal`, `Compare`, `Less` and the halves of `Max`, `Min` and `BinarySearch` are marked pure ([Pure bodies](#pure-bodies)). `SortFunc` and `SortStableFunc` take a function, so they are not, and neither is the body behind `Sorted`, which sorts the slice it has just collected in place.
7. **Laws and runners.** `TestStdSlicesLawsRun` (lower) restates each law as an Ergo property test and runs it with `--seed 1`. Under it, `TestStdSlicesLaws` (runtime/v1) checks the laws that a Go body decides over 10,000 seeded cases each, on `[]int` and `[]string` with empty, one-element and duplicate-heavy slices, the extremes of `int`, multi-byte UTF-8 and invalid bytes.
8. **A sorted slice is a type** (std-strengths SS5). `BinarySearch` takes an `Ascending[T]`, not Go's `[]T`. Go's `slices.BinarySearch(x []E, target E) (int, bool)` needs a sorted `x` and says so in prose: an unsorted `x` gives a wrong answer and no diagnostic, and so does Effect's `Array` search with an `Order`. `Ascending`'s one field is unexported, so only `slices` builds one ([types.md, Zero values](types.md#zero-values-and-definite-initialisation) 6): `Ascend(xs)` is a sorted copy (Go's `slices.Sort` on a clone), and outside `slices` a literal, an empty literal, a zero value (`let a slices.Ascending[int]`) and a literal of a defined type over it are S114, a `[]int` where an `Ascending[int]` is expected is S108, and a property parameter of the type is S108 (no generator builds it). A conversion to a defined type over it and back makes no new value, so it is allowed. `Items(a)` is a copy: a slice element is assignable and aliasing is visible, so a shared slice would let a caller unsort `a`. The departure from Go's signature is decided by NORTH_STAR "Strong abstractions with zero-cost implementations" under the 2026-11-08 std rule (std-strengths O2). The laws `AscendOrders`, `AscendPermutes`, `AscendLeavesItsArgument`, `ItemsIsACopy` and `BinarySearchFindsTheFirst` state it; `TestAscendingIsTheOnlyWayIn` (lower) and the check fixture `negative/ascending-is-the-only-way-in.ergo` hold the refusals, and `TestStdAscendingMatchesGo` (lower) holds `BinarySearch(Ascend(xs), x)` to Go's `slices.BinarySearch` on 10,000 seeded cases.

9. **Copies and views** (std-slices-maps). `Clone` is Go's `slices.Clone` (Effect's `Array.copy`): a write to the copy never reaches `xs`. `Concat(a, b)` is Go's `slices.Concat` (Effect's `Array.appendAll`): a new array, so an `Append` to `a` with room after its elements never changes the result (law `ConcatIsIsolated`); Ergo has no variadic parameter, so it takes two slices. `Repeat(xs, n)` is Go's `slices.Repeat`: `xs` n times over; Effect's `Array.replicate(x, n)` is `Repeat([]T{x}, n)`; a negative `n` is a defect, as Go's panics. `Slice(xs, i, j)` is Go's full slice expression `xs[i:j:j]` (Effect's `Array.slice`): it shares the array of `xs` but has no room after `j`, so an `Append` to it makes a new array and never writes `xs[j]` (law `SliceHasNoRoom`); Go's `xs[i:j]` keeps the room, and an `append` to it writes `xs`. A bound outside `0..len(xs)` or an `i` after `j` is a defect. `Len(a)` and `At(a, i)` read an `Ascending` with no copy, where `Items` copies; `At` out of range is a defect, as an index is.
10. **Map copies and upserts.** `maps.Clone` is Go's `maps.Clone`; its body restates it (a loop into a new map), because `maps` is not in `PureImports`. `maps.GetOr(m, k, def)` is the value of `k`, or `def`: Effect's `HashMap.get` with `Option.getOrElse`, Go's comma-ok read. `maps.Update(m, k, f)` sets `k` to `f` of its value now, `Some` or `None` (Effect's `HashMap.modifyAt`); it returns the result and leaves the caller's `m` unchanged, as the prelude's `Delete` does, since Maps are values ([types.md, Bindings](types.md#bindings) 1, q26), so a program writes `m = maps.Update(m, k, f)`. `m` is an owned parameter ([types.md, Bindings](types.md#bindings) 2): that assignment hands `m` over and writes it in place, as the prelude's `p = p.Delete(k)` does and as hand Go writes `m[k] = f(m[k])`, and a call whose `m` stays live copies it at the call. When that call cannot fail and names a package function as `f` (not generic, no failure, no Task result), the lowering writes `Update`'s body at the call with `f` called directly, as hand Go writes `v, ok := m[k]; m[k] = f(v, ok)`: the `Option` it passes then stays on the stack, so a loop of such calls allocates what Go's does. When `f`'s body is one `match` on its `Option` parameter, the parameter is used nowhere else, and each arm takes Some's value or nothing (the arms a `match m.Get(k)` reads with comma-ok), the lowering calls a comma-ok variant of `f` instead: `v, ok := m[k]; m[k] = fOk(v, ok)`. `fOk` is `f`'s match written as `if ok { … } else { … }`, so no `Option` is built and there is no type switch. `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.updateLowering=option` passes the `Option`, and `…=call` calls `Update`. `TestValueRuleAgrees` holds all three lowerings to the same interpreter, with a callback that has the variant and one that has none. `maps.GetOr` and a `match m.Get(k)` read with Go's comma-ok form, and the prelude's `Delete` and an index write change an owned Map in place. `f` may fail and need capabilities, as `Transform`'s callback may; its failure ends `Update` and leaves `m` as it was. The laws `CloneIsIndependent`, `UpdateSeesTheOldValue` and `GetOrDefaults` state them. `TestStdSlicesMoreMatchGo` (runtime/v1) holds `Clone`, `Concat`, `Repeat`, `Slice` and `maps.Clone` to Go's functions on 10,000 seeded cases, with arguments that have room after their elements; `TestStdSlicesMoreRuns` (lower) runs each function.

*Prior art:* Go's `slices`, `maps` and `cmp`, whose names these keep; Effect's `Array.map`, `filter`, `reduce`, `sort` with an `Order`, `findFirst` and `head` returning `Option`; Gleam's `gleam/list` (`map`, `filter`, `fold`, `sort` with a comparator, `first` returning `Result`) binds Erlang's `lists:sort` as an external, as `slices.Sort` binds Go's; Elixir's `Enum.map`, `Enum.sort_by` (stable) and `Enum.max` (raises on empty, unlike `Max` here); ReScript's `Belt.Array` returns new arrays and `option` for a missing element.

5. **ParseError.** `Parse` fails `ParseError { Layout, Value, Message }`, with Go's message. 6. **Manual.** Its time moves only by `Advance`; a `Sleep` returns when `Advance` reaches its deadline, and a stop of the sleeping task ends the sleep and removes it. Copies of a Manual share one timeline. Bind one value for both capabilities: `context { time.Clock: m, Scheduler: m }`. `NewManual` takes Unix seconds, not a Time, because a function whose first parameter is a Time must not reach state (`TestStdHostProvidersHaveAuthority`). `TestManualClockModel` (runtime/v1) checks it against a reference model over 500 seeds. **Advance settles** (fua-b; batch-13 MB2 G2). `NewManual` makes the calling task the first member of the Manual's domain, the same domain a `testing.VirtualClock` has: that task, and every task started below a member from then on, actors and their timers, works and children included. A task that made another clock before leaves that clock's domain. `Advance(m, d)` first waits until every member but its caller waits on a wait the clock sees (a `Sleep` on it, a queue's `Push` and `Pop`, a `Task`'s `Wait` and `Stop`, `timeout.After`, and an actor's inbox, `Send`, `Ask`, `State`, `Changes`, `ExitOf`, `Host.Get`, `Stop` and `Drain`). Then it moves the time to the earliest deadline due by now+d, wakes every sleeper of that instant, and waits again, one instant at a time. So when `Advance` returns, each timer due by then has fired at its own instant, and every task it woke, and every task those woke, has run to its next wait: an actor has stepped its timer's signal, committed and published the state. A driver reads the result at once, with no loop on `Sleepers` or `State`. A member that runs on, or waits on anything else (the host's input, a file, a lock), keeps `Advance` waiting until that wait ends, as Go's `synctest.Wait` does; those host waits are the only waits of a member that `Advance` does not see. A stop of the caller ends the wait. **One `Advance` at a time** (batch-13 round 2, B1): a call of `Advance` on a Manual while another task's `Advance` of it runs is a defect in its caller ("time.Manual: Advance while another task's Advance of this clock is running"), and the running one goes on. The running `Advance` waits for every other member to park, and a caller of `Advance` is not parked, so a second member's call can only come while the first runs: waiting for it would wait forever (each for the other), and letting both move the time would leave the sum of the moves undefined (two `Advance(1s)` from one instant both target the same time). Go's `synctest.Wait` makes the same call: two goroutines of one bubble that call it at once panic. `TestManualAdvanceSettles` (runtime/v1) holds this against a reference timed fold, for generated machines with timers, a ticking task and a `Changes` watcher, beside generated member tasks that wait on an actor in each of its waits (`Stop`, `Drain`, `Ask`, `ExitOf`, `State`, a full `Send`) while its step waits on the caller of `Advance`; `TestManualAdvanceOneAtATime` holds the one-at-a-time rule. *Prior art:* Effect's `TestClock.adjust` runs the fibers that each passed sleep woke before it returns; Go's `testing/synctest` `Wait` returns when every goroutine of the bubble is durably blocked; Tokio's paused time moves only when the runtime is idle.
7. **Laws and runners.** `TestStdTimeLawsRun` (lower) restates `FormatParseRoundTrip`, `SubAddInverse` and `Timeline.AdvanceMovesRead` as Ergo property tests. `TestTimeLaws` (runtime/v1) runs `NowNeverFalls` on the host clock and checks the round trip over 10,000 seconds of years 1 to 9999 against Go's own `time`. The sleep law `SleepAdvancesNow` needs a task beside the Manual. `task` imports `time` already (its law `StopIsIdempotent` sleeps on a Manual), so `time` cannot import `task` without a cycle (`TestStdImportsAreAcyclic`): the law is in `task`, with its row under `task`, and `TestStdTimeLawsRun` restates it. `TestManualClockModel` (runtime/v1) holds it too, against a reference model.

8. **Durations as text and numbers** (std-duration; `time/duration.ergo`). The language's `duration` takes `+`, `-`, ordering and `==` ([types.md, Operators](types.md#operators) 4); these functions give the rest of Go's `Duration`. `ParseDuration(s)` is Go's `time.ParseDuration`: an optional sign, then numbers with optional fractions, each with a unit (`ns`, `us`, `µs`, `μs`, `ms`, `s`, `m`, `h`), or `0`; any other text, or one past the range, fails `ParseError` with an empty `Layout`, the text as `Value` and Go's message (`time: missing unit in duration "12"`). `DurationText(d)` is Go's `Duration.String` (`1h2m3.5s`), which `ParseDuration` reads back (law `DurationTextRoundTrips`). `Times(d, n)` is `d` n times over, **saturated** at the range of a duration where Go's `d * time.Duration(n)` wraps, as `Sub` saturates (law `TimesKeepsTheSign`); Effect's `Duration.times` is unbounded. `Divide(d, n)` is Go's `d / time.Duration(n)`, toward zero, and `Count(d, unit)` is Go's `int(d / unit)` (`Count(d, 1ms)` is `d.Milliseconds()`); the one quotient past the range, the smallest duration over -1, saturates, and a zero divisor is a defect, as Go's division panics (laws `DivideInvertsTimes`, `CountIsWholeUnits`). So `time.Times(1ms, n)` is a duration of `n` milliseconds, where `duration(n)` of an `int` is refused (a conversion is only from `int64`). runtime/v1 `TestStdDurationMatchesGo` holds each body to Go's function on 10,000 seeded texts and durations (valid and invalid texts, fractions, every unit, missing and unknown units, the extremes) and `Times` to the exact product clamped; `TestStdDurationLaws` runs the four laws; lower `TestStdDurationRuns` runs each function and `flag.Duration`.
9. **The calendar** (std-time-civil; `time/civil.ergo`). In UTC, as every Time is (3). `t.Calendar()` is one `Civil` record of Go's `t.UTC().Date()`, `Clock()`, `Nanosecond()`, `Weekday()` and `YearDay()`, where Go has five methods; a record is one call and needs no tuples. `time.Date(year, month, day, hour, min, sec, nsec)` is Go's `time.Date(…, time.UTC)`, with Go's normalisation: a field outside its range carries into the next larger one, so day 0 is the last day of the month before, hour 24 the next day and nsec -1 the nanosecond before; the result has no monotonic reading. `Month` and `Weekday` are unions, where Go's are integers, so a `match` over a month or a weekday is total and a 13th month cannot be written; `MonthNumber`, `MonthOf(n) Option[Month]` and `WeekdayNumber` give Go's numbers. The arithmetic is the proleptic Gregorian calendar of Go's `time` (Howard Hinnant's `days_from_civil` and `civil_from_days`), in Ergo with no host call, so it lowers to integer arithmetic. The laws `DateRoundTrip`, `WeekdayStep`, `DateNormalises`, `YearDayCounts` and `MonthOfInvertsNumber` run in `TestStdTimeLawsRun`; lower `TestTimeCivilMatchesGo` holds `Calendar` and `Date` to Go's on 20,000 seeded instants and dates over years -9999 to 9999, with fields far out of range and the leap-day and era edges. Effect's `DateTime.getPart` and `DateTime.make` read parts by a string key; Gleam's `gleam/time/calendar` has `Date { year, month: Month, day }` with a `Month` type, as here.

*Prior art:* Go's `time` (monotonic readings in `time.Time`, `testing/synctest`'s fake clock); Effect's `Clock` service and `TestClock.adjust`; Gleam's `gleam/time` keeps instants as seconds and nanoseconds in UTC and formats RFC 3339 only; Elixir's `DateTime` is UTC-first and its `System.monotonic_time` is separate from wall time; ReScript binds JavaScript's `Date`.

## rand

Std `rand` (std-align S2c) follows Go's `math/rand/v2` for names and meaning, and Effect's `Random` for the capability and the seeded provider. The capability is the prelude's `Random`. `TestRandRuns` (lower) runs each function; the laws are in the prelude, `rand/source.ergo` and `rand/laws.ergo`, with their rows in [Std laws](#std-laws).

| Name | Signature | Go body |
| --- | --- | --- |
| `Random` (prelude) | `Random { Uint64() uint64, IntN(n int) int, Float64() float64 }` with the laws `IntNInRange` and `Float64InUnit` | none |
| `PCG`, `Seeded` | the seeded provider: `Seeded(seed uint64) PCG`; `Uint64(p PCG) uint64`, `IntN(p PCG, n int) int`, `Float64(p PCG) float64` | `Stream` (rand.go): Go's `*rand.Rand` over `rand.NewPCG(seed, RandSeedHi)`, behind a lock |
| `Host` | the host's provider: `NewHost() Host needs Ambient`; `Uint64`, `IntN`, `Float64` | `RandHostUint64`, `RandHostIntN`, `RandHostFloat64`: Go's global functions (ChaCha8) |
| `Shuffle`, `Perm`, `Choice` | `Shuffle[T](xs []T) []T needs Random`; `Perm(n int) []int needs Random`; `Choice[T](xs []T) Option[T] needs Random` | Ergo over `Random.IntN` |

1. **Random changed.** The prelude's `Random { Int63() int64 }` becomes Go `math/rand/v2`'s three draws. No program called `Int63` (measured: no `.ergo` file outside the prelude). An `IntN(n)` with `n` of zero or less is a defect, as Go's `IntN` panics.
2. **Seeded replays.** `Seeded(seed)` draws Go's stream of `rand.New(rand.NewPCG(seed, v1.RandSeedHi))`, call for call. It needs no `Ambient`, because it reads no host state: a test or a replay binds it, `context { Random: rand.Seeded(7) }`. `TestSeededRandModel` (runtime/v1) checks it against Go's generator over 1,000 seeds.
3. **One stream per provider.** The state is a runtime/v1 `Stream` that the `PCG` record points to, so every copy of a `PCG` shares one stream: `let b = a` draws on from where `a` is, and does not replay it. Two `Seeded` of one seed replay one stream (`SeedReplays`). The lock keeps the stream whole when tasks draw from one provider at once.
4. **Shuffle and Perm draw as Go's do.** `Shuffle` is Go's Fisher-Yates loop, from the last element down to the second, each swapped with the element at `IntN(i+1)`, so under `Seeded(seed)` it gives Go's `r.Shuffle` order. `Perm(n)` shuffles the identity, as Go's `r.Perm` does. `Shuffle` returns a new slice and leaves its argument, as `slices.Sort` does. `Choice` of an empty slice is `None`.
5. **Laws and runners.** `TestRandLaws` (runtime/v1) runs `IntNInRange` for each `n` in 1..1,000 and 1,000 seeded larger `n`, and `Float64InUnit`, on `Stream` and on the host. `TestStdRandLawsRun` (lower) restates `SeedReplays`, `PermPermutes` and `ShufflePermutes` as Ergo property tests.

*Prior art:* Go's `math/rand/v2` (`PCG`, `ChaCha8`, `IntN` that panics on a non-positive `n`, `Shuffle` and `Perm`); Effect's `Random` service with `Random.make(seed)`, `nextIntBetween`, `shuffle` and `choice`; Gleam's `gleam/int.random` and `list.shuffle` read the host's generator with no seed; Elixir's `:rand` keeps a seeded state per process (`:rand.seed/2`) and `Enum.shuffle` draws from it; ReScript binds JavaScript's `Math.random`, which has no seed.

## filepath

Std `filepath` works on file paths by their text alone (std-align S3a). It follows Go's `path/filepath` for its names, arguments and results, and Effect's `Path` service (`join`, `basename`, `dirname`, `extname`, `normalize`, `relative`, `isAbsolute`) for what it covers. It has no operation type and no capability: no function reads the file system or the working directory. Each export is an `extern go` of a pure `runtime/v1` body in `path.go` that calls the Go function of the same name, with one `runtimeBindings` row each that neither waits nor releases. `Split`'s body returns `v1.Parts`, so it scans the path once, as Go's `filepath.Split` does. The laws import `strings` for `strings.HasSuffix`; one Go body has one Ergo extern in the std (`TestStdBindsNoForeignBody`).

| Declaration | Meaning |
| --- | --- |
| `Join(parts []string) string` | The non-empty parts with a separator between each pair, cleaned; `""` when every part is empty. Ergo has no variadic parameters, so the parts are one slice. |
| `Base(path string) string`, `Dir(path string) string`, `Ext(path string) string` | The last element; the path without it, cleaned; the extension of the last element from its last dot. |
| `Clean(path string) string`, `IsAbs(path string) bool` | Go's lexical cleaning; whether the path begins with a separator. |
| `type Parts { Dir string, File string }`; `Split(path string) Parts` | The path cut after its last separator: `Dir + File` is the path. Go returns the two strings; Ergo returns one record. |
| `type NotRelative { Base string, Target string }`; `Rel(base string, target string) string fails NotRelative` | A path relative to `base` that names `target`. Go's `Rel` returns an `error`; Ergo's fails `NotRelative` in its row. |

1. The separator is `/`. Go's targets for Ergo are Linux and darwin, where no path has a volume name; Windows is not a target.
2. Every body is pure ([Pure bodies](#pure-bodies)), so a call of one is transparent in a footprint, and a function that only calls `filepath` has an empty footprint. `Abs`, `EvalSymlinks`, `Glob`, `Walk` and `WalkDir` are not in this package: they read the host. `v1.PureImportsExcept` lists them, and `BodyOf` refuses a pure body that names one.
3. `NotRelative` is the `runtime/v1` struct `v1.NotRelative` ([Types](#v1-packages-task-scope-queue-and-slice) 4). Its text is `filepath.NotRelative{Base:… Target:…}`, the generated text of a record.
4. The laws (Std laws below) are the algebra: `Clean` is idempotent and keeps the root, `Split` rebuilds its path, `Dir` and `Base` join back, `Base` has no separator, `Ext` ends `Base` and is the extension of `Base`, and `Join` of `base` and `Rel(base, target)` is `target`. `TestFilepathLaws` runs each over 10,000 generated paths of the segments `""`, `.`, `..`, names with and without dots, runs of separators, a multi-byte rune and an invalid byte; `TestFilepathMatchesGo` holds each body to `path/filepath` on the same paths; `TestFilepathRuns` (lower) runs each function.

*Prior art:* Gleam's `filepath` package and Elixir's `Path` module are lexical and read no host state, except Elixir's `Path.expand/1`, which reads the working directory, as Go's `Abs` does; Effect's `Path` is a service, so a test can replace it, which a lexical function never needs. Ergo keeps Go's names and binds Go's functions directly, as Gleam's externals bind Erlang's `filename`.

## math and bits

Std `math` and `bits` (std-text-runes) are Go's `math` for `float64` and Go's `math/bits`. They follow Go's names, arguments and special cases, and Effect's `Number` module for what it covers (`Number.round`, `Number.remainder`; JavaScript's `Math` behind it). Each export is an `extern go` of a pure `runtime/v1` body in `numbers.go` that calls Go's function of the same name, with one `runtimeBindings` row each that neither waits nor releases.

| Package | Signatures |
| --- | --- |
| `math` | `Abs`, `Ceil`, `Floor`, `Trunc`, `Round`, `Sqrt(f float64) float64`; `Pow(x float64, y float64) float64`, `Mod(x float64, y float64) float64`; `Inf(sign int) float64`, `NaN() float64`, `IsNaN(f float64) bool`, `IsInf(f float64, sign int) bool`; `MaxInt64() int64`, `MinInt64() int64`, `MaxInt() int`, `MinInt() int` |
| `bits` | `OnesCount(x uint) int`, `OnesCount64(x uint64) int`, `LeadingZeros`, `TrailingZeros`, `Len(x uint) int` and their `…64(x uint64) int` forms; `RotateLeft32(x uint32, k int) uint32`, `RotateLeft64(x uint64, k int) uint64` |

1. Go's constants are functions (`math.MaxInt64()`), because a std package `let` has no Go name in a program's build yet; each is an Ergo body of one literal, so the call is pure and inlines. Ergo's targets have a 64-bit `int`.
2. A negative `k` rotates right, as in Go; `LeadingZeros(0)` and `TrailingZeros(0)` are 64 and `Len(0)` is 0. Go compiles `bits` to one instruction where the target has it (POPCNT, LZCNT, TZCNT, ROL), and a body that only calls it inlines into the caller, so `RotateLeft32` costs what Go's costs.
3. `math/bits` joins `v1.PureImports` for these bodies, so a user `extern go math/bits.…` is allowed too (one list, [Pure bodies](#pure-bodies) 2; [grammar.md](grammar.md#declarations), Extern).
4. The laws (Std laws below): `Floor` and `Ceil` bracket a finite `f` at most 1 apart, `Trunc` moves toward zero and is idempotent, `Abs` is never negative; a rotation by `-k` undoes one by `k` (32 and 64 bits) and keeps the ones, and `Len64(x) + LeadingZeros64(x)` is 64. runtime/v1 `TestStdRunesLaws` runs each on 10,000 seeded cases over floats of every class (integral, halves, `-0`, the infinities, NaN, random bit patterns) and unsigned ints of every width; `TestStdRunesMatchGo` holds each body to Go's function on the same values, bit for bit; lower `TestStdRunesRuns` runs each function from an Ergo program.

*Prior art:* Gleam's `gleam/float` binds Erlang's `math` functions (`floor`, `ceiling`, `truncate`) as externals and `gleam/int` gives bitwise operations over BEAM instructions; ReScript's `Math` binds JavaScript's `Math` directly, with `Math.clz32` the only bit count; Elixir's `Bitwise` is BEAM instructions and `:math` is Erlang's. Ergo binds Go's functions with no wrapper, so Go's compiler sees its own intrinsics.

## Encodings and digests

Std `hex`, `base64`, `sha256` and `crc32` (G3 std-digest) are Go's `encoding/hex`, `encoding/base64`, `crypto/sha256` and `hash/crc32` over Ergo's `string`, which holds bytes ([types.md, Strings](types.md) 1), so they need no byte-slice type. They match Effect's `Encoding` module (`encodeHex`, `decodeHex`, `encodeBase64`, `encodeBase64Url` and their decoders) for behaviour; Effect has no hash module. Each extern binds a pure `runtime/v1` body in `digest.go`, with one `runtimeBindings` row each that neither waits nor releases.

| Package | Signatures |
| --- | --- |
| `hex` | `Encode(s string) string`; `Decode(s string) string fails Malformed`; `type Malformed { Offset int }` |
| `base64` | `type Encoding = StdEncoding \| URLEncoding`; `Encode(e Encoding, s string) string`; `Decode(e Encoding, s string) string fails Malformed`; `type Malformed { Offset int }` |
| `sha256` | `Sum(s string) string` (32 raw bytes) |
| `crc32` | `Checksum(s string) uint32`; `Update(crc uint32, s string) uint32` (IEEE polynomial) |

1. `hex.Encode` writes lower-case digits; `Decode` reads either case. Its `Malformed.Offset` is the index of the first byte that is not a hex digit, or the length for an odd-length text of digits (Go's `InvalidByteError` and `ErrLength`).
2. `base64` pads with `=` in both alphabets, as Go's `StdEncoding` and `URLEncoding`. The alphabet is a union, so `Encode` and `Decode` are Ergo bodies that match it to a private extern each, where Go has two `*Encoding` values and Effect two function names. `Decode` fails `Malformed` at Go's `CorruptInputError` offset for unpadded text or a byte outside the alphabet, and skips CR and LF as Go does.
3. `sha256.Sum` is the digest's 32 raw bytes, as Go's `Sum256` and as Gleam's `gleam/crypto` and Elixir's `:crypto.hash/2` give it; `hex.Encode(sha256.Sum(s))` is its usual text.
4. `crc32.Update(crc, s)` carries a checksum over more bytes, as Go's `Update` with `IEEETable`, so a text read in parts has the checksum of the whole.
5. The four Go packages join `v1.PureImports`, so a user `extern go encoding/hex.…` is allowed too ([Pure bodies](#pure-bodies) 2), and they leave `v1.PureUnlisted` (a table IG2 deleted). `hex.Malformed` and `base64.Malformed` are std records bound to `runtime/v1`'s `HexMalformed` and `Base64Malformed`.
6. The laws (Std laws below): `Decode` inverts `Encode` (hex, and base64 in both alphabets), hex doubles the length, base64's length is `(len(s) + 2) / 3 * 4`, every SHA-256 digest is 32 bytes, and `Update` chains (`Update(Checksum(a), b) == Checksum(a + b)`, `Update(0, s) == Checksum(s)`). runtime/v1 `TestStdDigestLaws` runs each on 2,000 seeded byte strings of every byte value; lower `TestStdDigestRuns` holds every function, called from an Ergo program, to Go's packages on seeded bytes, the FIPS 180-4 example inputs and malformed texts, with the `Malformed` offset a `catch` reads.

*Prior art:* Gleam's `gleam/bit_array` (`base16_encode`, `base64_encode`, `base64_url_encode`) and `gleam/crypto.hash` work on `BitArray`s over Erlang's `binary` and `crypto`; Elixir's `Base.encode16/1`, `Base.url_encode64/1` and `:crypto.hash/2` work on binaries, which are Elixir's strings, as Ergo's strings are bytes; ReScript binds JavaScript's `btoa` and has no digest. Ergo binds Go's functions, so each body is one conversion and Go's call.

## csv

Std `csv` (std-csv U4) is Go's `encoding/csv` with its defaults, over a text: a comma between fields, RFC 4180 quotes (a quote inside a quoted field written twice), CR LF at a line's end read as LF, `LazyQuotes` off, and every record as wide as the first. Its bodies in `runtime/v1` `csv.go` run Go's reader on a `strings.Reader` and Go's writer on a `strings.Builder`, so they are pure ([Pure bodies](#pure-bodies)). Effect has no CSV module.

| Name | Signature | Go body |
| --- | --- | --- |
| `ParseError` | `ParseError { Line int, Column int, Reason string, Message string }`: Go's `*csv.ParseError`, with `Err`'s text as `Reason` and the whole text as `Message` | `CSVParseError` |
| `ReadAll` | `ReadAll(text string) [][]string fails ParseError` | `CSVReadAll` |
| `Rows`, `Row` | `Rows(text string) Seq[Row]`; `Row = Parsed { Fields []string, At []Position } \| Malformed { Error ParseError }` | Ergo over `CSVScan` |
| `Position` | `Position { Line int, Column int }`: where a field starts, Go's `Reader.FieldPos` | `CSVPosition` |
| `Format` | `Format(rows [][]string) string` | `CSVFormat` |

1. **ReadAll** is Go's `csv.NewReader(strings.NewReader(text)).ReadAll()`, failing `ParseError` in the row, with Go's line, column and texts (`record on line 2: wrong number of fields`). A text with no record is no rows.
2. **Rows** gives each record as `Parsed` and, when the text breaks the format, the records before the error and then one `Malformed` with ReadAll's error. A `Seq` cannot fail, so the error is a row of the union, which a `match` must cover, where Go's `Read` returns an error beside a record. Rows is lazy and reads the text once (fs3): `CSVScan` runs Go's `Reader.Read` loop on the text and hands each record to the loop over the `Seq` when it asks for one, so a loop that stops (a `break`, or a `yield` that returns false) reads no further record, and the records before a break and the error come from that one pass. `TestCSVScanStopsTheRead` (runtime/v1) holds that a stop leaves the rest of the text unread. Each `Parsed` carries `At`, where each of its fields starts (fu6c, G-exup-6): Go's `Reader.FieldPos` for every field, a line and a byte column from 1, as `ParseError` has, and a quoted field starts at its opening quote. The purpose is an error that names the input: a program that finds a bad value in a field reports `file:line:column`, as the reader's own errors do, and a record's line differs from its count of records when a quoted field spans lines. Go gives the position on demand from the reader; here the record carries it, because a `Seq` hands on values, not the reader. Rust's `csv` gives one `Position` per record (byte, line, record); Python's `csv.reader` gives `line_num`, the line the reader has read to. Effect has no CSV module. `ReadAll` stays Go's `[][]string`, and a program that needs positions reads `Rows`.
3. **Format** is Go's `csv.Writer` with a line feed after each row: a field is quoted when it holds a comma, a quote, a CR or a LF, starts with a space, or is `\.`. One change from Go: a row of one empty field is written `""`, where Go writes an empty line that its reader skips, so every row with a field reads back. A row of no field is an empty line, which ReadAll skips.
4. **Laws.** `RoundTrip` (rows ReadAll can give read back from Format's text), `LinesCount` (Format writes one line per row and one per line feed in a field), `FormatIsStable` (Format of what ReadAll read from Format's text is the text) `RowsFollowReadAll` (Rows gives ReadAll's rows, or ends in one Malformed with its error) `RowsKeepTheRecordsBefore` (the records before a break are Parsed, in order), `PositionsPointAtFields` (one position per field, in order, at the field's text or its opening quote) and `RowsStops` (Rows stops when yield returns false; [Std laws](#std-laws) 5), over fields spiced with commas, quotes, CR and LF. Lower `TestStdCSVLawsRun` runs them; runtime/v1 `TestStdCSVMatchesGo` holds the bodies to Go's reader (its records, errors and `FieldPos`) and writer on 20,000 seeded texts and 20,000 seeded row sets.
5. `encoding/csv` is in `v1.PureImportHostMembers` with no host member, not in `PureImports`: a pure body's file imports neither `io` nor `os`, so the reader and writer can only be given a string, while a user extern of `encoding/csv` could hand them `os.Stdin`.

*Prior art:* Go's `encoding/csv`; Elixir's `NimbleCSV` (a library, RFC 4180, a parser per separator); Gleam has no std CSV (`gsv` is a package); ReScript programs bind a JavaScript library (`papaparse`). Python's `csv` module writes `""` for a lone empty field for the same reason as `Format`.

## Pure bodies

A std extern whose `runtime/v1` Go body is marked pure is transparent in footprints (wave std-1, unit G5b; [rows.md, Footprints](rows.md#footprints)). A call of it adds no capability, no task start and no opacity, so a function that calls `strings.TrimSpace` has the footprint of one that calls nothing: empty, with no entry poll. Every other extern call stays opaque.

1. The mark is the directive line `//ergo:pure` in the doc comment of an exported top-level function of `runtime/v1`. `v1.BodyOf` reads it and reports `Body.Pure`; the checker's footprint (`check/footprint.go`, `runs`) reads only that fact.
2. The mark is a reviewed claim. `BodyOf` refuses a marked body, with an error that names the rule, when:
   - it is a method;
   - its file imports a package outside `v1.PureImports` (`strings`, `strconv`, `unicode`, `unicode/utf8`, `unicode/utf16`, `slices`, `sort`, `math`, `math/bits`, `path/filepath`, `encoding/hex`, `encoding/base64`, `crypto/sha256`, `hash/crc32`) and outside `v1.PureImportHostMembers` (`time`, std-align S2b; `encoding/csv`, std-csv U4, with no host member: [csv](#csv) 5);
   - its body names a member of a `PureImportHostMembers` package that reads host state, as a package member or a method of that name: for `time`, `Now`, `Since`, `Until`, `Sleep`, `After`, `AfterFunc`, `Tick`, `NewTicker`, `NewTimer`, `Local`, `LoadLocation` and `Parse` (which reads the local zone for an abbreviation). `time` is not in `PureImports`, which is also the user extern list (G9): a user extern binds a whole package, so it could bind `time.Now`;
   - its body names a member of an allowed package that reaches the host, as `v1.PureImportsExcept` lists them (`filepath.Abs`, `EvalSymlinks`, `Glob`, `Walk`, `WalkDir`), or its file dot-imports such a package;
   - it takes a hidden argument (the frame, the call site, the task, the Scheduler, the reading package);
   - it takes a function, whose code is unknown;
   - its body names a top-level function or variable of `runtime/v1` (so it reaches no other body and no package state), starts a goroutine or uses a channel. A local name that shadows a top-level one is refused too.
   For a refused body `BodyOf` returns no shape, so the checker treats its call as opaque. A body that is not marked is not pure.
3. Purity is only std's. A user `extern go strings.TrimSpace` stays opaque: its Go body is outside the reviewed set.
4. An Ergo std function over pure externs, such as `strings.Cut`, is pure through its own footprint, which its package records.
5. Today the marked bodies are the bodies of `strings` and `strconv` in `text.go`, those of `slices` and `cmp` in `collections.go` named in [Slices, maps and cmp](#slices-maps-and-cmp) 6, those of `filepath` in `path.go`, those of `math` and `bits` in `numbers.go`, those of `hex`, `base64`, `sha256` and `crc32` in `digest.go`, those of `csv` in `csv.go`, the prelude's `Append`, `Get` and `Delete` in `data.go` (lw-pure-prelude), and the prelude's `Unreachable` in `data.go`, which raises a defect and reaches nothing (a defect is no capability; the lowering panics at each call site instead of calling it, [types.md, Unreachable](types.md#unreachable) 6). The prelude's `Append`, `Get` and `Delete` are intrinsics: the lowering writes a Go wrapper for each in the program (`Get` builds the program's `Option` from the comma-ok read that `v1.Get` is), and a marked intrinsic's wrapper is a pure function with no environment. So `func evens(n int) []int` that loops and calls `out.Append(i)` lowers to Go's `func evens(n int) []int` with no task poll, and `match m.Get(k)` in a function that does nothing else keeps it pure (`TestPurePreludeEmits`, `TestPurePreludeAgrees`). Their writes are the writes Go's `append` and `delete` make, on a source that no other binding sees ([types.md, Bindings](types.md#bindings) 2), so a pure function gives equal results for equal arguments. The reference lowering, in which their calls are opaque again, is selected with `-ldflags=-X=ergo.local/prototype/internal/sketch/check.pureCollections=off`, or in a test with `check.SetPureCollectionsForTest(false)`. `TestPureBodiesKeepTheAllowlist` reads every embedded runtime file and checks each marked body against the rules independently of `BodyOf`; `TestFootprintsPureStd` checks the footprints.

*Prior art:* GHC trusts a foreign import's declared type: an import whose result is not in `IO` is pure on the author's word. Gleam's and ReScript's externals carry no effect fact, and Elixir's compiler sees a remote call as unknown code. Koka infers effects only for code it can see, and its externs state their effect in the declared type. Ergo keeps the claim on the Go body, where a reviewer reads it, and checks its mechanical part: what the file can reach.

## Std laws

The std states its guarantees as laws (owner, 2026-11-06; std-align S1a). The rule:

1. Each operation type of each std package, the prelude included, has at least one member law. A type that no law over its own operations can observe has instead one doc-comment line `// law-exempt: <reason>`, and the reason is not empty. A type never has both. `TestStdOperationTypesHaveLaws` finds every operation type from the checked packages (`std.Packages()` and the prelude), never from a written list, and holds the rule.
2. A family of pure functions states its algebra as top-level laws in its package (round trips, idempotence, order).
3. A law is checked, not run, until [#162](https://github.com/cevr/ergo/issues/162) runs laws ([types.md, Laws](types.md#laws) 10), and it adds no Go to any build (Laws 11; lower `TestStdLawsAddNoGo`). Until #162, the table below names, for each law, the Go test that runs it now. A runner restates the law over the std's providers with seeded cases. `#162` stands only for a law that no Go test can run, such as a law on a type that the std provides no provider of, and its state is `checked`; a law with a Go runner is `tested`.
4. Each law of std source has exactly one row. The Statement is the law's source text from its name to its closing brace, each run of white space made one space. `TestStdLawLedger` holds both, and that each runner is a `func Test…` that a runner package (`internal/sketch/lower`, `internal/sketch/std`, `runtime/v1`) declares and that runs its laws through `lawledger.Run` (`internal/lawledger`). A runner gives `lawledger.Run` each law it restates, with the statement it restates and the check that runs it. `lawledger.Run` holds that the runner restates exactly the rows that name it, each with the row's statement (so a law changed in source and here fails its runner until its restatement changes too), and runs each law as a subtest named after its key (`queue.CloseKeepsValues`). `TestStdLawsRun` (lower) restates every law whose runner it is as an Ergo test of the same name, and runs them with `--seed 1`, as `ergo test --seed 1` does.
5. **A Seq stops.** A `Seq` calls yield with each value and stops when yield returns false (prelude, `Seq`). `Seq` is a function type, so it cannot carry a member law, and Go's `iter.Seq` states the rule in prose only. So each exported std function and operation whose result is the prelude's `Seq` states it as a law named `<Producer>Stops`: with n the count of values a yield that always returns true gets, a yield that returns false at its k-th call (k of 1 or more) is called exactly min(k, n) times. A function is a top-level law of its package, and a function whose first parameter is a type of its package is named by that type and itself (io's `Lines(input Input)` states `InputLinesStops`); an operation is a member law of its type (`Queue.ValuesStops`, which also states that the values not taken stay in the queue). A top-level stop law drives every k from 1 to n+1 itself; the runner of a member law drives each k. A producer that no law can drive with generated values has instead one doc-comment line `// seq-exempt: <reason>`, with a reason that is not empty, and never both: today `io.Lines(Host)` and the operation `io.Stdin.Lines`, which read the host. `TestStdSeqProducersStateStop` (`internal/sketch/std`) finds every producer from the checked packages by its result type, never from a list, and holds the rule.

The exempt types and their reasons are in their doc comments: `Console` and `Ambient` have no read, and `Scheduler` has no clock to observe a sleep by. `Clock` moved to std `time` with `Now() time.Time` and the law `NowNeverFalls` (std-align S2b).

## Std strengths over Effect

The std takes the behaviour and the guarantees of Effect's modules, not an Effect API shape that exists only because TypeScript has no construct for the job (owner, 2026-11-08; [decision](../decisions.md#owner-direction-2026-11-08)). Each such shape is a **workaround**, with an id:

- **W1** `Effect.gen` and `yield*`: plain statements, `try`, `catch` and the error row ([rows.md, Error rows](rows.md#error-rows)).
- **W2** `pipe`: the dot form `x.f(y)` ([types.md, Methods](types.md#methods)).
- **W3** dual data-first and data-last signatures: one data-first function.
- **W4** `Context.Service`, `Layer` and `Effect.provide`: an operation type with laws, a `needs` row, `context` and `with` ([rows.md, Capability rows](rows.md#capability-rows)).
- **W5** `Data.TaggedError`, `_tag` and `catchTag`: an error type in a row and a total `catch` ([rows.md, Catch](rows.md#catch)).
- **W6** `Match` and `Data.taggedEnum`: a union and an exhaustive `match` ([types.md, Unions](types.md#unions)).
- **W7** `Schema` classes: a declared type and its derived codec ([types.md, Codecs](types.md#codecs)).
- **W8** `Equal` and `Hash` traits: generated equality, `comparable` and Go's map hash.
- **W9** `Brand`: construction authority and refinements ([types.md, Zero values](types.md#zero-values-and-definite-initialisation) 6).
- **W10** `Option` and `Result` objects with combinators: the prelude union `Option[T]` and `match`.
- **W11** `Scope` values passed through the program: frame scopes and `scope.OnExit`.
- **W12** `Context.Reference`, `withSpan` and `annotateLogs` as fiber-local values: context values bound by `with` ([runtime.md, G1](runtime.md#g1-context-through-with)).
- **W13** `Config` and `ConfigProvider.fromEnv`: a capability that reads the process and a derived codec.
- **W14** every operation as an `Effect` value run by the fiber runtime: a direct Go call ([rows.md, Footprints](rows.md#footprints)).
- **W15** `Effect.forEach` and `Effect.all` with a `concurrency` option: a `for` loop, or `task.Go` for concurrent work.
- **W16** `Order` and `Equivalence` values passed by hand: the `ordered` and `comparable` constraints ([types.md, Generics](types.md#generics)).
- **W17** a command typed by inference from an object of flag values (`Flag`, `Command.make`): a declared type with a derived parser (S5a; not built).
- **W18** `Random` and `Clock` as references with a default: prelude and `time` capabilities bound by `context`.
- **W19** `Redacted` with a runtime `toString`: a record that interpolation refuses (#67; not built).
- **W20** `Effect.timeout` that forks a fiber per call: `timeout.After(d) { … }`, an ordinary function whose row adds `Expired` ([runtime.md, Timeouts](runtime.md#timeouts)).

The table has one row per std package, the prelude included. The Effect module is a file of `packages/effect/src` at pin `460272d3`, the pin of `conformance/effect-cases.json`. The last column is the package's lowering against hand-written Go: a benchmark the repository declares, as `<package dir>.Benchmark<Name>`, with its last recorded result and where the result is kept; or `pending:` and the file that holds the command; or `none:` and the reason. A result is a measurement on a shared host unless the cell says otherwise; a speed claim needs a quiet-host run (common rule). `TestStdStrengthsTable` finds the packages from `std.Packages()` and the prelude, never from a written list, and fails for a package with no row, a row for no package, an empty cell, a workaround id outside W1 to W20, an Ergo construct with no spec link, and a benchmark that the named package's tests do not declare. ## Schedule

[#179](https://github.com/cevr/ergo/issues/179). Package `schedule` says when to run work again and when to stop: the policy of a retry, a repeat, or a restart budget. `tasks.Retry` and `tasks.Repeat` run work by one.

| Declaration | Meaning |
| --- | --- |
| `type Schedule = …` | A policy. Its variants are unexported, so only the functions below make one. |
| `type Next = Continue \| Stop`, `type Continue { After duration }`, `type Stop {}` | A decision: run again after `After`, or stop. |
| `func Spaced(d duration) Schedule`, `func Forever() Schedule` | Continue forever, after `d` or with no delay. |
| `func Exponential(base duration, factor float64, cap duration) Schedule` | Continue forever; after run `n` the delay is `base × factor^(n−1)`, at most `cap`. |
| `func Recurs(n int) Schedule` | Continue after runs 1 to `n`, then stop. |
| `func UpTo(s Schedule, limit duration) Schedule` | `s`, but stop where a run would start more than `limit` after the first run began. |
| `func Jitter(s Schedule, low float64, high float64, seed uint64) Schedule` | `s`, each delay times a factor in `[low, high)` drawn from `seed` and the run count. |
| `func And(a Schedule, b Schedule) Schedule`, `func Or(a Schedule, b Schedule) Schedule` | Continue while both continue, after the longer delay; continue while either continues, after the shorter delay of those that continue. |
| `func Decide(s Schedule, runs int, elapsed duration) Next` | The decision after `runs` runs (1 for the first), `elapsed` after the first run began. |
| `func Retry[T, E, R](s Schedule, block func() T fails E needs R) T fails E needs R \| Scheduler \| time.Clock` (package `tasks`) | Run `block` until it gives a value; after a failure, `Decide` continues or stops, and on Stop `Retry` fails with that run's failure. |
| `func Repeat[T, E, R](s Schedule, block func() T fails E needs R) T fails E needs R \| Scheduler \| time.Clock` (package `tasks`) | Run `block`, and again while `Decide` continues; give the last value. A failure ends `Repeat`. |

1. **Purpose** (Effect `Schedule`). A program retries a call that fails for a while (a network, a lock), polls, or limits how often a supervisor restarts a worker. It needs one value that says how long to wait and when to give up, that it can test without waiting.
2. **A pure value.** A `Schedule` is data: a tree of the combinators above. `Decide` is a pure function of the schedule, the run count and the elapsed time, so a test folds it with no clock, and a law states each combinator. The schedule keeps no state between decisions: the run count and the elapsed time are the whole input, and the jitter draw is SplitMix64 of `seed + runs` (inferred: equal to Effect's state for every combinator here, since none of them reads its last output).
3. **One clock.** `Retry` and `Repeat` read the elapsed time from the context's `time.Clock` and sleep on its `Scheduler`, the clock of [runtime.md, Machines and actors](runtime.md#machines-and-actors) 9.6. On a `testing.VirtualClock` a retry with an hour of backoff runs at once (laws `RetryFollowsDecide`, `RepeatFollowsDecide`).
4. **Totality.** Each constructor takes every argument: a duration below zero is zero (as Go's `time.Sleep` reads it), an exponential factor below 1 (or NaN) is 1, a `Recurs` count below zero is zero, and each jitter bound is moved into `[0, 1000]` with `high` at least `low`. Each part of a jittered delay saturates at 4.6e18 ns, so their sum does not overflow.
5. **UpTo never starts late.** Effect's `upTo(d)` stops once the elapsed time passes `d`, so its last delay may start a run after `d`. `UpTo(s, limit)` stops where the delay would start the run after `limit` (law `UpToNeverPassesLimit`).
6. **Jitter is seeded.** The draw comes from the seed in the value, not from a `Random` capability, so `Retry` needs no `Random` and a test replays it. To keep many clients apart, each draws its seed once from `Random`. The jittered delay is the sum of two scaled durations, not `d × (low + span × u)`: no float product is added to, so no Go target can fuse a multiply-add and round another way (the model test compares exact nanoseconds).
7. **No predicate over the failure.** In `Retry[T, E, R]`, `E` is an error row, not a type ([types.md, Generics](types.md#generics) 1), so no function can take the failure as an argument, and `Retry` has no `while` predicate. A failure that must not be retried is caught in `block` and given as a value of its result.
8. **Re-raise.** `Retry`'s body catches `block`'s failure with `case err:` and, on Stop, returns `err`: a catch binding over a row parameter is a failure when returned ([rows.md, Catch](rows.md#catch) 7).
9. **Effect parts not taken.** `Schedule<Out, In, R>`'s three type parameters, its outputs and its input pipelining (`Schedule.passthrough`, `andThen`, `collectAllOutputs`, `whileInput`): no combinator here reads an input or an output, and a schedule's meaning is a function of the run count and the time (see 7 for the failure). Its fiber-backed step (W14) and `Schedule.driver` (an effect-returning state machine): `Decide` is a pure call. `pipe` and dual APIs (W2, W3): `s.And(t).UpTo(d)` by the dot form. Cron and calendar schedules (`Schedule.cron`, `windowed`) are not built.
10. **Laws.** `RecursStopsAfter`, `UpToNeverPassesLimit`, `ExponentialUnderCap`, `JitterInBounds`, `AndIsMaxOrIsMin`, and `tasks`'s `RetryFollowsDecide` and `RepeatFollowsDecide` ([Std laws](#std-laws)); lower `TestStdScheduleLawsRun` runs them on generated arguments. Lower `TestScheduleAgreesWithModel` compares `Decide`, lowered, with a Go reference model on generated schedules (every combinator, every clamp, both ends of each decision; `ERGO_SCHEDULE_SEED` replays a seed).

*Prior art:* Effect's `Schedule` (the reference for the intent); Go has no std backoff, and `cenkalti/backoff` keeps a mutable `ExponentialBackOff` with a randomization factor and a `MaxElapsedTime`; Erlang/OTP supervisors count restarts in a window (`intensity`, `period`); Elixir's `Retry` library composes delay streams (`exponential_backoff |> cap |> expiry`), a lazy list of delays, close to `Decide` folded over the runs; Gleam and ReScript have no schedule in their std.

## Tasks

[#207](https://github.com/cevr/ergo/issues/207). `tasks.Set` is G4 ([runtime.md](runtime.md#g4-tasksset)).

| Declaration | Meaning | Go body |
| --- | --- | --- |
| `func Transform[A, B, E, R](xs []A, limit int, f func(x A) B fails E needs R) []B fails E needs R` | `f` of each element, each call on a task of its own, at most `limit` at once, the results in the order of `xs` (batch 12, C2; built). | `TasksTransform(span Site, t *rt.Task, xs []A, limit int, f func(*rt.Task, A) (B, error)) ([]B, error)` (task.go), over `rt.MapSpan` (rt tasks.go) |
| `func Race[T, E, R](blocks []func() T fails E needs R) T fails E needs R` | Each block on a task of its own; the first to end decides, and the rest are stopped and waited for (batch 12, C4; built). | Ergo body over `race(n int, f func(i int) T fails E needs R)`, whose Go body is `TasksRace(span Site, t *rt.Task, n int, f func(*rt.Task, int) (T, error)) (T, error)` (task.go), over `rt.RaceSpan` (rt tasks.go) |
| `law TransformEqualsLoop(xs []int, k int)`, `law TransformKeepsOrder(xs []int, k int)`, `law LimitHolds(xs []int, k int)`, `law EarliestWins(ds []int)`, `law LosersStopped(n int)` | The laws ([Std laws](#std-laws)). | `TestTasksLaws` (runtime/v1) |

1. **Name.** The function is the concurrent form of `slices.Transform` and has its name: `Map` is the prelude's type, which no package redeclares ([#196](https://github.com/cevr/ergo/issues/196); S108).
2. **Limit.** At most `limit` calls of `f` run at once: a call starts only while fewer run, and when one ends the next element starts. A `limit` below 1 is a defect of the caller, and no call starts.
3. **Order.** The result holds `f(xs[i])` at index `i`, whatever order the calls end in.
4. **Fail fast.** `Transform` waits for whichever call ends first. The first failure it sees ends it: no call starts after it, every call still running is stopped, and all are waited for before `Transform` fails with that failure. A defect in a call, or in the stop of another, is raised in the caller, as `Task.Wait` raises it.
5. **Structured.** Every task `Transform` starts has ended when it returns, on every path. A stop of the calling task stops every call, and `Transform` raises the interruption. The calls share `f`'s providers, which the caller's row binds.
6. **Virtual time.** The caller's wait is one the VirtualClock sees ([Testing](#testing) 2), so a `Transform` over sleeping calls runs in virtual time.

`TestTransformModel` (runtime/v1) runs 300 generated cases on a VirtualClock against a discrete-event model: the results or the failure, the elements started, the most calls at once and the instant `Transform` returns. *Prior art:* Go's `errgroup.Group` with `SetLimit` (the first error cancels the group's context; `Wait` waits for all); Effect's `Effect.forEach(xs, f, { concurrency })`, fail-fast with interruption of the rest; Elixir's `Task.async_stream` with `max_concurrency` and `ordered: true`; Gleam and ReScript have no bounded parallel map in their std (Gleam's OTP `task` awaits one by one). *Effect workarounds replaced:* the `{ concurrency }` options object of one combinator for sequential and concurrent loops (W15) becomes a plain `for` and `Transform`; `Effect.gen` and `yield*` around `f` (W1) become the plain call.

`Race` (Effect's `raceAll`; Go's `select` over result channels with a cancel of the losers):

7. **The first to end decides.** `Race` waits for whichever block ends first. Its value is `Race`'s value, and its failure is `Race`'s failure. Every other block is stopped, and `Race` returns only after each has ended, its exit actions included. A loser's failure is dropped (laws R3, R6); a defect in any block is raised in the caller.
8. **Ties.** Blocks that end at the same instant, each with its own exit before the stop reaches it, tie, and the earliest of them in `blocks` wins. On a VirtualClock no time passes while a block can run, so a tie is a tie of virtual instants; a sleep whose deadline came at the instant of the stop ends as a sleep, not as an interruption ([Testing](#testing)). runtime/rt `TestVirtualSleepTieEndsAsSleep` holds this at the one point where both can be ready: a test hook brings the stop between the clock's unlock and the sleeper's select, after its own deadline fired.
9. **Shape.** Ergo has no variadic parameters, so the blocks are one slice. A slice of function values has no Go form a body can take, so `Race`'s Ergo body hands the Go body one function of an index, `func(i int) T { try blocks[i]() }`. `Race` of no blocks is a defect: it would never end. A stop of the calling task stops every block.
10. **No select (decision O13).** A block may finish its work before the stop reaches it, so a race of two `queue` `Pop`s can take a value from the losing queue and drop it. To wait for whichever of several sources has a value, give the task one queue of a union that every source pushes to (the inbox pattern), and `match` on what it pops. Ergo has no `select` construct in batch 12.

`TestRaceModel` (runtime/v1) runs 300 generated races of 1 to 6 blocks, with ties, on a VirtualClock against the model: the earliest-instant block wins (the lowest index on a tie), `Race` returns at that instant, and every block's exit action has run. *Prior art:* Effect's `raceAll` (first to complete; losers interrupted and awaited) and `race` (first success); Go's `select`, which picks at random among ready cases; Kotlin's `select { onReceive }`, an atomic choice that `Race` does not give; Elixir's `Task.yield_many` with `Task.shutdown`. Gleam and ReScript have no race in their std.

`Set` (runtime.md G4; batch 13 tasks-set; built):

*Intent.* A program that serves (a listener's connections, a supervisor's actors) starts tasks for as long as it runs. It keeps no `Task` per started task: each should end on its own and be forgotten, and none may outlive the code that started it. Effect's `FiberSet` serves this purpose (a fiber leaves the set when it ends; the scope's close interrupts the rest; `join` fails with the first failure), and so does Go's `errgroup.Group` (`Go`, then `Wait` for the first error; `WithContext` cancels the rest). Erlang/OTP's `one_for_one` supervisor adds restarts within an intensity limit.

11. **Owner.** The frame whose call made the Set owns it, by the rule that keeps a `Task` in its frame ([runtime.md, Tasks](runtime.md#tasks); check/taskescape.go): one rule for both owners of tasks (owner q39). The frame's end stops every member and waits for it, with the frame's other entries, last registered first. A return moves the Set to the caller (`open() tasks.Set[E]` returns one). A Set is never a field, an element, a type argument or a capture of a block or another task (S108 "a tasks.Set leaves its function only by return; stop it or return it"). So only the task that made it reaches it, and `Go`, `Wait`, `Stop` and `Len` run on the owner's task.
12. **Members.** `Go` starts `body` as a child of the calling task and returns at once; its site names the member in a defect chain (G2). A member that ends is dropped: `Len` counts the members still running, and the Set keeps no handle of an ended member past the owner's next call (`FinishedAreDropped`).
13. **Policy.** A member's typed failure or defect: under `FailFast`, the first one ends the Set: admission closes, the other members are stopped, and `Wait` gives it (`FailFastStopsTheRest`). Under `LogFailures`, it is written to the program's standard error as main's exit report writes it (`error: …`, or the defect report with its chain), and dropped; the Set goes on. Under `Restart{Limit}`, a defect runs the body again on the same task, up to `Limit` times for each `Go` (`RestartRunsAgain`); a typed failure, and the defect after the last restart, end the Set as under `FailFast`. A negative `Limit` is a defect. A member stopped by its Set or by its owner has no failure under any policy. A restart is immediate, as an OTP restart is: a backoff waits for std `schedule`.
14. **Wait.** `Wait` waits until no member runs. It fails with the typed failure that ended the Set, at this `Wait` and at each later one (errgroup's sticky error), and raises the defects that no `Wait` or `Stop` raised yet, with that failure beside them (every reason survives, G2 4). It is an interruption point of the owner: a stop raises the interruption, and the frame's end drains the Set. Under `LogFailures`, `Wait` never fails, though its row names `E`.
15. **Stop.** `Stop` closes admission, stops every member at once and waits until each has ended, its exit actions included (`StopEndsEveryMember`). It raises the members' defects and drops their typed failures (laws R3, R6). The frame's end does the same and joins the defects to the frame's exit.
16. **Closed.** `Go` on a Set that admits no more tasks (after `FailFast` ended it, after `Stop`) fails with `tasks.Closed` and starts nothing, as `queue.Push` fails `queue.Closed`: a normal end of the protocol, not a stop of the caller.
17. **Virtual time.** `Wait` and `Stop` park the owner where the VirtualClock sees it ([Testing](#testing) 2), and a member's end wakes it in the same step, so a Set of sleeping members runs in virtual time.

`TestSetModel` (runtime/v1) runs 400 generated cases under each policy on a VirtualClock against a discrete-event model: the result of each `Go`, `Len`, `Wait` and `Stop`, the members' runs, the logged failures, the frame's exit and its end instant; a stopped member's exit action sleeps and may panic, so a defect after the Set ended is kept. `TestSetNoRestartAfterClose` (runtime/v1) opens, with an unexported test hook (`closeGap`), the window between `Stop` closing admission and stopping a member, makes the member defect in it, and wants no second run under `Restart`. `TestSetRuns` (lower) builds and runs a program that uses each policy and returns a Set. *Not taken from Effect or Go, and why:* `FiberSet.make` returns an `Effect` in a `Scope` (W4: a `Scope` service in the context) where Ergo's frame owns the Set by the Task rule; `FiberSet.run` and `FiberSet.runtime` are two ways to add a fiber because a fiber is a value Effect must fork (W14), where `Go` takes the body; `FiberMap` and `FiberHandle` (keyed sets) are not built; errgroup's `WithContext` threads a cancel context by hand, which Ergo's task tree does by construction; errgroup's `SetLimit` is `tasks.Transform`'s limit; Effect's `Supervisor` is an observer of fibers, which `ergo ps` (G3) is to be. *Prior art:* Elixir's `Task.Supervisor` (`start_child` per task, `restart: :temporary` by default) and `DynamicSupervisor` (`max_restarts` within `max_seconds`); Gleam OTP's `static_supervisor` with `one_for_one` and an intensity; Kotlin's `supervisorScope` (a child's failure does not cancel its siblings, LogFailures) beside `coroutineScope` (FailFast); Trio's nursery. On the BEAM, a supervisor is a process that links its children, so a crash reaches it as a message; Ergo's Set is a frame-owned object and a member's end reaches it as a call in the member's own task.

## Actors

[#57](https://github.com/cevr/ergo/issues/57), [#101](https://github.com/cevr/ergo/issues/101). Std `actor` runs a machine live ([runtime.md, Machines and actors](runtime.md#machines-and-actors) 11). Effect module: none in the pin; the behaviour follows effect-machine's `Machine.spawn` and its actor ref. Go convention: a goroutine that owns the state, with a channel and a `switch`. Its laws are in [Std laws](#std-laws) (runner `TestStdActorLawsRun`).

1. `actor.StartMachine(m, capacity, sink)` starts the actor and returns at once. Its row is the step's `needs R` and `Scheduler`, so a test binds a `time.Manual` and controls the timers; the row holds the work's `R` too. Each entry's `machines.Work` runs as a child of the actor's task (runtime.md, Machines and actors 11 rule 11 and 12).
2. `a.Send(e) fails Stopped` queues `e`. `a.Ask(e) Decision[S, O] fails Stopped | F` waits for the step's decision or failure. The asker matches the `Decision` exhaustively, a `Reject` included.
3. `a.State() S` never fails. `a.Stop() fails F` returns the failure that ended the actor, if one did. `a.Dropped() int` counts the stale timer and work signals. `a.Changes() Seq[S]` gives the committed states.
4. Observing and ending (MU12; runtime.md, Machines and actors 13). `a.Drain() fails F` closes admission, steps every queued signal and ends; it returns as `Stop` does. `actor.WaitFor(a, pred) S fails Stopped` and `actor.SendAndWait(a, e, pred) S fails Stopped` wait for the first state `pred` accepts, from the state at the call (for `SendAndWait`, the state before `e`). `actor.ExitOf(a) Exit[S, O, F]` waits for the end: `Finished{State, Output} | Halted{State} | Failed{Error} | Defected`, where `Failed` holds the step's typed failure that ended it (q47). `actor.Latest(a) Option[D]` is the last step's decision. `actor.Select(changes, f) Seq[T]` (`T comparable`) and `actor.SelectBy(changes, f, same)` give `f` of each state with consecutive equal values dropped. They are std functions, not `Actor` members: the Go body never names the program's `Option`, `Decision` or `Exit` (one rule, the opaque runtime), and `WaitFor`, `SendAndWait` and `Select` are loops over `Changes`. Laws: `ExitIsShared`, `SelectOncePerChange`, `SelectStops`, `SelectByStops` ([Std laws](#std-laws)).
5. Children (MU5; runtime.md, Machines and actors 14). `actor.Child(send, m, capacity, toParent)`, called in a state's work with that work's `send`, starts `m` as an actor owned by the work's entry and returns it. Its `Emit` and `Done` outputs come back through `toParent` as signals of that entry; one that arrives after the entry ended is dropped. The entry's children stop, the last started first, before its timer and work stop and before the next entry opens, and when the parent ends; they are kept by identity, so two children of one machine are two children. A child's defect ends the parent. A `Child` whose first argument is not the send of the enclosing Listen work is S108 (mu5b). Effect intent: effect-machine's `self.spawn` and `ActorHost` give a state scoped child actors; Ergo takes the scope as the entry (no registry id, no generation check by hand, no host object), and the host's laws are properties of `TestActorChildrenAgreeWithTree`.
6. Sources and `Can` (MU10; runtime.md, Machines and actors 15). `actor.Feed(a, source) fails Stopped` gives `a` the values of a `Seq[E]` as signals, in order, on a task `a` owns: the source ends when `a` ends, and when `Stop`, `Drain` or `ExitOf` returns no source runs. `machines.Can(step, s, e)` is whether the pure step takes `e` in `s` (not `Ignore`, not `Reject`); `actor.Can(a, step, e)` is that in the actor's state, and `false` once the actor has ended, with no step run. Effect intent: effect-machine's `.background` and `can`; Ergo takes a `Seq` the runner owns instead of a handler with the actor's `self`, and a pure step by type instead of effectful guards. Laws: `FeedStepsInOrder`, `CanIsTheStep` ([Std laws](#std-laws)).
7. Hosts (mu-host; runtime.md, Machines and actors 16). `actor.NewHost[A]()`, made in a step, is an empty `actor.Host[A]` that the entry the step enters owns; that entry's work fills it once with `actor.ChildIn(send, host, m, capacity, toParent)`, and `host.Get() A fails Stopped` is the child, waits while the host is empty, and fails `Stopped` once the entry ended. The entry is published after its work filled its hosts, waited or ended. Effect intent: effect-machine's `ActorHost` names a lazily started child of a state scope; Ergo drops its identity string, its acquire-that-starts and its hand-written generation check (the entry's end closes the host). `Host` has no member law: its answers depend on an entry, which only the runner opens (`TestActorHostAgreesWithModel` holds them against `host.qnt`).
8. Durable actors (MU9; runtime.md, Machines and actors 17). `actor.StartDurable(m, capacity, sink, recover, save)` starts from the state `recover` gives and runs `save(prev, next, sig)` for each commit before anyone sees it; a failure of `save` is a defect. Std `journal` gives the contract `Journal[S, E]` and `Codec[T]`, with laws, and `journal.Start(m, j, every, capacity, sink)`, which replays the journal with `m`'s pure step and keeps each commit; `journal/memory` and `journal/file` are its providers. The checker refuses a durable machine whose step is not pure (S108). Laws: `AppendAddsOne`, `SnapshotDropsSignals`, `RoundTrips`, `RecoveryIsTheFold`, `DroppedIsNotJournaled` ([Std laws](#std-laws)).
9. Supervised actors (MU7; runtime.md, Machines and actors 18). `actor.Supervise(m, capacity, sink, policy tasks.Restart)` restarts the actor after a defect while fewer than `policy.Limit` restarts were made, by the restart rule of a `tasks.Set` (Tasks 13), each time in `m`'s initial state; `actor.SuperviseDurable(m, capacity, sink, policy, recover, save)` restarts in the state `recover` gives. A crash answers the `Ask` in the step and the queued ones `Stopped` and drops queued `Send`s; later ones go to the new incarnation. `Done`, `Stop`, `Drain` and a typed failure end it for good; the defect after the budget ends it (`Defected`). `actor.Restarts(a)` counts the restarts. Laws `RestartIsFresh`, `RestartRecovers`. *Effect intent:* effect-machine's `Supervision.restart`, OTP's restart intensity and Akka's `onFailure(restart)` keep an actor alive across a bug from a known state within a budget; Ergo takes that, and not a supervisor tree of its own, a mailbox kept across the restart (Akka), or an intensity window (waits for std `schedule`).
10. Not implemented yet: `actor.Start` with a handler, `actor.Ask` with an `actor.Reply`, `actor.Address`, `actor.StartAgent` and the resource rules (runtime.md, Machines and actors 6 and 7).

*Prior art:* Erlang `gen_statem` run by its process; Gleam OTP `actor` with a typed `Subject`; Akka Typed timers; XState `createActor`.

## Sync and STM

[#208](https://github.com/cevr/ergo/issues/208).

1. `sync.Ref`, `Latch`, `Semaphore` and `Deferred`. A blocking wait is an interruption point. `sync.Ref` is built; the others are designed.
   - **Ref.** `type Ref[T] { Get() T, Set(v T), Update(f func(v T) T) }`, `func NewRef[T](v T) Ref[T]` and `func Modify[T, R](r Ref[T], f func(v T) (R, T)) R`. A `Ref` is one cell: every copy of it, in a field, an argument, a capture or a task, is the same cell, so it is a synchronised handle that tasks share ([runtime.md, Tasks](runtime.md#tasks) 6). Each operation is atomic: no other operation of the `Ref` runs between `Update`'s or `Modify`'s read and its store, so Updates from several tasks at once are never lost (`UpdateIsAtomic`). `Update` and `Modify` call their function exactly once, never retried (`Ref.UpdateCallsOnce`); the function has an empty row, so it neither waits nor needs a capability while the `Ref` is held. `Modify` returns the first element of its function's result and stores the second, as Effect's `Ref.modify` does. No operation is an interruption point: none waits beyond the length of one operation.
   - **A Ref owns its value** (V6; owner q46, 2026-11-09). No binding outside the `Ref` sees a later write to its value, and no value the `Ref` holds is one a binding outside sees written ([types.md, Bindings](types.md#bindings)). A function literal written at the call of `Update` or `Modify` takes the held value over: its parameter is an unshared local, so its body writes the value in place (`u[k] = v`, `ws.Append(x)`, an owned parameter) and a change costs what it changes, not a copy of the value. The `Ref` keeps a flag: its value may be reached from outside (`NewRef`, `Set` and `Get` set it, and so does an `Update` or `Modify` whose function is not such a literal, since that function may keep its argument). Before it hands a value so marked to a literal, the `Ref` copies it, under its lock, once; the lowering proves each literal's results unshared (else the stored value is marked too). So a value `Get` returned never changes, and two tasks never write one value. `fstest.Memory` and `io.Recorder` change their `Ref` only through such literals: a file write costs O(its path) and a `Print` O(1) amortized (`lower.BenchmarkRefOwn`).
   - **Poison.** A defect in the function of an `Update` or `Modify` poisons the `Ref`: the defect goes on to the caller as it is, with its own stack, and every later `Get`, `Set`, `Update` and `Modify` of that `Ref` raises a defect that names the poisoning ("sync.Ref is poisoned: …"). The `Ref` does not recover the first defect to raise it again: only a task's boundary records a defect (runtime.md, defect ownership). The function may have written part of the value in place, so no task, and no later test, may see that value (owner q46: this replaces "a defect leaves the `Ref` usable, with the value it held before"). Prior art: Rust's `std::sync::Mutex`, which a panic in a holder of its guard poisons, and whose later `lock` returns a `PoisonError`, not the first panic. Ergo differs: v1 has no `into_inner` or `clear_poison` escape, since a value half written has no meaning a program could use; a test that wants a `Ref` after a defect makes a new one.
   - **Go body.** `*v1.Ref[T]`, a value guarded by a `sync.Mutex`, with the methods `Get() T`, `Set(v T)` and `Update(f func(v T) T)`; `NewRef(v T) *Ref[T]` and `RefModify(r *Ref[T], f func(v T) struct{ F0 R; F1 T }) R`, whose function returns the Go form of the tuple `(R, T)`; `RefUpdateOwned(r, f, clone, fresh)` and `RefModifyOwned(r, f, clone, fresh)`, the calls of an owned literal, with the copy function of `T` and the lowering's proof that the results are unshared (sync.go). `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.valueLowering=copy` lowers every call to the plain body, the reference `TestValueRuleAgrees` holds the owned calls to. Its control is a hand-written Go value guarded by a `sync.Mutex`; `atomic.Pointer` is a second control for reads (`runtime/v1.BenchmarkRef`).
   - *Workarounds not copied.* Effect's `Ref.make` returns an `Effect<Ref<A>>` and each operation is an `Effect` value (W14) to `yield*` in `Effect.gen` (W1); `Ref.update(ref, f)` and `ref.pipe(Ref.update(f))` are one dual API (W2, W3); `SynchronizedRef` exists because `Ref.update` cannot run an effect. Ergo's `Ref` is a value whose operations are plain calls, and its function's empty row is the checked form of "pure update".
2. `sync.TxRef[T]`, `sync.Atomically() { … }` and `sync.Retry()`. `Load` and `Store` need the `sync.Tx` capability, which only `Atomically` provides.
3. A transaction can re-run, so its body is a replayable parameter ([types.md](types.md#function-values)): its footprint holds only `sync.Tx`, and I/O inside a transaction is an error.
4. `Retry` rolls back, registers the read set and waits, interruptibly, until a `TxRef` it read changes. No lock-freedom or starvation-freedom is claimed.

*Prior art:* Haskell STM, ZIO STM, Effect `TxRef`; Go offers mutexes only. For `Ref`: Effect's `Ref` (an atomic reference with a pure update) and `SynchronizedRef`; Go's `sync.Mutex` and `sync/atomic`; Rust's `Mutex<T>`, which lends `&mut T` to the guard's holder and is poisoned by its panic; Swift's copy on write, which tests uniqueness by a reference count where the `Ref` keeps a flag set by a static proof; Haskell's `IORef` and `atomicModifyIORef`; Elixir's `Agent`, whose update runs in the agent's process; Gleam and ReScript have no shared cell in their std (Gleam's state lives in an actor process, ReScript's in a JavaScript `ref`, which a single thread makes safe).

## Batching

[#68](https://github.com/cevr/ergo/issues/68). A provider implements `FindMany`, and `context` wraps it: `Users = batch.Resolve(UsersDB, batch.Window(2ms), batch.Max(100))`. ## HTML

[#212](https://github.com/cevr/ergo/issues/212). Owner decision, 2026-10-26: HTML is "Functions", not markup syntax. There is no markup grammar.

```go
import html

func OrderRow(o Order) html.Node {
	return html.Tr([]html.Child{
		html.Class(statusClass(o.Status)),
		html.Td([]html.Child{html.Text(o.Member.Name)}),
		html.Td([]html.Child{html.Int(o.Quantity.Wire())}),
	})
}
```

1. The `html` package is ordinary functions: elements (`Tr`, `Td`, `P`, …), attributes (`Class`, `Href`, …), `Text`, `Int`, `Each` and `When`. A component is a function that returns `html.Node`.
2. An element takes one slice, `[]Child`, where `Child` is the closed union `Attr | Node`; Ergo has no variadic parameters. A void element such as `Br` or `Img` takes only `[]Attr`, so it cannot get children.
3. Escaping is decided by type. `Text` escapes its string; only an `html.Node` is inserted as markup. `Href` and `Src` take a `url.Safe`, not a string. `Raw` takes an `html.Trusted`, which only `html.Trust` builds, so `ergo inspect` lists every trust site.
4. **Lowering.** `html.Node` is a render function that writes to a buffered writer; `Text` escapes at write time, so no intermediate string is built. Folding static subtrees at compile time is a later, measured optimisation. `http.HTML(status, node)` renders a node into a response.

*Prior art:* Gleam Lustre (`html.td([], [text(name)])`), whose surface Ergo takes; Elm `Html`, which escapes by type with separate attribute and child lists, merged here into one `[]Child` slice of the union, so an element takes one argument; templ (Go), whose render-function representation Ergo takes, not its syntax; Phoenix HEEx (Elixir), whose compile-time validation Ergo gets from closed types instead of a parser.

## Host packages

[#210](https://github.com/cevr/ergo/issues/210). `os`, `fs`, `net` and `sql` are the only standard-library code that calls Go. They are reviewed. Every blocking call has a cancel hook, or is recorded as an uninterruptible host wait that `ergo inspect` lists (G8). Each package states the Go targets it supports. File handles are resources ([resources.md](resources.md)). Through host packages and `import go`, every effect appears in a footprint ([rows.md](rows.md#footprints)).

A host package has five parts: an operation type, the capability a program names in its rows; a record `Host { live hostOnly }`, the host's provider, whose unexported field of a zero-field type gives the package the construction authority and keeps `Host` zero size; one constructor `func NewHost() Host needs Ambient`; the provider's functions, with Ergo bodies; and unexported externs that bind the Go bodies in `runtime/v1` (`host.go`).

**Who chooses the host (host-authority H1).** Only code whose row holds the prelude's `Ambient` makes a host provider, and only the entry provides `Ambient`:
1. Outside its package, `fs.Host` as a value, `fs.Host{}`, `let h fs.Host`, a record update of it, and a type that holds it at zero are S114 "fs.Host has an unexported field, so only package fs builds it; use fs.NewHost" (types.md, Zero values 6). A generator or codec does not build it (`check.Constructible` is false).
2. A call of `fs.NewHost()` charges `Ambient`. Where no row holds it, the call is S102: in an exported function or `main` whose written row does not list it, in a `test`, in a package-level `let` and in a named context ("context Live requires Ambient while it is built"). In an unexported function the need is inferred and reaches its callers, up to `main`. A local context charges its `with`, and that need does not widen an inferred row ([rows.md](rows.md#composition-laws) 9).
3. The entry provides `Console` and `Ambient`: a `main` that lists `Ambient` gets it from the host, and any other capability in `main`'s row is S109 "the host provides only Console and Ambient". `Ambient`'s one operation is unexported, so a program type does not implement it. No context binds `Ambient`, in any package, the prelude included: an entry `Ambient: v` is S106 "no context binds Ambient: its one provider is the program entry", whatever `v` is (a parameter of type `Ambient` too). So `Ambient` has one source, the entry (fu-ambient-ctor r7).
4. Delegation stays open: a function that takes a host provider or a capability value as a parameter uses it with no row (GLOSSARY, Interface value). The caller that made it holds `Ambient`.
5. A test cannot get `Ambient`, so it binds its own provider: tests are hermetic. An opt-in for a test that needs the live host is a later unit (H3).
6. The prelude's `LiveScheduler` reaches the host's clock, so it follows the rule too (std-align S2b, host-authority H2): `type LiveScheduler { live liveOnly }`, and its one constructor is the prelude's `func NewLiveScheduler() LiveScheduler needs Ambient`. A program that sleeps on the host binds `Scheduler: NewLiveScheduler()` in `main`; a test or a law binds `time.NewManual(t0)`. `TestStdHostProvidersHaveAuthority` finds every std defined type whose function reaches a host extern and fails on one that another package can build with no authority, or that an exported name of std can hand out (fu-ambient-ctor r5). Let *held* be the provider `T` and the records another package needs to build it (`check.Authorities`). Every exported function, let and named context of every std package whose type mentions a held type lists `Ambient`; a let and a named context have no row, so they mention none. A type mentions what it is made of, at any depth (`check.Mentions`): every field of a record, hidden or not; type arguments; union variants; slice, `Map` key and element; a function's parameters, results, failure row and needs row; a type parameter's constraint; an operation type's operations and, for a sealed one, each type of its package that implements it; a machine's state and signal; an inferred row. The one exemption: a function with a parameter whose type is a held type itself, as in `func Clone(h Host) Host`, since its caller holds the authority. The rule over-reports on purpose: four rounds of a precise rule (what another package can obtain through results, failures, callbacks and needs rows) each missed a channel. `check.Mentions` is one switch over every kind of type that `TestMentionsWalkNamesEveryKind` keeps total; it lists no exception. A signature does not show a value that hides behind a type it does not name: an open operation type the provider implements (`func Open() Files { Host{…} }`, `let Disk = context { Files: Host{…} }`), a closure that captures it, or a call's argument (`try Read(Host{…})`). So the **mint rule** asks where a value is built (fu-ambient-ctor r6): in every std package, each place that builds a value of a held type (`check.Mints`: a record literal, a record update, the zero value of an omitted field or of a `let` with no value, a bare record, a conversion, a constant, a value a test or law generates) is in a function, or a closure in one, whose written row lists `Ambient` or that has a parameter of a held type. A package-level `let`, a named context, a type declaration (a machine's initial state, an operation type's law), a `test` and a `law` have no row, so a build there is always reported. A call is no build: the function it calls is asked where it builds. That holds because `Ambient` has one source (item 3), which the guard checks too: no std type implements `Ambient` and no std context binds it. An extern has no Ergo body to ask, so an extern whose signature mentions a held type lists `Ambient` in its written row (or takes a held parameter), and the result of a call of a generic extern, at its type arguments, is a build at the call (`zero[Host]()`). `check.Mints` decides each kind of expression in one switch that `TestMintFormNamesEveryKind` keeps total. "Another package can build it" is the checker's fact `check.Buildable(t, from)`: from literals, empty literals, zero values, conversions and function values, so a record with an exported field `Caps []Cap` fails, as an empty slice holds no `Cap` (fu-constructible). A sealed operation type is built when a type of its package that implements it is, so a host provider may be one (fu-hostguard2). A program package has no host provider of its own: it binds no Go that reaches the host (S108, S109), and it reaches the host only through a std provider, whose authority is std's (`TestProgramPackagesHaveNoHostProvider`).
7. **Who calls a host extern (fu-extern-callers).** Every std function, exported or not, whose body reaches a host extern lists `Ambient` in its written row or takes a parameter of a held type (item 6), as Go passes the handle. A function reaches when its body names a host extern or a function of its package that reaches, a fixed point; a function that holds the authority stops the chain, since its caller supplies the provider. An inferred row is no authority, and neither is a borrow of the provider. A closure is judged in the function around it, unless the closure holds the authority itself (a held parameter, or a written row that lists `Ambient`). An exported host extern follows the rule at its declaration, since another package calls it directly. A *host extern* is an extern whose runtime/v1 Go body its declaration marks `//ergo:host` in its doc comment (`v1.Body.Host`; fu4c), or whose Go package outside runtime/v1 is not on the pure allowlist (`runtime/rt.Sleep`). An impure body that is not marked reaches no host state: it makes or changes a slice, a Map, a queue or a task of the program, reads the running task's context, or makes the seeded stream or the manual timeline. `v1.BodyOf` keeps the mark honest: it refuses an unmarked body that reaches a host member (every member of `os`, `os/exec`, `os/signal`, `syscall` and `net`; the clock, timer and zone members of `time`; the global draws of `math/rand/v2`), directly or through a function or variable of the package, and a body marked both pure and host. A call through a function or interface value, or into `runtime/rt`, is not followed, so there the mark is the claim. An impure extern that a host provider's function reaches and that is not marked fails. So `func Peek(path string) string fails NotFound | Denied | Failed { try hostReadFile(path) }` in `fs` fails the guard (batch-10 r7 On base). `TestStdExternCallersHoldAuthority` runs the rule over every std package and over probe rows; `TestExternCallerRuleAgreesWithOracle` checks it against a model over generated call chains of depth 1 to 3.

So `main` reads `func main() needs Console | Ambient { with context { fs.Files: fs.NewHost(), os.Process: os.NewHost() } { run() } }`. The context in `cmd/<name>/main.ergo` is the one place that chooses the host, by convention: a library may wrap the choice when its own row lists `Ambient` (`func RunLive(f func() needs Console | fs.Files) needs Console | Ambient`). A test binds its own provider in the same place (`TestHostAuthority`, `TestHostAuthorityDomain`, lower `TestHostAuthorityRuns`).

### os

Std `os` is the host process (wave std-1, unit G2).

```go
import os

func run() fails os.Exit needs Console | os.Process {
	match os.Process.Getenv("TOPIC") {
	case Some[string] as t:
		Console.Println(t.Value)
	case None:
		return os.Exit{Code: 3, Message: "[NOT_FOUND] no TOPIC"}
	}
}

func main() fails os.Exit needs Console | Ambient {
	with context { os.Process: os.NewHost() } { try run() }
}
```

| Declaration | Meaning |
| --- | --- |
| `type Process { Args() []string, Getenv(key string) Option[string], law GetenvIsStable(key string) }` | The capability. |
| `type Host { live hostOnly }`; `func NewHost() Host needs Ambient`; `func Args(_ Host) []string`; `func Getenv(_ Host, key string) Option[string]` | The host's provider and its one constructor ([Host packages](#host-packages)). |
| `type Exit { Code int, Message string }` | The failure that ends `main` with status `Code`. |

1. `Args` is the arguments after the program name, Go's `os.Args[1:]`.
2. `Getenv` is `None` when `key` is unset and `Some("")` when it is set to the empty string. The law `GetenvIsStable` states `Getenv(key) == Getenv(key)`: two reads of one key agree, for any provider.
3. `os.Exit` is a failure in the row, not a call. When it is `main`'s only reason, the entry writes `Message` and a line feed to standard error, verbatim, and exits with `Code`; `Code` must be in 1..125 ([runtime.md](runtime.md#exit-causes) 8). It never skips cleanup: every scope's exit actions run before the entry writes it. Go's `os.Exit` skips deferred calls; Ergo has no call that does.
4. The Go bodies are `v1.OSArgs`, `v1.OSHasEnv` and `v1.OSGetenv`, each with one `runtimeBindings` row that neither waits nor releases. They read the host process, so none is pure. `os.Exit` is the `runtime/v1` struct `v1.Exit` (Types 4).
5. A program implements `os.Process`. A std operation type is sealed only when the result of a std extern names it, as `queue.New` names `queue.Queue` and `task.Go` names the prelude's `Task` (`check.SealedStd`, S109). No std extern returns `os.Process`, so it is open, as the prelude's `Console` is: `os.NewHost()` and a program's own type with an `Args` and a `Getenv` both convert to it, in `context { os.Process: … }` and at every other site that converts by assignability. It lowers as an interface of the program, not as a `runtime/v1` type. A test binds a memory provider in the same place as `cmd/<name>/main.ergo` binds `os.NewHost()`: `with context { os.Process: FakeEnv{…} } { run() }` (`TestOSProcessRuns`; check `TestStdProtocolOpen`).

*Prior art:* Roc's basic-cli platform gives `Arg` and `Env` as platform effects, and its `main` can fail with `Exit code message`, which the platform writes and exits with; `os.Exit` takes that shape and adds the 1..125 check. Effect Platform reads the environment through a `ConfigProvider` layer and leaves argv to `@effect/cli`. Gleam's `argv` and `envoy` packages, Elixir's `System.argv/0` and `System.get_env/1`, and ReScript's Node bindings read the process directly, with no capability; Elixir's `System.get_env/1` returns `nil` for an unset key, and Gleam's `envoy.get` returns `Result(String, Nil)`. Elixir's `System.halt/1` ends the VM at once with any status; Ergo's `os.Exit` is a failure, so cleanup runs first and the status is checked.

### fs

Std `fs` is the host file system (wave std-1, unit G4; writes, batch 9 unit G4b). `Files` reads it and `Writes` changes it: two capabilities, so code that only reads shows only `fs.Files` in its row.

```go
import fs
import strings

func title(path string) string needs fs.Files {
	let text = fs.Files.ReadFile(path) catch {
	case fs.NotFound as n:
		return "no file \(n.Path)"
	case fs.Denied, fs.Failed:
		return "unreadable"
	}
	strings.TrimSpace(text)
}

func main() needs Console | Ambient {
	with context { fs.Files: fs.NewHost() } { Console.Println(title("doc.md")) }
}
```

| Declaration | Meaning |
| --- | --- |
| `type Files { ReadFile(path string) string, ReadDir(path string) []string, Stat(path string) Info, law ReadIsRepeatable(path string) }`, each operation `fails NotFound \| Denied \| Failed` | The capability. |
| `type Writes { WriteFile(path string, text string), MkdirAll(path string) fails Denied \| Failed, WriteFileMode(path string, text string, mode Mode), MkdirAllMode(path string, mode Mode) fails Denied \| Failed, AppendFile(path string, text string), Chmod(path string, mode Mode), Rename(from string, to string), Remove(path string), law MkdirAllIsIdempotent(path string), law RemoveThenNotFound(path string), law RenameMoves(from string, to string, text string) }`, each operation with no row written `fails NotFound \| Denied \| Failed` | The capability to write. |
| `type Access = NoAccess{} \| Execute{} \| ReadOnly{} \| ReadExecute{} \| ReadWrite{} \| ReadWriteExecute{}`; `type Mode { Owner Access, Group Access, Other Access }`; `Private()`, `PrivateDir()`, `Shared()`, `SharedDir()`; `Bits(a Access) int`, `Perm(m Mode) int` | A file mode (11). |
| `type Host { live hostOnly }`; `func NewHost() Host needs Ambient`; `func ReadFile(_ Host, …)`, `func ReadDir(_ Host, …)`, `func Stat(_ Host, …)`, and one function of `Host` per operation of `Writes` | The host's provider of both, and its one constructor ([Host packages](#host-packages)). |
| `type Info { Name string, Size int, Dir bool, Perm int }` | What `Stat` gives; `Perm` is the permission bits, as `Perm(m)` gives them (17). |
| std `fstest`: `type Memory { tree sync.Ref[…] }`; `func NewMemory() Memory`; one function of `Memory` per operation of `Files` and `Writes`; laws `CopiesShare`, `AppendConcatenates`, `ModeIsKept` | The memory provider of both, for tests (17 to 19). |
| `type NotFound { Path string }`; `type Denied { Path string }`; `type Failed { Path string, Reason string }` | The failures. |

1. `ReadFile` is the whole text of the file at `path`. It returns `string`, not bytes: the language has no conversion from `[]byte` to `string` yet. A path is the host's; a relative path is relative to the working directory.
2. `ReadDir` is the names of the entries of the directory at `path`, sorted by name (Go's `os.ReadDir` sorts them). `Stat` follows symbolic links, as Go's `os.Stat` does (not `os.Lstat`). A link to a directory has `Dir: true`, and a link whose target is missing is `NotFound`. `Info.Name` is the last element of the path, so for a link it is the link's own name. `Info.Size` is the size in bytes of the target.
3. The failures are a closed row of three. `NotFound` is a path that does not exist (Go's `fs.ErrNotExist`), `Denied` a path the process may not read (`fs.ErrPermission`), and `Failed` every other failure, with the host's `Reason` without the operation and the path, such as `is a directory` for a directory read as a file. A `catch` that lists the three is exhaustive. An uncaught one is written with its generated text and status 1, such as `error: fs.NotFound{Path:missing.md}`.
4. The Go bodies are `v1.FSReadFile`, `v1.FSReadDir` and `v1.FSStat`, each with one `runtimeBindings` row that neither waits nor releases. They read the host, so none is pure. No body keeps a file open after it returns, so this set exposes no handle and needs no resource. The four records are the `runtime/v1` structs `v1.NotFound`, `v1.Denied`, `v1.Failed` and `v1.Info` (Types 4). The binding table keys each by its package and name (`fs.NotFound`), so a record of the same name in another package binds its own Go type.
5. A program implements `fs.Files`. No std extern returns it, so it is open, as `os.Process` is ([os](#os) 5, `check.SealedStd`). A test binds `fstest.NewMemory()` (17), or a provider of its own, such as one that fails a write on purpose, in the same place as `cmd/<name>/main.ergo` binds `fs.NewHost()`: `with context { fs.Files: memory.Files{…} } { run() }` (lower `TestFSFilesMemory`).
6. **Authority.** The externs are unexported, and only package `fs` builds an `fs.Host`: other code gets one from `fs.NewHost()`, which needs `Ambient`, or as a parameter ([Host packages](#host-packages), host-authority H1). So code that reads the disk with no `fs.Files` in its row, by `fs.ReadFile(h, p)`, by passing `h` as an `fs.Files` value, or by its own `with context { fs.Files: h }`, either has `Ambient` in its row (or in an inferred row that reaches `main`) or was given `h` by code that has it. `fs.ReadFile(fs.Host, p)` is S114; the same call on `fs.NewHost()` in a function whose row does not hold `Ambient` is S102. The same holds for `os.Host`.
7. The law `ReadIsRepeatable` states that two reads of one path agree: both give the same text, or both fail with the same failure (its kind and its fields). A first read that fails is followed by a second read whose failure is compared with the first; a second read that succeeds, or that fails after a first that succeeds, refutes it (batch-12 M2: a provider whose reads alternate NotFound and a text breaks it). It holds for a world with no writer: `Files` has none, so it holds for `fs.Host` on a quiet disk and for any memory provider. A law runner (#162) cannot build `fs.Host` by a generator (`check.Constructible` is false): it builds it through `fs.NewHost()` under `Ambient`, or it skips the host provider and says so.
8. **Writes.** `WriteFile(path, text)` makes the file at `path` hold `text`. The body `v1.FSWriteFile` opens a new file `path.tmpN` (N random) in the directory of `path`, with mode 0666, so the umask applies as for Go's `os.WriteFile`. It writes the text, syncs the file, gives it the mode of the file at `path` when there is one, closes it, and renames it over `path`. So a reader sees the old text or the new text, never a part, and the rename never crosses a device. A file that was at `path` keeps its permission bits; a second hard link of it keeps the old text. On any failure the new file is removed and the old file is whole. A crash between the write and the rename can leave a `path.tmpN` file. A symbolic link at `path` is followed, as Go's `os.WriteFile` and Effect's `FileSystem.writeFile` follow it: the file that the link names gets the text and keeps its mode, and the link stays a link. The new file is made beside the file that the link names, so the rename replaces that file, not the link. A link to a missing name makes that file; a link to a directory is `Failed` "is a directory", as a directory is, and the link stays; more than 40 links in a chain is `Failed` "too many levels of symbolic links". A `..` in a link's text is resolved by the host after the link's directory, as for an open, not removed by text (runtime/v1 `TestFSWriteFileFollowsLinks`). A directory at `path` is `Failed` "is a directory"; a missing directory on the way is `NotFound`; a directory the process may not write is `Denied`. The directory is not synced after the rename, so the rename itself can be lost in a power failure.
9. `MkdirAll(path)` makes the directory and each missing parent with mode 0777 less the umask (`v1.FSMkdirAll`, Go's `os.MkdirAll`). A directory that is there already is no failure, which the law `MkdirAllIsIdempotent` states. Its row has no `NotFound`: a missing path, such as the empty path, is `Failed` with the host's reason. A file on the way is `Failed` "not a directory".
10. A provider of `Files` and `Writes` over one store keeps one more contract: after `WriteFile(path, text)` succeeds, and with no other writer, `ReadFile(path)` is `text`. No law states it yet, because a member law sees only the operations of its own type. `fs.Host` keeps it (lower `TestFSWritesRuns`). `fs.Host` provides both capabilities. So `main` binds `context { fs.Files: fs.NewHost(), fs.Writes: fs.NewHost() }`; `Writes` is open as `Files` is (`check.SealedStd`), so a test binds a memory provider of it. The bodies have one `runtimeBindings` row each that neither waits nor releases.
11. **Modes** (std-fs-safe, decision O8). A file mode is the record `Mode { Owner, Group, Other }`, each an `Access`: `NoAccess` (bits 0), `Execute` (1), `ReadOnly` (4), `ReadExecute` (5), `ReadWrite` (6) or `ReadWriteExecute` (7). A write without a read is not a variant: no program needs it. So a mode reads as what it allows, and a program needs no octal literal. `Perm(m)` is the Unix bits, `Bits(m.Owner)*64 + Bits(m.Group)*8 + Bits(m.Other)`, the `int` the bodies take. Go's conventions for secrets are functions: `Private()` is 0o600 and `PrivateDir()` 0o700; `Shared()` is 0o644 and `SharedDir()` 0o755. They are functions, not package `let`s, because a std package `let` has no Go name in a program's build today (Follow-up of std-fs-safe).
12. **Exact modes.** `WriteFileMode(path, text, mode)` is `WriteFile`, but the file ends with exactly `mode`, whatever the umask, also when a file with another mode was at `path`. The body `v1.FSWriteFileMode` opens the new file `path.tmpN` with `mode` (the umask can only narrow it), gives it exactly `mode` with `fchmod`, and only then writes the text: from its creation on, no user outside `mode` can open the file, so a key written with `Private()` has no readable window (runtime/v1 `TestFSWriteFileModeIsExact`, under the umasks 0, 002, 022, 077 and 777). `MkdirAllMode(path, mode)` is `MkdirAll`, but each directory it makes is made with `mode` and then given exactly `mode`; a directory that is there keeps its mode (`TestFSMkdirAllModeIsExact`). `Chmod(path, mode)` is Go's `os.Chmod`, which follows a symbolic link. Go's `os.WriteFile(name, data, perm)` and `os.MkdirAll(path, perm)` apply the umask to `perm`; Ergo's exact mode is never wider than asked and never narrower.
13. **Append.** `AppendFile(path, text)` opens the file with `O_APPEND` (and `O_CREATE`, mode 0666 less the umask, for a missing file), writes `text` in one write and closes it, so the text lands at the end and two appends do not tear each other's text on a local file system (`TestFSAppendFileIsOneWrite`). A file that was there keeps its mode. It does not sync: an append costs one write, as Go's and Effect's `writeFile` with the flag `a` do. It is O(len(text)), where a read and a `WriteFile` of the whole file is O(size).
14. **Rename and Remove.** `Rename(from, to)` is Go's `os.Rename`: it replaces a file at `to`. The host's "no such file" does not say which name is missing: the body names `from` when nothing is at `from`, and `to` otherwise (a missing directory on the way to `to`); every other failure names `from`. `Remove(path)` is Go's `os.Remove`: a file, a symbolic link (not what it names) or an empty directory; a directory with entries is `Failed` "directory not empty". The laws `RemoveThenNotFound` and `RenameMoves` state what a provider of `Writes` alone shows; lower `TestFSMemoryAgreesWithHost` runs them, and `ReadIsRepeatable` and `MkdirAllIsIdempotent`, on `fs.Host` and on `fstest.Memory` alike (18), and `TestStdHostLawsHold` runs them on the host's edge cases (symbolic links, a file no one may read, `..`).
15. **Contracts over Files and Writes.** A member law sees only its own type's operations, so two contracts of a provider of both are written in `Writes`' doc comment and run by `TestFSWritesModel` (runtime/v1), not by a law: `AppendConcatenates` (after `WriteFile(path, a)` and `AppendFile(path, b)`, `ReadFile(path)` is `a + b`) and `ModeIsKept` (after `WriteFileMode(path, text, m)`, the file has mode `m`, and a later `WriteFile` or `AppendFile` keeps it). `TestFSWritesModel` runs 100 generated sequences of 30 steps of `WriteFile`, `WriteFileMode`, `AppendFile`, `Chmod`, `Rename`, `Remove`, `ReadFile` and `Stat` over four names, each under a umask it draws, against a map of name to text and mode, and checks every name after every step; a failing seed prints its steps.
16. **A breaking change.** Adding operations to `Writes` breaks a program's own provider of it, which must add them (decision O8: Effect's `FileSystem` is one service; a second capability would split one authority in two). The lower test `TestFSSafeRuns` runs every new operation through `fs.Host`.
17. **Memory** (std-fs-memory). `fstest.NewMemory()` is a provider of `Files` and `Writes` over a tree in memory, in the std package `fstest` after Go's `testing/fstest`: it is not in `fs`, so `fs.ReadFile(h, p)` and the other direct calls of an `fs.Host` keep one function of their name each. A test reads and writes no disk: `let m = fstest.NewMemory()` and `with context { fs.Files: m, fs.Writes: m } { run() }`, then `m.ReadFile(p)` to look. It has no `Ambient` in its row: it reaches nothing of the host. Its tree is in a `sync.Ref` (Sync and STM), so every copy of a `Memory` is the same tree (law `fstest.CopiesShare`), and each operation is atomic, so tasks may share one. "." and "/" are its two roots; a path is cleaned (`filepath.Clean`) before it is looked up, so "./a" is "a" and ".." is resolved by its text; the empty path names nothing; a failure names the path as given. `ReadDir` is sorted by name, `Stat` gives the last element, the size (0 for a directory), `Dir` and `Perm`, a missing directory on the way is `NotFound` (`MkdirAll`'s row has none: there it is `Failed` "no such file or directory" for the empty path only, since `MkdirAll` makes each missing parent), and a file on the way is `Failed` "not a directory". A new file has mode `Shared()` and a new directory `SharedDir()`, as the host gives under umask 022; `WriteFile` and `AppendFile` keep the mode of a file that is there (law `fstest.ModeIsKept`), and `AppendFile` adds at the end (law `fstest.AppendConcatenates`). `Rename` moves a directory with everything in it and has the host's failures: an existing directory at `to` is `Failed` "file exists" (Go's `os.Rename` refuses it before the host), a directory onto a file "not a directory", a directory into itself "invalid argument", a root "device or resource busy". `Remove` of a directory with entries is "directory not empty", of a root "invalid argument".
18. **Memory agrees with Host.** Lower `TestFSMemoryAgreesWithHost` is a model-based differential test: 150 seeded sequences of 60 operations, every operation of both capabilities and the laws of `fs`, over paths of one to three of three names (some written "./p", the empty path and "."), run on `fs.Host` in a new directory under umask 022 and on `fstest.NewMemory()`. On Linux every result agrees: the value, the failure, its path and its reason; the sequences reach each outcome of each operation that the host gives there (a list in the test), and each law and each Writes contract (`WriteThenRead`, `AppendConcatenates`, `ModeIsKept`) holds on both, in at least 20 cases that are not vacuous. On another host only the laws are held, since its reasons and the order of rename's checks are its own. `ERGO_FS_SEED=n` replays one sequence, and a failure prints its operations and both outputs. Mutants it kills: an unsorted `ReadDir`, a `WriteFile` into a missing directory, a `Rename` over a directory, copies that do not share, a `Remove` of a directory with entries, an `AppendFile` that replaces, a `MkdirAllMode` that drops the mode, a `Rename` that leaves a directory's entries, a `Stat` that drops the mode.
19. **What Memory does not do.** It has no symbolic links. It keeps each mode and never checks one, as Go's `testing/fstest.MapFS` does, so it never fails `Denied`: a test of a refused or failing write wraps it in a provider of its own that fails the operations it chooses and passes on the rest. A path with a doubled separator or a final "/" is cleaned, where Go's `os.MkdirAll` gives "file exists" for some of them. A provider cannot use a capability yet (#37), so a file-backed provider still reads every file when it starts.

*Prior art:* Gleam's `simplifile.read(path) -> Result(String, FileError)` gives a closed enum of POSIX reasons (`Enoent`, `Eacces`, …) plus `Unknown`; Effect Platform's `FileSystem` service gives `readFileString` and a `SystemError` whose `reason` is `NotFound`, `PermissionDenied` and others, bound by `NodeContext.layer`; Elixir's `File.read/1` returns `{:ok, binary} | {:error, posix}`; Go's `os.ReadFile` and `os.ReadDir` with `errors.Is(err, fs.ErrNotExist)`; ReScript binds Node's `readFileSync` as an `external` that throws. `NotFound | Denied | Failed` is their common core: the two reasons a program acts on, and one that carries the host's text. Like Effect and Roc, and unlike Gleam, Elixir and ReScript, the file system is a capability in the row, so a test swaps it in a context. Like Roc's platform and unlike Effect's layer, which any module may provide locally, Ergo keeps the disk out of reach of code that neither holds `Ambient` nor was given a provider (rule 6): Pony's `AmbientAuth` and Austral's `RootCapability` are the model.

*Prior art (writes):* Gleam's `simplifile.write(to:, contents:)`, Elixir's `File.write/3` (Erlang `file:write_file`), ReScript's binding of Node's `writeFileSync` and Go's `os.WriteFile(name, data, 0666)` all truncate and write the file in place, with mode 0666 less the umask for a new file: a reader can see a part, and a failure can leave a part. Go's `renameio` and Rust's `tempfile::NamedTempFile::persist` write a file in the same directory and rename it over the target, as `fs.Host` does; `renameio` also keeps the old mode only when asked. `MkdirAll` is Go's `os.MkdirAll`, Elixir's `File.mkdir_p/1` and Gleam's `simplifile.create_directory_all`. Effect Platform's `FileSystem` has `writeFileString` and `makeDirectory({ recursive: true })` in the one service; Ergo splits writes from reads, so a reader's row does not hold the authority to write.

*Prior art (modes, appends, renames):* Effect Platform's `FileSystem` has `writeFile(path, data, { mode, flag: "a" })`, `chmod`, `rename` and `remove` in its one service, with the mode as a number; Gleam's `simplifile` has `append`, `rename`, `delete` and `set_permissions_octal`, and also `set_permissions(FilePermissions(user:, group:, other:))` over sets of `Read | Write | Execute`, the shape `Mode` takes; Elixir's `File.write(path, data, [:append])`, `File.chmod/2` (an integer), `File.rename/2` and `File.rm/1`; Go's `os.OpenFile(O_APPEND)`, `os.Chmod`, `os.Rename` and `os.Remove`, and `renameio.WriteFile(name, data, perm)`, which applies the umask unless asked to ignore it. ReScript binds Node's `fs`, whose modes are numbers.

### io

Std `io` is the host process's standard streams (std-align S1b; wave std-1 G3 and G3b). It follows Effect's `Stdio` and `Terminal` and Go's `os.Stdout`, `os.Stderr` and `os.Stdin`. `Stdout`, `Stderr` and `Stdin` are three capabilities, so code that only writes errors shows only `io.Stderr` in its row.

```go
import io

func echo() needs io.Stdout | io.Stderr | io.Stdin {
	io.Stderr.Eprintln("reading")
	for line in io.Stdin.Lines() {
		io.Stdout.Println(line)
	}
}

func main() needs Ambient {
	with context { io.Stdout: io.NewHost(), io.Stderr: io.NewErrors(), io.Stdin: io.NewHost() } { echo() }
}
```

| `type ReadFailed { Reason string }` | The failure of a read. |

1. `Print` and `Eprint` write their text as it is; `Println` and `Eprintln` write the line and a line feed in one write. Each write is one unbuffered `WriteString`, as `Console.Println` is, so writes of `Console` and of `io.Stdout` appear in program order.
2. `Lines` gives each line without its line feed. A last line with no line feed is a line, an empty input has no lines, and a carriage return stays in its line, so the lines joined by line feeds, plus the final line feed if any, are the input (`LinesSplitInput`). A line has no length limit. A `Seq` has no failure row, so a read failure inside `Lines` is a defect; `ReadAll` returns it as `ReadFailed`. A `break` stops the read; the rest of the input stays unread. Every `Stdin` operation of `Host` reads through one buffered reader of the process, so the next `Lines` or `ReadAll` starts at the line after the break (`TestIOStdinRest`, `TestIOStdinShared`).
3. A read of standard input is an interruption point of the reading task (batch 12 C3; [decisions.md](../decisions.md), 2026-11-08, O15). A stop of the task that waits in `Lines` or `ReadAll` of `Host` ends the wait and raises the interruption; no input is lost. One read of the host's input runs at a time, on a goroutine of its own, and the line it lands after the stop stays for the next `Lines` or `ReadAll`. A `ReadAll` that a stop ends puts back what it had read. A masked task's read runs to its end. So rule 2's "the next `Lines` starts at the line after the break" holds after a stop too (`TestIOStdinStopModel`, runtime/v1; lower `TestStdinStopRuns`). The task is the iterating task for `Lines` (Hidden arguments, rule 5), and each body has one `runtimeBindings` row that waits on it. A read of a file is still an uninterruptible host wait.
4. `IsTerminal` reports whether standard output is a character device (Go's `os.ModeCharDevice`).
5. The Go bodies are `v1.IOPrint`, `v1.IOEprint`, `v1.IOIsTerminal`, `v1.IOReadAll` and `v1.IOLines` (host.go). `ReadFailed` is the `runtime/v1` struct `v1.ReadFailed` (Types 4); its name is not `Failed` because `v1.Failed` is `fs.Failed`.
6. The capabilities are open: a program implements them, and a test binds `io.NewRecorder()` or `io.Input{Text: …}` in the same place as `main` binds the host. `Stdout`, `Stderr` and `Stdin` are exempt from the law rule, each with its reason: the first two have no read, and a read of the host's input takes what it reads.
7. A `Recorder` keeps its writes in a `sync.Ref[[]string]` ([Sync and STM](#sync-and-stm) 1), so every copy of it keeps the same writes, and tasks may write to one `Recorder` at once: each write is kept whole, in the order the writes took the `Ref` (lower `TestIORecorderBehavesAsBefore`). No std code keeps state through a `Map` or slice that two bindings share.
8. `Stderr`'s operations are `Eprint` and `Eprintln`, names that `Stdout` does not have, so a `Stdout` provider is not a `Stderr` provider and the reverse: `io.Stderr: io.NewHost()` and `io.Stdout: io.NewErrors()` are check errors at the binding (`TestIOStreamsAreDistinct`). A program binds `Errors` to `io.Stderr`. The names follow Rust's `eprint!` and `eprintln!` and Gleam's `print_error`.
9. A std package may import another std package: `io` imports `strings` and `sync`. The std importer checks each package once, and the std has no import cycle (`TestStdImportsAreAcyclic`).

*Prior art:* Effect's `Stdio` gives `stdout` and `stderr` sinks and a `stdin` stream in one service, and `Terminal` gives `readLine` and `display`; Go writes `os.Stdout` directly and reads lines with `bufio.Scanner`, which has a 64 KiB line limit; Gleam's `gleam/io` has `print`, `println` and `print_error`, and `stdin` reading is a separate package; Elixir's `IO.puts(:stderr, …)` and `IO.stream(:stdio, :line)` keep the line feed; Roc's basic-cli gives `Stdout`, `Stderr` and `Stdin` as platform effects. Ergo takes Roc's three capabilities and Effect's guarantee that a test replaces each one.

### flag

Std `flag` reads a command line (std-align S1d). It follows Go's `flag` for the syntax, the names and the help layout, and Effect's `@effect/cli` for typed commands, required flags, choices, positional arguments and the closed union of failures. Two rules follow `@effect/cli` and not Go (owner, 2026-11-06, Q7): a flag may follow a positional argument until a bare `--`, and help goes to standard output with status 0. It is Ergo over `strings`, `strconv` and `time`, with no runtime body.

```go
import flag
import io
import os

let Json = flag.Bool("json", false, "print JSON")
let Sort = flag.Choice("sort", "date", []string{"date", "name"}, "the order")
let Files = flag.Remaining("files", "the files")

func run(args []string) fails os.Exit needs Console | io.Stdout {
	let set = flag.Set{Name: "list", Usage: "", Flags: []flag.Flag{Json, Sort}, Args: []flag.ArgSpec{Files}}
	let v = flag.Parse(set, args) catch {
	case err:
		try flag.Exit(err, flag.Usage(set))
		return
	}
	Console.Println("\(Json.Get(v)) \(Sort.Get(v)) \(len(flag.Rest(v)))")
}
```

| Declaration | Meaning |
| --- | --- |
| `type StringFlag`, `IntFlag`, `BoolFlag`, `ChoiceFlag`, `DurationFlag` (unexported fields); `type Flag = StringFlag \| IntFlag \| BoolFlag \| ChoiceFlag \| DurationFlag` | Flag handles; only package `flag` builds one. |

A `Duration` value is read by `time.ParseDuration` (std-duration); `Defaults` names its kind `duration` and writes a default that is not `0ns` with `time.DurationText`, as Go's `PrintDefaults` does. |

1. **Syntax** (Go's `flag.FlagSet.Parse`). An argument is a flag when it starts with `-` and is longer than `-`. `-name` and `--name` are one flag. A value follows `=` or, for a flag that is not a switch, is the next argument, whatever it is (`-s --` gives `s` the value `--`). A switch takes only `-name` or `-name=value`, with `strconv.ParseBool`'s values. `---x`, `-=x` and `--=x` are `Invalid` with `Name` empty ("bad flag syntax"). `-` alone and the empty string are positional. An `Int` value is read by `strconv.ParseInt(s, 0, 64)`, so `0x10`, `0o17` and `1_000` are read as Go reads them. A repeated flag keeps its last value.
2. **Position** (owner, Q7). Flags and positional arguments may interleave; a bare `--` ends the flags, and every argument after it is positional. A value that starts with `-` is given as `--name=value`. Go stops at the first positional argument; `@effect/cli` does not.
3. **Help.** `-h`, `-help` and `--help` (also with `=value`) fail `Help` with `Usage(s)` when the set declares no flag of that name, as in Go; a set that declares `h` reads `-h` as its flag. Help wins over every other failure (Q7, as `@effect/cli`'s `Command.runWith` reads its global `--help` from every argument before it reports a parse error): a help word anywhere before `--`, and not the value of a flag that takes one, fails `Help`, whatever comes before or after it (`-zz --help` is help). In `ParseCommand`, when the first argument names no command, a help word anywhere before `--` fails `Help` with `CommandUsage`; after a command name, the command's `Parse` reads it. `Exit` prints `Help`'s text to standard output and returns, so `main` ends with status 0 (Q7; Go prints usage to standard error).
4. **Order of checks.** First help (3). Then the arguments are read in order, and the first failure ends the parse. After the flags, each required flag must be given (`Missing`), then the positional arguments go to `s.Args` in order: an `Arg` takes one or fails `Missing`, an `OptionalArg` takes one if any is left, `Remaining` takes the rest. A positional argument left over fails `Extra`.
5. **Help text.** `Usage(s)` is `Usage of NAME:` (`Usage:` with no name), `s.Usage` on its own line when it is not empty, `Defaults(s.Flags)`, and an `Arguments:` block in declaration order (`name`, `[name]` or `name...`). `Defaults` is Go's `PrintDefaults` byte for byte for `String`, `Int` and `Bool`: sorted by name, the switch of a one-byte name on one line, a back-quoted word of the usage as the value's name, and a default that is not the zero value; a `Choice`'s value name is its choices joined by `|`, and a required flag ends with ` (required)`. The text of each failure is Go's where Go has one, with one difference: an invalid switch value reads `invalid value "x" for flag -b: parse error`, where Go writes `invalid boolean value`.
6. **Handles.** `Get` reads by handle name, and first checks that the handle is the set's flag of that name: the same kind, default, usage and choices. A handle of another set, or of another kind or default under the name of one of the set's flags, is a defect, whether the flag was given or not (the panic is an index out of range; its report names the Ergo frame; `TestFlagForeignHandle`). Two flags of one name in a set are not refused (Go panics on "flag redefined"; known gap).
7. **Laws** ([Std laws](#std-laws)): `RenderParseRoundTrip`, `IndependentFlagsCommute`, `LastWins`, `DoubleDashEndsFlags`, `ShortAndLongAgree`, `DefaultWhenAbsent`, `UnknownNamesTheFlag`, `HelpNamesEveryFlag`, `EachCommandReaches`, `BuildFailureReaches` (a `Build`'s own failure reaches the caller as it is, with its value) and `FlagCrossesPositional` (Q7). lower `TestFlagLaws` restates them as property tests. lower `TestFlagMatchesGo` checks the parse on 3,500 seeded argument lists (500 of them with a help word put in among other tokens): against Go's `flag` where every flag comes before the first positional argument and no help follows a failure, and against a written model of Go's `parseOne` with the Q7 rules (interleaving, and `@effect/cli`'s help precedence) on every list. `RenderParseRoundTrip` compares every read (each flag's `Get`, an `Arg`, an `OptionalArg` and `Rest`) of the result and of its re-parse, not `Equal`.
8. **Cost.** `Values` holds a `Map` of a union of the value kinds, so each value is boxed until a closed union of records lowers without boxing (X1). The `Set` is a value built at each call; a constant `Set` could lower `Parse` to a `switch` on the flag name (#243).

*Prior art:* Go's `flag` (syntax, `PrintDefaults`, `ContinueOnError` and `ExitOnError`); Effect's `@effect/cli` (`Flag.choice`, `Options.optional`, `Args`, `Command.withSubcommands`, `ValidationError` tags, help to stdout); Gleam's `glint` and `clip` build a command from typed flags and return a `Result`; Elixir's `OptionParser.parse/2` returns `{parsed, args, invalid}` and lets switches interleave with arguments; ReScript has no standard parser. Ergo takes Go's syntax, Effect's typed failures and commands, and `OptionParser`'s and `@effect/cli`'s interleaving.

### exec

Std `exec` runs programs of the host (std-align S3c, G8). It follows Go's `os/exec` for its names and its process model, and Effect's `ChildProcess` (`unstable/process`) for what a run gives back: the exit status and the output, with a stop of the caller that ends the child.

```go
import exec

func branch() string needs exec.Runner {
	let r = exec.Runner.Run(exec.New("git", []string{"branch", "--show-current"})) catch {
	case exec.NotFound:
		return "no git"
	case exec.Denied, exec.Failed:
		return "git did not start"
	}
	if r.Status != 0 {
		return "not a repository"
	}
	r.Stdout
}

func main() needs Console | Ambient {
	with context { exec.Runner: exec.NewHost() } { Console.Println(branch()) }
}
```

| Declaration | Meaning |
| --- | --- |
| `type Command { Name string, Args []string, Env Map[string, string], Dir string, Stdin string }`; `func New(name string, args []string) Command`; `WithEnv(c, key, value)`, `WithDir(c, dir)`, `WithStdin(c, text)`; `func Key(c Command) string` | One program to run, and the builder of changed copies. |
| `type Result { Status int, Stdout string, Stderr string }` | What a program that ran gives back. |
| `type Runner { Run(c Command) Result fails NotFound \| Denied \| Failed, law NotFoundNamesTheProgram(name string) }` | The capability. |
| `type Host { live hostOnly }`; `func NewHost() Host needs Ambient`; `func Run(_ Host, c Command) …` | The host's provider and its one constructor ([Host packages](#host-packages)). |
| `type Script { Results Map[string, Result] }`; `func Run(s Script, c Command) …` | The test provider: it runs nothing. |
| `type NotFound { Name string }`; `type Denied { Name string }`; `type Failed { Name string, Reason string }` | The failures. |

1. `Name` is a program on the `PATH`, or a path when it holds a `/`, as for Go's `exec.Command`. `Args` are the arguments after the name. `Env` holds entries set over the host process's environment: the program gets the host's environment with each entry of `Env` replacing or adding its key. `Dir` is the working directory, `""` for the caller's. `Stdin` is the whole of the standard input; the program reads end of file after it.
2. `WithEnv`, `WithDir` and `WithStdin` return a copy. `WithEnv` copies `Env`, so the command it is given keeps its own entries (the laws `WithEnvOverrides` and `WithEnvKeepsTheOriginal`).
3. A status that is not 0 is a `Result`, not a failure: a CLI matches on it. A program that a signal ended has the status 128 plus the signal's number, as a shell reports it. `Stdout` and `Stderr` hold all the program wrote, read to their end.
4. The failures are a closed row of three, for a program that did not start. `NotFound` is a name not on the `PATH`, a path with no file at it, or the empty name (Go's `exec.ErrNotFound`, `fs.ErrNotExist`). `Denied` is a file the process may not run, a directory included, as Go's `LookPath` reports it (`fs.ErrPermission`). `Failed` is every other reason, with the host's text, such as a `Dir` that does not exist (`dir /x: no such file or directory`). An uncaught one is written with its generated text and status 1, such as `error: exec.NotFound{Name:git}`. The law `NotFoundNamesTheProgram` states that `NotFound` names the program.
5. **The stop protocol.** The Go body is `v1.ExecRun(t *rt.Task, name, args, env, dir, stdin)`. Its `runtimeBindings` row waits on the caller's task (`callerWait`); the stop of that task is its cancel hook ([Host packages](#host-packages)):
   - The program starts in a process group of its own (`Setpgid`), which holds it and each process it starts that does not leave the group.
   - `Run` returns only after the program is reaped and its output is read.
   - A stop of the calling task sends `SIGKILL` to the group, waits until the program is reaped, and ends the call with an interruption. So the caller's exit actions run after the program is gone. Inside a mask the wait is uninterruptible, and the program runs to its end.
   - After the program exits, `Run` sends `SIGKILL` to what is left of its group.
   - After either kill, `Run` waits until the group is empty: `SIGKILL` only marks a process, the kernel ends it later, and the host's reaper then reaps it. A process keeps the group's id until it is reaped, so `kill(-group, 0)` fails with `ESRCH` exactly when no process of the group is left, zombies included. The wait is at most 500 ms (for a slow reaper, or a process in an uninterruptible wait, which has `SIGKILL` pending and runs no code of its own again); an empty group costs no wait. So a call leaves no process of the group, not even a zombie (measured: without the wait, a killed grandchild was still in the run state 22 µs after `Run` returned). A process left in the group that holds stdout or stderr open delays the return by at most 500 ms (as Go's `WaitDelay` does), and `Run` then returns the status and the output read so far. A program that must outlive the call leaves the group itself (`setsid`).
   - The body signals only the group of the program it started, whose id is the program's pid, and only while it holds it. `Run` waits for the program's end without reaping it (`waitid` with `WEXITED|WNOWAIT` on Linux; a kqueue `EVFILT_PROC`/`NOTE_EXIT` on Darwin and the BSDs, where `waitid` also returns on a stop, golang/go#19314). An unreaped program, alive or a zombie, keeps its pid and so the group's id, so no other group can have that id at either kill. `Run` reaps the program after the kill, and then waits for the group's end with `kill(-group, 0)`, which sends no signal. `Run` reads the output from pipes it owns, so it can wait for the output's end before the reap. `TestExecStopModel` checks, at each kill, that the program is still unreaped in its group (a test hook).
   `TestExecStopModel` runs 120 generated programs (output, grandchildren that close or hold the output, exits by status and by signal, a block) with the caller stopped before the call, while the program runs, inside a mask, or never, against a model of the states `Running`, `Exited(status)` and `Killed`: the result, the output, the reap of the program and the end of every process in its group. Lower `TestExecRuns` stops a task once its program has started, and the program never reaches the line after its 20 s sleep; the check is that order, not a wall-clock bound.
6. A program implements `exec.Runner`: no std extern returns it, so it is open (`check.SealedStd`). `exec.Script` is the std's test provider: `Run` gives the `Result` that `Results` holds at `Key(c)`, or `NotFound` (the law `ScriptReplaysRecorded`). `Key(c)` is the name and each argument with a NUL byte before each argument, made by one `strings.Join` (`exec` imports `strings` and `slices`); no program's name or argument holds a NUL byte, so two commands have one key exactly when their names and arguments are equal. The law records the arguments `arg, arg` and the one argument `arg + "," + arg` side by side, so a key whose separator a program can write makes it false. The environment, the directory and the standard input are not in the key. A test binds `with context { exec.Runner: exec.Script{Results: …} } { run() }` in the place where `main` binds `exec.NewHost()`.
7. The four records are the `runtime/v1` structs `v1.ExecNotFound`, `v1.ExecDenied`, `v1.ExecFailed` and `v1.ExecResult`, by the binding table (Types 4), so `exec.NotFound` and `fs.NotFound` are two Go types.
8. Speed: process start dominates a run. `BenchmarkExecRunTrue` holds `Run` of `true` to Go's `exec.CommandContext(ctx, "true").Run()`, and `BenchmarkExecRunMiB` holds a run that writes 1 MiB to a hand `bytes.Buffer` read and its `String()`. The body copies each stream once into its string, as the Go control does; no `unsafe` (std-align section 4: no measured gain over process start).

*Prior art:* Go's `exec.CommandContext` kills only the process it started, by `cmd.Cancel`, and `WaitDelay` bounds the wait for output a grandchild holds; Ergo kills the whole group, as a shell's job control does. Effect's `ChildProcess` spawns in a scope that kills the process when the scope closes, and gives `exitCode` as a value, not a failure. Elixir's `System.cmd/3` returns `{output, status}` with a status that is not 0 as data, and takes `env:` and `cd:` options; Gleam's `shellout.command(run:, with:, in:, opt:)` returns `Result(String, #(Int, String))`, which makes a status that is not 0 an error; ReScript binds Node's `child_process.spawnSync`, whose result holds `status`, `signal`, `stdout` and `stderr`. Ergo returns the status as data, as Elixir and Effect do, and keeps the failures for a program that did not start.

1. **Domain.** The clock's domain is the task that calls `NewVirtualClock`, from that call on, and every task started below a task of the domain. A task that made an earlier VirtualClock leaves that clock's domain. Tasks started before the call are outside it: the clock does not wait for them.
2. **When the time moves.** The clock counts the live tasks of its domain and those parked in a wait it sees: a `Sleep` on the clock, a queue's `Push`, `Pop` or `Values` step, a `Task`'s `Wait` and `Stop` (and a frame's drain of its tasks), and `timeout.After`. When the counts are equal and a sleeper is armed, the time moves to the earliest deadline, and every task asleep until that deadline wakes, in the order they slept. It never moves while a task of the domain can run.
3. **A host wait keeps the time still.** A wait on anything else, such as a read of the host's input or a file, a sleep on the host or on a `time.Manual`, or a lock, is not parked. So the clock does not move past it: a test that feeds standard input sees no timeout fire while the read waits.
4. **No lost window.** A waiter parks in the same step that checks its event, under the clock's lock, and the waker clears the parked flag of the task it wakes before the event is visible (the queue's signal, the end of a task, a timer, a stop). The Quint model of the batch-12 C1 unit checks the protocol (`time moves only when all are idle`, `no wake-up before its deadline`, `no lost wake-up`); `TestVirtualClockModel` (runtime/v1) runs generated programs of 1 to 5 tasks against a discrete-event model, 300 seeds.
5. **Time.** `Now` is `time.Unix` of the clock's reading: the Time has no monotonic reading, and the clock's wall time never falls. The clock is the one interface every machine timer reads ([runtime.md, Machines and actors](runtime.md#machines-and-actors) 9.6, one clock): `Scheduler.Sleep` and `time.Clock.Now`. `machines.RunTimed` reads both, and a live runner sleeps on them, so a machine's timers and a test's sleeps run on one virtual time with no change.
6. **Laws.** `SleepAdvancesExactly`: a lone `Sleep(d)` moves the clock by exactly `d`. `IdleOnlyAdvance`: a task that pushes while its parent sleeps reads the start time, and the parent wakes at its deadline.

*Prior art:* Go 1.25 `testing/synctest` moves a bubble's clock when every goroutine in the bubble is durably blocked, which the Go runtime knows; Ergo's runtime learns it from its own waits. Tokio `time::pause()` auto-advances when the runtime is idle; Trio `MockClock(autojump_threshold=0)`. Effect's `TestClock` moves only on `TestClock.adjust` (Ergo's `time.Manual`). Gleam, ReScript and Elixir lower no virtual clock: on the BEAM and in JavaScript it is a library over the host scheduler. *Effect workarounds replaced:* `TestServices` and `TestContext` layers become an ordinary `context`; `Effect.fork` before `adjust` becomes no step at all, since the clock moves on idle.

# Types

Definitions of every term used here are in the [glossary](../../GLOSSARY.md). Each section carries its status.

Types are nominal. Two named types are identical only when they are the same declaration. Which value goes where is one relation, [Assignability](#assignability). *Prior art:* Go's named types and implicit interface satisfaction; Gleam and ReScript custom types are nominal too.

## Assignability

Status: **checked** by `internal/sketch/check` as one relation, `assignability`, and **lowered** from the fact it records (check-v1 stage D3a).

```go
type Ints []int
type Store { Get() int }
type Count int
func Get(c Count) int { int(c) }

let raw []int = named      // clause 2: named is an Ints
let s Store = Count(3)     // clause 3: Count implements Store
let o Option[int] = None   // clause 4
```

1. **The clauses, in Go's order.** A value of type `V` is assignable to type `T` by the first clause that holds, and each clause names the implicit conversion the assignment makes, the fact `Info.Implicit` records at the value:
   1. `V` and `T` are identical. No conversion.
   2. `V` and `T` have identical underlying types, at least one of them has no name, and neither is a type parameter. A declared type, a basic type and a type parameter have a name; a slice, Map, function or tuple type written in place has none. No conversion: `let raw []int = named` and `let named Ints = raw` cross, `Ints` to another `type Other []int` does not.
   3. `T` is an operation type and `V` implements it ([Interface assignability](#interface-assignability)), whatever `V`'s name. `ConvOperations` with the function that provides each operation, or no conversion when `V` is itself an operation type's value. Check implementation first, so a missing operation is the diagnostic when both checks fail. Then refuse a `V` that holds a `Task` when `T` holds none ([Task ownership](#task-ownership)), so `Phantom[Task[int, Fault]]` still admits a `Task`.
   4. `V` is a variant of the union `T` ([Unions](#unions) 2), or a row value whose every error type is a variant of `T`. `ConvVariant` or `ConvRow`.
   5. `V` and `T` are function types with the same parameters and results, `V`'s error and `needs` rows are subsets of `T`'s, and at least one of them has no name ([Function values](#function-values) 1). No conversion: a function value has one Go shape.
   6. `V` is a machine declaration `type X machine[S, E]` and `T` is the prelude's `Machine[S, E, O, F, R, W]` with `O`, `F` and `R` its step's output, error row and capability row and `W` its work's capability row, apart from `R`, so a fold that runs no work needs `R` only (fumb-e) ([Prelude types](#prelude-types); README Gap 46). `ConvMachine`: the value becomes `Machine{Initial: X's initial value, Step: its step function, After: its after function}`, or, with no `after` entry, a function that gives every state `None`. A machine whose `initial` names a start function of an input `I` converts the same way to `InputMachine[I, S, E, O, F, R, W]`, with `Start` in place of `Initial`, and to no `Machine`. A `Machine` of another instance is S108, and the message names the output and rows the step gives. The checker tries this clause after clause 2: no operation type, union or function type is a `Machine`.

   Nothing else is assignable (S108). Two named types cross by no clause unless clause 3, 4 or 6 relates them: `type A Mem` and `type B Mem` over one record, `Count` and `int`, `type F func(n int) int` and `type G func(n int) int` each need a conversion ([Conversions](#conversions)), and the message names it only where one exists.
2. **Every site.** One relation decides every place a value is assigned: a `let` (single, and per element of a multi-name `let`, whose element conversions `Info.ImplicitElems` records), an argument, a result, a pattern's written type, a composite literal's field and element, the two operands of `==` and `!=` (one goes into the other's type), and a `context` value. The lowering reads the fact and never derives a conversion again.
3. **Comparison through operations.** A value that implements an operation type through its functions is not that type's value until it is assigned, so `s == Count(1)` with `s Store` is S108; assign it first.
4. *Prior art:* go/types `operand.assignableTo` has clauses 1 to 3 in this order, and cmd/compile's `typecheck.assignOp` returns the lowering operation (`OCONVNOP`, `OCONVIFACE`) with the reason from the same clauses, as `assignability` returns the conversion. Gleam and ReScript have no defined types over collections (an opaque type converts through functions); Rust newtypes cross only by `.0` or `From`.

## Bindings

Status: **implemented** for slices and Maps by the lowering (value-rule; owner q26, 2026-11-08; [decisions](../decisions.md)): `internal/sketch/lower/values.go`, with `TestValueRuleProbes`, `TestValueRuleAgrees`, `TestValueRuleRace`, `TestValueRuleElides` and `TestValueRuleMutants`.

```go
func example() {
	let m = Map[string, int]{"a": 1}
	let mut c = m
	c["b"] = 2 // m still has one entry
	let s = []int{1, 2}
	let t = s.Append(3) // s is still [1, 2]
}
```

1. **Every value is a value.** A slice and a `Map` are values, as an `int` and a record are: a binding, a field, an element, an argument, a capture and a value sent to a task each hold their own. A write through a `let mut` root or a borrow (`m[k] = v`, `xs[i] = v`, `p.f[k] = v`, `m = m.Delete(k)`, `xs = xs.Append(x)`) is seen through that root alone, never through another binding, a package `let`, a record field, a slice element, the caller's argument, a function literal's capture or another task. The prelude's `Append` and `Delete` leave their argument unchanged ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Slices and Maps). So a function the checker calls pure ([rows.md](rows.md#footprints)) gives equal results for equal arguments, and two tasks never write one Map. Owner q26, 2026-11-08: "Maps and slices are values: copy where two bindings would share, elided when the source is new or dead".
2. **Lowering.** A slice and a `Map` stay Go's slice and map. The lowering inserts a copy (`maps.Clone`, `slices.Clone`, or a generated copy function that copies each element when an element holds a slice or `Map`) only where a write could be seen through another binding, decided once per body from the checker's facts:
   - a value entering a `let mut` root or a place rooted at one is copied unless it is fresh: a literal, the result of a call whose results are fresh, or a local that is dead after the bind and was never shared (move on last use);
   - a read of a `let mut` root that another binding keeps is copied when a write through the root can follow it; a read that keeps nothing (`len`, `==`, interpolation, a `Get`) and a return of the root are never copied;
   - `p = p.Append(x)` and `p = p.Delete(k)` on one place write in place, so a loop that builds a slice or `Map` allocates what Go's does; elsewhere `Append` appends to a clipped slice and `Delete` deletes from a copy;
   - a function literal or block that may outlive its call ([Function values](#function-values) 2) takes a copy of each captured `let mut` slice or `Map` that a write can follow;
   - an *owned parameter* is copied by its caller, not by its callee. A parameter is owned when its function binds it to a `let mut` local once, in the body's own frame and outside any loop, reads it before that only in uses that keep nothing, never reads it after, and cannot fail after the bind (no call that can fail there, no returned error value). A direct call passes the argument unshared: a copy only when it is not fresh and not a local dead after the call. A rebinding `p = f(…, p, …)` (or `p = try f(…)`) of one place rooted at a `let mut` local hands the old value over with no copy, when no other frame reads or writes the local and the statement uses it nowhere else. So `m = maps.Update(m, k, f)` and `b.M = put(b.M, k)` write `m` in place, as hand Go writes `m[k] = f(m[k])`, and a loop of them allocates what Go's does. The function's own name stays a wrapper that copies each owned argument, which every indirect call (a function value, an operations conversion, a witness) reaches.
   - a `sync.Ref` owns its value ([stdlib.md, Sync and STM](stdlib.md#sync-and-stm) 1; V6, owner q46): the parameter of a function literal written at `Ref.Update` or `sync.Modify` is an unshared local, which the `Ref` copies first when its value may be reached from outside.

   Three facts sharpen what a use keeps: a call of a pure function whose result reaches no slice or Map type its argument reaches keeps nothing of the argument (`find(t, path)` that returns a place); a part of a returned tuple or literal is returned with it; and a use in one `return` (or last value) of a frame never runs before a use in another, since each ends the frame.

   A copy is deep through slices, Maps, records and tuples, and stops at a union, an `Option` and a function value, whose parts a match or a call binds immutably. The reference lowering, which shares as v1 did, is selected with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.valueLowering=alias`; `TestValueRuleAgrees` proves it equal to the rule on seeded programs with no shared write, and the rule equal to a value-semantics interpreter on programs with one. `valueLowering=copy` selects the rule without owned parameters, each callee copying at its bind; `TestValueRuleAgrees` holds it to the same interpreter on the same programs.
3. **Unchanged.** A `for` over a slice or `Map` keeps Go's rules ([Loops and len](#loops-and-len) 1). A captured scalar `let mut` still follows Go's capture by reference; Function values 3 owns it ([#197](https://github.com/cevr/ergo/issues/197)).
4. *Prior art:* Swift's `Array` and `Dictionary` are values copied on write after a uniqueness test of their reference count, and its optimizer removes the copies it proves unneeded; Hylo has mutable value semantics; Gleam, Elixir and ReScript lists and maps are immutable, so no write is shared; Rust refuses the shared write in its borrow checker; Go shares. Ergo has no reference count, so it copies on a static fact.

## Task ownership

Status: **checked** (check-v1 stage D3a). [runtime.md](runtime.md#tasks) rule 3 defines which types hold a Task and the type positions that admit them.

1. A Task-holding value flows only into these uses: a local `let` in its own frame; a return (an explicit return or a body's final value); a call argument; or the direct receiver of a called `Wait` or `Stop`. A dot call to a package function uses its receiver as the first argument and follows the argument rule. Assignment checks the parameter type; clause 3 refuses erasing a Task into an operation type that holds none. A type argument, written or inferred, never holds a Task: `id(t)` for a generic `id`, `Box[Task[int, Fault]]` and a method value of a generic type instantiated with a Task are S108 at the instantiation (**implemented**, check-v1 stage E2). *Prior art:* Swift generic parameters are implicitly `Copyable` and `Escapable`; Ergo has that default without the opt-out.
2. Parentheses, `try`, `catch` and `go` are transparent wrappers: the wrapped value must flow into an allowed use. They do not make a discarded Task legal. A final value can flow through `if`, `match`, `catch`, `try` or `with` into a return or another allowed sink.
3. Every other use is S108. A reference to a Task-holding local from another frame is also S108, wherever it stands. Function literals, trailing blocks other than `with`, and `go` blocks open frames. A refused type covers values assigned into it, so later uses add no diagnostic.
4. **Lowering** (check-v1 stage D3b; [stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Hidden arguments). A function whose result is a `Task` takes the caller's frame scope as a hidden destination and moves the Task there on return, so the Task outlives its own frame and the caller's scope stops and drains it if nobody waits. A result holds a Task only by being one: rule 1 refuses a Task as a type argument, and the type-position rule refuses a Task held inside another type (S108). A call that needs a frame scope (a call whose result is a Task, `scope.OnExit`, an owning `with` or a context `with`) outside a function body, in a package `let`'s value, is S108; inside a package `let`'s trailing block or function literal it has that block's frame scope (**implemented**, check-v1 stage E2). *Prior art:* Gleam's constants hold no effects.

These two uses are refused even though they mention the Task's local frame:

```go
// In a function that holds t:
t = task.Go() { work() }       // reassignment is not an allowed use
(func() { t.Stop() })()        // even an immediately called literal is another frame
```

4. *Prior art:* Rust checks ownership across scoped threads and trait objects; Elixir's Task checks its owner at run time. Gleam and ReScript have no Task ownership rule in their types. Ergo checks the frame and allowed uses before lowering.

## Basic types

Status: **implemented**: `bool`, `string`, `int` to `int64`, `uint` to `uint64`, `float32`, `float64`, `complex64`, `complex128` and `duration`, with `byte` and `rune`, are checked by `internal/sketch/check` and lowered to their Go types, `duration` to `time.Duration` (check-v1 stages B to E; `TestInterpolationText` runs a value of every basic kind through lowered code). Rules 6 and 8 are **implemented** by the checker and the lowering (check-v1 stage E1).

1. `string` holds bytes. A literal's value is the bytes its spelling decodes to ([grammar.md](grammar.md#literals)).
2. The integer types are Go's, with Go's sizes. Non-constant arithmetic wraps; constant overflow is an error (rule 7).
3. `bool` is the type of comparisons and `if` conditions.
4. `duration` is the type of duration literals. It is a basic type, usable in every type position: parameters, results, fields and type arguments. Its name is predeclared.
5. The composite types are slices `[]T`, maps `Map[K, V]`, queues `queue.Queue[T]` ([runtime](runtime.md#channels)), function types, tuples ([Tuples](#tuples)) and the prelude `Option[T]`. Ordering constraints such as `cmp.Ordered` are [#211](https://github.com/cevr/ergo/issues/211)'s.
6. **Literals are typed where they appear** (196u; checked by `internal/sketch/check`). A literal takes the type its context expects: a written `let` type, a parameter (after the type arguments that typed arguments fixed), a result (a `return` or a tail value), a record field, a slice element, a Map key or value, the other operand of a binary operator or of `..` (a composite literal of a generic type written without type arguments takes its type arguments from the other operand the same way, so `f() == Some{Value: A}` with `f()` an `Option[T]` compares two `Option[T]` values; K2, `TestComparisonGenericLiteralTakesOtherType`), an assignment's target, an index or slice bound (`int`), and a constant `case` (the subject's type). An integer literal may take any integer or float type, a float literal only a float type, a rune literal any integer type, and a string literal a string type; an integer literal is never a `duration` (S108 "an integer literal is not a duration: write a duration literal such as 5s"). Every other position gives no expected type, and the literal takes its default: `int`, `float64`, `rune`, `string`, `duration`, and `bool` for `true` and `false`. A literal that cannot take the expected type is S108 naming the form to write ("a float literal takes only a float type, not int; write 2").
7. **A name has one type.** A package-level `let` has one type, and no name converts by itself: `let b int8 = Limit` with `let Limit = 10` is S108 "Limit is int; write int8(Limit) or declare Limit int8". Constant expressions evaluate exactly, step by step, and each typed step must fit its type: an overflow is S108 ("the constant 200 overflows int8" for `let y int8 = 100 + 100`, and for `100 + 100 - 100`, whose first step overflows), as in Rust's constant evaluation. A literal fits its type after its sign, in parentheses or not, so `-128` and `-(128)` are `int8`. Ergo has no untyped constants: Go's untyped kinds, their defaulting order and the contextual types Go records afterwards are the counter-example (#196, 196u "Why"). *Prior art:* Rust and Swift type a literal from its context with `i32` and `Int` defaults, and `1 + 2.5` is an error in Rust; MoonBit overloads an integer literal by its expected type (`let x : Int64 = 1`); Gleam, and ReScript after OCaml, keep `Int` and `Float` apart with separate operators (`+`, `+.`); Elixir's numbers are dynamic.
8. **The closed world** (196d; check-v1 D-E2). `any` is not a type: its use, as a type or as a constraint, is S104 "Ergo has no any; use a type parameter or a union", and `[T any]` is written `[T]`. The one exception is not a constraint: `any` ends a group of unconstrained type parameters that a constrained group follows, `[E any, K comparable]` ([grammar.md](grammar.md#declarations) 3; fu8b); the parameters it ends have no constraint, as `[E]` has none. `error` is not a constraint either: `[E error]` is S104 at `error`, and a failure row parameter is written `[E]` and used after `fails`. No std package is named `reflect`. Equality is generated from declared types ([Operators](#operators) 1), so no value is compared through an interface. *Prior art:* Gleam has no `any` and compares by structure; ReScript and OCaml compare structurally; MoonBit derives `Eq`; Go's `==` on interfaces panics at run time on an incomparable dynamic type.
9. **Text form** (check-v1 E6a, D-E6). A value of every basic type interpolates, `"\(x)"`, as Go's `%v` prints it, complex and `duration` values included ([grammar.md](grammar.md#literals), Strings 5).

## Zero values and definite initialisation

Status: **implemented** for rules 1 to 3 and 5: checked by `internal/sketch/check` and lowered, a defaultable type to Go's zero value (check-v1 stages B to D; `let p Payment` with no value is S108 "let p of type Payment needs a value: Payment has no zero value (types.md, Zero values 3)", `TestDecidedMessages`). Rule 4 has no built-in to apply to. Rule 6 is **implemented**: checked by `internal/sketch/check` (196b Q7, [decisions](../decisions.md#decided-by-principle-2026-11-05); S114, `TestConstructionAuthority`, `TestConstructionAuthorityShapes`).

1. A type is *defaultable* when it has a valid zero value: a basic type (and a defined type over one), a slice, a Map, a record with no fields, or a tuple of defaultable types. A record with fields is not defaultable (rule 2), nor is a union, a capability, a function type, a `Task`, a resource, a borrow, or a tuple that holds any of them.
2. **No implicit zero** (owner q44, 2026-11-09). A record value is built only by a literal that names every field, keyed or positional, or by a record update (Structs 3). A keyed literal that leaves a field out is S108 at the literal, whatever the field's type; the message names every field it leaves out, in declaration order, and the two fixes: "Walk{…} does not set Retries: a record literal names every field; write Retries: …, or copy it from a value with Walk{..v, …} (types.md, Zero values 2)". So a field added to a record stops every literal that does not name it. *Principle:* every field value comes from a site that named it. *Prior art:* Rust E0063 "missing field", OCaml, Elm, Gleam and ReScript require every label; Go fills a left-out field with its zero value, and the third-party linter `exhaustruct` exists to catch that.
3. A variable of a non-defaultable type must be initialised before use. `let p Payment` with no value is an error, and so is `let w Walk` for a record `Walk` with fields, `let v (Walk, int)` and `let b Box[int]`. A basic type, a slice and a Map keep their zero value: `let n int` is `0`, `let xs []Walk` is empty. Outside its package, a record that only its package builds is S114 first (rule 6), since that message names the function to call. *Prior art:* Swift and Kotlin definite initialisation; Go instead gives every type a zero value, which is how a nil interface reaches a type switch.
4. Designed: an operation that invents zero values needs a defaultable element type. The decided language has no such built-in (`make`, the comma-ok forms and channels are gone, #196); the library returns `Option` instead, as `m.Lookup(k)` returns `Option[V]`.
5. There is no `nil`. *Prior art:* Gleam, ReScript and Rust have no null; Go's typed-nil interface and nil map are its most cited traps.
6. **Construction authority.** Outside the package that declares it, a struct type with an unexported field ([grammar.md](grammar.md#visibility)) is neither defaultable nor literal-constructible. A defined type over such a struct has the authority of the package that declares the fields (`type M lib.Q`), and a struct, tuple or instance that holds one by value needs it for its zero value. Each of these is S114 outside the package:
   - a composite literal of the type or of a defined type over it, keyed, positional or empty (`lib.Q{N: 1}`, `lib.Q{}`, `M{}`);
   - a record update of it, `lib.Q{..q, N: 2}`, even when it names exported fields only;
   - an implicit zero value: `let q lib.Q` with no value, at package level or in a body, also inside a tuple type (`let v (lib.Q, int)`) or an instance (`let b Box[lib.Q]`). A keyed literal of an enclosing struct that leaves a field unset (`H{B: 1}` with `A lib.Q`) is S108 by rule 2. A Map read never invents a value: it is `m.Get(k)`, which returns `Option`.

   The message names the package and up to three of its exported functions whose result is the type: S114 "a literal of lib.Q builds a new value: lib.Q has an unexported field, so only package lib builds it; use lib.ParseQ". Allowed outside: the values its package's exported functions return, a conversion between a defined type and its base (no new value is made), reads of exported fields, patterns, copies, and a literal or update of an enclosing struct that sets the field (`H{A: lib.ParseQ(1), B: 1}`, `H{..h, B: 2}`). A property parameter of such a type is S108 outside the package, because a generator builds it field by field, unless the package declares its constructor `New<T>`, which the generator then calls ([runtime.md, Tests](runtime.md#tests) 6) ([grammar.md](grammar.md) Declarations 11). The checker exports the rule as `check.Constructible(t, from)`, which generators, codecs and `refine` read. It exports a second fact, `check.Buildable(t, from)`: whether `from` makes a value of `t` at all with no authority, from literals, empty literals, zero values, conversions, function values and its own implementations of an open operation type (a sealed operation type is built when a type of its package that implements it is; an empty `[]lib.Q{}` is built, so a record whose exported field is `[]lib.Q` is Buildable and not Constructible); the std host guard reads it (stdlib.md, Host packages 6).

   Inside the declaring package, the construction-authority restriction is lifted, and the ordinary rules 1 to 4 still apply. A record with fields stays non-defaultable in its own package:

   ```go
   type State = Idle | Running
   type Idle {}
   type Running { Since int64 }
   type Box { state State }

   func newBox() Box { return Box{state: Idle} } // allowed: a literal inside the package
   func zeroBox() Box {
   	let b Box // error even inside the package: Box is a record with fields, so it has no zero value (rules 2 and 3)
   	return b
   }
   ```

   Values from outside come only from the functions the package exports, so `ParseQuantity` is the only way to build a `Quantity` and its check cannot be bypassed. Exports stay by capitalisation. *Prior art:* Rust forbids constructing a struct with private fields outside its module and gives it no `Default` unless the module derives or implements one; Gleam's `opaque` types hide constructors; Go leaves this hole open: a two-package probe builds `Quantity{}` and `make([]Quantity, 1)` from another package and reads `units=0` for both (review round 2 receipt).

## Structs

Status: **implemented**: rules 1 to 4 are checked by `internal/sketch/check` (check-v1 stage B, D-B2) and lowered to Go structs (check-v1 stage C). Rule 5 is [#197](https://github.com/cevr/ergo/issues/197)'s (aggregate resources, [resources.md](resources.md)); rule 6 is **designed**; rule 7 (included records) is **implemented**.

```go
type Order {
	ID    string,
	Total int64,
}

let order = Order{ID: "42", Total: 1999}
let same = Order{"42", 1999}
```

1. Field names in one struct are distinct (S108). A field and a function on the type (see [Methods](#methods)) may share a name: `x.f` is the field first (196m).
2. A composite literal is all keyed or all positional (S001). A positional literal lists every field in order (S108). A keyed literal sets each field exactly once (S108; [Zero values](#zero-values-and-definite-initialisation) 2) and names only declared fields (S104). A record update `T{..base, F: v}` is a keyed literal whose other fields are the base's (rule 3). **A record with no fields is written bare** (check-v1 D-B2): its name is its one value, `return Pending`, and `Pending{}` is S108 "a record with no fields is written bare: Pending"; a bare name of a record with fields is S108 "Paid has fields; write Paid{…}". A function on such a record is called on the bare name, `Runner.Each(f)`: there are no method expressions to confuse it with. In a pattern the bare name tests the type ([rows.md](rows.md#totality), Totality 1). *Principle:* one form per job. *Prior art:* Rust unit structs, Gleam fieldless constructors and ReScript constant constructors are bare.
3. Each field value must be assignable to the field's type (S108). A field value whose failure is not handled is S105. A field value that is a composite literal writes its type, keyed or positional: `Wrap[S]{value: {h: 1}}` is S108 "missing type in composite literal; write S{h: 1}" (the literal's source is `{…}` past 40 characters or across a line). As in Go, a composite literal may elide its type only as an element of an array, slice or map literal or as a map literal's key (Go spec, "Composite literals"; #196 round 17 C1). *Prior art:* go/types reports "missing type in composite literal" there, and Ergo adds the fix; Rust and Gleam always name a record's constructor.

   **Record update** (2026-11-05; [grammar.md](grammar.md#expressions), Expressions 11). `Walk{..w, Turn: w.Turn + 1}` is a copy of `w` with `Turn` replaced. It is a composite literal of `Walk`, so every rule about who may write a `Walk` literal applies to it unchanged ([grammar.md, Visibility 3](grammar.md#visibility)), and its fields follow rule 2 and this rule: each named once, declared, assignable, a failure handled.
   - `T` is a record type: an update of any other type is S108. A generic `T` written without type arguments takes them from the expected type, or else from the base: `Box{..b, V: 2}` with `b Box[int]` is a `Box[int]`.
   - The base is a record value, checked with `T` as its expected type. A value that is not a record is S108 at the base. A union value is not a record value: `Playing{..g, W: w}` with `g Game` is S108, because `g` may be another variant; match it first (`case Playing as p:` then `Playing{..p, W: w}`).
   - With a base of exactly `T`, every field the update does not name is the base's, and it names at least one field: `Walk{..w}` is S108 at the literal, "a record update names at least one field; the copy is w itself" (one form per job).
   - **Spread** (owner q43 = A, 2026-11-09). With a base `s` of another record type `S`, `T{..s, F: v}` is a spread: each field `G` of `T` it does not name is `s.G`, where `S`'s field `G` has the same declaration as `T`'s and the same type. Two fields have the same declaration when `S` and `T` are instances of one record type (`Box[string]{..b, V: "x"}` with `b Box[int]` copies `N` and must name `V`), or when both come from one included record `..R` (rule 7), at any depth. Every other field of `T` it does not name is S108 at the base, one diagnostic per field: `S` lacks it ("AtLimit{..c}: Counting has no Reached; name it: Reached: …"), has it from another declaration ("AtLimit{..c} does not copy N: Counting's N and AtLimit's N are declared apart, and a spread copies only a field both take from one declaration; write N: c.N"), or has it with another type. Fields of `S` that `T` lacks are not copied, so a spread need name no field: `Visit{..p}` projects a `Visit` out of a `Prompt` that includes it, and `Prompt{..v, Left: 3}` injects one. The desugaring is the meaning: `T{F: v, G: b.G, …}` with `b` bound to the base first, so construction authority (S114), field visibility (S104), assignability (S108) and handled failures (S105) apply as at any literal. *Principle:* a field gets its value from a site that named it or from the one declaration it shares with the base; a field added to `T` stops every spread that cannot take it from that declaration ([decisions.md](../decisions.md), q43). *Prior art:* Gleam 1.6 infers the variant of a record update and 1.7 changes a type argument in one; Rust's RFC 2528 proposed type-changing struct update; ReScript and TypeScript spread copy by name, which this rule refuses for fields declared apart. Status: **implemented** (`record_update.go`, `Info.Spreads`; `TestSpreadMatchesModel`).
   - Order: the base is evaluated once, first; then the field values, in source order. The result is a copy of the base with the named fields replaced; the base is unchanged. A slice or Map field of the copy is a value of its own: a later write through either record is not seen through the other ([Bindings](#bindings); owner q26, 2026-11-08).
   - Laws: `T{..b, F: x}.F == x`; every other field equals `b`'s; `T{..T{..b, F: x}, G: y} == T{..b, F: x, G: y}` for distinct `F` and `G`; for one field the later update wins.
   - Lowering: a spread from another type is one literal of `T` with a read of the base per copied field, `b := s; T{F: v, G: b.G}`, as hand Go writes it; a base that is a variable or a field path is read in place when no named value runs code first. An update of the same type is a copy of the base and one store per named field, `u := base; u.F = v`, with no allocation; a slice or Map field is copied only where [Bindings](#bindings) 2 says a write could be seen through the other record. *Prior art:* Go has no update expression; its idiom is copy then assign, which the lowering writes. Borgo lowers Rust's `..rest` to a called function literal that evaluates the field values before the base; Ergo evaluates the base first, in source order.
4. A struct must not contain itself by value, directly or through other structs or tuple elements (S108). Recursion behind a union is allowed, because a union value is a reference in the lowered Go. The diagnostic names the cycle's members, one report per group of declarations that form one cycle together, at the group's first name in byte order ("A contains itself by value with B"), and a generic declaration is named only when every instantiation of it is infinite or when it writes the instantiation that closes a cycle (`type P[T] { A T, B P[int] }`), never when it only holds one (`type Box[T] { V T }`). *Prior art:* Swift's `indirect enum` boxes recursion; Go rejects an invalid recursive type.
5. A struct with a resource field is itself a resource ([resources.md](resources.md#what-is-a-resource)).
6. Designed: struct embedding is allowed only in `context` and in interfaces. Value semantics hold: a copy is a snapshot, slice and Map fields included, and move-on-last-use keeps it cheap ([Bindings](#bindings), implemented for slices and Maps).
7. **Included record** (owner q43, 2026-11-09; [grammar.md](grammar.md#declarations) Declarations 4). In a record declaration or a variant declared in place, the member `..R` includes the fields of the record `R` at that position, in `R`'s order, as the record's own fields: `type Visit { ..Owned, S Session }`, `type Kiosk = Suspended{..Owned} | Prompt{..Visit, Left int}`. Status: **implemented** by `internal/sketch/check` (`include.go`) and lowered flat (`TestIncludedRecordFlattens`).
   - `R` is a record with fields declared in this package, possibly an instance (`..Page[T]`). A record of another package, a union, an operation type, a type parameter, a basic or tuple type is S108 at the member, and so is a record with no fields ("drop the member").
   - A field name occurs once after inclusion: two members that give one name, an include and an own field of one name, and one record included twice through two paths (a diamond) are S108 at the later member, also with one type. So one name has one declaration.
   - An inclusion cycle (`type A { ..B }`, `type B { ..A }`, also through a variant) is S108, by rule 4. A record that holds the including record through a field (`type A { X []B }`, `type B { ..A }`) is not a cycle.
   - Each included field keeps its declaration: the field of `R` that declares it, through any depth of includes and in every instance (`check.Field.Origin`). A spread copies a field only from a field of the same declaration ([rule 3](#structs)).
   - The included fields are ordinary fields everywhere: a keyed or positional literal, a field read, a record pattern (`case Prompt{S: s, Left: n}`), equality, text forms, generated values, codecs and construction authority. `R` stays an ordinary record type. `..` in a pattern stays S001.
   - Lowering: the Go struct lists every field flat, in order; there is no Go embedding, so the lowering is unchanged. *Prior art:* ReScript 11's record type spread `type c = {...a, x: int}` copies field declarations and refuses a duplicate label; Go embedding promotes fields and refuses an ambiguous one only where it is used; Elm's extensible records type functions over "any record with these fields".

## Unions

Status: **implemented**: checked by `internal/sketch/check` (check-v1 stage B) and lowered (check-v1 stage C): a union is a sealed Go interface that its variants implement (a small signal union of a machine is a tag and slots instead: [runtime.md](runtime.md#machines-and-actors) 8, Flat signals), and a `match` on it runs (`TestErgoRunUnionOfOneGenericRecord`; [rows.md](rows.md#totality)). A record of another package as a variant is S108, a permanent rule (rule 1; 196b Q8; `TestUnionVariantFromAnotherPackage`).

```go
type Payment = Pending | Authorized | Declined{ Reason string }

type Pending {}
type Authorized { AuthID string }

type Option[T] = Some[T]{ Value T } | None{}
```

1. **Types by member shape** (check-v1 D-B1). Fields make a record, operations and laws an operation type, `=` a union, and `type N T` a defined type ([Defined types](#defined-types)); a type has one kind. A union lists one or more variants, each a record of this package. A bare-name variant names a record declared in the package: a basic, operation, union or defined type there is S108 "a union variant is a record declared in this package; Store is an operation type", and a record from another package is S108 at the variant, "a union's variants are records of its package; wrap timeout.Expired: type E = … | Expired{ Cause timeout.Expired }" (196b Q8, a permanent rule: a union's marker is a function of the variant's type, and a type's functions live in its package; [diagnostics.md](diagnostics.md#s108-type-or-declaration-misuse); `TestUnionVariantFromAnotherPackage`). An error row still names a type of another package directly: `fails Declined | timeout.Expired`. An inline variant `Declined{ Reason string }` declares that record in the package scope, usable as a type anywhere in the package; `Name{}` declares one with no fields. An inline variant of a generic union takes exactly the union's type parameters its fields mention, in the union's order (`Some[T]`, `None`). A variant may not be listed twice (S108). These variant rules hold for a union of two or more variants, and for a union of one variant declared in place; a union whose only variant is an existing type is that type (rule 7). *Prior art:* Gleam custom types and ReScript variants declare constructors inside the type, but those constructors are not types; Ergo's variants are record types so rows can share them (Koka, Effekt).
2. A value of a variant type is assignable to every union that lists it ([Assignability](#assignability) clause 4). A struct may be a variant of several unions (fixture `multiple-unions`).
3. A union has no zero value.
4. A `match` narrows a union value to its variants, nested through record patterns ([rows.md](rows.md#totality)).
5. The lowering gives each variant a marker method per union, with a Go name that no field or function of the variants takes (`lower/decls.go`, `unionMarker`). Ergo has no receivers (196m), so no source name collides with it; the prototype's S109 for such a name is gone (probe `marker-method` checks clean, `parity.overrides`).
6. **Lowering.** A union becomes a sealed Go interface with an unexported marker method, and each variant keeps its own struct fields. *Prior art:* Borgo lowers an enum to a tagged struct and matches on the tag; ReScript picks a representation per variant; Ergo keeps the interface form so a Go type switch narrows and each variant keeps its fields. The size trade-off between the two forms is not measured.
7. **Aliases** (fu-mb2 F11). A union whose only variant is an existing type is that type: `type EditActor = actor.Actor[Edit, EditSignal, Decision[Edit, EditOut]]` is an alias, and every use of `EditActor` is that type. A value of the alias is a value of the type and the reverse, with no conversion; a record is built (`EditActor{…}` for a record target) and read through the alias; a `match` on the alias is the type's match; and an alias of a variant is a `case` of its union. The existing type may be of any kind and of any package: a basic type, a record, a union, an operation type, an instance (`Option[Line]`), a type of another package, or another alias. A union of one variant declared in place, `type Hub = Shop{ … }`, declares its variant and stays a new type. An alias that names itself, directly or through other aliases, is S108 "the alias A names itself" at the name that closes the cycle; a declaration body the target mentions may name the alias (`type E = … | Opened{ Sub EditActor }`). An alias takes no type parameters yet: `type A[T] = Box[T]` is S108 at the brackets. Diagnostics print the target, not the alias's name. **Lowering:** Go's `type A = B`; no lowered code names `A`, so a value never converts (`TestAliasChecksAsItsTarget`: a seeded program of aliases checks as the program with each alias written as its target). *Prior art:* Go `type A = T`, Gleam `type Headers = List(#(String, String))`, ReScript `type t = other`, Elixir `@type t :: …` and TypeScript `type A = …` are plain aliases; Ergo spells one as a union of one existing member, because a union over existing types is the set of those types.

## Defined types

Status: **checked** by `internal/sketch/check` (check-v1 stage B) and **lowered** (check-v1 stage C): a Go defined type over the base type's Go type.

```go
type Celsius float64
type Span (int, int)
```

1. `type N T` defines a new nominal type over `T`, a basic, slice, Map, function, tuple or record type; a record instance (`type P2 Pair[int, int]`) and a variant (`type S2 Some[int]`) are record types. `N` is not identical to `T`. A value crosses between them by conversion ([Conversions](#conversions)), or, when `T` has no name (a slice, Map, function or tuple type written in place), by assignment ([Assignability](#assignability) clause 2): `let raw []int = named`. A defined type over a type parameter or over itself is S108. A defined type over any other type, an operation type (Task and the std operation types included), a union or an instance of a generic one, is S108 at the definition, "a defined type is over a basic, slice, Map, function, tuple or record type, and Store is an operation type; use Store directly", and its uses add no diagnostic (check-v1 stage D3a). A use in a list (a row entry, a type argument, a tuple element, a union variant, a context entry key, a parameter, a field, a pattern of a case) makes that element invalid and keeps the others ([rows.md](rows.md) Inference 6 for rows). A defined type over a Task-holding record or slice, `type B Box[Task[int, Fault]]`, is S108 with the Task text ([runtime.md](runtime.md#tasks) rule 3). An operation type and a union keep one name each. *Prior art:* Gleam, ReScript and MoonBit have no newtype over a trait or a variant; Go has defined interface types.
2. A defined type over a tuple destructures like its tuple (`let (lo, hi) = span`); a defined type over a record keeps its braces, even with no fields.
3. Its operations are those of `T`: arithmetic on `Celsius`, comparison where `T` is comparable.
4. A defined type over a record, named in an error row, is an error type of its own ([Error types](#error-types)): it is thrown and caught as itself, by type test and by record pattern, and its text is its base record's. A constant of a defined type keeps that type: `func f() Flag { true }` is `Flag(true)` in Go.
5. A value of a type defined over a basic type, at any depth (`type Warm Celsius`), interpolates as its basic value prints; a value of a type defined over any other type has no text form, as its base has none (check-v1 E6a; [grammar.md](grammar.md#literals), Strings 5).

## Tuples

Status: **checked** by `internal/sketch/check` (check-v1 D-B6, 196t).

```go
func DivMod(a, b int) (int, int) { return (a / b, a % b) }

let (q, r) = DivMod(7, 2)
let pair (int, string) = (q, "x")
```

1. A tuple type `(A, B, …)` has two or more elements and is structural: two tuple types are identical when their elements are. A tuple value is `(a, b)`.
2. A tuple is read only through a pattern ([rows.md](rows.md#totality)): `let (a, b) = t`, `for (k, v) in …`, `case (A, _):`. There is no `.0`.
3. A function has one result, which may be a tuple; a call is one value, so `f(g())` passes `g`'s tuple as one argument. `let q, r = e` destructures a tuple result, and a value of a type defined over a tuple through its underlying tuple, as a tuple pattern matches it (check-v1 E6b, C45; `TestDefinedTupleLet`, `TestErgoRunDefinedTuple`). Tuple assignment does not convert its elements. Returning `pair()` from `(Mem, int)` as `(Store, int)` therefore names a repair when `Mem` implements `Store`: `let (m, n) = pair(); return (m, n)`, source on one line, with the call copied byte for byte, that checks in place of the body. There is no repair for a call written over more than one line. Each element of the returned literal takes its expected type. The checker chooses unbound names for the repair.
4. A tuple is comparable when its elements are, and defaultable when they are. It has no operations, so it implements no operation type.
5. *Prior art:* Gleam, ReScript and MoonBit tuples with pattern access; Elixir tuples; Go's several results exist mostly for `(T, error)`, which `fails` replaces.

## Capabilities

Status: **implemented**: checked by `internal/sketch/check` ([#196](https://github.com/cevr/ergo/issues/196)) and lowered: a capability call reaches the provider the nearest `with` binds, and a method call on a value of an operation type runs that value's method (check-v1 stages C and D3b; `TestErgoRunE1Witnesses`). The prelude capabilities' method sets are provisional until [#209](https://github.com/cevr/ergo/issues/209) (rule 5).

```go
type Orders {
	Find(id string) Order fails OrderNotFound,
}
```

1. An interface with method signatures declares a capability. Method names in one capability are distinct (S108).
2. **A capability is not a first-class value.** The capability name denotes the provider that the nearest `with` binds. `Orders.Find(id)` calls that provider and charges `Orders` ([rows.md](rows.md#capability-rows)). Any other use of the name as an expression is an error: `Orders.Find` without a call (S108), and passing, returning, storing or capturing `Orders` (S104; README Gap 29).
3. **Capability name against interface type.** The same interface declaration has two roles, told apart by position:
   - in a `needs` clause, a `context` entry, or as the receiver of a method call `Orders.m(…)`, the name is the **capability**: an ambient requirement that only `with` supplies;
   - in a type position (a parameter, result, field or type argument), the name is an ordinary **interface type**. A value of it is a provider value. Calling its method, `o.Find(id)`, runs that provider's method with the method's declared error row and charges no capability. A constructor that returns `Orders` returns such a value.

   This keeps decision #102: a capability is an ordinary interface bound by `context`, and only the ambient binding is second-class. The checker implements both roles (README Gap 29), and the lowering runs both. *Prior art:* Effect separates a service's tag, the requirement, from a service value; Scala 3 capture checking treats capabilities apart from their types.
4. A capability method's signature carries its error row. A capability or interface method writes no capability row (S108), because a provider's requirements are captured at construction (README Gap 17).
5. The prelude capabilities `Console`, `Scheduler` and `Random`, and std `time.Clock`, are ordinary interfaces bound by `context` (decision #102). The prelude (`internal/sketch/std/prelude.ergo`) declares its three with the methods the fixtures and the corpus call, provisionally until [#209](https://github.com/cevr/ergo/issues/209) fixes their method sets. `Clock` was a prelude capability whose `Now` returned an `int64` with no unit; it is `time.Clock` with `Now() time.Time` since std-align S2b, because the prelude cannot name a std type ([stdlib.md, time](stdlib.md#time)).
6. An interface is also a generic constraint, with Go's method-set rules.

## Methods

Status: **implemented**: checked (#196, 196m) and lowered: `x.f(…)` calls the function, a Go method on the type where rule 3 allows one (check-v1 stages C to E1; `TestErgoRunE1Witnesses`, `TestErgoRunMethodValues`).

There are no receivers. A package function whose first parameter is a named type declared in the package is a function on that type, and `x.f(y)` calls `f(x, y)` (196m).

1. `x.f(a)` resolves to a field `f` of `x` first. Otherwise it resolves to the package function `f`, in the package that declares `x`'s type, whose first parameter's type is `x`'s type: `T`, `*T` or, for a generic `T`, `T[A, B]` whose arguments are distinct type parameters of `f`, which a call on an instance binds. A first parameter written as one of the function's own bracket parameters is that parameter, never a package type of the same name. The call checks the other arguments against `f`'s signature without its first parameter, and its rows are `f`'s rows, inferred or written.
2. `x.f` without a call is only a field (S104 when `x` has no field `f`): a function on a type has no method value. Written type arguments keep the call: `x.f[int](a)` is the call `x.f(a)` with the bracket parameters of `f` that its first parameter does not bind written in order (`g.pick[string]("x")` for `func pick[T, U](g G[T], u U) U`); `x.f[int]` alone is still S104. When `f` has no such bracket parameter, the brackets are no type arguments: `s.hs[0]()` is the S104 of `s.hs`, which suggests the call `s.hs()[0]`.
3. Several package functions may share a name when their first parameters are distinct named types declared in the package. Such a name is called as `x.f(…)`; a plain call `f(x)` with more than one candidate is S108 "several functions are named f; call it as x.f(…)". Lowering emits them as Go methods on the type, which Go allows. A first parameter that names a type declared twice (S108) counts as such a type when its type arguments are distinct type parameters of the function and the function is not `main`: which declaration the package keeps depends on their order, so the group's verdict never reads it; two functions whose first parameters name it still share it (check-v1 stage D1 rounds 3 and 4).
4. A named type satisfies an operation type when, for each operation, a function on the type exists (a field of the same name does not hide it: `x.Value` reads the field, and `func Value(c Counter) int` still provides `Value() int`) with the same remaining signature, no wider error row and no extra `needs` (S106, rows.md Context 2). A function with type parameters beyond those its first parameter binds can be called as `x.f(…)`, but it cannot satisfy an operation, which takes no type parameters (S106, naming the parameter).
5. A first parameter `*T` needs an addressable `x` (S108), as Go's pointer receiver does ([Borrows](#borrows)).
6. An error type may not declare a function named `Error` on itself (S108), because the emitter generates it. An error type's text comes from its fields (fixture `error-method-on-error-type`). When a production row makes the type an error type, the S108 is at the function. When only a test's row does ([Error types](#error-types) 1), the run build gives the type no `Error` method, so the function is valid there, but the test build would lower it beside the generated one: the S108 is reported once, at the first such row in source order, and the function stays clean, so a test never changes the program's verdict.
7. The prelude's functions on slice and Map types, `Append`, `Get` and `Delete` ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Slices and Maps), resolve by rule 1 from a value whose type is exactly an unnamed `[]E` or `Map[K, V]`, which binds their bracket parameters as a generic first parameter does; they are in no scope, so a package declares its own `Get` freely, and their bare call is S104 naming the dot form (check-v1 D-D6, D-D8). A defined type over a slice reaches `Append` after assignment ([Assignability](#assignability) clause 2): `let raw []int = xs`, then `raw.Append(x)`; a defined Map uses `let raw Map[string, int] = m`, then `raw.Get(k)` or `raw.Delete(k)`. `Info.Calls` records such a call, and every call `x.f(…)` of a generic `f`, with every type argument of `f` in its order, the ones `x` binds included, so the lowering writes `F[A, B](x, …)` (D-D8). *Prior art:* MoonBit declares `fn Array::push` and calls it `xs.push(x)`; Nim and D call any function by its first argument (UFCS); go/types records a method value's full instance in `Info.Instances`.
8. A call `x.f(…)` reaches the one function `x`'s type picks, for the order of row inference and for Go's initialization order, never every function named `f`: an initialization cycle through it names it by its type, `B.m`. *Prior art:* MoonBit resolves `x.f` by `x`'s inferred type in the type's package and allows same-named methods on different types; go/types resolves a selector with LookupFieldOrMethod and orders initialization by the method it resolved.

## Interface assignability

Status: **implemented** (#196; check-v1 stage E1): rules 1 to 3 and 5 are checked, and every conversion they admit lowers, inside a generic function too, and so does one whose implementing function is itself generic over a method-set constraint (`TestErgoRunE1Witnesses`, `TestErgoRunGenericImplementingFunction`).

```go
type Store { Get() string }
type Mem {}

func Get(_ Mem) string { return "ok" }
func NewStore() Store  { return Mem{} } // Mem implements Store
```

1. A type `T` implements an interface type `I`, so a value of `T` is assignable to `I` ([Assignability](#assignability) clause 3), when `T`'s method set has every method of `I`, and for each such method:
   - the parameter types and the result type are identical to `I`'s;
   - the method is fallible exactly when `I`'s method is;
   - its error row is a subset of `I`'s method's error row;
   - its `needs` row is a subset of `I`'s method's `needs` row.

   This is method-row compatibility: an implementation may fail less and require less, never more. It is the same check `context` applies to a provider (S106; [rows.md](rows.md#context)). A value that holds a `Task` is not assignable to an operation type that holds none, which would erase its ownership (S108; [runtime.md](runtime.md#tasks) rule 3); a `Task` keeps its own type.
2. A union type is not an interface in this sense; it is assignable only by the variant rule (clause 4).
3. Resources keep their rules: assigning a resource to an interface without `Close` is an error (R22), and assigning it to one with `Close` moves it (R23) ([resources.md](resources.md#conversions)).
4. *Prior art:* Go satisfies interfaces implicitly by method set with identical signatures; Effect requires a service implementation's error and requirement types to fit the tag's; Java and Swift let an overriding method throw fewer checked errors, never more.
5. **Lowering.** An operation type is a Go interface. A value of another type converts to it through a generated adapter whose methods call the package functions that implement the operations ([Methods](#methods)), each with the caller's task. Inside a generic function the adapter is generic over the function's type parameters, and a value of a type parameter `T` that a method set constrains converts through `T`'s witness ([Generics](#generics) 5). A method set used as a constraint is satisfied by the same rule 1, with one restriction: an operation implemented on `*T` does not satisfy it (Generics 2).

## Error types

Status: **checked** (#196).

1. A type named in any error row is an error type. It must be a named struct type, of this package or of an imported one such as `timeout.Expired`, or a union that names a row (rule 4); anything else is S104. Inside a package, a struct type is an error type when an error row of that package, or of the package that declares the type, names it; a struct type that no such row names is an ordinary value type. A test's error rows make an error type only inside the tests ([grammar.md](grammar.md#declarations) 11; 196l, check-v1 stage E3a): a struct type that only a test's row names is an ordinary value type in every other body, so the test changes neither their verdicts nor the run build, which gives the type no `Error` method and no text helper; the test build reads the test's rows as well. Another package reads only the rows of the program that declares the type, never its tests.
2. An error type is not an ordinary value: returning a value of an error type is a failure ([rows.md](rows.md#error-rows); fixture `error-as-value`, S101), except from a function whose declared result is that error type, or a union whose every member is an error type and that holds it, which returns it as its value ([rows.md](rows.md#error-rows) 4, K1).
3. Error rows are sets of independent struct types, not one declared sum per function. *Prior art:* Gleam returns one declared `Result` error type per function; OCaml polymorphic variants and Koka effect rows are open sets; Ergo's rows are closed sets of nominal types with no open tail in v0.
4. **Named rows** (L2, decision O12). A union whose variants are error types names a row: `type Fail = Bad | Oops` lets a row write `fails Fail`, which means `fails Bad | Oops`, since a row is a set and the union names the set. The union may stand anywhere a row element may: a signature, a function type, a row argument (`run[Fail](f)`), and beside other elements (`fails Fail | Other`); the row is the union of its elements. A union of this package names a row, and naming it in any row makes its variants error types, as a row that listed them would (rule 1). A union of another package, std's included, names a row only when each of its variants is an error type of that package (S104 otherwise, naming the first variant that is not), so the prelude's `Option` is no row, and std's `flag.Failure` names the seven failures of `flag`. A union's variants are records of its own package ([Unions](#unions) 1), so a named row never gathers another package's failures; such a row is spelled. A `catch` arm may test the union and bind it ([rows.md](rows.md#catch) 9). *Prior art:* Effect writes `type E = A | B` and uses it as `Effect<A, E>`; OCaml abbreviates a polymorphic variant row with a type; Koka has effect aliases.

## Operators

Status: **implemented**: checked (#196, 196u) and lowered to Go's operators, so every operator of rules 1 to 4 runs (check-v1 stages C to E1; `TestErgoRunOperators`). Ordering constraints such as `cmp.Ordered` are [#211](https://github.com/cevr/ergo/issues/211)'s, and `duration` arithmetic beyond rule 4 is [#175](https://github.com/cevr/ergo/issues/175)'s.

1. Go's operators on Go's operand types, with exact constant arithmetic (an overflow of the typed result is S108): arithmetic on numeric types, `+` on strings, ordering on numbers and strings, `==` and `!=` on equatable types. Two predicates are kept apart (eq-structural, 2026-11-08, decided by principle: 196d "equality is generated"). *Comparable* is Go's comparability (structs whose fields are comparable included; README Gap 26), and a `comparable` constraint and a Map key read it: a record or tuple compares when its fields do, a union only when every variant does, and a row value (`case err:`) and an operation type's value never do, because Go would compare them as interfaces and panic on a variant that does not compare (stage C round 2 review M1, M2). *Equatable* is what `==` and `!=` read: every comparable type, and also a slice of an equatable element, a Map whose values are equatable, and a record, tuple or union whose fields, elements or variants are equatable. Their equality is structural: two slices are equal when their lengths are and their elements are, in order (an empty slice is one value: Ergo has no nil); two Maps when they hold the same keys with equal values; two records or tuples field by field; two union values when they have the same variant and its values are equal. A function, a row value and an operation type's value are not equatable. So `type Value = Leaf{N int} | Branch{Items []Value}` takes `a == b`, while `Map[Value, int]` and `eq[T comparable](a, b)` at `Value` stay S108. The lowering keeps Go's `==` for a comparable type and emits one equality function per other type, element by element, a recursive type's calling itself (lower `equal.go`; `TestEqualStructuralAgrees`). *Prior art:* Rust and MoonBit derive `Eq` per type (this lowering); Gleam compares by structure (on JavaScript a generated `isEqual` walk), ReScript emits `caml_equal`, Elixir compares terms; Go compares only comparable types and leaves slices to `slices.Equal`; `&&`, `||` and `!` on `bool`, shifts on integers. S108 otherwise. A comparison is `bool`.
2. **One type per operator** (196u rule 4). Both operands of a binary operator have one type, and no operand converts by itself: `a + b` with `a int32` and `b int64` is S108 "mismatched types int32 and int64; write int64(a)". A literal takes the other operand's type (`x + 1` with `x int8` adds two `int8`s). Two literals each take the expected type, else their defaults, so `let d = 1 + 2.5` is S108 "mismatched types int and float64; write 1.0 + 2.5". *Prior art:* Rust's rule; Gleam and OCaml separate float operators.
3. **Shifts and conversions** (spec D-A3). A shift's left literal takes the expected type when that is an integer type, else `int`; any other expected type is S108 "the left operand of a shift is an integer, and float64 is expected here; write int(1) << n, then convert the result". The count is any integer type. A conversion `T(x)` gives its operand `x` no expected type, a literal or any other form except a tuple `(a, b)` and a composite literal without a type, which have no type of their own and take `T` (`T0((A, B))` builds the tuple type `T0` is defined over): `x` is typed on its own, then converted, so `float64(1 << n)` converts an `int` shift (in Go it is invalid, a known trap) and `int64(if n < 0 { -n } else { n })` converts the `int` that the `if` gives, as `let v = …; int64(v)` does (K2; `TestConversionAgreesWithLet`). *Prior art:* Rust's `as` never types its operand from the target; Gleam and MoonBit shift through library functions on one integer type; Zig requires a fixed-width left operand unless the count is comptime-known.
4. `duration` takes `+`, `-`, ordering and `==` between durations; an integer literal is never a `duration` (S108). Its other arithmetic is [#175](https://github.com/cevr/ergo/issues/175)'s.
3. `&&` and `||` short-circuit (README Gap 10). `comparable` is a constraint; ordering constraints such as `cmp.Ordered` are [#211](https://github.com/cevr/ergo/issues/211)'s.

## Conversions

Status: **checked** by `internal/sketch/check` (check-v1 D-B7).

1. `T(x)` converts between numeric types by Go's rules (an integer or float to an integer or float, a complex to a complex, and a numeric constant to any numeric type that represents it), between `duration` and `int64`, and between a defined type and the type it is defined over, in both directions. Every assignment that makes no implicit conversion ([Assignability](#assignability) clauses 1, 2 and 5) is a conversion too, so a value converts to its own type, as go/types `convertibleTo` starts from `assignableTo`.
2. Nothing else converts (S108): not two defined types over one type (one hop is visible: `int(c)` of a `Celsius` over `float64` is S108 "convert through the type it is defined over: int(float64(c))"; a base with no name has none to call, so `Other(x)` of an `Ints` over `[]int` is S108 "go through the type it is defined over: let raw []int = x; then Other(raw)", under a name not bound there; each text checks when written back), not two records, not an integer to `string` (S108 "an integer does not convert to string; write \"\\(n)\" for its decimal text"), not a variant to its union or a value to an operation type (assignment does those: `let u Payment = p`).
3. *Principle:* nominal types, one visible hop. *Prior art:* Gleam and ReScript convert only through functions (`int.to_float`); Elixir uses functions; MoonBit uses `to_int64()` style methods; Go converts between any types with one underlying type, and `string(65)` is a vet warning.

## Function values

Status: rule 1 is **checked** (#196): a function value is assignable to a function type with identical parameters and results and rows that are subsets of the type's, when one of the two types has no name ([Assignability](#assignability) clause 5; S108 otherwise). Rule 2 is **implemented** (check-v1 stage E2, the minimal 196e rule, `check/escaping.go`); its lend of a non-escaping value to a task that the call consumes is **designed, not yet implemented**. Rules 3 to 5 are **designed, not yet implemented** ([#197](https://github.com/cevr/ergo/issues/197)).

1. A function type carries its parameters, result, error row and `needs` row. It carries requirements only, never purity ([rows.md](rows.md#footprints)).
2. A parameter whose type is written as a function type is non-escaping unless the type is written `escaping func(…)`. A function type anywhere else (a field, a result, an element, a type argument, a defined type's base, a local's written type) is escaping, so `escaping` there only repeats the default; a named function type is escaping. A `let` that binds one name from a non-escaping value is non-escaping too. Every use of a non-escaping local is one of: the callee of a call; an argument whose parameter is non-escaping; the value of such a `let`; the target of an assignment, or its value when the target is a non-escaping local declared in the value's frame or one nested in it. Every other use, such as a field value, a return or block result, an element, a conversion, or an argument of an escaping or generic parameter, is S108 at the use. A capture is a use too: every frame between the local's declaration and the use must be non-escaping. A function literal is a non-escaping frame when it is the callee of a call or an argument of a non-escaping parameter; a trailing block is one when its parameter is non-escaping, and a `with` block runs in place. Every other literal or block is an escaping frame, so `task.Go`, whose parameter is `escaping`, refuses a capture: a task that the call consumes cannot yet borrow one ([#197](https://github.com/cevr/ergo/issues/197)). `func(g func())` and `func(g escaping func())` are distinct types, so a function value cannot launder a non-escaping argument through a parameter that keeps it. *Prior art:* Swift non-escaping closures by default with `@escaping`; Kotlin inline lambdas and `crossinline`; Effekt second-class blocks; Gleam, Elixir, ReScript, MoonBit and Go have no marker.
3. A `func` literal that escapes captures by copy and may not assign captured locals. A non-escaping inline block may assign them. A captured resource follows [resources.md](resources.md#closures).
4. **Concurrent parameters.** A function parameter that the callee hands to `go`, directly or through another call, is concurrent. The compiler infers this fact and records it in the exported interface summary. A block or literal passed to a concurrent parameter may not assign captured locals, so `parallel { n++ }` is an error. *Prior art:* Swift `@Sendable` parameters.
5. **Replayable parameters.** A transaction body ([stdlib.md](stdlib.md#sync-and-stm)) may not assign captured locals, use channels or consume a resource, and its footprint holds only `sync.Tx`.

## Borrows

Status: placement (rule 1, first sentence) is **checked** (#196): `*T` outside a parameter or receiver type is S108; rule 5 is checked (check-v1 stage D3b). The rest is **designed, not yet implemented** ([#197](https://github.com/cevr/ergo/issues/197)).

1. `*T` appears only on parameters and receivers. A borrow is never nil, stored, returned, sent or captured by `go`.
2. Two mutable borrows into one value must not overlap. With constant indexes the checker decides; with dynamic indexes it needs a dominating guard or it rejects the call. *Prior art:* Swift's law of exclusivity; Rust `get_many_mut`.
3. There are no pointer fields and no reference fields. Linked structures use recursive values behind unions, index arenas or `sync.Ref`. This is a loss against Go. *Prior art:* Rust keeps both reference fields, at the cost of lifetime parameters on the struct, and owned pointer fields (`Box`, `Rc`); Ergo gives up reference fields so that no signature needs a lifetime, and replaces written owned pointers with compiler-boxed recursion behind unions; Swift value types and Hylo's mutable value semantics make a similar trade.
4. Resources are lent by passing them as arguments ([resources.md](resources.md#lending)). A borrow and a lend obey the same no-escape rule.
5. An operation type is already a reference: its Go form is an interface or a runtime pointer. An operation called through a borrow of an operation type, `p.Close()` with `p *queue.Queue[int]`, is S108 "an operation type is already a reference; call it on the value" at the receiver, for a std operation type and the program's own alike; call it on the value, `q.Close()` (checked, check-v1 stage D3b). *Prior art:* Go calls a method of an interface only on the interface value, never through `*I`; Gleam, Elixir and ReScript have no pointer to a module's abstract type.

## Generics

Status: **implemented** in the decided spelling of [#196](https://github.com/cevr/ergo/issues/196) (196g as amended, sixth round) by `internal/sketch/check` and the lowering (check-v1 stage E1, D-E1). Rules 1, 2, 5 and 6 are checked and lowered; rules 3 and 4 are outside stage E1. A type argument that stands for no value lowers in every position, a declared generic type and any function type included (lower-v1 stage 4, C11): a function value with no result has the one Go shape of a function value whose result is `struct{}`, so `func()` and `func() T` with T no value are one Go type (`TestNoValueTypeArgumentsLower`). An operations conversion whose implementing function is itself generic over a method-set constraint lowers (`TestErgoRunGenericImplementingFunction`), and so does a generic context protocol function (`TestErgoRunGenericContextKey`).

```go
func Transform[A, B, E, R](xs []A, f func(A) B fails E needs R) []B fails E needs R {
	let mut out = []B{}
	for x in xs {
		let y = try f(x)
		out = out.Append(y)
	}
	out
}
```

1. Type parameters are declared in brackets after the name, `[A, B, E, R]`; a bare upper-case letter that resolves to nothing is S104 (unknown type), never a parameter by itself. The kinds stay implicit: a parameter written after `fails` anywhere in its scope ranges over error rows (`E`), after `needs` over capability rows (`R`), else over types (`A`, `B`). **A row parameter may stand in every type position** (owner q47, 2026-11-09): a parameter written after `fails` and in a type position ranges over error rows, and in the type position it names the row's **value type**, the type a `case err:` binding has ([rows.md](rows.md#error-rows) 8). So `type Job[F] { Run func() int fails F, Last F }` declares a field that holds one failure of `Run`'s row, and `func ExitOf[T, F](body func() T fails F) Exit[T, F]`, with `type Exit[T, F] = Done{Value T} | Failed{Error F}`, passes `F`'s value type to `Exit`'s type parameter. A row written as a type argument names the same type, `Exit[int, NotFound | Busy]`, and a row argument of a row parameter is written the same way, `Job[NotFound | Busy]`. The value type follows the rules of a union over its members, as every type of that shape does (rows.md, Error rows 8: assignment, match, equality, generators, literals), and lowers to a Go `error`, with no Go type parameter for a row parameter. Any other two kinds of one parameter (a type and a capability row, or an error row and a capability row) are S108 at the declaration (a function's: "R is used as a capability row and as a type; a parameter has one kind"), since a capability row has no value type. *Prior art:* Zig's error sets are types, `error{NotFound, Busy}`, that a field or a variable holds, and an error set coerces to a wider one, as a row value goes into a wider row; OCaml's polymorphic variants are value types over a row (an open row of tags), and a match on an open one needs a default case, as a row value over a parameter does here; Gleam, ReScript and Rust carry a failure as data in `Result(a, e)` over a type `e`, and Effect's `Exit<A, E>` over a union type `E`; Koka keeps effect rows apart from value types, which is why its effects have no value type. Before q47 this was S108 "F is used as an error row and as a type" (fail-field, batch 13), which made rows the one kind of parameter that could not be a field. `[T any]` is written `[T]`, and `any` is S104 ([Basic types](#basic-types) 8).
2. A constraint follows its parameter inline, `[T ordered]`, and applies to the names before it back to the previous constraint (`[A, B ordered]` constrains both); `any` ends an unconstrained group before a constrained one, `[E any, K comparable]` ([grammar.md](grammar.md#declarations) 3, fu8b). A constraint is an operation type (a method set), or one of the predeclared `comparable`, `ordered` and `number`. There is no `where` clause. `comparable` admits the types with generated equality (D-E2) and gives `==` and `!=`; `ordered` admits the integer and float types, `string`, `duration` and defined types over them, and gives ordering and `+`; `number` admits the integer and float types and defined types over them, and gives the arithmetic operators. Method constraints resolve through the type's owner package, with one answer per type (196m), and an operation implemented on `*T` does not satisfy one: S108 "… has a *T receiver". A constraint may name its own parameter, `[T Lesser[T]]`.
3. Rows in a generic signature may be elided only where they pass through unchanged. A declared requirement is never elided.
4. Exported signatures spell their rows and type parameters, so clients check against interface summaries, Go's export-data model.
5. **Lowering.** Generics emit as Go generics, which Go compiles by GC shape. Specialised copies need a measured win under [#190](https://github.com/cevr/ergo/issues/190). An instantiation cycle, a generic type or function that instantiates itself with a growing argument (`func f[T]() { f[[]T]() }`), is S108, as Go rejects it: its instances never end. A method's receiver parameters count as the type's own, as `go/types` canonicalises them, so `func (r R[T]) M() { R[[]T]{}.M() }` is a cycle too. Signatures count like bodies: a parameter, a result, a bodiless declaration, an interface-typed parameter or a constraint that instantiates with a growing argument (`func (R[T]) M(x R[[]T])`), through a renamed receiver parameter or across two receiver types, is a cycle as well. The checker finds it on the instantiation graph, not by a depth limit, and before rows are inferred, so rows iterate over a finite set. A constraint lowers to a Go constraint that keeps its operations, never to `any`: `comparable` to Go's `comparable`, and `ordered` and `number` to generated type-set interfaces (`~int | … | ~float64`, with `~string` for `ordered`), so `<` and `+` compile in the Go body. A type parameter that a method set constrains lowers to a Go type parameter constrained by `any`, and the function takes one witness per such parameter after the environment: a struct with one function field per operation, in the uniform function shape with the value first. The caller builds it from the instance the checker records (`Info.Instances`: the callee, its type arguments and, per operation, the implementing function and its own instance), so the lowering never resolves an operation again; a Go method cannot carry it, since Go declares methods only on the package's own defined types. An instance used as a value, `Max[int]`, is the Go instance with its type arguments written. *Prior art:* Go GC-shape stenciling, whose dictionaries also carry a type parameter's methods; Swift witness tables and Haskell and Scala dictionaries pass a constraint's operations the same way; MoonBit and Rust monomorphise; Gleam, ReScript and Elixir have no constraints to lower; Ergo's earlier measurements refused frontend monomorphisation ([design.md](../design.md#compile-speed-is-a-language-constraint)).
6. **Inference.** Type arguments are inferred by unification over the value arguments with Go's unifier (`go/types` unify.go), never from a call's expected result. Inference is sound and a documented subset of Go's (D6 as amended in rounds 7 and 8): when Ergo infers, Go infers the same types for the same call after row erasure. The subset is typed value arguments, structural unification, interfaces through method sets, conflicts between arguments, literals (196u rule 6: a literal argument binds a parameter only when no typed argument binds it, and a parameter that only literals bind takes their common default, so `Two(1, 2)` infers `int` and `Two(x, 2)` with `x int8` infers `int8`; mixed defaults, `Two(1, 'a')`, are S108 "cannot infer T; write the type arguments"), and written type arguments. Every typed argument unifies first, in source order, then the literals default, and each literal is then checked with its parameter's type expected. A function literal whose parameter types are written is a typed argument; only its unwritten rows take the parameter type's, so `Apply(func(v int8) int8 { return v }, 1)` and `Rev(1, func(v int8) int8 { return v })` infer `int8`. A function literal with untyped parameters, `func(x) { x * 2 }` (#214, D-E1), binds nothing: it is checked after the typed arguments and the literal defaults, and each untyped parameter takes its type from the expected function type, so `Each(xs, func(x) { x * 2 })` with `xs []int` types `x` as `int`, and its tail's type binds a result parameter left open (`MapOf(xs, func(x) { "s" })` binds `U` to `string`). An untyped parameter never takes a default: with no expected type, or one that no other argument fixes, it is S108 "cannot infer the type of x; write func(x T)", once per literal, with no cascade. A trailing block writes no types and binds what is left after the literals. Outside the subset, the call is S108 "cannot infer T; write the type arguments, e.g. Fn[int](…)", its only diagnostic: a parameter only a method or core-type constraint determines (`Use(x)` for `Use[T comparable, P M[T]]`, where `type M[T] { M(T) }`), and a generic function passed as an argument without all its type arguments (`Apply(Id, 1)`, `Fix(Id)`). The written forms stay valid: `Use[int](x)`, `Apply(Id[int], 1)`; a constraint error stays a constraint error when typed or written arguments fix every type argument. A call whose inference fails or is refused reports one diagnostic, and its result is invalid, so nothing cascades from it. An argument that is invalid, or is itself a failed or refused call, fails the enclosing generic call with no diagnostic of its own (one rule, in the inference loop; round 9), so `Id(Apply(Id, 1))` reports one refusal; independent errors in other arguments still report. Each typed argument is assigned to its parameter: the match may be inexact at the top (an interface on either side matches a type that has its methods, by unifying the method signatures, so a wider interface, a named generic interface, a concrete type or a pointer infers through its method set), and element types match exactly. A parameter bound by an earlier argument must match every later one: a conflict is S108 at the argument (`Two(x, y)` with `x` an interface and `y` a struct; of an interface and a non-interface neither is chosen, so the order of the arguments never decides), while `Two[I](x, y)` for an operation type `I { M() }`, with every type argument written, infers nothing and only assigns. Ergo departs from Go where its types do: a named type unifies with a type literal only when it is an interface (types are nominal), and a named union unifies with the variant its argument names. A generic function inside parentheses is a value, as in Go: `(Fn[int])` is the instance, and `(Fn)[int]` or `(Fn)(1)` is S108. In `Info`, an explicit instantiation `Fn[int]` and the parentheses around it carry the instance type while the name `Fn` keeps its generic type; in an inferred call `Fn(1)` the name carries the instance, as in `go/types`. Every literal carries its one type in `Info`, recorded when it is checked ([Basic types](#basic-types) 6; 196u rule 7): no expression's type is updated afterwards. A row parameter binds to the row of a function-typed argument, less the row's written part; `fails E | Expired` is the union. When several arguments bind one row parameter, it binds to the union of their rows: rows are finite sets, and a function with a narrower row is assignable where a wider one is expected, so the union is the least binding that admits every argument. A written type argument is not widened. A composite literal of a generic type, or a generic variant in a `case`, written without type arguments takes them from the expected type, else from its field values (`Some{n}`, `Enter{x}`). A type parameter left unbound is S108; a row parameter left unbound is empty. A result-position type parameter bound by a block with no value stands for no value, lowered to `struct{}`. *Prior art:* Go `types2/infer.go`; Koka infers effect rows; OCaml and ReScript disambiguate constructors by the expected type; Gleam's `Nil` and Rust's `()` for no value.
7. **Left-out rows.** A generic type's trailing row parameters may be left out of its written type arguments, and each one left out is the empty row, as a row parameter that inference leaves unbound is (6): with `type Command[C, E] { Build func(v Values) C fails E }`, `Command[Cmd]` is the command whose `Build` fails nothing, the same type that `Command{Build: f}` infers for an `f` with no failure. A type parameter is never left out, nor a row parameter that a written argument follows: `Pair[int]` for `Pair[A, B]`, and `Mid[int, string]` for `Mid[A, E, B]`, are S108 "… takes 3 type arguments, not 2", as is an extra argument. At least one argument is written: a bare generic name is S108 "generic type … needs type arguments", since a bare name in a composite literal already means "infer the arguments" ([Structs](#structs)). Rows are erased (rows.md), so the rule changes no emitted Go. *Prior art:* Effect declares `Effect<A, E = never, R = never>` with TypeScript type-parameter defaults, which gives the same reading through a library default; Koka writes a total function's empty effect row as `<>` or leaves it out; Go and Gleam have no defaults for type parameters.
8. **Written rows.** The argument of a row parameter is a row, written as a row is written after `needs` and `fails`: `A | B`, bare, of one or more elements (lane MB F8; one rule for every row position, q39). It is the same in a type, `Option[machines.Work[Signal, Payments | Scheduler]]`, and in an expression's index, `run[A | B](j)`. A row of error types where a type parameter's argument is expected names its row value type (rule 1, q47: `Exit[int, NotFound | Busy]`); a row of capabilities there is S104 "A is not an error type", since a capability row has no value type; a parenthesised row is S001 "a row takes no parentheses", as `needs (A | B)` is. Each element is checked as the one-element row is: it is a capability when the parameter ranges over capabilities, and an error type when it ranges over errors (`TestRowArgFixtures`). *Prior art:* Koka writes an effect row argument as `<a, b>` in a type application; Effect writes `Effect<A, E1 | E2, R1 | R2>` with TypeScript unions, the spelling this rule takes; Scala 3 capture sets `{a, b}`; Go, Gleam, ReScript and Elixir have no rows.

## Loops and len

Status: **checked** by `internal/sketch/check` and **lowered** by `internal/sketch/lower`, with `ergo run` tests (check-v1 stage D2: D-D4, D-D5).

1. **Domains** (D-D4). `for x in e` binds the element and `for i, x in e` the position and the element, over five domains: a slice `[]T` (position `int`); a `Map[K, V]` (one name binds the value, two the key and the value; order unspecified); a string or a type defined over one (one name binds each `rune`, two the `int` byte offset where the rune starts and the rune; L4); the prelude's `Range[T]` (one name, counting from `Start` up to `End`, `End` excluded); and the prelude's `Seq[T]` (one name). A string is decoded as UTF-8 exactly as Go's range decodes it: each byte that does not begin a valid encoding (a stray continuation byte, a truncated or overlong sequence, an encoded surrogate) is one rune U+FFFD of width one, so the next offset is one byte on; a string's bytes are `for i in 0..len(s)` and `s[i]`. A second name over a `Range` or a `Seq` is S108 "a for over Range[int] binds one name, the element: for x in …". Any other domain is S108 with a message that names the Ergo form: an integer ("count with for i in 0..n"), a pointer ("write for x in *p"), anything else ("a for takes a slice, a Map, a string, a Range or a Seq"). A `Range` over a non-integer `T` is S108. A refused domain or name still binds its names, with no type, so nothing cascades: it adds no S110, and `for Some in xs` is one diagnostic. A `for` over a `Map` that the body changes follows Go: it visits each entry present at the start at most once, in unspecified order; an entry inserted during the loop may or may not be visited; an entry deleted before it is reached is not visited. There is no snapshot, which would allocate on every loop. *Prior art:* Go's range over a map has these rules; Rust's borrow checker refuses a change during the loop; Gleam's and Elixir's maps are immutable values, so a loop sees the map it started with.
2. **`a..b`** has the type `Range[T]` for one integer type `T`, the operands' (D-A1 types the literals), and works outside a `for`: `let r = 0..n`, `r.End - r.Start`. Other operand types are S108. *Prior art:* Rust's `0..n` is a `Range` value; MoonBit's `0..<n`.
3. **Bindings** are immutable and read: an unread one is S110, `_` ignores it. A single name follows the one binder rule (check-v1 D-D2 and D-D3; [rows.md](rows.md#totality), Totality 6): a known constant or capability name is a pattern, and a package type's name binds a local ([Scope](#scope) 1), so `for line in lines` binds `line` beside `type line`; a binding may be any irrefutable pattern. `for cond { }` needs a `bool`.
4. **`Seq[T]`** is `type Seq[T] func(yield func(v T) bool)`, a protocol any function implements by conversion, `Seq[int](f)`. `for v in s` runs the body as `yield`; a `break` or `return` makes `yield` return false. *Law:* a Seq never calls `yield` again after it returns false. `queue.Values()` returns one ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice)). *Prior art:* Go's `iter.Seq[T]` and range over func; Rust's `IntoIterator`.
5. **Map entries.** A write `m[k] = v` inserts or replaces the entry, and needs `m` rooted at a `let mut`; the write is seen through that root alone ([Bindings](#bindings) 1). A read `m[k]` is S108 "a Map read may miss; write m.Get(k), which returns an Option", whatever `V` is: there is no default value for a missing key, and `m[k] op= v` reads. The default of a `Map` is an empty, writable `Map`, wherever a default is made: a `let` with a `Map` type and no value, a field a record literal omits, and a `Map` inside a defaulted record or tuple, named or not, a generic instance included, at any depth. The lowering writes `map[K]V{}`, never Go's nil map. A defined type or instance whose default holds a `Map` has one generated Go function that builds its default, which a nested default calls, so the lowering's work and output grow linearly in the types; every default builds its own `Map`s, so two defaults never share one. *Prior art:* Rust's `#[derive(Default)]` emits one `default()` per type that calls each field's; Rust's `map[k]` panics on a missing key; Gleam's `dict.get` returns a `Result`; Go returns the zero value, the habit this rule removes, and its nil map panics on a write; Rust's `HashMap::new()`, Gleam's `dict.new()` and Elixir's `%{}` are empty and usable.
6. **`len` is the only built-in function** (D-D5). It takes a slice, a `Map` or a `string` (its bytes); a pointer is S108 "len takes a slice, a Map or a string", so write `len(*p)`. Every other Go built-in is S104 with the Ergo form ([diagnostics.md](diagnostics.md#s104-unknown-name)). An index does not see through a pointer either: `(*p)[i]`.
7. **Lowering.** A slice, a `Map` and a string are Go's `range` (a string's is Go's rune decoding, with no conversion or allocation); a `Range` is a counting loop over its value, evaluated once; a `Seq` keeps the one Go shape of every Ergo function value and is adapted at the loop to Go's range over func, so a `break` is Go's. Each binding is a Go variable of one iteration, so a function literal captures that iteration's value.

## Scope

Status: **checked** and **lowered** (L5, decision O16; L6, owner q30; `TestLocalShadowsPackageType`, `TestErgoRunLocalShadowProperty`, `TestPackageTypeHidesPreludeType`, `TestErgoRunPackageTypeHidesPreludeType`).

Scopes nest as in Go: the universe and the prelude, outside the package scope, outside each body's blocks.

1. **A local may take a package type's name** (L5), as in Go's block scope. A `let`, a `for` binding, a parameter, a function literal's parameter, a binding of a `let` or `for` pattern and a catch arm's `as` name may be named like a type the package declares: `let point = point{x: 1}`, `for line in lines`, `func f(rec rec) int`. For the rest of the binder's scope, function literals inside it included, the name is the local in value positions (`point.x`, `let q = point`, `point == p`, a call `point(…)`) and in pattern positions (`case point:` is then a binder, which D-D2 refuses). In a type position (a written type such as `let w point = …`, a composite literal's type, a record pattern's type), the name is the type, so `let point point = point{x: 1}` checks; a conversion `point(…)` is a call, so it calls the local. Outside the binder's scope the name is the type again. The rule covers a package's own types; a prelude name stays a name no local may take (D-D3; [grammar.md](grammar.md#reserved-names) 2), and `error`, a universe type that is no prelude name, keeps the type test. A package-level `let` lives in the package scope beside the type, so its name is a duplicate declaration (S108), and a type name in its pattern stays a type test. A match or catch arm's pattern keeps [Totality](rows.md#totality) 1: a name there that names a type is that type's test, unless a local of the name is in scope. The lowering gives every local its own Go name, never a package entity's (lower naming.go), so `point := point{x: 1}` never reaches Go. *Prior art:* Go block scope, `point := point{}` (Go then loses the type in the scope, which Ergo keeps for type positions); Rust, OCaml, ReScript and Gleam keep types and values in separate namespaces, so the clash never arises; Elixir has no static types to clash with.
2. **A package type may take a prelude type's name** (L6, owner q30, 2026-11-08). A package-level `type` declaration may be named like a type of the prelude or the universe: `type Option[T] = Present[T]{ V T } | Absent{}`, `type Map[K, V] { … }`, `type Range { … }`, `type int { n int64 }`. The prelude scope is outside the package scope, so inside the package the name is the package's type wherever a type name stands, `Map[K, V]` included ([grammar.md](grammar.md#parser) 8). The prelude's own declarations, std's and every other package's keep the prelude's type: `slices.Max(xs)` returns the prelude `Option`, matched with `Some` and `None`, and `0..n` builds the prelude `Range`. Only a type declaration may: a package function, `let`, context, import alias or type parameter named like a prelude name, a local of such a name (rule 1), and any declaration of a prelude function or constant name (`len`, `true`), a type's included, stay D-D3's S108. The prelude's variants `Some` and `None` are prelude types, so `type Opt = Some{ V int } | None{}` declares the package's own `Some` and `None` ([grammar.md](grammar.md#reserved-names) 2). The lowering emits the package's type under its own Go name in the package and reaches the prelude's types through their own package, so the two never meet in Go. *Prior art:* Go's universe scope encloses each package scope, so `type error struct{}` or `type int struct{}` is legal and hides the predeclared type in that package; Gleam, ReScript and Elm let a module define its own `Option` or `Result`, which hides the auto-imported one inside the module; Elixir's `Kernel` imports are overridden by a local `def` of the same name (with `import Kernel, except:`); Rust's prelude is a glob import that any local item shadows.

## Unreachable

Status: **implemented**: checked and lowered (owner q29, 2026-11-08; synthesis M22). `Unreachable(reason string)` is a prelude function. It states that a path cannot run, such as the `None` arm of a lookup whose key is always present. Before it, such a path had to invent a value or declare a failure that cannot happen.

1. **Bottom type.** The call has the bottom type: it checks in every position that expects a value, and it has the type that position expects. These positions expect a value: a `let` with a written type, an argument, a `return`, a record field, an operand, and a branch of a value `if`, `match` or `catch` after an earlier branch fixed the type. As a statement it has no value, like any call whose value is dropped.
2. **Leaves the branch.** As the last statement of a body or a branch, it yields no value and joins any type, as `return` does ([Totality](rows.md#totality) 3). So `let x = if c { 1 } else { Unreachable("why") }` has type `int`, and `func f() T { Unreachable("why") }` needs no value after it.
3. **Needs a type.** In a position that expects no type, `let x = Unreachable("why")`, the call has no type to take. This is S108, which asks for the type: `let x T = Unreachable("why")`. The bottom type has no name in source.
4. **A defect, never a failure.** When it runs, it raises a defect that holds the reason and the call's position ([runtime.md](runtime.md#exit-causes) 3). Its row is empty, so it adds nothing to a function's error row, and a `catch` on it is S108, as on any expression that cannot fail ([rows.md](rows.md#catch) 1). Every `catch` passes it on, `case _` included (Catch 6). `ergo run` reports `panic: unreachable at main.ergo:12:3: why` and exits 2. A call in a std package's body names the std file by its path in the std tree, `unreachable at std/maps/maps.ergo:12:3: why`, as a std match's no-case defect does (fs5, batch 12: before, such a call was an internal compiler error; `TestStdGapPrelude`).
5. **The name.** `Unreachable` is a prelude name (D-D3): a declaration or a local of that name is S108, with the message "(the prelude function Unreachable)".
6. **Lowering.** As a statement or a last statement, the call is `panic(ergo.UnreachableAt(reason, "file:line:col"))`, the Go statement a hand-written program writes, and a terminating statement for Go. In a value position, it is `ergo.Never[T](reason, "file:line:col")`, which panics the same way. The call adds no frame, and its Go body `v1.Unreachable` is not called. Tests: `TestUnreachableChecksInEachPosition`, `TestUnreachableRefusals`, `TestErgoRunUnreachable` and `TestUnreachableLowersToPanic`.

*Prior art:* Rust's `unreachable!()` and `panic!()` have type `!`, which coerces to any type. Go's `panic` is a statement that ends a path, and has no value. Gleam's `panic` and `todo` are expressions of any type. ReScript's `assert(false)` and Elixir's `raise` are expressions that leave. Effect's `Effect.die` and `Effect.dieMessage` put a defect in the cause, never in the error channel. Kotlin's `Nothing` and Scala's `Nothing` are named bottom types; Ergo does not name its bottom type in source (rule 3).

## Laws

Status: **implemented: checked and run by `ergo test`** for top-level laws, for member laws of a non-generic operation type ([#162](https://github.com/cevr/ergo/issues/162) law-run-1, rule 10) and for laws in a machine (MU6, rule 13). The checker checks every law (check-v1 stage E3b, 196l; [#125](https://github.com/cevr/ergo/issues/125), [#170](https://github.com/cevr/ergo/issues/170)). A member law of a generic operation type, and a law of an imported operation type against this package's providers, are checked and not run yet.

```go
type Codec[T comparable] {
	Encode(v T) string,
	Decode(s string) T fails Malformed,

	law RoundTrip(v T) { try Decode(Encode(v)) == v },
}

type Store {
	Find(id string) Order fails NotFound,
	Put(id string, o Order),

	law FindAfterPut(id string, o Order) { Put(id, o); try Find(id) == o },
	law Taxed(o Order) { with context { Rates: Flat } { taxed(o) == o.Total+7 } },
}

// A law about plain functions stands at top level, beside test.
law AddCommutes(a Money, b Money) { add(a, b) == add(b, a) }
```

1. **Placement sets the quantifier.** A law is `law X(params) { … }`. It stands in one of three places (196l; law-top, 2026-11-04):
   - at top level, beside `test`: it is quantified over its parameters only. A top-level law has no type parameters (S001, [grammar](grammar.md#declarations) rule 11); a generic law belongs once on the library protocol, as a member of its operation type;
   - as a member of an operation type, beside its operations: it is quantified over its parameters and every provider of its type;
   - in a machine, after its entries ([#57](https://github.com/cevr/ergo/issues/57), MU6): it is quantified over its parameters, or, as a reachability law, over the machine's runs (rule 13).

   A type with laws and no operations is S108 once, at its name: "T has laws and no operations; write it as a top-level law: law X(…) { … }". Its laws are still checked, with no operation scope, so their own errors show and nothing cascades from the S108. A law beside fields or in a union variant is S108 from the parser ([grammar](grammar.md#declarations) rule 5).
2. **No value.** A law is entered into no value scope, so `RoundTrip(1)` in any body is S104 "unknown name RoundTrip", and `Codec.RoundTrip` is S104 as an unknown member. A member law's name is in its type's own namespace: a second law of one name in one type is S108 "law X is declared twice", at the second, and a law named like an operation of its type is S108 "law X is named like an operation of T". A top-level law's name is in the namespace of the package's tests: a second top-level law of a name is S108 "law X is declared twice", and a top-level law and a test of one name are S108 at the second in source order ("law X is named like test X", or "test X is named like law X"). A top-level law may share its name with a function, a type or a member law.
3. **Scope.** A top-level law's body sees its parameters, then the package. A member law's body sees its parameters, then the operations of its type, then the package. An operation therefore wins over a package function of its name: in `law Stable(v int) { Encode(v) == Encode(v) }`, `Encode` is the operation even beside `func Encode(_ Plain, v int) string`. A law of a generic type is generic in the type's bracket parameters, as a generic function body is in its own: its parameters and its locals, `let w T = v`, may name `T`. Rules 5 and 6 apply to member laws: a top-level law has no operation scope, so they have nothing to apply to. Every other rule is the same for both placements, and the checker takes one path for both.
4. **Parameters** are typed as a function's are. A lone name is a type, so `law L(v)` is S104 "unknown type v", as `func f(v)` and `test T(v)` are. A parameter written as a function type without `escaping` is non-escaping. A parameter named twice is S108 "v is already a parameter of law L". A law parameter need not be generatable: that is a property test's rule, and #162 decides how laws are run.
5. **Operation names are not rebound.** The operation scope encloses the law's body, so the no-shadowing rule (D-D2) applies to it: a parameter, `let`, pattern, `as`, loop, catch-arm or function-literal binder named like an operation of the type is S108 at the binder. An operation also hides a package context of its name, so `with Encode { … }` in a law of a type with an operation `Encode` is S108 ([runtime](runtime.md#g1-context-through-with), G1 rule 2).
6. **Operations are call-only.** A call of an operation is checked against the operation's signature. It charges nothing, and its failure row joins the law's. Any other use, as a value, an argument or a selector base, is S108 "an operation of T is called inside a law; it is not a value".
7. **Rows.** A law's failure row is inferred and unbounded: a failure that escapes the body refutes the law when it runs. A top-level law needs no service. A member law of a non-generic operation type `T` has `T` in its service row, and nothing else: a run binds `T` to the provider under test (rule 10), so a helper `func twice() int needs Store` runs inside a law of `Store`, and so does `Store.Count()`. Any other call that charges a capability, a package function whose row needs one or a capability operation such as `Rates.Get()`, is S102 unless a `with` in the law discharges it, as `Taxed` above does. A member law of a generic type has no capability in its row: a capability takes no type arguments.
8. **The tail.** The body ends in a `bool`. `return e` leaves early and means the same as a tail `e` ([rows](rows.md#totality) rule 3), so one rule admits every success value of the law, a tail, a whole-body `return` or an early `return`: its type's underlying type is `bool`. A law declares no result type to convert to, so `v` of `type Flag bool` is a result as `bool(v)` is. A tail or a returned value whose type's underlying type is not `bool` is S108 "a law's body ends in a bool, not string", once, at that value. A body that can end with no value is S108 "a law's body ends in a bool, not nothing", at the end of that path. A function literal inside the law keeps its own declared result: `func(x Flag) bool { return x }` is S108 there, as anywhere. A `return` of a fallible value or of an error value passes the failure out of the law ([rows](rows.md#error-rows) rule 4). A fallible tail must be tried (S105), so a law writes `try Find(id) == o`. An invalid tail adds no diagnostic.
9. **A frame of its own.** A law body is checked as if it ran in a frame, as a test body is: `task.Go`, an owning `with` and a `Task` in a law follow the frame rules of a function body. `assert` stands in a law body ([grammar](grammar.md#declarations) rule 11), but not in a function literal inside one (S108). An unused local is S110.
10. **Run by `ergo test`** ([#162](https://github.com/cevr/ergo/issues/162) law-run-1). After the tests, the test build runs each law of the package in source order:
    - a top-level law once, over values of its parameters;
    - a law quantifies over each operation type it names: its owner, for a member law of a non-generic operation type, and each parameter whose type is a non-generic operation type. It runs once per binding of those slots to providers, each a named type that implements the slot's type ([Interface assignability](#interface-assignability) rule 1), wherever the provider is declared (law-xpkg, G-exup-1, G-exup-3). The test build of package P runs a binding when P sees the law and every bound provider (P declares it or imports its package, at any depth, the prelude and std included) and no other package that P sees sees them all: the least package that sees the binding runs it, once in the module. So the laws a domain package declares on its operation type run in the `memory` package that declares its provider, and the std `fs.Files` laws run against a program's disk. A law with no slots runs in its own package. Each case builds each provider, converts it to its slot's type, binds it to that capability for the case (rule 7), and takes the other parameters. A provider is built as its package builds it: by its constructor, the package function `New<P>` whose one result is `P`, with no type parameters, no error or capability row and generatable parameters, when its package declares one (each case calls it with generated arguments, so each case starts from a fresh provider, and a record whose invariant only its functions keep is never generated around them; fs4, integration finding F3); else by a generator, with the construction authority of its own package. A parameter value is generated with the authority of the law's package. A law with no binding in its own package prints `law T.L runs where T has a provider: none is in this package or its imports`, which is not a skip: its own package's test names where it runs.

    **One rule decides each run** (MU6b; owner q39, one rule across the language). The values of a run are its parameters, and for a member law the provider first. When the type of each value can be listed, the run takes every combination of values once, and a run that holds is reported **proved**. A type can be listed when it is a `bool`, a record whose fields can all be listed, a union whose variants can all be listed, a type defined over one, or a tuple of them, and it has at most 256 values; a run can be listed when its cases, the product of its values' counts, number at most 4096. A run with no values has one case. Any other run, with a value of an unbounded type (`int`, `string`, a slice, a record with such a field) or past a cap, takes 100 cases generated with the generators of property tests ([runtime.md](runtime.md#tests) rule 3) and the run's seed, and is reported tested, never proved (NORTH_STAR pillar 4). The rule is the same for top-level laws, member laws and the laws with a body in a machine (rule 13), and for property tests, a test with parameters being a run over its parameters ([runtime.md](runtime.md#tests) rule 2; mu6c): `ok Name (proved: all N cases)`, `FAIL Name (case K of N, every value: …)`, or `ok Name (100 cases)`. A test with no parameters is an example and runs once.
    - A proved run prints `ok law Flags.Merge (proved: all 8 cases)`, or `(proved: 1 case)` for a run of one case. A listed case that refutes the law prints `FAIL law Store.Clears for Toggle (case 3 of 8, every value: provider = Toggle{on: true}, b = false): …`; the run stops at its first refuted case, so the case is the first in the order of the values (the provider, then the parameters in order, the last one fastest).
    - A tested run prints `ok law Store.PutCountsOne for Tally (100 cases)`.

    A case refutes the law when its body ends in `false`, a failure escapes it, or an `assert` in it fails. The report names the law, the provider, the case, the seed, the size, the provider value and each argument as Ergo literals: `FAIL law Store.PutCountsOne for Stuck (case 1 of 100, seed 7, size 0: provider = Stuck{at: 3}, n = -9): law refuted at main.ergo:4:2: the law is false`. A run that holds prints `ok law Store.PutCountsOne for Tally (100 cases)`, and each run counts as one test in the summary. A law that cannot run prints `skip law T.L: …` with the reason and is not counted: a parameter with no generator or a generic operation type; so does a provider whose values have no generator and that has no constructor (`skip law T.L for P: …; a func NewP() P with no rows would build one for each case`). The summary counts every skip (`PASS (2 tests, 1 skipped)`), and the examples gate fails a program whose `ergo test` prints a skip line that its `expected-skips` file does not list, so a skip is never silent (fs4). A refuted law fails `ergo test` (exit 1). A law that passes generated cases is reported as tested, never as proved (NORTH_STAR pillar 4); only a run over every value is proved. `lower/law_run_test.go` holds the generated runs: a generated property over operation types with one to three providers, one of them broken at random, shows that exactly the broken one fails, and `TestLawRunOtherPackage` that a false law fails, with its seed, in the package of a provider that another package's operation type declares the law of. `lower/machine_law_test.go` (`TestMachineLawTables`) holds the rule: generated top-level and member laws over generated types, the caps' edges among them (255, 256 and 257 values; 4096 and 4097 cases), are proved exactly when a reference count lists their run, refuted at their first listed case when false there, and tested otherwise. *Prior art:* QuickCheck and Hypothesis run a property over generated arguments and print the seed; Haskell's `quickcheck-classes` and Rust's `proptest` laws check a class's laws against each instance as separate tests, as a member law runs per provider here. SmallCheck checks a property over every value up to a depth, and Lean's `decide` proves a proposition over a finite type by evaluating every case; Ergo takes every value when the type is small and finite, by a fixed cap, and falls back to QuickCheck's generated cases otherwise, so the report says which one ran. Elixir's StreamData, Gleam's `qcheck` and ReScript's fast-check bindings only generate; none reports a proof.
11. **Lowering.** The `ergo run` build includes no law, top-level or member: the lowering emits no Go for a law body there. A law also adds nothing else to it: the checker records the facts of a law body under the law owner (`OwnerLaw`), and the run build does not read them. So an import, a package, a tuple type, a generic instance, a `with`, an adapter, a default or an error type that only a law uses is not in the Go of the run build. The properties in `lower/stage_e3b_test.go` and `lower/stage_lawtop_test.go` hold this, with no exception: the run build of a program is, byte for byte, the run build of the program with its laws removed. The test build reads the law facts (its view, `ViewTestBuild`, sees the tests' and the laws' owners) and lowers each law that runs to a Go function `func ergoLawX(env *Env, params…) (bool, error)`; a bare operation call in a member law calls the capability field of `env`, which the case sets to the provider. *Prior art:* Zig compiles `test` blocks only under `zig test`; Go keeps `_test.go` files out of the package build; Rust compiles `#[cfg(test)]` items only in the test configuration; Elixir compiles `test/`, where StreamData properties live, only under `mix test`. Gleam, ReScript and MoonBit have no laws to erase.
12. Laws are declared where their quantifier is, not found by name; the `LawX` naming rule is gone. The same form serves every client: codecs, providers, schedules and machines, and plain functions at top level. *Prior art (placement):* Haskell has both places: QuickCheck properties are top-level `prop_x` functions, and class laws stand beside the class as documentation. Lean, Coq/Rocq, Idris and Dafny state a `theorem` or `lemma` at top level, and a class or structure carries its protocol's laws as fields. Elixir `StreamData` states `property "…" do check all … end` at the top of a test module, beside `test`. MoonBit puts properties in top-level `test` blocks with a quickcheck library; Gleam and ReScript have no laws. Ergo has the same two placements: a member law for a protocol, checked against its providers, and a top-level law for functions. It checks both as code and keeps them out of the binary as Zig keeps `test` blocks out of non-test builds.
13. **Machine laws** (MU6; decision 2026-11-03 (b)). A machine's laws follow its entries:

    ```go
    type Lights machine[Light, Tick] {
    	initial: Red,
    	step:    step,

    	law Cycles reaches Yellow,
    	law Safe never reaches Broken,
    	law Starts path [Red, Green, Yellow],
    	law NoDone(s Light, t Tick) { !ends(step(s, t)) },
    }
    ```

    - **Names.** A machine law's name is in its machine's namespace: a second law of a name in one machine is S108 "law X is declared twice". Its report names `Machine.Law`.
    - **A law with a body** is checked as a top-level law is (rules 2 to 9): its scope is its parameters, then the package. A law over one transition takes a state and a signal (`law L(s S, e E)`); a law over a signal sequence takes `signals []E` and runs the machine with `machines.Run` or `machines.Next`. It runs by the one rule of rule 10: when every parameter's type can be listed, the law runs once for every value and a run that holds is reported proved, `ok law Lights.NoDone (proved: all 12 cases)`; a refuted case prints `(case K of N, every value: s = …, t = …)`. Any other law runs over 100 generated cases and is reported tested, `(100 cases)`, never proved: a law that reads a payload of an unbounded type is tested.
    - **A reachability law** names variants of the machine's state: `reaches V` holds when some run reaches a state of `V`; `never reaches V` holds when no run does, the start included; `path [V1, …, Vn]` holds when some run's first n states are of `V1` to `Vn` in order. A target that is not a variant of the state is S108 "V is not a variant of S, the state of machine M". A run starts at `initial`, or for a machine with an input, at the start of any input. Each signal is an edge: `Enter`, `Stay` and `Emit` go to their `Next`; `Ignore`, `Reject` and a step failure keep the state; `Done` ends the run and is no edge. A timer's signal is a signal of `E`, so the runs cover the timers.
    - **Decided on the graph** (X1). When the starts and the signals can be listed and the state has a key, `ergo test` decides the law by a breadth-first search (runtime/explore) with a visited set of 128-bit hashes of each state's key. The key is a canonical encoding of the value: a record's fields in declaration order, a union's variant and its fields, a slice's length and elements, a Map's entries in a fixed order, a float's bits with one zero and one NaN; so two states have one key exactly when `==` holds ([Operators](#operators) 1), NaN aside. A state that holds a function, an operation type's value, a Go type or a runtime handle has no key. The search stops at a budget of states, `ergo test --states N`, 1,000,000 by default; it counts states, edges and run lengths, and never reads a clock. A law is **proved** only when the whole graph was seen: `ok law Lights.Safe (proved: 3 states, 4 edges, longest shortest run 2)`, or with a witness, `ok law Lights.Cycles (proved by the run from Red with []Tick{Go, Stop})`. A counterexample or a witness is a shortest run: `FAIL law Lights.Safe (3 states, 1 signals): law refuted at main.ergo:9:2: the run from Red with []Tick{Kick} reaches Broken`, then, indented, an Ergo `test` that runs the same signals with `machines.From` and fails by itself (it names the import it needs when the file has none), and the command that replays the search, `replay: ergo test main.ergo --states 3`. When the budget stops the search first, the law also runs over 100 generated runs (below) and passes with what was checked: `ok law Design.Safe (no counterexample in runs of at most 11 signals; 1000000 states; 100 runs; not proved)`; a scope that must be proved stays small enough to finish. When the starts or the signals cannot be listed, or the state has no key, the law runs over 100 generated runs from the run's seed, each with up to the case's size of signals (a keyless state says so: `(100 runs; the state has no key: …)`): `never reaches` is tested, `FAIL law Meter.NeverHigh (run 16 of 100, seed 7, size 4): … the run from Low{N: 0} with []Push{…} reaches High`; `reaches` and `path` hold at the first run that is a witness, which proves them, and fail when no generated run is one. When the state has a key and the signals are listed, a generated run picks at each step among the signals that change the state, so it does not spend its steps on `Ignore` and `Reject`. *Prior art:* TLC keeps 64-bit fingerprints of the states it has seen and reports the diameter; Quint's `run` samples random traces and keeps no state, so a deep counterexample (the children model's `epochWraps`, 13 signals) passes 250,000 traces that a search of 24,852 states finds.
    - **Skipped**, with the reason: a reachability law of a machine whose step needs a capability, whose state, signal or input has no generator, or whose start has a row.

    *Prior art:* effect-machine's `assertPath`, `assertReaches` and `assertNeverReaches` check hand-picked event lists in a test; here they are declared laws over every run. TLA+'s TLC and Quint check an invariant by breadth-first search of the reachable states and print the shortest counterexample trace; SmallCheck checks a property over every small value, as a machine law over listable types is checked over every value. XState's `@xstate/graph` enumerates the shortest paths of a finite machine for model-based tests. Gleam, ReScript and Elixir have no machine laws: OTP's `gen_statem` is tested by hand or with PropEr's `proper_statem`, whose generated command sequences are this rule's generated runs.

# Types

Definitions of every term used here are in the [glossary](../../GLOSSARY.md). Each section carries its status.

Types are nominal. Two named types are identical only when they are the same declaration. Which value goes where is one relation, [Assignability](#assignability). *Prior art:* Go's named types and implicit interface satisfaction; Gleam and ReScript custom types are nominal too.

## Assignability

Status: **checked** by `internal/sketch/check` as one relation, `assignability`, and **lowered** from the fact it records (check-v1 stage D3a).

```go
type Ints []int
type Store { Get() int }
type Count int
func Get(c Count) int { int(c) }

let raw []int = named      // clause 2: named is an Ints
let s Store = Count(3)     // clause 3: Count implements Store
let o Option[int] = None   // clause 4
```

1. **The clauses, in Go's order.** A value of type `V` is assignable to type `T` by the first clause that holds, and each clause names the implicit conversion the assignment makes, the fact `Info.Implicit` records at the value:
   1. `V` and `T` are identical. No conversion.
   2. `V` and `T` have identical underlying types, at least one of them has no name, and neither is a type parameter. A declared type, a basic type and a type parameter have a name; a slice, Map, function or tuple type written in place has none. No conversion: `let raw []int = named` and `let named Ints = raw` cross, `Ints` to another `type Other []int` does not.
   3. `T` is an operation type and `V` implements it ([Interface assignability](#interface-assignability)), whatever `V`'s name. `ConvOperations` with the function that provides each operation, or no conversion when `V` is itself an operation type's value. Check implementation first, so a missing operation is the diagnostic when both checks fail. Then refuse a `V` that holds a resource when `T` crosses ([resources.md](resources.md) R22; a `Task` is one, [Task ownership](#task-ownership)).
   4. `V` is a variant of the union `T` ([Unions](#unions) 2), or a row value whose every error type is a variant of `T`, or a declared union each of whose variants is a variant of `T`. `ConvVariant`, `ConvRow` or `ConvWiden`.
   5. `V` and `T` are function types with the same parameters and results, `V`'s error and `needs` rows are subsets of `T`'s, and at least one of them has no name ([Function values](#function-values) 1). No conversion: a function value has one Go shape. A slot row keeps its Go type (ROW-PARAM), so with `type Classed[E] { Of func(e E) Fate }` and `func serve[E](c Classed[E], h func() int fails E)`, `Classed[Boom]`'s `Of` takes a `Boom`: `func(e Boom) Fate { … }` checks with no conversion, and `func(e Other) Fate` there is S108. (CK-FAILPARAM's narrowing conversion, for a parameter that was a row value of one error type, went with ROW-PARAM r3, d8f68b1b7: no checked source reached it.) *Prior art:* Go's function types are invariant, and so are Ergo's.
   6. `V` is a machine declaration `type X machine[S, E]` and `T` is the prelude's `Machine[S, E, O, F, R, W]` with `O`, `F` and `R` its step's output, error row and capability row and `W` the capability row of its work and its exit actions, apart from `R`, so a fold that runs neither needs `R` only (fumb-e; FK9-g1) ([Prelude types](#prelude-types); README Gap 46). `ConvMachine`: the value becomes `Machine{Initial: X's initial value, Step: its step function, After: its after function, Work: its work function, Exit: its exit function}`, each of the last three, with no such entry, a function that gives every state `None`. A machine whose `initial` names a start function of an input `I` converts the same way to `InputMachine[I, S, E, O, F, R, W]`, with `Start` in place of `Initial`, and to no `Machine`. A `Machine` of another instance is S108, and the message names the output and rows the step gives. The checker tries this clause after clause 2: no operation type, union or function type is a `Machine`.

   Nothing else is assignable (S108). Two named types cross by no clause unless clause 3, 4 or 6 relates them: `type A Mem` and `type B Mem` over one record, `Count` and `int`, `type F func(n int) int` and `type G func(n int) int` each need a conversion ([Conversions](#conversions)), and the message names it only where one exists.
2. **Every site.** One relation decides every place a value is assigned: a `let` (single, and per element of a multi-name `let`, whose element conversions `Info.ImplicitElems` records), an argument, a result, a pattern's written type, a composite literal's field and element, the two operands of `==` and `!=` (one goes into the other's type), and a `context` value. The lowering reads the fact and never derives a conversion again.
3. **Comparison through operations.** A value that implements an operation type through its functions is not that type's value until it is assigned, so `s == Count(1)` with `s Store` is S108; assign it first.
4. *Prior art:* go/types `operand.assignableTo` has clauses 1 to 3 in this order, and cmd/compile's `typecheck.assignOp` returns the lowering operation (`OCONVNOP`, `OCONVIFACE`) with the reason from the same clauses, as `assignability` returns the conversion. Gleam and ReScript have no defined types over collections (an opaque type converts through functions); Rust newtypes cross only by `.0` or `From`.

## Bindings

Status: **implemented** for slices and Maps by the lowering (value-rule; owner q26, 2026-11-08; [decisions](../decisions.md)): `internal/sketch/lower/values.go`, with `TestValueRuleProbes`, `TestValueRuleAgrees`, `TestValueRuleRace`, `TestValueRuleElides` and `TestValueRuleMutants`.

```go
func example() {
	let m = Map[string, int]{"a": 1}
	let mut c = m
	c["b"] = 2 // m still has one entry
	let s = []int{1, 2}
	let t = s.Append(3) // s is still [1, 2]
}
```

1. **Every value is a value.** A slice and a `Map` are values, as an `int` and a record are: a binding, a field, an element, an argument, a capture and a value sent to a task each hold their own. A write through a `let mut` root or a borrow (`m[k] = v`, `xs[i] = v`, `p.f[k] = v`, `m = m.Delete(k)`, `m = m.Put(k, v)`, `xs = xs.Append(x)`) is seen through that root alone, never through another binding, a package `let`, a record field, a slice element, the caller's argument, a function literal's capture or another task. The prelude's `Append` and `Delete` leave their argument unchanged ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Slices and Maps). So a function the checker calls pure ([rows.md](rows.md#footprints)) gives equal results for equal arguments, and two tasks never write one Map. Owner q26, 2026-11-08: "Maps and slices are values: copy where two bindings would share, elided when the source is new or dead".
2. **Lowering.** A slice and a `Map` stay Go's slice and map. The lowering inserts a copy (`maps.Clone`, `slices.Clone`, or a generated copy function that copies each element when an element holds a slice or `Map`) only where a write could be seen through another binding, decided once per body from the checker's facts:
   - a value entering a `let mut` root or a place rooted at one is copied unless it is fresh: a literal, the result of a call whose results are fresh, or a local that is dead after the bind and was never shared (move on last use). A `let mut` is dead after a use, even in a loop, when a later statement of the same block rebinds it whole (`buf = b`) and every run of the use reaches that statement next: no `break` or `continue` between them, and the reads between them (the rebinding's right side among them) are the only reads of the old value (S2-COPY: `let (b, n) = try f.Read(buf); …; buf = b` hands Go `buf` with no copy, and `buf = b`, b's last use, moves b);
   - a read of a `let mut` root that another binding keeps is copied when a write through the root can follow it; a read that keeps nothing (`len`, `==`, interpolation, a `Get`) and a return of the root are never copied;
   - `p = p.Append(x)`, `p = p.Delete(k)` and `p = p.Put(k, v)` on one place write in place, so a loop that builds a slice or `Map` allocates what Go's does; elsewhere `Append` appends to a clipped slice, and `Delete` and `Put` write a copy. The rule reads how a call treats its first operand from the callee's Go form, never from which operation it is (REUSE RU6; `internal/residue`, `TestValueRuleReadsNoOperation`): Go's builtin `append`, or a runtime/v1 appender whose every return is its first parameter or a call on it (the prelude's `Append`, `slices.Concat`), appends; Go's builtin `delete`, or a runtime/v1 body whose every return is its `Map` parameter (the prelude's `Put`), writes the `Map`; `Take`'s intrinsic takes its entry in place. So the prelude's operations are users of the rule, as a user's extern of Go's `append` is;
   - a function literal or block that may outlive its call ([Function values](#function-values) 2) captures a `let mut` only when no write to it follows ([Function values](#function-values) 3), so its capture shares the storage with no copy;
   - an *owned parameter* is copied by its caller, not by its callee. A parameter is owned when its function binds it to a `let mut` local once, in the body's own frame and outside any loop, reads it before that only in uses that keep nothing, never reads it after, and cannot fail after the bind (no call that can fail there, no returned error value). A direct call passes the argument unshared: a copy only when it is not fresh and not a local dead after the call. A rebinding `p = f(…, p, …)` (or `p = try f(…)`) of one place rooted at a `let mut` local hands the old value over with no copy, when no other frame reads or writes the local and the statement uses it nowhere else. So does `p = f(…, p, …) catch { … }` (*own-catch*, REUSE RU2), whose arms may also read `p`: an owned parameter is taken only where `f` cannot fail after the taking, so on the failure route `p` is as it was. The catch's value stored back into `p` copies none of its arms that yields `p` itself (the store puts it back) or a fresh value; an arm that yields another live binding is copied, as any value entering a root is (rows f2 and f3 in `TestHandoverGrowsLinearly`). So `m = maps.Update(m, k, f)` and `b.M = put(b.M, k)` write `m` in place, as hand Go writes `m[k] = f(m[k])`, and a loop of them allocates what Go's does. The function's own name stays a wrapper that copies each owned argument, which every indirect call (a function value, an operations conversion, a witness) reaches.
   - **hand-over** (V7, STD-sh). A rebinding `p = f(…, p, …)` of one place `p` rooted at a `let mut` local or a borrow passes the old value with no copy, and its result enters `p` with no copy, when all of these hold. `p` may be any operand: an argument, or the receiver of a dot call `p = p.m(…)` whose `m` takes it by value (a receiver `m` borrows is not handed). The rule names no function and no package; it holds for a user function as for std's:
     - nothing else in the statement, and nothing in another frame, names `p`'s root, so the old value is dead from the call to the store-back and only `f` reads it;
     - `f` is pure ([rows.md](rows.md#footprints)) and has no failure row, so nothing `f` runs can observe the old value, and the store-back always follows the call;
     - `f` writes no storage of the argument that its length covers, and `f`'s result shares no storage but the argument's. For a function with an Ergo body that owns no parameter, its body writes a parameter only through a `let mut` copy, and the analysis of its body, with that parameter read as an unshared local, proves every returned value fresh; so a result that may be another argument, a package `let` or a capture's value is not handed over. For a std extern bound to a pure runtime/v1 body ([stdlib.md, Pure bodies](stdlib.md#pure-bodies)), the body keeps nothing of its arguments but its result and writes no element their length covers, and every other argument must hold no slice or `Map`.

     **Consumed arguments.** A runtime/v1 body may name an *owned form* of the same shape (`//ergo:owned Name`, `v1.Body.Owned`) that takes its first argument over, so it may keep that argument's storage in its result with no copy; an `unsafe` one is reviewed and listed in `internal/residue/testdata/unsafe.txt` (owner q112). A call of such a body calls the owned form when its first operand is fresh: a local dead after the call and never shared, a literal, a fresh result, or a copy. A parameter whose one use, or one use in each arm of a `match` or an `if` (one run of the statement runs one arm; REUSE RU1b), in the body's own frame and outside any loop, is an operand (or a field path of one) at a position a call consumes (an owned form's first operand, or another function's owned parameter) is an *owned parameter* as above, a method's receiver included: its callers pass it unshared, a copy unless it is dead or fresh, and its body reads it as an unshared local. So `b.String()` on a `strings.Builder` that nothing reads after the call shares the buffer, as Go's `String` does, and one that is read again copies it first (`TestValueRuleElides`). `slices.Sort(xs)` names an owned form that sorts `xs` in place, so a slice dead at the call is sorted with no copy, and one read again is left as it was (law `SortLeavesItsArgument`; the seeded property sorts both kinds, `TestValueRuleAgrees`). The rule keys on the body's directive and the operand's liveness, never on a function's name.

     The same body fact makes a pure runtime/v1 body's result fresh when every argument is fresh, and a read that a rebinding handed over leaves `p` unshared. So `p = utf8.AppendRune(p, r)` in a loop, `b.buf = …` through a borrow in `strings.Builder`'s writes, and `p = addByte(p, c)` of a user function `func addByte(b []byte, c int) []byte { utf8.AppendRune(b, rune(c)) }` append in place as hand Go does, where a copy at each call made the loop quadratic (`TestValueRuleElides`). The copying lowering (`valueLowering=copy`) hands nothing over and is the reference of the seeded property `TestValueRuleAgrees`, which rebinds through generated user functions.

     **Views.** A runtime/v1 body that is one return of a slice expression of its first parameter, with bounds that are its other parameters (`return xs[i:j:j]`, `slices.Slice`), is a *view*: it writes nothing and keeps its operand only in its result, a window of the operand's array (`goBodyView`). Where the value rule would copy the operand (the root is written later), it copies the window instead, `slices.Clone(slices.Slice(r.stack, i, j))`, which is O(window), not O(field). A window that a call reads and keeps nothing of (`len`, or a pure call whose result is basic or reaches no slice or `Map` type the window reaches, at a parameter it does not own) is not copied at all, unless a later operand of that call writes the root. So a parser's scratch stack closed as windows costs what the windows hold (wf10 DF1; `TestHandoverAgrees`, `TestHandoverGrowsLinearly`'s ownwindow; the reference is `aliasLowering=type`);
   - **dead-value hand-over** (OWN1; `internal/sketch/lower/handover.go`, `TestHandoverAgrees`, `TestHandoverGrowsLinearly`; it subsumes speed-2's V1). An `Append` or `slices.Concat` writes its source in place where no other binding can see the write. A shortcut that took the source when it must not would be a shared write, so each form is a row of the shortcut registry (`internal/sketch/lower/shortcuts.go`) with its admission, its mutant and its reference (`valueLowering=copy`):
     - *own-consume*: `p = slices.Concat(p, q)` on a `let mut` or a borrow root, and `Concat` on a dead unshared local, call the owned form `SlicesConcatOwned`, which appends to `p` as `p = p.Append(x)` does. A spread operand whose elements hold no slice or `Map` is not copied, since only its elements enter the root.
     - *own-field*: `r.f.Append(x)` writes in place when `r` is a local that is dead after the call and unshared. A read of another field whose value holds no slice or `Map` (`r.head` beside `r.items`) keeps nothing and does not count as a later use, and neither does a use outside the `return` statement that holds this one. A parameter that its body takes over only through its fields is owned (*own-parts*, below). So `r = push(r, v)` on a ring writes one slot, not a copy of every slot.
     - *own-parts* (consume by parts, REUSE RU1; `internal/sketch/lower/parts.go`): a parameter whose every use, in the body's own frame and outside any loop, is a field path that keeps nothing, a field path at a consuming position (the value of a `let mut`, an owned parameter of an Ergo body, an owned form's first operand, the source of an `Append`), a whole `return p`, or the base of a returned update `T{..p, …}`, with no failure after the first consuming use, is owned, as above: its callers pass it unshared and its body reads it as an unshared local. Each consuming use still takes its path in place only when no other use of `p` overlaps it (the per-site rule above). So `St{set: Insert(s.set, x), n: s.n + 1}` and `Raw{..s, xs: s.xs.Append(x)}` in a loop of `s = f(s, x)` copy nothing.
     - *own-move*: the base of an update `T{..p, f: e}` and a field path of `p` used in `e` share no storage when no field the update keeps can hold a slice or `Map` that the path's field holds (by type: two fields of one record may hold one array). The base gives the result only the kept fields, so `St{..s, set: Insert(s.set, x)}` hands `s.set` to `Insert` and keeps `s.n`, with no copy of either.
     - *own-return*: a whole `return p` that comes before the one `let mut` bind of `p` ends its route before the bind, so on that route `p` goes back to the caller unchanged, and on the other the bind takes it alone: `p` stays owned (`InsertNew`'s early `return s`). A `return p` after the bind refuses: it would return what the bind wrote.
     - *own-update-self* (LWR-SPREAD-SELF): `r = T{..r, f: e, g: w}` on a `let mut` record `r` lowers to the field values, all evaluated before the first store, then one store per named field, with no copy of `r` into a temporary and back. The old value of `r` is dead once the statement stores, so its base is handed over (V7) when every other use of `r` in the statement reads a field that holds no slice or `Map`, or a path under a field the update names. A value that reads a named field reads the old one, as the update does.
     - *own-read*: `let b = p.blocks[id]` through a borrow or a `let mut` root takes the element without a copy when `b` is a plain `let` whose every use keeps nothing, and no use of the root in the body can write a slice or `Map` type that `b`'s value reaches. A write of a field `p.blocks[id].kind` writes only `[]block`'s array. Passing the borrow on (`poke(p, id)`, a pointer method) can write everything its target reaches. A borrow is the only path to its target (Borrows 2), so no other name writes there (`internal/sketch/lower/storeread.go`).
     - *own-reslice*: `s.xs = s.xs[:len(s.xs)-1]` or `xs = xs[1:]` stores a cut of a place back into the same place, rooted at a `let mut` or a borrow. The old value is overwritten and the root held its array alone, so the cut is not copied, and a stack's pop keeps its room. A cut of another place (`m.Items = b.Items[0:k]`) is copied. A bound that writes the root (a call given `&s`) still takes the cut uncopied: the old array is left to no binding. A window of the place that another binding keeps (`let w = stack[mark:len(stack)]`) is copied at that binding, so an Append after the cut (`stack = stack[0:mark]; stack = stack.Append(id)`) writes no row the window shows; a scratch stack cut back to a mark and grown again is linear (SL3, `cmd/ergo/testdata/ownshrink` in `TestHandoverGrowsLinearly`). A cut of the place passed to an owned parameter of a call whose result the statement stores back into it, `buf = f(…, buf[:0])`, hands the cut over for the same reason (LWR-INLINE-OWNED, REUSE RU1b): a reused buffer is not copied at each call.
     - *own-cut* (NB-CUT; `internal/sketch/lower/cut.go`): a cut keeps uniqueness. A cut of a fresh value is fresh, so `let mut ys = MakeSlice[T](m)[0:k]` takes it with no copy. A parameter is owned (V5), as above, when the body takes it into a `let mut` as a cut of itself (`let mut ys = xs[0:n + 1]`), in the body's own frame and outside any loop, and every other use either runs in another arm of a `match` or an `if` than the taking, or comes before it as a read that keeps nothing (`len(xs)`, a binding of Go's `cap`); and no failure can come after the first taking. Its callers pass it unshared, and the cut, its last use, is taken with no copy. So a push written in plain Ergo over `cap`, `copy`, a cut and an index write appends in place, as Go's `append` does, and `xs = push(xs, x)` in a loop copies nothing; a parameter read after its cut in the same arm, or kept by an earlier `let`, is not owned, and the cut is copied. The reference is `-X …/lower.cutLowering=copy`, and `valueLowering=copy` turns it off too; `TestCutKeepsUniqueness` holds each seeded shape's copies and owned forms to a model on the Go text and on the IR, and `TestCutAgrees` runs the programs under the rule, under the reference and on the IR through `ergo run`, writing through every cut and reading every source and alias after.
     - *own-fresh-call*: a call of an Ergo body returns a fresh value when every operand that holds a slice or `Map` is fresh, handed over or consumed, and the body's analysis proves every result fresh with every parameter read as an unshared local (`freshAll`). In that analysis, a one-extender site on a dead field of such a parameter counts as fresh: it writes in place only an array the token says it made last, and that array is the parameter's alone. A parameter is also owned through its fields when it is returned whole by a `return` (`return d` beside `let mut b = d.Buf`). A use in one return statement or last value ends the frame for a use in another arm. So GP2b's `d = Make(d, edits, after)` with `b = apply(b, e)` copies neither the buffer nor the document.
     - *own-ref-in-place*: an owned `Update` or `Modify` site whose literal first binds its parameter to one `let mut s` with no copy, and ends with `s` or `(x, s)`, with no `return`, no function literal and no trailing block inside it, lowers to `v1.RefUpdateInPlace` or `v1.RefModifyInPlace`: the literal gets the held value's address, and `s` is that value, so no copy of `T` is made into or out of the cell (ST's G1: json.Stream's Reader operations). A shared value is still copied first, under the lock, and a defect poisons the cell as before.
     - *own-lineage* (run-time checked): an `Append` of one element on a field path that no static rule proves dead (`Idle{..i, Log: i.Log.Append(d)}`, a value kept by a machine's runner) appends through a per-site token, `v1.LineageAppend`. Under the token's lock it appends in place only when the source is exactly the slice this site made last (same array, same length) and has spare capacity; otherwise it appends to a copy. Then it records the result. Older values are shorter than the slot written, so they never see it. A slice that came from such a site is never fresh, so it enters a `let mut` root only as a copy.
     
     Test builds take none of these. Instead they call checking forms (`SlicesConcatPoison`, `AppendPoison`, `LineageAppendCheck`) that copy, then overwrite the storage the shortcut would have reused, so a test that kept that storage fails. `ergo build -report copies` prints each site's form and its reason on stderr.
   - a `sync.Ref` owns its value ([stdlib.md, Sync and STM](stdlib.md#sync-and-stm) 1; V6, owner q46): the parameter of a function literal written at `Ref.Update` or `sync.Modify` is an unshared local, which the `Ref` copies first when its value may be reached from outside.
   - a read of a place (a `let mut` or a borrow, its fields, or a borrow's pointee) that the next write overwrites whole moves with no copy (V7, VC1; `internal/sketch/lower/moves.go`): a *take* `let got = P` whose next statement is `P = e`, with `e` a literal that calls nothing, indexes nothing and names nothing of `P`'s root, and a *reslice* `P = P[a:b]`. The old value leaves the place as the place gets its new one, so `got` holds it alone, and the reslice keeps the array that only `P` held. A write between the read and the overwrite, or an overwrite of another place, makes the read a copy as before. The reference is `valueLowering=copy`, which moves nothing.
   - an argument read from a `let mut` or a borrow root is not copied at a call of a function that keeps nothing of it (KEEP1; `internal/sketch/lower/keeps.go`). A function keeps nothing of a parameter when no use of it, or of what it flows into (a let, a loop's element, a match's case bindings, a call's result where the result depends on it), reaches a return, a function literal, a store through a borrow or a call that may keep it (a function value, an operation, a Go function, or a function whose own summary keeps it). The argument is still copied when the call could write the root while it runs: another operand names the root (`f(xs, &xs)`), an operand is a function value, or a function literal writes the root. So `Apply(s, p.out, u)` followed by `p.Clear()` passes the list with no copy. The reference is `keepLowering=copy`, and `valueLowering=copy` turns it off too.
   - a pure call whose result can hold a function or operation value that depends on an argument copies the argument, not the result: a copy of a function value copies none of what it captured (`let g = hold(xs); xs[0] = 2` leaves `g` with the old `xs`).

   Three facts sharpen what a use keeps: a call of a pure function whose result reaches no slice or Map type its argument reaches keeps nothing of the argument (`find(t, path)` that returns a place); a part of a returned tuple or literal is returned with it; and a use in one `return` (or last value) of a frame never runs before a use in another, since each ends the frame.

   **Result aliasing** (OPT1; `internal/sketch/lower/alias.go`, `TestKnownCallbacksAgree`). A function with an Ergo body has a *result-alias summary*: for each parameter, whether its result can share a slice or `Map` with that parameter's value. The summary follows the parameter's value through paths, conversions, `try` and `catch`, literals and tuples, lets, assignments (which taint the root of the place), `for` loops over it, and calls (a call of a function with an Ergo body passes it on only at a parameter its own summary marks; a pure std body passes it to its result). Any other call, a use in a function literal, a `match` on it, and any other statement count as reaching the result. A use whose type reaches no slice or `Map` carries nothing; a type parameter may hold one, so it carries. At a call of a pure function, an argument read from a `let mut` root on which the result does not depend keeps nothing and is not copied; an argument on which it depends is not copied either, and the call's *result* is copied instead when a write through the root can follow. A pure call has no other output, so its copied result is as unshared as a result computed from a copy of the argument, and it costs the result's size: `arena.Get(store, r)` copies the element it returns, not the store, and nothing when the element holds no slice or `Map` at its instance. The reference lowering, which reads only the types, is selected with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.aliasLowering=type`.

   Two rules hold in both lowerings. A read that keeps nothing (a pure call's argument) is still copied when a write through its root runs in a later operand of the same call, `f(c, bump(&c))`: the callee must see `c` as it was when it was read. And a generic function returns the parts of a type parameter through a borrow as they are, since its copy stops at a type parameter: when its result's instance holds a slice or `Map` and the summary says the result depends on a borrowed operand, the caller copies the result.

   **The entry rule** (V8; MAPCOPY, `internal/sketch/lower/values.go`, `TestCopyCountsMatchModel`, `TestCopyRuleAgrees`, `TestUIPassGrowsLinearly`). A `Map` entry has no write path: `m[k][i] = v` and `m[k].f = v` are refused (S108), and a write through `m` replaces or removes a whole entry. So:
   - a read of an entry (`m.Get(k)`, through a `let mut` root or a borrow) keeps nothing that a write through the root can change, and is not copied; only the rule above copies its receiver, when a later operand writes the root, and a borrow passed whole to a call in a later operand counts as such a write;
   - an Ergo copy of a `Map` is a copy of its table (`maps.Clone`), not of its entries, since no Ergo write reaches an entry in place. A value given to Go (an argument of a Go call, a Go result, a Go callback's arguments and results) is copied deep, entry by entry, since Go may write an entry two Ergo Maps share (`TestGoGetsEntryCopies`);
   - a pure std body's result is copied instead of its argument when a write through the root can follow and the result's type shows every slice or `Map` it holds (no union, `Option`, type parameter or function value hides one): `slices.Slice(r.s, i, j)` kept in a field copies the window, not `r.s`;
   - `Append`, `Put` and `Delete` on the result of another write that result in place, since nothing else holds it; `p = p.Append(a).Append(b)` writes the whole chain in place on the root. A chain on a shared source copies once, at its first link.

   **The entry move-out** (V9; MAPCOPY round 2, `internal/sketch/lower/moveout.go`, `TestFanOutGrowsLinearly`). A read-modify-write of an entry that holds a slice or `Map`, `let mut kids = …; match m.Get(k) { case Some[…] as v: kids = v.Value case None: }; kids[x] = y; m[k] = kids`, takes the entry itself and writes it in place, as Swift's `_modify` and Lean's `Array.modify` do on a unique value. Every `Map` type the program moves an entry out of is *entry-written*, and for it:
   - a copy of the `Map` copies its entries too, as a copy of a slice of slices does;
   - a value `Put` stores is unshared (copied unless fresh), as an index write's already is;
   - a `Get` whose result is kept copies the entry it gives where a `match` binds it, or its receiver when the `Option` is kept whole; a `Get` only compared with `None` copies nothing.

   In a `sync.Ref`'s owned callback the move-out and *own-ref-in-place* are one rule: the cell's copy-if-shared is the only copy of the held `Map` (deep for an entry-written type, since a value `Get` handed out shares its entries), it runs under the lock before the callback, and the callback then writes the held value in place, the moved-out entry included (`examples/bucketstore`, `Bump`: no copy when the cell is not shared).

   The move-out holds at a site when the store `m[k] = kids` follows the `match` in the same block; the statements between do not name `m`'s root, cannot fail or leave (`return`, `break`, `continue`, `try`, a function literal), and use `kids` only to read it or write through it; `kids` is a `let mut` of that block, not used after the store; `k` is a literal or an immutable variable; and `m` is a path of fields from a `let mut` or a borrow. Anywhere else the entry is copied at the bind, as under V8 alone: it costs the entry's size, not the Map's.

   *Arm form* (REUSE RU8): the store may instead be the `Some` arm's last statement, `case Some[V] as v: m[k] = f(v.Value)`. The value is evaluated before the store overwrites `m[k]`, so the old entry is read once, by the value, and kept only where the value keeps it: `v.Value` is taken with no copy, an `Append` on it extends it in place, and an owned parameter takes it as handed over. The arm form holds when `k` is as above, `v` is used once, in the value, nothing in the arm before the store or in the value names `m`'s root (`wr(v.Value, r)` would read `r.m` after writing the entry), and nothing there can fail or leave. So keepCard's Bump (`p.cards[key] = keepCard(v.Value, k)`) and a group-by over a `Map` (`m[key] = g.Value.Append(x)`) copy nothing per step (`cmd/ergo/testdata/reuse` rows kc and gm in `TestHandoverGrowsLinearly`).

   *Element Append* (LWR-ELEM-APPEND, REUSE RU8): `gs[j] = gs[j].Append(x)` on an element of a `let mut` or borrowed slice is the in-place pattern on that element, when `j` is a literal or a path of fields from an immutable variable, so both sides name one element. An element holds its array alone, as a root does: what enters a root is fresh or copied (V1). `gs[0] = gs[1].Append(x)` is not the pattern: it clips, since `gs[1]`'s next `Append` would write the slot `gs[0]` shows. Row gs.

   Three holes the move-out rests on are closed in both lowerings: a pure call whose result is an `Option` or a union copies its argument, not its result, since that copy stops at the `Option`; a generic call's result is not fresh when a type argument holds a slice or `Map`, since it may return the argument, unless every operand that may carry such a value is handed over (V5), fresh, or a function literal whose every result is fresh, so `b.threads = maps.Update(b.threads, k, func(o) { … })` writes the `Map` in place on an entry-written type as on any other; and a law's body decides its copies as a function's does. A rebinding through a borrow, `b.f = f(…, b.f, …)`, hands `b.f` over as a `let mut`'s place does, since a borrow is the only path to its target (Borrows 2). A `let mut` stored whole into a `Map` whose type is not entry-written stays unshared for its later reads (`p.paths[id] = path; len(path)`): neither the entry nor the local is written after. A callback passed by name, a top-level function with an Ergo body (`maps.Update(m, k, start)`), counts as a literal does: unshared when its every result is fresh. A one-extender Append that such a function returns, of elements that hold no slice or `Map`, takes the plain clipped Append when any package of the program names the function as a value (`maps.Update(m, k, cbs.Start)` from another package as well), so its result is fresh; a function only called keeps the one-extender site (`settleNamedTails`). A call's result used only by a read that runs at once copies nothing, whatever the call returns (a pure call's result, a pure std body's, a generic result through a borrow, a Go call's): `len(x)`, an index read `x[i]` whose element holds no slice or `Map` or is itself read at once (`len(x[0])`), a comparison, a field read `x.f` on the same terms as an index read (`len(x.xs)`), a `for` loop over `x` whose body makes no call, takes no address, returns nothing and assigns only locals that hold no slice or `Map`, and an operand of a call or method call whose result is basic and whose other operands are call-free basic values (`total(x)`, `x.Sum()`, but not `total3(x, r)`, which may write through `r`); the index and the other compared operand make no call, and `&x[i]` is not a read (`internal/sketch/lower/readonly.go`, `TestReadOnlyUsesAgree`). The reference, the rule before V8 and V9 (each `Get` through a root copied it, a `Map` copy was deep, no move-out; a `Get` of a scalar entry copies its receiver when a later operand writes the root, as above), is selected with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.copyLowering=whole`; `TestCopyRuleAgrees` holds the two equal on seeded programs.

   Otherwise a copy is deep through slices, records and tuples, and stops at a union, an `Option` and a function value, whose parts a match or a call binds immutably. The reference lowering, which shares as v1 did, is selected with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.valueLowering=alias`; `TestValueRuleAgrees` proves it equal to the rule on seeded programs with no shared write, and the rule equal to a value-semantics interpreter on programs with one. `valueLowering=copy` selects the rule without owned parameters, each callee copying at its bind; `TestValueRuleAgrees` holds it to the same interpreter on the same programs.
3. **Unchanged.** A `for` over a slice or `Map` keeps Go's rules ([Loops and len](#loops-and-len) 1). A captured scalar `let mut` still follows Go's capture by reference; Function values 3 owns it.
4. *Prior art:* Swift's `Array` and `Dictionary` are values copied on write after a uniqueness test of their reference count, and its optimizer removes the copies it proves unneeded; Hylo has mutable value semantics; Gleam, Elixir and ReScript lists and maps are immutable, so no write is shared; Rust refuses the shared write in its borrow checker; Go shares. Ergo has no reference count, so it copies on a static fact.

## Task ownership

Status: **implemented** (L8 B3t). A `Task` and a `tasks.Set` are resources ([resources.md](resources.md) R1, [runtime.md](runtime.md#tasks) rule 3): the prelude's `Task[T, E]` and std `tasks.Set[E]` declare `Close()`, so the resource rules (one owner, a hand-off moves, an index lends, `slices.Take` and `Map.Take` move out) govern them, and the checker names neither type. The rules of check-v1 stage D3a that kept a Task in its frame (type positions, allowed uses, type arguments) and the hidden destination of stage D3b gave way to them: a returned `Task` is an owned value its caller registers (R10), and a slice or a `Map` of tasks is a resource (R34).

1. **Running code.** One rule stays specific to code that runs: the value of an owning `with` holds no `Task` or `Set`, since its code may use the providers the `with` closes (S108). It reads runtime/v1's reviewed table (`v1.StopsRunning`, `check/running.go`).
2. **Frame scope.** A call that needs a frame scope (`task.Go`, `scope.OnExit`, an owning `with` or a context `with`) outside a function body, in a package `let`'s value, is S108; inside a package `let`'s trailing block or function literal it has that block's frame scope (**implemented**, check-v1 stage E2). *Prior art:* Gleam's constants hold no effects.
3. *Prior art:* Rust moves a `JoinHandle` as any value and tokio's `JoinSet` aborts its tasks on drop; Swift's `~Copyable` types; Elixir's Task checks its owner at run time. Gleam and ReScript have no Task ownership rule in their types.

## Basic types

Status: **implemented**: `bool`, `string`, `int` to `int64`, `uint` to `uint64`, `float32`, `float64`, `complex64`, `complex128` and `duration`, with `byte` and `rune`, are checked by `internal/sketch/check` and lowered to their Go types, `duration` to `time.Duration` (check-v1 stages B to E; `TestInterpolationText` runs a value of every basic kind through lowered code). Rules 6 and 8 are **implemented** by the checker and the lowering (check-v1 stage E1).

1. `string` holds bytes. A literal's value is the bytes its spelling decodes to ([grammar.md](grammar.md#literals)).
2. The integer types are Go's, with Go's sizes. Non-constant arithmetic wraps; constant overflow is an error (rule 7).
3. `bool` is the type of comparisons and `if` conditions.
4. `duration` is the type of duration literals. It is a basic type, usable in every type position: parameters, results, fields and type arguments. Its name is predeclared.
5. The composite types are slices `[]T`, fixed arrays `[N]T` ([Arrays](#arrays)), maps `Map[K, V]`, queues `queue.Queue[T]` ([runtime](runtime.md#channels)), function types, tuples ([Tuples](#tuples)) and the prelude `Option[T]`. The ordered types are the prelude's type set `ordered` ([Generics](#generics) 2), and an order on a type is a `cmp.Order[T]` provider passed to the call, as `slices.SortBy(xs, ByPriority)` ([stdlib](stdlib.md#slices-maps-and-cmp) 11).
6. **Literals are typed where they appear** (196u; checked by `internal/sketch/check`). A literal takes the type its context expects: a written `let` type, a parameter (after the type arguments that typed arguments fixed), a result (a `return` or a tail value), a record field, a slice element, a Map key or value, the other operand of a binary operator or of `..` (a composite literal of a generic type written without type arguments takes its type arguments from the other operand the same way, so `f() == Some{Value: A}` with `f()` an `Option[T]` compares two `Option[T]` values; K2, `TestComparisonGenericLiteralTakesOtherType`), an assignment's target, an index or slice bound (`int`), and a constant `case` (the subject's type). An integer literal may take any integer or float type, a float literal only a float type, a rune literal any integer type, and a string literal a string type; an integer literal is never a `duration` (S108 "an integer literal is not a duration: write a duration literal such as 5s"). Every other position gives no expected type, and the literal takes its default: `int`, `float64`, `rune`, `string`, `duration`, and `bool` for `true` and `false`. A literal that cannot take the expected type is S108 naming the form to write ("a float literal takes only a float type, not int; write 2").
7. **A name has one type.** A package-level `let` has one type, and no name converts by itself: `let b int8 = Limit` with `let Limit = 10` is S108 "Limit is int; write int8(Limit) or declare Limit int8". Constant expressions evaluate exactly, step by step, and each typed step must fit its type: an overflow is S108 ("the constant 200 overflows int8" for `let y int8 = 100 + 100`, and for `100 + 100 - 100`, whose first step overflows), as in Rust's constant evaluation. A literal fits its type after its sign, in parentheses or not, so `-128` and `-(128)` are `int8`. Ergo has no untyped constants: Go's untyped kinds, their defaulting order and the contextual types Go records afterwards are the counter-example (196u "Why"). *Prior art:* Rust and Swift type a literal from its context with `i32` and `Int` defaults, and `1 + 2.5` is an error in Rust; MoonBit overloads an integer literal by its expected type (`let x : Int64 = 1`); Gleam, and ReScript after OCaml, keep `Int` and `Float` apart with separate operators (`+`, `+.`); Elixir's numbers are dynamic.
8. **The closed world** (196d; check-v1 D-E2). `any` is not a type: its use, as a type or as a constraint, is S104 "Ergo has no any; use a type parameter or a union", and `[T any]` is written `[T]`. The one exception is not a constraint: `any` ends a group of unconstrained type parameters that a constrained group follows, `[E any, K comparable]` ([grammar.md](grammar.md#declarations) 3; fu8b); the parameters it ends have no constraint, as `[E]` has none. `error` is not a constraint either: `[E error]` is S104 at `error`, and a failure row parameter is written `[E]` and used after `fails`. No std package is named `reflect`. Equality is generated from declared types ([Operators](#operators) 1), so no value is compared through an interface. *Prior art:* Gleam has no `any` and compares by structure; ReScript and OCaml compare structurally; MoonBit derives `Eq`; Go's `==` on interfaces panics at run time on an incomparable dynamic type.
9. **Text form** (check-v1 E6a, D-E6). A value of every basic type interpolates, `"\(x)"`, as Go's `%v` prints it, complex and `duration` values included ([grammar.md](grammar.md#literals), Strings 5).

## Zero values and definite initialisation

Status: **implemented** for rules 1 to 3 and 5: checked by `internal/sketch/check` and lowered, a defaultable type to Go's zero value (check-v1 stages B to D; `let p Payment` with no value is S108 "let p of type Payment needs a value: Payment has no zero value (types.md, Zero values 3)", `TestDecidedMessages`). Rule 4 has no built-in to apply to. Rule 6 is **implemented**: checked by `internal/sketch/check` (196b Q7, [decisions](../decisions.md#decided-by-principle-2026-11-05); S114, `TestConstructionAuthority`, `TestConstructionAuthorityShapes`).

1. A type is *defaultable* when it has a valid zero value: a basic type (and a defined type over one), a slice, a Map, an array whose element type is defaultable ([Arrays](#arrays)), a record with no fields, or a tuple of defaultable types. A record with fields is not defaultable (rule 2), nor is a union, a capability, a function type, a `Task`, a resource, a borrow, or an array or a tuple that holds any of them.
2. **No implicit zero** (owner q44, 2026-11-09). A record value is built only by a literal that names every field, keyed or positional, or by a record update (Structs 3). A keyed literal that leaves a field out is S108 at the literal, whatever the field's type; the message names every field it leaves out, in declaration order, and the two fixes: "Walk{…} does not set Retries: a record literal names every field; write Retries: …, or copy it from a value with Walk{..v, …} (types.md, Zero values 2)". So a field added to a record stops every literal that does not name it. The empty `go.Error{}` is not such a literal: it is the nil Go error ([interop](interop.md#go-errors) 1 and 3), whose `Text` Go gives and no literal stores (batch-14 integration). *Principle:* every field value comes from a site that named it. *Prior art:* Rust E0063 "missing field", OCaml, Elm, Gleam and ReScript require every label; Go fills a left-out field with its zero value, and the third-party linter `exhaustruct` exists to catch that.
3. A variable of a non-defaultable type must be initialised before use. `let p Payment` with no value is an error, and so is `let w Walk` for a record `Walk` with fields, `let v (Walk, int)` and `let b Box[int]`. A basic type, a slice and a Map keep their zero value: `let n int` is `0`, `let xs []Walk` is empty. Outside its package, a record that only its package builds is S114 first (rule 6), since that message names the function to call. *Prior art:* Swift and Kotlin definite initialisation; Go instead gives every type a zero value, which is how a nil interface reaches a type switch.
4. Designed: an operation that invents zero values needs a defaultable element type. The decided language has no such built-in (`make`, the comma-ok forms and channels are gone); the library returns `Option` instead, as `m.Lookup(k)` returns `Option[V]`.
5. There is no `nil`. *Prior art:* Gleam, ReScript and Rust have no null; Go's typed-nil interface and nil map are its most cited traps.
6. **Construction authority.** Outside the package that declares it, a struct type with an unexported field ([grammar.md](grammar.md#visibility)) is neither defaultable nor literal-constructible. A defined type over such a struct has the authority of the package that declares the fields (`type M lib.Q`), and a struct, tuple or instance that holds one by value needs it for its zero value. Each of these is S114 outside the package:
   - a composite literal of the type or of a defined type over it, keyed, positional or empty (`lib.Q{N: 1}`, `lib.Q{}`, `M{}`);
   - a record update of it, `lib.Q{..q, N: 2}`, even when it names exported fields only;
   - an implicit zero value: `let q lib.Q` with no value, at package level or in a body, also inside a tuple type (`let v (lib.Q, int)`) or an instance (`let b Box[lib.Q]`). A keyed literal of an enclosing struct that leaves a field unset (`H{B: 1}` with `A lib.Q`) is S108 by rule 2. A Map read never invents a value: it is `m.Get(k)`, which returns `Option`.

   The message names the package and up to three of its exported functions whose result is the type: S114 "a literal of lib.Q builds a new value: lib.Q has an unexported field, so only package lib builds it; use lib.ParseQ". Allowed outside: the values its package's exported functions return, a conversion between a defined type and its base (no new value is made), reads of exported fields, patterns, copies, and a literal or update of an enclosing struct that sets the field (`H{A: lib.ParseQ(1), B: 1}`, `H{..h, B: 2}`). A property parameter of such a type is S108 outside the package, because a generator builds it field by field, unless the package declares its constructor `New<T>`, which the generator then calls ([runtime.md, Tests](runtime.md#tests) 6) ([grammar.md](grammar.md) Declarations 11). The checker exports the rule as `check.Constructible(t, from)`, which generators, codecs and `refine` read. It exports a second fact, `check.Buildable(t, from)`: whether `from` makes a value of `t` at all with no authority, from literals, empty literals, zero values, conversions, function values and its own implementations of an open operation type (a sealed operation type is built when a type of its package that implements it is; an empty `[]lib.Q{}` is built, so a record whose exported field is `[]lib.Q` is Buildable and not Constructible); the std host guard reads it (stdlib.md, Host packages 6).

   Inside the declaring package, the construction-authority restriction is lifted, and the ordinary rules 1 to 4 still apply. A record with fields stays non-defaultable in its own package:

   ```go
   type State = Idle | Running
   type Idle {}
   type Running { Since int64 }
   type Box { state State }

   func newBox() Box { return Box{state: Idle} } // allowed: a literal inside the package
   func zeroBox() Box {
   	let b Box // error even inside the package: Box is a record with fields, so it has no zero value (rules 2 and 3)
   	return b
   }
   ```

   Values from outside come only from the functions the package exports, so `ParseQuantity` is the only way to build a `Quantity` and its check cannot be bypassed. Exports stay by capitalisation. *Prior art:* Rust forbids constructing a struct with private fields outside its module and gives it no `Default` unless the module derives or implements one; Gleam's `opaque` types hide constructors; Go leaves this hole open: a two-package probe builds `Quantity{}` and `make([]Quantity, 1)` from another package and reads `units=0` for both (review round 2 receipt).

## Structs

Status: **implemented**: rules 1 to 4 are checked by `internal/sketch/check` (check-v1 stage B, D-B2) and lowered to Go structs (check-v1 stage C). Rule 5 is resource ownership's (aggregate resources, [resources.md](resources.md)); rule 6 is **designed**; rule 7 (included records) and rule 8 (layout) are **implemented**.

```go
type Order {
	ID    string,
	Total int64,
}

let order = Order{ID: "42", Total: 1999}
let same = Order{"42", 1999}
```

1. Field names in one struct are distinct (S108). A field and a function on the type (see [Methods](#methods)) may share a name: `x.f` is the field first (196m).
2. A composite literal is all keyed or all positional (S001). A positional literal lists every field in order (S108). A keyed literal sets each field exactly once (S108; [Zero values](#zero-values-and-definite-initialisation) 2) and names only declared fields (S104). A record update `T{..base, F: v}` is a keyed literal whose other fields are the base's (rule 3). **A record with no fields is written bare** (check-v1 D-B2): its name is its one value, `return Pending`, and `Pending{}` is S108 "a record with no fields is written bare: Pending"; a bare name of a record with fields is S108 "Paid has fields; write Paid{…}". A function on such a record is called on the bare name, `Runner.Each(f)`: there are no method expressions to confuse it with. In a pattern the bare name tests the type ([rows.md](rows.md#totality), Totality 1). *Principle:* one form per job. *Prior art:* Rust unit structs, Gleam fieldless constructors and ReScript constant constructors are bare.
3. Each field value must be assignable to the field's type (S108). A field value whose failure is not handled is S105. A field value that is a composite literal writes its type, keyed or positional: `Wrap[S]{value: {h: 1}}` is S108 "missing type in composite literal; write S{h: 1}" (the literal's source is `{…}` past 40 characters or across a line). As in Go, a composite literal may elide its type only as an element of an array, slice or map literal or as a map literal's key (Go spec, "Composite literals"; round 17 C1). *Prior art:* go/types reports "missing type in composite literal" there, and Ergo adds the fix; Rust and Gleam always name a record's constructor.

   **Record update** (2026-11-05; [grammar.md](grammar.md#expressions), Expressions 11). `Walk{..w, Turn: w.Turn + 1}` is a copy of `w` with `Turn` replaced. It is a composite literal of `Walk`, so every rule about who may write a `Walk` literal applies to it unchanged ([grammar.md, Visibility 3](grammar.md#visibility)), and its fields follow rule 2 and this rule: each named once, declared, assignable, a failure handled.
   - `T` is a record type: an update of any other type is S108. A generic `T` written without type arguments takes them from the expected type, or else from the base: `Box{..b, V: 2}` with `b Box[int]` is a `Box[int]`.
   - The base is a record value, checked with `T` as its expected type. A value that is not a record is S108 at the base. A union value is not a record value: `Playing{..g, W: w}` with `g Game` is S108, because `g` may be another variant; match it first (`case Playing as p:` then `Playing{..p, W: w}`).
   - With a base of exactly `T`, every field the update does not name is the base's, and it names at least one field: `Walk{..w}` is S108 at the literal, "a record update names at least one field; the copy is w itself" (one form per job).
   - **Spread** (owner q43 = A, 2026-11-09). With a base `s` of another record type `S`, `T{..s, F: v}` is a spread: each field `G` of `T` it does not name is `s.G`, where `S`'s field `G` has the same declaration as `T`'s and the same type. Two fields have the same declaration when `S` and `T` are instances of one record type (`Box[string]{..b, V: "x"}` with `b Box[int]` copies `N` and must name `V`), or when both come from one included record `..R` (rule 7), at any depth. Every other field of `T` it does not name is S108 at the base, one diagnostic per field: `S` lacks it ("AtLimit{..c}: Counting has no Reached; name it: Reached: …"), has it from another declaration ("AtLimit{..c} does not copy N: Counting's N and AtLimit's N are declared apart, and a spread copies only a field both take from one declaration; write N: c.N"), or has it with another type. Fields of `S` that `T` lacks are not copied, so a spread need name no field: `Visit{..p}` projects a `Visit` out of a `Prompt` that includes it, and `Prompt{..v, Left: 3}` injects one. The desugaring is the meaning: `T{F: v, G: b.G, …}` with `b` bound to the base first, so construction authority (S114), field visibility (S104), assignability (S108) and handled failures (S105) apply as at any literal. *Principle:* a field gets its value from a site that named it or from the one declaration it shares with the base; a field added to `T` stops every spread that cannot take it from that declaration ([decisions.md](../decisions.md), q43). *Prior art:* Gleam 1.6 infers the variant of a record update and 1.7 changes a type argument in one; Rust's RFC 2528 proposed type-changing struct update; ReScript and TypeScript spread copy by name, which this rule refuses for fields declared apart. Status: **implemented** (`record_update.go`, `Info.Spreads`; `TestSpreadMatchesModel`).
   - Order: the base is evaluated once, first; then the field values, in source order. The result is a copy of the base with the named fields replaced; the base is unchanged. A slice or Map field of the copy is a value of its own: a later write through either record is not seen through the other ([Bindings](#bindings); owner q26, 2026-11-08).
   - Laws: `T{..b, F: x}.F == x`; every other field equals `b`'s; `T{..T{..b, F: x}, G: y} == T{..b, F: x, G: y}` for distinct `F` and `G`; for one field the later update wins.
   - Lowering: a spread from another type is one literal of `T` with a read of the base per copied field, `b := s; T{F: v, G: b.G}`, as hand Go writes it; a base that is a variable or a field path is read in place when no named value runs code first. An update of the same type is a copy of the base and one store per named field, `u := base; u.F = v`, with no allocation; a slice or Map field is copied only where [Bindings](#bindings) 2 says a write could be seen through the other record. *Prior art:* Go has no update expression; its idiom is copy then assign, which the lowering writes. Borgo lowers Rust's `..rest` to a called function literal that evaluates the field values before the base; Ergo evaluates the base first, in source order.
4. A struct must not contain itself by value, directly or through other structs or tuple elements (S108). Recursion behind a union is allowed, because a union value is a reference in the lowered Go. The diagnostic names the cycle's members, one report per group of declarations that form one cycle together, at the group's first name in byte order ("A contains itself by value with B"), and a generic declaration is named only when every instantiation of it is infinite or when it writes the instantiation that closes a cycle (`type P[T] { A T, B P[int] }`), never when it only holds one (`type Box[T] { V T }`). *Prior art:* Swift's `indirect enum` boxes recursion; Go rejects an invalid recursive type.
5. A struct with a resource field is itself a resource ([resources.md](resources.md#what-is-a-resource)).
6. Designed: struct embedding is allowed only in `context` and in interfaces. Value semantics hold: a copy is a snapshot, slice and Map fields included, and move-on-last-use keeps it cheap ([Bindings](#bindings), implemented for slices and Maps).
7. **Included record** (owner q43, 2026-11-09; [grammar.md](grammar.md#declarations) Declarations 4). In a record declaration or a variant declared in place, the member `..R` includes the fields of the record `R` at that position, in `R`'s order, as the record's own fields: `type Visit { ..Owned, S Session }`, `type Kiosk = Suspended{..Owned} | Prompt{..Visit, Left int}`. Status: **implemented** by `internal/sketch/check` (`include.go`) and lowered flat (`TestIncludedRecordFlattens`).
   - `R` is a record with fields declared in this package, possibly an instance (`..Page[T]`). A record of another package, a union, an operation type, a type parameter, a basic or tuple type is S108 at the member, and so is a record with no fields ("drop the member").
   - A field name occurs once after inclusion: two members that give one name, an include and an own field of one name, and one record included twice through two paths (a diamond) are S108 at the later member, also with one type. So one name has one declaration.
   - An inclusion cycle (`type A { ..B }`, `type B { ..A }`, also through a variant) is S108, by rule 4. A record that holds the including record through a field (`type A { X []B }`, `type B { ..A }`) is not a cycle.
   - Each included field keeps its declaration: the field of `R` that declares it, through any depth of includes and in every instance (`check.Field.Origin`). A spread copies a field only from a field of the same declaration ([rule 3](#structs)).
   - The included fields are ordinary fields everywhere: a keyed or positional literal, a field read, a record pattern (`case Prompt{S: s, Left: n}`), equality, text forms, generated values, codecs and construction authority. `R` stays an ordinary record type. `..` in a pattern stays S001.
   - Lowering: the Go struct lists every field flat, in order; there is no Go embedding, so the lowering is unchanged. *Prior art:* ReScript 11's record type spread `type c = {...a, x: int}` copies field declarations and refuses a duplicate label; Go embedding promotes fields and refuses an ambiguous one only where it is used; Elm's extensible records type functions over "any record with these fields".
8. **Layout** (NOSCAN1, 2026-11-12). A record promises no field layout: every field is read and written by its name, literals are keyed in the lowered Go, and codecs, text, equality and patterns walk the declared order. So in a run build the Go struct of a record lists the fields that hold a pointer word (a string, a slice, a Map, a pointer, a function, an interface or union, a record that holds one) and the fields whose layout the lowering does not know first, in declared order, then the pointer-free fields by alignment, largest first (`lower/layout.go`). Go's collector scans a value only up to its last pointer word, so a record with one string and six numbers is scanned for two words, not eight. The order is a function of the declaration. A test build and `layoutLowering=declared` keep the declared order. No Go code outside the program sees a record's struct in v1 ([interop](interop.md) Limits 5). *Prior art:* Rust reorders fields unless `repr(C)`; GHC puts a closure's pointers first; OCaml marks blocks with no pointers; Go keeps declared order.

## Unions

Status: **implemented**: checked by `internal/sketch/check` (check-v1 stage B) and lowered (check-v1 stage C): a union is a sealed Go interface that its variants implement (a union that the flat-union rule admits, and the prelude's `Option`, are a tag and slots instead, and an `Option` of a `go.Ref` the pointer itself: rule 6), and a `match` on it runs (`TestErgoRunUnionOfOneGenericRecord`; [rows.md](rows.md#totality)). A bare-name variant names a record or a union declared in the package: a basic, operation or defined type there is S108 "a union variant is a record declared in this package; Store is an operation type", and a record or a union from another package is S108 at the variant, "a union's variants are records of its package; wrap timeout.Expired: type E = … | Expired{ Cause timeout.Expired }" (196b Q8, a permanent rule: a union's marker is a function of the variant's type, and a type's functions live in its package; [diagnostics.md](diagnostics.md#s108-type-or-declaration-misuse); `TestUnionVariantFromAnotherPackage`). 3. A union has no zero value.
4. A `match` narrows a union value to its variants, nested through record patterns ([rows.md](rows.md#totality)). 6. **Lowering** (flat unions: MU8b, OPT2, OPT3, MSB3). A union of any Ergo package the program reaches, its own, an imported module's or std's (MSB3: the rule is one of shape, and std has no privilege; std is lowered with the program, so a std function that returns a union, such as `tz.Resolve`, pays no box, time's `Month` is a byte, and a std machine's state and signal are flat past the bounds as a program's are), is a Go struct of a tag (the variant's index) and one slot per variant that has fields, each slot that variant's record, where the rule below admits it; any other union is a sealed Go interface with an unexported marker method, and each variant keeps its own struct fields. A flat union that a function returns, a record holds or a slice keeps is a value and never a box on the heap, and a `match` on it switches on the tag. Where the struct fits, the variants' fields share typed slots in place of a slot per variant (U1): the struct holds one slot per field of the widest variant, by Go type, the variants' fields of one Go type share the slots of that type (a basic type by its kind, a non-generic declared type by its declaration, a slice, array or `Map` of such types by its parts, VI1; any other field type has a slot of its own), a constructor writes its fields into their slots and leaves the others zero, and narrowing rebuilds the variant's record from them, so `type Instr = Push{N int} | Jump{To int} | Add{}` is a tag and one `int`; a union whose shared slots miss the bound and whose per-variant slots fit keeps a slot per variant. The reference `-X …/lower.msb3Lowering=off` keeps signals to the bound, every union with an error variant and every std union an interface. ## Defined types

Status: **checked** by `internal/sketch/check` (check-v1 stage B) and **lowered** (check-v1 stage C): a Go defined type over the base type's Go type.

4. ## Tuples

Status: **checked** by `internal/sketch/check` (check-v1 D-B6, 196t).

```go
func DivMod(a, b int) (int, int) { return (a / b, a % b) }

let (q, r) = DivMod(7, 2)
let pair (int, string) = (q, "x")
```

1. A tuple type `(A, B, …)` has two or more elements and is structural: two tuple types are identical when their elements are. A tuple value is `(a, b)`.
2. A tuple is read only through a pattern ([rows.md](rows.md#totality)): `let (a, b) = t`, `for (k, v) in …`, `case (A, _):`. There is no `.0`.
3. A function has one result, which may be a tuple; a call is one value, so `f(g())` passes `g`'s tuple as one argument. `let q, r = e` destructures a tuple result, and a value of a type defined over a tuple through its underlying tuple, as a tuple pattern matches it (check-v1 E6b, C45; `TestDefinedTupleLet`, `TestErgoRunDefinedTuple`). Tuple assignment does not convert its elements. Returning `pair()` from `(Mem, int)` as `(Store, int)` therefore names a repair when `Mem` implements `Store`: `let (m, n) = pair(); return (m, n)`, source on one line, with the call copied byte for byte, that checks in place of the body. There is no repair for a call written over more than one line. Each element of the returned literal takes its expected type. The checker chooses unbound names for the repair.
4. A tuple is comparable when its elements are, and defaultable when they are. It has no operations, so it implements no operation type.
5. *Prior art:* Gleam, ReScript and MoonBit tuples with pattern access; Elixir tuples; Go's several results exist mostly for `(T, error)`, which `fails` replaces.

## Arrays

Status: **implemented**: checked by `internal/sketch/check` and lowered by `internal/sketch/lower` (196y, unit L1; decisions.md 2026-11-02 (c)). A Go `[N]T` in an `import go` binding is this `[N]T` when its elements hold no slice or `Map` (batch 14; [interop](interop.md#type-mapping)).

```go
type Grid { cells [81]int }

func With(g Grid, i int, v int) Grid {
	let mut cells = g.cells // a copy: g is unchanged
	cells[i] = v
	Grid{cells: cells}
}
```

1. **Type.** `[N]T` is a fixed array of `N` elements of type `T`. `N` is an integer literal from 0 to 2147483647, so every Go target's `int` holds it; a name or another expression is S001 "expected \"]\" or an integer length", and a larger literal is S108. Two array types are identical when their lengths and element types are. There is no array of unknown length: `[...]T` is S001 with the habit message ([grammar.md](grammar.md), Go habits). A type may be defined over an array (`type Cells [81]int`).
2. **Literal.** `[N]T{a, b, …}` lists all `N` elements in order (S108 "a literal of [3]int lists all 3 elements, found 2"); an index key is S108. `[N]T{}` is the array of `N` defaults when `T` is defaultable ([Zero values](#zero-values-and-definite-initialisation) 1); else it is S108, so no element is invented. A `let` of an array type with no value takes the same default, and every element that holds a `Map` gets its own empty `Map` (Loops and len 5).
3. **Index.** `a[i]` reads element `i`, an `int`. A constant index outside `0` to `N-1` is S108 "index 3 is out of bounds of [3]int, whose length is 3"; another index is checked when it runs, and one outside the array is a defect, as Go's index panics. A write `a[i] = v` needs `a` rooted at a `let mut` or a borrow, as a slice element write does ([Bindings](#bindings) 1).
4. **Slice.** `a[lo:hi]` (and `a[lo:hi:max]`) is a slice `[]T` of the elements, and a value as every slice is: a later write to `a` is not seen through it, and a write through it is not seen in `a` (Bindings 1). A constant bound past `N` is S108.
5. **Value.** An array is a value, as an `int` and a record are ([Bindings](#bindings) 1): an assignment, an argument, a field, a capture and a value sent to a task each hold their own. `len(a)` is `N`, an `int` ([Loops and len](#loops-and-len) 6), and `for i, x in a` visits the elements in order, the value of `a` at the start of the loop. An array compares with `==` when its element type does, element by element; it is equatable when its element is ([Operators](#operators)).
6. **Lowering.** `[N]T` is Go's `[N]T`, which Go copies as a whole, so an array of elements that hold no slice or `Map` needs no copy. When an element holds one, the value rule copies it as it copies a record's field (Bindings 2), with a generated copy function that copies each element. `==` is Go's when the element is comparable, else a generated function that compares each element. A slice of an array is Go's slice of the array, of a temporary when the array is not addressable (a literal); the value rule copies it where a write could be seen through another binding, as it copies a slice of a slice. A default that holds a `Map` is a loop that builds each element's default, so the Go text stays linear in the type, not in `N`.
7. **Not yet.** An array has no text form (interpolation is S108, as for a slice); a property parameter of an array type is S108 (no generator yet); an error type's field of an array type waits for derived text forms, as a `Map` field does.

*Prior art:* Go's `[N]T` is a value type copied on assignment and compared element by element; Rust's `[T; N]` and Zig's `[N]T` carry the length in the type and check a constant index at compile time; MoonBit's `FixedArray[T]` is a mutable reference, the choice Ergo does not take, as Gleam, ReScript and Elixir have no fixed arrays and use lists or tuples. Every Ergo collection is a value (owner q26), so an array is too.

## Capabilities

Status: **implemented**: checked by `internal/sketch/check` and lowered: a capability call reaches the provider the nearest `with` binds, and a method call on a value of an operation type runs that value's method (check-v1 stages C and D3b; `TestErgoRunE1Witnesses`). The prelude capabilities' method sets are provisional until the prelude services (rule 5).

```go
type Orders {
	Find(id string) Order fails OrderNotFound,
}
```

1. An interface with method signatures declares a capability. Method names in one capability are distinct (S108).
2. **A capability is not a first-class value.** The capability name denotes the provider that the nearest `with` binds. `Orders.Find(id)` calls that provider and charges `Orders` ([rows.md](rows.md#capability-rows)). Any other use of the name as an expression is an error: `Orders.Find` without a call (S108), and passing, returning, storing or capturing `Orders` (S104; README Gap 29).
3. **Capability name against interface type.** The same interface declaration has two roles, told apart by position:
   - in a `needs` clause, a `context` entry, or as the receiver of a method call `Orders.m(…)`, the name is the **capability**: an ambient requirement that only `with` supplies;
   - in a type position (a parameter, result, field or type argument), the name is an ordinary **interface type**. A value of it is a provider value. Calling its method, `o.Find(id)`, runs that provider's method with the method's declared error row and charges no capability. A constructor that returns `Orders` returns such a value.

   This keeps the decision on the Foreign protocol: a capability is an ordinary interface bound by `context`, and only the ambient binding is second-class. The checker implements both roles (README Gap 29), and the lowering runs both. *Prior art:* Effect separates a service's tag, the requirement, from a service value; Scala 3 capture checking treats capabilities apart from their types.
4. A capability method's signature carries its error row. A capability or interface method writes no capability row (S108), because a provider's requirements are captured at construction (README Gap 17). Today go.Foreign and Ambient are captured: a provider whose functions need go.Foreign or Ambient, and nothing else beyond the operation's row, converts to an operation type (an argument, a binding, a return, a context entry), and the converting site is charged what they need (S102 there when its row lacks it: "building Real as Pid, whose operations call Go, requires go.Foreign, which is not in the capability row of function main and no with provides it"; "building Real as Env, whose operations read the host, requires Ambient, …"). Ambient is captured for a provider whose operations call Go's host functions ([interop](interop.md#purity-and-authority), host rows; HOST-ROW). A constraint `[P Pid]` is not a build, so `Real` does not satisfy it. A law case of the test binary is the one other build site that holds `go.Foreign` ([Laws](#laws) 10, owner q277); it holds no Ambient, so a provider that captures Ambient is a skip of the law, with its reason.
5. The prelude capabilities `Console`, `Scheduler` and `Random`, and std `time.Clock`, are ordinary interfaces bound by `context` (the decision on the Foreign protocol). The prelude (`internal/sketch/std/prelude.ergo`) declares its three with the methods the fixtures and the corpus call, provisionally until the prelude services fixes their method sets. `Clock` was a prelude capability whose `Now` returned an `int64` with no unit; it is `time.Clock` with `Now() time.Time` since std-align S2b, because the prelude cannot name a std type ([stdlib.md, time](stdlib.md#time)).
6. An interface is also a generic constraint, with Go's method-set rules.
7. **Generic capabilities** (L4, item 10). An operation type with type parameters is a capability once its type arguments are written and concrete: `needs Store[Job]`, `with context { Store[Job]: jobs }`, and `Store[Job].Put(j)` calls the provider that the nearest `with` binds to that instance. Each instance is its own capability: `Store[Job]` and `Store[Note]` stand in one row and bind to two providers, and a provider of one never discharges the other. The type arguments are written in every position, a call included, so a capability has one name everywhere and two instances are never ambiguous (2026-11-09). A bare `Store` in a row or a context key is S108 "generic capability Store needs type arguments: write Store[…]". `Store[T]` with a type parameter `T` is S108 "a capability's type arguments are concrete types, and Store[T] names a type parameter": the provider is a field of the program's one environment, which has no type parameters. Elsewhere `Store[Job]` is the interface type (rule 3). Lowering: one environment field per instance, of the instance's Go interface type. *Prior art:* Effect keys a service by a tag value, so each instance of a generic service needs its own tag (`Context.GenericTag<Store<Job>>("StoreJob")`); Koka writes an effect's type arguments in its row (`state<int>`); ZIO keys a layer by the instance's type tag. Ergo keys the binding by the instance type, which needs no tag.

## Methods

Status: **implemented**: checked (196m) and lowered: `x.f(…)` calls the function, a Go method on the type where rule 3 allows one (check-v1 stages C to E1; `TestErgoRunE1Witnesses`, `TestErgoRunMethodValues`).

There are no receivers. A package function whose first parameter is a named type declared in the package is a function on that type, and `x.f(y)` calls `f(x, y)` (196m).

1. `x.f(a)` resolves to a field `f` of `x` first, or an operation `f` of an operation-type `x`. Otherwise it resolves to the package function `f`, in the package that declares `x`'s type, whose first parameter's type is `x`'s type: `T`, `*T` or, for a generic `T`, `T[A, B]` whose arguments are distinct type parameters of `f`, which a call on an instance binds. A first parameter written as one of the function's own bracket parameters is that parameter, never a package type of the same name. The call checks the other arguments against `f`'s signature without its first parameter, and its rows are `f`'s written rows. The type may be an operation type (G-ex-e-2): `e.Filter(lines)` calls `func Filter(m Matcher, lines Seq[string])`; such a function gives the type no operation, and it lowers as a plain Go call, since a Go interface has no methods of its own.
2. `x.f` without a call, when `x` has no field `f`, is a *method value* (CV1, owner q265): the function value of `f`'s signature without its first parameter, with `x`'s value bound when the expression is evaluated, as Go's method value, so a later change of `x` does not reach it. Here it differs from its eta twin `func(k) { x.f(k) }`: a literal that does not escape reads `x` when it runs ([Function values](#function-values) 2 and 3), so after `let g = x.f; let h = func(k int) int { x.f(k) }; x = …`, `g` still sees the old `x` and `h` sees the new one. A write through a borrow of `x`, or by a later argument of the same call (`apply(x.f, bump(&x), m)`), is a later change too. So the two agree when no write can follow the take: `x` is a parameter or a `let`, not a `let mut` or a borrow, and there `ergo fix --lint` writes the eta twin as `x.f` (lint `eta-method-value`, CV1-FIX). Its rows are `f`'s. It is S108 "a method value of f …; write the closure func(…) { x.f(…) }" when `f`'s first parameter borrows `x` (`mut T`) or takes it (`own`), when `x` holds a resource (which has one owner), or when `f` has a type parameter that `x`'s type does not bind; an extern on a type (the prelude's `Append`, a Go body) stays call-only (S104), as the extern itself is. The lowering is a Go closure over a copy of `x` taken at the expression, on both paths. When a call passes a pure method value to a known-callback variant, the closure is the plain `func(…) R` (CV1 r2). Written type arguments keep the call: `x.f[int](a)` is the call `x.f(a)` with the bracket parameters of `f` that its first parameter does not bind written in order (`g.pick[string]("x")` for `func pick[T, U](g G[T], u U) U`); `x.f[int]` alone is still S104. When `f` has no such bracket parameter, the brackets are no type arguments: `s.hs[0]()` is the S104 of `s.hs`, which suggests the call `s.hs()[0]`.
3. Several package functions may share a name when their first parameters are distinct named types declared in the package. Such a name is called as `x.f(…)`; a plain call `f(x)` with more than one candidate is S108 "several functions are named f; call it as x.f(…)". One more function of the name may be a plain function, whose first parameter is no type of the package (CONSTRAINTS C3, 2026-11-18): a plain call or reference `f(a, b)` names it, and `x.f(…)` names the function on `x`'s type. So std `cmp` has `Compare[T ordered](a T, b T) int` beside `func Compare[T ordered](_ Natural[T], a T, b T) int`, which makes `Natural` a `cmp.Order`. Go declares a function and a method of one name in one package the same way; the plain function lowers as a Go function and the others as Go methods. Lowering emits them as Go methods on the type, which Go allows. A std record that the runtime declares (a row of the binding table, such as `rpc.Malformed`) takes no Go method, since Go declares a method only in its receiver's package: such a function lowers as a Go function. A first parameter that names a type declared twice (S108) counts as such a type when its type arguments are distinct type parameters of the function and the function is not `main`: which declaration the package keeps depends on their order, so the group's verdict never reads it; two functions whose first parameters name it still share it (check-v1 stage D1 rounds 3 and 4). A function on a type may also share the name of a type of the package, as a Go method may (std json's `func Null(t *text)`, the provider's operation, beside the union case `type Null`; LR3): one such function per type, called as `x.f(…)` only; a second one on the same type, or one that is no function on a type, is S108 "f is already declared as a type in this package".
4. A named type that declares an operation type ([Interface assignability](#interface-assignability) 1) meets it when, for each operation, a function on the type exists (a field of the same name does not hide it: `x.Value` reads the field, and `func Value(c Counter) int` still provides `Value() int`) with the same remaining signature, no wider error row and no extra `needs` (S106, rows.md Context 2). A function with type parameters beyond those its first parameter binds can be called as `x.f(…)`, and it satisfies an operation only when those parameters match the operation's own ([Interface assignability](#interface-assignability) 8, Generic operations); an operation with none is S106 naming the parameter.
5. A first parameter `*T` needs an addressable `x` (S108), as Go's pointer receiver does ([Borrows](#borrows)).
6. An error type may not declare a function named `Error` on itself (S108), because the emitter generates it. An error type's text comes from its fields (fixture `error-method-on-error-type`). When a production row makes the type an error type, the S108 is at the function. When only a test's row does ([Error types](#error-types) 1), the run build gives the type no `Error` method, so the function is valid there, but the test build would lower it beside the generated one: the S108 is reported once, at the first such row in source order, and the function stays clean, so a test never changes the program's verdict.
7. The prelude's functions on slice and Map types, `Append`, `Get`, `Delete` and `Put` ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Slices and Maps), resolve by rule 1 from a value whose type is exactly an unnamed `[]E` or `Map[K, V]`, which binds their bracket parameters as a generic first parameter does; they are in no scope, so a package declares its own `Get` freely, and their bare call is S104 naming the dot form (check-v1 D-D6, D-D8). A defined type over a slice reaches `Append` after assignment ([Assignability](#assignability) clause 2): `let raw []int = xs`, then `raw.Append(x)`; a defined Map uses `let raw Map[string, int] = m`, then `raw.Get(k)`, `raw.Delete(k)` or `raw.Put(k, v)`. `Info.Calls` records such a call, and every call `x.f(…)` of a generic `f`, with every type argument of `f` in its order, the ones `x` binds included, so the lowering writes `F[A, B](x, …)` (D-D8). *Prior art:* MoonBit declares `fn Array::push` and calls it `xs.push(x)`; Nim and D call any function by its first argument (UFCS); go/types records a method value's full instance in `Info.Instances`.
8. A call `x.f(…)` reaches the one function `x`'s type picks, for Go's initialization order, never every function named `f`: an initialization cycle through it names it by its type, `B.m`. *Prior art:* MoonBit resolves `x.f` by `x`'s inferred type in the type's package and allows same-named methods on different types; go/types resolves a selector with LookupFieldOrMethod and orders initialization by the method it resolved.

## Interface assignability

Status: **implemented** (check-v1 stage E1; the declared relation of rule 1, EXC1): rules 1 to 3 and 5 are checked, and every conversion they admit lowers, inside a generic function too, and so does one whose implementing function is itself generic over a method-set constraint (`TestErgoRunE1Witnesses`, `TestErgoRunGenericImplementingFunction`).

```go
type Store { Get() string }
type Mem {} implements Store

func Get(_ Mem) string { return "ok" }
func NewStore() Store  { return Mem{} } // Mem declares Store
```

1. **One relation, and it is written** (EXC1; owner q167, q170). A type `T` implements an operation type `I`, so a value of `T` is assignable to `I` ([Assignability](#assignability) clause 3), exactly when `T`'s declaration names `I` in its `implements` clause ([grammar.md](grammar.md#declarations) 15), at the instance it writes (`implements Codec[int]`), or names an operation type that includes `I` (`..I`, at any depth). Functions that match give nothing: a type that declares nothing implements nothing. A value of an operation type `K` is used as `I` only when `K` includes `I`. Every reader asks this one question: a value in an operation-type position (an argument, a result, an assignment, a field, an element), a context entry and a `with` operand ([rows.md](rows.md#context) Context 2), a method-set constraint ([Generics](#generics) 2), the providers of a member law ([Laws](#laws) 10), and an Ergo value passed as a Go interface (`implements io.Writer`). A use that needs an undeclared relation is S108 at the use (S106 at a context entry), naming the clause to write: "Mem does not declare that it implements Store: write implements Store after Mem's body"; for a type of another package the message names both repairs (the clause in that package, or a record here that holds the value and implements `I`), and for a Go type the wrapping record ([interop.md](interop.md#checking)). Between two Go types Go's own method sets decide. Only the type's own declaration can say it, so a type of another package, a Go-bound type or a std type is wrapped. The clause names operation types, so a name that a package type hides from the prelude ([Scope](#scope) 2) names the prelude's operation type in it when that package type is not an operation type (`type Stream { … } implements Reader` in std json, whose `Reader` is a record; `hidesNoOps`), and the declaring type's own name always does (`type Reader { … } implements Reader`). A sealed std protocol (C28) is declared by no clause: a conversion into it stays its S109. The clause is **checked once, at the type**: for each operation `T` has a function on `T` (or `*T`), and for each such function:
   - the parameter types and the result type are identical to `I`'s;
   - the method is fallible exactly when `I`'s method is;
   - its error row is a subset of `I`'s method's error row;
   - its `needs` row is a subset of `I`'s method's `needs` row.

   This is method-row compatibility: an implementation may fail less and require less, never more. A clause that fails it is S106 at the clause, and a use of the type adds nothing. The prelude's `Closer` is met by the release shape, `Close(x T)` with no result and an empty failure row ([resources.md](resources.md) R1, R2); in a Go binding `Close() error` meets it. `ergo fix [--dry-run] [--go] PATH…` writes the clauses that the old method-set rule admitted. A value that holds a `Task` is not assignable to an operation type that holds none, which would erase its ownership (S108; [runtime.md](runtime.md#tasks) rule 3); a `Task` keeps its own type. *Prior art:* Java, C# and Hylo declare conformance on the type; Rust declares it apart and allows only the trait's or the type's crate; Elixir's `@behaviour` is checked at compile time in the module; ReScript checks a module against a signature where it is declared; Go stays structural and asserts by hand (`var _ io.Closer = T{}`).
2. A union type is not an interface in this sense; it is assignable only by the variant rule (clause 4).
3. Resources keep their rules: assigning a resource to an interface without `Close` is an error (R22), and assigning it to one with `Close` moves it (R23) ([resources.md](resources.md#conversions)).
4. *Prior art:* Go satisfies interfaces implicitly by method set with identical signatures; Effect requires a service implementation's error and requirement types to fit the tag's; Java and Swift let an overriding method throw fewer checked errors, never more.
5. **Lowering.** An operation type is a Go interface. A value of another type converts to it through a generated adapter whose methods call the package functions that implement the operations ([Methods](#methods)), each with the caller's task. Inside a generic function the adapter is generic over the function's type parameters, and a value of a type parameter `T` that a method set constrains converts through `T`'s witness ([Generics](#generics) 5). A method set used as a constraint is satisfied by the same rule 1, with one restriction: an operation implemented on `*T` does not satisfy it (Generics 2).
6. **Provider cells** (owner q121, 2026-11-11; **implemented**, PS3: `check/cells.go`, `lower/cells.go`; `TestProviderCellsAgree`, `TestProviderCellConfinementModel`, `TestProviderCellDiagnostics`). A value of a value provider `P` ([Laws](#laws) 10) whose functions provide every operation of `T`, one or more of them on `*P`, converts to `T` by moving into a *cell*, a new place the operations write. The conversion is admitted only when `T` is sealed (it has an unexported operation, so only a type of its package implements it) and is no Go interface, the conversion is written in that package, and it is not a `with`'s provider (the provider of a `with` is shared by the tasks of its block). Otherwise S108 names the missing condition. A borrow `&p` keeps its own rule.
   - **Move.** The cell holds its own value: the lowering copies the value (deep, as the value rule copies a value entering a `let mut`, [Bindings](#bindings) 2) unless it is fresh or a local dead after the conversion. A write through the cell is never seen through the source, nor the reverse. A `P` that holds a resource keeps R22 and R23 ([resources.md](resources.md#conversions)): it converts only to a `T` with `Close()`, the conversion moves it (a later use of the source is S108), and the cell's release runs once, on the cell's state. The Go form is the operations adapter, `&adapter{v: …}`, one allocation as Go's `&T{…}`. The reference lowering copies at every cell: `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.cellLowering=copy`.
   - **Task confinement.** A *cell type* is a sealed operation type that a type of its package provides every operation of, one or more on `*P`; it is decided from the declarations. A type *holds a cell* when it is a cell type or holds one in a field, element, variant, tuple element or type argument. S108 when an escaping frame ([Function values](#function-values) 2) captures a local whose type holds a cell, when a type argument holds a cell (a generic body, a queue, a `Ref` or a `Task` could carry it to another task), when a package `let`'s type holds a cell, and when a value that holds a cell converts to an operation type that is no cell type, except a cell passed as `encode`'s writer (`encode(v, t)` with `t` a `json.Text`, a Writer) or as `decode`'s reader (`decode[T](r)` with `r` a package's sealed reader, such as std `xml`'s `Cursor`), which lends the cell to the codec for the call, as a borrow argument does: neither keeps its operand (LR3, DREAD; `check/typeops.go` `encodeLend`). A non-escaping frame, a local frame and a `with` block run on the calling task and may use a cell.
   - **Rewrites.** A window of operation calls on an immutable local that a `let` binds by a cell conversion runs on the cell's own value, so the provider's proved laws rewrite it as they rewrite a window on a `P` local, with the same ledger entry ([Laws](#laws) 14). An `encode` whose writer is a cell of a sealed std type whose provider gives every Writer operation (std json's `Text`, provider `text`) is a *cell writer* (LR3, `lower/wiretext.go`): its codec functions take and return the provider's value (`func(env, w text, v T) text`), each Writer event is a call of the provider's function, and each straight run of events is a window that the provider's proved laws rewrite, with unfold by definition ([Laws](#laws) 14), so a record's keys and commas are constant appends. A run carries the comma state an idempotent call leaves into the arms of an `if` and into a nested codec function, which has a variant for that state. The reference is `-X=…lower.wireLowering=writer` (every encode through the Writer interface).
   *Prior art:* Swift keeps a non-`Sendable` value in its isolation domain and refuses its capture by a `@Sendable` closure; Rust's `Rc` and `RefCell` are `!Send`, so `thread::spawn` refuses a closure that captures one; Swift copies a value into an existential's buffer, and Rust's `Box::new(v)` moves `v`. Gleam, Elixir and ReScript have no mutable cell: an Erlang process owns its state and sends copies.
7. **Known providers** (DT4; `internal/sketch/lower/provider.go`, `TestKnownProvidersAgree`). When a call converts a value to an operation-type parameter of its callee at the call itself (`PlayOn(&s, input)` with `s` a `*screen.Screen`), the call goes to a copy of the callee whose parameter has the adapter's Go type, a pointer to a struct, instead of the interface. Each operation call on it is then a static call that Go can inline, and a call that passes the parameter on, at a parameter of the same operation type, goes to that callee's copy for the same adapter. A parameter has copies only when every use of it is an operation call's receiver or such an argument: a store, a `let`, a return or a generic argument keeps the function as written. The copy differs from its function only in that parameter's Go type, so its polls, failures and defects are the function's own. It applies to an adapter with no type parameter and no script or sealed std source. The reference is `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.providerLowering=dynamic`. This is a lowering choice, not a promise. *Prior art:* GCC's and LLVM's devirtualization of a known receiver, the JVM's class-hierarchy analysis and inline caches, and Go's own inliner, which devirtualizes a call on a value whose concrete type it sees; MLton and Rust specialize per implementation. Gleam, Elixir and ReScript dispatch through the host's value.
8. **Generic operations** (ADT-NOPRIV roles.md R1; GENERIC-OP, `TestGenericOperations`). An operation may declare type parameters after its name, `Fold[A](z A, f func(acc A, x T) A) A`, with the kinds and constraints a function's have ([Generics](#generics) 1, 2). A function on a type provides it ([Methods](#methods) 4) when its bracket parameters beyond those its first parameter binds match the operation's, in order, in kind and in constraint, and its remaining signature matches after renaming them (S106 "Maybe.Fold has 2 type parameters beyond its first parameter's, and Foldable.Fold has 1"; "Box.Fold's type parameter A is comparable, and Foldable.Fold's A is unconstrained"). An operation type with a generic operation, directly or through an include, is a **constraint only**: it has no values, so it is no field, parameter, result, `let` or context-entry type and no conversion target (S108 "Foldable has a generic operation, so it is a constraint and has no values; write [M Foldable[int]]"). A call `m.Fold(z, f)` on a value of a type parameter it constrains infers the operation's type arguments as a generic function's are inferred ([Generics](#generics) 6); `m.Fold[int](z, f)` writes them. Any provider meets the rule the same way, a std type too: no name is special.
   - **Lowering.** A function with a type parameter that a constraint-only operation type constrains is lowered only as plain copies, one per instance (Generics 5, MONO1), in the run build and the test build alike; its generic form is never written, and it takes no witness. In a copy an operation call is a direct call of the provider's copy at the receiver's type arguments and the call's own. Go's interfaces and function fields take no type parameters, so no witness struct could hold a generic operation. The instances are finite by the instantiation-cycle rule. *Prior art:* Rust's generic trait methods make a trait not object-safe (no `dyn`) and are monomorphised; Go refuses generic methods; Swift's protocols with generic requirements are dispatched by witness tables, which Go cannot express.

## Error types

Status: **checked**.

1. A type named in any error row is an error type. A row written as the type argument of a failure parameter is such a row: of an error row parameter, or of a type parameter that a function of the type's own package takes as a slot row (`F` of `type Async[T, F]`, which `func Await[T, F](a Async[T, F]) T fails F` fails), so `ui.Async[int, Oops]` makes `Oops` an error type of the body that writes it, and `ui.Async[int, string]` is S104 at `string` (ROW-PARAM). The parameter stays a type parameter, so a slot row keeps its Go type ([rows.md](rows.md#error-rows) Lowering); only the declaring package's functions count, so a type whose only slot use is another package's function holds no failure. A type that an arm of a `catch` tests (`case T`, `case T as e`, `case T{…}`) is named the same way: it is an error type of the arm's own body owner, read before any body is checked as a `fails` row is. So `one(Gone) catch { case Gone: 1 }`, where `func one[F](f F) int fails F`, binds `F` to `Gone` with no `fails Gone` written anywhere (orchestrator ruling, 2026-11-20). The arm guarantees nothing it did not before: its type must still be in the caught expression's row ([rows.md](rows.md#catch) Catch 2), so an arm that names a type the expression cannot fail with is still S108. A type named only by an arm of another owner (a test, a law), or of another package, is not an error type here. It must be a named struct type, of this package or of an imported one such as `timeout.Expired`, or a union that names a row (rule 4); anything else is S104. Inside a package, a struct type is an error type when an error row of that package, or of the package that declares the type, names it; a struct type that no such row names is an ordinary value type. A test's error rows make an error type only inside the tests ([grammar.md](grammar.md#declarations) 11; 196l, check-v1 stage E3a): a struct type that only a test's row names is an ordinary value type in every other body, so the test changes neither their verdicts nor the run build, which gives the type no `Error` method and no text helper; the test build reads the test's rows as well. Another package reads only the rows of the program that declares the type, never its tests. The rule reads the rows of the body's own package, whichever package that is: a type that package `a` declares and only its importer `b` names in a row is a failure in `b`'s bodies, as a type `b` declares would be. The Go type has one shape in the whole program: it implements Go's `error` when a row of any package of the program names it (gap-fail; `TestFailureRaisedByImporter`).
2. An error type is not an ordinary value: returning a value of an error type is a failure ([rows.md](rows.md#error-rows); fixture `error-as-value`, S101), except from a function whose declared result is that error type, or a union that holds it, which returns it as its value ([rows.md](rows.md#error-rows) 4, K1). A union that holds it may have other variants that are no error type, `type Got = Have | Lost`, as long as the function's written row does not declare that error type (Tail results 3; FK3-g1): `func early(n int) Got { if n == 0 { return Lost{Why: "early"} }; Have{V: n} }` returns a `Got`, and so does a catch binding `case Lost as l: return l`. A union that does not hold it, `type Other = Have`, leaves the failure: `return Lost{…}` from `func notHeld(n int) Other` is S101.
3. Error rows are sets of independent struct types, not one declared sum per function. *Prior art:* Gleam returns one declared `Result` error type per function; OCaml polymorphic variants and Koka effect rows are open sets; Ergo's rows are closed sets of nominal types with no open tail in v0.
4. **Named rows** (L2, decision O12). A union whose variants are error types names a row: `type Fail = Bad | Oops` lets a row write `fails Fail`, which means `fails Bad | Oops`, since a row is a set and the union names the set. The union may stand anywhere a row element may: a signature, a function type, a row argument (`run[Fail](f)`), and beside other elements (`fails Fail | Other`); the row is the union of its elements. A union of this package names a row, and naming it in any row makes its variants error types, as a row that listed them would (rule 1). A union of another package, std's included, names a row only when each of its variants is an error type of that package (S104 otherwise, naming the first variant that is not), so the prelude's `Option` is no row, and std's `flag.Failure` names the seven failures of `flag`. A union's variants are records of its own package ([Unions](#unions) 1), so a named row never gathers another package's failures; such a row is spelled. A `catch` arm may test the union and bind it ([rows.md](rows.md#catch) 9). **A named row is its row** (NAMED-ROWS NR1, owner q271, 2026-11-20): the union and the row value of its variants are one type, so with `type LookFail = NotFound | Busy`, `func(e LookFail) int` fits where `func(e NotFound | Busy) int` is wanted, a row parameter that meets `LookFail` binds to `NotFound | Busy` ([Generics](#generics) 8), a value crosses between the name and a caught row value with no conversion, and two named rows of one set are one type. A `match` over the name is the match over its variants, exhaustive with the same diagnostics. The rule reads the error types of the program's bodies: a union whose variants only a test's or a law's row names is no row there. **Lowering:** the row value's form, Go's `error` (`type LookFail = error`), where it was a sealed interface; a test of the name is a test of each variant, since Go's `error` holds every failure (lower `namedrow.go`; `check.TestNamedRowChecksAsItsRow` and `lower.TestNamedRowLowersAsItsRow`, seeded properties against the program with each use spelled as its set). A catch of the row whole (`case Fail as e`) binds the error itself, with no type switch when it takes every failure of the call. *Prior art:* Effect writes `type E = A | B` and uses it as `Effect<A, E>`; OCaml abbreviates a polymorphic variant row with a type; Koka has effect aliases.

## Operators

Status: **implemented**: checked (196u) and lowered to Go's operators, so every operator of rules 1 to 4 runs (check-v1 stages C to E1; `TestErgoRunOperators`). The ordering constraint is the prelude's type set `ordered`, an order on a type is a `cmp.Order[T]` provider passed to the call, as `slices.SortBy(xs, ByPriority)` ([stdlib](stdlib.md#slices-maps-and-cmp) 11), and `duration` arithmetic beyond rule 4 is duration literals's.

1. Go's operators on Go's operand types, with exact constant arithmetic (an overflow of the typed result is S108): arithmetic on numeric types, `+` on strings, ordering on numbers and strings, `==` and `!=` on equatable types. Two predicates are kept apart (eq-structural, 2026-11-08, decided by principle: 196d "equality is generated"). *Comparable* is Go's comparability (structs whose fields are comparable included; README Gap 26), and a `comparable` constraint and a Map key read it: a record or tuple compares when its fields do, a union only when every variant does, and a row value (`case err:`) and an operation type's value never do, because Go would compare them as interfaces and panic on a variant that does not compare (stage C round 2 review M1, M2). *Equatable* is what `==` and `!=` read: every comparable type, and also a slice of an equatable element, a Map whose values are equatable, and a record, tuple or union whose fields, elements or variants are equatable. Their equality is structural: two slices are equal when their lengths are and their elements are, in order (an empty slice is one value: Ergo has no nil); two Maps when they hold the same keys with equal values; two records or tuples field by field; two union values when they have the same variant and its values are equal. A function, a row value and an operation type's value are not equatable. So `type Value = Leaf{N int} | Branch{Items []Value}` takes `a == b`, while `Map[Value, int]` and `eq[T comparable](a, b)` at `Value` stay S108. The lowering keeps Go's `==` for a comparable type and emits one equality function per other type, element by element, a recursive type's calling itself (lower `equal.go`; `TestEqualStructuralAgrees`). *Prior art:* Rust and MoonBit derive `Eq` per type (this lowering); Gleam compares by structure (on JavaScript a generated `isEqual` walk), ReScript emits `caml_equal`, Elixir compares terms; Go compares only comparable types and leaves slices to `slices.Equal`; `&&`, `||` and `!` on `bool`, shifts on integers. S108 otherwise. A comparison is `bool`.
2. **One type per operator** (196u rule 4). Both operands of a binary operator have one type, and no operand converts by itself: `a + b` with `a int32` and `b int64` is S108 "mismatched types int32 and int64; write int64(a)". A literal takes the other operand's type (`x + 1` with `x int8` adds two `int8`s). Two literals each take the expected type, else their defaults, so `let d = 1 + 2.5` is S108 "mismatched types int and float64; write 1.0 + 2.5". *Prior art:* Rust's rule; Gleam and OCaml separate float operators.
3. **Shifts and conversions** (spec D-A3). A shift's left literal takes the expected type when that is an integer type, else `int`; any other expected type is S108 "the left operand of a shift is an integer, and float64 is expected here; write int(1) << n, then convert the result". The count is any integer type. A conversion `T(x)` gives its operand `x` no expected type, a literal or any other form except a tuple `(a, b)` and a composite literal without a type, which have no type of their own and take `T` (`T0((A, B))` builds the tuple type `T0` is defined over): `x` is typed on its own, then converted, so `float64(1 << n)` converts an `int` shift (in Go it is invalid, a known trap) and `int64(if n < 0 { -n } else { n })` converts the `int` that the `if` gives, as `let v = …; int64(v)` does (K2; `TestConversionAgreesWithLet`). *Prior art:* Rust's `as` never types its operand from the target; Gleam and MoonBit shift through library functions on one integer type; Zig requires a fixed-width left operand unless the count is comptime-known.
4. `duration` takes `+`, `-`, ordering and `==` between durations; an integer literal is never a `duration` (S108). Its other arithmetic is duration literals's.
5. **Float arithmetic rounds each operation** (corpus-wave HP4, on Q5's assumption: a float result is the same on every host). Every `+`, `-`, `*` and `/` of `float32` or `float64` values (and of types defined over them) rounds to its type, as IEEE 754 does each operation; no host fuses a product and a sum into one multiply-add that rounds once. Go allows that fusion (arm64, ppc64, s390x and riscv64 do it, and amd64 at `GOAMD64=v3` and above, across statements too), so the lowering writes every product of floats that is not a constant under an explicit conversion to its type, `T(a * b)`, which Go rounds, and `x *= y` as `x = T(x * y)`, on the text path and the IR path alike (lower `expr.go`, `floatLowering`, and `ir_order.go` `rounded`; `TestFloatProductsRound`, which checks that form in the lowered Go with go/types, and `TestIRFloatProductsRound` in the IR file, as the form is the promise). So a float result and a law verdict over floats do not change with the build's CPU level ([tooling](../tooling.md#platforms)). The conversion costs no instruction: gc lowers it to a rounding no-op that only stops the multiply-add rule. A fused multiply-add is asked for by name: std `math.FMA(x, y, z)` is x*y + z rounded once, on every host (laws `FMARoundsOnce`, `FMAWithinTheUnfusedError`). The reference lowering, Go's own form, is `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.floatLowering=fuse`, to count the cost on a host that fuses. Complex products are not covered: Go expands them into float operations it may fuse (a gap). *Prior art:* Java's `strictfp` (the default since Java 17) and WebAssembly round every operation; Rust and Swift never contract without an explicit `mul_add`/`fma`; C allows contraction unless `#pragma STDC FP_CONTRACT OFF`; Gleam and Elixir run on hosts (the BEAM, JavaScript) that do not fuse; ReScript inherits JavaScript's rounded doubles.
3. `&&` and `||` short-circuit (README Gap 10). `comparable` is a constraint; the ordering constraint is the prelude's type set `ordered`, and an order on a type is a `cmp.Order[T]` provider passed to the call, as `slices.SortBy(xs, ByPriority)` ([stdlib](stdlib.md#slices-maps-and-cmp) 11).

## Conversions

Status: **checked** by `internal/sketch/check` (check-v1 D-B7); rule 4 is **implemented** (S-conv): `runtime/v1.TestFloatToIntegerMatchesModel`, `lower.TestFloatConversionIsPortable`.

1. `T(x)` converts between numeric types by Go's rules (an integer or float to an integer or float, a complex to a complex, and a numeric constant to any numeric type that represents it), except that a float converts to an integer by rule 4, between `duration` and `int64`, and between a defined type and the type it is defined over, in both directions. Every assignment that makes no implicit conversion ([Assignability](#assignability) clauses 1, 2 and 5) is a conversion too, so a value converts to its own type, as go/types `convertibleTo` starts from `assignableTo`.
2. Nothing else converts (S108): not two defined types over one type (one hop is visible: `int(c)` of a `Celsius` over `float64` is S108 "convert through the type it is defined over: int(float64(c))"; a base with no name has none to call, so `Other(x)` of an `Ints` over `[]int` is S108 "go through the type it is defined over: let raw []int = x; then Other(raw)", under a name not bound there; each text checks when written back), not two records, not an integer to `string` (S108 "an integer does not convert to string; write \"\\(n)\" for its decimal text"), not a variant to its union or a value to an operation type (assignment does those: `let u Payment = p`).
3. *Principle:* nominal types, one visible hop. *Prior art:* Gleam and ReScript convert only through functions (`int.to_float`); Elixir uses functions; MoonBit uses `to_int64()` style methods; Go converts between any types with one underlying type, and `string(65)` is a vet warning.
4. **A float to an integer saturates** (S-conv, orchestrator decision 2026-11-11, prior art Rust 1.45). `T(x)` of a `float32` or `float64` value `x` and an integer type `T` (every width, signed and unsigned, `byte`, `rune` and `uintptr` included) truncates `x` toward zero; a result past `T`'s bounds is the bound on its side, so `+Inf` gives `T`'s maximum and `-Inf` its minimum; NaN gives 0. The rule is the same on every host: Go leaves a non-constant conversion of a value that `T` cannot hold to the implementation (linux/amd64 gives `math.MinInt64`, arm64 saturates), so `int64(1e19)` would be negative on one host and the maximum on another, and a large wait would turn negative. A constant converts at check time, exactly: `int64(2.0)` is `2`, and a constant that `T` cannot hold, or that has a fraction (`int(2.5)`), stays S108. A caller who must know that the value fits uses the checked form for `T`, one per integer type (`math.ToInt`, `math.ToInt8` … `math.ToUintptr`), which fails `math.OutOfRange{Value}` for NaN, an infinity or a value out of range ([stdlib.md](stdlib.md#math-and-bits) 5). **Lowering:** a call of the `runtime/v1` function for `T` (`v1.FloatToInt64(x)`; a `float32` widens to `float64` first, exactly): for `int64`, one Go conversion guarded by one compare (below -2^63 Go's conversion already gives the minimum on both supported platforms, linux/amd64 and darwin/arm64, so a lower guard would be code no input tells apart); for `uint64`, one conversion guarded by two; for every narrower width, one form, the `int64` result clamped to the width's bounds with Go's `min` and `max`. Each is within Go's inlining budget, so the call inlines and a constant argument folds (`TestFloatConversionInlines`). `TestFloatConversionIsPortable` type-checks generated conversions to every integer type with go/types under the sizes of amd64 and arm64 and finds no Go conversion of a float to an integer in the lowered Go; `TestFloatToIntegerMatchesModel` holds each function to the rule on exact numbers (`math/big`) over NaN, the infinities, both zeros, subnormals, every width's bounds and the floats next to them. The check-time evaluator, when it takes this conversion, calls the same `runtime/v1` functions, so a law decided at check time and its native run agree; until then it refuses the conversion as unsupported. Integer arithmetic keeps [Signed-64 wrap](../../GLOSSARY.md); the two rules are separate. *Prior art:* Rust's `as` saturates and sends NaN to 0 since 1.45, for this reason (it was undefined behaviour in LLVM before); Java's `(int)` and `(long)` casts and WebAssembly's `trunc_sat` instructions are the same rule; C and C++ leave it undefined; Go leaves it to the implementation. Gleam's `float.truncate` on the BEAM makes a bignum and on JavaScript is `Math.trunc` into a float; ReScript's `Float.toInt` is JavaScript's `\|0`, which wraps modulo 2^32; Elixir's `trunc/1` makes a bignum. Ergo has fixed-width integers, so it takes Rust's rule, not a bignum.

## Function values

Status: rule 1 is **checked**: a function value is assignable to a function type with identical parameters and results and rows that are subsets of the type's, when one of the two types has no name ([Assignability](#assignability) clause 5; S108 otherwise). Rule 2 is **implemented** (check-v1 stage E2, the minimal 196e rule, `check/escaping.go`); its lend of a non-escaping value to a task that the call consumes is **designed, not yet implemented**. Its local frames and rule 3 for `let mut` captures are **implemented** (C2, owner q60, 2026-11-09: `check/escaping.go`, lowered by `lower/closures.go`; `TestCaptureRuleModel`, `TestCaptureLoweringAgrees`); rule 3's captured resource is [resources.md](resources.md#closures)'s. Rule 2's clause for a body in Go is **reviewed and tested** (ESC1, lang audit B F1): `std.ArgClauses` lists every function and resource parameter of a std declaration whose body is Go, with its clause and the body fact (`TestExternArgumentClauses`), and `TestStdCallbackClausesRace` runs generated callbacks through each under Go's race detector. Rule 4 is rule 2's `escaping` (ESC1). Rule 5 is **designed, not yet implemented**.

1. A function type carries its parameters, result, error row and `needs` row. It carries requirements only, never purity ([rows.md](rows.md#footprints)).
2. A parameter whose type is written as a function type is non-escaping unless the parameter is written `own`: `f own func(…)` (q168; `escaping func(…)` is S108 naming it, [grammar](grammar.md) Declarations 13). The word states what the callee does with the argument, one rule for every callee, std included (ESC1, 2026-11-11). A **non-escaping** argument runs only on the calling task, before the call returns, one run at a time, and no one keeps it. A registered exit action runs in the caller's frame before that frame returns (`scope.OnExit`). **`escaping`** permits everything else: keeping it, running it after return, or running it on another task (`tasks.Transform`, `task.Go`, `timeout.After`, an actor's `sink`). That is the meaning of **`own`** on a function value. Joining the task does not make its resource operations safe on that task: a caller's `tasks.Set` cannot run there. The checker holds an Ergo body to the clause; a body in Go is held to it by review and test (Status). Bound Go callbacks default to escaping, and only the reasoned per-function table narrows them ([interop.md](interop.md#callbacks)). A function type anywhere else (a field, a result, an element, a type argument, a defined type's base, a local's written type) is escaping, and `own` is a parameter's word only; a named function type is escaping. A `let` that binds one name from a non-escaping value is non-escaping too. Every use of a non-escaping local is one of: the callee of a call; an argument whose parameter is non-escaping; the value of such a `let`; the target of an assignment, or its value when the target is a non-escaping local declared in the value's frame or one nested in it. Every other use, such as a field value, a return or block result, an element, a conversion, or an argument of an escaping or generic parameter, is S108 at the use. A capture is a use too: every frame between the local's declaration and the use must be non-escaping. A function literal is a non-escaping frame when it is the callee of a call or an argument of a non-escaping parameter; a trailing block is one when its parameter is non-escaping, and a `with` block runs in place. Every other literal or block is an escaping frame. `func(g func())` and `func(g own func())` are distinct types, so a function value cannot launder a non-escaping argument through a parameter that keeps it. *Prior art:* Swift non-escaping closures by default with `@escaping`, and its `consuming` parameter modifier, one word before the type for a kept value; Kotlin inline lambdas and `crossinline`; Effekt second-class blocks; Gleam, Elixir, ReScript, MoonBit and Go have no marker.
   A **local frame** is a function literal that a `let` binds to one immutable local that only runs in place: each use of the local is the callee of a call or an argument of a non-escaping parameter, and no escaping frame lies between the `let` and the use. It is a non-escaping frame, so `let use = func() { lines = lines.Append(x) }` called twice writes `lines` in place (owner, 2026-11-10). Every other literal a `let` binds is an escaping frame. *Prior art:* Swift's local functions may capture an `inout` parameter when they are only called; Kotlin's local functions capture by reference; Go's escape analysis keeps a closure that is only called on the stack.
3. **Captures of a `let mut`** (owner q60, 2026-11-09: "escaping let mut capture allowed only when no write follows"). An escaping frame may capture a `let mut` of an enclosing frame only when no known write to it follows the capture in either frame: the escaping frame, and every frame inside it, writes it nowhere (S108 at the write); and outside it, every write starts before it and shares with it no loop, for-in or frame inside the local's scope, which may run the write again (S108 at the write). A write is an assignment rooted at the local, an explicit borrow `&x` of a place rooted at it, or an implicit borrow of a dot call whose function takes `*T`. A write in a local frame runs where the frame is called. A known borrow holder writes every root it may alias at each use, independently of holder mutability and escape classification. These facts follow local value flow through bindings, assignments, tuples and value blocks. An escaping frame that captures a value whose type holds a borrow is refused (Borrows 1). The rule is source order, not reachability: a known write in the other arm of an `if` after the literal is refused too.
   **Value capture is an optimization, not the default for an unknown alias.** It requires a positive proof that no alias of the captured local can exist at the capture: its address is never taken, or every borrow provably ends before the capture. Otherwise the lowering uses Go's reference capture, or the existing diagnostic when a rule forbids the program. In particular, a borrow passed to any call, generic or not, may travel in its result, a closure or an out parameter; lack of a known local alias is not proof of no alias. The current sufficient proof is conservative: only locals whose address is never taken anywhere in their declaration, explicitly or by an implicit borrowed receiver, use value capture. It does not attempt a new borrow-lifetime proof. For these locals, the lowering copies into a Go variable when it makes the literal, and default and reference lowering give the same result.
   The reference lowering is selected with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.captureLowering=reference`. `TestCaptureRuleModel` checks diagnostics and the positive proof, and reports fast/reference capture counts on examples (no timing); `TestCaptureLoweringAgrees` runs admitted generated programs, including call-returned aliases, under both lowerings. A non-escaping block or local frame may assign its captures. State that an escaping literal keeps across its calls lives in a `sync.Ref` ([stdlib.md](stdlib.md#sync-and-stm)). A captured resource follows [resources.md](resources.md#closures). *Prior art:* Java captures effectively final locals; Kotlin boxes a captured `var`; Swift captures by reference and checks exclusivity at run time; Rust carries a borrow's lifetime through a generic type and refuses conflicting captures. Gleam, Elixir and ReScript have immutable locals; their value captures are not evidence that an unknown mutable alias is safe to copy.
   Borrow legality and alias tracking are independent of holder mutability: a `let mut` holder is refused by Borrows 1 just as an immutable holder is. Every holder use records the roots it may write, including uses in escaping frames; the root's own frame determines whether that write crosses a capture boundary.
4. **Concurrent parameters.** A function parameter that the callee runs on another task while another run or the caller may run is `own` (rule 2); no separate clause marks it (ESC1, 2026-11-11, which replaces the inferred "concurrent" fact designed here). A block or literal passed to it may not assign captured locals (rule 3), so `tasks.Transform(xs, 4, func(x int) int { n = n + 1; x })` is S108 at the write. *Prior art:* Swift marks `@Sendable` and `@escaping` apart and checks both at the closure; Rust needs `Send + 'static` for `thread::spawn` and `Send` with a scope lifetime for `thread::scope`. Ergo keeps one clause: a callback that may run at once with another run is treated as one that may outlive the call, which costs a scoped parallel map its in-place captures and keeps the signature Go-simple.
5. **Replayable parameters.** A transaction body ([stdlib.md](stdlib.md#sync-and-stm)) may not assign captured locals, use channels or consume a resource, and its footprint holds only `sync.Tx`.
6. **An entry's send** (STD-NOPRIV NP3b; [runtime.md](runtime.md#machines-and-actors) 12 and 14). `entry func(e E)` is the type of the send that the runner gives a machine's work: `machines.Work`'s `Start` takes `send entry func(e E)`, and `actor.Child` and `actor.ChildIn` take one, so the capability to start a child of an entry is a type that std declares and any function may take. `entry` is part of the type's identity, so `func(s entry func(e E))` and `func(s func(e E))` are distinct. A value of an `entry` type is assignable to the plain function type of the same shape, but no other value is assignable to an `entry` type (S108 "only an entry's send is one"). Only a parameter has the type: the runner's call of `Start` gives the value, a parameter written `entry` passes it on, and a local bound to it keeps it. `entry func(…)` written anywhere but a parameter's type is S108 at the word. It is non-escaping, as every parameter written as a function type is (rule 2), so a send never outlives the call that got it. It lowers to the plain Go function type. *Prior art:* effect-machine gives the spawn capability in a `.spawn` handler's context argument, typed by TypeScript; XState's `spawnChild` is an action creator that is only legal in an action, checked at run time; Rust's scoped threads give a `Scope` handle only inside `thread::scope`, whose lifetime keeps it from escaping. Gleam, Elixir and ReScript leave it to the program.

## Call sites

Status: **implemented** (item 13, unit L3): `check/call.go` (`siteless`), `lower/calls.go` (`siteValue`); property `TestCallSitesAgree` (lower), row `TestCallSiteDiagnostics` (check).

1. `CallSite { File string, Line int, Column int, Pkg int, Id int }` is a prelude record: a position in Ergo source. `File` is the path the program's defects name for that source file, `Line` and `Column` count from 1, and `Column` counts bytes. `Pkg` identifies the package and `Id` identifies the position within it.
2. **The hidden parameter.** A call may leave out an argument for its callee's final parameter when that parameter's declared type is `CallSite`. The compiler then passes the site of the call: the position where the call expression starts, as a defect names it. One rule holds for every callee: a declared function, a method, a dot call, an operation of an operation type or a capability, a function literal and a function value. A function type keeps the parameter: `func(n int, at CallSite)` is the type of such a function, and a value of it is called with or without the site.
3. **Forwarding.** A call that writes the argument passes it as written. So a helper hands its own caller's site on, as Rust's `#[track_caller]` chains: `func expect(ok bool, at CallSite) { … report(at) }`. Nothing is passed on without being written: a call inside a function with a `CallSite` parameter that leaves the site out passes its own position.
4. Only the final parameter is hidden, and only when its declared type is `CallSite` itself: a type parameter instantiated with `CallSite` is an ordinary parameter, and a call with one argument too few for any other function is S108 ("not enough arguments"). A trailing block is the final written argument, so with the site left out it fills the parameter before the `CallSite`.
5. Passing a site leaves a call pure. The compiler passes one record literal with `Pkg` read from a variable that assembly initializes and the program never writes. No stack walk is needed.
6. **Site identity.** The compiler numbers packages from 1, by final path element, then import path, then embedded before sourced if both have the same path. Within each package, it numbers the positions where calls start in file path, line and column order, from 1. Compiler-passed sites share `(Pkg, Id)` exactly when they share a source position: `f(x)(y)` has two calls that start at one position. Neither field is 0. A written `CallSite` keeps the fields it writes. Use 0 in both fields for a site with no compiler identity; a written positive pair names the site of that pair. A library may key by the pair and use the whole record for a site with no compiler identity. An edit can renumber calls in the edited package. Changing the set of packages can renumber `Pkg` without changing any package's `Id` values or embedding the new `Pkg` in its lowered code.

*Prior art:* Swift's `#fileID` and `#line` as default arguments (the caller's position, written at the caller); Rust's `#[track_caller]` and `Location::caller()` (a hidden argument, chained through annotated functions); Kotlin's Compose positional keys (a call site's identity, for the `ui` hooks of item 14); MoonBit's `#callsite` attribute (autofill of a source location argument). Go has `runtime.Caller`, a run-time stack walk. Gleam, Elixir and ReScript have no call-site parameter; Elixir's `__CALLER__` is a macro's compile-time environment, the closest form. Ergo takes Swift's shape (the argument is ordinary, written or supplied) with no attribute, since the type alone names it, as the std externs' hidden `Site` argument is named by its Go type ([stdlib.md](stdlib.md), Hidden arguments).

## Borrows

Status: placement (rule 1, first sentence) is **checked**: `*T` outside a parameter or receiver type is S108; rule 5 is checked (check-v1 stage D3b). Rule 1's "captured by an escaping frame" and rule 2 are **checked** (C2: `check/escaping.go`, `check/borrows.go`; `TestBorrowOverlapModel`). Rules 6 and 7 are **checked** (`check/borrowconv.go`; `TestBorrowConvModel`). Rule 8 is **checked** (`check/mappedtext.go`; `TestMappedTextModel`, `TestMappedTextRows`). The rest is **designed, not yet implemented**.

1. A borrow is written `mut T`, the write-in-place mode before the type ([grammar](grammar.md#declarations) Declarations 18; MODES-1, q169). `*T` is Go's pointer, written only in a Go binding, where it is the same borrow type; elsewhere it is S108 naming `mut` (MODES-2), and `ergo fix` writes `mut T`. A borrow appears only on parameters and receivers. A borrow is never nil, stored, returned, sent or captured by `go`. A call lends with `&x` or a dot call, and a `mut` parameter is passed on the same way: `&x` of a `mut` parameter `x` is the borrow `x` holds, of type `mut T`, not a borrow of the parameter (MODES-3; `Info.Relends`, which every lowering reads; `TestBorrowOverlapModel`, whose relay passes its parameters on), so `func twice[T](x mut T, f func(v mut T)) { f(&x); f(&x) }` stands. Passing `x` itself stays legal. `&x` of a read parameter is still refused (D-D1).
   An escaping frame that captures a borrow is S108 at the use: "p is a borrow (*T), and this function literal or block may outlive the call that lent it; …".
2. Two mutable borrows into one value must not overlap. The borrows of a call are each `&x`, the implicit borrow of a dot call's receiver, and a borrow passed on. A place is a root and a path of fields and indexes; two places overlap when they have one root and one path is a prefix of the other step by step, where two fields are one step when they have one name and two indexes when they are one constant or one binding. Two different constants or two different fields keep the places apart. With constant indexes the checker decides; with dynamic indexes it needs a dominating guard or it rejects the call: the call is in the body of `if a != b` (a conjunct of its condition), in the else of `if a == b`, or after `if a == b { … }` whose body ends in `return`, `break` or `continue`, with each index a constant or a field path of an immutable binding read through no borrow. Otherwise S108 at the second borrow: "xs[0] and xs[0] are borrows of one place; …" or "xs[i] and xs[j] may be borrows of one place, since i may equal j; guard the call with if i != j, …". The lowering emits no run-time check. *Prior art:* Swift's law of exclusivity, static where it can and at run time otherwise; Rust refuses two `&mut` into one slice and offers `split_at_mut` and `get_many_mut`, which check the indexes at run time.
3. There are no pointer fields and no reference fields. Linked structures use recursive values behind unions, index arenas or `sync.Ref`. This is a loss against Go. *Prior art:* Rust keeps both reference fields, at the cost of lifetime parameters on the struct, and owned pointer fields (`Box`, `Rc`); Ergo gives up reference fields so that no signature needs a lifetime, and replaces written owned pointers with compiler-boxed recursion behind unions; Swift value types and Hylo's mutable value semantics make a similar trade.
4. Resources are lent by passing them as arguments ([resources.md](resources.md#lending)). A borrow and a lend obey the same no-escape rule.
5. An operation type is already a reference: its Go form is an interface or a runtime pointer. An operation called through a borrow of an operation type, `p.Close()` with `p *queue.Queue[int]`, is S108 "an operation type is already a reference; call it on the value" at the receiver, for a std operation type and the program's own alike; call it on the value, `q.Close()` (checked, check-v1 stage D3b). *Prior art:* Go calls a method of an interface only on the interface value, never through `*I`; Gleam, Elixir and ReScript have no pointer to a module's abstract type.
6. A value converted from a borrow keeps the borrow's lifetime (checked, `check/borrowconv.go`; `TestBorrowConvModel`). A `*T` whose functions provide an operation type's operations converts to it, and the value still points at the lender's place, so the conversion stands only as the value of a local `let` of one name, whose local then holds the borrow, or as a provider in the context of a `with`, which installs it for its block only. A local that holds a borrow stands only where its borrow may: as the receiver of an operation call, `c.Bump()`, as a one-name `let`'s value, as a provider in a `with`'s context, and in a frame that cannot outlive the call. Everywhere else, the conversion or the use is S108 naming the borrow, "t is a borrow (*T), and as Counter it keeps the borrow's lifetime: …" or "c holds a borrow (*T) as Counter, …": a return or tail, an argument (a parameter of an operation type may keep its value), a field, an element, an `Option` or union payload, a generic instantiation, an assignment, an `if` or `match` arm's value, a context value or local context, a capture by an escaping frame or a `task.Go` block, and a conversion again. The rule is an allow-list over the parent, so a position the checker gains later is refused until it is listed. A conversion into a Go interface ([interop](interop.md)) is a conversion too and obeys this rule, with one addition: at an argument of a Go call, the Go argument rule judges the borrow (a reviewed lent argument, such as `io.WriteString`'s writer, takes it for the call only; any other is S108 "b is a borrow, and NewWriter may keep it; …"). A local that holds a borrow is no Go argument: pass the borrow itself. *Prior art:* Rust gives `&'a mut T as &'a mut dyn Trait` the borrow's lifetime, so the trait object cannot outlive it; Swift's non-escapable values (`~Escapable`) stay non-escapable in an existential, and an `inout` parameter cannot be captured by an escaping closure; Gleam, Elixir and ReScript have no borrows; Go's interface conversion of a pointer moves it to the heap and is always legal.
7. A type parameter binds no borrow (q169, q172; MODES-4 deleted the mark `[T lent]` of q137 EX3 and the rule that checked a body against it). A call that binds a type parameter to a type that holds a borrow is S108 at the call, whatever the body does: "hold cannot take a borrow as its T (mut Tally): a type parameter binds no borrow; to write through the argument, declare the parameter x mut T and pass &x". A generic function that writes through its argument says so in its mode, `func bump[T Counter](x mut T) int { x.Bump() }`, and the caller lends `&t` to that parameter ([Generics](#generics) 2); inside the body `x` is a borrow like any other, and a value of `T` is a plain value. A literal of a generic type built over a borrow, `Box{V: t}`, is S108, since a record never holds a borrow (rule 1). A function type that takes a borrow holds none, so `later(func(v mut Tally) int { … })` stands. `[T lent]` and `[T lent C]` are S108 "lent is gone: …", and `ergo fix` writes `[T C]` with each parameter of type `T` written `x mut T` (`[T]`, read, for a bare `[T lent]`, whose `T` has no operation to write through) (checked, `check/borrowconv.go`, `check/decl.go`; `TestBorrowConvModel`, `TestModeDeclarations`, `fix.TestMutDropsLent`). *Prior art:* Swift cannot pass an `inout` as a generic `T`, and a generic function that writes takes `inout T`, as `x mut T` does here; Rust carries the lifetime in `T = &'a mut Tally` instead; Gleam, Elixir and ReScript have no borrows.
8. A mapped text is a borrow of its Mapped (checked, `check/mappedtext.go`; `TestMappedTextModel`, `TestMappedTextRows`; wf10 MAPPED). `fs.Text` is the text of an `fs.Mapped`, a file mapped read-only into memory (`fs.MapFile`) or a text held in memory (`fs.MapText`); its Go form is a `string` that points into the mapping, and the Mapped's `Close` unmaps it, so a text read after `Close` would read unmapped memory. Three parts, with no lifetime written:
   - **Placement.** `fs.Text` is written only as a parameter's type (std `fs` declares `Mapped.Text`'s result): as a result, a field, an element, a type argument or a `let`'s type it is S108 "fs.Text is a borrow of its Mapped and stands only as a parameter's type, …".
   - **Positions.** A value of `fs.Text` stands only as the value of a `let` of one name that is not `mut`, an argument of a parameter of type `fs.Text`, the operand of an index, a slice or `len`, an operand of a comparison, or the range of a `for`; a slice of a text is a text. It is never captured by a frame that may outlive the call or run on another task, except a callback whose callee ends every run of it before it returns (reviewed in runtime/v1 `EndsRunsBeforeReturn`: `tasks.Transform`'s `f`), where the runs read the read-only text during the call only. No conversion makes a string of a text or a text of a string, and an interpolation and `+` are refused, since their Go forms may alias the mapping; `fs.Clone(t)` copies a text into a string that outlives it. Every other place is S108 "t is a mapped text (fs.Text), a borrow of its Mapped: it stands only as …". The rule is an allow-list over the parent, as rule 6 is.
   - **Lifetime.** Every use of a text is a use of its Mapped's owner, in the resource flow ([resources.md](resources.md)): `let t = m.Text()` and `let u = t[a:b]` make `t` and `u` texts of `m`, so a use of either after `m` is closed or handed off is S108 "t is a text of m, which was handed off at …" (or "may have been … on one path"). A call passed a text of `m` that takes `m` is R17's lend and hand-off in one call; a local closure that captures a text holds a lend of `m` (R31), so `m` is not closed while it may still run. A text is read only from a Mapped that a `let` or a parameter holds: `m.Text()` with `m` a `let mut` or a borrow is S108 (an assignment would release the Mapped and keep the text), and `let t = f().Text()` is S108 (the Mapped is a temporary its statement releases).

   So no text outlives its Mapped's `Close`. A fault on a mapped page (another process truncated the file) is a defect of the reading task that names the file, never a crash ([stdlib.md](stdlib.md), fs note 4). *Prior art:* Rust's memmap2 hands out `&[u8]` borrowed from the `Mmap`, so the borrow checker refuses a read after drop, and makes the map itself `unsafe` to build for the truncation case; Swift's `~Escapable` spans borrow their owner the same way; Go's `golang.org/x/exp/mmap` copies through `ReadAt` instead of handing out the memory, and Java's `MappedByteBuffer` is never unmapped until collected and raises an `InternalError` on a truncated page; Gleam, Elixir and ReScript read a file whole into a fresh binary or string, so they have no borrow to check (Elixir's sub-binaries keep the whole binary alive, the copy-free view Ergo gets here with a checked lifetime).

## Generics

Status: **implemented** in the decided spelling of the v1 language (196g as amended, sixth round) by `internal/sketch/check` and the lowering (check-v1 stage E1, D-E1). Rules 1, 2, 5 and 6 are checked and lowered; rules 3 and 4 are outside stage E1. A type argument that stands for no value lowers in every position, a declared generic type and any function type included (lower-v1 stage 4, C11): a function value with no result has the one Go shape of a function value whose result is `struct{}`, so `func()` and `func() T` with T no value are one Go type (`TestNoValueTypeArgumentsLower`). An operations conversion whose implementing function is itself generic over a method-set constraint lowers (`TestErgoRunGenericImplementingFunction`), and so does a generic context protocol function (`TestErgoRunGenericContextKey`).

```go
func Transform[A, B, E, R](xs []A, f func(A) B fails E needs R) []B fails E needs R {
	let mut out = []B{}
	for x in xs {
		let y = try f(x)
		out = out.Append(y)
	}
	out
}
```

1. Type parameters are declared in brackets after the name, `[A, B, E, R]`; a bare upper-case letter that resolves to nothing is S104 (unknown type), never a parameter by itself. The kinds stay implicit: a parameter written after `fails` anywhere in its scope ranges over error rows (`E`), after `needs` over capability rows (`R`), else over types (`A`, `B`). **A row parameter may stand in every type position** (owner q47, 2026-11-09): a parameter written after `fails` and in a type position ranges over error rows, and in the type position it names the row's **value type**, the type a `case err:` binding has ([rows.md](rows.md#error-rows) 8). So `type Job[F] { Run func() int fails F, Last F }` declares a field that holds one failure of `Run`'s row, and `func ExitOf[T, F](body func() T fails F) Exit[T, F]`, with `type Exit[T, F] = Done{Value T} | Failed{Error F}`, passes `F`'s value type to `Exit`'s type parameter. A row written as a type argument names the same type, `Exit[int, NotFound | Busy]`, and a row argument of a row parameter is written the same way, `Job[NotFound | Busy]`. The value type follows the rules of a union over its members, as every type of that shape does (rows.md, Error rows 8: assignment, match, equality, generators, literals), and lowers to a Go `error`, with no Go type parameter for a row parameter, except a slot row (rows.md, Error rows 8, Lowering: an error row parameter standing alone in its function's signature, as a type argument or as a value parameter's type, is a Go type parameter `F error`). A row of one error type in that position names the type itself (rows.md, Error rows 8, One member). Any other two kinds of one parameter (a type and a capability row, or an error row and a capability row) are S108 at the declaration (a function's: "R is used as a capability row and as a type; a parameter has one kind"), since a capability row has no value type. *Prior art:* Zig's error sets are types, `error{NotFound, Busy}`, that a field or a variable holds, and an error set coerces to a wider one, as a row value goes into a wider row; OCaml's polymorphic variants are value types over a row (an open row of tags), and a match on an open one needs a default case, as a row value over a parameter does here; Gleam, ReScript and Rust carry a failure as data in `Result(a, e)` over a type `e`, and Effect's `Exit<A, E>` over a union type `E`; Koka keeps effect rows apart from value types, which is why its effects have no value type. Before q47 this was S108 "F is used as an error row and as a type" (fail-field, batch 13), which made rows the one kind of parameter that could not be a field. `[T any]` is written `[T]`, and `any` is S104 ([Basic types](#basic-types) 8).
2. A constraint follows its parameter inline, `[T ordered]`, and applies to the names before it back to the previous constraint (`[A, B ordered]` constrains both); `any` ends an unconstrained group before a constrained one, `[E any, K comparable]` ([grammar.md](grammar.md#declarations) 3, fu8b). Type parameters bind by name, never by position: a caller may declare them in any order. A constraint failure, in a call or in a written instantiation such as `show[int, X]`, names the function's parameter. When that parameter takes its constraint from a later name in its group, the message says so and writes the repair: `S does not satisfy the constraint comparable of show's S: S is not comparable; [S, E comparable] constrains S as it does E: write [S any, E comparable] to leave S unconstrained` (`TestTypeParamGroups`). A constraint is an operation type, which a type argument meets when it declares it (or, as a type parameter, when its own constraint includes it; [Interface assignability](#interface-assignability) 1, EXC1), or the predeclared `comparable`. There is no `where` clause. `comparable` admits the types with generated equality (D-E2) and gives `==` and `!=`; it stays a name of the language because it is a predicate over the structure of any type, not a finite set of types. **Type sets** (CONSTRAINTS C1, 2026-11-17). An operation type may have one type-set member, terms joined by `|`: `type Count { ~int | ~int64 }`. A term `~T` (T a basic type) admits every type whose underlying type is T, a bare term `T` admits T alone, and the term `comparable` admits the comparable types; no term names a type parameter, and a refined type is no term and enters through no `~T` (Refinements 7). A type is in the set when one term admits it, with no clause; a type parameter is in it when every term of its own set is. A constraint with a type set and operations needs both. Inside a body, a type parameter under a set takes the operators that every type of the set has (Go's rule): ordering when every term orders, `+` when every term adds, `-`, `*` and `/` when every term is a number, `%` and the bit operators when every term is an integer, `==` when every term compares; a term `comparable` gives `==` and `!=` only. An operation type with a type set is a constraint only: no value has it as its type, and `func f(c Count)` is S108 "Count has a type set, so it is a constraint only and no value has it as its type; write a type parameter: [T Count]". The prelude declares `ordered` (the integer and float types, `string`, `duration` and the types defined over them; ordering and `+`) and `number` (the integer and float types and the types defined over them; the arithmetic operators) as ordinary type sets, in scope everywhere with their lowercase names, and no rule of the checker or the lowering reads either name: a user's set with the same terms gets the same verdicts, operators and Go (`TestTypeSetsAgree`). A type not in the set is S108 at the argument: "string does not satisfy the constraint Count of Sum's T: string is not in Count's type set, ~int \| ~int64" (a set of more than 8 terms prints its first 8 and `, …`). *Prior art:* Go's type sets and `~T`, with `comparable` predeclared and `cmp.Ordered` an ordinary interface of the standard library. Method constraints resolve through the type's owner package, with one answer per type (196m), and a constraint says which of its operations write: an operation declared `mut`, `type Counter { mut Bump() int }`, writes its receiver (q169; MODES-4). At a constraint and at a type's `implements` clause, a function on `mut T` implements only a `mut` operation (S108 at the constraint, S106 at the clause: "Tally.Bump writes its receiver (mut Tally), and the operation Bump does not: declare it mut Bump(…)"), and a function on `T` implements either kind ([Interface assignability](#interface-assignability) 1; report CSX §7 EXM3). A Go interface spells no `mut`: a function on `mut T` provides its operation for a value with a place, as Go's pointer-receiver method does ([interop](interop.md#checking)). A generic body calls a `mut` operation only on a `x mut T` parameter: on a read `x T` it is S108 "Bump is a mut operation, which writes its receiver, and x is a read T; write x mut T where it is declared". So the signature says what the body writes, and the call reads no body (q137). The witness of a `mut` operation takes the value's place (`*S` in Go), so the write reaches the caller's value. A value of an operation type with a `mut` operation is built from a place, `let c Counter = &t` (Borrows 6); a value with no place is refused when a function on `mut T` provides one of its operations ("… has a mut T receiver"). `ergo fix` marks `mut` each operation that a function on `mut T` implemented, at a constraint or a clause, where the operation is declared (an included operation in the type that declares it; `fix.TestFixMarksMutOperations`); over the corpus it marked 93 operations (vt 38, prelude `Reader` and `Writer` 29, json 13, xml 7, cbor 5, counter 1). A constraint may name its own parameter, `[T Lesser[T]]`. **Self bounds** (CONSTRAINTS C2, 2026-11-18). An operation type's parameter may be bounded by an operation type, the declaring one included: `type Ranked[T Ranked[T]] { Compare(other T) int, law Reflexive(a T) { a.Compare(a) == 0 } }`, as Go 1.26 admits `type Adder[A Adder[A]] interface`. Every parameter of a bracket is declared before any constraint resolves, so a bound may name the type itself or a later parameter. Inside the type, a value of `T` has the bound's operations, so a member law calls `a.Compare(b)`; a run of the law at a provider's instance passes the instance's witness, as a call of a generic function does (rule 5). A bound that grows its own argument, `type R[T R[[]T]]`, is an instantiation cycle (rule 5). A clause meets the bound at its instance: `type Level int implements Ranked[Level]` with `func Compare(a Level, b Level) int`. A clause whose instance breaks the bound is S106 at the clause: "Tag implements Ranked[Other], and Ranked's T must satisfy Ranked[T]: Other does not declare that it implements Ranked[Other]: …". A predeclared or unnamed type declares nothing, so it meets no operation constraint, and the reason says what to write: "int is a predeclared type and declares nothing; define a type over it that declares the constraint: type N int implements Ranked[N]" (`[]int is not a declared type and declares nothing; …` for a slice, a Map, a tuple or a function type).
3. **No elision.** A row in a generic signature is written wherever it passes through, as `func Filter[T, E, R](xs []T, keep func(x T) bool fails E needs R) []T fails E needs R` writes `E` and `R`; an unwritten row is the empty row ([decisions](../decisions.md#owner-direction-2026-11-12)).
4. Exported signatures spell their rows and type parameters, so clients check against interface summaries, Go's export-data model.
5. **Lowering.** Generics emit as Go generics. In a run build and in a test build, a call of a generic function, or of a method of a generic record, whose type arguments are all known Go types goes to a plain copy of the callee for those Go types (MONO1, `lower/mono.go`): Go compiles it with no GC-shape stencil and no dictionary. Inside a copy every type parameter is a Go type, so the copies close over the program's instances. Two instantiations with the same Go type arguments share one copy, so the copies are bounded by the distinct instances, never by the call sites; row arguments are erased and key nothing. A callee with owned parameters, an owned body, a known-callback variant, a known-record copy, a checked Close keep the Go generic, and `genericLowering=stencil` selects it everywhere as the reference. A test build takes the copies too (MONO-HOOKS-MIN, owner 2026-11-19: tests run what ships): a copy is a plain function that Go compiles once, in its package, where a generic instance is compiled again in every package and shard that names it, so a split or sharded build pays for each instance once with no change to Go's compiler; `TestGenericLoweringsAgree` holds the copies to the stenciled reference. The instances are finite because of the next rule. An instantiation cycle, a generic type or function that instantiates itself with a growing argument (`func f[T]() { f[[]T]() }`), is S108, as Go rejects it: its instances never end. A method's receiver parameters count as the type's own, as `go/types` canonicalises them, so `func (r R[T]) M() { R[[]T]{}.M() }` is a cycle too. Signatures count like bodies: a parameter, a result, a bodiless declaration, an interface-typed parameter or a constraint that instantiates with a growing argument (`func (R[T]) M(x R[[]T])`), through a renamed receiver parameter or across two receiver types, is a cycle as well. The checker finds it on the instantiation graph, not by a depth limit. A constraint lowers to a Go constraint that keeps its operations, never to `any`: `comparable` to Go's `comparable`, and a type set (the prelude's `ordered` and `number` as much as a user's) to one generated Go type-set interface per declaration, its terms spelled in Go (`~duration` is `~int64`, a bare term a `~` term covers is left out, and a set with the term `comparable` is Go's `comparable`; `lower/ir_typeset.go`), so `<` and `+` compile in the Go body. A type parameter that a method set constrains lowers to a Go type parameter constrained by `any`, and the function takes one witness per such parameter after the environment: a struct with one function field per operation, in the uniform function shape with the value first. The caller builds it from the instance the checker records (`Info.Instances`: the callee, its type arguments and, per operation, the implementing function and its own instance), so the lowering never resolves an operation again; a Go method cannot carry it, since Go declares methods only on the package's own defined types. **A known witness** (VI1, `lower/witspec.go`): when a call binds a function's one type parameter, a method set's, to a named type whose operations are package functions (`PlayOn(&s, input)` with `s` a `screen.Screen`), the call goes to a copy of the function for that type, one Go instance with no witness parameter, whose operation calls call the implementing functions directly (Go inlines them); in the copy, a call that binds a callee's parameter to the copy's own goes to the callee's copy for the same type, and a use of the witness itself (a conversion to the operation type, a call of a function with no copy) takes the struct the call would have built. The copy's body, polls, failures and defects are the function's; a defect inside an operation names the generic body's frame, where the passed witness's closure names its building call as well. The reference is `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.witnessLowering=dynamic`; `TestKnownWitnessesAgree` runs generated programs under both. An instance used as a value, `Max[int]`, is the Go instance with its type arguments written. *Prior art:* Go GC-shape stenciling, whose dictionaries also carry a type parameter's methods; Swift witness tables and Haskell and Scala dictionaries pass a constraint's operations the same way; MoonBit and Rust monomorphise; Gleam, ReScript and Elixir have no constraints to lower; Ergo's earlier measurements refused frontend monomorphisation ([design.md](../design.md#compile-speed-is-a-language-constraint)); the IR-G plan (owner, 2026-11-12, q155) makes the plain copies a v1 unit, with their cost (program text and compile work) counted in the unit's receipt.
6. **Inference.** Type arguments are inferred by unification over the value arguments with Go's unifier (`go/types` unify.go), never from a call's expected result. Inference is sound and a documented subset of Go's (D6 as amended in rounds 7 and 8): when Ergo infers, Go infers the same types for the same call after row erasure. The subset is typed value arguments, structural unification, interfaces through method sets, conflicts between arguments, literals (196u rule 6: a literal argument binds a parameter only when no typed argument binds it, and a parameter that only literals bind takes their common default, so `Two(1, 2)` infers `int` and `Two(x, 2)` with `x int8` infers `int8`; mixed defaults, `Two(1, 'a')`, are S108 "cannot infer T; write the type arguments"), and written type arguments. Every typed argument unifies first, in source order, then the literals default, and each literal is then checked with its parameter's type expected. A function literal whose parameter types are written is a typed argument; only its unwritten rows take the parameter type's, so `Apply(func(v int8) int8 { return v }, 1)` and `Rev(1, func(v int8) int8 { return v })` infer `int8`. A function literal with untyped parameters, `func(x) { x * 2 }` (D-E1), binds nothing: it is checked after the typed arguments and the literal defaults, and each untyped parameter takes its type from the expected function type, so `Each(xs, func(x) { x * 2 })` with `xs []int` types `x` as `int`, and its tail's type binds a result parameter left open (`MapOf(xs, func(x) { "s" })` binds `U` to `string`). An untyped parameter never takes a default: with no expected type, or one that no other argument fixes, it is S108 "cannot infer the type of x; write func(x T)", once per literal, with no cascade. A trailing block writes no types and binds what is left after the literals. Outside the subset, the call is S108 "cannot infer T; write the type arguments, e.g. Fn[int](…)", its only diagnostic: a parameter only a method or core-type constraint determines (`Use(x)` for `Use[T comparable, P M[T]]`, where `type M[T] { M(T) }`), and a generic function passed as an argument without all its type arguments (`Apply(Id, 1)`, `Fix(Id)`). The written forms stay valid: `Use[int](x)`, `Apply(Id[int], 1)`; a constraint error stays a constraint error when typed or written arguments fix every type argument. A call whose inference fails or is refused reports one diagnostic, and its result is invalid, so nothing cascades from it. An argument that is invalid, or is itself a failed or refused call, fails the enclosing generic call with no diagnostic of its own (one rule, in the inference loop; round 9), so `Id(Apply(Id, 1))` reports one refusal; independent errors in other arguments still report. Each typed argument is assigned to its parameter: the match may be inexact at the top (an interface on either side matches a type that has its methods, by unifying the method signatures, so a wider interface, a named generic interface, a concrete type or a pointer infers through its method set), and element types match exactly. A parameter bound by an earlier argument must match every later one: a conflict is S108 at the argument (`Two(x, y)` with `x` an interface and `y` a struct; of an interface and a non-interface neither is chosen, so the order of the arguments never decides), while `Two[I](x, y)` for an operation type `I { M() }`, with every type argument written, infers nothing and only assigns. Ergo departs from Go where its types do: a named type unifies with a type literal only when it is an interface (types are nominal), and a named union unifies with the variant its argument names. A parameter that an earlier argument binds to a variant takes the union a later argument names, so `machines.Next(Green{…}, d)` with `d` a `Decision[Light, O]` infers `Light` (G-exup-2); each argument is then assigned to the instance, so `Pick(xs, l)` with `xs []Green` and `l Light` is the S108 of `xs`. A generic function inside parentheses is a value, as in Go: `(Fn[int])` is the instance, and `(Fn)[int]` or `(Fn)(1)` is S108. In `Info`, an explicit instantiation `Fn[int]` and the parentheses around it carry the instance type while the name `Fn` keeps its generic type; in an inferred call `Fn(1)` the name carries the instance, as in `go/types`. Every literal carries its one type in `Info`, recorded when it is checked ([Basic types](#basic-types) 6; 196u rule 7): no expression's type is updated afterwards. A row parameter binds to the row of a function-typed argument, less the row's written part; `fails E | Expired` is the union. When several arguments bind one row parameter, it binds to the union of their rows: rows are finite sets, and a function with a narrower row is assignable where a wider one is expected, so the union is the least binding that admits every argument. A written type argument is not widened. An error row parameter that stands as a type argument binds from the argument's type argument in that position (CK-rowarg): for `func Await[T, F](a Async[T, F]) T fails F`, `Await(x)` with `x Async[int, NotFound | Busy]` binds `F` to `NotFound | Busy`, and with `x Async[int, NotFound]` binds `F` to `NotFound`; a row value binds its row, and an error type a row of that one type. Go infers the same after row erasure, where `F` is the Go type parameter of a slot row (rows.md, Error rows 8) and its argument the instance's Go type argument (`TestRowParamBindsFromTypeArg`). A composite literal of a generic type, or a generic variant in a `case`, written without type arguments takes them from the expected type, else from its field values (`Some{n}`, `Enter{x}`). A type parameter left unbound is S108; a row parameter left unbound is empty. A result-position type parameter bound by a block with no value stands for no value, lowered to `struct{}`. *Prior art:* Go `types2/infer.go`; Koka infers effect rows; OCaml and ReScript disambiguate constructors by the expected type; Gleam's `Nil` and Rust's `()` for no value.
7. **Left-out rows.** A generic type's trailing row parameters may be left out of its written type arguments, and each one left out is the empty row, as a row parameter that inference leaves unbound is (6): with `type Command[C, E] { Build func(v Values) C fails E }`, `Command[Cmd]` is the command whose `Build` fails nothing, the same type that `Command{Build: f}` infers for an `f` with no failure. A type parameter is never left out, nor a row parameter that a written argument follows: `Pair[int]` for `Pair[A, B]`, and `Mid[int, string]` for `Mid[A, E, B]`, are S108 "… takes 3 type arguments, not 2", as is an extra argument. At least one argument is written: a bare generic name is S108 "generic type … needs type arguments", since a bare name in a composite literal already means "infer the arguments" ([Structs](#structs)). Rows are erased (rows.md), so the rule changes no emitted Go. In a `case` pattern the variant takes its arguments from the subject, so a row left out there is the subject's, never the empty row: over `Async2[T, F] = Waiting | Retrying{Again func() T fails F} | Failed{Error F}`, `case Retrying[T] as r` is the subject's `Retrying[T, F]` and `r.Again()` fails `F`. An inline variant's parameters are its union's and have their kinds, so that one variant's `fails F` makes the union's `F`, and every variant's, an error row (ROW-PARAM). *Prior art:* Effect declares `Effect<A, E = never, R = never>` with TypeScript type-parameter defaults, which gives the same reading through a library default; Koka writes a total function's empty effect row as `<>` or leaves it out; Go and Gleam have no defaults for type parameters.
8. **Written rows.** The argument of a row parameter is a row, written as a row is written after `needs` and `fails`: `A | B`, bare, of one or more elements (lane MB F8; one rule for every row position, q39). It is the same in a type, `Option[machines.Work[Signal, Payments | Scheduler]]`, and in an expression's index, `run[A | B](j)`. A row of error types where a type parameter's argument is expected names its row value type (rule 1, q47: `Exit[int, NotFound | Busy]`), and a row of one error type names that type, so `Exit[int, NotFound]` is one type however `NotFound` came there (CK-rowarg; rows.md, Error rows 8, One member); a row of capabilities there is S104 "A is not an error type", since a capability row has no value type; a parenthesised row is S001 "a row takes no parentheses", as `needs (A | B)` is. Each element is checked as the one-element row is: it is a capability when the parameter ranges over capabilities, and an error type when it ranges over errors (`TestRowArgFixtures`). The written row is a set, as every row is ([rows.md](rows.md#error-rows) 1): a named row stands for its variants, and order and repetition carry no meaning, so `Work[E, A | A]` is `Work[E, A]`, and `Box[U | V]` is `Box[E1 | E2 | E3]` for `U = E1 | E2` and `V = E2 | E3`. A repeated element is not refused, in this position or any other, since an element can be opaque (a row parameter, or a named row that overlaps another), and two instances are one type exactly when their rows are one set (owner q1, wf10 F8; `TestRowArgsAreSets`, a seeded property against the set model). *Prior art:* Koka writes an effect row argument as `<a, b>` in a type application; Effect writes `Effect<A, E1 | E2, R1 | R2>` with TypeScript unions, the spelling this rule takes; Scala 3 capture sets `{a, b}`; Go, Gleam, ReScript and Elixir have no rows.
9. **A type parameter's ownership is written: `[T own]`** (q172; report CSX §7 EXM2; MODES-5 replaced the copy-site rule of resource ownership L8 A3). A type parameter binds plain data unless its declaration marks it `own`: `func keep[T own](x own T) T { x }`, `type Stack[T own] { items []T }`; with a constraint the mark stands before it, `[T own Counter]`, and it applies to the names before it as a constraint does, so `[A, B own]` marks both and `[A any, B own]` marks `B` (grammar.md Declarations 3). A call, a function value, a written or inferred instance of a generic type, that binds a resource, or a value of the caller's own `T`, to an unmarked type parameter is S108 at the instantiation, which reads the signature and never the body: "dup cannot take Res as its T: T is not marked own, so it binds plain data only; write [T own] where dup declares it, which holds its body to a resource's rules (types.md, Generics 9)". Inside a body that writes the mark, a value of `T` has one owner as a resource's has: a use after a hand-off, a second hand-off, a part a pattern drops, a value dropped at the end of its scope (the release of a dropped `T` is Gap 42) and a call that binds `T` to an unmarked callee are S108 at the site, with "T is marked own, so its value has one owner as a resource's has"; an own `T` as a map key is S112 (R40). A value that holds `T` only as a part, a field, a variant or an `Option[T]`, is dropped under the same rule, even when it also holds a concrete resource: its release would skip the `T` part. A `match` arm whose pattern narrows such a value to a variant that holds no `T`, directly or through a part, holds nothing of `T`: dropping it there is admitted, and its concrete resources, if any, are released as any value's. So `case MyNone: None` in a marked `func toOption[T own](o own MyOpt[T]) Option[T]` checks, while `case MySome: None` is Gap 42 (GEN9-GAP42 D). An unmarked `T` is plain data, so `func dup[T](x T) (T, T) { (x, x) }` stands and admits `dup(1)`, and refuses `dup(file)` at the call. A generic type admits a resource exactly when its declaration marks the parameter: `type MyOpt[T own] = MySome[T] | MyNone` admits `MyOpt[File]`, and an unmarked `MyOpt[T]` refuses it at the instance, as a function's `T` does. The mark asks nothing of the type's functions, in its package or another: a function over `Box[T]` with an unmarked `T` binds plain data, and its calls decide it as any unmarked `T`'s do. The prelude declares `Option[T own]` and `Some[T own]` and `go.Ref[T]` is declared with its `T` marked, so the language's options are the same case as a user's union, with no admission of their own (GEN9-GENERAL). The ownership argument: a resource reaches a value of `Box[Res]` only through an instance that binds `T = Res`, which needs `Box`'s mark; each function that receives that value binds its own `T` to `Res` at its call, so it is marked or S108; a marked body is held to one owner, so every path that holds the resource is under the flow rules and its last owner releases it once. The language's built-in containers admit a resource with no mark: `[]T`, `[N]T` and `Map[K, V]` (its value; a key stays R40). A row parameter takes no mark (S108). An extern's mark is reviewed: `own` on an extern's type parameter is S108 unless runtime/v1's table (`v1.MovesOnly`) lists the Go body as moving its values only, so the table is the review ledger of the std marks (queue `New`, `Append`, `WithCapacity`, `MakeSlice`, `Take`, `TakeAt`, task `Go`, `tasks.Race`, `tasks.Transform`, timeout `After`). `ergo fix` writes ` own` on each type parameter where the old inference admitted a resource, until no mark is left to write (`fix.Report.WroteOwn`); `ergo api` lists a function's marked parameters (`own T`), and dropping a mark breaks resource callers. Checked: `check/resource.go` (`checkOwnMarks`), `check/takes.go` (`ownSite`, `ownExternReviewed`); `TestTakesInferenceModel` generates marked and unmarked bodies over the copy productions. *Prior art:* Rust's `T: Copy` and Swift's `~Copyable` mark the type parameter as well, with the opposite default (Swift's `T` copies unless it writes `~Copyable`; Ergo's `T` is plain data unless it writes `own`); OxCaml's mode crossing lets plain data cross a mode boundary, as an unmarked `T` here binds only plain data; Gleam, Elixir and ReScript have no resources to mark.

## Loops and len

Status: **checked** by `internal/sketch/check` and **lowered** by `internal/sketch/lower`, with `ergo run` tests (check-v1 stage D2: D-D4, D-D5).

1. **Domains** (D-D4). `for x in e` binds the element and `for i, x in e` the position and the element, over five domains: a slice `[]T` or an array `[N]T` (position `int`); a `Map[K, V]` (one name binds the value, two the key and the value; order unspecified); a string or a type defined over one (one name binds each `rune`, two the `int` byte offset where the rune starts and the rune; L4); the prelude's `Range[T]` (one name, counting from `Start` up to `End`, `End` excluded); and the prelude's `Seq[T]` (one name). A string is decoded as UTF-8 exactly as Go's range decodes it: each byte that does not begin a valid encoding (a stray continuation byte, a truncated or overlong sequence, an encoded surrogate) is one rune U+FFFD of width one, so the next offset is one byte on; a string's bytes are `for i in 0..len(s)` and `s[i]`. A second name over a `Range` or a `Seq` is S108 "a for over Range[int] binds one name, the element: for x in …". Any other domain is S108 with a message that names the Ergo form: an integer ("count with for i in 0..n"), a pointer ("write for x in *p"), anything else ("a for takes a slice, a Map, a string, a Range or a Seq"). A `Range` over a non-integer `T` is S108. A refused domain or name still binds its names, with no type, so nothing cascades: it adds no S110, and `for Some in xs` is one diagnostic. A `for` over a `Map` that the body changes follows Go: it visits each entry present at the start at most once, in unspecified order; an entry inserted during the loop may or may not be visited; an entry deleted before it is reached is not visited. There is no snapshot, which would allocate on every loop. *Prior art:* Go's range over a map has these rules; Rust's borrow checker refuses a change during the loop; Gleam's and Elixir's maps are immutable values, so a loop sees the map it started with.
2. **`a..b`** has the type `Range[T]` for one integer type `T`, the operands' (D-A1 types the literals), and works outside a `for`: `let r = 0..n`, `r.End - r.Start`. Other operand types are S108. *Prior art:* Rust's `0..n` is a `Range` value; MoonBit's `0..<n`.
3. **Bindings** are immutable and read: an unread one is S110, `_` ignores it. A single name follows the one binder rule (check-v1 D-D2 and D-D3; [rows.md](rows.md#totality), Totality 6): a known constant or capability name is a pattern, and a package type's name binds a local ([Scope](#scope) 1), so `for line in lines` binds `line` beside `type line`; a binding may be any irrefutable pattern. `for cond { }` needs a `bool`.
4. **`Seq[T]`** is `type Seq[T] func(yield func(v T) bool)`, a protocol any function implements by conversion, `Seq[int](f)`. `for v in s` runs the body as `yield`; a `break` or `return` makes `yield` return false. *Law:* a Seq never calls `yield` again after it returns false. `queue.Values()` returns one ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice)). *Prior art:* Go's `iter.Seq[T]` and range over func; Rust's `IntoIterator`.
5. **Map entries.** A write `m[k] = v` inserts or replaces the entry, and needs `m` rooted at a `let mut`; the write is seen through that root alone ([Bindings](#bindings) 1). A read `m[k]` is S108 "a Map read may miss; write m.Get(k), which returns an Option", whatever `V` is: there is no default value for a missing key, and `m[k] op= v` reads. The default of a `Map` is an empty, writable `Map`, wherever a default is made: a `let` with a `Map` type and no value, a field a record literal omits, and a `Map` inside a defaulted record or tuple, named or not, a generic instance included, at any depth. The lowering writes `map[K]V{}`, never Go's nil map. A defined type or instance whose default holds a `Map` has one generated Go function that builds its default, which a nested default calls, so the lowering's work and output grow linearly in the types; every default builds its own `Map`s, so two defaults never share one. *Prior art:* Rust's `#[derive(Default)]` emits one `default()` per type that calls each field's; Rust's `map[k]` panics on a missing key; Gleam's `dict.get` returns a `Result`; Go returns the zero value, the habit this rule removes, and its nil map panics on a write; Rust's `HashMap::new()`, Gleam's `dict.new()` and Elixir's `%{}` are empty and usable.
6. **`len` is the one built-in function Ergo keeps from Go** (D-D5). Ergo's own built-ins are `with`, `encode` and `decode` ([Codecs](#codecs)), `embedded` ([stdlib.md](stdlib.md)) and the row former `wired`. `len` takes a slice, an array, a `Map` or a `string` (its bytes); a pointer is S108 "len takes a slice, an array, a Map or a string", so write `len(*p)`. Every other Go built-in is S104 with the Ergo form ([diagnostics.md](diagnostics.md#s104-unknown-name)). An index does not see through a pointer either: `(*p)[i]`.
7. **Lowering.** A slice, a `Map` and a string are Go's `range` (a string's is Go's rune decoding, with no conversion or allocation); a `Range` is a counting loop over its value, evaluated once; a `Seq` keeps the one Go shape of every Ergo function value and is adapted at the loop to Go's range over func, so a `break` is Go's. Each binding is a Go variable of one iteration, so a function literal captures that iteration's value.
8. **Reserved room.** A `for` over a slice or a `Map` whose body appends one element to a local slice on every iteration, `out = out.Append(e)` at the top of the body with no `break`, `continue` or `return` in it and no other assignment of `out`, reserves room for all of them before the loop (`out = ergo.Reserve(out, len(src))`, Go's `slices.Grow`), so `out`'s array grows once and not about log2(len(src)) times. The domain is a variable, a field of one or another package's `let`, reached through no pointer and no call, or a call such as a store's `All()`, which runs once, its value held for both the length and the loop (GX8), that does not name `out`: a range over `out`'s own array sees its element writes until an append moves the array ([Bindings](#bindings) 3), so there a reservation would change what the loop reads. Capacity is not otherwise visible, since the value rule clips or copies a slice where it is still seen elsewhere; a loop that ends early with a failure or a defect leaves the room unused, as hand Go's `make([]T, 0, len(src))` does. A `Range` written in the loop is reserved when its count is backed by memory or bounded: `lo..len(p)`, with `lo` a non-negative integer literal and `p` such a path, counts at most `len(p)`; `lo..hi` of two integer literals at most 4096 apart. Each reserves `End - Start`, or nothing for an empty Range. Any other `Range` is not reserved: its count is no length of memory, so a reservation could fail for a loop that would have ended first. The reference lowering reserves nothing (lower `reserveLowering` "off"; `TestReserveAgrees`). *Prior art:* Go's own `make([]T, 0, len(src))` idiom; Rust's `collect` and `Vec::extend` reserve from the iterator's `size_hint`; OCaml's `List.map`, Gleam's `list.map` and Elixir's `for` over a list build a list of the known length in one pass.
9. **Loop idioms** (DT4; `internal/sketch/lower/loops.go`, `TestLoopIdiomsAgree`). A counted loop `for i in lo..hi` whose body is one statement is written as a Go call when that is provably its effect: a fill `P[i+d] = v` doubles a written part with `copy`, or clears it when `v` equals its type's zero value and that type's Go form is all zero bits exactly then (a bool, a string, an integer, a Duration, a record of those; not a float, whose -0.0 equals 0.0), as Go writes its memclr range loop (VI1), a move `P[i+d] = P[i+s]` within one slice is `copy` (memmove), and a collect `xs = xs.Append(Q[i+s])` is one `append` of `Q[lo+s:hi+s]`. The offsets are `i`, `i + c`, `c + i` or `i - c`. It is taken when the element holds no `Map` or slice, the frame takes no back-edge poll, and `P`, `Q`, `c` and `v` are names, constants, fields and operators that do not name `i` and read through no pointer to a type the element holds. A guard tests every bound first, and a move's direction (a target that starts inside the source, after its start, smears forward, so the loop runs); when the guard fails the loop runs as written, so a defect is raised at the same index after the same writes. The reference is `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.loopLowering=plain`. This is a lowering choice, not a promise. *Prior art:* LLVM's LoopIdiomRecognize and GCC's loop distribution turn store and copy loops into `memset`, `memcpy` and `memmove`; Go turns only the zeroing range loop into `memclr`; Gleam, Elixir and ReScript have no mutable arrays to loop over.

## Scope

Status: **checked** and **lowered** (L5, decision O16; L6, owner q30; `TestLocalShadowsPackageType`, `TestErgoRunLocalShadowProperty`, `TestPackageTypeHidesPreludeType`, `TestErgoRunPackageTypeHidesPreludeType`).

Scopes nest as in Go: the universe and the prelude, outside the package scope, outside each body's blocks.

1. **A local may take a package type's name** (L5), as in Go's block scope. A `let`, a `for` binding, a parameter, a function literal's parameter, a binding of a `let` or `for` pattern and a catch arm's `as` name may be named like a type the package declares: `let point = point{x: 1}`, `for line in lines`, `func f(rec rec) int`. For the rest of the binder's scope, function literals inside it included, the name is the local in value positions (`point.x`, `let q = point`, `point == p`, a call `point(…)`) and in pattern positions (`case point:` is then a binder, which D-D2 refuses). In a type position (a written type such as `let w point = …`, a composite literal's type, a record pattern's type), the name is the type, so `let point point = point{x: 1}` checks; a conversion `point(…)` is a call, so it calls the local. Outside the binder's scope the name is the type again. The rule covers a package's own types and the prelude's alike, since a local may take a prelude name too (D-D3, owner q244; [grammar.md](grammar.md#reserved-names) 2); `error`, a universe type that is no prelude name, keeps the type test. A package-level `let` lives in the package scope beside the type, so its name is a duplicate declaration (S108), and a type name in its pattern stays a type test. A match or catch arm's pattern keeps [Totality](rows.md#totality) 1: a name there that names a type is that type's test, unless a local of the name is in scope. The lowering gives every local its own Go name, never a package entity's (lower naming.go), so `point := point{x: 1}` never reaches Go. *Prior art:* Go block scope, `point := point{}` (Go then loses the type in the scope, which Ergo keeps for type positions); Rust, OCaml, ReScript and Gleam keep types and values in separate namespaces, so the clash never arises; Elixir has no static types to clash with.
2. **A package type may take a prelude type's name** (L6, owner q30, 2026-11-08). A package-level `type` declaration may be named like a type of the prelude or the universe: `type Option[T] = Present[T]{ V T } | Absent{}`, `type Map[K, V] { … }`, `type Range { … }`, `type int { n int64 }`. The prelude scope is outside the package scope, so inside the package the name is the package's type wherever a type name stands, `Map[K, V]` included ([grammar.md](grammar.md#parser) 8). The prelude's own declarations, std's and every other package's keep the prelude's type: `slices.Max(xs)` returns the prelude `Option`, matched with `Some` and `None`, and `0..n` builds the prelude `Range`. Since owner q244 (2026-11-19, D-D3) every other declaration may too: a package function, `let`, context, import alias or type parameter named like a prelude name, a local of such a name (rule 1), and a declaration of a prelude function or constant name (`len`, `true`, `encode`), a type's included; a package value named like a prelude type hides the type in type positions too, as in Go. The prelude's variants `Some` and `None` are prelude types, so `type Opt = Some{ V int } | None{}` declares the package's own `Some` and `None` ([grammar.md](grammar.md#reserved-names) 2). The lowering emits the package's type under its own Go name in the package and reaches the prelude's types through their own package, so the two never meet in Go. Inside the package the hidden type has no spelling, so a clause that must name it (a capability of another package whose argument is the prelude's `Option`, the map type or `string`) cannot be written there: its S102 asks to rename the package's type ("the clause cannot be written here, since this package's type Map hides the prelude's …") and carries no clause, and `ergo fix` writes none (REL-needs r5, `TestFixHiddenPreludeType`). *Prior art:* Go's universe scope encloses each package scope, so `type error struct{}` or `type int struct{}` is legal and hides the predeclared type in that package; Gleam, ReScript and Elm let a module define its own `Option` or `Result`, which hides the auto-imported one inside the module; Elixir's `Kernel` imports are overridden by a local `def` of the same name (with `import Kernel, except:`); Rust's prelude is a glob import that any local item shadows.

## Unreachable

Status: **implemented**: checked and lowered (owner q29, 2026-11-08; synthesis M22). `Unreachable(reason string)` is a prelude function. It states that a path cannot run, such as the `None` arm of a lookup whose key is always present. Before it, such a path had to invent a value or declare a failure that cannot happen.

1. **Bottom type.** The call has the bottom type: it checks in every position that expects a value, and it has the type that position expects. These positions expect a value: a `let` with a written type, an argument, a `return`, a record field, an operand, and a branch of a value `if`, `match` or `catch` after an earlier branch fixed the type. As a statement it has no value, like any call whose value is dropped.
2. **Leaves the branch.** As the last statement of a body or a branch, it yields no value and joins any type, as `return` does ([Totality](rows.md#totality) 3). So `let x = if c { 1 } else { Unreachable("why") }` has type `int`, and `func f() T { Unreachable("why") }` needs no value after it.
3. **Needs a type.** In a position that expects no type, `let x = Unreachable("why")`, the call has no type to take. This is S108, which asks for the type: `let x T = Unreachable("why")`. The bottom type has no name in source.
4. **A defect, never a failure.** When it runs, it raises a defect that holds the reason and the call's position ([runtime.md](runtime.md#exit-causes) 3). Its row is empty, so it adds nothing to a function's error row, and a `catch` on it is S108, as on any expression that cannot fail ([rows.md](rows.md#catch) 1). Every `catch` passes it on, `case _` included (Catch 6). `ergo run` reports `panic: unreachable at main.ergo:12:3: why` and exits 2. A call in a std package's body names the std file by its path in the std tree, `unreachable at std/maps/maps.ergo:12:3: why`, as a std match's no-case defect does (fs5, batch 12: before, such a call was an internal compiler error; `TestStdGapPrelude`).
5. **The name.** `Unreachable` is a prelude name: a declaration or a local of that name hides it for the rest of its scope, as any declaration hides a prelude name (D-D3, owner q244).
6. **Lowering.** As a statement or a last statement, the call is `panic(ergo.UnreachableAt(reason, "file:line:col"))`, the Go statement a hand-written program writes, and a terminating statement for Go. In a value position, it is `ergo.Never[T](reason, "file:line:col")`, which panics the same way. The call adds no frame, and its Go body `v1.Unreachable` is not called. Tests: `TestUnreachableChecksInEachPosition`, `TestUnreachableRefusals`, `TestErgoRunUnreachable` and `TestUnreachableLowersToPanic`.

*Prior art:* Rust's `unreachable!()` and `panic!()` have type `!`, which coerces to any type. Go's `panic` is a statement that ends a path, and has no value. Gleam's `panic` and `todo` are expressions of any type. ReScript's `assert(false)` and Elixir's `raise` are expressions that leave. Effect's `Effect.die` and `Effect.dieMessage` put a defect in the cause, never in the error channel. Kotlin's `Nothing` and Scala's `Nothing` are named bottom types; Ergo does not name its bottom type in source (rule 3).

## Never

Status: **implemented**: checked and lowered (owner, 2026-11-13; [decisions](../decisions.md#owner-direction-2026-11-13); unit FKG2). `Never` is a prelude type with no value: a closed union of no variants. A machine that gives no output is a `Decision[S, Never]`, so its step writes no `Emit` and no `Done`, and the code that reads its decisions or its runs writes no arm for them.

1. **No value.** No expression makes a `Never`: it has no variant to build, `Never{}` is S108 ("cannot write a composite literal of Never"), and no conversion or zero value gives one. A record with a field of type `Never`, or a tuple with such an element, has no value either: `Emit[S, Never]`, `Done[Never]`, std `machines.Finished[S, Never]`. A union, a slice, a map, an `Option` and a function of such types do have values (`None`, an empty slice).
2. **Matches leave it out** ([Totality](rows.md#totality) 2). A match is total without an arm for a variant that has no value: `match d { case Enter[S]: … case Stay[S]: … case Ignore, Reject: … }` on a `Decision[S, Never]`, and one `case machines.Running[S, Never]` on a run's `Outcome[S, Never]`. An arm that names such a variant never runs, and is S108: "Emit[S, Never] has no value: it holds a Never, so this case never runs; leave it out (types.md, Never)". A match on a `Never` value, or on a union whose every variant holds one, needs no arm: `match n {}`, which has the type its position expects, as [Unreachable](#unreachable) does.
3. **No bottom type.** `Never` converts to no other type and is assignable to none: `func f(n Never) int { n }` is S108. Where a branch that holds a `Never` must give a `T`, `n.Absurd[T]()` (or `match n {}`) gives it. `Absurd[T](n Never) T` is a prelude function on `Never`, so it is reached by the dot form (stdlib.md, Prelude); it is never called, since no `Never` exists. Its type argument is written: Ergo infers type arguments from arguments only (D6).
4. **No failure row.** `fails Never` is S108: a function that never fails writes no `fails` (one way; [rows.md](rows.md#error-rows)).
5. **The name.** A package type may still take the name (rule 2 of [Scope](#scope)), and then hides the prelude's `Never` in that package; `type Never {}` so declared is an empty record, which has a value, so a program that means "no value" uses the prelude's.
6. **Lowering.** `Never` is Go's `struct{}`, which the lowered code never builds, so a `Decision[S, Never]` costs what a `Decision[S, struct{}]` does. A match of no arm is `panic(ergo.UnreachableAt(…))` in both match lowerings, a terminating statement, and its subject is not evaluated. Tests: `TestNeverTotality`, `TestNeverRefusals` (check), `TestNeverLowers` (lower, both lowerings, `go/types`).

*Prior art:* Elm's `Never` and `never : Never -> a`, the model here (a type, not a bottom); Rust's `Infallible` (an enum of no variants, matched with `match x {}`) and `!`, which coerces to any type; TypeScript's `never`, a bottom type assignable to every type, which Ergo does not take; Haskell's `Void` and `absurd`; Effect's `never` in an error or requirement channel, which Ergo's rows already say by leaving the row out. Gleam and ReScript have none and write an arm that cannot run.

## Laws

Status: **implemented: checked and run by `ergo test`** for top-level laws, for member laws of an operation type, a generic one included at each provider's instance (law-run-1, rule 10; L4), and for laws in a machine (MU6, rule 13). The checker checks every law (check-v1 stage E3b, 196l). A law of an imported operation type runs against this package's providers in the least package that sees the binding (rule 10; `TestLawRunLeastPackage`).

```go
type Codec[T comparable] {
	Encode(v T) string,
	Decode(s string) T fails Malformed,

	law RoundTrip(v T) { try Decode(Encode(v)) == v },
}

type Store {
	Find(id string) Order fails NotFound,
	Put(id string, o Order),

	law FindAfterPut(id string, o Order) { Put(id, o); try Find(id) == o },
	law Taxed(o Order) { with context { Rates: Flat } { taxed(o) == o.Total+7 } },
}

// A law about plain functions stands at top level, beside test.
law AddCommutes(a Money, b Money) { add(a, b) == add(b, a) }
```

1. **Placement sets the quantifier.** A law is `law X(params) { … }`. It stands in one of three places (196l; law-top, 2026-11-04):
   - at top level, beside `test`: it is quantified over its parameters only. A top-level law has no type parameters (S001, [grammar](grammar.md#declarations) rule 11); a generic law belongs once on the library protocol, as a member of its operation type;
   - as a member of an operation type, beside its operations: it is quantified over its parameters and every provider of its type;
   - in a machine, after its entries (MU6): it is quantified over its parameters, or, as a reachability law, over the machine's runs (rule 13).

   A type with laws and no operations is S108 once, at its name: "T has laws and no operations; write it as a top-level law: law X(…) { … }". Its laws are still checked, with no operation scope, so their own errors show and nothing cascades from the S108. A law beside fields or in a union variant is S108 from the parser ([grammar](grammar.md#declarations) rule 5).
2. **No value.** A law is entered into no value scope, so `RoundTrip(1)` in any body is S104 "unknown name RoundTrip", and `Codec.RoundTrip` is S104 as an unknown member. A member law's name is in its type's own namespace: a second law of one name in one type is S108 "law X is declared twice", at the second, and a law named like an operation of its type is S108 "law X is named like an operation of T". A top-level law's name is in the namespace of the package's tests: a second top-level law of a name is S108 "law X is declared twice", and a top-level law and a test of one name are S108 at the second in source order ("law X is named like test X", or "test X is named like law X"). A top-level law may share its name with a function, a type or a member law.
3. **Scope.** A top-level law's body sees its parameters, then the package. A member law's body sees its parameters, then the operations of its type, then the package. An operation therefore wins over a package function of its name: in `law Stable(v int) { Encode(v) == Encode(v) }`, `Encode` is the operation even beside `func Encode(_ Plain, v int) string`. A law of a generic type is generic in the type's bracket parameters, as a generic function body is in its own: its parameters and its locals, `let w T = v`, may name `T`. Rules 5 and 6 apply to member laws: a top-level law has no operation scope, so they have nothing to apply to. Every other rule is the same for both placements, and the checker takes one path for both.
4. **Parameters** are typed as a function's are. A lone name is a type, so `law L(v)` is S104 "unknown type v", as `func f(v)` and `test T(v)` are. A parameter written as a function type without `own` is non-escaping. A parameter named twice is S108 "v is already a parameter of law L". A law parameter need not be generatable: that is a property test's rule, and laws and proofs decides how laws are run.
5. **Operation names are not rebound.** The operation scope encloses the law's body, so the no-shadowing rule (D-D2) applies to it: a parameter, `let`, pattern, `as`, loop, catch-arm or function-literal binder named like an operation of the type is S108 at the binder. An operation also hides a package context of its name, so `with Encode { … }` in a law of a type with an operation `Encode` is S108 ([runtime](runtime.md#g1-context-through-with), G1 rule 2).
6. **Operations are call-only.** A call of an operation is checked against the operation's signature. It charges nothing, and its failure row joins the law's. Any other use, as a value, an argument or a selector base, is S108 "an operation of T is called inside a law; it is not a value".
7. **Rows.** A law's failure row is unbounded and is not computed: a failure that escapes the body refutes the law when it runs. A top-level law needs no service. A member law of a non-generic operation type `T` has `T` in its service row, and nothing else: a run binds `T` to the provider under test (rule 10), so a helper `func twice() int needs Store` runs inside a law of `Store`, and so does `Store.Count()`. Any other call that charges a capability, a package function whose row needs one or a capability operation such as `Rates.Get()`, is S102 unless a `with` in the law discharges it, as `Taxed` above does. A member law of a generic type has no capability in its row: its type names its own type parameters, `Codec[T]`, and a capability's type arguments are concrete ([Capabilities](#capabilities) rule 7). Its bare operation calls still reach the provider under test (rule 11).
8. **The tail.** The body ends in a `bool`. `return e` leaves early and means the same as a tail `e` ([rows](rows.md#totality) rule 3), so one rule admits every success value of the law, a tail, a whole-body `return` or an early `return`: its type's underlying type is `bool`. A law declares no result type to convert to, so `v` of `type Flag bool` is a result as `bool(v)` is. A tail or a returned value whose type's underlying type is not `bool` is S108 "a law's body ends in a bool, not string", once, at that value. A body that can end with no value is S108 "a law's body ends in a bool, not nothing", at the end of that path. A function literal inside the law keeps its own declared result: `func(x Flag) bool { return x }` is S108 there, as anywhere. A `return` of a fallible value or of an error value passes the failure out of the law ([rows](rows.md#error-rows) rule 4). A fallible tail must be tried (S105), so a law writes `try Find(id) == o`. An invalid tail adds no diagnostic.
9. **A frame of its own.** A law body is checked as if it ran in a frame, as a test body is: `task.Go`, an owning `with` and a `Task` in a law follow the frame rules of a function body. `assert` stands in a law body ([grammar](grammar.md#declarations) rule 11), but not in a function literal inside one (S108). An unused local is S110.
10. **Run by `ergo test`** (law-run-1). After the tests, the test build runs each law of the package in source order:
    - a top-level law once, over values of its parameters;
    - a law quantifies over each operation type it names: its owner, for a member law, and each parameter whose type is a non-generic operation type. It runs once per binding of those slots to providers, each a named type that declares the slot's type in its clause, directly or through an include ([Interface assignability](#interface-assignability) rule 1; a type whose functions merely match is no provider, EXC1), wherever the provider is declared (law-xpkg, G-exup-1, G-exup-3). A named type `P` whose operations take `*P`, as a mutable store's do, meets the slot only by its address (rule 5): it is a **borrow provider**, and each case builds its `P` as any provider's is built (its constructor `New<P>`, or a generated value) and binds `&P`, so a law over a store whose commands write it runs with no adapter (fu-law-ptr). A generic operation type has no borrow provider. The test build of package P runs a binding when P sees the law and every bound provider (P declares it or imports its package, at any depth, the prelude and std included) and no other package that P sees sees them all: the least package that sees the binding runs it, once in the module. So the laws a domain package declares on its operation type run in the `memory` package that declares its provider, and the std `fs.Files` laws run against a program's disk. A law with no slots runs in its own package. Each case builds each provider, converts it to its slot's type, binds it to that capability for the case (rule 7), and takes the other parameters. A provider is built as its package builds it: by its constructor, the package function `New<P>` whose one result is `P`, with no type parameters, no error or capability row and generatable parameters, when its package declares one (each case calls it with generated arguments, so each case starts from a fresh provider, and a record whose invariant only its functions keep is never generated around them; fs4, integration finding F3); else by a generator, with the construction authority of its own package. A parameter value is generated with the authority of the law's package. A law with no binding in its own package prints `law T.L runs where T has a provider: none is in this package or its imports`, which is not a skip: its own package's test names where it runs.
    - a member law of a generic operation type `G[T]` runs at each provider's instance (L4): the instance the provider's clause writes fixes `T`. So with `type IntCodec { pad int } implements Codec[int]`, `Codec.RoundTrip` runs for `IntCodec` at `Codec[int]`, and its `v` is an `int`: the run's values have the instance's types, and the one rule below decides the run on them. A generic provider, `Mem[T]`, fixes nothing and is no provider of the law, as it is none of a non-generic type's. A binding whose parameter has no generator at the instance is an error at the provider's implements entry (S108, LAW-UNFED): `law Box.Keeps, declared at box.ergo:3:6, cannot run at Fns: its parameter v has no generator at Box[func(int) int]: …`.
    - **Built honestly.** A provider record with a field private to its package, whose package declares a function of any name and rows whose one result is that record and that takes none, is built only by such a function, even where the law runs in that package and sees the fields. If a generated case cannot call a constructor (it fails, needs a capability, or takes what no case draws), a runnable named context in any package of the provider's module can feed the law by building the provider. The test runs under the context, not against a second, directly generated provider. Without such a context, the binding is unfed (S108 at the provider's `implements` entry, as below), not skipped. A case never runs on a value the constructor would refuse.
    - A provider whose constructor or operations call Go is a provider of the law, and its binding runs **natively**. The test binary's generated law harness holds `go.Foreign` for the provider build as the program entry gives it to `main` ([rows.md](rows.md) Entry 4). The case can call a `New<P>` constructor with drawable arguments, no failures and `go.Foreign` as its only requirement, even if the provider's operations do not call Go. A law body and a named context do not hold that authority. The run reports the ordinary seeded verdict, as any other law does. The check-time evaluator runs no Go, so `ergo check` reports the binding `native`, not passed, and gives the native replay command (runtime.md Tests 9).
    - **Under a context** (L5, stage 3; item 10c). A member law whose one slot is its owner `T` also runs once for each named context of the package under test that binds `T` (its own entry, an embedding or a `replace`), in the context's name order, after its provider runs: `ok law Photos.DeleteIdempotent under Live (100 cases)`. Each case copies the runner's environment, builds the context into it with the builder a `with Live` uses, so the provider is the one the program binds, made by its constructor with its arguments and its other capabilities in place, draws the parameters and calls the law. The context builds the provider, so the run's values are the law's parameters alone, and the one rule below decides its cases: a law with none runs once, `ok law Repo.Fresh under Live (proved: 1 case)`, one whose parameters can all be listed takes every value, and any other takes 100 (WG1 r4: a host law under a test's ambient started its processes 100 times; `TestLawUnderAContextTakesTheOneRule`). A law of a generic operation type `G[T]` runs at the instance the context binds, `G[Job]`, as it runs at a provider's instance. A case owns the providers with a `Close` its build acquires, as a `with` does ([resources](resources.md), Context ownership): when the case ends, on every path and after the law's last operation, it releases them, last built first, each once, and a release's defect fails the case as any defect does. A provider with no `Close` whose fields hold resources is released by its generated release, as at a `with`. A context whose release a case cannot run is a skip that says why: a release that needs a capability, by the provider's `Close` or a part's (a case has none outside the context), a provider that names a package `let` (the first case's release would close it for every later one), or a generic `Close` that takes witnesses, as `skip law T.L under Needy: its provider's release needs Console; a law case has no capability to release it with`. So is a context whose header's needs row is not empty ([rows](rows.md#context), Context 4): a case provides no capability from a `with` site, only `TestAmbient`, as `skip law T.L under Live: context Live needs {Clock} from the with site that builds it, which a law case does not provide` (CTX-ROWS-1; CTX-ROWS-3 makes it a check error). A context whose header's fails row is not empty runs: a case whose build fails is a failed case, "law context Live could not be built: Missing{…}", with its replay line, never a skip or a refutation (FALLIBLE-CONTEXT Design 4; CTX-ROWS-2b, `TestLawUnderAFallibleContext`); a rewrite law's run under it is a skip for CTX-ROWS-2c. `examples/chat/memory/tests.ergo` runs `server.Conn.HangupIsFinal` this way, under `oneConn`, a `memory.Server` each case closes. A law of another package runs under this package's contexts too: the package that declares the context sees the law. A provider whose values have no generator and that has no constructor runs only this way: when a context of the package that runs, binds the owner to a value of the provider's type, the run under it is the provider's run, and the provider is no skip. So a provider that takes another provider, an adapter over a contract, takes it as an argument and picks nothing; its test file picks one, as `cmd/NAME/main.ergo` picks the binary's: `let overMemory = context { limits.Limiter: NewLoopback(memory.NewMemory()) }` in `examples/limiter/loopback/tests.ergo` runs the `limits.Limiter` laws through the RPC wire (`ok law limits.Limiter.NeverOverdraws under overMemory (100 cases)`). Lint `with-at-entry` admits such a context only in `cmd/NAME/main.ergo` and in a test file, which may hold only unexported named contexts and the unexported lets they need ([tooling](../tooling.md#lint)). `TestLawRunSkips` holds it: a provider with no generator under a context that runs is fed by it; under a context that does not run, or that binds another type, its law is unfed, an error (check's `TestUnfedLawIsAnError`). `lower/law_run_test.go` holds it: in the generated property, half the providers are also bound by a named context, and the run under it fails exactly when its provider is the broken one. *Prior art:* Terraform's acceptance tests run against a configured provider, and Hedgehog's state-machine tests against a real implementation; Effect's `TestServices` swap a service for a test layer but state no laws; Gleam, ReScript and Elixir have no laws to run.

    **One rule decides each run** (MU6b; owner q39, one rule across the language). The values of a run are its parameters, and for a member law the provider first. When the type of each value can be listed, the run takes every combination of values once, and a run that holds is reported **proved**. A type can be listed when it is a `bool`, a record whose fields can all be listed, a union whose variants can all be listed, a type defined over one, or a tuple of them, and it has at most 256 values; a run can be listed when its cases, the product of its values' counts, number at most 4096. A run with no values has one case. Any other run, with a value of an unbounded type (`int`, `string`, a slice, a record with such a field) or past a cap, takes 100 cases generated with the generators of property tests ([runtime.md](runtime.md#tests) rule 3) and the run's seed, and is reported tested, never proved (NORTH_STAR pillar 4). The rule is the same for top-level laws, member laws and the laws with a body in a machine (rule 13), and for property tests, a test with parameters being a run over its parameters ([runtime.md](runtime.md#tests) rule 2; mu6c): `ok Name (proved: all N cases)`, `FAIL Name (case K of N, every value: …)`, or `ok Name (100 cases)`. A test with no parameters is an example and runs once.
    - A proved run prints `ok law Flags.Merge (proved: all 8 cases)`, or `(proved: 1 case)` for a run of one case. A listed case that refutes the law prints `FAIL law Store.Clears for Toggle (case 3 of 8, every value: provider = Toggle{on: true}, b = false): …`; the run stops at its first refuted case, so the case is the first in the order of the values (the provider, then the parameters in order, the last one fastest).
    - A tested run prints `ok law Store.PutCountsOne for Tally (100 cases)`.

    A false result names the expression that returned it, including the selected tail of an `if`, `match`, `catch` or `with`, not the law's declaration. Both check-time evaluation and the native test use this site. The declaration is related information (`declaration` in check JSON; an indented `law declared at file:line:column` line in the native report). A reachability law names its clause.

    For a law declared in the package being checked, an unfed parameter diagnostic names a top-level law as `L` and a member law as `T.L`, where `T` declares `L`: `law L cannot run: its parameter f has no generator: …` or `law T.L cannot run: its parameter f has no generator: …`.

    A case refutes the law when its body ends in `false`, a failure escapes it, or an `assert` in it fails. The report names the law, the provider, the case, the seed, the size, the provider value and each argument as Ergo literals: `FAIL law Store.PutCountsOne for Stuck (case 1 of 100, seed 7, size 0: provider = Stuck{at: 3}, n = -9): law refuted at main.ergo:4:2: the law is false`. A run that holds prints `ok law Store.PutCountsOne for Tally (100 cases)`, and each run counts as one test in the summary. A law no case can feed is an error at check time (S108, LAW-UNFED), never a skip: a law parameter with no generator, at the parameter; a provider whose values have no generator, that has no constructor and that no named context of a package of its module builds, at the provider's implements entry (or at the law, when only the law's package is the one checking). A contract's laws live with the contract and its providers in the packages that import it (`memory`, a file store), so a named context of any package of the module feeds the binding: `memory.Workspaces` feeds `work.Api.NewIsListedOnce` for `work.Tool`, and the run is the context's. A context of another module feeds nothing. The check of one package cannot see the packages that import it, so in a module the binding is judged over the module, by `ergo check DIR/...` and `ergo test DIR/...` of its whole module, `…; no named context of a package of module M builds one`; in every load the binding leaves its package's law runs, so `ergo test` of any package neither runs nor skips it (the contexts' runs are the law's), and a load of one package of a module, or of part of one, reports nothing for it. A binding of two other packages is the provider's package's to judge: the importing package neither runs nor skips it. A member law of an operation type that no package of its module provides, by a binding or a named context, is unfed too: an error at the law, `law Store.Kept cannot run: no package of module M provides Store, so no case runs it; …`, where a package of no module still prints `law Store.Kept runs where Store has a provider: …`. Std is one module for this rule: `llm/memory`'s contexts feed `llm.Model`'s laws for `Retry`, and the check of every std package (the std snapshot's build) judges them. A package of no module is a program of its own and reports at once (`check.ReportUnfed`; check's `TestStdIsOneModuleForUnfedLaws`; sketchfront's `TestUnfedLawIsJudgedOverTheModule`); a parameter with no generator at a provider's instance, at that entry; a named context under which the law's parameters have none, at the context. The error names the explicit fix: for a member law whose one slot is its owner, a named context that binds the provider, `law T.L, declared at FILE:LINE:COLUMN, cannot run at P: …; bind one in a named context of a test file, let Name = context { T: … }, and the law runs under it` (Under a context, above); for any other law, which runs under no context, the constructor, `…; a func NewP() P with no rows would build one for each case`. A generated type whose least value is deeper than 1024 levels (`check.GenRankLimit`) has no generator either. `check/unfed_test.go` (`TestUnfedLawIsAnError`) holds the rows. A law that cannot run for another reason prints `skip law T.L: …` with the reason and is not counted: a parameter of a generic operation type, or an owner whose type has a row parameter or a type parameter that operations constrain. The summary counts every skip (`PASS (2 tests, 1 skipped)`), and the examples gate fails a program whose `ergo test` prints a skip line that its `expected-skips` file does not list, so a skip is never silent (fs4). A refuted law fails `ergo test` (exit 1). A law that passes generated cases is reported as tested, never as proved (NORTH_STAR pillar 4); only a run over every value is proved. `lower/law_run_test.go` holds the generated runs: a generated property over operation types with one to three providers, one of them broken at random, shows that exactly the broken one fails, and `TestLawRunOtherPackage` that a false law fails, with its seed, in the package of a provider that another package's operation type declares the law of. `lower/machine_law_test.go` (`TestMachineLawTables`) holds the rule: generated top-level and member laws over generated types, the caps' edges among them (255, 256 and 257 values; 4096 and 4097 cases), are proved exactly when a reference count lists their run, refuted at their first listed case when false there, and tested otherwise. *Prior art:* QuickCheck and Hypothesis run a property over generated arguments and print the seed; Haskell's `quickcheck-classes` and Rust's `proptest` laws check a class's laws against each instance as separate tests, as a member law runs per provider here. SmallCheck checks a property over every value up to a depth, and Lean's `decide` proves a proposition over a finite type by evaluating every case; Ergo takes every value when the type is small and finite, by a fixed cap, and falls back to QuickCheck's generated cases otherwise, so the report says which one ran. Elixir's StreamData, Gleam's `qcheck` and ReScript's fast-check bindings only generate; none reports a proof.

    **At check time** (L7). `ergo check` runs the same runs of the root package, by the same rule, in the checker's process and with no Go build, when they are pure: it interprets the checked program, draws the same cases for the same seed, and decides a machine's reachability and invariant laws (`always`, `sometimes`, their predicate run as any function is) with the same explorer (rule 13). A run that reaches a capability, a task, Go code or a form the evaluator does not run is skipped with its reason, never passed; a run that exhausts the step or byte budget is incomplete. Its verdicts are in the check envelope's `evaluation` ([testing](../testing.md#check-time-evaluation)). *Prior art:* Zig runs `comptime` code under a branch quota and names what cannot run at compile time; Lean's `#eval` runs a checked term and proves nothing by it. Gleam, ReScript and Elixir run properties only in the host's test runner, so their checkers report no test verdicts.
11. **Lowering.** The `ergo run` build includes no law, top-level or member: the lowering emits no Go for a law body there. A law also adds nothing else to it: the checker records the facts of a law body under the law owner (`OwnerLaw`), and the run build does not read them. So an import, a package, a tuple type, a generic instance, a `with`, an adapter, a default or an error type that only a law uses is not in the Go of the run build. The properties in `lower/stage_e3b_test.go` and `lower/stage_lawtop_test.go` hold this, with no exception: the run build of a program is, byte for byte, the run build of the program with its laws removed. The test build reads the law facts (its view, `ViewTestBuild`, sees the tests' and the laws' owners) and lowers each law that runs to a Go function `func ergoLawX(env *Env, params…) (bool, error)`; a bare operation call in a member law calls the capability field of `env`, which the case sets to the provider. A law of a generic operation type `G[T]` lowers to a Go generic function in `G`'s type parameters, `func ergoLawX[T any](env *Env, own G[T], params…) (bool, error)`, as a generic function does ([Generics](#generics) 5); the case passes the provider as `own`, and calls the function with the instance's type arguments; a bare operation call calls `own`. *Prior art:* Zig compiles `test` blocks only under `zig test`; Go keeps `_test.go` files out of the package build; Rust compiles `#[cfg(test)]` items only in the test configuration; Elixir compiles `test/`, where StreamData properties live, only under `mix test`. Gleam, ReScript and MoonBit have no laws to erase.
12. Laws are declared where their quantifier is, not found by name; the `LawX` naming rule is gone. The same form serves every client: codecs, providers, schedules and machines, and plain functions at top level. *Prior art (placement):* Haskell has both places: QuickCheck properties are top-level `prop_x` functions, and class laws stand beside the class as documentation. Lean, Coq/Rocq, Idris and Dafny state a `theorem` or `lemma` at top level, and a class or structure carries its protocol's laws as fields. Elixir `StreamData` states `property "…" do check all … end` at the top of a test module, beside `test`. MoonBit puts properties in top-level `test` blocks with a quickcheck library; Gleam and ReScript have no laws. Ergo has the same two placements: a member law for a protocol, checked against its providers, and a top-level law for functions. It checks both as code and keeps them out of the binary as Zig keeps `test` blocks out of non-test builds.
13. **Machine laws** (MU6; decision 2026-11-03 (b)). A machine's laws follow its entries:

    ```go
    type Lights machine[Light, Tick] {
    	initial: Red,
    	step:    step,

    	law Cycles reaches Yellow,
    	law Safe never reaches Broken,
    	law Starts path [Red, Green, Yellow],
    	law OneLit always oneLit,
    	law Flashes sometimes flashing,
    	law NoDone(s Light, t Tick) { !ends(step(s, t)) },
    }
    ```

    - **Names.** A machine law's name is in its machine's namespace: a second law of a name in one machine is S108 "law X is declared twice". Its report names `Machine.Law`.
    - **A law with a body** is checked as a top-level law is (rules 2 to 9): its scope is its parameters, then the package. A law over one transition takes a state and a signal (`law L(s S, e E)`); a law over a signal sequence takes `signals []E` and runs the machine with `machines.Run` or `machines.Next`. It runs by the one rule of rule 10: when every parameter's type can be listed, the law runs once for every value and a run that holds is reported proved, `ok law Lights.NoDone (proved: all 12 cases)`; a refuted case prints `(case K of N, every value: s = …, t = …)`. Any other law runs over 100 generated cases and is reported tested, `(100 cases)`, never proved: a law that reads a payload of an unbounded type is tested.
    - **A reachability law** names variants of the machine's state: `reaches V` holds when some run reaches a state of `V`; `never reaches V` holds when no run does, the start included; `path [V1, …, Vn]` holds when some run's first n states are of `V1` to `Vn` in order. A target that is not a variant of the state is S108 "V is not a variant of S, the state of machine M". A run starts at `initial`, or for a machine with an input, at the start of any input. Each signal is an edge: `Enter`, `Stay` and `Emit` go to their `Next`; `Ignore`, `Reject` and a step failure keep the state; `Done` ends the run and is no edge. A timer's signal is a signal of `E`, so the runs cover the timers.
    - **Decided on the graph** (X1). When the starts and the signals can be listed and the state has a key, `ergo test` decides the law by a breadth-first search (runtime/explore) with a visited set of 128-bit hashes of each state's key. The key is a canonical encoding of the value: a record's fields in declaration order, a union's variant and its fields, a slice's length and elements, a Map's entries in a fixed order, a float's bits as they are; so two states have one key exactly when they are identical: `==` holds ([Operators](#operators) 1) and each float has the same bits. A merge is sound only when no step can tell the two states apart, and a step can tell `0` from `-0` (`"\(x)"` shows `-0`) and one NaN from another (`math.Float64bits`), so these stay apart, though `0 == -0`; every other part of a key is exact for `==`, since `==` on an integer, a bool, a string, a variant, a slice's length and elements and a Map's entries leaves nothing a step can read (a Map's iteration order is unspecified, so it is no part of the value). A NaN state is one state, though `NaN != NaN` (batch-15 X1 M1). A state that holds a function, an operation type's value, a Go type or a runtime handle has no key. The search stops at a budget of states, `ergo test --states N`, 1,000,000 by default; it counts states, edges and run lengths, and never reads a clock. A law is **proved** only when the whole graph was seen: `ok law Lights.Safe (proved: 3 states, 4 edges, longest shortest run 2)`, or with a witness, `ok law Lights.Cycles (proved by the run from Red with []Tick{Go, Stop})`. A counterexample or a witness is a shortest run: `FAIL law Lights.Safe (3 states, 1 signals): law refuted at main.ergo:9:2: the run from Red with []Tick{Kick} reaches Broken`, then, indented, an Ergo `test` that runs the same signals with `machines.From` and fails by itself (it names the import it needs when the file has none), and the command that replays the search for that law alone, `replay: ergo test main.ergo --law Lights.Safe --states 3` (X1b; it names the source as `ergo test` was given it, a file or a folder; every refuted law prints one, with the seed of its generated case when it had one). When the budget stops the search first, the law also runs over 100 generated runs (below) and passes with what was checked: `ok law Design.Safe (no counterexample in runs of at most 11 signals; 1000000 states; 100 runs; not proved)`; a scope that must be proved stays small enough to finish. When the starts or the signals cannot be listed, or the state has no key, the law runs over 100 generated runs from the run's seed, each with up to the case's size of signals (a keyless state says so: `(100 runs; the state has no key: …)`): `never reaches` is tested, `FAIL law Meter.NeverHigh (run 16 of 100, seed 7, size 4): … the run from Low{N: 0} with []Push{…} reaches High`; `reaches` and `path` hold at the first run that is a witness, which proves them, and fail when no generated run is one. When the state has a key and the signals are listed, a generated run picks at each step among the signals that change the state, so it does not spend its steps on `Ignore` and `Reject`. *Prior art:* TLC keeps 64-bit fingerprints of the states it has seen and reports the diameter; Quint's `run` samples random traces and keeps no state, so a deep counterexample (the children model's `epochWraps`, 13 signals) passes 250,000 traces that a search of 24,852 states finds.
    - **An invariant law** (X2; owner q76, 2026-11-10) names a predicate: `always p` holds when every state a run reaches satisfies `p`, the start included; `sometimes p` holds when some reachable state does. `p` names a package function of type `func(S) bool`, `S` the machine's state, with no error and no capability row, and it is pure: its footprint is empty ([rows.md](rows.md#footprints) 2), so the explorer may call it at any state any number of times and a run replays. Else S108: "the predicate p of law L must have the type func(S) bool, with no error or capability row: the explorer calls it at every state"; "the predicate of law L must be pure, since the explorer calls it at every state: predicate p calls a function value at 8:2"; a host function, or a name that is not a function, is S108 too. The state may be a record, since the law reads it through `p`. The law is decided as a reachability law is (above and below): `always p` as a never law whose target is a state where `p` is false, `sometimes p` as a reaches law whose target is a state where `p` holds; so a counterexample and a witness are shortest runs when the graph is decided. The texts: `ok law Counter.Small (proved: 5 states, 10 edges, longest shortest run 4)`; `FAIL law Counter.Tiny (4 states, 3 signals): law refuted at main.ergo:31:2: the run from Count{N: 0} with []Tick{Inc, Inc, Inc} reaches Count{N: 3}, where tiny is false`, then the counterexample's `test`, whose check is `assert tiny(r.State)`, and the replay command; `ok law Counter.Full (proved by the run from Count{N: 0} with []Tick{Inc, Inc, Inc, Inc})`, then, indented, the witness as an Ergo `test` that passes by itself (`assert full(r.State)` when the run ends running, `assert false` when it does not); `FAIL law Counter.Over (5 states, every run): … no run reaches a state where over holds (5 states)`. **A sometimes law with no witness when the budget stopped the search is not found, and fails**: `FAIL law Road.SomeGone (100 runs, seed 7; no run of at most 4 signals reaches a state where isGone holds; 5 states): … not found: no generated run reaches a state where isGone holds`. A search that stopped early proves no absence, but a sometimes law states that a state exists, and only a witness shows it; this is the rule `reaches` follows, and the opposite of `always`, which passes "not proved" at the budget (owner q77). `TestMachineLawTables` holds the rule: generated predicates over generated tables, both forms, against a reference breadth-first search, with the length of each counterexample and witness equal to the reference's shortest run. *Prior art:* Quint's `--invariant` is `always`, and its witnesses (an invariant expected to be violated) are `sometimes`; TLC's `INVARIANT` and Apalache's `--inv` are `always`; TLA+ writes `sometimes` as a negated invariant whose counterexample is the witness. Here both are named laws, and a witness prints as a test the owner can keep.
    - **Skipped**, with the reason: a reachability law of a machine whose step needs a capability, or whose start has a row. One whose state, signal or input has no generator is an error at the law (S108, LAW-UNFED).

    *Prior art:* effect-machine's `assertPath`, `assertReaches` and `assertNeverReaches` check hand-picked event lists in a test; here they are declared laws over every run. TLA+'s TLC and Quint check an invariant by breadth-first search of the reachable states and print the shortest counterexample trace; SmallCheck checks a property over every small value, as a machine law over listable types is checked over every value. XState's `@xstate/graph` enumerates the shortest paths of a finite machine for model-based tests. Gleam, ReScript and Elixir have no machine laws: OTP's `gen_statem` is tested by hand or with PropEr's `proper_statem`, whose generated command sequences are this rule's generated runs.
14. **Rewrite laws** (LR1; owner q108, q109 form B, 2026-11-11). A member law whose body is two blocks joined by `==` is a rewrite law: an equation between two straight-line uses of its operation type's own operations, which the compiler may use as a rewrite, the left block the pattern and the right block the replacement. Every other law is unchanged.

    ```go
    type Counter {
    	Add(n int),
    	Total() int,

    	law AddJoins(a int, b int) { Add(a); Add(b) } == { Add(a + b) },
    }

    type Text {
    	…
    	law SepAfterValue() when pos() == AfterValue { sep() } == { raw(",") },
    }
    ```

    - **Form.** `law L(params) [when R() == C] { lhs } == { rhs }`, as a member of an operation type `T` (a machine law of this form is S108; a top-level one is a rewrite law over functions, below). Each statement of a side is a bare call of an operation of `T`, `Op(…)` or `try Op(…)`: one to 3 on the left, at most 8 on the right; anything else is S108 "a rewrite law's left side is calls of T's own operations, one per statement". The guard `when R() == C` names `R`, an operation of `T` with no parameters, no failure and one result, and `C`, an expression with no parameter and no call (S108 otherwise). `when` is a word only after a law's parameters, and the guard parses as a control clause, so `C { … }` is `C` and then the left block.
    - **Parameters.** Each left argument is a bare parameter, and each parameter is a left argument exactly once: the left side binds it (S108 "parameter p is not bound by the rewrite's left side", "… is bound twice by the left side", "a rewrite law's left side passes parameters only"). A parameter that the right side uses inside a computed argument, `Add(a + b)`, is **constant**: a site passes a constant for it, and the compiler computes the argument at compile time. Every other parameter **passes through**: it is a bare right argument at most once (linear; S108 "parameter p passes through the right side twice"). A computed argument calls no operation and has no `try` (S108). A site evaluates its arguments in source order before the rewritten window, so a rewrite never reorders, drops or duplicates a user expression, though a side may drop or reorder a parameter.
    - **Rows.** Both sides fail with the same row: S108 "the sides of rewrite law L fail differently: {} on the left, {Missing} on the right; a rewrite keeps the failures".
    - **Unfolds.** An unfold law is a rewrite law with no guard and one left call. When an unfold law's right side reaches its own left operation through the unfold laws of `T` (a cycle), the first such law is S108 "rewrite law L unfolds Op into itself: an unfold law's right side unfolds again (a cycle)", so the compiler's rewriting ends.
    - **Meaning.** The law holds for a provider `P` when, from every state that a prefix of `T`'s operations reaches and that the guard admits, `prefix; lhs; cont` and `prefix; rhs; cont` read the same for every continuation `cont`: each result of `cont`'s operations, then each read operation of `T` (no parameters, one result), compared as Ergo literals; a failure is read as its text. This is observational equality, a congruence for sequencing, so rewrites chain soundly.
    - **The run** (rule 10). Each case builds a provider for each side with `P`'s constructor `New<P>`, from the same drawn arguments: a provider must be deterministic, and need not be copyable. A provider with no constructor is a skip, `skip law T.L for P: a rewrite law runs each side on a fresh provider, and only a constructor func NewP(…) P builds one`. A run under a named context (rule 10) builds each side's provider with the context instead, as a `with` of it does: `ok law Counter.Joins under Live (400 cases, prefixes up to 31 operations)`. It runs only when the context's entry for `T` calls the provider's constructor, so each build makes a fresh provider; an entry that is a `let` holding a provider would give both sides the same one, so it is a skip, `skip law T.L under Live: a rewrite law runs each side on a fresh provider, and only an entry that calls a constructor func NewP(…) P builds one`. A run takes 400 drawn cases. A case draws the law's parameters, a prefix of zero to 31 operations of `T` and a continuation of zero to four (those whose parameters have generators); the deep prefix is for a law that may drive code (the audit's law false only at a state nine operations deep is refuted in a case with chance 0.0436, so 400 cases miss it with chance 1.8e-8), runs the prefix on each provider, then the guard, then each side's block and the continuation. A case whose guard is false is not admitted and not counted; a guard that reads differently on the two fresh providers refutes the law ("the provider is not deterministic"); a run with no admitted case is a skip, never a pass. Two sides that read differently refute it: `FAIL law Counter.AddMul for Tally (case 1 of 400, seed 3, size 0: provider = NewTally(), a = 1, b = 0, prefix = [], continuation = []): assert failed at main.ergo:8:2: the sides read differently: left 1; right 0`. The prefix and the continuation are sequences, an unbounded value, so a run is **tested, never proved**: `ok law Counter.AddJoins for Tally (400 cases, prefixes up to 31 operations)`, the number of admitted cases and the deepest prefix a case ran (the receipt entry's `deepest`). To the drawn cases a run adds 40 cases at each **site instance**, the constants at which a module's lowering used the law, with the other values drawn; its receipt entry ([runtime](runtime.md#tests), Tests 8) has `"rewrite": true`, `admitted` and `instances`. Check-time evaluation (L7) skips a rewrite law: its run builds two providers. `lower/rewrite_law_test.go` (`TestRewriteLawVerdicts`) holds the rule: generated operation types over a two-bit state machine, each provider built by its constructor and run against every type, get from the runner the verdict a reference model decides by exhaustive search (state equivalence by partition refinement, every reachable state, every parameter residue, each injected instance).
    - **Value-provider proof** (PS1; q120). For a named record `P`, a law run owns the record and lends it to its `*P` operations; by-value operations read the same value. This is law discovery, not an implicit conversion to an operation-type value (such a conversion remains S108 until provider cells). The record is the state: no projection or independently written model supplies evidence. It has a key exactly by the X1 state-key rule of rule 13; a field holding a function, operation-type value, Go value or runtime handle has no key and cannot prove a rewrite. Each result of a side is compared by the same key rule, in order; unequal result sequences refute the law even when the final state agrees. A result without a key does not prove a law. The runner checks every reachable operation body and helper for an Ergo body with no `needs` or `fails` row; a foreign or indirect call does not prove a law. In PS1 a law parameter must be listable; symbolic values are not supported yet.
    - **Coverage and equality.** When every operation parameter and constructor input is listable and `P`'s construction is closed (Proved states, below), the runner starts at every constructor result and closes the states under every operation and argument tuple, breadth first. Each law argument tuple runs from every reached state its guard admits. Both sides run the provider's own lowered bodies, each on a separate value copy, and must end with identical X1 state keys. A guard that changes state is not proved. No constructor, an open construction, or an unlistable operation parameter: every combination of the record's finite field values is instead a conservative superset. A false case in reachable search is `FAIL` with its state and path, and refuses the build; a false case in the superset is `not proved: false at a state which may be unreachable`, never a refusal. No finite field product means not proved. The state budget is `--states N`, 1,000,000 by default; reaching it is `not proved: explored N states, depth D`, never proof. A complete true run prints `ok law Counter.AddJoins for Wheel (proved: all 1000 cases)` for the ten-state, two-Digit counter. The drawn, deep-prefix runs above remain the tested report for unkeyed providers, never evidence that changes code.
    - **Proved states** (LR-sound; v1 audit 3, G1). A rewrite applies to any value of `P` at a site, so a proof covers every value the program can hold. The search from the constructor stands for that only when `P`'s construction is **closed**: every field of `P` is unexported (so no other package builds or writes one, Zero values 6), no field holds a `P`, no operation takes a `P` besides its receiver or returns one, and in `P`'s package, outside the constructor's and the operations' bodies, no literal or record update builds a `P`, no conversion makes one from a type defined over it, and no expression writes a field of one (an assignment to it or into it, its address, or an argument a function takes by borrow, a dot call's receiver included). A record with fields has no zero value (Zero values 2) and a record with an unexported field has no derived codec (Codecs 1), so neither builds one; a `ParseP` is an ordinary function and is checked as one. When the construction is open, the run lists every combination of field values, as with no constructor: a law false only at a state the constructor never reaches is `not proved: false at a state which may be unreachable; the proof covers every value of Tally, not only the states NewTally and its operations reach: a literal builds one at main.ergo:50:14`, and `ergo inspect` gives the same reason in the site's `why`. The rule is checked by `lower/construction.go`, `TestConstructionModel` (a model of every form) and `TestProvedRunsModel`; `TestRewriteAgrees` builds providers by literal, update and field write. *Prior art:* Lean 4 `@[csimp]` proves the equation for every input of the type, so no reachable-set question arises; Rust and Koka take a type invariant from constructor privacy, which is the closed rule here; Gleam's `opaque` and ReScript's `private` types keep an invariant to the constructors; GHC `RULES` trust the author.
    - **Symbolic runs** (PS2; plan-2 §1 rule 3). When a law parameter cannot be listed, when there is no closing search (no constructor, or an unlistable operation parameter) and a field of `P` cannot be listed, or when a side reaches a function with no Ergo body, the test build's verdict comes from a symbolic run of the check-time evaluator, fixed when the test build is lowered. Each listable field and parameter is listed; each other one is a **symbol**, which stands for every value of its type. Both sides run `P`'s own Ergo bodies from the same state, through the record lent to its `*P` operations. Only these forms take a symbol or a term: a binding, an argument, a result, a record or tuple part, a field write, a read of a field of a record that holds one; `+` on strings and `xs.Append(x)`, which build a concatenation in normal form (flattened, adjacent constants joined, empty parts dropped, the order kept: concatenation is associative, not commutative); and a call of a rowless, non-generic `extern go` function with at most one result, which is the uninterpreted term `f(args)` and is never run (a rowless function is a function of its arguments). A term in any other place stops the run: `not proved: sep branches on t.out at json.ergo:88` for a condition, a match or a case, `not proved: f computes with t.out at …` for every other place (a comparison, another operator, an index, a conversion, `len`, an interpolation). A function with a needs or fails row, a Go import, a package `let` and every other evaluator stop are `not proved` too. A case holds when both sides end with identical terms (symbols by identity, floats by bits) and identical results; the law is then proved for every value of each symbol, `ok law T.L for P (proved: 4 cases, symbols out a b)`. Different terms are `not proved: the sides end in different terms at state …`, never a refutation: the terms may be equal by an identity the run does not know, and the listed states are a superset of the reachable ones.
    - **Over functions** (LAWFFI LF6a). A top-level law `law L(params) { lhs } == { rhs }`, each side one expression, is the property `lhs == rhs`: it is checked, run by `ergo test` and lowered as that property. It is also a rewrite of `lhs` into `rhs` when it is in the rewrite's scope, which the checker decides after the footprints; a law outside it is S108 "law L is no rewrite: …; write { lhs == rhs } for a property", naming the first rule it breaks, in this order:
        1. *Shape.* The left side is a call tree of declared functions, conversions and `len` over the parameters and constants, with `try` and parentheses, and every parameter occurs in it ("parameter b does not occur in its left side, which binds every parameter"); the right side uses only the parameters, constants, such calls and operators. The **root function** is the first declared function the left side calls, outermost first: `Encode` in `len(Encode(s))`.
        2. *Fewer rewritable calls* (LAWFFI LF2m). The pair (calls of Ergo bodies, calls) is smaller on the right than on the left, compared in order: fewer calls of Ergo bodies, or as many and fewer calls. A Go body is a leaf the rewrite never unfolds, so `{ indexByteRef(s, c) } == { indexByte(s, c) }`, an Ergo reference to its Go body, is a rewrite, and so is `{ Unquote(Quote(s)) } == { s }` over Go functions, from (0, 2) to (0, 0). The pair is one well-founded measure: each rewrite makes it smaller, so rewriting ends, and `f(a, b) == f(b, a)` is no rewrite.
        3. *No guard.* No parameter takes a `where`: a law true only under a guard stays a property. A `when` on a top-level law is S001.
        4. *Pure.* Each function a side calls is an Ergo function with an empty footprint and no `needs` row, or a Go function in the reviewed pure set (a `runtime/v1` body marked pure, a function of a `PureImports` package), or an effect-free body of the module's own Go ([interop.md](interop.md), Trusted Go 3; LAWFFI LF2m), which no review makes pure: the rewrite applies only on the law's current validated entry, so the law is what admits it; a `fails` row is allowed.
        5. *Value class.* The sides' type has key equality and holds no pointer, operation type, function, type parameter or Go type.
        6. *Failures.* The right side fails nothing the left side does not: a rewrite may remove a failure, never add one.
        7. *No orphan.* The law is declared in the package of its root function.

      - **Over function parameters** (FUSION; owner q234, "Extend laws", 2026-11-18). A top-level rewrite law may take type parameters of its own and parameters of a function type, and its right side may hold function literals: `law TransformFuses[T, U, V comparable](xs []T, f func(x T) U, g func(x U) V) { Transform(Transform(xs, f), g) } == { Transform(xs, func(x T) V { g(f(x)) }) }`. The rules above apply with these readings:
        - Rule 1: a function literal stands only on the right side ("its left side is a call tree, and a function literal is not a call"). Its body is one expression over its own parameters and the law's. It may call a function parameter of the law, and no other function value.
        - Rule 2: a call of a function parameter is no declared function's call and is not counted.
        - Rule 4: a function parameter's type fails nothing and needs nothing ("parameter f is a function that fails or needs, and a rewrite's functions are pure: …"). A function whose footprint holds only calls of its own function parameters (rows.md, Footprints 3) is pure when each such argument's type has empty rows.
        - Rule 5: each of the law's type parameters is read at `int`; a site's types are checked where it is matched. The sides compare with `==`, so the type parameter of the sides' type is `comparable`.
        - The parser takes type parameters only on such a law: on any other top-level law they are S001 at the `[`.

        Such a law is not run as a property. `ergo test` prints a note for it, not a skip: `law TransformFuses runs as its licence run (ergo.laws): a law with type parameters of its own runs as its licence run, at int, not as a property` (LICENCE-ADT). Its evidence is the licence run (FUSION-EVIDENCE, `eval/licencefuncs.go`; [runtime.md](runtime.md#tests) Tests 7):
          1. It runs at `int`: each of the law's type parameters stands for `int`, wherever it occurs. That includes a slice's element, a generic union's instance (`Maybe[T]` is `Maybe[int]`) and a recursive union's nodes (`Tree[T]` draws `Tree[int]` values of any depth, down to the union's finite variants). A union's classes are its variants, so a `Tree`'s `Leaf` and `Node` are each reached (LICENCE-ADT).
          2. A function parameter takes a family of pure functions as its classes:
             - for `func(int) int`: `func x`, `func x + 1`, `func x * 3`, `func 7` and `func defect at odd x`;
             - for a predicate: `func x > 0`, `func x is even`, `func true`, `func false` and `func defect at x < 0`;
             - for a two-parameter step `func(a, x int) int` (a fold's): `func a + x`, `func a * 3 + x`, `func a`, `func x`, `func 7` and `func defect at odd x`. Its members tell the arguments apart, so a law that swaps a step's arguments is refuted (LICENCE-ADT);
             - for `func(a, x int) bool`: `func a < x`, `func a == x`, `func true`, `func false` and `func defect at x < 0`.

             Each member is reached alone and paired with each class of the other parameters, and a drawn case takes one at random. A function type with no family makes the run skipped.
          3. The right side's outcome is read as the site gives it under `v1.FuseOr`: a defect of the right side gives the left side's outcome. A defect the left side raises and the right side does not refutes the law.
          4. A refutation names the family members (`f = func x + 1`). It writes no corpus line, since no corpus text holds a function.
          5. **A skipped licence fails the test** (AC10, LICENCE-ADT). A rewrite law in scope must have a verdict. When its licence run is skipped, `ergo test` still writes the skipped entry, then fails with a line naming the reason and its fix: `FAIL licence law main.TwiceUnfolds: skipped: the run has no family of pure functions for f func(s string) string; state the law over functions whose parameters and result are int or bool, the families the run draws`. A skipped entry is never current, so the next `ergo test` runs the law again. Std holds no skipped licence: `go run ./scripts/stdlaws` fails on one.
        Its verdict, validated like any licence run's, is what admits it at a site.

        **Its sites** (FUSION-LOWER, `lower/ir_fusion.go`). Such a law is matched at the call, from the call's source, before the call is lowered, and not by the pass's IR patterns: the IR of a call with a function operand depends on the operand (a known callback's call goes to its known variant). A call is a site when the law's left side and the call are calls of the same functions at the same shape, and their types unify; that binds the law's type parameters, and the sides are lowered at the site's types. The same decision applies as at any site (`rewriteAt`), with three additions:
          1. Each operand is lowered once, in the order the left side evaluates it, before either side.
          2. The run build places the right side under `v1.FuseOr(right, left)`. The fused form runs the law's functions in another order (`f`, then `g`, per element, where the staged form runs `f` over every element first), so it may meet a later stage's defect first. On a defect, `FuseOr` runs the left side again, from the start, at the same operands. The law's functions are pure, so the rerun raises the staged form's own defect, the first in stage order.
          3. A site whose operands could show the order keeps its left side, in the run build and the test build. These are: an operand of a function parameter that is not a declared function or function literal with an empty footprint, or a literal that assigns a variable it captures (`not applied: the operand of f is not a pure function literal or function, so the fused order could show`); and an operand that the left side evaluates after a stage, unless it is a name or a literal (`not applied: the operand of k runs after a stage in the left side, and the fused form would run it first`).

        Std `slices` states four such laws: `TransformFuses`, `FilterFuses`, `TransformThenFilter` (to `TransformFilter`, one loop) and `FilterThenTransform` (to `FilterTransform`).

      - **Fallible laws' sites** (ENCDEC, `lower/ir_unfold.go`). A law whose left side is `try` of a call and whose right side holds no `try` (std's inverse laws: `law AtoiInvertsItoa(n int) { try Atoi(Itoa(n)) } == { n }`) is matched where the build binds a fallible call, under `try` or `catch`, from the call's source. Where the law's left side and the site differ, the site unfolds:
        1. A call of an Ergo function whose body is one call (at the site's top, `try` of one call), not generic and with no receiver, is its body, with the function's parameters standing for the call's operands. The body is matched whole, so it runs nothing the left side does not.
        2. A name a `let` (not `let mut`) bound in the body being built is its value.
        3. A law parameter binds an operand in the site's own source. One reached through a `let` must be a name that keeps its value or a literal, since the `let` already evaluated it ("not applied: the operand of n is a let mut, which may change between the let and the site"; "… is reached through a let, and the right side would evaluate it again"). The `let` itself still runs.
        4. The run build replaces the call by the right side at the bound operands; under `catch` the error is nil. The test build and a canary keep the site as written.

        So `let line = Encode(value); …; try Decode(line)`, with `Encode` and `Decode` one-call wrappers of `strconv.Quote` and `strconv.Unquote`, is a site of `strconv.UnquoteInvertsQuote` (`examples/wtcache`).

      A law over Ergo functions only is in scope as one over Go functions is (owner q195). Its ledger entry, `law <pkg>.<L> <verdict> [by <run>] [with <keys>] h1:…`, is keyed by the tokens of the law and of every declaration either side reaches, transitively, and by the foreign key of each Go function it reaches, so an edit of any body the law reaches makes the entry stale ([facts](facts.md#evidence) Evidence 3). Std states ten such laws (`strconv.UnquoteInvertsQuote`, `strings.TrimSpaceIsIdempotent`, `hex.EncodeDoublesLength`, …). The licence run that validates one is LF6b's ([runtime.md](runtime.md#tests) Tests 7).
      - **The engine** (LF6c; IR path only, `lower/ir_rewrite.go`; a pass on the IR since LF6p, `lower/ir_rewrite_pass.go`). The builder lowers every call as written; the pass runs on each IR body before its forms are erased. A call tree of the body's IR that is a law's left side's IR (the same Go calls, conversions and `len`, the same constants, and at each parameter an operand of its Go type; a parameter that occurs twice takes the same local or constant twice) is a **site**, wherever the IR holds it: an operand, a placed body, another law's right side. One decision, `rewriteAt`, takes three forms. The run build lowers the right side where the law's entry is current and its level admits a value-class change ([facts](facts.md#evidence) Evidence 2). The reference (`rewriteLowering=reference`) and `ergo build -rewrites=off` lower the left side; `-rewrites=proved` admits a proved entry only; `-rewrites=on` is the default. The test build lowers `shadow.Shadow(left, right, …)` (the runtime leaf `runtime/v1/shadow`) at every matched site, also one whose entry is stale or missing and one inside a dependency the test reaches: the site's value is its left side's, the right side is evaluated after it, and when key equality (floats by their bits, a NaN equal to a NaN; slices, maps, records and variants by their parts) tells them apart, the site raises the defect `law main.UndoBad is false at main.ergo:15:27: Undo(Bad(s)) gave "abx", and the right side gives "ab"`.
        1. Each matched operand is evaluated once, in source order, into a temporary (a local or a constant is read where the side reads it), so a rewrite never drops, repeats or reorders a user expression. The temporaries, and any statement a right side, a canary or a shadow needs, go right before the statement that holds the site, and only where that keeps the program's order: the statement evaluates the site once (not a loop's condition, not a case's value), the site is not in the right operand of `&&` or `||`, and nothing the statement evaluates before the site can fail (a call, an index, a division). Elsewhere a site rewrites only when its operands are locals or constants and its right side needs no statement; otherwise it reports `not applied: the site's statements would run before code that may fail, or the site is evaluated more than once`. A right side the run build placed is a site too: with `law IdId(s string) { Id(Id(Id(s))) } == { Dec(Enc(s)) }` and `DecEnc`, `Id(Id(Id(t)))` becomes `t`. A right side makes fewer calls than its left, so this ends. A canary's and a shadow's sides are compared as the laws state them, never rewritten.
        2. A call tree inside `AsWritten(v)` (prelude: `v`) is never the root or a part of a match. The matcher knows it by the line `// ergo:aswritten` in its doc comment, never by its name: any function so marked keeps its argument's call tree the same way, a user's as std's (owner q230, AW-ERGO). The checker accepts the line only above a pure identity of one parameter (`func Keep[T](v T) T { v }`: no receiver, no extern, one result of the parameter's type, empty rows, a body that is the parameter), else S108 ([diagnostics](diagnostics.md)), and the lowering never inlines a marked function, so its call stays a call while the laws rewrite. Its site keeps the left side and reports `not applied: AsWritten`.
        3. Only an IR body rewrites, and a law with a `try` in a side is not matched: the text emitter is frozen (IR-ONLY). A site in a body that keeps its source body keeps its left side and reports why.
        4. `ergo inspect rewrites FILE [--json]` lists each site: `main.ergo:7:27  main.DecEnc  validated by eval  current  applied`. The producer record counts the rewrites applied, those over functions by level.
        5. The matcher reads the law's sides as the builder lowers them, never a function's or a package's name.
        6. **The canary** (LF6d). `ergo build -rewrites=canary[=N]` (N is 1,024 when not given) is `on`, and each rewritten site has a counter: on each N-th call at the site, the site evaluates its left side too, at the same operands, and compares. A difference is a defect that names the law and the site and no value: `law main.DecEnc is false at main.ergo:12:27: the canary evaluated both sides of the rewrite, and key equality tells them apart`. It is a defect, not a log line: the law is false, and the site's other calls return wrong values. Where Go's `==` is key equality (a bool, an integer, a string), the site compares itself and stays small enough for Go to inline: 5 instructions per call over the plain rewrite, counted on `Dec(Inc(x)) == x`. A float or a composite is compared by `shadow.Canary`, a call. The producer record names the mode (`; -rewrites=canary=N`).
        7. **A shadow's refutation is a ledger fact** (LF6d). A test build's shadow that finds its law false writes `ergo-shadow: law <law> refuted (<case>)` to standard error before its defect; the defect says the arguments (`…, for s = "zq-17"`). `ergo test`, passing or not, writes the law's entry `refuted by shadow` at the sources' digest and the case into `ergo.cases` ([runtime.md](runtime.md#tests) Tests 10). So the run build stops on it, a later licence run of the same sources keeps it, and once the sources change the licence run takes the case first. A law of another module (std's) is named and not written: its own ledger holds it. A parameter of a listable type has no case at run time (its text is a class index), so such a refutation writes the entry alone.

Test: `TestFunctionRewriteShapes`, `TestFunctionRewriteRows` (`internal/sketch/check`), `TestFuncLawEvidenceKeysReachedBodies` (`internal/sketch/lower`). *Prior art:* GHC `RULES` (an unchecked left-to-right equation, in force in every importing module); Lean 4 `@[csimp]` (a proved one); neither Gleam, ReScript nor Elixir rewrites a call by a law.
    - **Use.** The lowering applies a rewrite law at a site only with evidence for the receiver's provider: the law's ledger entry is current and its level admits a value-class change, proved, or validated by a named run ([facts](facts.md#evidence) Evidence 2; owner q192 to q195, superseding q115's proved-only rule in part; a tested run is reported, never acted on). A tested run gives the reason `law T.L for P is tested, not proved: only proved laws change code`. The mechanism is open to every type, std or user.
    - **Windows** (LR2). The run build rewrites a *window*: consecutive statements `x.Op(args)` on one local `x` whose type is a provider `P` of `T`, so the provider is known. Each call has no result and no failure, its parameters are basic, and each argument is a constant or a local. Any other statement ends the window. The receiver and each non-constant argument are read into temporaries in source order where the window starts, so a rewrite never reorders, drops or repeats a user expression. The rules run to a fixpoint in a fixed order: unfold laws, then guarded laws, then every other law, and again while one applied. A computed argument of the right side is computed at compile time by the check-time evaluator from the site's constants; when it cannot be, the law does not apply. The engine counts its work, and a window past 64 units per call keeps the reference lowering. The matcher reads the laws, the operations and the provider's conversion only, never a name. On the IR path (LF6w, `lower/ir_window.go`) the same engine runs as a pass on each IR body, before the rewrites over functions: a window is a run of call statements whose call facts name such calls on one provider local, and the rewritten calls are written from the window's own call nodes. Its arguments are locals and constants, which no call of the window assigns, so the result reads them where the window did. A window whose laws call a function no call node of the window can write (another call kind, environment or receiver) keeps its calls.
    - **Unfold by definition** (LR3, from PS2; `lower/unfold.go`). A window call of a provider function whose body is a straight line of calls of the provider's functions on its receiver, each argument a parameter, a constant, or an expression the check-time evaluator folds from the call's constants (`head(3, uint64(len(s)))` at `s = "id"` passes `2`; NOPRIV-JSON), is the same as that line, so the engine replaces the call by it with no law: a definition is its own proof. An `if` whose condition the check-time evaluator folds from the call's constants is its taken arm; any other statement (an `if` on the state, an extern call, an assignment) keeps the call. A body that is one `if` on a pure function of its parameters, both arms straight lines, is emitted as that `if` around the two rewritten lines. Unfolds are bounded by 8 per call of the window, so a recursive definition stops. So a law that only restates a body (`Int(n) == { sep(); intBody(n); setComma(true) }`) is not written: std json's `Text` states only the laws a body does not give (`SepAfterSet`, `RawJoins`, `PlainIsRaw`, `SetCommaLast`, `SetCommaSinks…`), each proved. *Prior art:* GHC's simplifier inlines a definition and then lets RULES fire on the result; Lean's `simp` unfolds by a definition's equation lemma.
    - **Post laws.** An ordinary member law `{ Op(params); R() == X }`, `X` a constant or a parameter, is a fact for the guard: after a window call of `Op` whose arguments make `X` a constant, `R()` is `X`. Any other call forgets every fact, and a window starts with none. A post law gives a fact only when its ledger entry for `P` is current and proved; its check run, unlike the plain run of `ergo test`, starts each of its 400 cases from a drawn prefix of up to 31 operations, as a rewrite law's does, since the fact is used after the operation from every state.
    - **Evidence: the law ledger** (LL1; owner q116, q122; [runtime.md](runtime.md#tests) Tests 10). The build reads its evidence from checked-in files and never runs a law: `ergo.laws` beside `ergo.mod` and the std ledger. A law applies for `P` at a site only when the entry for the law and `P` is current (its digest is the one the sources give, and it lists the site's constants) and its verdict is proved; else the site keeps the reference lowering. `ergo test` writes the entries: it lowers the run build to learn the laws and the site instances it would use, builds the test build with those instances as cases of their own, and runs each such law alone (`--law`, seed 1). A run that ended `ok (proved…)` for `P` is proved; one that ended `ok` over drawn cases is tested; a reachable refutation fails `ergo test` and writes no entry. A refused law changes what the lowering asks for next, so the writer lowers again with the verdicts and checks what is new, at most three checks. Only the laws that the root package's test build runs are checked; a law and provider that only an imported package's test build runs keep the reference lowering. The test build never rewrites.

    *Prior art:* GHC `RULES` rewrite calls of a library's own functions by equations the author states, and "GHC makes absolutely no attempt to verify that the LHS and RHS of a rule have the same meaning" (GHC user guide, Rewrite rules); here a rule is a law, run against each provider. Lean 4 `@[csimp]` replaces a function in compiled code only by a proved equation, and simp and Coq's `autorewrite` orient proved equations left to right, as this form does. Alive2 proves LLVM's peephole rewrites before they enter the compiler. Elixir's Jason escapes keys at compile time by a macro, and ReScript folds string concatenation of constants in its IR (`js_exp_make.ml`); Gleam folds constant expressions and leaves the rest to the host. None of Gleam, ReScript or Elixir checks a user's rewrite.
15. **Placement in a file** (LAWLOC; owner, 2026-11-15: "laws being in their own file is kind of an anti-pattern. Because they're really tied to implementation"; "maybe we should make this rule about laws a sort of a language level construct"). A law states a rule about declarations of its own package, its **subjects**, and stands beside one of them (`check/lawplace.go`):
    - **Subjects.** A top-level law's subjects are the declarations of its package that its parameters or its body name: functions, types and their operations, variants, fields and dot-called functions, package lets and contexts. A member law's subject is its operation type and a machine law's its machine, which declare them, so they always hold; a law the parser derives (a refinement's or a codec pair's) stands at its declaration.
    - **Helpers.** A law helper is an unexported declaration every user of which is a law, a test or another helper: a function other than `main` with no receiver, an unexported package `let` or context, or an unexported type with no `extern`, origin or `derive`, with the functions dot-called on it. An exported function dot-called on a package type is the package's surface, never a helper. A helper is not a subject; the subjects it names, at any depth, are the law's, after those the law names itself. So helpers never pin a law to a file of their own.
    - **The rule.** A top-level law stands in a file that declares one of its subjects. Else S115 at its name names each subject's file: "law Fresh is about Add (shelf.ergo) and Len (count.ergo); state it in one of those files". A law with no subject in its package (it names only the prelude, std and imports) is S115 "law L names nothing in package P; state it in the package it is about". A law in a test-only file follows the same rule. A package with another diagnostic gets no S115, since an unresolved name is no subject.
    - **ergo fix** moves a misplaced law into its main subject's file, after that declaration: the subject whose name is a word of the law's name, earliest (`SortPermutes` goes beside `Sort`), else its first subject. Each helper goes beside the first law or test that uses it, with the imports they need. In a file named for laws (`laws.ergo`, `tree_laws.ergo`), an exported declaration that only laws and tests use was written for them too: fix moves it the same way, and unexports such a function, unless it is dot-called, another package names it, the rename adds a diagnostic, or the package is std. A file left with no declaration is deleted. A file named for laws that is left holding other declarations is renamed by its concept: its first machine, else its first exported type, else its first type, else its first exported function, else its first other named declaration, in lower case; one left holding only tests is a test file, `tests.ergo` (FIX-LEFTOVER: it was named after the Go type of the test's declaration and reported deleted). When the package already has a `tests.ergo`, those tests go into it, after its own declarations, with the imports they need, and the file of laws goes: `moved tests T from OLD to tests.ergo`. A name another file of the package has keeps the file's own, and the report says `renamed OLD -> NEW`, never that the file was deleted. A move changes no verdict: `ergo test` runs the same laws, and the law ledger's digest has no position (runtime.md, Tests 10).

    *Prior art:* Rust keeps unit tests in a `mod tests` of the file they test, Zig a `test` block beside its function, Go its tests in `_test.go` files of the package; none checks the placement. Elixir's doctests sit in the function's `@doc`. Idris states an interface's laws in the interface. Ergo checks the placement, since a law is part of its subject's contract.

15. **A where over earlier parameters** (CONSTRAINTS C5, owner q218). A law parameter's `where` may name the earlier parameters and the operations of the law's type: `law EqualKeysHashEqual(a K, b K where Equal(a, b)) { Hash(a) == Hash(b) }`. It is an *admission*, not a refinement: the checker keeps it as a law of its own over the parameters up to it (`check.Law.Admit`), and a generated case runs only when every admission holds. A parameter whose where names an earlier parameter of an identical type is found by search, not by rejection ([runtime](runtime.md#tests) Tests 6): the run lists that earlier value's near variants and takes the first the where admits and that is not identical to it. The run reports how many admitted cases had a searched value distinct from its source, `ok law Hashing.EqualKeysHashEqual for FoldCase (100 cases, 55 with distinct admitted values)`, and **a run with none is a skip, never a pass**: its equal values were all identical, which say nothing about the law. The check-time evaluator does not run such a law yet (its obligation is skipped: "a where over earlier parameters: ergo test runs it"). A law of the prelude is named bare in every report (`Hashing.EqualKeysHashEqual`), as its names are written.

## Maps

Status: **implemented** for rules 1 to 6 (CONSTRAINTS C5, C5b and C5d, owner q218 "Accept providers"); rule 7 lists what is not built yet.

1. **The type.** `Map[K, V, H]`, with `H` bound by the prelude's operation type `Hashing[K]` (`Hash(k K) uint64`, `Equal(a K, b K) bool`, `NormalForm() bool`, `NormalKey(k K) K` (rule 6) and six laws: `Equal` is reflexive, symmetric and transitive, equal keys hash equal, and under a normal form a key is `Equal` to its normal key and equal keys have one normal key), is the Map that finds its keys through `H`. `Map[K, V]` is `Map[K, V, Structural[K]]`: one type with two spellings. `Structural[K comparable]` is the prelude's provider of `==` and `hash`. An `H` that does not implement `Hashing[K]` is S108 "Plain does not satisfy the constraint Hashing[string] of Map's H: …". `K` stays `comparable`, since a Map iterates in the sorted order of its stored keys (owner q104).
2. **One provider, one type.** Two Maps with different providers are different types: an assignment, an argument or a return across them is S108 "cannot use Map[string, int, FoldCase] as Map[string, int]: the two Maps find their keys through different providers, FoldCase and Structural[string]; build one from the other's entries (types.md, Maps)".
3. **The same forms.** `m.Get(k)`, `m.Put(k, v)`, `m.Delete(k)`, `m.Take(k)`, `m.Clone()`, `len(m)`, `m[k] = v`, `for k, v in m` and a literal `Map[K, V, H]{k: v, …}` mean for every provider what they mean for `Map[K, V]`, with `H.Equal` in place of `==`. A key keeps the spelling it was first put with (`Host`, then `HOST`, stores `Host`), and `for` visits the stored keys in sorted order. A Map holds one value of `H`: `Map[K, V, H]{}` holds `H`'s default, and is S108 when `H` has none, naming `maps.Using[K, V, H](by)`, the empty Map with the provider `by` (the prelude's `MakeMap`, as `MakeSlice` is the empty slice); `m.Using(by)` is `m`'s entries put again under `by`. `a == b` of two Maps of one type holds when they have the same keys under `H.Equal`, each with an `==` value (so `V` is comparable); the checker writes it as `a.Equal(b)`, and `!=` as its negation.
4. **hash.** `hash(k)` is a predeclared function, as `len` is: for a value of a `comparable` type it is a `uint64` such that `a == b` gives `hash(a) == hash(b)` (`0.0` and `-0.0` included), generated from the declared type as `==` is. It is seeded once per process; its numbers differ between runs, and nothing a program prints by default, no Map order, codec or law verdict reads them beyond their equality. Lowering: Go's `maphash.Comparable` under one `maphash.MakeSeed()` per process. Go's maphash takes no seed from a number, so `ergo test` cannot fix it from its own seed.
5. **Lowering.** A `Map[K, V]` is Go's `map[K]V`, unchanged. A Map with any other provider is the prelude's record `hashTable[K, H, V]`, written in Ergo, one type for every provider (C5d). By `H`'s `NormalForm()` it holds its entries in Go's own map keyed by `NormalKey(k)`, each entry holding the key as first put (rule 6), or in a table: one array of slots, each free or holding a key and its value (MI-1's IntMap layout), linear probing from `Hash(k) & mask`, at most three quarters full, and a delete that shifts its probe run back, so no slot is a tombstone. `H`'s operations are called directly in a copy for one provider (MONO1), where `NormalForm()` is a constant. The checker checks the syntax forms of rule 3 once, then writes them as calls of the record's functions (`m.Len()`, `m = m.Put(k, v)`, `for k, v in m.Stored()`, `Map[K, V, H]{}.Put(k, v)…`) and checks the package again, so every later reader sees ordinary calls (`check/mapprovider.go`). A store into such a Map names its Map by a variable, a field, or an element at a name or a literal (S108 otherwise), since the rewrite reads it twice.
6. **The normal form** (C5b, C5d). Every provider has `NormalForm() bool` and `NormalKey(k K) K`. A provider may write both (a provider that writes one writes both); the checker otherwise writes them beside its `Hash`, derived from the type: when its `Equal(_, a, b)` is `n(a) == n(b)` and its `Hash(_, k)` is `hash(n(k))` for one pure, rowless expression `n` of the key alone, of the key's own type (the same expression in both bodies, parentheses aside; the identity included; reading no field of the provider), `NormalForm` is `true` and `NormalKey(k)` is `n(k)`; else `false` and `k`. Under `NormalForm`, the Map is Go's map keyed by `NormalKey(k)`, so a get is one `n(k)` and one Go map read; the two laws of rule 1 check a written normal form. A generic function over `H Hashing[K]` takes every Map with a provider, the one type. The reference lowering, `-X ergo.local/prototype/internal/sketch/check.mapLowering=table`, derives every `NormalForm` false (a written one stands); `TestProviderMapAgrees` runs seeded programs under both and `TestNormalFormShapeIsRead` checks the derived bodies.
7. **Not yet.** The codec of a Map with a provider (S108 "… is a Map with a provider, which has no wire form yet"): its wire form is a by-name pair on the prelude's generic `hashTable`, and pairs are not generic yet (Codecs 1); so its TS projection (S109) too. Go interop takes only `Map[K, V]` (Go's `map[K]V`), as any other Map is a different type.

*Prior art:* OCaml's `Map.Make(Ord)` and Rust's `HashMap<K, V, S>` put the key's comparison in the type, as here; Go has no map over a custom equality; Effect's `HashMap` reads `Equal` and `Hash` symbols from the key at run time. Gleam's `dict` and Elixir's `Map` compare keys structurally only, and ReScript's `Belt.HashMap.make(~id)` takes a hashable module whose identity is part of the type, the closest to this design.

```go
law DivMod(a int, b int where b != 0) { (a / b) * b + a % b == a }
```

1. **Syntax.** `type N T where P` refines the defined type `N` by the predicate `P`, in which `it` names the value. `where` is a contextual word after a type, not a keyword. A law parameter takes `name T where P`, in which the parameter's own name is the subject (rule 10); a `where` on any other parameter is S108. A `where` on a host type (`extern go … type`) is S001, and a `where` after a parameter group (`a, b int where …`) is S001.
2. **The decidable fragment.** `P` compares its subject with integer literals, each with an optional sign: `it OP c` or `c OP it`, `OP` one of `==`, `!=`, `<`, `<=`, `>`, `>=`. The subject is `it` for an integer base and `len(it)` for a string or slice base. `&&`, `||`, `!`, parentheses, `true` and `false` join them. Anything else is S108 at the first node outside the fragment ("a where is decidable: comparisons of it with integer literals, joined by &&, || and !; this is outside it"). The checker decides `P` to the set of subject values that satisfy it, a list of disjoint closed spans within the base's range (or 0 to MaxInt64 for a length). An empty set is S108 "no value of int satisfies this where". *Principle:* a refinement never hides a runtime check the compiler cannot decide.
3. **Bases.** The base's underlying type is an integer type, a string or a slice. A float or Map base is S108 (a float's NaN and a Map's distinct keys stay open; questions Q2). A refined type has no type parameters (S108), and a refined base (`type P2 Port where …`) is S108: one where holds both predicates.
4. **The derived parse function.** The parser derives, after the type, `func ParseN(it T) N fails Unsatisfied` (`parseN` for an unexported `n`): `if P { N(it) } else { Unsatisfied{Type: "N", Where: "P"} }`. It is an ordinary function of the package, so a call, a codec and `ergo inspect` find it by name as they find a written `ParseX`. The prelude's `Unsatisfied { Type string, Where string }` is its one failure. A package function of the same name is S108 "ParsePort is already declared in this package: the where of Port derives it". The formatter does not print the derived declarations. *Lowering:* the function lowers as any function, with `P` as written: `if 1 <= it && it <= 65535 { return Port(it), nil }`, the check hand Go writes.
5. **The derived law.** The parser derives `law NWhere(v N) { let it = T(v); (P) && try ParseN(it) == v }` (an assignment `let it T = v` for an unnamed base): every generated `N` passes `P`, and `ParseN` gives it back. `ergo test` runs it as any top-level law.
6. **The ways in.** A value enters `N` only as: a constant whose value lies in the set (an integer literal where `N` is expected, a signed literal, a constant conversion `N(80)`; a string literal by its length), else S108 "70000 is not a Port: its where is 1 <= it && it <= 65535"; a result of `ParseN`; or a value already of type `N`. A conversion `N(x)` of a value that is not a constant is S108 "a conversion into Port is checked only for a constant; write ParsePort(x), …", except in `ParseN`'s own body. An assignment from the unnamed base (`let ns Names = xs`, clause 2) and a composite literal of `N` are S108 too. So every constant of type `N` satisfies `P`: `p < 0` of a `Port` is S108, and the fix is `int(p) < 0`.
7. **No way out.** An arithmetic, bitwise or shift operator, its assignment form (`p += 1`), and a unary `-`, `+` or `^` on a refined operand are S108 "operator + on Port could leave its where; convert first: int(…) + …"; a slice expression of a refined value is S108 too. Comparisons stay. A refined type satisfies `comparable`, and no `~T` term of a type set (so not `ordered` or `number`) as a type argument, since a generic body may apply `+` (questions Q4).
8. **Zero value.** A refined type is defaultable ([Zero values](#zero-values-and-definite-initialisation) 1) only when its base's zero, 0 or the empty value, satisfies `P`: `let p Port` is S108, `let c Count` with `type Count int where it >= 0` is `0`.
9. **Generators.** A generated value of `N` lies in the set (decisions 17c): a span, each as likely, then its low end, its high end or a uniform value in it, half the time an end. A length is drawn the same way, at most 32 above its span's low end, and a string or slice of exactly that length is built. A refined integer type of at most 256 values is listed, so a law over it is proved over every value, as a `bool` parameter's is (`law Small(d Digit)`: "proved: all 10 cases").
10. **Law parameters.** `law L(b int where b != 0)` draws `b` inside the predicate's set. The predicate's subject is the parameter's name; the fragment is rule 2's. A parameter of a refined type takes no further where (rule 3).
11. **Patterns.** Status: **implemented** (FKre). ``type Email string where matches(it, `[^\s@]+@[^\s@]+\.[^\s@]+`) && len(it) <= 254`` refines a string by a pattern, which the compiler compiles: no regexp is built when the program runs. `matches(it, lit)` is a contextual word of a where, as `where` is: a function named `matches` stays an ordinary name everywhere else. Its first argument is the subject, its second a string literal (raw or interpreted). It stands only on a string base and only as a top-level conjunct of `P`, at most one: under `!` or `||`, twice, on another base, or with other arguments it is S108 at the call. The other conjuncts are rule 2's, and give the length set. A pattern matches the whole value, as Go's `regexp` matches `^(?:p)$`; an invalid UTF-8 byte reads as U+FFFD, as there.
    - *The subset* is the regular part of Go's syntax (RE2): literal runes; a backslash before ASCII punctuation; `\t \n \r \f \v`; `\d \D \w \W \s \S` (ASCII, as Go's); `.` (any rune but a newline); classes `[…]` and `[^…]` of runes, ranges and those escapes, a `]` first standing for itself; groups `(…)` and `(?:…)`; alternation `|`, empty branches allowed; repeats `*`, `+`, `?`, `{n}`, `{n,}`, `{n,m}` with counts at most 100, each optionally lazy (`*?`), which a whole-value match does not tell apart. `^` first and `$` last are allowed and say nothing more. Everything else is S108 at its byte in the literal: flags `(?i)` and named groups, `\b \B \A \z` and the other assertions, `\p` classes, `\x`, octal and `\Q` escapes, POSIX classes `[[:alpha:]]`, a `{` that starts no repeat, a repeat of nothing or of a repeat (`a**`), `^` or `$` elsewhere, a class of no rune, and a pattern whose automaton passes 2000 states.
    - *The check.* The checker compiles the pattern to a minimal deterministic automaton over rune spans (Thompson's construction, the subset construction over the spans' cut points, Moore's minimisation). A string constant enters `N` (rule 6) only when its length is in the set and the pattern matches it. A where no value satisfies, by its lengths and its pattern together (lengths up to 1024 bytes past each span's start), is rule 2's S108. `N` is defaultable (rule 8) only when `""` is in both.
    - *Lowering.* `ParseN` and `NWhere` call the pattern as written. Each distinct pattern lowers once to a package function `func ergoMatch(s string) bool`: a loop over the runes of `s` with a switch on the state, each state's spans as comparisons (`r >= 'a' && r <= 'z'`), and a return of whether the state accepts. An automaton of more than 24 states lowers instead to a table in a package variable (the class of each ASCII rune, the spans past ASCII with their classes, found by binary search, a transition per state and class, and the accepting states) read by one loop; two runes are of one class when no state tells them apart. Up to 24 states the straight-line form takes up to 1.6 times fewer instructions per match (Email's table takes 7 percent fewer) for at most 1.8 times the bytes; past that the table's bytes stay near flat while the straight-line code grows with the automaton (domain-search' `Label`, 125 states: 929 bytes against 7,118). A match allocates nothing and builds nothing in either form ([receipt](../receipts/fkre-patterns.md)).
    - *Generators.* A generated `N` (rule 9) draws a byte length the pattern reaches inside the length set, then walks the automaton: at each step an edge and a UTF-8 width that can still reach an accepting state in the bytes left, each as likely, then a rune of that width on the edge, half the time printable ASCII when the edge has some.

*Prior art:* Ada and SPARK range subtypes (`subtype Port is Integer range 1 .. 65535`) check every conversion and SPARK proves the checks, the model of rules 2, 6 and the proof tier; Pascal subranges list small domains (rule 9); Liquid Haskell and F\* refine by SMT-decidable predicates, of which rule 2 takes a decidable part; Gleam `opaque` types, ReScript `private` types and Rust private-field newtypes make a hand-written parse function the only way in, which rule 4 derives instead, so it cannot drift from the predicate; Elixir guards (`when x in 1..65535`) check at a call only. Effect Schema (`Schema.Int.pipe(Schema.between(1, 65535), Schema.brand("Port"))`) derives a decoder and an Arbitrary that draws inside a `between` filter and rejects otherwise; Ergo takes that purpose (one declaration, a parser and a generator that draws inside) without the `pipe`/`brand` library shape, and checks constants at compile time. Go has no refinements: a type validates in its own constructor or `UnmarshalJSON`. For rule 11, Go's `regexp.MustCompile` parses and compiles when the program starts and interprets the program per match (one-pass, backtracking or NFA); Elixir's `~r` sigil compiles at compile time but still runs the PCRE engine; Gleam's `gleam/regexp` and ReScript's regex literals hand the pattern to the host's engine (Erlang's `re`, JavaScript's `RegExp`); Effect Schema's `Schema.pattern` tests a `RegExp` at decode. re2c, Ragel and Rust's `regex-automata` (a DFA built ahead of time) compile a pattern at build time to a table or straight-line code, the model of rule 11's lowering; RE2's subset, without backreferences or lookaround, is what keeps that automaton finite.

## Codecs

Status: **the core is implemented** (L11). JSON is std `json` over it ([stdlib.md, json](stdlib.md#json); S-json), whose `Text` the lowering writes bytes into directly. Generic codecs (rule 6) and the round-trip law of a by-name pair (rule 7) are implemented (L11b).

1. **wire.** The predeclared constraint `wire` (owner q83; predeclared as `comparable` is, not a keyword, so a declaration named `wire` shadows it) admits the types with a wire form, decided from the type's structure as `comparable` is: `bool`, the integer types but `uintptr`, the float types, `string`, a refined type (its base on the wire, its `ParseN` on decode, [Refinements](#refinements)), a record whose fields are wire and that has no unexported field, a union whose variants are wire, a slice, a Map whose key is `string` or a type over it (not a refined one), a tuple, and a type `X` with a **by-name pair**: its own package declares `ParseX(b B) X fails …` (`parseX` for an unexported `x`, the name rule of a refined type's parse function) and `Wire(x X) B` with no failure, for a wire `B`. The pair's **append form** (GX10, GX11) is `ParseX(b []byte) X` with `Wire(x X, into []byte) []byte`, both halves over bytes as Go's `TextUnmarshaler` and `TextAppender` are: `Wire` gives `into` with the UTF-8 bytes of `x`'s text added, and `x`'s wire form is that text as a string, so an encode lends `Wire` a buffer and writes the string event from the bytes (the prelude Writer's `StringBytes`), making no string of the text, and a decode reads the string event into a buffer it lends (the prelude Reader's `StringBytes(into)`, GX12) and gives `ParseX` those bytes, making no string of the text either; std time's `Time` is such a pair (RFC 3339 with nanoseconds, in UTC). The parser derives its round-trip law as for any pair (rule 7). A pair is looked up in `X`'s package only (coherence: one wire form per type). A function, an operation type, a pointer, `duration`, a complex type, a record that only its package builds and a type parameter without `wire` are not; S108 names the first part that is not, with its path (`Hook.Run`). `wire` is not a keyword: a let, a parameter or a type named `wire` shadows the constraint (196w).
2. **encode and decode.** `encode(v, w)` writes the events of `v`'s wire form on `w`, a value of the prelude's operation type `Writer`; `decode[T](r)` reads a `T` from `r`, a `Reader`. Both are predeclared, as `len` is, and take a wire type, which may hold a type parameter under `wire` (rule 6). The events: a record is `BeginObject(n)`, then `Key` and the field for each field in declaration order, then `EndObject`; a union value is its variant's record with `Tag(name)` first, the variant's name as written (`Some`, `None`); a slice or tuple is `BeginList(n)`, its elements, `EndList`; a Map is an object with its keys in order. A string may also come as `StringBytes(b)`, the string b's UTF-8 bytes spell, which the append form of rule 1 writes, and a `Reader` gives one back as `StringBytes(into)`, `into` with the string's bytes added, which the append form reads (GX12); every `Writer` and every `Reader` provider declares its `StringBytes`, as it declares `String`: the prelude gives it no default body, since an operation type's contract is explicit and a default through `String` would make the string the operation exists to avoid (decisions, 2026-11-15). A field's key is its name with its leading run of capitals lowered (`Port` as `port`, `Some.Value` as `value`, Effect's `Schema.Option` encoded form; `ID` as `id`, `URL` as `url`, `X` as `x`); a run that a lower-case letter follows keeps its last capital, which starts the next word (`HTTPStatus` as `httpStatus`, `IOError` as `ioError`) (orchestrator, refining owner q81, 2026-11-10). This one function (`check.WireFieldName`) is every key mapper: the codec, the TS projection and `ergo gen rpc`. The map must be injective on each record: a record with two fields of one key (`ID` and `Id`) has no wire form, and the S108 names both fields and the key. `TestWireKeysFollowTheRule` holds the rule against a reference split into words, and the refusal exactly when two keys meet. An integer is `Int` or `Uint` with its exact value; JSON writes the exact digits.
   **Explicit keys override the default in rule 2.** A field declaration may end in a key literal: `NodeID int "node_id"`. That key is shared by every format (JSON, TOML), `ergo gen rpc` and the TS projection; there is no global naming policy. A key must be non-empty valid UTF-8, or the declaration is S108, even when the record has no wire form. A key that holds a double quote is a key (the quotes go on the wire); the strict lint rule `wire-key-quote` names it, since it is the Go struct-tag habit ([tooling](../tooling.md)). A field with no literal keeps rule 2's capital-run mapping. Included and instantiated fields keep the declaring field's key. Two declared or default keys that meet in a wire record are S108, naming both fields and the key. A variant field with key `_tag` has no wire union form because the discriminator owns that key; an ordinary record may use it. An unused valid key is allowed on a type with no wire form. The checked field's origin carries the literal, and `check.WireFieldName(field)` is the one key rule for every consumer. `TestWireKeysDeclared` holds the checker and formatter to it; `examples/wire-config` holds JSON and TOML to independently written documents. This is static metadata, not a runtime tag lookup: the same literal constants that hand-written Go would pass are emitted.
3. **Rows.** `decode[T]`'s error row is the union of what `T`'s wire form may fail, computed at the call: `WireWrongKind` always (an event of another kind, or an integer outside its type's range), `WireMissingField` when `T` reaches a record with fields or a union (whose tag may be missing), `WireUnknownTag` when it reaches a union, `Unsatisfied` when it reaches a refined type, and the row of each `ParseX` it reaches, which must be written. `encode` fails nothing.
4. **Two phases.** A format checks its whole input before `decode` reads it (phase 1, the format's own failure), so the `Reader` fails only the shape failures and no partial value escapes a failed decode.
5. **Lowering.** One Go function per type and direction walks the structure: no reflection and no `any`; a basic value is one inline event. std `codec`'s `Events` and `Replay` record and replay the events, and its laws hold the round trip on generated values ([stdlib.md, Std laws](stdlib.md#std-laws)).
6. **Generic codecs.** `func Decode[T wire](r Reader) T fails Malformed | wired[T]` reads any wire `T`. The predeclared row former `wired[X]` (owner q80) stands in a fails row for the row of `decode[X]` (rule 3); each wire type parameter `T` that `X` reaches stays in the row as `wired[T]`, and an instance replaces it by its argument's row, so the caller of `Decode[Draft]` handles `Draft`'s failures and no others. `decode[Option[T]]` reaches a union, so its row is `wired[Option[T]]`, wider than `wired[T]`. `wired` takes one wire type and stands only in a fails row or a needs row (S108 otherwise); in a needs row it names the capabilities of the codec (rule 8). The lowering passes a wire type parameter's codec as a witness, a struct of its encode and decode functions, so a generic codec is Go generic code with no reflection; the caller builds the witness from the argument's derived functions.
7. **Round-trip law of a pair.** A file that declares both `ParseX(b B) X` (no `needs`) and `Wire(x X) B` (no failure, no `needs`) gets the law the parser derives, `law XRoundTrips(x X) { try ParseX(x.Wire()) == x }`, which `ergo test` runs as any law; for the append form (rule 1) the law calls `x.Wire([]byte{})`, the empty buffer (GX11). The dot form `x.Wire()` names `X`'s own `Wire` when the package declares several (196m rule 3); a `ParseX` that fails nothing gets the law without `try`; a `ParseX` with a `needs` clause derives no law, since the law has no provider for it. The law draws `x` from `X`'s **own generator**, the values `X`'s package makes: its constructor `NewX` ([runtime.md, Tests](runtime.md#tests) 6), or any value of a record or union whose fields every package may write (confparse's `LevelRoundTrips`, proved over the four levels; std time's `TimeRoundTrips` over the instants `NewTime` makes). It never draws `B`: `ParseX` refuses almost every drawn `B`, so such a law would read as coverage and test nothing (GX11). An `X` with no own generator, a record with an unexported field and no `NewX` or a defined type over a basic type with none, gets a law that does not run, and the test build reports it as a skip with the reason ("its pair draws X from X's own generator, and it has none: declare NewX, …"), as for any law that cannot run (Laws 8). `X` must be comparable; the formatter does not print the law. A pair whose halves are in two files derives none.
8. **Declared wire forms.** A type's own package may declare a rowless
   `func WireForm(x X) WireOmittable { WireOmittable }`, or its generic
   counterpart. The result is one of the predeclared protocol markers
   below. This signature declares representation metadata; a derived codec
   does not call the function. Its body is ordinary checked source.
   The declaration takes only its receiver and its receiver's type
   parameters, with no failure or service row. The rule is open to every
   package; no std package, type, variant or field name selects a form.
   A marker with the wrong structural shape is S108 when used as `wire`.
   A structural form cannot also declare an independent Parse/Wire pair;
   `WireNumberText` is the exception because its pair supplies its spelling.

   - `WireOmittable`: a union of two record variants, one empty and one
     with a single wire payload. In a record field the empty variant
     omits its key; the other writes its bare payload. A missing key
     decodes to the empty variant. At the root or in a list the union
     keeps its ordinary tagged representation.
   - `WireNullable`: the same union shape, but the empty variant writes
     null and the other writes its payload everywhere. A record key is
     still required. Nesting an omittable form around a nullable form
     gives absent, present null and present value.
   - `WireBare`: a union of records with distinct event kinds. An empty
     variant is null. A one-field variant writes that field directly.
     A variant with its own `WireNumberText` or `WireMembers` form uses
     that form. Decode selects by `Reader.Peek`, not a variant tag.
     A variant with no single statically known event kind, or two
     variants of the same kind, is refused.
   - `WireNumberText`: a record with one string field and a string
     Parse/Wire pair (rule 1). Its wire string is emitted as a number's
     spelling, not a quoted string; decode reads `Reader.Number` and
     calls the parser. The pair's failures remain in `wired[X]`.
   - `WireMembers`: a record with one slice field. Each element is a
     two-field record, first a string key and then a wire value. It writes
     an object in slice order and preserves duplicate keys. Decode
     reconstructs the entries in that order.

   Construction authority and wire admission still apply to every payload.
   The record alternatives of an omittable/nullable form, and the slice,
   entry record and key of a members form, must have no independent
   Parse/Wire form or refinement that direct field access would bypass.
   A number-text pair's base is the ordinary `string` type.
   Generic record fields use their argument's field form through the
   codec witness, exactly as a concrete field does. std json declares
   Optional, Nullable, Value, Num and Object through these same rules.
9. **Needs.** `encode(v, w)` calls the `Wire` of each by-name pair that `v`'s type reaches, and `decode[T](r)` each `ParseX`, so the call is charged their capabilities as a written call of them there is: a `with` that binds one provides it; a row that lacks it is S102 at the call ("Wire, which this encode calls, requires Console, …"), with the clause to write. Codecs may carry needs, counted (owner, 2026-11-12). Under `ergo fix`'s clause writer (`Options.Infer`), a `ParseX` that writes no needs clause is reached by no name in the body that decodes, so the checker orders it before that body (a second check with the edge), and the decoding function's clause takes its final needs; a `decode` in a package `let` has no clause to take them, so when it reaches such a `ParseX` that needs a capability it is S108, write that clause. A wire type parameter `T` carries the capability row `wired[T]` in a needs row (owner q141, 2026-11-12: "needs wired[T]"): the needs of the `Wire` and `ParseX` functions `T`'s argument reaches, both directions in one row. An `encode` or `decode` of a value whose type reaches `T` charges `wired[T]`, so a generic codec writes it, `func Decode[T wire](c Codec[T], text string) T fails Malformed | wired[T] needs wired[T]`, and an instance replaces it by its argument's needs, so the caller of `Decode[Level]` is charged `Level`'s codec needs and an instance whose codec needs nothing adds nothing (S102 at the call that lacks them, with the clause to write; `func G() Lv fails wired[Lv] needs A`). Before EX3 such an instance was refused (S108). Status: **checked** (wf10 REL-needs and EXPLICIT EX3, `check/wirecall.go`; `TestReleaseNeedRows`; G3 of the v1 audit 3: before, such a program checked and its codec reached a nil service). *Prior art:* Effect Schema's `transformOrFail` carries its requirement `R` in the schema type and `decodeUnknown` needs `R`, the charge at the call; Rust serde's `Deserialize` takes no context (a decoder that needs one is an explicit `DeserializeSeed` value); Gleam's decoders and ReScript's `@spice` codecs are pure functions.
10. **A format writes its own types** (CX1; Q14 (a)). The package of a record or union `X` that also declares `P`, the one cell provider of a sealed operation type that provides the prelude's `Writer` ([Interface assignability](#interface-assignability) 6), may declare `func WireWrite(x X, w *P)`, with no type parameter, result, failure or `needs`. Wherever a derived codec writes a value of `X` (a field, an element, the root), it writes it with that function when its writer is a cell of `P`, and by `X`'s ordinary form (its by-name pair, else its structure) on every other writer. It is a protocol function found on `X` by its name and shape, as `Wire` is, so only `X`'s package can give it: one answer per type and provider. A field's `Key` event comes first, so the writer holds the key. Any other `WireWrite` is S108: one whose first parameter is not a type of its own package, one of another shape, or one whose provider is not such a cell. A generic `X` has none yet. On the direct path the codec function made for `P`'s cell is the call; on the `Writer` interface the codec function of `X` asks first whether the writer is `P`'s cell, so both paths write the same (`TestCellWriterAgrees`). std `xml`'s `Attribute` is the worked case: `type Product { Sku xml.Attribute, … }` writes `<item sku="…">` in XML and `"sku": "…"` in JSON.
11. **A format reads its own types** (WIRE-READ). The package of a record or union `X` that also declares `R`, a direct reader (a named record that provides the prelude's `Reader` by its own functions, each taking `R` by value, as std json's `Reader` does; `check.DirectReaderShape`), may declare `func WireRead(x mut X, r R) fails F`, with no type parameter, result or `needs`: it reads the value the reader is at into `x`. `X` comes first, as in rule 10, so the function belongs to `X` ([Methods](#methods)), and a package whose `R` reads several types declares one `WireRead` for each. Wherever a derived codec reads a value of `X` (a field, an element, the root), it reads it with that function when its reader is an `R`, and by `X`'s ordinary form (its by-name pair, else its structure) on every other reader. `F` joins the decode's row as a `ParseX`'s row does (rule 3): `decode[T]`'s row and `wired[T]` gain `F` wherever `T` reaches `X`. It is a protocol function found on `X` by its name and shape, as `Wire` and `WireWrite` are, so only `X`'s package can give it: one answer per type and reader. `WireRead` reads exactly the one value the reader is at, and nothing after it. The checker cannot prove that, so `X`'s package states it as a law beside `WireRead`, named `<X>ReadsOneValue`, which takes one `X` and names `R` in its body. The law writes the list `[s, x, s]`, a sentinel on each side of `x`, opens a reader `R` over that text, and decodes `[s, X, s]`; it holds when the decode gives `s`, `x` and `s`. A read that goes past `x` takes the second sentinel, and one that stops short leaves part of `x` where the sentinel should be, so either breaks the law. The checker requires the law to exist with that shape: one parameter of type `X`, and a body that mentions both `R` and `X`. Like every law it must be fed, in `X`'s package or a provider package (runtime.md, Tests). Any other `WireRead` is S108: one whose first parameter is not a record or union of its own package, one of another shape, one whose reader is not such a record of its package, and one with no such law. A generic `X` has none yet. On a direct reader the codec function made for `R` is the call. On the `Reader` interface, the codec function of `X` first asks whether the reader is `R`'s operations adapter (it exists when the program converts an `R` into `Reader`), so both paths read the same value and fail with the same failure at the same path (`TestCellReaderAgrees`). With no such adapter, no `Reader` can be an `R`, and the function has the ordinary form alone. Rule 10 gains no second law: when `X` has both `WireWrite` and `WireRead`, the one sentinel law covers both, since its `[s, x, s]` is written by `P`'s write when `P` is the writer it uses; a type with only `WireWrite` keeps rule 10 as it is. std json's `Raw` is the worked case (JSON-RAW): a member kept as its text, with no tree.

*Prior art:* Rust serde and Roc's `Encoding` derive per type over a format's event interface, monomorphised (rules 2 and 5); ReScript's `@spice` emits plain functions; Elixir's `@derive Jason.Encoder`; Effect Schema gives one declaration, typed issues with a path and a round trip, as runtime values; Go's `encoding/json` walks by reflection with struct tags, and json v2's `jsontext` streams tokens, the model of the events; Swift's `Codable` names the constraint.

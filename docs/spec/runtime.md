# Runtime rules

The runtime gives Effect's guarantees on Go's scheduler: structured tasks, cooperative interruption, release that always completes, and typed exits. Go supplies goroutines, the garbage collector and preemption; Ergo adds no scheduler of its own. Definitions are in the [glossary](../../GLOSSARY.md).

Status summary: `runtime/rt` implements the task tree, stop propagation, masks, scopes, the context store and defect propagation. `runtime/v1` adapts them to lowered frames and holds the Go bodies of the std packages `task`, `scope`, `queue` and `timeout` ([Tasks](#tasks), [Exit actions](#exit-actions), [Queues](#queues), [Timeouts](#timeouts)); their Ergo signatures check ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice)), and `ergo build` lowers their calls (check-v1 stage D3b). Each section's status says what is lowered.

**#199 contract status.** [#199](https://github.com/cevr/ergo/issues/199) lowers interruption points ([I1](#i1-interruption-points)), task-aware blocking waits, release masks ([I2](#i2-automatic-masks)), context cleanup and acquisition ([resources.md, Context ownership as built](resources.md#context-ownership-as-built)), context values ([G1](#g1-context-through-with)) and fork-tree defects ([G2](#g2-fork-tree-defects)). These tests prove it, each generated from its rule: `TestRuntime199I1Property`, `TestRuntime199BlockingProperty`, `TestRuntime199MaskProperty`, `TestRuntime199ContextBuildProperty`, `TestRuntime199AcquireProperty`, `TestRuntime199ContextValueProperty` and `TestRuntime199DefectProperty`. The cost of the emitted polls against a hand-written Go target is in [docs/receipts/runtime-199.md](../receipts/runtime-199.md). The bounds of v1:
- **Contexts.** A `with` owns the providers it builds from a named context of its own package, or from an inline or a local context whose entries are explicit provider expressions; a local context is built again at each `with` that names it ([rows.md](rows.md#context), Context 9). A resource provider must be proved fresh, else S109 names [#197](https://github.com/cevr/ergo/issues/197). Until check-v1 stage E the lowering refuses a provider whose `Close` is an operation of its type, generic, a std or extern function, or takes a pointer; a `with` that owns a resource outside a function body; and constructors ([#37](https://github.com/cevr/ergo/issues/37)). A `with` of an imported context, `with b.W`, and of a context that embeds one lowers too: it builds and releases the providers as it does for a named context of its own package (196b U4; `TestRunImportedContext`; [rows.md](rows.md#with)).
- **Context values.** A `with` of several operands, context values and contexts in any order, is their nesting ([rows.md](rows.md#with), With 7). A value is a string, stored under its type's declaring package and its protocol key. Typed and mutable payloads and the rest of the trace and log APIs are [#206](https://github.com/cevr/ergo/issues/206).
- **Left for #197.** A `Task` that moves other than by a direct `return` ([Tasks](#tasks) rules 3 and 11), the unobserved failure dropped at a normal return (rule 12, law R3), a generated `Close`, and the ownership of local and aggregate resources (I2 item 4 outside a `with`).
- **Left for tooling.** Showing footprints and warning about a pure loop that cannot be stopped are [#203](https://github.com/cevr/ergo/issues/203); `ergo ps` (G3) is [#201](https://github.com/cevr/ergo/issues/201). `timeout.After` is not left: `ergo build` lowers its call to its `runtime/v1` body, `v1.After` ([Timeouts](#timeouts)).

Every other rule here is **designed, not yet implemented**.

## Tasks

Status: the task tree is **implemented** in the task runtime `runtime/rt`, and every built program runs on it. The bodies of `task.Go`, `Wait` and `Stop` are **implemented** in `runtime/v1` (rules 7 to 12); the signature of `task.Go` checks, and its calls lower (check-v1 stage D3b; `TestTaskGoAndTaskResults`).

1. **Tree.** Every task has a parent, except the task that runs `main`. Stopping a task stops every task below it. A child that finishes detaches from its parent.
2. **Starting.** `task.Go() { … }` starts a task and yields a `Task[T, E]`. `T` is the body's value and `E` its error row.
3. **Resource.** A `Task` is a resource ([resources.md](resources.md)). Its owner scope stops and drains it at scope end if it was not consumed. A `Task` can move by `return`, into a provider field, into another task or into a container ([resources.md](resources.md#moves)). In v1 only a direct `return` moves it (rule 8); a `Task` stored in a field, a container, a capture that outlives its frame or a generic value is refused with a located diagnostic until [#197](https://github.com/cevr/ergo/issues/197) designs aggregate ownership. A queue of tasks is an error in v0 (README Gap 30).
   Checked (check-v1 stage D3a), each refusal S108 "a Task leaves its function only by return; wait on it or return it":
   1. *Holds a Task.* A type holds a `Task` when it is one or one is in its structure: a type argument, a declared body, an element, a field or a variant. The property is coinductive over type identity: a recursive type terminates, the walk visits each type of the declaration graph once and checks an instance's arguments without expanding its body again, so recursive generic types whose arguments grow reach the S108 instantiation-cycle diagnostic. An operation type and a function type hold none; assignment keeps a Task-holding value out of an operation type that holds none ([types.md, Assignability](types.md#assignability) clause 3).
   2. *Type positions.* A Task-holding type is only the whole type of a local, a parameter or a result, a function type's parameters and results included (`Option[Task[T, E]]` as a local's type is one). As a slice or Map element or key, a tuple element (several results are one tuple), a pointer's element, a record or variant field, a defined type's base or a package `let`'s type it is refused at the type, and the values assigned to that type add nothing. A type argument elsewhere is stage E's.
   3. *Uses.* A Task-holding value may be bound by a local `let`, returned (by `return`, or as a block's final value through `if`, `match`, `catch`, `try` and `with`), passed as an argument, or be the receiver of a called `Wait` or `Stop`. Every other use is refused at the value: a discarded value, `_ = t`, `let _ = t`, a reassignment, a method value `t.Wait`, a borrow, a part of a composite literal, a match subject. A read of a Task-holding local from another frame is refused wherever it stands: a function literal, a trailing block and the block of `task.Go` are frames, as they may run after the function returns (stage E's `escaping` may admit a block its callee does not keep). A refused value's parts and the locals its `let` binds add no diagnostic.
   4. `Info.TaskResults` names each function whose result holds a `Task`; the lowering passes it the caller's scope as its hidden destination (stage D3b).

   *Prior art:* Rust's auto traits (`Send`) are coinductive over the type graph, and its `thread::scope` handles cannot outlive the scope; Kotlin's `Job` belongs to its `CoroutineScope`; Trio's nursery owns its tasks; Go lets a goroutine outlive its caller. Gleam, Elixir and ReScript put no task ownership in types: an Elixir `Task` is a process reference any term may hold.
4. **Consuming.** `t.Wait()` waits for the task and returns `T` or fails with `E`; a defect of the task re-raises in the waiter. `t.Stop()` interrupts the task and waits for it to finish, including its releases. Each consumes the task.
5. **Containers.** Not in v1 (rule 3). Tasks may live in a slice or map; the container is then a resource ([resources.md](resources.md#containers)). Indexing lends a task, so `running[j].Wait()` is an error. `running.Take(j)` moves a task out of the map before its fallible `Wait`, so a drain cannot run it twice.
6. **Captures.** The block of `task.Go` may not assign captured locals. Values copy into a task. A resource is lent to the task under the structured-lend rule, and moved into it otherwise ([resources.md](resources.md#structured-lend)). Only synchronised handles are shared: queues ([Queues](#queues)), `sync.Ref`, `sync.TxRef` and actor handles. *Prior art:* Swift `Sendable`; Go shares memory freely and relies on the race detector.

*Prior art:* Go `errgroup` is function-scoped in the same way; Effect fibers are forked into a scope; Elixir `Task.async` links the task to its caller, and `Task.shutdown` keeps the abnormal exit, as `Stop` keeps a defect here.

The runtime contract of `runtime/v1` (task.go), which the signature `task.Go` binds ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice)) and the lowering of check-v1 stage D calls:

7. **Start.** `task.Go() { … }` starts its block on a new goroutine, as a child of the task that runs the calling function, and returns the `Task` at once; the block runs later (parse-v1 ruling 5). The child starts interruptible, even inside an exit action. There the exit action's block owns it (rule 8), and the stop of the ending function does not cascade into it, so the cleanup completes; the block's own drain still stops it. Each task carries its Ergo identity, the block's definition and source site, which a defect's task chain names ([G2](#g2-fork-tree-defects)). *Prior art:* Go `go` and `errgroup.Go`; Effect 4 `Effect.fork` is interruptible unless asked to inherit; Kotlin `launch` in a `coroutineScope`.
8. **Owner.** The function that called `task.Go` owns the `Task`; a function literal and the block of `task.Go` are functions here, as for [exit actions](#exit-actions). The block of an exit action owns the tasks started in it: they are drained when the block ends ([Exit actions](#exit-actions) 5). When the owner returns, on any path, without `Wait` or `Stop`, it stops the task and waits until it has ended, its exit actions included. The owner's exit actions and its tasks form one last-in-first-out list: a task started after an exit action is drained before that action runs (law R2, structured lend). **Return (v1).** A `Task` leaves its function only by a direct `return`, which transfers it to the caller's frame in one step. A function whose result holds a `Task` receives its caller's frame scope as a hidden destination argument, the frame of [stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Hidden arguments, as `Push` and `Pop` receive the hidden task, and its return moves the `Task` into that frame (`runtime/v1`: `return c.Move(dest)`; the lowering of check-v1 stage D passes the destination and places the move). The caller's frame then owns the `Task`: the caller can `Wait` for it or `Stop` it, and its frame drains it when the caller returns. A call inside an exit action passes the action's frame. A `Task` never belongs to no frame, nor to a frame that cannot reach it. Ownership is one removable entry: a transfer moves it from the old frame to the new one, and `Wait`, `Stop` and a drain remove it, so a frame holds only the tasks it still owns, never the history of transfers. A `Task` that left its function without the move was drained when the function returned, and a later `Wait` is a defect that names the missing move: a guard of the lowering's calling convention, not an outcome of admitted source. *Prior art:* Rust moves a value to the caller on return, but a dropped tokio `JoinHandle` detaches its task, which Ergo does not take: the receiving frame drains it; Effect `forkIn` picks the scope at fork time, and removes the fiber's finalizer from it when the fiber completes; Trio passes the nursery to the function that starts tasks in it; a Go goroutine has no handle and no owner. *Prior art:* Trio nurseries and Swift task groups end their children before the scope; Kotlin `coroutineScope`; Go `errgroup.Wait` is explicit.
9. **Wait.** `t.Wait()` returns the task's value, or its typed failure when that failure is the task's whole exit, so a `catch` can handle it (law R6). Any other exit is raised in the waiter: a defect, with the task chain and the Go stack at the panic, and an interruption. `Wait` is an interruption point of the waiter: when the waiter is stopped first or while it waits, the task is stopped and drained, and the waiter's exit is the interruption with the task's defects; neither the task's value nor its typed failure is delivered (law R4). A second `Wait`, or a `Wait` after `Stop`, is a defect. *Prior art:* Effect `Fiber.join` re-raises the fiber's cause, interruption included; Elixir `Task.await` exits the caller with the task's exit; Go `errgroup.Wait` returns only the first error.
10. **Stop.** `t.Stop()` is rule 4: it returns only after the task's exit actions ran (law R5). The task's interruption and an abandoned typed failure are the expected result of the stop and are dropped (laws R3, R6); its defects are raised in the caller. A `Stop` after `Wait` or `Stop` does nothing. *Prior art:* Effect `Fiber.interrupt` waits for the fiber's finalizers; Elixir `Task.shutdown`.
11. **One waiter.** A `Task` belongs to the task that started it: only that task waits for it, stops it or returns it. Starting a task on a function that has returned is a defect (law R9), and so is a transfer into a frame that has returned, into a frame of another task or to no frame. Not yet: a move into another task is #197's.
12. **Not yet: an unobserved failure at a normal return.** When the owner returns normally while an unconsumed task has already ended with a typed failure, the failure is dropped. Law R3 keeps it; `runtime/rt` drops it (#198 handover O1). #197 makes a dropped `Task` a compile error, which removes this case from checked programs.

## I1. Interruption points

Status: **implemented** for capability calls, loop back-edges and recursive or opaque impure frame entries (#199 stage 1), and task-aware blocking waits (#199 stage 2); stage 5a places loop and capability-call points where no delivered value is in flight (rule 2). `Sleep`, `Wait`, `Push`, `Pop` and `Values` observe interruption in their runtime primitives.

1. Interruption is cooperative. A stopped task stops at its next interruption point.
2. The compiler inserts an interruption point before each capability call, queue operation, `Wait` and `Sleep`, and at each loop back-edge, in every frame whose footprint is not empty ([rows.md](rows.md#footprints)). The point checks the frame's own task (`env.task.Check()`), so a task body checks itself, never the task that started it.
   - **Delivered values.** A point the compiler inserts never separates the completion of a step that delivers a value (a `Values` loop's next element, a `Pop`, a `Wait`, any call's result) from the first statement that receives the value. A stop that arrives after the delivery stays pending: the receiving statement runs, and the next point observes the stop. The placements below follow from this rule. Each blocking primitive keeps its own check before it waits, so a stopped wait takes nothing (rule 5). The entry point of a frame that receives a delivered value as an argument is not such a site: the call has already handed the value over. Where the user's own code places an interruptible step between a delivery and its use, such as a second capability call among the operands, that step's point stays where the user wrote it. *Prior art:* Trio's cancellation is atomic at a checkpoint: a cancelled operation did not happen, so a cancelled receive consumes nothing, and a completed one delivers to user code. Erlang's `receive` takes a message from the mailbox only into a matching clause, but an exit signal can end the process at any point, a taken message included, with no such contract. Go code checks `ctx.Err()` after a receive, and Kotlin calls `ensureActive`, only where the author writes it. Effect checks interruption between steps, so a taken item can be lost there; Ergo inserts the point itself, so it places it where no value is in flight.
   - **Capability call.** The point comes before the call's operands, which then run once and in source order, and before the operation. So no point separates an operand's delivered value from the operation that receives it: `Sink.Put(try q.Pop())` either stops before the `Pop` or hands the popped value to `Put`. The point lands in the frame that calls, so a recursion through a capability call stops at its next call. A call of a checked `Close` is never a capability call, because a capability's `Close` is refused ([resources.md](resources.md#context) R24), so no point precedes a release.
   - **Back-edge.** The point ends each loop iteration, after the body, on every path that continues the loop: a `continue` jumps to it (the lowering writes a `goto` to a label before the point, and puts the body in a block of its own so the jump skips no declaration). It never heads the body, so the loop's bindings and the body receive each element first, and a condition that writes statements runs at the top of the next iteration. Every back-edge passes the point. The lowering emits a Go loop only for a source loop; no rewrite makes one.
   - **Frame entry.** An impure frame polls once at entry when it belongs to a nontrivial strongly connected component of the call graph or has a self-edge. It also polls at entry when its footprint is opaque: a function value, a `Seq` or a host call may re-enter it, directly or through a known callee. The checker records this placement in `Footprint.EntryPoll`; the lowering reads it. A nonrecursive impure frame with only known callees has no entry poll unless its footprint is opaque. Pure recursion has none. Each function, literal, task body and provider method checks its own task; named-context builders and package initializers use the task passed to them.
   - **Queue operation.** `Push`, `Pop` and a `Values` loop take the caller's task and check in their `runtime/v1` bodies, so the call site adds none.
   - **Blocking binding.** One lowering owner binds each std runtime call, using a catalog of waiting policies. `Sleep` and queue waits receive the task of the running call; a deferred `Values` binds it when iterated. `Wait` observes the handle's owning task; returning the handle transfers its frame registration within that same task. `Stop` drains uninterruptibly. These bindings add no second call-site poll. The prelude's `LiveScheduler.Sleep` calls `rt.Sleep` with the running task and `rt.Live`, and raises interruption through the canonical exit path. Its finite host bridge is keyed by the declared Go target; general host signature loading remains stage E's.
3. An interruption point is one atomic load on the path where the task is not stopped (`rt.Task.Check`); a blocking primitive's wait costs what its wait costs. [docs/receipts/runtime-199.md](../receipts/runtime-199.md) measures the emitted points against a hand-written Go target. When the task is stopped, the function exits with interruption ([Exit causes](#exit-causes)).
4. A frame with an empty footprint has no interruption point, at entry or in its loops. Such a loop or recursion cannot be stopped until it ends, as with Effect on JavaScript. Go preemption keeps the scheduler fair but does not stop it. A pure function literal written in an impure function has no check.
5. A blocking runtime primitive waits for either its event or the stop, so a stopped task never stays parked.

*Prior art:* the `select` on `ctx.Done()` Go programmers write by hand; Effect checks interruption between steps; BEAM processes are preempted and can be killed outright, which Ergo does not do.

## I2. Automatic masks

Status: items 1 and 2 are **implemented** for a written `Close` and for `scope.OnExit` (#199 stage 3a, [Release masks as built](#release-masks-as-built)). Item 3 is **implemented** for providers with a written `Close` (#199 stage 3b, [resources.md, Context ownership as built](resources.md#context-ownership-as-built)): each release is the provider's masked `Close`. Item 4 is **implemented** for the providers a `with` builds (#199 stage 3c, [resources.md, Context ownership as built](resources.md#context-ownership-as-built) 8): the constructor and the registration of its release are one masked step. Item 4 for other acquisitions, and a generated `Close` (#197), are **designed, not yet implemented**.

These run uninterruptibly, to completion:

1. a resource release and a generated or written `Close` ([resources.md](resources.md));
2. a `scope.OnExit` body;
3. context cleanup at the end of a `with`;
4. the step between a successful acquisition and its registration for release.

If an acquisition succeeds, its release runs. A blocking primitive inside a masked region waits uninterruptibly, unless it is explicitly marked as an interruptible wait in the mask (the `poll` pattern). Masks nest; an inner region restores the outer mask state, never an unmasked one. *Prior art:* Cats Effect `MonadCancel.bracket` and `uncancelable` with `poll`; Effect `acquireRelease` and `uninterruptibleMask`.

### Release masks as built

1. **Which `Close` is a release.** The checker records a Close identity fact (`Info.Closes`) on the declaration of a function named `Close` whose only parameter is its receiver, a named type or a pointer to one, and which has no result and no error row (R1, R2), and on each call, operation and method value that resolves to such a declaration or to an operation type's `Close()`. Lowering reads the fact, never the spelling: `Finish()` with the same body, and `Close(n int)`, are ordinary calls.
2. **One boundary.** `runtime/v1` has one mask and cause boundary for a release, `release` in `task.go`: it masks the task, runs the body through `rt.Release`, and unmasks with a deferred call, so the caller's mask depth comes back on a normal return, a typed exit, a defect and a panic. A frame's exit actions, the drains of the tasks it still owns, and every checked `Close` body go through it. `v1.Release(t, body)` is the entry for a `Close` body.
3. **The mask is in the body.** The lowering writes the whole Go body of a checked `Close`, its frame scope, entry poll and first capability checkpoint included, inside `Release(env.task, func() { … })`. So every dispatch path reaches the same masked body: a call, a dot call, an operation of an operation type, a function value, a method value, and the release a `with` registers for a provider it built. A capability's `Close` is refused ([resources.md](resources.md#context) R24). The release catalog is the bindings of `runtimeBindings` with a release route (`internal/sketch/lower/release.go`): `Release` for a checked `Close` body on the invocation's task, and `OnExit` for an exit action on its frame's task. A new route fails a test until it is listed.
4. **Inside the mask.** A stop that arrives before or during the release does not end it. A blocking primitive in the body (`Sleep`, a queue wait) waits uninterruptibly. The stop stays pending, and the caller sees it at its next interruption point after the release. A call of a checked `Close` is not an interruption point of its own: no poll precedes it ([I1](#i1-interruption-points) 2).
5. **Causes.** A defect in a release is raised whole for the caller's frame to join beside its earlier exit ([Exit causes](#exit-causes) 4). It is never turned into a typed failure, and it never replaces an exit already in flight. An exit action runs on the task of the frame it ends, which is the task its block was registered on.

## Exit causes

Status: **partly implemented**: the rules hold as each item states, and the "Prototype:" notes say how the built programs do it today.

1. A task ends with one exit: a success value, or a cause. A cause holds one or more of: a typed failure from the error row, a defect, and an interruption.
2. **Interruption is not a typed error.** No error row names it, and every `catch` passes it on ([rows.md](rows.md#catch)). In a function with no error row, interruption still propagates as part of the exit, not through the row (README Gap 2). Prototype: such a function panics with `rt.Interrupted`, and the nearest task boundary recovers it.
3. **Defects.** A Go panic in Ergo code is a defect. Source raises one by name with the prelude's `Unreachable(reason)`, whose defect holds the reason and the call's position, `unreachable at main.ergo:12:3: reason` ([types.md, Unreachable](types.md#unreachable); owner q29). A defect in a child re-raises in the parent at the join, on every path, including the timeout and stop paths. `v1.After` keeps it on its deadline path (TestAfterDefects).
4. **Release defects.** A defect or an interruption during a release joins the cause beside the body's outcome. No cause is dropped.
5. **Stop wins.** When a task is stopped while its body runs, interruption wins over the body's success.
6. **Entry.** When `main`'s exit is a cause, the program prints each reason and exits with status 2 when any reason is a defect, 130 when every reason is an interruption, and 1 otherwise. Prototype: an interruption that reaches `main` exits 130; a defect prints `defect: …` and exits 2. The entry of `runtime/v1`, `Main`, runs `main` as the root task and writes one report per reason on standard error: `error: VALUE` for a typed failure, `panic: VALUE` for a defect, followed by the task chain when the defect began below `main` and by the Go stack at the panic, and `interrupted`. A lowered program runs `main` under `Main` and registers its source map (`RegisterCalls`, #230), always, even when it has no call: a table of its declarations with their lines and a table of its calls. Code outside the lowered frames that recovers a panic to classify it, the test build's case runner ([grammar.md](grammar.md#declarations) 11), reads the exit with `Capture`, which records the panic as a boundary does (a fresh defect with its stack and chain, a carried exit whole), and raises what it does not keep with `Raise`, so the next boundary and the report receive every reason unchanged (check-v1 E3a). The program's package-level `let` initializers run inside `Main`, in Go's initialization order (a `let` after every `let` it refers to, directly or through functions, else in declaration order), before `main`'s body, so a defect in one is reported like any other. Its defect report names the Ergo frames in place of the Go stack, innermost first, and never a Go frame: `pick at main.ergo:2` for the frame that panicked, the first source frame after the runtime's `panic(` frame, named by the declaration that holds its line; then `middle calls pick at main.ergo:7:2` for each call, by Ergo function, callee and `.ergo` position (when several calls share a line, the one whose callee is the frame inside it); a run of one frame, as in a recursion, is written once with `(N times)`, and Go's own elision of deep stacks stays visible as `...N frames elided...`. Each line is exact: a call's Go line follows the `//line` directive of its position, an operation that can raise a defect (an index, a slice, a division, a shift, a dereference) carries an inline `/*line file:line:col*/` directive, and every other Go line repeats its statement's directive, so go/format's line breaks cannot shift a position (stage C round 2 review m1 to m3). Every call of the source has an identity, a pure one included. **Exception: Go fatal errors.** A stack overflow, an out-of-memory failure and concurrent map writes are Go fatal errors, not panics: no `recover` sees them, so `Main` cannot report them, and the program prints Go's own report, with Go frames, and exits with status 2 (stage C round 3 review m1). Naming the Ergo frame of a stack overflow is a follow-up of #230. It exits with status 2 when any reason is a defect, as Go's own panic report does, 130 when every reason is an interruption, and 1 otherwise.
7. **How exits cross lowered code.** A lowered function returns a typed failure as its last Go result, and nothing else travels that way. An interruption, an exit already recorded at a boundary, and a fresh defect travel as Go panics, so no `catch`, which is a Go type switch over returned errors, can handle one (rule 2; [rows.md](rows.md#catch), catch rule 6). A boundary (a task's block, the end of a function that owns tasks or exit actions, an exit action, `Main`) recovers the panic and records it; a fresh defect is recorded with the Go stack at the panic, so the `//line` anchor of the faulting `.ergo` line survives the crossing of tasks and functions. *Prior art:* Effect keeps failures in the error channel and defects and interruptions in the `Cause`; Elixir separates `rescue`, `throw` and `exit`; Go returns errors and panics for the rest.
8. **`os.Exit`.** The failure `os.Exit { Code int, Message string }` ([stdlib.md](stdlib.md#os)) changes rule 6 only when it is the only reason of `main`'s cause:
   1. `Main` writes `Message` and a line feed to standard error, verbatim, with no `error:` prefix, and exits with `Code`.
   2. `Code` must be in 1..125. Otherwise `Main` writes `Message`, then `error: os.Exit code N is outside 1..125`, and exits 1: 0 would claim success, and 126 and up are the shell's. Code 2 is allowed, as Go's `flag` uses it for usage; a defect also prints `panic:`.
   3. A defect anywhere in the cause wins, as rule 6 states: status 2.
   4. With any other reason beside it, `os.Exit` is a typed failure like any other: each reason is written as rule 6 states, `os.Exit` as `error: os.Exit{Code:N Message:TEXT}`, and the status is 1, or 2 under 3.

   `Main` writes the report after `main` and every scope it owns have ended, so every exit action runs first. `TestMainExit` runs each case in a real process, codes 0, 1, 2, 3, 125, 126 and -1 included. *Prior art:* Roc's basic-cli `main` fails with `Exit code message`, which the platform writes and exits with; Go's `os.Exit` and Elixir's `System.halt/1` end the process at once with any status and skip deferred calls or `after` blocks.

## Exit actions

Status: the runtime body is **implemented** in `runtime/v1` (`OnExit`, rule 5); the signature of `scope.OnExit` checks, and its calls lower (check-v1 stage D3b), masked (#199 stage 3a; `TestRuntime199MaskProperty`).

1. `scope.OnExit() { … }` registers its block on the innermost enclosing function. The block runs when that function returns, on every path, and the blocks one call registered run last registered first. This is Go's `defer`, exactly. Each block runs masked ([I2](#i2-automatic-masks)).
2. A function declaration, a function literal and the block of `task.Go` are functions here: an OnExit in a task's block runs when the task ends. The block of an exit action is one too, as a deferred function literal is in Go: an OnExit in it runs when the block ends, and a task started in it is drained then (rule 5). A `with` block, an `if` or `match` arm and a loop body are not: an OnExit inside them registers on the enclosing function, and one inside a loop registers once per iteration. Whether the block of another call (`timeout.After`, `sync.Atomically`) counts as a function is not decided here.
3. Cleanup at the end of a `with` block is a resource's release, not an OnExit: the providers the `with` built are released when the block ends, before the exit actions of its function run ([resources.md, Context ownership as built](resources.md#context-ownership-as-built)). An exit action registered in that block still runs when the function returns, so one that needs a capability the `with` provides is an error (S108).
4. The block reads its variables when it runs. Go evaluates a `defer` call's arguments at the `defer` statement instead, so `scripts/migrate196` rewrites `defer f(x)` only when `f` is a function name, each argument is a literal or a local that nothing writes, and the `defer` stands at the top level of a function body; any other `defer` is a hand edit.
5. **What the runtime adds to `defer`.** `scope.OnExit` is a direct call (an extern that takes a hidden argument is call-only), so the lowering always knows its frame. It gives each function that registers an exit action or starts a task one frame scope, ends that scope with the function's first Go `defer`, and registers each block on it. Go's `defer` alone gives the timing of rules 1, 2 and 4. The frame scope adds what `defer` cannot give:
   - the block runs masked ([I2](#i2-automatic-masks));
   - a defect in a block joins the function's exit beside its earlier reasons ([Exit causes](#exit-causes) 4). With Go's `defer`, a panic in a deferred call replaces the panic already in flight, and drops a typed failure the function already returned;
   - the blocks and the function's tasks are one last-in-first-out list, so a task started after a block is stopped and drained before the block runs (law R2; [Tasks](#tasks) rule 8). Separate Go `defer`s would run every block first, then drain the tasks;
   - while a block runs, it is a frame of its own: a task it starts (`task.Go`, [Tasks](#tasks) rule 8) and an exit action it registers belong to it, and they end when the block ends, before the next block of the function runs. The route to the block's frame lasts through the block and through its frame's own release, so an exit action that the block registers is itself a frame for what it starts, at any depth. So a cleanup can start a task and `Wait` for it.

*Prior art:* Go's `defer` is function-scoped, and Ergo takes it because Go is the target, so the lowering and the translation are exact. Swift and Zig `defer` run at the end of the enclosing block. Effect `Scope.addFinalizer` and `Effect.onExit` run finalizers uninterruptibly and keep every finalizer's failure in the `Cause`; Go `errgroup` and Trio nurseries join children before the scope's own cleanup.

**Traced releases ([#230](https://github.com/cevr/ergo/issues/230)).** On a traced tree (`rt.TracedRoot`), each release of a frame's list, an exit action or the drain of a task the frame still owns, reports through rt's tracer as rt's own scopes report theirs. `runtime/v1` runs each through `rt.Release`, rt's one hook for scopes whose entries it does not hold. The tracer receives one release event per release. A defect in an exit action is a panic event marked as raised in a release. Events come in causal order: an action's panic event, then the releases of the frame its block ends (nested exit actions and tasks), then the action's own release event. A panic first closes the capability calls that the release opened and left open, never an outer one, and the panic event links the innermost of them. A traced run has the same exit as an untraced one. A frame's release unmasks its task on every path.

## Timeouts

Status: **lowered** as the library function below (lower-v1 stage 4). `ergo build` calls its `runtime/v1` body, `v1.After`, which takes the caller's `Scheduler` as a hidden argument ([stdlib.md, Hidden arguments](stdlib.md#v1-packages-task-scope-queue-and-slice)). The prototype's name-keyed exception (README Gap 31) is retired with the prototype.

```go
let payment = try timeout.After(500ms) { Gateway.Authorize(order) }
```

**Classification.** `timeout.After` is an ordinary library function in the `timeout` package, not a construct. Under the owner's rules, constructs get keywords, a dot form is library, and kernel primitives are functions (owner, 2026-10-12). Its kernel primitives are task start (`task.Go`), `Task.Stop` and `Task.Wait`, and the `Scheduler` capability. Its designed signature, in the generic spelling of [types.md](types.md#generics):

```go
func After[T, E, R](d duration, body func() T fails E needs R) T fails E | Expired needs Scheduler | R {
	// designed: the body runs as a child task raced against the deadline
}
```

The callback type carries `needs R`, so the requirements of the block appear in `After`'s own row. A trailing block is the `body` argument ([grammar.md](grammar.md#expressions)). *Prior art:* Effect's `Effect.timeout` is an ordinary combinator over fibers and the clock; Go's `context.WithTimeout` is a library function.

1. `timeout.After(d) { block }` needs `import "timeout"`. It takes one `duration` (S108) and a block (S108). The duration is a value position, so a fallible duration is S105.
2. It charges `Scheduler` and the block's requirements ([rows.md](rows.md#capability-rows)), because its signature says so.
3. Its block is a function literal and so a failure target: a `try` in the block escapes into the `timeout.After` expression, not into the enclosing function. The expression's error row is `timeout.Expired`, plus the block's last expression's row, plus every error a `try` in the block escapes, which is `E | Expired` in the signature.
4. The block runs as a child task. If the deadline passes first, the child is stopped and drained, and the expression fails with `timeout.Expired`. The result comes only after the child has finished, so completed cleanup beats deadline punctuality (NORTH_STAR tiebreak).
5. If the parent is stopped first, or while the block runs, the child is stopped and drained, and the expression's exit is an interruption.
6. A defect in the child re-raises in the parent on every path.
7. The block ends with an expression, and it may not contain `return` ([grammar.md](grammar.md#expressions), trailing-block rule; S109 in the prototype). Write an explicit `func` literal to return early.
8. **Deadline.** The deadline is time, and time is a capability: `v1.After` arms no host timer. It starts a second child of the caller's task that calls `Sleep(d)` on the `Scheduler` the caller's environment binds, and the deadline passes when that `Sleep` ends without a stop. So a test `Scheduler` decides when the deadline passes, and a timeout test needs no real sleep (Q-S4-7; `TestTimeoutDeadlineIsTheProgramScheduler`). `rt.AfterSpan` races the two children and stops and drains both before `After` returns, so no child outlives the call. A `Sleep` that ends by a defect ends the race too, and the defect is raised in the caller (rule 6).
9. **Lowering.** The block is a function literal of the uniform shape, adapted to `func(*rt.Task) (T, error)`, which runs on the body's child task with a copy of the caller's environment ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Hidden arguments). `timeout.Expired` is `v1.Expired`, so a `catch` arm of it matches the value `After` returns.

*Prior art:* Effect `Effect.timeout`; Go `context.WithTimeout`, which cancels but does not wait for the work to stop; Elixir `Task.yield` followed by `Task.shutdown`.

## Observability and supervision

Status: G1 and G2 are implemented ([#199](https://github.com/cevr/ergo/issues/199)). G4 is implemented (batch 13 tasks-set; [#207](https://github.com/cevr/ergo/issues/207)), with an immediate restart: the `schedule` backoff waits for std `schedule`. Actor supervision is implemented on G4's restart rule (Machines and actors 18, batch 13 MU7). G3 is **designed, not yet implemented** ([#69](https://github.com/cevr/ergo/issues/69), [#200](https://github.com/cevr/ergo/issues/200)).

### G1. Context through `with`

Status: G1 is implemented for string values ([#199](https://github.com/cevr/ergo/issues/199) stage 4a). Restarted tasks (item 6) wait for supervision.

1. `with` takes a context value as well as a context: `with trace.Span("ingest") { with log.Annotate("region", "eu") { … } }`. Several operands are that nesting: `with trace.Span("ingest"), log.Annotate("region", "eu") { … }` ([rows.md](rows.md#with), With 7).
2. A value is a context value when its type satisfies the context-binding protocol: two functions on the type, `func contextKey(v T) string` and `func contextText(v T) string`, each with no `needs` and no `fails`. The checker admits the operand by its type alone, by the rule every operation type uses ([types.md](types.md)), never by the package or the function that made the value. So a user type binds as `trace.Span` and `log.Annotate` do. The names are unexported: the protocol adds no exported declaration to a package. A name operand resolves lexically, before the package's contexts: a local value (a `let`, a parameter, a pattern or loop binding) hides a package context and binds as a context value. A type parameter or a capability of the function's written `needs` row also hides a context of its name, but it is no operand: `with W` there is S108, naming the hidden context. The checker and the reference walk resolve the name by this one rule. A package value (a `let`, a name a pattern `let` binds, a function, or a record type with no fields, which is also a value) and a named context may not share a name (S108 at the later declaration, the later file first), and neither may an import name and a context, so a package name never names both. A rejected protocol operand is S108; the existing refusal for a non-context variable remains S109, naming 196x.
3. The operand is evaluated once, in the enclosing frame, before the region opens. A failure or defect there leaves nothing bound and runs no block. The binding stores the protocol's text under the pair of its type's declaring package namespace and its protocol key, both strings. The namespace keys on the package's identity: a std package's is `std:` and its path (`std:log`), and a program package's is its path. An import path holds no `:`, so a program package checked under a std path, such as `log`, never shares std's keys. A read sees only bindings declared in its own package. Lowering supplies that package as a hidden argument to the read extern ([stdlib.md](stdlib.md)); a user type cannot forge a `trace` or `log` binding by spelling its key.
4. Inside the block the binding shadows an outer one of the same key. It is restored on every exit of the block: its normal end, a typed failure, a defect and a stop, the innermost region first. A context with's `Close` runs with the regions around the with in force, not those inside it.
5. A context value is immutable. A task started inside the block takes the values in force at its start and keeps them after the region ends. It never sees a binding that its parent or a sibling opens later, and its own bindings stay its own. The region owns no task: a task started in it belongs to the enclosing scope, as it would without the with. The values are kept only by the tasks that hold them, and a task drops them when it finishes, so a handle kept past the task holds none.
6. A restarted task inherits the values its factory captured.
7. A read of a context value (`trace.Current`, `log.Annotation`) is effectful: its rows are empty, but it reads the running task, so its frame's footprint is not pure ([rows.md](rows.md#footprints)). A with of a context value adds its operand's footprint and the footprints of its protocol calls. These can be impure even with empty rows. Opening and restoring the region add no further effect.
8. v1 values are strings. Typed payloads, mutable reference payloads and the rest of the trace and log APIs ([#206](https://github.com/cevr/ergo/issues/206)) are follow-ups.
9. *Prior art:* Java `ScopedValue.where(k, v).run(…)`, whose binding children inherit through `StructuredTaskScope`; Effect `References` and `FiberRef` locally; Kotlin `withContext`; Go `context.WithValue`, which has to be threaded by hand.

### G2. Fork-tree defects

Status: G2 is implemented for `task.Go` ([#199](https://github.com/cevr/ergo/issues/199) stage 4b) and for the members of a `tasks.Set` (G4): a member is a child of the task that started it, named by the site of its `tasks.Go`, and a restarted member keeps its task.

1. Each task records its number, its parent while both run, and its site. The site is the source function that forks the task, the call and its position, written as a call frame is: `middle calls task.Go at main.ergo:12:11` ([stdlib.md](stdlib.md), hidden argument 2). The root task is `main`. A task keeps its site when its `Task` moves to another scope.
2. A defect is recorded once, on the goroutine of the task where it happens, while the panicking frame is still on the stack. The record holds the panic's value, that task's Go stack, its chain of tasks and a snapshot of the context values in force for it ([G1](#g1-context-through-with)). A panic that no frame of the task meets, in a function without exit actions, is recorded at the task's boundary in the same form; rt's own recovery never records it. The record travels whole. `Wait` raises it in the waiter. `Stop` and an owner's drain raise it or join it to their other causes. A release joins it to the frame's other causes. No path rebuilds it, so a report never shows the waiter's frames or the parent's later context.
3. When main exits with a defect, the status is 2, and stderr holds each reason of the exit. A defect reads:

   ```text
   panic: runtime error: index out of range [3] with length 1
   	leaf at main.ergo:7
   	middle calls leaf at main.ergo:13:43
   	task #3 middle calls task.Go at main.ergo:12:11
   	  context std:trace.span="ingest" std:log.peer="10.0.0.4" std:log.region="inner"
   	task #2 main calls task.Go at main.ergo:22:12
   	task #1 main
   ```

   - The first line is `panic: VALUE`. A defect in a release (an exit action or a `Close`) adds ` (in an exit action)`.
   - The Ergo frames of the failing task follow, innermost first. The innermost frame is `F at FILE:LINE`, where F is the declaration that holds the panicking line. Each later frame is the call that it made, from the call table: `F calls G at FILE:LINE:COL`. When several calls share a line, the frame names the callee that is the declaration of the frame inside it, or else all of them (`G or H`). A run of one frame, as in a recursion, is written once with its count, `(N times)`. The Go closure around an exit action's block is part of its call, not a repeat. A defect in an exit action shows the action's frames, then the function that registered it, at the line where its exit actions run. When the action runs because the body panicked, that line is the body's panic: the action's frames are followed by the body's panicking frames (`B at FILE:LINE`, `F calls B at FILE:LINE:COL`), then F's callers. The frames end at the body of the failing task. No Go runtime or wrapper frame is written.
   - The chain follows, from the failing task to `main`, each task with its site. It is written when it holds more than the root, or when context values were in force.
   - Under the failing task, a `context` line holds the values in force for it at the defect, outermost first, without shadowed bindings. Each is `PACKAGE.KEY="TEXT"`: the namespace of the package that declares the value's type ([G1](#g1-context-through-with) 3), the protocol key, and the text. The trace span is the value `std:trace.span`.
4. Every reason survives. `Stop` and an owner's drain drop a child's typed failure but keep its defects; `Wait` keeps every reason, and a waiter interrupted while it waits keeps its child's defects beside the interruption. A release defect joins the earlier exit and never replaces it. A `catch` handles typed failures only: an exit that holds a defect or an interruption passes through the `catch` whole. A traced run writes the same report as an untraced run.
5. Ancestry retention is bounded. A defect copies at most 32 tasks of its chain, the failing task first; a longer chain is cut, and the report marks the cut with the line `... (the chain is cut at 32 tasks)` after the last frame, so a cut chain reads apart from a complete chain of 32 tasks. A task's link to its parent is cleared when the task finishes. A defect holds copied frames, not tasks, so no report keeps a task past its lifetime.
6. *Prior art:* Go's traceback names one creator, `created by main.main in goroutine 1`, and drops the creator's own ancestors; Elixir crash reports list the process's `$ancestors`; Effect's `Cause` pretty-printer keeps every failure of a fiber tree with its spans; Kotlin's debug mode adds a `Coroutine boundary` to recovered stack traces. Ergo keeps each defect's own frames, the chain of fork sites and the context snapshot, bounded as the BEAM keeps ancestry: by copying, never by holding the parent.

### G3. `ergo ps <pid>`

1. `ergo ps <pid>` shows the live task tree of a running program: each task's state, what it waits on, its span and its restarts.
2. It is served over a debug endpoint, for people and agents, with the same schema in CLI and MCP.
3. Spans are keyed to checked definition identities ([#188](https://github.com/cevr/ergo/issues/188)), so a trace line links to the source definition and to `ergo inspect`.

### G4. `tasks.Set`

1. `tasks.NewSet[E](policy)` owns any number of tasks and drops each one that ends ([stdlib.md, Tasks](stdlib.md#tasks) 11 to 17). The frame that made it owns it, by the rule that keeps a `Task` in its frame (Tasks rule 8; one rule for both owners of tasks, owner q39): the frame's end stops and drains it with its other entries, last registered first, and a return moves it to the caller. A Set is never a field, an element, a type argument or a capture, so only its owner's task reaches it. A provider that owns a Set waits for the Task-in-a-provider rule (R26), which covers a Set when it lands.
2. The policy is a union, `tasks.FailFast | tasks.LogFailures | tasks.Restart{Limit}`, matched by `NewSet`. Under `FailFast` the first failure or defect closes the Set and stops the other members; under `LogFailures` it is written to standard error and dropped; under `Restart` a defect runs the body again, at once, up to `Limit` times for each `Go`, and a typed failure or the last defect acts as `FailFast`. A backoff (`tasks.Restart(schedule.Exponential(1s).UpTo(5))`) waits for std `schedule`.
3. `tasks.Go(set, body)` takes `body` as an escaping function, as `task.Go` takes its block, because the Set runs it after `Go` returns. Its captures follow the rules of `task.Go`'s block: the structured-lend rule for a captured resource ([resources.md](resources.md#closures) R31, R32) is #197's, for both.
4. A restart runs the same function value, so it starts from what the function captured, never from what the run before it left in local variables. A connection moved into its handler cannot restart; such a Set uses `tasks.LogFailures`.
5. *Prior art:* Erlang/OTP `one_for_one` supervisors restart from the child specification, within an intensity; Elixir's `Task.Supervisor` and `DynamicSupervisor`; Gleam OTP's `static_supervisor`; Effect `FiberSet`; Go's `errgroup.Group`; Kotlin's `supervisorScope` and `coroutineScope`.

## Queues

Status: the runtime body is **implemented** in `runtime/v1` (queue.go); the signatures of the std package `queue` check ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice)), and their calls lower (check-v1 stage D3b; `TestErgoRunQueueOperations`), with task-aware waits (#199 stage 2; `TestRuntime199BlockingProperty`) ([#207](https://github.com/cevr/ergo/issues/207), [#64](https://github.com/cevr/ergo/issues/64)).

Ergo has no channels (parse-v1 ruling 3): `chan` and `select` are reserved words, and there are no nil queues and no direction types. A `queue.Queue[T]` is a first-in-first-out list of values between tasks, with a fixed capacity. Its operations are `queue.New[T](capacity)`, `q.Push(v)`, which fails with `queue.Closed`, `q.Pop()`, which returns `T` or fails with `queue.Closed`, `q.Values()`, `q.Close()`, `q.Poll()`, which returns `Option[T]` and never waits, and `q.Len()`.

1. **New.** `queue.New[T](capacity)` makes an open, empty queue. The capacity is how many values the queue holds that no `Pop` has taken yet. With capacity 0, each `Push` waits for the `Pop` that takes its value. A negative capacity is a defect. *Prior art:* Go `make(chan T, n)`, where 0 is unbuffered and a negative size panics; Kotlin `Channel(RENDEZVOUS)`; Effect `Queue.bounded(n)`.
2. **Push.** `q.Push(v)` adds `v` at the back. While the queue is full, `Push` waits (backpressure). Pushes that wait enter in the order they began to wait. *Prior art:* a Go send on a full channel waits, and Go serves waiting senders in order; Effect's bounded `Queue.offer` suspends; Rust `tokio::sync::mpsc::Sender::send` waits for capacity.
3. **Pop.** `q.Pop()` takes the value at the front, and waits while the queue is open and empty. It returns `T` or fails with `queue.Closed` (rule 5), so it never invents a value ([types.md](types.md#zero-values-and-definite-initialisation) rule 4). *Prior art:* Go receive; Effect `Queue.take`; Kotlin `receive`.
4. **Close.** `q.Close()` ends admission. It does nothing on a closed queue, never waits and never fails. The values already in the queue stay for `Pop` and `Values`. *Prior art:* Effect `Queue.shutdown` and Kotlin `close` may be called again; Go panics on a second `close`.
5. **After Close: `queue.Closed`.** A `Push` on a closed queue, and a `Push` that still waits when the queue closes, fail with the typed failure `queue.Closed`, and the value never enters the queue. A `Pop` on a closed queue takes each value that entered before the close; a `Pop` on a closed, empty queue fails with `queue.Closed`, because it has no value to return. A closed queue is a normal end of the protocol, not a stop: `queue.Closed` is in the error row of `Push` and `Pop`, so a public contract names it and a `catch` handles it, as `actor.Stopped` is for `Send` and `Ask` after `Stop` ([Machines and actors](#machines-and-actors)). An interruption stays the result of a stop from outside ([Exit causes](#exit-causes) 2). *Prior art:* tokio `mpsc`: `send` returns `SendError` and `recv` returns `None`; Kotlin throws `ClosedSendChannelException` on a send and `ClosedReceiveChannelException` on a receive after the drain; Go gives `v, ok` on a receive, but panics on a send to a closed channel, which Ergo does not take: when several producers share a queue, a send after the close is not a programmer error. Effect 3 `Queue.shutdown` interrupts every waiting and later `offer` and `take`, which Ergo does not take either: it would make a closed queue look like a stop.
6. **Values.** `q.Values()` returns `Seq[T]`, which the lowering represents as Go's `iter.Seq[T]` (lower-v1 Q1). Each step is a `Pop`, so `for v in q.Values()` drains the queue in FIFO order, and it ends normally, with no failure, when the queue is closed and empty. A loop that stops early (`break`, `return`, `try`) takes no more values; the rest stay in the queue. *Prior art:* Go's `for v := range ch` ends at `close`; an `iter.Seq` stops when `yield` returns false; Elixir `Enumerable` halts; GenStage consumers take only what they ask for.
7. **Delivery.** Every value whose `Push` succeeded is taken exactly once, by one `Pop`, one `Poll` or one step of `Values`, in the order the values entered. A value whose `Push` failed with `queue.Closed` is never taken. Several tasks may push, pop and iterate one queue at the same time; the order in which waiting `Pop`s are served is not specified. Values copy into a queue; a queue whose element type is a resource is an error in v0 ([resources.md](resources.md#channels); README Gap 30). *Prior art:* Go channels; Effect `Queue`; tokio `mpsc`.
8. **A stop reaches a waiting Push or Pop.** `Push`, `Pop` and each step of `Values` are interruption points ([I1](#i1-interruption-points)) of the calling task. The lowering passes the caller's task to them as a hidden first argument, as it does for every runtime-provided type (gap 1 ruling; [stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Hidden arguments); the runtime operations are `Push(t, v)`, `Pop(t)` and `Values(t)`. When the task is stopped before the operation begins, or while it waits, the operation raises an interruption, not `queue.Closed`: a closed queue is a protocol outcome, a stop comes from outside. A stopped `Push`'s value never enters the queue, and a stopped `Pop` takes no value. A `Push` whose value entered at the moment of the stop succeeds, and the task sees the stop at its next interruption point. Inside a mask ([I2](#i2-automatic-masks)) the waits are uninterruptible. So a frame that ends while its producer waits on a full queue stops and drains the producer (poller.ergo). User code polls at the points of [I1](#i1-interruption-points). *Prior art:* Kotlin's suspending `send` and `receive` are cancellable while suspended; tokio drops a cancelled task's pending `send` or `recv`; in Go the waiter needs its own `select` on `ctx.Done()`.
9. **Poll.** `q.Poll()` takes the value that `Pop` would take when one can be taken now, and returns `Some` of it; otherwise it returns `None`. It never waits, so it is not an interruption point and takes no task. An empty queue gives `None`, open or closed, so `None` does not tell an open queue from a closed one: a consumer that must see the end uses `Pop` or `Values`. On a queue with capacity 0, `Poll` takes the value of the oldest waiting `Push`, and that `Push` succeeds; with no waiting `Push` it gives `None`. When a value leaves a full queue, its room goes to the oldest waiting `Push`, as for `Pop`. The Go body returns Go's comma-ok `(T, bool)`, which the lowering adapts to the program's `Option[T]` ([stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Types 5); the `None` path allocates nothing. *Prior art:* Go's `select` with a `default` case and `v, ok := <-ch`; Effect `Queue.poll`, which returns an `Option`; Kotlin `tryReceive`; tokio `try_recv`.
10. **Len.** `q.Len()` is how many values are in the queue that nothing has taken yet, from 0 to the capacity. The value of a `Push` that still waits for room is not counted, so a queue with capacity 0 always has `Len` 0. It never waits. Another task may change the count at once, so `Len` is a measure, not a promise that a later `Poll` finds a value. *Prior art:* Go `len(ch)`; Effect `Queue.size`, which also counts waiting takers as a negative size (Ergo does not: `Len` is never negative).

## Runtime laws for task, scope and queue

The laws of [docs/research/lawful-runtime-contract.md](../research/lawful-runtime-contract.md) ([#124](https://github.com/cevr/ergo/issues/124), now in #199) that apply to `runtime/v1`'s bodies run as Go tests in `runtime/v1`, under `go test -race`. A passing finite suite is evidence, not proof.

| Law | What runs | Test | State |
| --- | --- | --- | --- |
| R1 | A function's exit actions run last registered first, a loop's once per iteration. | TestFrameReleaseOrder | tested |
| R2 | A function's end drains each unconsumed task, its exit actions included, before an action registered earlier; an exit action's block drains its own tasks before the next action runs. | TestFrameReleaseOrder, TestGoInExitAction | tested |
| R3 | When the owner ends with a failure, an abandoned task's typed failure is dropped and its defect kept. At a normal end, an unobserved typed failure is dropped. | TestAbandonedChild, TestGapR3NormalClose | partial: the normal end is the Tasks rule 12 gap |
| R4 | A completed `Wait` delivers the exit; an interrupted `Wait` delivers neither value nor typed failure. | TestWait, TestWaitInterrupted | tested |
| R5 | `Stop` and an interrupted `Wait` return after the task's exit actions. | TestStop, TestWaitInterrupted | tested |
| R6 | Every reason is kept (a failure with an action's defect, two defects); only a lone typed failure reaches a `catch`. | TestExitCauses, TestWait | tested |
| R7 | A `catch` runs in the failing function. | lowering (a Go type switch in that function) | not a runtime body |

## Tests

Status: **implemented** (lower-v1 stage 4). `ergo test FILE [--seed N] [-work]` checks the file, builds its test binary through `lower.LowerTests` in test mode (`build.ModeTest`, a module of the emission cache apart from the run build's, so `-work` names a different module), writes the binary into a private temporary directory, and runs it as a child, as `ergo run` runs a program: SIGINT gives 130 and SIGTERM 143.

1. **Order.** Each test runs once, in source order, after the package's `let` values are initialised. `main` is not called and is not required.
2. **Verdicts.** A pass prints `ok Name`. A property (a test with parameters) runs by the one rule of laws ([types.md](types.md#laws) rule 10; mu6c, owner q39): when every parameter's type can be listed, within the same caps (256 values a type, 4096 cases), it runs once for every combination of values and prints `ok Name (proved: all N cases)`, and a failed case prints `FAIL Name (case K of N, every value: x = …): …`, the run stopping at that case; any other property takes 100 generated cases (rule 5) and prints `ok Name (100 cases)`, tested, never proved. A test with no parameters is an example: it runs once and prints `ok Name`. A failed assert prints `FAIL Name: assert failed at file:line:column: text`; a failed comparison adds its operands, `text: left L, right R`, and a line diff for two multi-line strings ([grammar](grammar.md#declarations), Declarations 11). A typed failure that escapes the body prints `FAIL Name: a failure escaped the test at file:line:column: text`, the site being the test's declaration. Both fail the test, and the run goes on.
3. **Defects stop the run.** A defect, an exit action's defect after a failed assert included, prints `FAIL Name: a defect, which stops the run` and the runtime's report, and the binary exits 2 with no summary ([decisions](../decisions.md), 2026-11-04).
4. **Summary and status.** The run ends with `PASS (N tests)` and exit 0, or `FAIL (K of N tests)` and exit 1. When a law or a provider was skipped (rule 7), the summary counts the skips too, `PASS (N tests, S skipped)` or `FAIL (K of N tests, S skipped)`, so a skip is never silent (fs4). `ergo test` returns the binary's status. An invalid invocation, a malformed `--seed` included, is exit 2, runs nothing and prints no report line.
5. **Replay.** A property that is not listed (rule 2) draws its 100 cases from its own stream, the seed (`--seed N`, a decimal number, 1 by default) mixed with the test's name, so another test never changes them. A refuted property prints `FAIL Name (case K of 100, seed S, size N: x = …)`, each argument as an Ergo literal of its type: `Point{X: 1, Y: 6}`, a bare empty variant (`Wait`), a quoted string, `[]int{1, 2}`, `Map[string, int]{"a": 1}` with its keys sorted, `(1, "a")`, a float in its shortest exact form with a decimal point or an exponent, a duration in its largest exact unit (`1500ms`). The literal checks in a test and gives an equal value (`TestArgumentTextRoundTrips`). A complex value prints in Go's form, `complex(1.5, -2)`, because Ergo has no complex literal. There is no shrinking ([#162](https://github.com/cevr/ergo/issues/162)).
6. **Generators.** A property's arguments come from generators derived from their types (T4, batch 12; decision O7: wider generators, new failures are findings).
   - **Size.** Case K has size N = K/4 (0 to 25), as QuickCheck's `sized` does. A slice or a Map at the top has 0 to N elements, and each level below halves the bound, so nested collections stay small. The size is printed with the seed, and the same seed replays every case.
   - **Strings.** Strings are biased to short ones: half of them are 0 to 5 units long, the others 0 to N. Each unit comes from a class that a codec treats apart. Half the units are a rune of `abz AZ09_-é世` and line feed. The other half are one of these classes: a quote, a backslash, a control byte (0x00 to 0x1F), DEL, a byte that is not UTF-8 (0x80 to 0xBF alone, 0xFE or 0xFF), an astral rune (U+10000 to U+10FFFF), another BMP rune that is not a surrogate, or printable ASCII. So a string may be invalid UTF-8, as a Go `string` may be.
   - **Integers.** 40% are in -10..10, 15% are an edge, 15% are in -999999..999999, and 30% are any 64 bits. The edges are 0, ±1, and the bounds of each Go width: 127, -128, 128, -129, 255, 256, 32767, -32768, 65535, 65536, 2^31-1, -2^31, 2^32-1, 2^32, and the int64 maximum and minimum. A narrower type wraps the value, so each width meets its own bounds.
   - **Floats.** Floats are unchanged: half are a small half-integer, and the others a finite value.
   - **Constructors.** A named type is built as its package builds it (fu6a, G-exup-7). When its package declares its constructor, the function `New<T>` with no type parameters, the one result `T`, no error or capability row, and parameters that package generates without reaching `T`, the generator calls it with generated arguments, wherever `T` is declared: in the program, in std, or in a field of another record. Else the generator builds the value field by field, which needs the authority of `T`'s package ([types.md, Zero values](types.md#zero-values-and-definite-initialisation) 6). One rule builds a law's provider and a value (rule 7). So `time.Time` is drawn by `time.NewTime(sec, nsec)` from two generated integers: the integers' bias puts most instants near 1970, and `NewTime` keeps each one in the years 1 to 9999 that `Format` and `Parse` read, so a law over a record that holds a time runs (`examples/logstat`). An `fstest.Memory` is drawn by `fstest.NewMemory()`, an empty disk for each case. A value built so prints as its record, `time.Time{sec: 1, nsec: 0, mono: 0, hasMono: false}`, which only its package may write (the seed replays it), or as the call `fstest.NewMemory()` when the constructor takes no argument or a field has no literal (an operation type's). `duration` is a basic type, drawn as an integer of nanoseconds. Gleam's `qcheck` and Elixir's StreamData build a value of an opaque type through the module's own functions (`map` over a generator of its inputs), not field by field; here the compiler picks the function by its name.
   - **Capabilities.** A value of an operation type is built by its builder (fu7a; `internal/sketch/check/builders.go`), so a record that holds an `fs.Files`, an `io.Stdout` or a `sync.Ref` is generated, and a law over it runs, with no constructor written for the test. The builder is the operation type's own `New<I>` (no row, the one result `I`; for a generic `I`, generic in `I`'s parameters in their order: `sync.NewRef[T](v T)`). Else it is the one `New<X>` with no row and no type parameter, in `I`'s package or in its test package (`fs` → `fstest`) when the package under test sees that package, whose result `X` provides `I`: `fstest.NewMemory()` for `fs.Files` and `fs.Writes`, `io.NewRecorder()` for `io.Stdout`, `io.NewInput(text)` for `io.Stdin`. Two such functions are no builder. A builder has no row, so a host provider (`fs.NewHost()`, which needs `Ambient`) is never one: a generated value never touches the disk or the terminal. A builder with no parameters builds the case's world: one value per case, shared by every value it builds in that case (a record's `fs.Files` and `fs.Writes` are one file system), and a new one for each case. A builder with parameters builds a new value each time (two `sync.Ref` fields are two cells). Such a value prints as its builder's call, `fstest.NewMemory()` or `sync.NewRef[int](…)`. `queue.Queue` has none: its constructor `queue.New(capacity)` is not `New<Queue>`, and a generated capacity may be negative or too large to allocate. The prelude's own data types (`Option`, `Range`) are generated as a program's are; a std package's type only by its constructor. Effect provides a test layer per service (`TestClock`) that the test's author picks; here the compiler picks it by its name and its package, as it picks a record's `New<T>`.
   - *Prior art:* QuickCheck `sized` and `choose`; Hypothesis `text()` draws from every Unicode category and biases integers to boundaries; Elixir StreamData grows its size with the run (`max_runs` and `initial_size`); Gleam `qcheck` has generators as values with a size.
7. **Laws.** After the tests, the binary runs each law of the package in source order ([types.md](types.md#laws) rule 10; #162 law-run-1): a top-level law as one run, a member law as one run per provider, and a law whose parameter is an operation type as one run per provider of it. A provider may be declared in another package than the operation type: the least package that sees the law and its providers runs it (law-xpkg). A run whose values can all be listed takes every value and prints `ok law T.L for P (proved: all N cases)` (`(proved: 1 case)` with no values), or `FAIL law T.L for P (case K of N, every value: provider = …, x = …): …`; any other run takes 100 generated cases and prints `ok law T.L for P (100 cases)` or `FAIL law T.L for P (case K of 100, seed S, size N: provider = …, x = …): law refuted at file:line:column: the law is false` (types.md Laws 10, one rule). A run counts as one test in the summary. Its cases draw from their own stream, the seed mixed with the run's name (`law T.L for P`). A failed assert, an escaping failure and a defect in a law's case are reported as in a test's case (rules 2 and 3). A law that cannot run prints `skip law …: reason`, is not counted as a test, and is counted in the summary as skipped (rule 4). A provider whose values have no generator, such as one whose state is a `sync.Ref`, runs when its package declares its constructor `New<P>` with no rows, and a provider with a constructor is always built by it: each case builds the provider with it, from generated arguments, and the report shows `provider = NewTally()` (fs4). The constructor is the one a generator builds any value of the type with (rule 6).

## Machines and actors

Status: **machine plan values, `Emit`, state timers and the pure runs (std `machines`, items 8 to 10), machine inputs and the live machine runner (`actor.StartMachine`, item 11) are implemented; `actor.Start`, `actor.StartAgent`, `actor.Address` and the resource rules of item 7 are not yet** ([#57](https://github.com/cevr/ergo/issues/57), [#101](https://github.com/cevr/ergo/issues/101)). A machine declaration is checked and lowered (lower-v1 stage 4): a program that declares a machine builds and runs, and a value `X{}` is bound, passed, returned and stored like a record value. The lowering is a plan value (item 5), not a running machine:

- `X` is a Go type with no fields, so its values have zero size and are all equal.
- `Initial()` returns the initial value. The program computes it once at start, after every package `let`: package by package in initialization order (a package after the packages it imports), each package's machines in declaration order. A machine of an imported package counts the same as one of the root package (F13). It is checked like a package `let`: it has no typed failure and uses no capability. A defect in it stops the program at start, as a package `let`'s defect does, even when nothing uses the machine.
- `Step(s, e)` calls the step function directly, with no closure and no allocation. A plan `Step` takes no environment only when the step has no error row and no `needs` row and its lowered body reads no environment. Then a plan call costs the same as the direct call (D5). The lowering decides this from what the lowered body reads, not from the rows and the footprint ([rows.md](rows.md#footprints)) alone: a step with no row and an empty footprint still reads the environment when it opens a `with` or calls a declared function (every declared function receives the environment), so its plan `Step` takes it. A step with a row takes the environment and returns the failure, as a function with that row does (D3). `TestMachinePlanValues` holds these rules against a reference model, with steps that open a `with`, call a function that opens one, or loop.
- `Initial` and `Step` are Go methods of `X`, so a user function named `Initial` or `Step` does not collide with them.

The Ergo surface reads a machine through its value: `X{}` converts to the prelude's `Machine[S, E, O, F, R, W]`, a record of `Initial`, `Step` and `After` (items 8 and 9; README Gap 46). The pure run is std `machines` (item 8); the live runner, with an inbox, is the actor library ([#57](https://github.com/cevr/ergo/issues/57), [#101](https://github.com/cevr/ergo/issues/101)).

```go
type State = Closed | Open | HalfOpen
type Signal = Failure | Success | Retry

func step(s State, sig Signal) Decision[State, string] fails ProbeDown needs Probe {
	match (s, sig) {
	case (Closed, Failure):
		return Enter{Open{sig.Endpoint}}
	case (HalfOpen, Success):
		return Enter{Closed{0}}
	case (_, _):
		return Ignore{}
	}
}

type Breaker machine[State, Signal] {
	initial: Closed{0},
	step:    step,
}
```

1. **Machine.** `type X machine[S, E] { initial v; step f }` declares a state machine. `S` and `E` are unions or records: a record is a union of one variant, as it is for `match`, which reads a record subject as one constructor, so one arm covers it (fu-mb2 F10). `initial` is a value of `S`, or names a start function of an input (item 10); `step` names a function from `S` and `E` to `Decision[S, O]`, with any error and `needs` rows.
2. **Decision.** A step returns `Enter{next}` (re-enter, even with the same variant), `Stay{next}` (keep the entry), `Emit{next, output}` (move to `next` and open a new entry, as `Enter` does, and give `output` while the machine keeps running; V5, decision MQ1: "moves and emits"), `Ignore{}`, `Reject{}` (observable, state unchanged) or `Done{output}` (terminal). An entry is the stretch of a run from the commit that opens it (the first state, an `Enter`, an `Emit`) to the next such commit or the end; `Stay`, `Ignore` and `Reject` keep it. *Prior art:* gen_statem returns actions beside the next state (`{next_state, S, Data, Actions}`); Elm's `update` returns `(Model, Cmd)`; XState's `emit` action.
3. **Totality.** The step's switch is total over `S × E` (README Gap 12).
4. **Inspection.** `ergo inspect machine` draws the machine's graph from the step's cases (item 15). A helper the step calls is static in the graph only when its footprint is empty, not its row ([rows.md](rows.md#footprints)).
5. **Protocol.** A machine is a plan that any lawful provider can run; the actor below is the standard library's provider. *Prior art:* XState machines with interpreters; Erlang `gen_statem`.
6. **Actors are library code** (owner, 2026-10-27: "Let's see if we can make actor a library mechanism"; [#101](https://github.com/cevr/ergo/issues/101); [research note](../research/actor-library.md)). The `actor` package is ordinary code over generics, unions, function types with rows, resources and tasks. No compiler rule names it, and it has no syntax.
   - `actor.Start(initial, capacity, handle)` runs `handle func(S, M) actor.Next[S] fails E needs R` over a mailbox of `capacity` messages and returns an `actor.Actor[M, E]`. It charges `R`, which the actor captures. A handler failure ends the actor.
   - A message that wants an answer carries an `actor.Reply[T, E]`. `actor.Ask(to, request)` builds the message around a fresh reply and returns `T` or fails with `E | actor.Stopped | actor.NoReply`. `T` and `E` come from `request`'s parameter type, so a wrong reply type is a type error.
   - `Reply[T, E]` is a resource. `Send` and `Fail` consume it. Releasing it unanswered answers `NoReply` while the actor runs, and `Stopped` once its stop is requested. An answer nobody can receive, because the asker was stopped and detached, is released exactly once (README Gap 37); an answer or failure the library releases is released masked, by its kind, and a refusal releases nothing. A successful result discarded by stop-wins after the handoff (an answer taken just before the asker's task stops, a callback result discarded by a scope's stop) needs README Gap 47.
   - A message, a reply, an agent result and a state snapshot cross a task boundary, so each is a copy that shares no mutable storage with the sender's value (Tasks rule 6; README Gap 45). A resource moves.
   - `Send` waits only while the mailbox is full. Messages are handled in admission order.
   - `Stop` closes admission, then interrupts the actor and waits until it ends. After the stop is requested, no `Send` or `Ask` is admitted: each fails with `actor.Stopped`. Queued requests are answered `Stopped`, every queued message and then the state is released, and every release runs even when an earlier one panics. It returns the typed failure that ended the actor, if any, and every defect in order.
   - `actor.StartMachine(m, capacity, sink)` (implemented; item 11) runs a machine value `m Machine[S, E, O, F, R, W]` (README Gap 46) with `Send`, `Ask`, `State` and `Stop`. `Ask` returns the step's `Decision[S, O]` or the step's failure. `State` returns a snapshot, never a shared reference. A step failure goes to the asker; a step failure after a `Send` ends the actor, because it has no other observer.
   - `actor.StartAgent(initial, capacity)` and `actor.Call(a, f)` serve calls on a state value. The protocol is the functions whose first parameter is `*S`. `f func(r *S) T fails E` borrows the state for one call, and the borrow cannot escape ([types.md](types.md#borrows) Borrows rules 1 and 4; R17, R30, R33). `f` has an empty `needs` row, which is not purity: `f` runs on the actor's task, so a wait inside it is an interruption point (I1) that `Stop` interrupts. A typed failure of `f` is the caller's; an interruption or a defect ends the agent, and the agent releases its state.
   - `actor.Supervise(m, capacity, sink, tasks.Restart{Limit})` (implemented; item 18) restarts a machine actor after a defect, within the budget; a restart starts from `initial`, or from `recover` under `actor.SuperviseDurable`.
7. **Owner and address (resolved 2026-10-27).** `actor.Actor[M, E]` holds the actor's task, so it is a resource (R1, R14): its owner scope stops it at scope end, and `Stop` consumes it. `actor.Address[M]`, from `a.Address()`, holds only synchronised handles, so it copies into tasks and is not a resource. After the actor ends, `Send` and `Ask` on an address fail with `actor.Stopped`. The rules these items need from the checker and the linearity pass are README Gaps 35 to 47.
8. **Machine values and the pure run** (V2 machine-run). A value of a machine declaration `type X machine[S, E]` is assignable to the prelude's `Machine[S, E, O, F, R, W] { Initial S, Step func(s S, e E) Decision[S, O] fails F needs R }`, where `O`, `F` and `R` are the step's output, error row and capability row ([types.md, Assignability](types.md#assignability) 6), and a generic call infers them from the value. The conversion builds `Machine{Initial: X's initial value, Step: the step function, After: the after function}` (item 9; with no `after` entry, a function that gives every state `None`). Std `machines` runs a `Machine` as a fold:
   - `machines.Run(m, signals)` steps `m` from `m.Initial` over `signals`, in order, one signal at a time. `Enter`, `Stay` and `Emit` commit their `Next`; `Ignore` keeps the state; each `Emit`'s output is kept, in order. The run ends at the first `Done` with `Finished{State, Output, Emitted}`, where `State` is the state the step saw, or after the last signal with `Running{State, Emitted}`; `Emitted` holds the outputs of the run's `Emit`s. `Run` has no clock, so the machine's timers never fire. The first `Reject` fails the run with `machines.Rejected{At}`, the index of the rejected signal. A failure of the step ends the run with that failure: `Run` has the row `fails Rejected | F needs R`.
   - `machines.From(m, s, signals)` is `Run` from the state `s`. The law `RunSplits` holds: when `Run(m, a)` is `Running{s}`, `Run(m, a ++ b)` is `From(m, s, b)`, with the rejected index counted from the start of `a ++ b`.
   - `machines.Next(s, d)` is the state after the decision `d` in `s`: the `Next` of `Enter`, `Stay` and `Emit`, else `s` (law `NextTakesItsState`). `machines.Initial(m)` is `m.Initial`.

   **The flat run** (MU8). A call `machines.Run(X{}, signals)` or `machines.From(X{}, s, signals)` whose machine is a machine declaration's value lowers to a loop of its own: the state is a Go value (the index of its variant and that variant's record, never an interface), the step's body is lowered a second time to switch on that index and to return its decision as a kind, a next state and an output, and the loop calls it directly. A run of 100,000 signals of effect-machine's "simulate" counter allocates twice per run, not twice per signal, and costs about 1.4 ns a transition where std's loop costs about 68 ns (`BenchmarkMachineFlatRun`, measured beside a hand Go loop over the same `[]Sig`). The loop keeps a cancellation check (at each signal, or for a pure step once every 256 signals: Flat signals, below). A step with an error row, an owned parameter or a frame scope, a state union of more than 255 variants, a machine with an input and a machine passed as a `Machine` value keep std's loop. The reference lowering, std's loop for every run, is selected with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.machineLowering=interface`; `TestMachineFlatRunAgrees` holds the two equal, and both equal to `machines.RunTimed` at time 0, over seeded machines and signal lists.

   **Flat signals** (MU8b). A union that a machine declaration takes as its signal is, where the rule admits it, a Go struct of a tag (the variant's index) and one slot for each variant that has fields, not a sealed interface ([union-repr.md](../research/union-repr.md) forms B and D, each variant's record whole in its slot). A `[]Sig` is then a slice of small values, and a match on a signal switches on the tag. The rule: the union is in a package of the program's source, it is not generic and is no machine's state, its variants are records that are neither generic nor error types and have at most 4 fields of basic types, at most three variants have fields, the struct is at most 32 bytes (what Go keeps in registers), and no Go extern's signature names it. Every other union keeps its interface, and so does one that an error type holds or that a test property takes as an argument: the lowering meets its text, literal or generator, and lowers the program again with that union an interface. Values, `==`, matches and runs are unchanged. A run of a pure step (one that takes no capability) checks for a stop once every 256 signals instead of after each one, so a stop is seen within 256 steps; a step that takes a capability checks after each signal. The reference representation, a sealed interface for every union, is selected with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.unionLowering=interface`; `TestMachineFlatRunAgrees` runs each generated program with flat signals, with interface signals and through std's loop, with and without the match tree, and requires one output.

   The fold is ordinary Ergo code, one call of the step function value per signal. `lower/machine_run_test.go` holds it against a reference fold over generated step tables and signal lists (`TestMachineRunAgreesWithFold`). *Prior art:* XState's pure `transition(machine, state, event)` and `createActor` for the live run; `@effect/experimental` `Machine`; Erlang `gen_statem`'s callback module apart from its process; Elm's `update` folded over messages.
9. **State timers** (V5 machine-after; decisions MQ1, MQ3, MQ6). A machine may declare `after: timer`, where `timer` is a package function `func(s S) Option[Timeout[E]]` with no rows; `Timeout[E] { In duration, Signal E }` is a prelude record. The runner owns the timer, the program never starts or stops one:
   1. When an entry opens (the first state, an `Enter`, an `Emit`), the runner calls `timer` on the committed state, after the commit; `Some{Timeout{In, Signal}}` arms the entry's timer to give `Signal` `In` after the commit. `In` is computed from the state, so two states of one variant may wait differently. A timer whose `In` is not positive (`0s` or less) is a defect, raised when the runner arms it (fs2; decided by principle, owner may overrule): such a timer would fire at its entry's instant, and a state whose timer re-enters it would never let time pass, so the run would loop at one instant. The defect of a declared machine names the machine, the state and the duration, `machine Loop: the timer of state Idle{n:1} has In 0s, which is not positive; a timer waits a positive duration`: the lowering wraps the machine value's `After` (`v1.MachineTimerNotPositive`), so every runner that calls it, `RunTimed` and the live runner alike, raises it. A `Machine` built from parts has no name, so `RunTimed` raises it with the run's time instead (`a Machine built from parts: the timer armed at 0s has In -1ns, …`). `TestMachineTimerNotPositive` holds both over generated durations: a positive one arms and fires, a non-positive one is this defect, and no run loops. *Prior art:* Go's `time.NewTicker` panics on a non-positive period; Erlang `gen_statem`'s `state_timeout` of 0 fires at once, before any later message, so a state that re-arms it loops.
   2. `Stay` keeps the entry and its timer: it neither restarts nor cancels it. `Ignore` and `Reject` keep it too.
   3. An entry that ends takes its timer with it. Each armed timer carries the epoch of its entry, and the runner drops a timer whose entry has ended instead of stepping it (rule 6 of the runner contract: no stale signal), so a timer never fires after its entry, even one already due when the entry ended. A re-entry of the same variant (`Enter` or `Emit`) is a new entry with a new timer.
   4. A fired timer's `Signal` is stepped like any signal. A `Reject` of it keeps the state, as `Ignore`, since no one asked.
   5. **Order on a clock.** A signal that arrives at the instant a timer is due is stepped first; the timer then fires only if its entry still holds. Of two timers due before a signal, the earlier fires first.

   6. **One clock** (batch 12, finding F4). A program has one notion of time: the `time.Clock` and the `Scheduler` its context binds. Every machine timer reads that clock and waits on that scheduler, as a task's `Scheduler.Sleep` and `timeout.After`'s deadline do; no runner keeps a clock of its own. In production the context binds the host (`time.NewHost`, `NewLiveScheduler`); a test binds one `testing.VirtualClock` or `time.Manual` for both, and then one advance of that clock moves the machine's timers and the test's sleeps together. A runner that arms a timer by `Scheduler.Sleep` of its `In`, as the actor runner does, follows this rule with no change.

   `machines.RunTimed(m, trace, end)` is the timed fold, the reference of the live runner (the actor library, #57). It reads time by rule 6: its row is `fails Rejected | F needs time.Clock | Scheduler | R`. `trace` is `[]machines.Timed[E]{At, Signal}`, signals at times since the call, by `time.Clock`. Before it steps a signal or a timer, the run waits on `Scheduler` until the clock reads its time, and it takes the time the clock reads as the step's instant: a signal earlier than that is stepped at it (the clock never goes back), and a timer is armed `In` after it. The order of the steps (5) follows the times of the trace and of the timers, never a reading. After the last signal, each timer due by `end` fires, and a run with no `Done` waits until `end`. It ends as `Run` does, `Rejected{At}` naming the index in `trace`. On a virtual clock the instants are exactly the trace's and the timers' times, so the run is a function of `m`, `trace` and `end`, and it takes no wall time. The law `UntimedRunsAsRun` holds: with no timer, `RunTimed` over signals at any times is `Run` over them (on a `testing.VirtualClock`). `TestMachineRunAgreesWithFold` holds `RunTimed` against a discrete-event model with one timer slot (a different algorithm from the std body's epoch-tagged timers) over generated step tables, timers whose `In` reads the state, and traces with ties and late signals; its generator checks it reaches a fired timer, a fire after a `Stay`, an entry that ends before its timer, a signal at a timer's deadline and a rejected timer signal. Each timed run is on a `testing.VirtualClock`, beside a task that sleeps until each of the trace's times on the same clock: the program prints the clock's reading when the run ends, which must be the model's last instant, and the times the task woke, which must be the trace's times (the clock moves for both). *Prior art:* Erlang `gen_statem` `state_timeout` (cancelled by a state change, kept by `keep_state`); XState `after` transitions (cancelled on exit); Akka Typed `TimerScheduler` (a cancelled or restarted timer's message is never received, even when already queued: the epoch rule). Elixir's `Process.send_after` and Gleam OTP's `send_after` are not cancelled by a state change, so programs check a timer reference by hand; Ergo's runner does that check.
10. **A machine's input** (V4 machine-start; owner decision O3b). A machine's `initial` may name a package function `start` whose result is `S`: `type Saga machine[Stage, Signal] { initial: start, step: step }` with `func start(order string, now int) Stage`. Its parameters are the machine's input `I`: the one parameter's type, or the tuple of the parameters' types (`(string, int)`). `start` has no type parameters and no error or capability row: the caller computes the input with its own capabilities, so the first state stays pure. A start of another shape, or with a row, is S108. Such a machine's value converts to the prelude's `InputMachine[I, S, E, O, F, R, W] { Start func(input I) S, Step, After }`, not to `Machine` (S108 names `machines.Start`); its plan has no `Initial`, and nothing runs at program start. `machines.Start(m, input)` is the `Machine` whose `Initial` is `m.Start(input)`, computed at that call, with `m`'s step and timers, so `machines.Run(machines.Start(Saga{}, ("o1", now)), signals)` runs it, and every run of `Run`, `From` and `RunTimed` takes it. A start of several parameters lowers to a function of the tuple that calls `start` with its elements. `TestMachineRunAgreesWithFold` generates machines with no input, one input and two, and holds each run against the reference fold from `start(input)`. *Prior art:* XState `createActor(machine, { input })`; Erlang `gen_statem` `init(Args)`; Elm `init : flags -> (Model, Cmd)`.
11. **The live machine runner** (MU3 machine-actor; decisions MQ1 to MQ6). `actor.StartMachine(m, capacity, sink)` runs `m Machine[S, E, O, F, R, W]` on a task of its own, a child of the calling task, and returns an `actor.Actor[S, E, Decision[S, O], F]` at once. A machine with an input starts as `actor.StartMachine(machines.Start(m, input), capacity, sink)`. The body is `runtime/v1.MachineStart`; std `actor` builds its helpers from the `Machine` value. The runner contract (the Quint model `docs/research/actor-machine/actor_machine.qnt` checks rules 1 to 8 and 11 for 2 and 3 senders):
    1. **Run to completion.** One task takes one signal at a time from the inbox, then steps it, commits, arms the next timer and answers, before it takes the next signal.
    2. **Order.** Every signal enters one FIFO inbox of `capacity` signals: outside signals and timer signals. So each sender's signals are stepped in the order it sent them. `Send` waits only while the inbox is full; with capacity 0 it waits until the runner takes the signal.
    3. **Commit.** `Enter`, `Stay` and `Emit` commit their `Next`. `Ignore` and `Reject` keep the state. `Done` keeps the state, gives its output to `sink` and ends the actor.
    4. **Entry.** The first state, an `Enter` and an `Emit` open an entry with a new epoch (item 9). `Stay` keeps the entry and its timer.
    5. **Exit before entry.** When an entry ends, the runner stops its timer child and waits for the child to end before the next entry arms its own timer.
    6. **No stale signal.** A timer signal carries its entry's epoch. The runner drops the timer signal of an ended entry and does not step it. `a.Dropped()` counts these signals (MQ6).
    7. **Timer.** `m.After` of an opening state arms a child that sleeps `In` on the caller's `Scheduler` (a `time.Manual` gives virtual time), then puts the timer signal in the inbox. The sleep is registered as part of the commit: the runner publishes the entry only after the child reached its first wait (its `Sleep` armed), so an observer that sees the entry and then calls `Advance(In)` always fires the timer (`TestActorTimerArmsBeforePublish`). An `In` that is not positive is a defect that ends the actor, after the commit and the `Emit` output (rule 15) and before the answer (an asker gets `actor.Stopped`; `Stop` raises the defect). It is the one defect of Machines and actors 9.1 (`v1.MachineTimerDefect`), with the same text in either runner: a declared machine's wrapped `After` raises it first with the machine's name, and a `Machine` built from parts raises it here with the state and the duration, `panic: a Machine built from parts: the timer of state Idle{n:1} has In 0s, which is not positive; a timer waits a positive duration`. Such a timer would fire at its entry's instant, so a state whose timer re-enters it would never let time pass. `machines.RunTimed` has the same rule (fs2), as Go's `time.NewTicker` panics on a period that is not positive.
    8. **End.** After `Done`, after a step failure of a `Send` or a timer signal, after a defect, or after `Stop`, the runner steps no more signals. The inbox closes, so a later `Send` or `Ask` fails `actor.Stopped`. A queued `Ask` is answered `actor.Stopped`. A queued `Send` is dropped. A queued `State` read gets the last state.
    9. **Failure.** A step failure of an `Ask` goes to the asker, and the actor goes on. A step failure of a `Send` or a timer signal ends the actor, and `Stop` returns that failure. A defect ends the actor, and `Stop` raises it.
    10. **Reference.** On a virtual clock, the actor steps a trace as the pure timed fold `machines.RunTimed` does (item 9). One difference: a `Reject` of an outside signal keeps the state and goes to the asker, but `RunTimed` ends the run with `Rejected`.
    12. **Observers** and 13. **Drain**: item 13.
    14. **Children**: item 14. An entry's children stop, the last started first, before its timer and work stop and before the next entry opens.
    11. **Work.** An entry's work (item 12) starts after the commit that opens the entry and after its timer is armed, before observers see the state; it is a child of the actor's task. Its `send` puts a work signal with the entry's epoch in the inbox. When the entry ends, the runner stops the work and waits for it to end before the next entry starts its own; an interrupted work sends nothing. The runner drops the work signal of an ended entry and counts it in `a.Dropped()`, as rule 6. A defect of the work ends the actor and is never dropped.
    16. **A manual clock settles** (fua-b; batch-13 MB2 G2). Every wait of an actor (the runner's inbox, a full `Send`, an `Ask`'s and a `State`'s answer, a `Changes` loop, `ExitOf`, `Host.Get`, and the uninterruptible waits of `Stop` and `Drain`, which take the caller's task for it) is a wait that a clock's domain sees, as a queue's is: the waiter parks, and the runner unparks it before it makes the event visible. Before batch-13 round 2 (B1), `Stop` and `Drain` waited for the runner's end unparked, so an `Advance` whose caller alone could free the runner (its sink waited on a full queue that the caller popped after `Advance`) waited forever. One `Advance` of a clock runs at a time; a second is a defect in its caller (stdlib.md, time 6). So on a `time.Manual`, whose `Advance` returns only once every task it woke waits again (stdlib.md, time 6), an observer that calls `Advance(In)` after it saw an entry reads the timer's step committed at once. On a `testing.VirtualClock` the time moves while an actor waits on its inbox. Before fua-b, a runner on its inbox was a wait no clock saw: a `VirtualClock` stood still while an actor ran, and `Advance` returned before the actor stepped, so a driver kept the runner's timer rule itself (`search`'s `Play`).
    15. **Output with its commit** (fua-a; batch-13 MB2 G3). An `Emit`'s output and a `Done`'s output go to `sink` first, once the step decided them (a durable actor's save is part of the step, item 17): before `actor.Latest` gives the decision, the old entry's exit (rule 5), the new entry's timer and work, the state is shown (`Changes`, `State`, `WaitFor`), the `Ask` is answered, and the actor ends (`ExitOf`). A signal that the old entry's children, timer or work send while the sink runs carries the old epoch, so it is dropped (rule 6). So an observer that sees a state has every output of the commits up to it, and one rule holds for `Emit`, `Done` and a child's outputs: a child's sink is its `toParent` (item 14), so its output is in the parent's inbox before the child's state is shown. A timer that is not positive (rule 7) raises after the output. Until fua-a the runner showed an `Emit`'s state before it called the sink, so a driver that read `State` and then the sink's values could miss the output. `TestActorModelAgreesWithTimedFold` holds, for each output, the state that a `Changes` loop begun in the sink sees first: the state before the commit (mutant: show the state, then give the output). *Prior art* (inferred from the documented semantics, not measured): Erlang `gen_statem` runs a transition's actions (replies, `next_event`) as part of the transition, and a `sys:get_state` is a system message that the process handles only between events, so no reader sees the new state before its actions ran; Akka Typed persistence runs `thenRun` effects after the event is persisted and stashes the next command until they ran. Gleam OTP and Elixir `GenServer` leave the order to the program (a `send` in the handler, before or after it returns the new state). Ergo takes gen_statem's order as a runner rule, so no program has to choose it.

    The operations: `a.Send(e)` returns once `e` is queued, before it is stepped. `a.Ask(e)` waits for the step's `Decision` or the step's failure. `a.State()` is read in inbox order, so a sender's `State` comes after its own `Send`s. `a.Stop()` interrupts the runner (its next take raises, so nothing queued is stepped after the request), closes admission, waits until the runner and its timer child have ended, and is idempotent. `a.Changes()` is a `Seq[S]` of the state when the loop begins and then each committed state. `sink` gets each `Emit` output and the `Done` output, in order, on the actor's task (MQ2). The waits of `Send`, `Ask`, `State` and `Changes` are interruption points of the caller's task (I1). The `Actor` value is not yet the resource of item 7: it lives until `Stop`, its end, or a stop of the task that started it (the starting task's stop stops it).

    `runtime/v1.TestActorModelAgreesWithTimedFold` holds the runner against a reference timed fold with one timer slot. It uses generated step tables, timers whose `In` reads the state (negative, zero and positive), and traces of `Ask`s, `Send`s, signals at a timer's deadline and `Stop`s, on a test `Scheduler` whose sleeps the test releases. The generator must reach a fired timer, a `Stay` that keeps a timer, a dropped stale timer, a failure to an asker, a failure that ends the actor, a `Done`, an asked `Reject`, a `Stop`, and the defect of a timer that is not positive. Its first case is an `Emit` whose timer would re-enter with the same `In` of 0 and fire forever at one instant; it ends with the defect. `TestActorSendersKeepTheirOrder` (three senders), `TestActorWaitsAreInterruptible` and `TestActorStopCascades` hold rules 2, 8 and I1. The provider laws (`SendsStepInOrder`, `RejectKeepsState`, `DoneIsFinal`, `Actor.StopIsFinal`, `Actor.ChangesStops`) run over the lowered std body. *Prior art:* Erlang `gen_statem` run by its process (one mailbox, run to completion, `state_timeout` cancelled by a state change); Akka Typed (a timer's message from a cancelled timer is never received); Gleam OTP `actor` (a typed `Subject`, one message at a time); XState `createActor` (`send`, `getSnapshot`, `subscribe`, `stop`); effect-machine `Machine.spawn`. Elixir and Gleam do not cancel a `send_after` on a state change, so a program checks the timer's reference by hand; Ergo's runner does that check with the epoch (rule 6).
12. **A state's work** (MU4 machine-work; decisions MQ3, MQ11). A machine may declare `work: w`, where `w` is a package function `func(s S) Option[machines.Work[E, R]]` with no rows of its own: each state owns at most one piece of work (MQ11), and `None` is no work. `machines.Work[E, R] { Start func(send func(e E)) needs R }` is a record of std `machines`, not a prelude name, so a program may declare its own `Work`. The work's capability row is the machine's own row parameter `W`, apart from the step's `R`: the prelude `Machine`'s `Work` field is `func(s S) Option[func(send func(e E)) needs W]`, the work's `Start`. `actor.StartMachine` and `actor.Child` need `R | W | Scheduler`; a fold (`machines.Run`, `RunTimed`) runs no work and needs `R` only, so a law folds a machine whose work needs a service with no binding (fumb-e, lane MB F1; `TestFoldRow`). `machines.Run` and `RunTimed` are folds over signals and start no work; `actor.StartMachine` runs it by rule 11 of item 11. A work is written as a literal of one of two forms, the work rule (S108; effect-machine's task-handler table as one checker rule):
    1. `machines.Work{Run: f, OnSuccess: g, OnFailure: h}`: `f` is `func() T fails F needs R`, and its result becomes a signal through `g func(t T) E`. `OnSuccess` may be left out when `T` is assignable to `E`.
    2. `machines.Work{Listen: f, OnFailure: h}`: `f` is `func(send func(e E)) fails F needs R`, a listener that sends as it goes (effect-machine's `.spawn`); its end sends nothing, and it has no `OnSuccess`.
    3. A typed failure of `f` becomes a signal through `h func(f U) E`, where `U` is `F`'s one type or `F`'s row value. `OnFailure` may be left out when every type of `F` is a variant of `E`.
    4. A map that the types need and the literal leaves out is S108, and its text names the map, the types that need it and the function to write: `this Work's Run gives int, which is not a signal Sig: write OnSuccess: func(t int) Sig, which makes the signal of the result`. A map the types never call (`OnFailure` of an `f` that fails with nothing) is S108 too.
    5. An interruption is not a failure (rows.md, Catch 6): the end of an entry sends nothing. A defect is not one either: it ends the actor.

    `check.TestWorkLiteralRule` generates every (form, result type, failure row, given maps) and holds the checker's verdict against the rule's table. `runtime/v1.TestActorWorkAgreesWithFold` runs generated traces with work (one-shot and listening work, typed failures, interruptions, stale results and defects) against the pure fold, and the Quint model checks start after commit, interruption before the next entry, no send after an interruption, and dropped stale results. *Prior art:* effect-machine `.task(state, run, { onSuccess, onFailure })` requires each handler by TypeScript overloads, whose miss is `TS2769 No overload matches this call`; XState `invoke` with `onDone` and `onError`, both optional and untyped, and cancelled on state exit; Elm `Task.attempt` with one function of a `Result`; Erlang `gen_statem` leaves a spawned worker to the program, which must link or monitor it and ignore its late messages by hand.
13. **Observing an actor, Drain and the exit** (MU12 actor-observe). The runner's rules 12 and 13 of item 11 continue here; the Quint model checks rules 12 and 13 too, with two observers.
    1. **Observers (rule 12).** Each loop over `a.Changes()` gets the state shown at its start, then each state shown after it, once each, in commit order, whatever the number of loops (`ChangesInOrderOnce`). A `Stay`'s state is shown at its commit, an entry's state once its timer and work run (rule 11), and a state whose entry a `Stop` overtook is still shown. A loop ends after the actor ended and it gave every state shown to it: a state written just before a `Stop` counts, and nothing is shown after the end (`NothingAfterEnd`). Each loop has its own buffer, so a slow loop never holds the runner; a returned or broken loop releases its subscription.
    2. **Waits.** `actor.WaitFor(a, pred) S fails Stopped` is the first state `pred` accepts, from the state at the call on; it fails `Stopped` when the actor ends with no such state. Its answer is the one a replay of the written states from its start gives (`WaitForMatchesReplay`): never a state from before the call. `actor.SendAndWait(a, e, pred)` takes the state, sends `e`, then judges that state and the later ones, so it never misses the change `e` makes. Both are loops over `Changes`: no callback is registered with the actor, and none runs on its task.
    3. **Drain (rule 13).** `a.Drain() fails F` closes admission (a later `Send` or `Ask` fails `Stopped`), and waits, uninterruptibly as `Stop` does, until the runner has stepped every signal queued before it, in order, and ended (`DrainStepsQueued`). A `Done`, a failure or a defect among them ends the actor there. Timer and work signals of the open entry cannot enter after the close. A `Stop` overtakes a `Drain`: the rest is dropped. `Drain` returns as `Stop` does.
    4. **Exit.** The actor's exit is one value, written once when the runner ends. `actor.ExitOf(a) Exit[S, O, F]` waits for it: `Finished{State, Output}` after `Done`, `Halted{State}` after `Stop`, `Drain` or a stop of the starting task, `Failed{Error}` after the step's typed failure of a `Send` or a timer signal (a value of the row `F`, owner q47; batch-13 integration), and `Defected` after a defect. Every caller gets the same, at any time, and `Stop` returns the same failure or raises the defect (`ExitIsShared`, `FailedIsExit`). The wait is an interruption point of the caller.
    5. **Latest and Select.** `actor.Latest(a) Option[D]` is the decision of the last signal the runner stepped (a `Reject` and an `Ignore` included, a dropped one not), `None` before the first; it does not wait. `actor.Select(changes, f) Seq[T]` (`T comparable`, or `SelectBy` with an equality) gives `f` of each state with consecutive equal values dropped (`SelectOncePerChange`).

    `runtime/v1.TestActorObserveAgreesWithFold` runs generated traces against the pure fold's state list: several observers (full, lagging behind a `Stop`, and waits) started at random points while the runner is held in a step, `Stop`s that overtake queued signals and unread states, `Drain`s with queued signals, `Done`s and failures; it holds each loop's states, each wait's answer, the exit seen by three callers and by `Stop`, `Latest`, and that no subscription is left. The std laws `ExitIsShared` and `SelectOncePerChange` run over the lowered std body. *Prior art:* effect-machine `waitFor`, `sendAndWait`, `subscribe`, `drain`, `awaitExit` (docs/actors.md): `subscribe` registers a listener callback run by the actor, and its order rules are tested by generated properties; Ergo's observers are loops over `Changes`, so a listener cannot run on the actor's task and its release is the loop's end. XState `waitFor` and `subscribe`; Erlang `gen_statem` has no observers (a program monitors the process); Akka `watch` reports only the end; Elixir `GenServer` with a `Registry` broadcasts by hand.
14. **Children of an entry** (MU5 machine-children; M47). `actor.Child(send, m, capacity, toParent) Actor[S, E, Decision[S, O], F] needs R | Scheduler`, called in a state's work with that work's `send`, runs `m` as an actor that the work's entry owns (rule 13 of the runner contract in `runtime/v1/actor.go`; body `MachineChild`). It runs as `StartMachine` runs a machine; a machine with an input is `machines.Start(m, input)`, as for `StartMachine`.
    1. **Owner.** The entry is found through the hidden task: the work's task binds its entry, so no registry, name or key is involved. `send` gives `toParent`'s result type: it must be the entry's signal type, so the checker holds the map to the parent's signals. The send is the capability to start a child, and only an entry's work has one: the checker accepts a `Child` call only when its first argument is the `send` parameter of the Listen work literal that encloses the call, named as it is; a call in a step, in `main`, in a helper that takes a send, in a Run work (it has no send) or with a copy of the send is S108 at that argument (`check.TestChildOnlyInWork`). The send is a non-escaping function value, so no other task can hold it. The run-time defect `ActorChildDefect` stays as the runner's own guard.
    2. **Identity.** An entry keeps its children in start order, by identity: two children of one machine are two children, and each one stops.
    3. **Outputs.** A child's `Emit` and `Done` outputs go through `toParent` into the parent's inbox as signals of the owning entry. One that arrives after that entry ended is dropped and counted in `Dropped`, never stepped (`NoLateChildOutput`), by the entry's epoch, as a stale timer or work signal is (item 11 rule 6). No program code checks an epoch.
    4. **Lifetime.** When the entry ends (an `Enter` or an `Emit`), and when the parent ends, the runner stops the entry's children one at a time, the last started first, each one with its own children first, and waits for each end. Only then does it stop the entry's timer and work, and only then does the next entry open (`ChildInsideEntry`, `ChildrenStopFirst`). A child's task is a child of the work's task, shielded from its interruption, so only its owner stops it, in this order. A work that started children ends after their stop, so no task ends before its children. A `Child` that races its entry's exit starts nothing, and the call is interrupted, as its work is. A `Send` or `Ask` to a child of an ended entry fails `Stopped`, so an address taken in one entry never reaches the next.
    5. **Ends.** A child's typed failure ends only the child (`ExitOf` on it reads it). A child's defect ends the parent, as a work's defect does: it is pushed as a defect signal, which is never dropped, or, when it cannot be pushed, the parent's stop of the child raises it. So a defect deep in a tree ends each ancestor in turn, and the root's `Stop` raises it. A child of a child is allowed, to any depth.
15. **Sources and `Can`** (MU10 machine-sources; M49, M51). `actor.Feed(a, source Seq[E]) fails Stopped` gives `a` the values of `source` as signals for as long as `a` runs (rule 14 of the runner contract in `runtime/v1/actor.go`; body `ActorFeed`). A source is a library helper, not a machine member (MQ3): `ergo inspect` need not draw it.
    1. **Owner.** `Feed` admits the source as an envelope of the inbox and returns; the runner starts it on a task that is a child of the runner's, so the source lives as long as the actor, not as the caller. A `Feed` on an ended actor, or one whose `Stop` was requested, fails `Stopped`, and its source never runs.
    2. **Order.** A source's values are a sender's: in the source's order, waiting while the inbox is full, and dropped by `Stop` when queued. They carry no epoch: a source belongs to the actor, not to an entry (an entry's sources are its work, item 12).
    3. **End.** When the actor ends (a `Done`, a failure, a defect, `Stop`, `Drain`), admission closes, so the source's next value is not sent: the send raises the interruption and the source ends there. The runner then stops the source's task and waits for its end, so a source that waits is interrupted, and when `Stop`, `Drain` or `ExitOf` returns, no source of the actor runs. A source that ends ends only its feed. A source's defect ends the actor, as a work's defect does (item 12).
    4. **`Can`.** `machines.Can(step, s, e) bool` is whether the pure `step` takes `e` in `s`: its decision is `Enter`, `Stay`, `Emit` or `Done`, not `Ignore` or `Reject`. `actor.Can(a, step, e) bool` is `false` when `a` has ended, with no step run, and else `machines.Can(step, s, e)` for the state `s` after every signal admitted before it (a `State` read through the inbox, body `ActorLiveState`). The step is pure by its type (no failure, no capability), so `Can` acts on nothing and commits nothing.
    5. **A fed value has no answer, by design** (fua-c; batch-13 MB2 G1). A source's value is a `Send`: `Feed` reports nothing per value, and no Ask-like form of `Feed` exists. The reasons:
       - A source is one more sender (rule 2). A value that needs its decision is an `Ask`, and a program writes that source as a task that loops over its `Seq` and asks each value with `a.Ask(v)`, with a `catch` of the step's failure and of `actor.Stopped`. That source gets each decision and each step failure, and it lives as long as its task, not as long as the actor. A second form of `Feed` would duplicate that loop with a second lifetime rule.
       - The question MB2's `sign-in` asked was not "what did the actor decide" but "when has the actor stepped what the source sent". On a `time.Manual` that question is answered by `Advance` (item 11 rule 16): the source and the runner are members of the clock's domain, so `Advance(0)` returns once the source has sent and the runner has stepped and published. In a program on the host, the answer is the state: `actor.WaitFor`, `Changes` or `State` (read in inbox order) after the source's own signal of progress.
       - A per-value answer would make the source wait on the runner for each value, so a source that sends faster than the actor steps would stop being a sender with backpressure and become a requester that waits one step at a time. The inbox's capacity already gives backpressure.
       *Prior art:* effect-machine's `.background` handler sends events with no answer; XState's `fromCallback` `sendBack` returns nothing; Akka Streams `Sink.actorRef` sends with no acknowledgement, and `Sink.actorRefWithBackpressure` adds an acknowledgement for flow control, which Ergo's bounded inbox gives already; Elixir's `GenServer.cast` against `call` is the same split as `Send` against `Ask`; Gleam OTP's `process.send` has no reply, and a reply is `process.call` with a reply subject. None of these gives a stream source a per-element reply.

    `runtime/v1.TestActorFeedSourcesEndWithTheActor` runs generated sets of one to three sources, each ending, failing with a defect, waiting after its values or sending without end, with a `Done` or a typed failure among the values, and ends the actor by those or by `Stop` or `Drain`. It holds that each source's stepped values are a prefix of its values, that a `Drain` steps every value sent before it, that no source runs when the end returns, the exit kind, and that a `Feed` and a live read on the ended actor fail `Stopped` with the source never called. The laws `FeedStepsInOrder` and `CanIsTheStep` run the std bodies.

    *Intent, and what Ergo does not take.* effect-machine's `.background(h)` runs actor-lifetime work that reads `self` and sends events; its `can(event)` answers whether the current state handles an event and is false after the actor stopped. Ergo takes both purposes. The source is a `Seq` of signals, not a handler that holds the actor's `self`: the runner owns its lifetime, so no program code checks whether the actor still runs before it sends. `Can` takes the pure step by type instead of evaluating effectful guards with captured services, so asking cannot act. *Prior art:* Akka Streams `Source.runWith(Sink.actorRef)`, which stops with the actor's stop only through a completion message; Elixir `GenServer` with a linked producer process; Gleam OTP selectors, which merge subjects into one receive; XState `fromCallback` actors invoked at the root and `state.can(event)`.

    The Ergo model `models/children` (`ergo test models/children`, the gate's full tier; wf10 X3) proves `ChildInsideEntry`, `NoLateChildOutput` and `ChildrenStopFirst` by a breadth-first search of every state in a scope of 3 nodes, a tree depth of 2, an inbox of 1 output and entry epochs 0 to 4 ("proved in this scope", not beyond it); each mutant (lateOutput, parentFirst, byKind, and epochWraps, an entry compare modulo 4) is refuted in the same scope with a shortest run, and five witnesses are reached. It replaced the Quint model `children.qnt` (a random simulation of 50000 samples at 5 nodes and depth 3 with two kinds of child, which never found epochWraps), deleted with its script and log. `runtime/v1.TestActorChildrenAgreeWithTree` runs generated trees of depth up to 3 on the real runner against a reference tree: re-entries of any actor at random points, child `Emit`s and `Done`s, a parent held in a step while a child's output is queued behind its re-entry, a child's defect, and the root's `Stop`. It holds the order in which entries end, each parent's stepped and dropped outputs, that a stepped output carries its entry, that each ending child's parent is live and in the child's entry, that a `Send` to a child of an ended entry fails `Stopped`, and that a `Changes` loop on a child ends with the root. `lower.TestErgoRunMachineWork` (`testdata/work/children.ergo`) runs two children of one machine through the CLI.

    *What Ergo removes from effect-machine.* effect-machine starts a child with `self.spawn` inside a `.spawn` handler and shares a lazily started child through `ActorHost` (`acquire`, generations per parent state scope, closed and occupied errors). Its children are named by a string id in the system registry, so two children of one kind need distinct ids, and its host checks a generation by hand. In Ergo the owner is the entry by construction (the hidden task), the child is a value (no id, no registry), the entry's epoch drops late outputs, and the stop order is the runner's rule, so the host's generation check and its closed state are not needed: a child acquired in one entry fails `Stopped` after the re-entry. The host's laws (one screen per entry, an acquire sees its entry, a closed host ends its waiters) are properties of the test above; item 16 adds the host as a value, so a reader can name a child before the child exists.

16. **Hosts** (mu-host; fu-mb F12, em-parity M63). `actor.Host[A]` is an empty slot for one child; `actor.NewHost[A]() Host[A]` makes one, `actor.ChildIn(send, host, m, capacity, toParent)` is `Child` that fills `host` with the child it starts, and `host.Get() A fails Stopped` reads it (rule 15 of the runner contract in `runtime/v1/actor.go`; bodies `NewHost`, `Host.Get`, `MachineChild`).
    1. **Owner.** A host made in a step of an actor (`NewHost` on the runner's task, in the step) belongs to the entry the step's decision opens: an `Enter`'s or an `Emit`'s new entry, or the current entry for a `Stay`. An `Ignore`, a `Reject`, a `Done` or a step failure enters no state, so its hosts close at once. A host made anywhere else (in `main`, a work, a law, the pure fold) has no owner and is closed when it is made. The runner finds the step through a binding of its own task, which no program reads.
    2. **Fill.** `ChildIn` fills a host once, only from a work of the entry that owns it, with the child it starts. Any other host (a host of an ended entry that a state carried into a new one, a filled host, or a host with no owner) is the defect `actor.ChildIn at …: the host is not an empty host of this work's entry`, and no child starts. The check and the fill are made under the entry's lock, so the entry's end comes before the check or after the fill (`NoFillAfterEnd`).
    3. **Get.** `Get` is the child once the host is filled, and waits while it is empty; a stop of the waiting task ends the wait. It fails `Stopped` once the owner entry ended, also after a fill, so a host never gives a child of another entry (`GetSeesItsEntry`): the lease check of effect-machine's `ActorHost` is the runner's, by construction.
    4. **Publish.** An entry with hosts and a work is published (its `Changes` state, the `Ask`'s answer, the first `State`) once its work filled all of them, reached its first wait, or ended, whichever comes first (`FillBeforePublish`; the first wait is `rt.WhenWaiting`, as for the timer of item 7). So a reader that sees the entry finds each host filled, unless the work itself waited before it filled it. An entry with no host keeps the old publish.
    5. **End.** When the entry ends (an `Enter`, an `Emit`, the actor's end), its hosts close first, then its children stop (item 14). A `Get` from then on fails `Stopped`.

    The Ergo model `models/host` (`ergo test models/host`, the gate's full tier; wf10 X4) proves `FillBeforePublish`, `NoFillAfterEnd` and `GetSeesItsEntry` by a breadth-first search of every state in the scope of the Quint model it replaced (4 hosts, entries 0 to 4, at most 2 new hosts an entry, 4 readers; "proved in this scope"), with hosts carried into new entries; each mutant (publishEarly, fillAfterEnd, getNewer) is refuted in the same scope with a shortest run, and four witnesses are reached. It replaced the Quint model `host.qnt` (a random simulation of 50000 samples), deleted with its script and log. `runtime/v1.TestActorHostAgreesWithModel` runs generated scripts on the real runner against the model's rules: entries with zero to two hosts, each filled before the work's first wait, after it, or never, carried hosts, `Stay`s and `Ignore`s that make hosts, a `ChildIn` on a carried host, and the actor's end. After each step it holds each host's state and the entry of the child `Get` gives.

    *Intent, and what Ergo does not take.* effect-machine's `ActorHost.make({identity, spawn})` lets consumers `acquire` a lazily started child of the parent's current state scope, and checks a generation by hand. Ergo takes the purpose, a name for the child that a reader can hold before the child runs, and drops the workarounds: no identity string, no acquire that starts the child (the entry's work starts it, so the start is part of the entry), no generation check (the entry's end closes the host). A `Host` in the first state is closed, since no step made it: a machine whose first state hosts a child enters that state from a first signal. *Prior art:* XState's `assign({ ref: ({ spawn }) => spawn(child) })` stores the reference in the same transition; Akka Typed's `context.spawn` returns an `ActorRef` at once; Erlang's `gen_statem` keeps a pid from `spawn_link` in `Data`; Go's convention is a channel or a `sync.WaitGroup` the parent fills, with the lifetime checked by hand. Gleam OTP and Elixir name processes with a registry or pass a `Subject`/pid in a message, as `Child`'s signal does. *Prior art:* XState `invoke` (a child per state, stopped on exit) and `sendParent`; Akka Typed children, which stop with their parent; OTP supervisors stop children in reverse start order (the order here); Gleam OTP and Elixir link processes, and a late message of an ended state is the program's to ignore.

17. **Durable actors** (MU9; survey M54, MQ5; em-parity rows 35 and 44). A durable actor keeps its committed transitions outside itself, so a new actor, in this process or a later one, recovers its state. The step is pure, so a state is a fold of the signals the actor committed, and a recovery is that fold.
    1. **Hooks.** `actor.StartDurable(m, capacity, sink, recover, save)` is `StartMachine` with two hooks. `recover() Option[S] fails G` runs once, at the start: `Some` is the state the actor starts in, `None` starts it in `m`'s initial state, and a failure fails `StartDurable`. `save(prev, next, sig) fails G` runs for each step that commits (`Enter`, `Stay`, `Emit`; a timer's and a work's signal too), after the step decided and before the actor commits the state, opens the entry, gives an output or answers the `Ask`. So no observer, sink or asker sees a state that `save` did not keep. `Ignore`, `Reject` and `Done` commit no state and save nothing. A failure of `save` is the defect `ActorSaveDefect` (with the failure's text) that ends the actor, and the state does not change; an `Ask` in that step gets `Stopped`. Ergo's type arguments cannot spell a row union (`Actor[S, E, D, F | G]`), so the save's failure cannot join the actor's row; effect-machine's cluster journal makes an append failure a defect too.
    2. **Journal.** Std `journal` is the contract: `Journal[S, E] { Append(e E), Snapshot(s S), Load() Log[S, E] }`, each `fails Failed`, with the laws `AppendAddsOne` and `SnapshotDropsSignals`; `Log` is the last snapshot and the signals after it. `journal.Start(m, j, every, capacity, sink) Actor fails Failed | Diverged` loads `j`, replays its signals from its snapshot (or `m`'s initial state) with `m`'s step, and starts `StartDurable` in the state it reaches, with the save `j.Append(sig)` and a `j.Snapshot(next)` after every `every` saves. A replayed signal that does not commit (the step ignores, rejects, ends or fails) is `Diverged{At}`: the journal is of another machine, or of a step that changed. Providers are packages named after where they keep the journal: `journal/memory` (`memory.New[S, E]()`, for tests and a restart in one process) and `journal/file` (`file.Open(host, path, states, signals)` over an `fs.Host` the entry makes; each write replaces the whole file by a rename, so a crash leaves the old journal or the new one). A file journal needs a `journal.Codec[T]` for the states and one for the signals, with the law `RoundTrips` (em-parity M64: states are not codecs).
    3. **Pure step.** The machine given to `actor.StartDurable` or `journal.Start` has a pure step: its footprint is empty ([rows.md, Footprints](rows.md#footprints) 2 and 3). The checker must see which function is the step, so the machine is a declaration's value `X{}`, `machines.Start(X{}, input)`, or a prelude `Machine` literal whose `Step` names a package function. Anything else, and a step with a capability, a task start or an opaque call, is S108 at the machine argument, naming the step's first impure call and its position: `journal.Start replays the saved signals with the machine's step, so the step must be pure: step step calls the capability operation Console.Println at 10:2`. Work and timers stay allowed: their results reach the step as signals, and the save keeps those the step commits.
    4. **Dropped signals.** A timer's or a work's signal of an ended entry is dropped before the step (item 6 of the runner), so it is never saved and never replayed.
    5. **Fold.** `machines.From(m, s, signals)` (item 8) is the reference: after any crash, the recovered actor's `State()` is `machines.From(m, m.Initial, every signal the journal kept)`, and every `Ask` answered with a commit is in the journal.

    The Ergo model `models/durable` (`ergo test models/durable`, the gate's full tier; wf10 X4) proves `AnsweredIsJournaled` and `LiveIsTheFold` by a breadth-first search of every state in the scope of the Quint model it replaced (7 signals, an inbox of 3, a snapshot every 2 saves; "proved in this scope"), with crashes between any two actions, snapshots and dropped work signals; each mutant (saveAfterAnswer, saveAtSend, staleSnapshot) is refuted in the same scope with a shortest run, and four witnesses are reached. It replaced the Quint model `durable.qnt` (a random simulation of 50000 samples of 40 steps), deleted with its script and log. The law `journal/memory RecoveryIsTheFold` is the model-based test: a generated trace of `Ask`s with crashes at generated points (between steps, a save that fails before it writes, a save that fails after it writes), each followed by a recovery, checked against `machines.From`; `DroppedIsNotJournaled` makes a work's signal queue behind the signal that ends its entry and holds that it is dropped and not kept (lower `TestStdJournalLawsRun`). Lower `TestJournalFileRecovers` recovers a file journal across three processes.

    *Intent, and what Ergo does not take.* effect-machine's persistence lets an entity survive a restart: `lifecycle.recovery.resolve` gives the state at spawn, `durability.save` keeps a snapshot after each commit, and `call` settles after the save; its cluster journal replays accepted events. Ergo takes the purpose and removes two workarounds. Replay determinism is by construction: the checker refuses a step with an effect, where effect-machine documents that handlers must not act on replay and checks nothing. And the save runs before the commit is visible, not after it, so no observer sees a state that a crash could take back. Not taken: `shouldSave` (a provider decides what to write; `every` sets the snapshots), the hydrate-beats-recovery order (one hook), and a runtime codec on every state (a file journal takes a `Codec` for the two types it writes). *Prior art:* Akka Persistence (an event journal with snapshots; `persist` runs its handler after the write, and recovery replays the events with the event handler, which must be pure); Temporal (workflow code replays from its history and must be deterministic, checked at run time by history mismatch, the `Diverged` here); Erlang `gen_statem` keeps no journal (Mnesia or a `dets` table is the program's); Gleam, Elixir and ReScript have no durable actor in their standard libraries.
18. **Supervised actors** (MU7; survey M53; on G4's restart rule). `actor.Supervise(m, capacity, sink, policy tasks.Restart)` is `StartMachine` for an actor that restarts after a defect; `actor.SuperviseDurable(m, capacity, sink, policy, recover, save)` is its `StartDurable`. `actor.Restarts(a)` counts the restarts.
    1. **Budget.** The policy is G4's `tasks.Restart{Limit}`, under the rule a Set's member follows (one rule, owner q39; Go's `restartable`): a defect of the actor's step, timer, work, child, source or save ends the incarnation, and a new one starts while fewer than `Limit` restarts were made, the actor's stop was not requested and its admission is open. A negative `Limit` is a defect. The defect that finds the budget spent ends the actor: `ExitOf` gives `Defected` and `Stop` raises it. A backoff waits for std `schedule`, as G4's does.
    2. **Fresh state.** A new incarnation starts in `m`'s initial state, or, under `SuperviseDurable`, in the state `recover` gives then (the last one `save` kept), never in the crashed incarnation's memory. A failure of `recover` at a restart is a defect of the new incarnation (`ActorFreshDefect`), which the budget counts. Its first entry opens on a new epoch, so no signal of the crashed incarnation's entries is stepped.
    3. **The crash.** A crash ends the incarnation as an end does (item 11's rule 8), but leaves admission open: the entry's children, timer and work stop; the `Ask` in the step and every queued `Ask` get `Stopped`; queued `Send`s and signals are dropped; queued `State` reads get the last state; queued `Feed`s start, since a source lives as long as the actor (item 15). `Send`s and `Ask`s after the crash go to the new incarnation through the same `Actor`.
    4. **Final ends.** `Done`, `Stop`, `Drain` and a typed failure after a `Send` or a timer end the actor for good: no restart follows them, and a defect while a `Drain` runs ends the actor.
    5. **Checks.** The Ergo model `models/supervise` (`ergo test models/supervise`, the gate's full tier; wf10 X4) proves `withinBudget`, `freshState`, `asksAnswered`, `endAnswered`, `terminalFinal` and `exhaustion` by a breadth-first search of every state in the scope of the Quint model it replaced (a budget of 2 restarts, 5 admitted envelopes; "proved in this scope"), and refutes them under the mutants reuse-state, ask-unanswered, restart-after-done and budget-off-by-one, each with a shortest run. It replaced the Quint model `supervise.qnt` (a random simulation), deleted with its script and log. `runtime/v1.TestActorSupervisionAgreesWithModel` holds the runner against a sequential reference with defects injected at random steps, failing fresh states, `Done`, typed failures, `Stop` and `Drain`; the std laws `RestartIsFresh` and `RestartRecovers` hold `Supervise` and `SuperviseDurable` against the pure fold.

    *Intent, and what Ergo does not take.* OTP's restart intensity and Akka's `supervise(...).onFailure(SupervisorStrategy.restart)` keep a process alive across a bug, from its specification, within a budget; effect-machine's `Supervision.restart` does it for a machine actor. Ergo takes the restart from a known state and the budget. It does not take a supervisor tree of its own (the actor's own runner restarts it, and a `tasks.Set` supervises tasks), Akka's `restart` that keeps the mailbox (the queued signals were sent to the state that crashed; OTP drops them with the process), or OTP's intensity window (`MaxR` in `MaxT`), which waits for std `schedule`.

15. **Inspection: the graph and the runner's events** (MU15 machine-inspect; M62).
    1. **Graph.** `ergo inspect machine FILE|DIR [--json]` draws each machine of the root package from its checked declaration (`internal/sketch/machinegraph`): its state and signal variants, its first state's variant (`*` when a start function or a call gives it), each arm of the step in match order with the state and signal variants it takes and the decisions it can give (kind, target variant, `.ergo` position), the timer signal of each state (from `after`) and the states that have work (from `work`). An arm is a case of the step's match on its two parameters, as one match on the tuple or a match on one parameter whose arm matches the other; a step of another shape is one arm that takes every pair. A pattern that tests a field or a literal makes its arm partial: a pair it takes may pass to a later arm. A decision is a `Decision` literal in a value position; a call of a package function of the same package with an empty footprint is read through (item 4); any other value is an edge of unknown kind, `?`. A state whose timer or work is not a `Some` or `None` literal is listed as unsure.
    2. **Coverage.** `Graph.Reachable` lists every pair of a reachable state (from the first state, by the arms' `Enter`, `Stay` and `Emit` edges; an edge of unknown target or kind reaches every state) and any signal, with the arm that steps it (each arm that may, after a partial one). `ergo inspect machine` prints it as `reach (S, E) by file:line`. `machinegraph.TestGraphMatchesTheModel` writes generated machines as Ergo source and holds the graph and the coverage against the generator's model.
    3. **Events.** A traced actor raises an `rt.TraceMachine` event (trace kind `machine`) at each step of the runner contract: `start` (incarnation, state), `signal` (the source: send, ask, work or child; the state and signal variants), `timer-fired`, `dropped` (a stale timer, work or child signal, with its own epoch), `decide` (state, signal, decision kind, the arm's `file:line`, the next state's variant, the epoch after it), `fail` (a step failure), `timer-armed` (epoch, state, the timer's signal, its delay), `work-started`, `work-ended`, `work-failed` (a defect), `work-interrupted` (each with the entry's epoch and no state: the `decide` or `start` of that epoch names it), `child-started`, `child-stopped` (with the epoch of the entry that owns the child; `child-stopped` once the child ended), `stop` (asked by `Stop` or `Drain`; an owner entry's stop shows as the child's `child-stopped`) and `exit` (finished, halted, failed or defected, and the last state). Events name variants and positions, never values. The incarnation is 1 until supervision restarts an actor (MU7).
    4. **The arm.** Go cannot tell which return of the step gave a decision, so the arm is read from the graph: the lowering registers each machine's arms and timers with the program (`v1.RegisterMachine`, as it registers the source map), keyed by its state and signal Go types, and the runner names the first arm that takes the pair of variants; a timer's signal variant comes from the graph's timers. Two machines with the same state and signal types report no arm. This is effect-machine's guard and handler names without the names: the compiler knows the arm's position.
    5. **Cost and binding.** Each event has one hook in the runner, `if t.Traced() { … }`, and its helper is never inlined, so an untraced actor pays one load and compare per hook and builds no event. The hooks sit outside the runner's hottest frames, so its stack stays inside MU18's 2 KB: `start` and `timer-armed` in `loop` and `open` (after the entry's timer and work started), `signal`, `timer-fired`, `decide` and `fail` in `handle` (the helpers read the envelope from the actor), `dropped` in the stale path's `drop`, the work events in the work's goroutine, the child events in `adopt` (which wraps the child's halt), `stop` in `Stop` and `Drain`, `exit` at the runner's end. Measured interleaved against MU18 with no trace bound (`BenchmarkActorSpeed`, 15 rounds): Send, Ask and spawn-and-stop within noise (55 vs 57 ns, 554 vs 568 ns, 2353 vs 2339 ns). `ERGO_TRACE=path` runs a program on a traced root and writes the trace as JSON Lines (`rttrace`, the `machine` field) when `main` returns; the rest of the tracing API is [#206](https://github.com/cevr/ergo/issues/206). `TestActorModelAgreesWithTimedFold` runs each generated case traced and holds the event list against the reference fold's, each decision annotated with the arm the reference finds in the generated arms.
    6. **Not yet.** `ergo ps` ([G3](#g3-ergo-ps-pid), [#201](https://github.com/cevr/ergo/issues/201)) needs a way to reach a live program; until then the trace's last `decide` or `start` of an actor gives its state variant and epoch.

    *What Ergo takes from effect-machine.* Its inspectors receive spawn, event, guard, transition, task and stop events, and `Machine.definition` gives the registrations; a guard or handler shows only when the program names it. Here the graph comes from the step's source and each decision carries its arm's position, so nothing is named twice. Not taken: per-actor inspector options and inspector composition (a trace sink is one `rt.Tracer` per tree). *Prior art:* XState's inspect API (`@xstate/inspect`, actor and event records); OTP `sys:trace` and `sys:get_state` on a live process; Akka's event stream; Elixir `:sys` and Observer.

*Prior art:* Erlang/OTP `gen_server` and `gen_statem`; Gleam OTP `process.call` with a typed reply subject in the message, and Akka Typed `ask` with `replyTo`, which `actor.Ask` follows; Tokio's `oneshot::Sender`, whose drop answers the receiver as a released `Reply` does; Elixir `Agent` for `actor.Call`; Effect cluster entities. Swift and Pony give actors syntax to check shared mutable state; Ergo's actor state is a value owned by the actor's task, so it needs none.

## Host and lowering notes

These notes are not normative; they record the lowering of `internal/sketch/lower` (lower-v1), which a later compiler may change while keeping the rules above. `ergo build` and `ergo run` lower from the checker's `Info` alone; no second checker or emitter runs.

- **Module layout.** A program is one Go module, `ergo.local/program`, with `main.go` and the runtime support `runtime/v1` copied beside it under `ergo/` and named by a `replace` directive, so a build downloads nothing and the emission cache key covers the runtime bytes. One embed owns the runtime files, `runtime/embed.go`: `runtimefiles.Files("runtime/v1")` gives every file of `runtime/v1` and of the runtime packages it imports (`runtime/rt`), and a module laid out with them builds and passes `go vet` alone. The lowering copies that whole closure, `runtime/v1` with `runtime/rt` (check-v1 stage D3b; `TestRuntimeFilesHoldRT`).
- **Capabilities.** Every lowered function, method, function literal, function value, context builder and package initializer takes a hidden first parameter, a pointer to one `Env` struct with one field per capability of the package and the running task, `task *rt.Task` (check-v1 stage D3b; [stdlib.md](stdlib.md#v1-packages-task-scope-queue-and-slice), Hidden arguments). A pure function is the exception: it has no interruption point and reads no capability, so it takes no `Env` and its callers pass none (D5; lower-v1 stage 5). `main` builds the `Env` inside `v1.Main` with the root task and the host providers its row names (today `Console`), and runs the package initializers with it; a host capability it cannot provide is refused at build (S109). An operation of a capability or of the program's operation type takes the running task first ([rows.md](rows.md#capability-rows) 7); a provider's method builds an `Env` that holds only that task, because a provider's requirements are met where the context builds it. A `with` block copies the `Env`, sets the fields its context binds and passes the copy's address on; a context is a generated builder function that evaluates each entry it keeps once, in dependency order, and never builds an overridden entry.
- **Rows.** A function with a non-empty error row returns Go `error` last. A typed failure is the error type's value, a Go struct with an `Error` method; `try` returns it on; `catch` is a Go type switch, whose missing arms re-return the value for a partial catch. `main`'s remaining failure prints `error: VALUE` on standard error and exits with status 1. An error type's text is its name and its fields, written by a generated function per type: `Bad{at:{code:7} ok:true tags:[a b]}`. No user function (a 196m `String` or `Error`) takes part; an operation value writes `<Type>`, a function value `<func>`. A generic error type's text is written per instance, from its type arguments: `type Fault[T] { F T }` with `F` 5 writes `Fault{F:5}`. An error type with a field of a type that has no text form, such as a Map, is refused at build (S109 naming [#49](https://github.com/cevr/ergo/issues/49)).
- **Defects.** A defect is an ordinary Go panic (an index out of range, an integer division by zero). No catch handles it. `Main` recovers it at the root task and reports it with exit status 2, naming the Ergo call chain from the call table (rule 6 of [Exit causes](#exit-causes)). The bodies of `task` and `scope` record it at a task or function boundary with the Go stack at the panic, and `Main` prints that stack ([Exit causes](#exit-causes) 6 and 7), so the line survives.- **Order.** Operands run left to right, each once; an operand a later operand could change is bound to a temporary first. An assignment fixes its place first: the pointer, slice and index that pick it are bound before the value runs. A place is a variable, `*p`, a field or an element, nested in any order. A `*T` function called on a `T` place takes the place's address where the receiver stands, never a copy.
- **Names.** Every package-scope Go name (declarations, reached library declarations, context builders, adapters, text functions, imports, `Env`) is given by a naming pass over the declarations and the checker's Info before any body is lowered; it lowers no body, and lowering runs once. Every local, in user functions and in generated helpers alike, comes from a scope whose parent holds those names, so neither captures the other. A source name keeps its spelling unless Go reserves it.
- **Extern bodies.** A Go body is bound to the prelude or std declaration it implements (`Sleep` of `LiveScheduler`, the prelude's `Append`, `Get` and `Delete`, and the `runtime/v1` bodies of `task.Go`, `scope.OnExit`, `queue.New` and `slices.WithCapacity` with the operations of `Task` and `Queue`), never to the extern's target text. A user extern (one declared outside std) has no Go body: each call of it is a direct call of its Go target, imported under a name the naming pass gives, with no environment and no wrapper. Each argument has its Ergo type (a literal is typed, never an untyped Go constant). Before the call, the lowered Go writes the same call in a block that never runs, as a `defer` statement (`if false { defer strings.ToUpper(s) }`), which admits only a function call. So the target must be a Go function: a Go type, whose call would be a conversion, is a `go build` error ("defer requires function call, not conversion"), and so is a constant. A variadic Go function (`fmt.Sprint`) and a generic Go function (`cmp.Compare`) behind the concrete Ergo signature run: Go infers the type arguments from the typed arguments, as at the call. The Go compiler drops the block. The result is bound at its Ergo result type in every use, a discarded result too. So `go build` checks the target against the Ergo signature and reports a mismatch at the Ergo call's line. The checker admits a user extern only with basic types, empty rows, no type parameter, at most one result and a target in Go's standard library other than `unsafe` ([grammar.md](grammar.md), Extern; `unsafe` is S108, so no Go built-in such as `unsafe.Sizeof`, which `defer` refuses, reaches the block; the rest is [#202](https://github.com/cevr/ergo/issues/202)). A host call is not an interruption point: a blocking Go function such as `time.Sleep` runs to its end, and an interrupt is seen at the next poll after it returns. Two match arms with one value in their type are refused at the second arm, so Go never sees a duplicate case.
- **Values.** Records are named structs; a union is a sealed interface with an unexported marker method; a 196m same-name function on a local record type is a Go method. An operations value is a Go interface; a record that does not have the exact methods passes through a generated adapter. Every function value has one Go shape, `func(*Env, params) (result, error)`, so a value of any row passes where a wider row is expected without a wrapper; a function type whose result is a `Task` adds the destination `*v1.Scope` after the `*Env`.
- **Match.** A pattern match lowers to a decision tree of nested Go type switches and expression switches that tests each value at most once on every path and narrows by the switch, never by a type assertion; an arm that several leaves reach (an or-pattern, or a row the tree copies into several branches) is emitted once after the tree and reached by `goto`, and a match whose tree would exceed max(64, 4 × its pattern nodes) nodes keeps the flat lowering, one expressionless `switch` (batch-10 M1). A catch with record patterns, `case err:` or `case _` lowers through the same tree, with the caught error as its one subject; a branch that no arm takes passes the error on or re-panics with it, as the flat catch does ([rows](rows.md#catch), Catch 8; batch-10 M1b).
- **Actors (MU18).** A machine actor's inbox is `runtime/v1`'s mailbox: a ring with one reused wake channel. The runner is its one taker and waits with a plain receive; its task's stop puts a token in that channel (`rt.Task.OnInterrupt`), and a stopped take returns the interruption as the runner's exit instead of raising it, so a stop does not unwind or grow the runner's stack. An Ask reuses a spare reply channel, never one that a stopped Ask may still be answered on. An idle actor fits a 2 KB goroutine stack. The rules of [Machines and actors](#machines-and-actors) are unchanged: the Queue runner stays as the reference (`ERGO_ACTOR_REFERENCE=1` runs `runtime/v1`'s actor tests on it), and `TestMailboxAgreesWithQueue` holds the mailbox to the Queue over generated traces. Measured against a goroutine with a channel (interleaved, `BenchmarkActorSpeed`): Send about 1.4x, Ask about 1.5x (1.0x against the same goroutine when its waits also wake on a stop), spawn and stop about 1.85x, an idle actor about 670 B more.
- **Packages (196b).** A program lowers to one Go package: every file of the root package, in file order, and every user package it imports. Each declaration keeps the `//line` directive, call table and declaration table entries of its own file, and a refusal names its file. Package-level lets run imported packages first, each after the packages it imports, else in path order (Go 1.21's rule), each package's lets in Go's initialization order; then the root package's. Same-named declarations of two packages get distinct Go names. A test build runs the root package's tests only, as `go test` runs one package's.
- **Not yet lowered.** The build refuses with S109, naming the open owner: an error type's text with a field of a type that has no text form (#49); an indexed slice literal (#196) ([diagnostics.md](diagnostics.md#s109-owned-by-another-ticket)). A `Task` held inside another type or passed as a type argument (S108) and an interpolated value with no text form are the checker's, so the build never meets them. A value of the program converted to a sealed std operation type is the checker's S109 ([#206](https://github.com/cevr/ergo/issues/206)).
- Source positions are carried with `//line` directives, so Go panics, pprof, delve and the race detector point at Ergo lines. A directive names the source by its admitted absolute path. A path that a directive cannot name (a control character, invalid UTF-8, U+FEFF, or a path that is not absolute and clean) is refused before anything is emitted, because a line feed in it would end the directive and turn the rest of the name into Go code.
- **Emission cache ([#224](https://github.com/cevr/ergo/issues/224)).** `ergo build` and `ergo run` emit each package's Go module into `$XDG_CACHE_HOME/ergo/modules/KEY` (else `os.UserCacheDir()/ergo`; a relative `XDG_CACHE_HOME` is ignored for this root; the go command itself still needs `GOCACHE` then). `KEY` is the SHA-256 of a canonical summary of everything emission reads: the sorted source paths and bytes, the dependency summaries (each bundled std package and each imported package of the program is summarised by one digest of all its file names and bytes, which stands for both its interface and its implementation; a summary of the interface alone is not built yet: `stdDependencies` and `sourceDependency` in `internal/sketchfront/sketchfront.go`, `dependencies` in `internal/sketchfront/load.go`), the compiler's producer identity (`internal/producer`, the identity check envelopes report, acquired once, when the cache first needs the key): on Linux the SHA-256 of the executing file (`/proc/self/exe`); on darwin the SHA-256 of the executing image's authenticated code, the bytes below its code signature in the thin Mach-O at the executable's path, accepted only when the kernel's cdhash of the running image names a CodeDirectory of full SHA-256 page hashes and every page matches (a SHA-1 or truncated directory gives a process-scoped identity; two signed files with the same code and different signature data share the identity, by design), under the domain tag `ergo-producer-darwin-code-1` (the signature container and trailing bytes cannot change the running code and are not part of the key), so a compiler replaced during a build cannot key one compiler's output with another's digest, the emitter revision, the runtime files copied into the module, the fixed language revision, the build or test mode and the emission flags. The module's `ergo-manifest.json` states that summary, every output's digest and completion. Where no kernel record exists, or the darwin verification fails (the file was replaced), the identity is process-scoped (`process:` and a nonce): it never keys a published module. The module is built in the process's private root, `ergo/private/ID/modules/KEY`, reused only by that process, and never renamed into `modules`. A build holds a shared `flock` lease on the root from the moment it takes the root until its link ends, on every path, including a failed build; builds of one process share the lease and count their uses, so a long-lived host holds nothing between builds. A build also holds a shared `flock` on the module's directory, published or private, from before it verifies the entry (or, on a miss, from before it writes the first byte into its staging directory, a lock that follows the directory through the rename that publishes it) until its link ends; after the lock it checks that the path still names the locked directory, and opens it again if not. A reused entry is marked as used, by setting the directory's modification time to now, at most once per hour; a hit on an entry marked less than an hour ago writes nothing. The cache trims itself, as Go's build cache does: a build starts a trim at most once per hour per cache, after it has decided and locked its own module. A stamp file, `ergo/trim.txt`, holds `SECONDS CURSOR`: the Unix time at which the last complete trim ended, and where an unfinished trim continues (a missing, torn or future stamp makes a trim due). One process claims each pass by locking the stamp (the kernel drops the claim if that process dies), and a build that finds the stamp recent reads only that file. A pass reads `modules`, `staging` and `private` as one sequence of names in chunks, examines at most 1024 of them and removes at most 64 directories; a pass that hits a bound, or dies, leaves the trim due with a cursor, so the next build continues it. It removes a published entry that no build used for 24 hours, a staging directory older than one hour (a crashed builder's, a moved-aside corrupt entry, a killed trim's leftover) and a private root older than 24 hours, each only when the pass takes the directory's lock (for a root, its lease) exclusively without waiting, so no build holds it, and after it checks under the lock that the path still names that directory and that it is still old. It renames the directory aside into `staging` before it deletes anything, so `modules/KEY` names a whole entry or nothing, and a build that arrives meanwhile emits a fresh entry or root. Ages decide what goes, locks decide when it may go. Where `flock` does not exist, nothing is removed. A producer with no identity at all stops the build with its reason. A module is staged privately and published by one rename, so a partial module never satisfies a hit. A reused module is first verified against its manifest; an entry that does not verify is moved aside and replaced. A valid hit writes nothing. The go command then always links the module, and Go's action cache decides what to rebuild for the toolchain, `GOOS`, `GOARCH` and `GOFLAGS`. `ergo build -work` prints `WORK=DIR` on stderr, where `DIR` is the module. Limits: there is no command that trims or clears the cache on request yet. Any file added in `DIR`, such as the executable of a `go build` run there without `-o`, makes the entry fail verification, so the next build emits it again.
- *Prior art:* Ergo's earlier Go emitter built a closure per effect step and measured a 47.8 s `go build` for 1,024 sequential operations; direct calls rebuilt in 2.08 s in the same measurement. Gleam source maps and ReScript's readable output follow the same "erase to idiomatic host code" goal.

# Decisions

This file is the dated log of the owner's decisions for Ergo, newest first. A decision applies the principles to one feature, construct, stage or tool; [NORTH_STAR.md](../NORTH_STAR.md) holds the principles: what Ergo is for, the pillars, the north stars, the tiebreaks, the owner rules and the rejected directions. Each entry keeps the owner's words, the decision, and its tickets and links as NORTH_STAR.md recorded them; only relative link targets changed, so that they resolve from `docs/`. An entry with two or more dates sorts by its latest date, and entries with the same date keep their order from NORTH_STAR.md. Entries with no date are in the [Undated](#undated) group at the end. Where a moved passage says "above" or "below" and the new order changes what it means, a bracketed note names the entry.

## Owner direction, 2026-11-10

- **The queue's half-close is `End()`; the release method stays `Close()` (2026-11-10, q53).** Asked in #197 lane A: A1 built the half-close of `queue.Queue` as `CloseSend`, on an assumption, beside the release method of a resource. The owner first ruled on the release method ("i think close is fine"), then on the half-close ("i like end"). Decided:
  - A resource's release method is `Close()`, as Go's `io.Closer` names it; it is not renamed `Release()`.
  - The queue's half-close is `End()`, as Node's `writable.end()`: no more values go in, and the values already in the queue still come out. The laws are `EndIsIdempotent`, `PushAfterEndFails` and `EndKeepsValues`. A2 renamed `CloseSend` to `End` everywhere (std, runtime, lowering, tests, examples, docs, CHANGELOG) in its own commit (6cb3b076).

  Rules: [stdlib.md](spec/stdlib.md), queue; [resources.md](spec/resources.md). Principles: one name for one act (a release is `Close`; a half-close is not a release). Prior art: Go's `io.Closer`; Node streams' `end()`; Go's `close(ch)` is the half-close of a channel, and Ergo keeps that word for the release.

- **`examples/chat`'s connection is a full resource (2026-11-10, A2 q1).** Asked in #197 A2 whether the chat example's `Conn` only takes the new names or becomes a resource. The owner chose a full resource in A2, not a rename only, with A2 pulling forward the A4/B3 pieces it needs. Decided: `server.Conn` (`Read`, `Peer`, `Close`) is a resource; `server.Peer` (`Write`, `Hangup`) is a shared handle the room keeps per member; `Serve` takes an accept `queue.Queue[Conn]`, and each serving frame owns one connection, which its scope releases. No code closes a connection by hand. Rules: [resources.md](spec/resources.md). Principle: examples show what makes Ergo different (AGENTS.md).

- **A local helper literal is a non-escaping frame (2026-11-10, #197 C2 q1).** Asked in C2 (captures and borrows) because `examples/router/script` and `examples/search/script` have local helpers, `let f = func…`, that write an enclosing `let mut`; under C2's capture rule they would be refused. The owner accepted the proposal. Decided: a literal bound by `let f = func…` to an immutable local is a non-escaping frame when every use of `f` is a callee or a non-escaping argument and no escaping frame lies between the `let` and the use. One classification, `Info.LocalFrames`, serves the checker and the value lowering. Rules: [types.md, Function values](spec/types.md) 2 and 3. Principle: one rule (q39): a frame that cannot escape is checked as a frame run in place. Prior art: Swift's non-escaping closures; Rust's closures that borrow their environment for a local call.

- **`needs`, `fails` and `takes` stay keywords (2026-11-10, L9 q1).** Asked in L9 (checker gaps, G-ex-d-12: a program could not name a value `needs`). The owner answered that `needs` stays a keyword, as `fails` and `takes` do. Decided: the three row and ownership words are keywords; batch-12 K4's diagnostic for a keyword used as a name closes the gap, and only `examples/deps/README.md` changes. Rules: [grammar.md](spec/grammar.md), Keywords. Principle: explicit contracts (a row word always means a row).

- **Remote calls: Effect RPC, after codecs, with a TypeScript content mapper first (2026-11-10, q73 to q75).** Asked after the RPC research (run dir `r-ts-rpc/plan.md`), from the owner's wish to use Ergo at work beside TypeScript and Effect. Decided:
  - q73: RPC enters v1, right after the codecs (L11) and std `json` (S-json).
  - q74: the wire is Effect RPC only for now; no tRPC.
  - q75, "Mapper first" (it differs from the assumption): the TypeScript side reads `.ergo` files through a TypeScript 7.1 content mapper written in Go, not through a generated, checked-in `.ts`. The mapper unit comes first among the TypeScript-side units and is the path the examples use. A loader-plugin unit ships the runtime half for Bun, Node (module hooks) and Vite/esbuild, with one Go-side emitter, so the types the mapper shows and the JavaScript the loader runs come from the same code. TypeScript 7.1 beta is pinned in the examples and the `ts` tag of `scripts/examples`; a version bump is a reviewed change. `ergo gen ts` is not built now: it is the recorded fallback if the mapper API changes or a consumer cannot run a loader. Acceptance: a changed Ergo signature fails `tsc` at the TypeScript line, an unknown type is reported at its `.ergo` line, and both examples run under Bun and Node with the loader.

  Principles: Go is the only target (the mapper and the emitter are Go; TypeScript reads Ergo, Ergo does not compile to TypeScript); explicit contracts across the wire. Prior art: Effect RPC (its client is the peer the probe ran against); tRPC (not taken); gRPC's generated stubs (the fallback's shape).

- **The interleaving explorer replaces Quint (2026-11-10, q76 to q78).** Asked in the explorer plan (run dir `explorer/plan.md`); the owner answered as assumed. Decided:
  - q76: invariant laws are spelled `law N always f` and `law N sometimes f` on a machine, with `f` a pure `func(s S) bool` (unit X2, after #197 lane A). Until X2, a model uses a `Broken` variant with `never reaches`.
  - q77: a search that reaches its budget passes with "not proved: explored N states, depth D"; the default budget is 1,000,000 states, a count of states and never a time.
  - q78: Quint is retired as the ports land. New protocol designs are Ergo models that the explorer checks; each Quint file is deleted when its Ergo port lands (X4 deleted four).

  Rules: [types.md, Laws](spec/types.md#laws) 13; [stdlib.md](spec/stdlib.md), Testing 13. Principles: one language for code and design; a guarantee is stated as proved only when the whole graph was seen (NORTH_STAR pillar 4). Prior art: TLA+'s TLC and Quint (breadth-first search with an invariant, a shortest counterexample); SPIN's bounded search; Hypothesis's stateful tests sample where this search enumerates.

- **Codecs: a predeclared `wire` constraint, `encode`/`decode` built-ins, and std `codec` (2026-11-10, q79 to q83).** Asked in L11 (codecs). The owner answered q79 to q81 as assumed. To q82 the owner asked "whats the std wire"; the orchestrator explained that it was the test helper (an `Events` recorder Writer, a `Replay` Reader and their round-trip laws), not a format, and asked again. q83 decided the names. Decided:
  - q79: the compiler knows one predeclared constraint and two predeclared operations, `encode(v, w)` and `decode[T](r)`, over the prelude operation types `Writer` and `Reader`. A format, such as std `json`, is ordinary Ergo over those events. No library item is fulfilled by name, and nothing uses reflection: the lowering writes one Go function per type and direction.
  - q80: the row former `wired[T]` spells, in a generic signature, the row `decode[T]` can fail with: the Reader's failures, the shape failures, and each `ParseX` row that `T` reaches.
  - q81: an exported field's name goes on the wire with its first letter lowered (`Port` is `port`), and a union is `{"_tag": "<Variant>", …}`, as Effect's `Schema` writes them.
  - q83: the constraint is `wire` (`func f[T wire]`), a predeclared identifier like Go's `comparable`: not a keyword, so a local declaration may shadow it. The std test-helper package is `codec` (`codec.Events`, `codec.Replay`, and its laws). The derived `ParseX`/`Wire` pair keeps the function name `Wire`. Until the rename lands with S-json (one commit: `codable` to `wire` in the spec, the checker, the lowering, std, the examples, the diagnostics and the ledgers, and std `wire` to std `codec`), the code spells the constraint `codable` and the package `wire`, as L11 built them.

  Rules: [types.md, Codecs](spec/types.md#codecs). Principles: no reflection, a Go function per codec (NORTH_STAR principle 7); a typed failure for every shape error. Prior art: Rust's serde (a data model of events between types and formats); Roc's `Encoding` abilities; Effect's `Schema`, whose class and `_tag` workarounds Ergo replaces with a constraint and unions; Gleam's and Elixir's hand-written decoders.

## Owner direction, 2026-11-09

- **Ownership spelling: a `takes` clause, shown copies, `escaping` merged later (2026-11-09, q69 to q71).** Asked after the #197 ownership prior-art study (run dir `v1-L8/prior-art.md`); the owner answered as assumed. Decided:
  - q69: a function that keeps an argument says so in a clause after its rows, `func NewLog(f File) Log takes f`, and a bare `takes` on an operation takes its receiver. The clause is inferred for an unexported function and written on an exported signature, as rows are; it is part of a function type's identity, as `escaping` is.
  - q70: an exported generic function that copies a `T` carries no mark: the copies are shown in docs, `ergo inspect` and the summary diff.
  - q71: `escaping` (a kept function value) and `takes` (a kept resource) say one thing, that an argument outlives the call; they merge into the `takes` clause in a later unit, as one rule (q39), not in L8.

  Rules: [resources.md](spec/resources.md); [types.md, Function values](spec/types.md). Principles: inferred where private, written where public (as rows); one rule (q39). Prior art: Lean 4's owned and borrowed parameters (an inferred lent-to-taken fixpoint per component); Swift's `consuming` and `borrowing`; Rust's moves.

- **A trailing function literal (2026-11-09, q72).** Asked in the GUI plan (q68, explained and asked again as q72): the owner chose option (c), a trailing `func(...)` literal with Go's parameter list. Decided: `ui.Each(todos, keyOf) func(t Todo) ui.Node { row(t) }` means `ui.Each(todos, keyOf, func(t Todo) ui.Node { row(t) })`. It is an ordinary function literal moved after the call, so `return` works in it as in any literal. The parameterless trailing block `f() { body }` stays as it is: one rule for both (q39). Unit L-tb built it (grammar.md, Trailing blocks). Prior art: Kotlin's and Swift's trailing lambdas and closures; Ruby's blocks.

- **`any` only as the type-parameter group marker (2026-11-09, q50).** Asked when batch 12's fu8b let `any` end an unconstrained group of type parameters before a constrained one, `[E any, K comparable]`, which D-E2's closed world ("`any` is not a type") did not allow. The owner allowed it there and nowhere else. Decided:
  - `any` ends a group of unconstrained type parameters that a constrained group follows; the parameters it ends have no constraint, as `[E]` has none. It is not a constraint and not a type.
  - Every other use stays S104 "Ergo has no any; use a type parameter or a union", `[T any]` alone included (written `[T]`). D-E2 is narrowed by this one marker; the closed world holds otherwise (no value is compared or held through an interface).

  Rules: [types.md, Basic types](spec/types.md#basic-types) 8 and [Generics](spec/types.md#generics) 2; [grammar.md, Declarations](spec/grammar.md#declarations) 3. Principles: explicit contracts (a constraint applies to the names before it, so a marker is needed to end an unconstrained group); one rule for `any` (only the marker). Prior art: Go writes `[E any, K comparable]` and the marker is Go's `any`; Gleam and ReScript have no `any` and no constraints on type parameters.

- **A Ref owns its value; a defect poisons it (2026-11-09, q46).** Asked in batch 12 (fu-small-2 fs6: a write to `fstest.Memory` cost O(tree), and n `io.Recorder` Prints O(n²), because the function given to `sync.Modify` copied the held Map before each write); the owner chose option A. Decided:
  - V6: the parameter of a function literal written at `Ref.Update` or `sync.Modify` takes the held value over and may write it in place. No binding outside the `Ref` ever sees that write: the `Ref` marks a value that may be reached from outside (`NewRef`, `Set`, `Get`, and an `Update` or `Modify` with any other function) and copies it, under its lock, before it hands it over; the lowering proves the literal's results unshared, or the stored value is marked too.
  - A defect in an `Update`'s or `Modify`'s function poisons the `Ref`: the defect reaches the caller as it is, and every later `Get`, `Set`, `Update` and `Modify` raises a defect that names the poisoning (as Rust's `PoisonError`; the runtime records a defect only at a task's boundary, so the `Ref` does not recover the first one to raise it again). This replaces "a defect leaves the `Ref` usable, with the value it held before" (runtime/v1 `TestRefSurvivesADefect`, now `TestRefPoisonedByADefect`): an in-place write may be half done, and no task may see a torn value. v1 has no escape such as Rust's `into_inner`.
  - The copying lowering (`valueLowering=copy`) hands nothing over and stays the reference; a seeded property holds the two equal.

  Rules: [stdlib.md, Sync and STM](spec/stdlib.md#sync-and-stm) 1; [types.md, Bindings](spec/types.md#bindings). Principles: correctness first (no torn value is observed); one rule for every `Ref` (owner q39); zero-cost implementations (a change costs what it changes). Prior art: Rust's `Mutex` poisoning; Swift's copy on write; Clojure's transients.

- **Building a value from another value: one rule (2026-11-09, q43 to q45).** The owner answered the spread plan's three questions (run dir `spread/plan.md`; the one-rule direction of q39: "a language hole gets one consistent rule across the language, not a construct-local fix"). Decided:
  - **q44, no implicit zero.** A record value is built only by a literal that names every field, or by a spread. A keyed literal that leaves a field out is S108, whatever the field's type, and `let x R` with no value is S108 for a record `R` with fields and for a tuple or instance that holds one. Basic types, slices and Maps keep their zero value. This replaces Go's zero fill ([types.md, Zero values](spec/types.md#zero-values-and-definite-initialisation) 2 and 3; sp-total-literal).
  - **q43, a spread copies by declaration (option A).** `T{..s, F: v}` fills each field of `T` that it does not name from the field of `s` that has the same declaration: `s` is an instance of the same record type (its type arguments may differ), or both fields come from one included record `..R`. A record declaration or an inline variant includes the fields of a record `R` of its package with the member `..R`. A field of the same name from another declaration is not copied: the spread is S108 and the message shows the explicit copy. Not taken: a spread by field name from any record (option B), because a field added to `T` that the source already declares by that name would be copied with no decision (sp-include, sp-spread).
  - **q45, no nested path keys now.** `Config{..c, Listen.Port: p}` is not added; a nested spread and a `let mut` copy with a path assignment both work. Revisit when an example needs three levels.
- **A row parameter may stand in every type position (2026-11-09, owner q47).** Asked after batch 13's fail-field unit found that `type Exit[T, F] = … | Failed{Error F}` could not hold an actor's failure row `F` (S108 "F is used as an error row and as a type"). Owner: "whatever is more consistent and correct". The orchestrator's ruling: the consistent rule is that a type parameter may appear in every type position, rows included. Decided:
  - An error row parameter in a type position names the row's value type, the type a `case err:` binding already has: the anonymous union of the row's error types. A row written as a type argument names it too (`Exit[int, NotFound | Busy]`), and the parser reads `|` in type arguments.
  - The value type has the rules of a union over its members: a member or a narrower row value goes in; a `match` is total over known members and needs `case _` or a binding for a parameter member; `==` applies when every member is equatable (so `err == err` now compares, where it was S108); a property draws one member and prints it as its literal.
  - It lowers to a Go `error`; a row parameter has no Go type parameter.
  - A capability row still has no value type, so a type and a capability row stay S108.

  Rules: [types.md, Generics](spec/types.md#generics) 1 and [rows.md, Error rows](spec/rows.md#error-rows) 8. Principles: one consistent rule across the language (q39); explicit contracts (the field's type is the row the operation fails with). Prior art: Zig error sets as value types; OCaml polymorphic variants; Effect's `Exit<A, E>`.

- **A union of one existing type is an alias (2026-11-09, owner q48).** Asked after batch 13's lane MB (finding F11: `actor.Actor[Edit, EditSignal, Decision[Edit, EditOut]]` written nine times in order-builder, with no way to name it: `type A T` is a new type that `actor.Child`'s result does not convert to). fu-mb2 built the alias on the assumption; the owner answered "F11 yes". Decided:
  - `type A = T`, a union whose only variant is an existing type, is that type: every use of `A` is `T`, with no conversion either way. The existing type may be of any kind and any package. A one-variant union declared in place (`type V = R{ … }`) declares its variant and stays a new type.
  - An alias that names itself is S108; an alias takes no type parameters yet (S108 at the brackets). Diagnostics print the target.
  - It lowers to Go's `type A = T`; `TestAliasChecksAsItsTarget` holds a program of aliases to the program with each alias written out.

  Rules: [types.md, Unions](spec/types.md#unions) 7. Principles: one rule (a union over existing types is the set of those types, so a union of one is that type; no new keyword). Prior art: Go `type A = T`, Gleam and ReScript type aliases, TypeScript `type A = …`.

- **A parent reaches its child through `actor.Host` (2026-11-09, owner q49).** Asked after lane MB's finding F12: a child's address reached its parent only as a signal (`Opened{Sub: actor.Child(…)}`), so the parent's state held `Option[Actor]` that was `None` until the signal was stepped, and every reader waited for it. mu-host built `actor.Host`; the owner answered "F12 yes". Decided:
  - `actor.NewHost[A]()`, made in a step, is an empty `actor.Host[A]` that the entered entry owns; the entry's work fills it once with `actor.ChildIn(send, host, m, capacity, toParent)`; `host.Get() A fails Stopped` waits while the host is empty and fails `Stopped` once the entry ended. The entry is published after its work filled its hosts, waited or ended.
  - `Host` has no member law (its answers depend on an entry only the runner opens); `TestActorHostAgreesWithModel` holds it against the Quint model `host.qnt`.

  Rules: [stdlib.md](spec/stdlib.md), actor 7 (Hosts); [runtime.md, Machines and actors](spec/runtime.md#machines-and-actors) 16. Principles: explicit contracts (the address is in the entered state, not a later signal); Effect behaviour, Ergo constructs (owner, 2026-11-08). Prior art: effect-machine's `ActorHost` (Ergo drops its identity string and hand-written generation check: the entry's end closes the host); Erlang/OTP `supervisor:start_child` returns the pid synchronously.

## Owner direction, 2026-11-08

- **Maps and slices are values (2026-11-08, q26).** Owner, answering batch 12's question 26 (map-alias, #222): "Maps and slices are values: copy where two bindings would share, elided when the source is new or dead". Decided:
  - A write through a `let mut` root or a borrow is seen through that root alone: never through another binding, a package `let`, a record field, a slice element, the caller's argument, a capture or another task. `xs.Append(x)` and `m.Delete(k)` leave their argument unchanged. So a pure function gives equal results for equal arguments, and two tasks never write one Map. This replaces v1's "a slice and a Map alias as in Go".
  - The lowering keeps Go's slice and map and inserts a copy only where a write could be seen through another binding. It elides the copy when the source is fresh or dead after the bind, and writes in place for `p = p.Append(x)` and `p = p.Delete(k)`, so a loop that builds a collection allocates what Go's does. Shared state across tasks or providers is a `sync.Ref`, not a shared Map.
  - The aliasing lowering stays selectable as the reference (owner rule on speed lowerings, 2026-11-08), and a seeded property proves the two equal where nothing is shared.
  - A captured scalar `let mut` and a `for` over a changing collection keep Go's rules for now ([types.md, Bindings](spec/types.md#bindings) 3; #197).

  Rule: [types.md](spec/types.md#bindings) Bindings. Principles: correctness first; explicit contracts (a pure function's purity holds); strong abstractions with zero-cost implementations (the copy is elided where it cannot be seen). Prior art: Swift's copy-on-write `Array` and `Dictionary` and its optimizer's copy elision; Hylo's mutable value semantics; Gleam, Elixir and ReScript have immutable collections, so no write is shared; Go shares.

- **A defect is raised by the prelude function `Unreachable(reason)` (owner q29, 2026-11-08).** Asked in batch 12 (synthesis M22, repro G-ex-a-3: five examples invented a value or declared a failure that cannot happen); the owner answered "prelude function", as recommended over a keyword. Decided:
  - `Unreachable(reason string)` is in the prelude, so it is a prelude name (D-D3). Its call has the bottom type: it checks in every position that expects a value and takes that type, and as the last statement of a body or a branch it joins any type, as `return` does. The bottom type has no name in source; a position that expects no type (`let x = Unreachable("why")`) asks for the type.
  - It raises a defect that holds the reason and the call's position. It is never a typed failure: it is in no row, and no `catch` handles it.
  - It lowers to Go's `panic` at the call site, as hand-written Go does. Rules: [types.md, Unreachable](spec/types.md#unreachable).

  Prior art: Rust's `unreachable!()` has type `!`; Gleam's `panic` and `todo` are expressions of any type; Go's `panic` ends a path; Effect's `Effect.die` puts a defect in the cause, never in the error channel.
- **A package type may take a prelude type's name (2026-11-08, owner q30).** Owner answer to batch 12's q30: allow a package-level declaration to shadow a prelude *type* name inside its own package, Go universe-scope style; locals still may not. Decided:
  - This reverses the eighth review round's item 3 ("a prelude name cannot be redeclared") for package-level type declarations only. A package's `type Option`, `type Map[K, V]`, `type Range` or `type int` hides the prelude's in that package; other packages, std's results and the prelude's own declarations keep the prelude's ([types.md](spec/types.md#scope) 2, [grammar.md](spec/grammar.md#reserved-names) 2).
  - Locals, parameters, type parameters, package functions, `let`s, contexts and import aliases named like a prelude name stay D-D3's S108, as does any declaration of a prelude function or constant name (`len`, `true`); the prelude's variants `Some` and `None` are types, so a package union may declare its own; the improved S108 message for these (K4) stays. Widening it to package functions named like a prelude function waits for the owner.
  - The parser still reads `Map[K, V]` as the map type; where the package declares its own `Map`, the checker reads it as that type's instance. The lowering keeps the Go names distinct.
  - Examples that renamed a type to dodge the old rule may take the prelude name back (batch 12 L6 request lists them).

  Prior art: Go's universe scope encloses the package scope; Gleam and ReScript let a module define its own `Option` or `Result`, hiding the auto-imported one there; Elixir overrides a `Kernel` import with a local definition; Rust's prelude is a glob import that local items shadow.

- **Tests earn their keep (2026-11-08).** Owner: "cut down our unit tests to the ones that really earn their keep, to the very bare minimum; keep examples as an end-to-end layer; make rules for these new tests." Earlier the same day: "are we making too many unit tests, or should we start to rely upon our laws, and proofs, and examples more?" and "I wouldn't mind if the unit tests were very fast, but it feels like these unit tests are very slow." Decided:
  - Ergo's evidence has four layers, in this order of preference: (1) laws on operation types and machines, run by the law runners; (2) seeded, replayable properties against a reference model or interpreter; (3) the example programs in `examples/`, the end-to-end layer: they check, lower, build and run real programs, and their recorded cases and laws are the oracle; (4) concrete Go test rows, only for diagnostic text and positions, and for the smallest repro of a fixed bug.
  - A test is kept only when it catches a mutant that nothing else catches. Each package keeps a mutant ledger, and a deletion is allowed when every ledger mutant is still killed. A test that only restated a rule that a property or law now covers is deleted, not rewritten, when the rule changes.
  - Unit tests check in process (the checker, the lowering, `go/types` on the emitted Go). A unit test that builds and runs a Go binary says why an in-process check is not enough, builds its programs into one binary, runs each program under a memory bound, and runs in the full tier only. The examples step runs in every tier.
  - Pinned counts and digests of generated domains, and goldens of the lowered Go's shape, are not tests unless the shape is the spec. A test waits for events, never for a fixed time, and a growth guard counts work, never time.
  - The rule for new tests is in [AGENTS.md](../AGENTS.md#tests). `internal/residue` checks what it can read from the source: fixed waits, wall-clock comparisons (none in `internal/sketch`), split pins, and the "builds Go because" doc line; today's offenders are allow rows that name the unit that removes them.

  Measured basis: the test-speed plan of run wf10 (2026-11-08). `go build` and `go vet` of lowered programs were 71 % of the lowering tests' CPU, and the examples and the std laws covered 75 % of the checker's and the lowering's covered blocks. A cut by coverage alone would have lost 16 of 67 sampled mutants, so every cut goes through the mutant ledger. Prior art: Gleam tests its code generators in process (snapshot tests in `compiler-core`) and keeps target runs to its `test/language` projects; ReScript compiles its runtime tests once and runs them in one Node process; Elixir's compiler tests run in process under ExUnit; Go's own `test/` directory is the slow end-to-end layer beside the fast package tests; mutation tools (PIT, Stryker) run only the tests that cover a mutated line.

- **The standard library uses Ergo's strengths, not Effect's workarounds (2026-11-08).** Owner: "When making the standard library, design it in a way that uses Ergo's strength: where Effect has to do workarounds or hacky syntax, we can overcome that because we are making a language that compiles down to code faster than, or at least as good as, hand-optimized code." Decided:
  - A std package matches the behaviour and the guarantees of its Effect module. It does not copy an Effect API shape that exists only because TypeScript has no construct for the job. Each such shape has its Ergo construct: `Effect.gen` and `yield*` are plain statements with `try` and rows; `pipe` and dual signatures are one data-first function, called by the dot form; `Context.Service` and `Layer` are operation types with laws, `context` and `with`; `Data.TaggedError`, `_tag` and `Match` are error types, unions and exhaustive `match` and `catch`; `Schema` classes and `Config` are a declared type and a derived codec; `Equal` and `Hash` are generated equality; `Brand` is construction authority and refinements; `Option` and `Either` objects are the prelude union, lowered by shape; `Scope` values are frame scopes; fiber-local references are context values; the fiber runtime is direct Go calls. The table is in [stdlib.md](spec/stdlib.md#std-strengths-over-effect).
  - Each std package has one row in that table: its Effect module, the workarounds it does not copy, the Ergo construct it uses, and its lowering against hand Go, measured or with the follow-up that measures it. `TestStdStrengthsTable` holds every package of the std to a row.
  - Where the Ergo construct needs a compiler feature that is not built, the package takes the nearest Ergo form now and names the feature. A builder that stands in for a derivation stays only as the reference implementation of the derived form, which a seeded property proves equal to it (owner rule 2026-11-08 on speed lowerings).
  - This refines the 2026-11-06 rule "Effect's guarantees with Go's names". Where a Go signature leaves an invalid state open and an Ergo construct closes it (a sorted slice for `BinarySearch`), the construct wins, and the package doc states the departure from Go.
  - The lowering of the Ergo form is at least as fast as hand-optimized Go. Where it is slower, the unit records the loss with numbers and names the compiler follow-up (union representation, pure callbacks, fusion, devirtualisation, law-licensed rewrites). A guarantee is never removed for speed.

  Prior art: ReScript makes pipe-first syntax and uncurries by default, so neither costs a call; Elixir's `|>` is a macro and `with` chains the happy path; Gleam's `use` replaces callbacks with plain lines; Roc and MoonBit derive equality, hashing and codecs in the compiler; Koka's evidence passing turns a tail-resumptive handler into a direct call, as Ergo's environment of capabilities does; Elm, with no derivation, writes JSON decoders by hand, the shape this rule avoids.

## Decided by principle, 2026-11-08

- **A stop ends a read of standard input (batch 12, O15; the owner may overrule).** This reverses stdlib.md io rule 3 ("a read of standard input … cannot be stopped"). A task that waits in `io.Stdin.Lines()` or `ReadAll()` of the host provider ends its wait when it is stopped, and raises the interruption. No input is lost. One read of the process's input runs at a time, on a goroutine of its own. The line that it lands after the stop stays for the next read, and a `ReadAll` that a stop ends puts back what it read. The examples-wave program g3 showed the cost of the old rule: a reader stopped while the input stayed open (`sleep 3 |`) kept `Stop` waiting until the input closed, 3.0 s (measured). With the change it waits 3 ms (measured).

  Rule: [stdlib.md, io](spec/stdlib.md#io) 3. Principles: structured concurrency (a stop reaches every wait of the task); correctness first (each line is taken once and in order: `TestIOStdinStopModel`). Prior art: Go's reader goroutine with a `select` on its channel and `ctx.Done()`, the hand-Go control; Effect's `Terminal.readInput`, a stream that interruption ends; Tokio's `stdin`, a blocking read on a thread whose result waits for the next read.

## Decided by principle, 2026-11-05

- **Record update is `T{..base, F: v}` (2026-11-05).** Decided by principle under the owner's "dont block on me" (2026-10-28), for the sketch gap "no record update syntax" (examples/tidewalk-replay rebuilt five fields of `Walk` in four arms to change one; a full rebuild also resets a field added later). Recorded on [#196](https://github.com/cevr/ergo/issues/196). Rules: [grammar.md](spec/grammar.md#expressions) Expressions 11 and [types.md](spec/types.md#structs) Structs 3.
  - Form: a composite literal of a record type whose first element is `..` and the base, then one or more keyed fields: `Walk{..w, Turn: w.Turn + 1}`.
  - The base has exactly the literal's type, with its type arguments. A union that has the type as a variant is S108 at the base: match it first. `Walk{..w}` is S108: the copy is `w` itself (one form per job).
  - The fields follow the keyed-literal rules. A positional element, a second base, a base that is not first, a base in a slice or Map literal and `..` in a pattern are S001.
  - The base is evaluated once, first, then the field values in source order. The result is a copy; the base is unchanged. A slice or Map field is a value of its own: a write through either record is not seen through the other (owner q26, 2026-11-08, which replaced "shares its backing with the base's, as every record copy does in v1").
  - The update is a composite literal of its type, so every construction rule for that type applies to it unchanged.
  - Laws: `T{..b, F: x}.F == x`; every other field equals `b`'s; `T{..T{..b, F: x}, G: y} == T{..b, F: x, G: y}` for distinct fields; for one field the later update wins.
  - It lowers to a copy and one store per field, with no allocation.

  Principles: algebraic data (a machine steps to a new state by an expression); Go idioms beat novel notation, with the departure recorded (Go has no update expression because its values are mutable by default, and Ergo's `let` is immutable by default, 196v); visually distinct constructs (literal syntax, no keyword, no dot form); composable primitives (an update nests, by the laws). Rejected: `{ m with x }` (OCaml, F#) reuses `with` with a new meaning; `{ m | x }` (Elm) overloads `|`, which Ergo uses for rows and unions; `m.copy(x: …)` (Kotlin) is a dot form and needs named arguments; base-last `T{x: 1, ..m}` (Rust) reads against the order of evaluation. Prior art: Gleam `Walk(..w, turn: 1)` and MoonBit `{ ..w, turn: 1 }` put the base first with `..`; ReScript `{...w, turn: 1}`; Elixir `%Walk{w | turn: 1}`.

- **Fields and operations follow exportedness across packages (2026-11-05, 196b Q6).** Decided by principle for [#196](https://github.com/cevr/ergo/issues/196) (196b, packages). Outside its package, an unexported field is not read, written, named as a keyed literal's key or named in a record pattern, and an unexported operation is not called: each is S104, "units is not an exported field of lib.Q", "inner is not an exported operation of lib.Ops". An operation type with an unexported operation is implemented only by a type of its package (sealed, as in Go): another package's type is S108 "inner is an unexported operation of lib.Ops, so only a type of package lib implements it". The operation's identity is its name and its package, as Go qualifies an unexported method name by its package, so a constraint or operation type of another package that declares the same name does not launder a type into the sealed one. Rule: [grammar.md](spec/grammar.md#visibility) Visibility 2. Principles: Go idioms (Go's interface with an unexported method); explicit contracts and clear guardrails (construction authority is unsound while `lib.Q{units: 2}` is accepted). Prior art: Go and Rust (E0616, E0451) refuse a private field outside its package or module; Gleam hides an opaque type's fields; Elixir leaves every struct field open.

- **Construction authority is S114 (2026-11-05, 196b Q7).** Decided by principle for #196 (196b). A record with an unexported field, a defined type over it (authority follows the package that declares the fields), and a record, tuple or instance that holds one by value are built only by that package. Outside it, each of these is S114: a literal of the record or of a defined type over it, keyed, positional or empty; a record update of it, even of exported fields only; an implicit zero value (a `let` with no value at any level, a keyed literal that leaves a field of such a type unset, `let b Box[lib.Q]`). Allowed outside: values the package's exported functions return, conversions between a defined type and its base, reads of exported fields, patterns, copies, and a literal or update of an enclosing record that sets the field from such a value. The message names the package and up to three exported functions whose result is the type: "lib.Q has an unexported field, so only package lib builds it; use lib.ParseQ". One predicate owns the rule (`internal/sketch/check/authority.go`), and `check.Constructible(t, from)` exports it for `refine`, generators (#162) and codecs (#49). Two consequences the principle "a brand has no bypass" decides: a property parameter of such a type is S108 outside its package (a generator builds field by field), and an operation type with an unexported operation is sealed (Q6). Rule: [types.md](spec/types.md#zero-values-and-definite-initialisation) Zero values 6. Principles: explicit contracts and clear guardrails; agent interpretability (the message names the way in); composability (one predicate for every site). Prior art: Rust E0451 refuses a struct literal and a functional update with a private field outside its module; Gleam's `opaque` hides constructors; ReScript's abstract type in `.resi` hides the representation; Elixir has none (`@opaque` is not enforced); Go leaves `Q{}` open across packages.

## Owner direction, 2026-11-04

- **A defect stops the test run.** Orchestrator ruling for lower-v1 stage 4 (Q-S4-3), on the owner's decided-by-principle delegation: the written test rule ([grammar](spec/grammar.md) Declarations 11) stands, and it overrides the sentence of lower-v1 spec D8 that a test's defect is caught at the test boundary so that another test can run. A failed assert, a typed failure that escapes a test and a refuted property fail their test, and the run goes on. A defect fails its test and stops the run with exit 2. Principle: after a defect, the state of the shared process is not trusted. `ergo test` exits 0 when every test passes, 1 when a test fails, and 2 for a defect or an invalid invocation; the output tells the last two apart (a defect prints its test's `FAIL` line and the runtime's report). Design, decided by principle ([#241](https://github.com/cevr/ergo/issues/241)):

- **Laws stand at top level.** Owner: "Why do we have certain types just for laws? ergonomic failure?" The answer: yes, a gap. 196l made laws members of operation types only, and a record cannot hold a law, so every probe that stated a law about plain functions made an empty wrapper type (`OrderRules`, `ViewLaws`, `BoardLaws`), and one sketch fell back to an unrun `func LawMoveConservesMoney`. Decided by principle (one construct, and its placement sets the quantifier; constructs are visually distinct; no compatibility while pre-release), and built in check-v1 law-top:
  - `law X(params) { … }` is also a top-level declaration, beside `test`. It is quantified over its parameters only. It has no type parameters (S001): a generic law, such as log replay or delta equals recompute, belongs once on the library protocol, as a member of its operation type.
  - A law in an operation type stays, quantified over every provider of its type. A law in a machine stays designed (2026-11-03 (b), [#57](https://github.com/cevr/ergo/issues/57)), quantified over the step graph. (Built in batch 13, MU6: [types.md](spec/types.md#laws), Laws 13.)
  - A type with laws and no operations is S108 once, at its name: "T has laws and no operations; write it as a top-level law: law X(…) { … }". Its laws are still checked, so their errors show. No shim keeps the old form.
  - A top-level law takes the checker rules of a member law, minus the operation scope: its scope is its parameters, then the package. Top-level laws and tests share one namespace, because a report names each by its name alone. A top-level law has no owning type in the checker's data (`Law.Owner` is nil).
  - It is checked, not run: [#162](https://github.com/cevr/ergo/issues/162) runs a top-level law as a fuzz target over its parameters, and a member law against every provider. No build contains Go from a law ([types](spec/types.md#laws) rule 11).

  Prior art: Haskell QuickCheck states `prop_x` at top level and class laws beside the class; Lean, Coq/Rocq, Idris and Dafny state `theorem` and `lemma` at top level and put protocol laws in a class or structure; Elixir StreamData's `property` sits beside ExUnit's `test` at the top of a test module, compiled only under `mix test`; MoonBit uses top-level `test` blocks with a quickcheck library; Gleam (`qcheck`) and ReScript (fast-check) have property tests as library functions and no law construct; Fai checks `example:` contracts beside definitions. Zig, Go and Rust keep their tests out of the normal build, as Ergo keeps laws out of both builds.

The goal is to be 1x or below handwritten optimized Go code". The compiler (about 42,000 lines of Go today) is ported in stages: `format`, then `syntax`, then `check` and `lower`. Each stage goes on only when its output is byte-identical to the Go compiler's on the conformance corpus and its benchmark ratio against the Go version is at most 1.0. A three-stage build closes the port, and the compiler's own generated Go is the bootstrap seed. Prerequisites: packages, Go interop ([#202](https://github.com/cevr/ergo/issues/202)), predictable map and slice aliasing ([#222](https://github.com/cevr/ergo/issues/222)), record update and `let … else`. Prior art: Go 1.5 translated its C compiler to Go; TypeScript left self-hosting for Go for about a 10x speedup; Elixir bootstraps from Erlang; Gleam, ReScript, Elm and PureScript stay on their host language.
- **Speed levers keep the guarantees.** Owner: "Ideally, we would be able to kind of take advantage of compiler tricks and hints that we can give to make certain operations even faster - And for the rest, we should be able to kind of provide levers that increase speed while maintaining the simplicity and the capabilities and the guarantees that Ergo's North Stars provide". Decided by principle (pillar 7 and the tiebreak **Contract guardrails** beat **zero-cost slogans**): a lever changes speed, never meaning. It is admitted in one of three forms: proved by the checker from facts it already has (exhaustive unions, unique ownership, purity, refinements, as the proof tier of 2026-11-02 (b) removes a proved check); licensed by a law the program states and the test tier checks; or a hint whose removal never changes a result (layout, inlining, a profile). Unsafe code stays at the FFI edge. The owner asked whether Ergo has branded types ("a kind of parse, don't validate perspective that certain types must be insured") and whether machines and laws both have a place, as type laws do. The orchestrator answered with two sketches; the owner replied "Yes, I like both."

- **(a) Brands are construction authority.** A defined type (`type Celsius float64`) is a label: anything can convert into it. A law that reads only which variant follows which is checked exhaustively on the finite graph `ergo inspect` already builds, and is reported proved; one that reads payloads or an effectful helper runs as a fuzz target and is reported tested. Every runner of a machine plan, the actor library included, passes the provider laws (Reject keeps state, Done is final, steps apply in send order). Tickets: [#57](https://github.com/cevr/ergo/issues/57) (machines), [#162](https://github.com/cevr/ergo/issues/162) (running and proving laws).

### Owner construct bar, 2026-10-12

Owner construct bar, 2026-10-12: "if we're gonna have language constructs, they should be distinct from other already possible constructs. Like normal dot chaining and whatnot." On keywords and primitives: "I think the else block is overloading if else, since that's already a well-known programming concept. … scope and all these things are actually just normal methods in typescript effect. Time out, I look at it as just part of a schedule and whatnot. So I'm wondering why they need to be Language constructs. I mean, if we can justify it, it makes sense, but we'd have to think about a good way to make them primitive rather than blocks." And: "the goal is to provide a language that has enough guardrails so that bad code or illegal states cannot be represented. And that's really where machine as a language construct earns its keep … layers … So if we can make these language constructs and they make sense, then I think we should. But they need to be designed in a way that really makes sense and that are portable across different domains. So [userland] implementations of various different things that may not necessarily be effect runtimes, but are effectual … may not be the default standard library that we provide, but it could have a [userland] implementation that is superior in whatever domain they're in."

The recorded synthesis of these three directions, not owner words, follows. A construct earns its place by passing the guardrail test and the portability test, both defined in the [glossary](../GLOSSARY.md); its protocol's laws come from [#125](https://github.com/cevr/ergo/issues/125). Where the guardrail test fails, the behavior is a primitive function with honest rows plus library, as in Effect. A construct that passes both tests uses a keyword or block form distinct from dot and pipe. A dot or pipe form is always ordinary library, and no well-known keyword is reused with a new meaning. Machines already follow this through provider-independent plans. [#134](https://github.com/cevr/ergo/issues/134) decides, for `.provide`, `.timeout` and `.orFail`, between a keyword or block construct and ordinary library, and it replaces [#95](https://github.com/cevr/ergo/issues/95)'s plan to reserve postfix words. Until #134 decides, those forms remain postfix constructs. Of the compile-to-host peers in the [compiler-known construct comparison](../PRIOR_ART.md#compiler-known-construct-comparison-2026-10-09), Elixir's fixed special forms over library functions are the closest match for this bar.

### Owner construct direction, 2026-10-09

Owner construct direction, 2026-10-09: "i think in the case of machines, syntax is preferred over special cased library constructs" — "and generally i should say all of our langauge constructs". Whenever the compiler must know a construct's meaning, for checking, inference, plan facts, inspection or special lowering, that construct is syntax: a keyword, operator, declaration form, postfix construct or predeclared language identifier defined by the language (Go's predeclared `len` and `error` model). It is never a bundled or prelude library item that the compiler recognises by identity or name to grant language semantics, which is the Rust "lang item" pattern. Library code the compiler treats exactly like user code stays library; an item becomes library by losing every compiler branch, not by moving its declaration. A library intrinsic, which swaps the implementation of an ordinary declared signature without changing diagnostics, types, rows or ownership, is a separate permitted category and must be documented; so is the implementation of a syntax construct. A language protocol, a row label whose charging a construct's own rule defines (such as `Foreign` for host calls), is language; an ordinary capability service stays library. Foreign identities that `import go` adapts, such as `context.Context`, form that construct's finite host-protocol table. This sharpens the 2026-10-07 [visible-construct refinement](design.md#language-design-principles) and supersedes the earlier plan to turn `.catch` and `.provide` into ordinary library operations: they are dedicated parser forms today, and they stay syntax. Two parts of this paragraph are superseded by later direction. First, "they stay syntax" no longer holds as stated. The [effect rows note](research/effect-rows-as-types.md#verdict) ([#115](https://github.com/cevr/ergo/issues/115)) finds `.catch<E>` and `.provide<S>` GO as ordinary library through general row features, each gated on its unit ([#128](https://github.com/cevr/ergo/issues/128), [#131](https://github.com/cevr/ergo/issues/131), [#132](https://github.com/cevr/ergo/issues/132)). It finds `.recover<E>` conditional ([#133](https://github.com/cevr/ergo/issues/133)) and `.timeout` and `.provide(Layer)` NO-GO as library. Second, the 2026-10-12 construct bar below no longer admits a postfix construct as a construct spelling. [#134](https://github.com/cevr/ergo/issues/134) is re-deciding provide and timeout, including whether one provide block absorbs `.provide<S>`. Until those units land, every form named here remains a dedicated parser form. The [compiler-known constructs audit](research/compiler-known-constructs-audit.md) inventories current and planned violations and their migrations; it is direction, not a claim that they are fixed.

### The no-value contract `void`

The canonical no-value contract is `void`: the `void` type and bare `void` expression describe successful completion without an information-bearing result. Empty parameter and argument lists remain `()`, while `()` is rejected as a type or expression so no-value syntax cannot be confused with grouping or calls. `void` is not absence, `never`, nil, null, or a backend sentinel; `Option<void>` retains its `Some`/`None` distinction. The Go target may use a zero-size carrier in value positions, but that representation does not change the source contract.

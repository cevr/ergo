# Pattern and guardrail index

Ergo's public architecture is described through generic patterns. This index records the decisions that source reviews inform, without making an external application's structure part of the language contract. Read [NORTH_STAR.md](NORTH_STAR.md) and [GLOSSARY.md](GLOSSARY.md) alongside it.

## Language and library references

Owner direction refreshed 2026-10-06: preserve Go-like simplicity, Effect-style guarantees and Borgo-like algebraic data/abstractions. This repository keeps the established `PRIOR_ART.md` name as its canonical prior-art index.

Owner direction, 2026-10-26: Go is Ergo's only target ("we're removing the js interop id say"), and Effect is prior art for the guarantees, not a runtime or an ABI. Rows that compare JavaScript hosts, TypeScript tooling or front-end frameworks (TypeScript, ReScript's generated TypeScript adapters, Foldkit, Solid, React, effect-atom and the JSX pragma sources) stay as research records. Where their comparison column names a JS projection, generated TypeScript declarations, a pinned Effect ABI or client mount ownership, it no longer describes planned Ergo work. The compile-to-host peers (Gleam, ReScript, Elixir, MoonBit) stay standing comparisons for lowering and optimization paths.

### Zero-cost abstraction comparison, 2026-10-08

The owner added a destination obligation that strong abstractions should make
the illegal states and invalid operations covered by their checked contract
unrepresentable in checked Ergo source, while foreign/trusted behavior remains
explicit, without imposing an abstraction-only executable cost. The follow-up
target is explicit: a native Go application must match or beat optimized
idiomatic Go under the same contract, and JS must pursue every measurable
lowering or specialization opportunity. The following primary sources constrain
that phrase and its limits:

The adopted evidence shape is a three-way semantic baseline: an Ergo
candidate, an explicit Go program and an explicit TypeScript/Effect program
perform the same validation and observable work, preserve the same ownership,
cancellation and cleanup behavior, and expose the same failure/service rows.
Receipts must identify whether the abstraction was erased, directly lowered or
retained behind dispatch; they must report retained modules, emitted source,
executable bytes, allocations, dispatch and residual checks. Unequal work,
weakened guardrails, an omitted TypeScript typecheck or an isolated
microbenchmark is counterevidence, not a pass. This joins the existing
measurement ledger and benchmark-last gate; no current Ergo performance claim
is made here.

The native Go acceptance cohort is an optimized idiomatic Go implementation of
the same contract, including validation, failure/service rows, ownership,
cancellation and completed cleanup. The native executable target is to match or
beat that cohort; a slower, equal or inconclusive result stays visible rather
than being reframed as a win. The JS cohort keeps the pinned Effect-compatible
ABI and userland runtime behavior while exploring every material measurable
compiler/lowering opportunity: static match dispatch to `if`/`switch`, direct
calls, join-point sharing, tail-resumptive paths and generated or specialized
effect-runtime code are examples. A potential many-times speedup is an ambition
to test, not a current result or universal multiplier.

Generated runtime code is allowed when it is an ordinary compiler/provider
implementation, not new user syntax. It must retain the same typed errors and
service rows, ownership, cancellation, scopes, interruption behavior and
completed cleanup. The pinned default JS ABI remains the compatibility boundary;
an alternate ABI requires a separate decision and conformance record.

Rejected alternatives are a universal zero-overhead promise, forcing every
abstraction to inline, removing ownership/validation checks, or judging only a
small straight-line fixture. Rewriting every `match` to `if`, relying on V8's
warm tiers without cold/warm evidence, or replacing the pinned Effect runtime
without an ABI decision are also rejected. The Rust page's scope and Ergo's
size/retention measurement obligation, C++ Per.11's compile-time/code-size
tradeoff, Go's context-dependent escape analysis, V8's speculative deoptimization and the
effect-handler paper's scope of equivalence are direct reasons to retain losing
results and keep the decision scoped.

Application usage is surveyed as generic patterns below. Exact private checkout pointers stay in local research notes; private source is not copied into this public repository. Upstream reference tests retain their own license and provenance and remain distinct from passing Ergo tests.

### plusthree, a compiled-language port of XState v6, 2026-11-18

The owner named [plusthree](https://tangled.org/rockorager.dev/plusthree) as prior art: "interesting prior art". It is a Rust port of XState v6 (0.1.0, design accepted 2026-11-17, ported from XState `6.0.0-beta.3` at `8e53990`), read on 2026-11-18 from a `main` snapshot: `README.md`, `docs/design.md` §2, §4 to §7, §9 and §10, `DEVIATIONS.md`, `crates/plusthree-bench/{BASELINES.md,src/lib.rs,examples/allocs.rs}` and `conformance/traces`. Typed machines, written with a builder, a `machine!` macro or as MachineJSON, compile to one flat table IR that one `no_std` kernel interprets. It is the nearest prior art to Ergo's machines, because it ports XState's semantics into a statically typed host and measures the cost of each event. Ergo compiles a machine's step to Go rather than interpreting a table. So plusthree's kernel numbers are a ceiling for Ergo, and its compiled-dispatch controls (statig and smlang, 4 to 6 instructions per event) are the floor.

[`benchmarks/machines`](benchmarks/machines/README.md) runs plusthree's scenarios S1 to S4 and S7 as Ergo machines, beside a hand-written Go switch. Measured on main `d3bb9dac6` with `perf stat -e instructions:u`, the `machines.From` fold costs 25 to 43 instructions per event for a union state, 1.6 to 2.9 times the switch, with no allocation. plusthree's kernel costs 628. A record state costs 200 to 275 instructions and one boxed decision per event. `machines.RunTimed` costs about 4,960 instructions and 271 heap bytes per timer fire, against plusthree's 1,626 and none.

| plusthree choice (source) | Ergo today | Take / reject / open |
| --- | --- | --- |
| **Effects as data.** `step(&machine, &mut snapshot, event, &mut effects)` fills a reused buffer with `Effect`s (the user's actions, `Schedule` and `Cancel` for timers, and spawn, start, stop and send), and the host runs them (design §5.2, §6.4). | A step returns a `Decision[S, O]` value. A state's timer is the data `after` returns, and its work is the recipe `work` returns. The runner (`machines.Run`/`RunTimed`, `actor.StartMachine`) carries them out ([runtime](docs/spec/runtime.md), Machines and actors 2, 9 and 12). | **Take, held already.** The program never starts or stops a timer itself. **Open:** plusthree reuses one buffer across steps. Ergo's `Decision` is a Go interface, so a fold over a record state boxes a decision on every event. |
| **No clock in the kernel.** `after` becomes `Effect::Schedule{key, delay}`, and the host calls `fire` when the timer is due. So tests fire timers at once, and persisted timers survive a restart (README; design §6.4; D19). | `machines.Run` has no clock. `RunTimed` and the live runner read the context's one `time.Clock`/`Scheduler`, so a test binds `testing.VirtualClock` or `time.Manual` (Machines and actors 9.6). | **Take, held already, in Ergo's form.** The host is the context's clock, not a callback, so a program cannot forget to fire a timer. **Open:** plusthree persists each timer's remaining delay. A durable Ergo actor instead restarts its entry's timer when it recovers. |
| **Snapshots are plain data.** A snapshot holds no reference to its machine: the configuration bitset, the context, history, timers, children and the status (design §6.1, §7). | The state is the machine's own value `S`. `State()` returns a copy, and `journal`/`StartDurable` save it through a `Codec` with laws. | **Take, held already.** **Reject** XState's persisted snapshot format as Ergo's own format. Interchange belongs to an export. |
| **An IR, validated and flattened.** States are numbered in pre-order with `subtree_end`. Each transition is precomputed into a `StaticPlan` (its domain, exit range and entry set), so a plain microstep is one bit operation. Every JSON target is resolved when the machine loads (design §4, §6.3; D13). | The checker builds the machine plan (`ergo inspect machine`: arms, decisions, timer facts and reachable pairs), and reachability laws are decided on the state graph. The step is ordinary code lowered to Go. | **Reject** the interpreted table: Ergo's floor is plusthree's compiled control, not its kernel. **Take** validation when the program is built, held already. |
| **A differential harness.** 406 recorded XState traces, written by hand or drawn at random, record each step's state value, context, effects and microsteps. They are replayed on every change, with an allow-list keyed by deviation (design §9). | Ergo's runners are checked against Ergo reference models: `TestMachineRunAgreesWithFold`, `TestActorModelAgreesWithTimedFold` and `models/{runner,children,host}`. | **Open.** About 52 of the 406 traces use a flat machine (measured with a rough filter). Replaying them commits Ergo to XState's semantics, so they wait until real programs show demand for statechart features. |
| **A DEVIATIONS ledger.** Each departure from XState (D1 to D21) states its rule, its reason (XState's docs first, then SCXML, then the simplest invariant), one test and the trace steps it masks. An allow-listed step that starts to match fails CI. | Departures are prose in runtime.md, Machines and actors 2, 9 and 11: `Enter` re-enters, each entry has one timer, a stale timer is dropped by its epoch, a `Reject` of a timer signal counts as an `Ignore`. | **Open**, under the same demand condition as the traces. |
| **0 allocations per steady event**, held by a counting allocator for S1 to S4 and S7 (design §10; `examples/allocs.rs`). | `TestMachineFlatRunAllocates` holds 0 allocations per signal through a Go driver, for a union state. An Ergo program cannot count its own allocations: `runtime.ReadMemStats` takes a borrow, and a local Go package is not bindable yet ([#202](https://github.com/cevr/ergo/issues/202)). | **Take.** The test's corpus has to include record states, which allocate today. |
| **Instruction-count budgets.** gungraun or Callgrind count instructions per scenario, and `just bench-instr` fails on a regression above 5% (design §10). | Receipts count work, never time. | **Reject as a gate:** a saved baseline is a pinned count, which the [test rules](AGENTS.md) refuse. **Take** the scenarios as receipt rows set against the Go floor. |
| **Typed MachineJSON import and export**, for Stately Studio and the Inspector (design §7). | `ergo inspect machine` prints the plan as text. | **Open:** an export for flat machines. **Reject** the import, because it builds a machine at run time and Ergo machines are source. |
| **Correctness over parity.** XState's bugs and its JavaScript artifacts are not reproduced. Each such departure is a deviation with its own test (design §2). | The guarantees follow the prior art, not its accidents ([north star](NORTH_STAR.md)). | **Take, held already.** |

Ergo machines do not have these plusthree features: compound and parallel states with entry and exit per state, shallow and deep history, eventless (`always`) transitions, several timers per state, delayed raise and send, choice states, wildcards and a rollback of the whole macrostep on error. Ergo writes hierarchy as a state whose payload is the sub-state, and writes regions as a record with one union per region. Entry per level, timers per region and history have no Ergo form. A form is admitted only after a count of its use in real programs.

The compile-to-host peers do not compile a statechart either. Erlang/OTP `gen_statem` compiles to BEAM callbacks, with state enter calls and one `state_timeout` that a state change cancels. It has no hierarchy, regions or history, and it is tested with PropEr's `proper_statem`. gleam_otp's `actor` is a typed message loop with no machine construct. ReScript uses XState through bindings, interpreted in JavaScript: v6's `transition()` takes 2.3 to 11 µs per step (plusthree's BASELINES.md). So on the compiled path, plusthree's numbers and the Rust controls are the only comparison.

## Settled

- Adopt first-class layer graph assembly from the owner contract and production composition audit. Node identity determines sharing; binding visibility is independent of graph leaves and selected acquisition effects. Replace deliberately before solving effective construction edges. Reject last-writer precedence, roots-only output inference, type/config-equality memoization and constructor-failure erasure: they break **Explicit contracts and clear guardrails** and **Owned lifetimes**. Runtime concurrency/rollback/cleanup remains executable implementation work.

- A canonical shared formatter is required. Inspected Go1.27.0 `go/format` and Gleam `compiler-cli/src/format.rs` at52e735c82d42811dd08d29d5508f564da081fd7d: adopt syntax-only printing and shared check/stdin/write paths, with Ergo-specific preservation of line-sensitive lint directives. The shared syntax printer is integrated; CLI/MCP adapters and editor formatting remain open under the [formatting contract](docs/specs/formatting.md).

- Use LSP's standard severities and UTF-16 range semantics as an adapter over shared compiler snapshots, retaining byte anchors and explicit checked/unknown state. The [tooling contract](docs/specs/semantic-tooling.md) records the pinned 3.18 source inspection; CLI/MCP must expose the same full types and diagnostics without requiring an editor process.

- Adopt Borgo's direction of direct Go-targeted application code with first-class closed data and patterns; records/enums/match already have Go/JS receipts. Its broader interop and inference claims are comparison inputs, not inherited Ergo guarantees.
- Adopt Effect's behavioral contracts as explicit conformance inputs. Native error/service rows, service identity and ownership are compiler concepts; retry, cache, routing and other runtime policies remain reusable library implementations.
- Keep upstream Effect cases as provenance records (file, line, label, status) in an Ergo-owned case manifest, each mapped to executable Go evidence. No upstream checkout or submodule is required (superseded 2026-10-26 with the JS target; the earlier pinned-submodule adoption is historical). Reject vendoring a copy of upstream, and reject counting an upstream reference as native parity unless a passing Ergo Go test backs it: it breaks **Explicit contracts and clear guardrails**.
- Adopt typed-AST host declaration projection, explicit target capabilities, source-location preservation and independently versioned interface/build artifacts from the [host compilation comparison](docs/research/host-language-compilation.md). Keep automatic declaration ingestion as the adoption goal; reject requiring handwritten bindings for every ordinary import. A content mapper complements Ergo tooling but does not own its guarantees.
- Adopt ordinary transition functions and a declaration-only machine binding from the [XState v6 and Effect Machine comparison](docs/research/machines-and-transforming-codecs.md). The declaration is justified by its static `stay` same-tag check, which no compared system has ([machine admission gate](docs/specs/state-machines.md#construct-admission-gate), 2026-10-07). Keep conservative graph edges explicit; require completed entry cleanup and bounded admission as separately tested Ergo policies.
- Adopt opt-in structural codec derivation plus named transforming witnesses with independent directional contracts. Preserve multiple representations, versioned wire policies and transformation-specific laws; reject global witness uniqueness and automatic reversibility claims. Implemented 2026-10-09 with `decode:`/`encode:` functions and explicit `with` composition; decoding is structure-first, an executed difference from pinned Schema's per-field transformations ([decision](docs/research/machines-and-transforming-codecs.md#transforming-codec-implementation-decision-2026-10-09)).
- Dead-value hand-over (OWN1, `internal/sketch/lower/handover.go`). Go's design 74299 (`runtime.freegc`, Go 1.27.0, off by default) proves at compile time that an append's old array is unaliased (`ir.CallExpr.AppendNoAlias`, `growsliceNoAlias`) and frees it, for pointer-free memory only. Ergo's value rule proves the same fact from the source, so it appends in place instead of growing and freeing, at any element type. Where no proof holds, it uses a per-site one-extender token checked at run time. Go's memory-regions design 70257, which follows the arena experiment on hold (#51317), checks dynamically, region-wide, for values that leave. Ergo's check is per site and per array: it costs a compare under an uncontended lock and makes no allocation. Gleam, ReScript and Elixir have immutable lists and leave reuse to their hosts. Koka's in-place reuse after a uniqueness test (Perceus) is the nearest relative, but it counts references, and Ergo has no count.
- `.ef` text remains authoritative. Dependency graphs are rebuildable views with revision-scoped expression IDs.
- Compiler soundness diagnostics cannot be disabled by optional lint. Unchecked files do not receive authoritative expression types or dependency graphs.
- Lazy construction does not execute an effect. Unused local recipes receive lint advice; bare discarded recipes remain compiler errors.
- A managed timeout waits for shutdown. A process watchdog may force termination and must report cleanup as unconfirmed.
- Host signatures do not prove purity, cancellation, retained-reference safety or resource ownership. Partial native results survive explicit adaptation.
- Tests supply only assertions implicitly. Fixture services stay explicit, and live host/time capabilities require opt-in. This is a capability check, not an OS sandbox.
- Application-specific state machines, identity, transaction and overflow policies remain explicit even when syntax becomes shorter.

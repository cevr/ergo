# limiter

A rate limiter written in Ergo, served over Effect RPC to a TypeScript
Effect HTTP gateway. The contract is written once, in Ergo; TypeScript
reads it through the content mapper (`tools/ts`), so there is no generated
`.ts` file and no second declaration to keep in step.

- `limits/` is the contract: `Limiter` (Take, Hold, Peek, Advance, Buckets;
  Hold is a take that waits until an Advance lets the bucket pay) with
  its typed failures `Limited{RetryAfterMs}`, `UnknownBucket{Key}` and
  `BadCost{Cost, Capacity}`, and its laws: `NeverOverdraws`,
  `RetryAfterIsExact` (a limited take is still limited one millisecond
  before its RetryAfterMs and granted at it) and `LimitedTakesNothing`.
- `limits/limitsrpc/` is generated by `ergo gen rpc limits.Limiter`: the
  server's `Handle` and the Ergo client.
- `bucket/` is one key's token bucket as a machine (`Tokens`, over
  `Elapse` and `Spend` signals), with its laws `NeverOverdraws`,
  `RefillCapsAtCapacity`, `RetryAfterIsExact` and
  `GrantsPlusShortsCountSpends`. It is pure; the clock is a signal.
- `memory/` is the provider: a bucket per key in a `sync.Ref`, so each
  take is one atomic step. A Hold waits on a wake queue of its own,
  which the next Advance closes; its release (`scope.OnExit`) runs on
  every exit, a stop of its caller included, and notes it. `ergo test memory` runs the contract's laws
  against it.
- `loopback/` is the same limiter through the wire: the generated client
  of a memory limiter that the generated server serves in process
  (`rpc.Loopback`: Serve's own server answers each call in memory).
  `ergo test loopback` runs the contract's laws against the client, so
  the laws that hold for the provider hold through the wire.
- `cmd/limiter/main.ergo` chooses the buckets (`api`: 5 tokens, one back
  per 200 ms; `search`: 3, one per second), binds `limits.Limiter` to the
  memory provider and serves it on `127.0.0.1:0`, printing the address
  first. The clock moves only through `Advance`, so the case is exact.
  `limiter check URL` is the small Ergo caller: it asks the limiter at
  URL for its buckets through the generated checked call
  (`limitsrpc.BucketsChecked`), so a URL that names no limiter is the
  typed `rpc.Transport`, a line and status 1, not a defect.
- `ts/gateway.ts` is the Effect gateway: `GET /fetch/:key?cost=N` takes,
  `Effect.catchTag` turns `Limited` into 429 with `Retry-After`,
  `UnknownBucket` into 404 and `BadCost` into 400; `GET /level/:key`
  matches the `Level` union by `_tag`; `POST /advance?ms=N` moves the
  clock; `GET /hold/:key` holds. A client that hangs up interrupts the
  route's fiber, which interrupts the RPC call, which stops the Ergo Hold. `ts/main.ts` is the case's driver: it starts the built limiter,
  serves the gateway on a loopback port and sends a fixed script.

Cases (tag `ts`: `go run ./scripts/examples -tags ts`; needs Bun and a
warmed Bun cache, see `tools/ts/README.md`):

- `gateway`: the script, through both servers; then a Hold whose client
  hangs up (the limiter prints that the Hold waits, then that its release
  ran) and a Hold that an Advance lets through. The driver waits on the
  limiter's lines, never on time. Last, `limiter check` against the
  running limiter and against a URL with no RPC mount.
- `tsc`: `tsc --runExternalCode` type-checks the gateway against the
  contract.
- `tsc-drift`: the contract renames `BadCost.Capacity`; tsc fails at the
  gateway's `e.capacity`, the exact call site, with no regeneration step.

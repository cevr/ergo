# fk-domains

A domain search, ported from `foldkit/foldkit-domains` at `039c941a` (MIT, (c) 2025 Devin Jameson; `origin/`). This is stage a of plan §20: the domain, its Api and the server (FD1a), and the pure parts of the search page (FD2a), with no pages yet. The binary searches the sample registry from the command line, or serves it over Effect RPC at `/rpc`, where a stock client of the original can call it.

Tag: `default`.

```sh
fk-domains search foldkit 0 4     # one listing a line
fk-domains serve 127.0.0.1:8787   # POST /rpc, SearchDomains
fk-domains bench 1000             # the P11 workload (below)
```

## The shape

- Package `domains` is the domain and the Api.
  - `Label` is parsed from text (`ParseLabel`, `fails Invalid`): 1 to 63 bytes of `a` to `z`, `0` to `9` and inner hyphens, the original's `DomainLabel` pattern. With `Wire` it is a by-name pair, so a label on the wire is decoded through `ParseLabel`.
  - `Offset` (0 to 555) and `Limit` (1 to 556) are refined ints, the bounds of the original's `DomainCandidateRange`. Law `BoundsAreTheCatalog` ties them to the catalog's size.
  - `Listing = Available{Name, TLD, Price, RenewalPrice, Years, IsPremium} | Unavailable{Name, TLD}`.
  - The catalog: 556 TLDs, the 24 featured first (`catalog.ergo`, generated from the original's `tld.ts` and `domain.ts`).
  - The Api is one operation type, `Registry { SearchDomains(label, offset, limit) []Listing fails Down }`, with laws `PageIsSliceOfWhole`, `SameAnswerTwice`, `FeaturedFirst` and `AtMostLimit`.
- `domains/domainsrpc` is generated by `ergo gen rpc domains.Registry` (run in this folder): the `Request` union, `Handle` and `Client`.
- `sample` is the provider with the original's sample data (`demoDomains.ts`): a price per featured TLD, 19.99 for the others, and `vercel`, `google`, `github` and `foldkit` taken under `.com` and `.dev`. It builds only the listings it answers.
- `loopback` is the generated client of a sample registry served in process (`rpc.Loopback`). The `Registry` laws run against it as against `sample`, so they hold through the wire.
- `server` answers HTTP with the original's refusals (`src/server/rpc.ts`).
- `cmd/fk-domains` is the only place that binds `domains.Registry` (to `sample`).
- `search/` holds the pure parts of the search page (unit FD2a). Each part is a set of functions on values, with no clock and no `ui`, and the search machine (FD3a) will hold them in its state.
  - `search/cache` is the original's keyed query cache (`domainsQuery.ts`): an entry stays fresh for a set time, and at most a set number of entries stay settled.
    - The time is an argument.
    - Each load gets a new generation, and an answer is taken only for the generation its entry is waiting on. So a late answer of a load that was cut, or replaced by a newer one, changes nothing.
    - A hit makes the entry the most recent, but it never makes it fresher. The least recent settled entry is the one evicted, and an entry still loading is never evicted.
    - Law `CacheFollowsModel` runs drawn reads, loads, answers (current and late), cuts and clock advances against a plain-list reference model.
  - `search/plan` chooses the next range to load. The ranges are the original's (`domainPlanning.ts`): the top 4 listings, the rest of the first page of 60, then pages of 60. A price order or the available-only filter loads the whole catalog in one request instead.
    - Its work reads only the rows the window shows, and law `StepWorkIsFlat` counts it at 556, 1,000, 10,000 and 100,000 listings.
  - `search/window` is the virtual list's window. Every row has the same height, so the window is a division with no measuring pass, and `WindowIsBounded` holds for every count.
  - `search/route` maps the URL to a route and back. The URL holds the query, the TLD filter, the available-only filter and the order. A parameter with an invalid value falls back to its default, and any path but `/` is `NotFound`.

## How it differs from the original, and why

- **One operation, named for the wire.** The operation is `SearchDomains`, the original's RPC tag, so its wire name is the original's. Its payload is `{label, offset?, limit?}`: the range parameters are `json.Optional`. A search with no range lists the whole catalog, as the original's defaults do.
- **The failure is `Down`.** The original's `SearchError` has one variant, `Unavailable`. Here `Listing` already has a variant of that name, so the failure is `Down`. No recorded case fails this way.
- **The bounds are types.** A label, an offset or a limit out of range does not decode. As in the original, it is a 200 whose frame is a `Die`. The original's defect text is Effect's schema message, and the port's is `rpc.Decode`'s, so the texts differ.
- **A body that is not JSON** is a 200 whose one frame is a `Defect` named `SyntaxError`, as the original's Effect server answers it; std `rpc.Answer` gives it. Its message is Go's JSON error, not JavaScript's.
- **A GET of `/rpc` is 404** with no body, as the original's router has one `POST` route; std `rpc.Answer` answers it so, before the endpoint's own refusals.

## The wire, checked against the original

`server/recorded/` holds 20 cases that FD0 recorded from the original's worker with `wire.mjs`, with `index.json` (status, content type, `Cache-Control`). The `server` test `WireAgreesWithOrigin` reads them through `embedded`. For each case, `server.Answer` must give the original's status, `Content-Type` and `Cache-Control`. For a 200 it must also give the same frames: a success has the same listings, field for field, and a failure or a defect must be the same kind.

The case's body reaches `Answer` as `http.Serve` hands it over under `server.Limits()`: a body over `MaxBodyBytes` is `http.BodyTooLarge`. So the 1,024-byte and 1,025-byte cases check the limit that the binary serves with.

## The server's cost (target P11)

`fk-domains bench N` answers the first N requests of a fixed script (`server/script.ergo`: six labels, offsets in steps of 61, limits 4, 56, 60 and 556) through `server.Answer`, in process. It prints the bytes answered and a CRC-32 of each answer's status, headers and body. `testdata/control` is the same handler written by hand in Go with `encoding/json`. It answers the same script and prints the same line, so the two give the same bytes. `scripts/opcount -control` compares the two. On 2026-11-13, with 3 rounds at 1,000 and 6,000 requests, the Ergo handler took 0.46 times the control's instructions per request and 0.77 times its allocations, but 2.5 times its bytes allocated (the run's `receipts/fk-domains.json`).

## Upstream tests

Each upstream story and scene test, and what restates it, is a line of `origin/tests.txt`, which the examples runner checks against the vendored files in `origin/upstream/` (`origin/source`). FD3a restates the stories, and FD4b the scenes.

## Cases

- `search-top`: the top four for `foldkit` (the first page the original loads). `.com` and `.dev` are taken.
- `not-a-label`: `Foldkit` is refused, as the original's schema refuses it.

The mutants these kill are in `testdata/mutants.json`.

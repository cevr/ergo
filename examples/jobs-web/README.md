# jobs-web

A job server written in Ergo that also serves the page that drives it,
from one origin. The page's program is TypeScript (Effect): a stock
`RpcClient` built from the contract that `jobs/jobs.ergo` declares, read
through the content mapper (`tools/ts`), so there is no generated `.ts`
file and no second declaration to keep in step.

- `jobs/` is the contract: `Jobs` (Submit, Cancel, Status, List, Work;
  Work moves every job on by some ticks, so a client that waits says how
  long) with its typed failures `Rejected{Reason}`, `NoSuchJob{Number}` and
  `AlreadyDone{Number, State}`, the `State` union `Queued | Running{Step, Of}
  | Finished | Failed{Why} | Cancelled`, and its laws
  `CancelOfTerminalFails`, `ProgressMonotone` and `RejectsWhatCannotRun`.
- `jobs/jobsrpc/` is generated by `ergo gen rpc jobs.Jobs`: the server's
  `Handle` and the Ergo client.
- `job/` is one job's life as a machine (`Lifecycle`, over `Tick` and
  `Cancel` signals; an end is emitted, a cancel of an ended job is
  rejected), with its laws `TerminalAbsorbs`, `ProgressMonotone` and
  `OneTerminalPerJob`. It is pure.
- `memory/` is the provider: a `job.Run` per job number in a `sync.Ref`, so each
  change is one atomic step. `ergo test memory` runs the contract's laws
  against it.
- `loopback/` is the same server through the wire (`rpc.Loopback`):
  `ergo test loopback` runs the contract's laws against the generated
  client, so the laws that hold for the provider hold through the wire.
- `cmd/jobs-web/main.ergo` opens the page's folder (its one argument) as an
  `fs.Root`, listens on `127.0.0.1:0`, prints the address first, and
  serves one `http.Serve` whose handler sends `/rpc` to `rpc.Answer` over
  the generated `jobsrpc.Handle` and every other path to `http.Files`
  (`/` is `index.html`). It binds `jobs.Jobs` to the memory provider: the
  only place that chooses it.
- `ts/jobs.ts` is the session the page runs: it submits jobs (and two the
  server rejects), works them, cancels one while it runs and one after it
  ended (`AlreadyDone` is shown with the state the job ended in), and asks
  for a job that is not there. `describe` matches the `State` union by
  `_tag`, exhaustively. The protocol is ndjson, which the server streams
  an Exit line at a time.
- `ts/app.ts` and `ts/index.html` are the page: the session against
  `/rpc` of the page's own origin, printed into the page.
- `ts/main.ts` is the case's driver: it builds `app.ts` with `Bun.build`
  and the ergo-ts esbuild plugin (the same projection tsc reads) into a
  fresh folder beside `index.html`, starts the built `jobs-web` on it, checks
  that the origin serves the page and the built program, then runs the
  page's session against the same origin under Bun. A real browser run is
  a manual check: open the printed address.

Cases (tag `ts`: `go run ./scripts/examples -tags ts`; needs Bun and a
warmed Bun cache, see `tools/ts/README.md`):

- `page`: the page, the program and the refusals from the origin, then
  the session's lines.
- `tsc`: `tsc --runExternalCode` type-checks the page's program against
  the contract.
- `tsc-drift`: the contract renames `Running.Of` to `Total`; tsc fails at
  `describe`'s `s.of`, the exact use, with no regeneration step.

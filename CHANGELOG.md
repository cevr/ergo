# Changelog

Entries describe user-visible changes and are true at the commit that carries them. The layout follows Gleam's: one `## Unreleased` section with headed groups, newest work first within a group. Codes such as EF111 are compiler diagnostics.

## Unreleased

### Breaking changes

- An owned resource is released automatically (#197 L8 B1; [resources](docs/spec/resources.md#owner-scope) R5, R6, R9, R10, R41, R43): a local, a parameter the function takes, or a temporary whose type has a `Close` is closed at the end of its scope (a block, a loop iteration, a statement), last acquired first, on every exit, failures, defects and stops included; a hand-off moves it and a return gives it to the caller. Code that closed such a value by hand on every path still checks, and its hand `Close` is the one release: a direct call, a method value (`let f = r.Close` takes `r`), a function value (`let f = Close; f(c)` takes `c`) and a call through a borrow (`let p = &h; p.Close()` takes `h`); a value whose resource sits inside a record, union or container is S109 until its generated release (L8 B2).
- `queue.Queue[T]`'s `Close()` is now `End()` (#197 q53, owner 2026-11-10; [runtime](docs/spec/runtime.md#queues) Queues 4): it ends admission and leaves the values in the queue for `Pop`, as Node's `writable.end()` does. `Close()` is the name of a release (resources R1), and a queue of plain values is no resource: it stays a shared handle that copies. The laws are `EndIsIdempotent`, `PushAfterEndFails` and `EndKeepsValues`. `Push(v T)` now writes `takes v`: the value moves into the queue. Rename each `q.Close()` to `q.End()`.
- One `time.Manual` `Advance` runs at a time (batch-13 B1; [stdlib](docs/spec/stdlib.md#time) 6): a call while another task's `Advance` of the clock runs is a defect in its caller, where two members' calls used to wait for each other forever. An actor's `Stop` and `Drain` wait parked in a clock's domain, so an `Advance` returns past a member that stops or drains an actor whose step waits on the caller of `Advance`.
- A defect in the function of `Ref.Update` or `sync.Modify` poisons the `sync.Ref` (owner q46; [stdlib](docs/spec/stdlib.md#sync-and-stm) 1): the defect reaches the caller, and every later `Get`, `Set`, `Update` and `Modify` of that `Ref` raises the defect "sync.Ref is poisoned: …". The `Ref` was usable after a defect, with the value it held before. Make a new `Ref` after a defect. In return a function literal written at `Update` or `Modify` takes the held value over and writes it in place, with no copy (V6, a Ref owns its value): an `fstest.Memory` file write costs O(its path), not O(tree), and n `io.Recorder` Prints cost O(n), not O(n²). A value `Get` returned or `Set` stored never sees such a write: the `Ref` copies a shared value once before it hands it over.
- `machines.RunTimed(m, trace, end)` runs on the context's one clock (batch 12, F4; [runtime](docs/spec/runtime.md#machines-and-actors) 9.6): its row is `fails Rejected | F needs time.Clock | Scheduler | R`, it waits on `Scheduler` until `time.Clock` reads each step's time, and a run with no `Done` waits until `end`. Bind a `testing.VirtualClock` for both (`context { time.Clock: c, Scheduler: c }`) and a machine's timers and a task's sleeps move together, in no wall time; a call with no clock in its context is S102.
- `fs.Writes` has six more operations (std-fs-safe, decision O8; [stdlib](docs/spec/stdlib.md#fs) 11 to 16): `WriteFileMode(path, text, mode)` and `MkdirAllMode(path, mode)` give exactly `mode`, whatever the umask, and the new file has no readable window; `AppendFile(path, text)` adds at the end in one `O_APPEND` write; `Chmod(path, mode)`, `Rename(from, to)` and `Remove(path)`, each failing `NotFound | Denied | Failed`. A mode is the record `fs.Mode { Owner, Group, Other }` of the union `fs.Access` (`NoAccess`, `Execute`, `ReadOnly`, `ReadExecute`, `ReadWrite`, `ReadWriteExecute`), with `fs.Private()` (0o600), `fs.PrivateDir()` (0o700), `fs.Shared()` (0o644), `fs.SharedDir()` (0o755) and `fs.Perm(m)`. A program's own provider of `fs.Writes` must add the six functions. New laws `RemoveThenNotFound` and `RenameMoves`.
- A union whose only variant is an existing type is that type, an alias (fu-mb2 F11; [types](docs/spec/types.md#unions) 7): `type EditActor = actor.Actor[Edit, EditSignal, Decision[Edit, EditOut]]` names the instance once, and a value passes between `EditActor` and the instance both ways with no conversion; a `match` on an alias is its type's match. It lowers to Go's `type A = B`. Before, `type A = B` with `B` a record of the package was a new union of one variant, and with any other `B` (a basic, operation, union or defined type, or a type of another package) S108. A program that used `type A = B` as a wrapper over its own record `B` now has `A` and `B` as one type: two 196m functions of one name on `A` and on `B` collide, and a message names `B`. No example and no std package had such a wrapper (measured: every `type X = Y` of one variant in `examples/` and `internal/sketch/std` is declared in place or has two or more variants). Declare the variant in place to keep a new type: `type A = B{ … }`. An alias takes no type parameters yet (`type A[T] = Box[T]` is S108), and one that names itself is S108 "the alias A names itself".
- `slices.BinarySearch(a slices.Ascending[T], x T) Option[int]` takes a sorted slice as a type, not `xs []T` (SS5; [stdlib](docs/spec/stdlib.md#slices-maps-and-cmp) 8). `slices.Ascend(xs)` is the one way to make an `Ascending[T]`: it sorts a copy and leaves `xs` as it was. `slices.Items(a)` gives a copy of its values. `slices.Ascending[int]{}` and `let a slices.Ascending[int]` outside `slices` are S114, so an unsorted slice cannot reach `BinarySearch`; the old call `slices.BinarySearch(xs, x)` is S108. Write `slices.BinarySearch(slices.Ascend(xs), x)`, or `slices.Ascend(xs).BinarySearch(x)`. The result is `Some(i)`, `i` the first index of `x`, exactly when Go's `slices.BinarySearch` gives `(i, true)`. New laws `AscendOrders`, `AscendPermutes`, `AscendLeavesItsArgument` and `ItemsIsACopy`.
- `strconv.Atoi` fails `strconv.Malformed | strconv.OutOfRange`: a number out of `int`'s range is the new `OutOfRange`, not `Malformed`, so a total `catch` of `Atoi` lists both (std-align S1c; [stdlib](docs/spec/stdlib.md#strings-and-strconv)). New: `strings.ReplaceAll`, `LastIndex`, `Count`, `SplitN`, `EqualFold`, `ContainsRune`, `Lines`; `strconv.ParseInt`, `ParseFloat`, `ParseBool`, `FormatBool`, `FormatFloat`, `Unquote`; package `utf8` with `RuneCount`; and 20 laws of their algebra.
- The prelude's `Random { Int63() int64 }` is `Random { Uint64() uint64, IntN(n int) int, Float64() float64 }`, after Go's `math/rand/v2`, with the laws `IntNInRange` and `Float64InUnit`; `IntN` of zero or less is a defect, as Go's panics (std-align S2c; [stdlib](docs/spec/stdlib.md#rand)). New std `rand`: `rand.Seeded(seed)`, a `Random` provider that draws Go's PCG stream for its seed, call for call, and needs no `Ambient`, so a test replays; the host provider `rand.NewHost()` (needs `Ambient`); and `Shuffle`, `Perm` and `Choice` (an `Option`), which draw as Go's do. Copies of a seeded provider share one stream. Write `IntN(n)` where `Int63() % n` was.
- The prelude's `LiveScheduler` is a host provider under `Ambient` (std-align S2b; [stdlib](docs/spec/stdlib.md#host-packages) 6): `LiveScheduler` as a value, `LiveScheduler{}` and `let s LiveScheduler` are S114, and the one constructor is the prelude's `NewLiveScheduler() LiveScheduler needs Ambient`. Write `func main() needs Console | Ambient { with context { Scheduler: NewLiveScheduler() } { … } }` where a context bound `Scheduler: LiveScheduler`; a test or a named context binds `time.NewManual(t0)` instead.
- The prelude's `Clock { Now() int64 }` is std `time.Clock { Now() time.Time }`, with the law `NowNeverFalls` (std-align S2b; [stdlib](docs/spec/stdlib.md#time)). New std `time` after Go's: `Time` with a monotonic reading, `Unix`, `Add`, `Sub`, `Before`, `After`, `Equal`, `Format` and `Parse` in UTC over a `Layout` union (`time.RFC3339`, `RFC3339Nano`, `DateTime`, `DateOnly`, `TimeOnly`, `Custom{Text}`), `Parse` failing `time.ParseError`, `Since(t) needs time.Clock`, the host clock `time.NewHost()` (needs `Ambient`), and `time.Manual`, a test `Clock` and `Scheduler` whose time moves only by `Advance`. Write `import time` and `needs time.Clock` where `needs Clock` was.
- The std package `slice` is `slices`, after Go's, with `maps` and `cmp` beside it (std-align S2a; [stdlib](docs/spec/stdlib.md#slices-maps-and-cmp)): `slices.Sort`, `SortFunc`, `SortStableFunc`, `Contains`, `Index`, `IndexFunc`, `Reverse`, `Equal`, `Collect`, `Sorted`, `Values`, Effect's `Transform` (`Array.map`), `Filter` and `Fold`, and `Max`, `Min` and `BinarySearch` that return an `Option`; `maps.Keys` and `maps.Values` as Seqs; `cmp.Compare` and `cmp.Less`. A function that sorts or reverses returns a new slice, and each family states its laws. Write `import slices` where `import slice` was.
- Only code whose row holds the new prelude capability `Ambient` makes a host provider, and only the entry provides `Ambient` (host-authority H1; [stdlib](docs/spec/stdlib.md#host-packages)). `fs.Host` and `os.Host` were zero-field records, so any function made one and read the disk or the environment with an empty row: `fs.ReadFile(fs.Host, p)`, `with context { fs.Files: fs.Host } { … }`, and a `test` that did the same all checked and ran. Each host provider now has an unexported field, and its package exports one constructor, `func NewHost() Host needs Ambient`. `fs.Host` as a value, `fs.Host{}`, `let h fs.Host` and a record update of it are S114 "fs.Host has an unexported field, so only package fs builds it; use fs.NewHost". A call of `fs.NewHost()` where no row holds `Ambient` is S102: in an exported function or `main` that does not list it, in a `test`, a package-level `let` and a named context; an unexported helper's inferred row carries it to its callers. `Ambient`'s one operation is unexported, so `with context { Ambient: Fake } { … }` is S106. A program writes `func main() needs Console | Ambient { with context { fs.Files: fs.NewHost(), os.Process: os.NewHost() } { run() } }`; a package-level `let Live = context { fs.Files: fs.Host }` becomes a local context in `main`. A function that takes a host provider or a capability value as a parameter needs nothing. The entry's S109 for another capability in `main`'s row now reads "the host provides only Console and Ambient". The prelude's `LiveScheduler` follows in H2.
- A user `extern go` binds only a package of the pure allowlist: `math`, `slices`, `sort`, `strconv`, `strings` and `unicode/utf8`, by exact import path (wave std-1, G9; [grammar](docs/spec/grammar.md#declarations), Extern). Any other Go package may reach the host, and an extern has no `needs` row, so `extern go os.Getenv func Getenv(k string) string` built and ran with a hidden effect. It is now S109 at the declaration: "extern go os.Getenv reaches the host; wait for std os.Process or #202" (std `os.Process` is the coming host capability, wave std-1 G2). `time.Sleep`, `fmt.Print`, `math/rand/v2.IntN`, `runtime.GC` and pure packages outside the list such as `math/bits`, `unicode` and `cmp` get the same S109. Std's own externs are not under the rule. The list is the one that std's purity fact (G5b) uses for the imports of a pure Go body.
- A law stands at top level, beside `test`: `law AddCommutes(a Money, b Money) { add(a, b) == add(b, a) }` is checked with a member law's rules and its parameters, then the package, in scope, and no build contains it (law-top; [types](docs/spec/types.md#laws)). A type with laws and no operations is S108 "T has laws and no operations; write it as a top-level law: law X(…) { … }"; a top-level law with type parameters is S001; top-level laws and tests share one namespace.
- A capability row is written with `|`, as an error row is (196n; [#196](https://github.com/cevr/ergo/issues/196)): `func Checkout(id string) Receipt fails NotFound | Declined needs Orders | Payments { … }` and `let Live = context provides Orders | Payments { … }`. The same row needs no parentheses inside a parameter list: `func g(h func() needs A | B)`. A comma between the names is S001 at the comma, "a capability row separates its names with |: write needs A | B", and a parenthesised row is S001 at the `(`. `with E, F`, a context entry's keys, type arguments and parameters keep their commas. The checker prints rows in messages with `|` too, error rows included (`{NotFound | Declined}`).

- The construct that binds services to providers is spelled `context` (196w; [#196](https://github.com/cevr/ergo/issues/196), [preview](docs/previews/2026-11-02-wire-to-context.md)): `with context { Store: Mem{} } { … }` and `let Live = context provides Orders needs Config { … }`. `context` is a reserved keyword in place of `wire`, which is now an ordinary identifier: an old `wire { … }` gets the plain diagnostic any stray name gets, with no rename hint. Go's `context` package is imported under another name, `import go gocontext context`; `import go context` is S108, "context is a keyword; import the package under another name: import go gocontext context". The glossary terms are Context, Context exposure, Inline context and Named context; a context value keeps its name and is a value in the context. The network sense of wire (wire formats, wire keys of a codec) is unchanged.
- Std calls run under `ergo run` (check-v1 stage D3b; [#196](https://github.com/cevr/ergo/issues/196)):
  - `task.Go`, `Wait`, `Stop`, `scope.OnExit`, `queue.New`, `Push`, `Pop`, `Close`, `Values` and `slice.WithCapacity` call their `runtime/v1` bodies with the hidden frame scope, call site and task. `Push`, `Pop` and `Values` take the caller's task, so a stop reaches a task waiting on `Pop`; a `catch` arm `case queue.Closed:` matches the queue's failure, and exit actions run after the body in reverse order.

  - `"\(v)"` runs for a value of a basic type (string, bool, the integer and float types, duration) and prints it as Go's `%v` does; a value of any other type is refused at build with S109 naming check-v1 stage E.

  - A method value of an operation, such as `q.Push` of a `queue.Queue` or `s.Area` of the program's operation type, runs: it evaluates its receiver once, where it is made, and calls the operation with the task of the code that calls it.   - Operands run left to right, each once, also when a later operand takes a method value or a later part of `"\(…)"` calls: `use(10 / zero, ss[0].Area)` and `"\(10 / zero) \(f(ss[0]))"` fail with integer divide by zero, not with the later index out of range.   - A block with no value runs as a type argument: `task.Go() { work() }` starts, and `t.Wait()` returns nothing. A declared generic function called with such a block runs too. A no-value type argument in any other position, such as a declared generic type, is refused at build with S109 naming check-v1 stage E.
  - `timeout.After` is still refused at build with S109, now naming lower-v1 (a `runtime/v1` body for `timeout.After`): its Go body is in `runtime/rt` and takes a timer factory, not the Ergo `Scheduler`.

With an expected type every branch takes it; without one the branches have the first branch's type and never join into a union. A value `if` without `else` is S108. A branch that ends in `return`, `break` or `continue` joins any type.
  - One `catch`: arms are match arms over the failure. `case Declined{Reason: r}:` handles a type only when it matches every value of it; `case err:` binds the row value of the failures the earlier arms leave, which can be returned, matched or assigned to a declared union that lists each of them; `case _` handles the rest. An arm after `case err:` or `case _` is S108.
  - `try` covers the whole expression to its right: `try a() + b()` propagates both failures. A `try` over a catch that handles the whole row, with nothing inside it that propagates, is a redundant `try`, S108.
  - One statement-position rule, for a statement and for the tail of every body with no result (an `if` or `match` arm, a `with` block, a trailing block, a `catch` arm): a call, `try`, `catch` or `with` has its result discarded whatever its type; a pure value (a literal, a name, an operator or a conversion, by any spelling of its type: `int8(n)`, `N[int](n)`, `pkg.T(x)`) is S110 "this value is not used". An arm with no work is empty. A `with` whose value is used reports a path without a value as S107 at that path. A fallible tail of an `if` or `match` branch in value position passes its failure to the enclosing `catch` or `try`, as a `with` block does.
  - `break` and `continue` inside a `match` act on the enclosing `for`; outside a `for` they are S108.
  - Comparability is structural: a union compares only when every variant does, and a row value or an operation-type value never compares. `==`, tuples, record fields, `comparable` constraints and map keys all follow it, so a checked program never panics with "comparing uncomparable type". `Map[any, …]` is S108.
  - The lowering now runs every stage B form: record, nested, constant, tuple, `as` and several-subject patterns, `let` destructuring (package-level too: the initializer runs once, before every binding), tuples and defined types (a defined error type has its own `Error` text; a constant of a defined `bool` or `string` type keeps its type). Unnamed parameters (`func M(S, int)`), and every operations conversion lower too: from a record, an instance of a generic record (`G[int]`) or a pointer to either, to an operation type or an instance of a generic one (`A[int]`, `B[int, string]`). A total match whose value Go needs has a default arm that panics with a named defect, never a zero value. Each call of the source keeps its Ergo identity in the program's call table, `ergoCalls` (#230); a defect that escapes `main` is reported with its Ergo call chain from that table (`pick at main.ergo:2`, `middle calls pick at main.ergo:7:2`), never Go frames; only Go's fatal errors (a stack overflow, out of memory, concurrent map writes) still print Go's own report. Every program registers its declaration and call tables, even with no call; package-level `let` initializers run inside the root task in Go's initialization order, so a defect in one is reported the same way. The frame that panicked is always written `F at file:line`, even when its line holds a call or it recurses, and every reported line is exact: operations that can panic carry an inline `/*line*/` directive and each Go line repeats its statement's directive.
- The checker enforces stage B of the v1 checker ([#196](https://github.com/cevr/ergo/issues/196), 196p and 196t; check-v1):
  - A record with no fields is written bare: `return Pending`, `Runner.Each(f)`. `Pending{}` is S108 "a record with no fields is written bare: Pending", and a bare name of a record with fields is S108.
  - A type's members decide its kind. A union's variants are records of the package, named bare or declared inline (`type Payment = Pending | Declined{ Reason string }`); an inline variant of a generic union takes the union's parameters its fields mention. A variant from another package is S109 naming 196b. `type Celsius float64` defines a nominal type.
  - `match` takes a subject of any type and checks the full pattern language: names that bind, constants, type tests, nested record patterns, tuples and `as`. A match must be total over a union's variants (nested), `bool`'s constants and tuples, and constants of other types never cover (S103 names one missing pattern). A case the cases before it cover is S108. `case A as e, B as e:` is S108: every pattern of a case binds each name with one type.
  - Unreachable cases include a final `case _`; duplicate constant arms name the earlier pattern. Pattern proofs share a deterministic budget for work and allocated cells, proportional to written pattern nodes and subjects. Unwritten fields are implicit wildcards; sparse rows and memo keys keep them implicit. A proof over its budget stops with S103.
  - `let` and `for` destructure with irrefutable patterns; a partial one is S103 ("use match"). A single-name `let` follows the binder rule: it may reuse a package function or value, a known type still tests, and prelude names remain protected (`let true = false` is S108). A refused pattern name still binds a placeholder, so later uses add no diagnostic. A type test may name the subject's own union type.
  - Tuples are values and types: `func DivMod(a, b int) (int, int)`, `return (q, r)`, `let (q, r) = DivMod(7, 2)`. A call is one value, so `f(g())` no longer spreads `g`'s results.
  - `T(x)` converts only between numeric types, between `duration` and `int64`, and between a defined type and its base. `string(65)` is S108 with the fix `"\(n)"`; two defined types convert through their base.
- The checker enforces stage A of the v1 checker ([#196](https://github.com/cevr/ergo/issues/196), 196u; check-v1):
  - Ergo has no untyped constants. A literal takes the type its context expects (a written `let` type, a parameter, a result, a field, an element, the other operand, an assignment's target), else its default: `int`, `float64`, `rune`, `string` or `bool`. An integer literal may take an integer or float type, a float literal only a float type. `let c int = 2.0` and `1 + 2.5` are S108 (write `1.0 + 2.5`). A named constant has one type and never converts by itself (write `int8(Limit)`). A constant expression is evaluated exactly, and an overflow of its typed result is S108 (`let y int8 = 200 - 100` is S108 at `200`): each typed step must fit. A literal fits its type after its sign, in parentheses or not (`-(128)` is an `int8`).
  - A conversion gives a literal operand no expected type, so `float64(1 << n)` shifts an `int`. A shift's left literal takes an integer context, else `int`; a float context is S108, which says to write `int(1) << n` and convert the result. Go's untyped shift rule is gone.
  - Go's built-in functions that Ergo drops (`append`, `delete`, `make`, `new`, `cap`, `copy`, `close`, `clear`, `print`, `println`, `min`, `max`, `panic`, `recover`, `complex`, `real`, `imag`) are S104, each with the Ergo form to write, such as `xs.Append(x)`.
  - Diagnostics speak the decided language: `fails` rows (never `error[…]`), `let` (never `var`), `match` and `case _` (never `switch` or `default`), `Map[K, V]`, records `{ F T }` and unions `A | B`. A recursive group's message names the row to write: "write its error row: func f(…) T fails …", or its capability row with `needs`.
  - A node the decided parser never builds is S109 "not produced by the decided parser", never a panic.
  - A call of a constant, `1()`, `""()` or `K()` with `let K = 1`, is S108 "cannot call …". The checker accepted it before.
  - `s == m`, where `s` holds an operation type and `m` is a record that satisfies it through its functions, is S108 "cannot compare …". The checker accepted it before.
  - A removed built-in reports one S104: `new(int)` no longer adds "int is a type, not a value".
  - Two own entries for one capability in one context are S111 even when they are `replace` entries: `context { replace Store: a, replace Store: b, Base }` reports "Store has a second entry in this context, entry 2; the first is entry 1". The checker accepted two replaces before and bound the first. A capability written twice in one entry, `context { Store, Store: Mem{} }`, names its two keys: "Store is listed twice in entry 1, as its keys 1 and 2".
- Sources use the decided syntax of [#196](https://github.com/cevr/ergo/issues/196) and end in `.ergo` ([#221](https://github.com/cevr/ergo/issues/221)). Every command refuses any other extension, `.ef` included, with `source file must have .ergo extension`. The grammar is [docs/spec/grammar.md](docs/spec/grammar.md). What stopped parsing:
  - The Go spellings: the package clause, grouped and quoted imports, `:=`, `var`, `const`, `struct`, `interface`, receivers, `(T, error)` results, `switch` and type switches, `default:`, `go`, `defer`, channels, `select`, `map[K]V`, `++` and `--`, three-clause and `range` loops, variadic parameters, fixed arrays, labels, `goto` and `fallthrough`. Each is S001 with a message that names the Ergo form (`let`, `type Name { … }`, `T fails E`, `match`, `case _:`, `task.Go`, `scope.OnExit`, `Map[K, V]`, `for x in xs`, …).
  - The old Ergo spellings: `error[…]` rows, `wire Name { A = x }`, `catch e { … }`, bodiless functions with `//ef:go`, `uses` and `try` in operand position. Each is the plain S001. Tests are `test Name { … }`, laws `law Name(…) { … }` and contexts `let W = context { A: x }`.
  - Record members and context entries are separated by commas, which a line break does not replace. In a context, a comma run of names ended by `:` is one entry's key list on one line or several, so an embedded context is written after the entries. `ergo fmt` writes `with (W) { … }` as `with W { … }`. Its identity (`formatterVersion` in `ergo fmt --json`) is `ergo-2026/formatter-2`.
  - `scripts/migrate196` translates one old-syntax file into the decided syntax. It is a one-off and goes after v1.
- The earlier `.ef` language is retired ([#205](https://github.com/cevr/ergo/issues/205)). Every command reads a source as the one language that `internal/sketchfront` checks, formats and builds. What stopped working:
  - Editions and the manifest. `ergo.json` is no longer read; a stray one beside a source is ignored. `ergo edition` prints `ergo edition: removed in v1; there is one language and no editions (#205)`. EF144, EF145 and EF146 are retired. A source written in the earlier language now gets the parse diagnostics of the one language.
  - Semantic tooling. `ergo inspect`, `explain`, `query`, `type` and `graph` are removed until they return on the new front end ([#203](https://github.com/cevr/ergo/issues/203)). Each prints one line to stderr and exits 1, before it reads its arguments.
  - Linting. `ergo lint`, `lint rules`, `lint test` and `lint receipt`, the rule packs and the lint-pack SDK (`lint/`) are removed until linting returns on the new checker (#203). `ergo diagnostics --lint-config` and `--rules` are unknown options (exit 2).
  - Formatting. `ergo fmt --stdin` formats only the one language; a source in the earlier language is a syntax failure. The formatter identity in `ergo fmt --json` (`formatterVersion`) changed from `ergo/formatter-16` to `ergo-2026/formatter-1`.
  - Invalid UTF-8 is no longer refused. The earlier front end refused it (EF001 from `ergo check`, `EFMT_SYNTAX` from `ergo fmt`, exit 2). Now `ergo check` accepts invalid bytes in comments and strings, and `ergo fmt` writes them back unchanged.
  - `ergo test FILE [--seed N] [-work]` runs the file's tests (lower-v1 stage 4; [runtime.md](docs/spec/runtime.md)): `ok`/`FAIL` per test, `PASS (N tests)` and exit 0, `FAIL (K of N tests)` and exit 1, exit 2 for a defect or a usage error. The earlier stub is gone.
  - `ergo lsp` and `ergo mcp` print `unavailable until ported to the new front end (#203)` and exit 1. The MCP server and the language server are gone until then.
  - `ergo build --receipt` and its application receipt are removed.
  - JSON shapes. The `ergo check` envelope drops `edition` (`schemaVersion` 10). The `ergo diagnostics --json` report drops `lintAvailable`, `lintComplete`, `lintUnavailableReason` and `suppressions` (`schemaVersion` 2). `ergo fmt --json` keeps its shape and reports the one formatter's identity.
  - `ergo --help` lists only the commands that run.

- The language is renamed Ergo (owner, 2026-10-27; [#218](https://github.com/cevr/ergo/issues/218)). The CLI is `ergo` (`cmd/ergo`, built as `bin/ergo`), the manifest is `ergo.json` (formerly `effra.json`), the Go module is `ergo.local/prototype`, edition and tool identities are `ergo-…` (formerly `effra-2026/formatter-1` and the like), bundled modules are `ergo/…`, the runtime package is `runtime/ergo`, the MCP server and LSP language id are `ergo`, environment variables are `ERGO_*`, the lint suppression directive is `ergo-lint-disable-next-line`, and links point at `github.com/cevr/ergo`. The `.ef` extension, `//ef:go`, and the `EF` and `EFMT_` codes keep their spelling until #205. Entries below describe their changes under the old name.
- In the 2026 edition, the keyword `uses` is now `needs` (owner, 2026-10-27; [#217](https://github.com/cevr/ergo/issues/217)): `func main() needs Console`. `uses` is an ordinary identifier with no compatibility path, so old text gets a plain S001. A named context states what it exposes with the new keyword `provides`, and may also state what its providers need: `context App provides Account | Invoice needs Config { … }`. Both header clauses parse and format; the bridge refuses them with S109 until #196 checks them. The language has 28 keywords. The legacy edition keeps `uses { … }`.
- Go is Effra's only target (owner, 2026-10-26: "we're removing the js interop id say"). The JavaScript emitter, `--entry`, running programs and tests with Bun or Node, the JavaScript receipt, and the `js` target in the CLI, MCP, LSP and lint manifests are removed. `--target js` is now the EF110 diagnostic `unsupported target js; the only target is go`. Effect stays the model for the guarantees, not a runtime or an ABI. Entries below that mention JavaScript describe work that this change removes.
- The repository no longer has a Node toolchain: the root `package.json`, `bun.lock` and `node_modules` are gone, and the gate needs only Go and Git. The pinned Effect upstream checkout (`conformance/upstream/effect`, `.gitmodules`, `scripts/init_upstream.sh`, the manifest and the `import` step) and `conformance/framework-ports/` are removed; there is no exact Bun version requirement. `conformance/effect-cases.json` keeps each case's upstream file, line and label as provenance text, and `go run ./scripts/conformance check` validates it without a checkout, with Go-only evidence tests. The codec comparator outputs under `conformance/codecs/` are frozen golden files.
- The research tooling under `benchmarks/*/ts` no longer runs: it loaded TypeScript from the removed framework-port leaf and Effect from the removed `node_modules`. Its recorded runs stay as research records.

- `enter`, `stay`, `ignore`, `reject` and `done` are reserved for machine decision forms. A function, parameter, local or declaration with one of these names is now an EF002 parse diagnostic that names the decision form; rename it. They stay legal as explicit field labels (`done: bool`, `Todo { done: true }`, `todo.done`), so wire keys such as `"done"` keep working, and as qualified host members (`sdk.done`); only shorthand `{ done }` is refused.
- An unhandled failure at `main` now writes the same entry failure report on Go and JavaScript: one stderr line per cause reason, such as `failure: AssertionFailed { message: "expected \"b\"; received \"a\"" }`, `defect: "..."` or `interrupt`. Go used to print only the failure tags, and JavaScript printed a host object dump that kept only the first reason. The exit status is 130 when every reason is an interruption, including a SIGINT or SIGTERM, and 1 otherwise. `ef run` forwards those signals and passes the program's report and status through without adding `exit status N`. Payloads are rendered from the checked types of `main`'s failure row, so the report is identical for every failure in that row that both targets can raise, including built-in, codec and HTTP listener failures. The one exception is an unclassified HTTP listener failure, which keeps the host's text. A record field named `_tag` stays ordinary data. A Go `Timeout` failure no longer carries a payload, which matches JavaScript. Built-in diagnostics now read the same on both targets: `Assert.equalText` quotes both sides with the report's string rule on Go and JavaScript (Go used `%q`, JavaScript `JSON.stringify`), and using `TestClock` or `TestScheduler` outside `ef test` raises one defect message on both, such as `test clock requires the ef test harness`. The full grammar is in [the design](docs/design.md#entry-failure-report).
- `Http.listen` checks its address before the host sees it, and reports listener failures in Effra's words on both targets. An address must be `host:port` with a decimal port from 0 to 65535 and a bracketed IPv6 host. Go used to accept service names such as `:http` and an empty port, and JavaScript raised a defect for an address without a colon. Both now fail with `IoError`, such as `invalid HTTP address "bad": missing port`. A failed listen reads `HTTP listen on "ADDRESS": address in use` (or `address not available`, `permission denied`, `host lookup failed`); any other listener failure keeps the host's text. The rules are in [the runtime guide](docs/runtime.md#http-server).
- A declared Go import the generated program cannot import is now refused by `ef check` with EF111 at its import declaration, whether or not any call uses it. The rule is the Go command's: a `main` package, a vendored package (any non-final `vendor` element; a package whose path merely ends in `vendor` is an ordinary package), and an `internal` package whose parent tree does not contain the generated main package. Every standard-library `internal` package is refused. Such imports used to pass `ef check` and fail later in `ef build` with a raw Go error.
- Declared Go imports initialize their package even when every caller is unreachable. An explicit Go import declares a runtime initialization dependency as well as host declarations, so the package's `init` functions and variables run before `main` or the test harness. Pruning still removes unreachable callers, bindings and helpers, never that initialization. Delete the import to drop the initialization. `ef check` and MCP `project.check` report each mode's `goInitialization` packages and whether they lower as a named or blank import.
- `GoHttp` is now `LiveHttp`.
- `Http.serve(address, handler)` and the `Handler` shorthand are removed. Use `Http.listen(address, HttpLimits, handler)` with an effectful `HttpRequest -> HttpReply` handler (`HttpHandler`). `Handler` is an ordinary user name again, and a call to `Http.serve` is EF102 on Go and JS. Paths keep their percent-encoding and failure bodies are empty.
- A declaration named like a builtin Http type (`HttpRequest`, `HttpResponse`, `HttpReply`, `HttpLimits`, `HttpHandler`) is EF101 once the program refers to the global `Http` or `LiveHttp`. Until then every one of these names is free for your own data and an ordinary type on Go and JavaScript, including `HttpHandler` (a `record HttpHandler` is declared, used in fields and signatures, constructed and built like any record). Without a declaration of your own, `fn f(h: HttpHandler)` is EF102 (unknown type) until the program refers to Http. A local value or row parameter named `Http` or `LiveHttp` is not a reference.
- Every generated JavaScript executable entry now interrupts `main` on SIGINT and SIGTERM, including programs that do not use Http. An interrupted run reports the interruption on stderr instead of dying from the signal. Library emission installs no handlers.
- `effra.bindings.json` is validated strictly. Each contract key must be the go/types full name of an exported function or method in the package it names (that package is loaded for the check even when the source does not import it), otherwise EF111, one diagnostic per key, sorted, with near misses from the same package. A key for an unnamed interface's method (`(interface).M`), which Go spells identically for unrelated declarations, is refused as ambiguous, and so is a package pattern such as `std`, `./...` or `all`. A refused key is never applied to a binding. Keys that used to be silently ignored now fail the check.

A run with a value of an unbounded type keeps 100 generated cases and prints `(100 cases)`, never proved. A listed case that refutes a law prints `(case K of N, every value: …)`.

- An interpolated value has a text form exactly when its type is a basic type or a type defined over one, at any depth (check-v1 E6a, D-E6, Q5; [grammar.md](docs/spec/grammar.md#literals) Strings 5): `"\(t)"` with `type Celsius float64` runs and prints `21.5`, complex values print as Go's `%v` does, and a record, union, tuple, slice, Map or type-parameter value is S109 naming [#49](https://github.com/cevr/ergo/issues/49) at the value (a function, operation-type, `Task` or pointer value is S108), where the checker accepted it before and the build refused it. The lowering appends each number with `strconv` into a stack buffer that Go's concatenation reads in place, so `"n=\(n) f=\(f) s=\(s)"` makes one allocation, as hand-written Go does; it calls no `fmt`.
- A local context, `let quiet = context { Greeter: Plain }` in a body, and a `with` of several operands, `with Live, quiet { … }`, check and run (check-v1 stage E5, 196x; [rows.md](docs/spec/rows.md#context) Context 9 and With 7): a local context is a recipe that each `with` naming it builds again, its needs are charged (S102) at that `with`, any other use of it is S108, and `with A, B { b }` is `with A { with B { b } }`.
- A user `extern go` binding of Go's `unsafe` package (such as `extern go unsafe.Sizeof func Size(x int64) uintptr`) is S108 at the declaration: "Ergo has no unsafe; unsafe stays at the FFI edge" ([grammar.md](docs/spec/grammar.md), Extern). So no Go built-in is the target of a user extern.
- A user `extern go` binding runs (check-v1 stage E4, 196x; [runtime.md](docs/spec/runtime.md)): a call of an extern whose signature has only basic types and whose target is in Go's standard library lowers to a direct call of the Go function, with no wrapper, and `go build` reports a target that does not match the written signature at the Ergo call's line. Before, `ergo run` refused every user extern with S109. A host call is not an interruption point. The context values of a std package are now keyed by its identity, so a defect report's `context` line writes `std:trace.span="…"` and `std:log.KEY="…"`, and a program package checked under a std path never shares std's keys.
- Laws are checked, not run (check-v1 stage E3b, 196l; [types.md Laws](docs/spec/types.md#laws)): a law sees its parameters, then its type's operations, which are call-only and charge nothing, then the package; its body ends in a `bool` (S108), a fallible tail is tried (S105), it needs no service (S102), and no binder of it may take an operation's name (S108). A law was S109; running laws is [#162](https://github.com/cevr/ergo/issues/162).
- A name in a context `with` follows lexical scope: a local or parameter shadows a package context. A package value (a `let` or a function) and a named context of one name are S108 at the later declaration; a type and a context may still share a name. Context keys are private to the package that declares the binding's type. Lowering supplies the package to each read, so a user type cannot forge a span or log annotation by spelling its key (#199 stage 4a).
- A `with` now binds a context value for its block (#199 stage 4a, [runtime.md G1](docs/spec/runtime.md#g1-context-through-with)). `with log.Annotate("request", id) { … }` and `with trace.Span("load") { … }` bind a value that `log.Annotation(key)` and `trace.Current()` read inside the block and in every task the block starts, and the caller's values come back on the normal end, a typed failure, a defect and a stop. A task keeps the values it started with: a later binding in its parent never reaches it. A user type becomes a context value by declaring the two unexported protocol functions `contextKey` and `contextText` in its package; the checker admits a `with` operand only through that checked protocol, never by package name. The operand is evaluated once, before the region opens, and is checked as an ordinary argument; the region discharges no need and starts no task. Context values are strings at run time, and a context read is effectful: it counts as opaque in the frame's footprint, so a loop that reads one keeps its interruption point. New errors: a `with` operand that is neither a context nor a context value (S108), and a `with` of a local non-context value or of several operands (S109, #196).
- The v1 std packages `task`, `scope`, `queue` and `slice` have Ergo signatures, and the checker checks a program that imports them (lower-v1 stage 3b-std): `task.Go() { … }` yields a `Task[T, E]` and needs what its block needs; `scope.OnExit() { … }` takes a block with no error row; `queue.New[T](capacity)` makes a `queue.Queue[T]` whose `Push` and `Pop` fail with `queue.Closed`; `slice.WithCapacity[T](n)` is an empty `[]T`. An import of them was S109. Each signature is an `extern go` declaration bound to its Go body in `runtime/v1`; a body's hidden arguments (the caller's frame, the call's site, the caller's task) are named by their Go types ([stdlib.md](docs/spec/stdlib.md#v1-packages-task-scope-queue-and-slice), Hidden arguments). Not yet: `ergo build` refuses a call of them with S109 until check-v1 stage D lowers them, and `q.Values()` waits for the prelude's `Seq[T]`.
- A lexical error after a construct the 2026-edition parser reads ahead over is a located S001, not a crash or a hang ([#226](https://github.com/cevr/ergo/issues/226)). `func A(){match A{"` crashed `ergo check` and `ergo fmt` with a slice out of range, and `func A(){for "` or `type A{F["` never returned. The scanner now ends its token stream with EOF after the error, and its error token never lies behind a token already read. When a reading reaches the lexical error, the error is reported, not an earlier parser error from a fallback reading: `for i, x in xs` with a pasted no-break space before `in` names the U+00A0, not the comma.
- `machine Name { initial S.V {}; step f }` declares a state machine over ordinary named functions: `step` is a pure or effect `(S, E) -> decision<S, O>`, `initial` is a literal constructor of `S`, and a `stay` must keep the current variant (EF139). Decisions are syntax: the predeclared `decision<S, O>` and the forms `enter e`, `stay e`, `ignore`, `reject` and `done e` (bare `done` for a void output), matched with the same words; the five words are reserved as names but stay legal as explicit field labels (so a derived codec can carry the wire key `"done"`), and a form where no decision is expected, or a decision a statement discards, is EF143. Plan transitions and graph edges publish the same words (`enter`, `stay`, `ignore`, `reject`, `done`). Checking publishes one inspectable plan per declaration (states, possible transitions, function contracts and terminal output) through `ef check`, MCP and `ef graph --kind machine`; contract violations are EF140, unadmitted forms EF141, and every analysis is bounded, refusing with EF142 rather than admitting what it did not inspect. A module admits at most 256 declarations; each has a 65,536-unit analysis budget, of which a fixed 171 units pay for its own state, and all of them share one 1,048,576-unit budget per module. `enter`, `complete` and the runtime are specified, not built. The formatter identity is `effra/formatter-16`, which also admits `machine` declarations and decision forms. See [state machines](docs/specs/state-machines.md).
- Three checker passes whose cost was quadratic in the program's declarations now look names up in an index. Resolving a data type by name used to copy and scan every record and enum: a program of 20,000 one-field records plus one record naming them all took a median 7.6 s in `ef check` and allocated 13.4 GB, and now takes 0.39 s and allocates 0.31 GB, between 329 and 388 bytes per source byte from 2,500 to 80,000 records. Publishing generic data declarations used to search every published declaration for each one, and checking a callable's `uses` row used to scan every service for each label. Checked results are unchanged.
- `derive w = Json.codec<T>(..., decode: f, encode: g) with w1, w2` declares a transformed codec witness: ordinary functions convert to and from a structurally derived representation, rows are direction-specific, and decoding validates the whole structure before any transformation runs. A transformed domain must be plain data (EF138 for a resource, function or runtime value), checked under a 4096-unit layout work budget (EF127). Encoding writes as it transforms and retains nothing beyond `maxBodyBytes`; on Go it runs a writer generated per plan that reads the value in place, without reflection, and calls each witness's encode function directly with its typed domain value, matching a hand-written Go encoder of the same contract in retained and allocated memory.
- `derive e = Http.endpoint(method:, path:, input:, handler:, output:, status:) raises { Failure: status witness }` and `derive api = Http.routes(...)` declare typed JSON endpoints served by `Http.listen`; `derive w = Json.codec<SomeError>(...)` is a failure witness that encodes a mapped failure's body. Every reachable named failure must be mapped (EF107); the endpoint's row keeps the mapped failures, which a compound cause propagates. The formatter identity is `effra/formatter-16`.
- Service operations and implementation methods may declare row parameters (`E: raises`, `R: uses`), so a callback operation can state that its result rows follow the callback's rows. An operation's `uses` may name only its row parameters (a fixed label is still EF103), type parameters on operations and implementation methods are EF125, and an implementation conforms up to row-parameter renaming (arity or kind mismatch is EF104). An Effra implementation body cannot catch an abstract row (EF125). The JavaScript declarations of the service and provider carry the generic row variables. An implementation method body may use only its declared `uses` row plus the constructor's captured services; a callback requirement it does not declare is EF108.
- `Http.listen` and `Http.text`, with the builtin types `HttpRequest`, `HttpResponse`, `HttpReply`, `HttpLimits` and `HttpHandler`, provide bounded buffered HTTP/1.1 on Go and on server JavaScript. JavaScript programs can use Http (previously rejected); only Go imports still require the Go target (EF110).
- Admission of the Http contract follows lexically resolved references. Value and row bindings are resolved once, before checking, and the checker, lint and dependency ordering read that single resolution.
- The JavaScript library surface exports `LiveHttp` only where checked code selects it: a module function that provides it, or a provided layer. A library that only requires the `Http` interface exports the service tag and embeds no transport.
- Imported Go declarations are checked as canonical host types identified by package path and name: `string`, `bool`, `int64` and `[]byte` keep their Effra primitives, native `int` and `uintptr` keep their own width, and exported non-generic named types, pointers, slices and maps are nominal host values. Unsupported widths, generics, variadics and unimportable types diagnose with their reason.
- Nullable native results adapt through bundled `Option` (nil is `None`; every other value, including an interface holding a nil dynamic pointer, is `Some`). A nullable parameter receives only a present value. There is still no nil in source.
- Every result component of an imported function is retained: several results form a tuple with positional fields `v0`..`vN`, and a trailing `error` yields `GoResult` with `.value`, `.hasError` (Go's `err != nil`, so a typed-nil error is an error) and `.error` as `Option<error>` holding the original native error. `.orFail()` preserves the whole partial value.
- A source declaration may share a name with a predeclared Go annotation (`record int` beside `i64(n)`): the program builds, because the generated alias for the native `int` lives in its own `efHostType_` namespace.
- Source can annotate native types with Go's own spelling: `*sdk.Client`, `[]string`, `map[string]int`, and `error`, `any`, `int`, `uintptr` in programs that import Go.
- Go method calls follow Go's method sets on any executed receiver, such as `(run sdk.Open()).Close()`. A call is a lazy `Foreign` recipe that evaluates its receiver once. Pointer-receiver methods need a pointer; native fields and method values are not admitted. Universe methods such as `error.Error` work.
- A concrete host value reaches a native interface parameter with Go's assignment rule, so `io.Copy` keeps `WriterTo`/`ReaderFrom` dispatch. `value.as<T>()` is Go's comma-ok assertion, returning `(Option<T>, bool)`. `i64(n)` widens a native `int` and `int(x)` narrows to `Option<int>`.
- Checked Go I/O: `Read`, `ReadAt` and `Write` on `io.Reader`, `io.ReaderAt` and `io.Writer` implementations follow those interfaces' contracts (data returned with `io.EOF` stays beside the error; a short write is reported as `io.ErrShortWrite`), and `fs.FS` values keep `ReadDirFS`/`ReadDirFile` dispatch.
- `effra.bindings.json` contracts are keyed by the go/types full name, so methods can carry context-forwarding and cancellation contracts, and a promoted method (including from an embedded generic instance) carries the contract of the method it promotes. To give a method of an unnamed interface a contract, pass an explicit `context.Context` or declare a named Go interface with the method in your module.
- Native bindings are keyed by canonical identity (`go:<package path>.<name>` for a function, the actual receiver type and method for a method), so two receivers that display alike no longer share a binding. Inspection reports both the display symbol and the identity.

### Runtime

- New std `schedule` says when to run work again and when to stop (batch 13; [stdlib](docs/spec/stdlib.md#schedule)): `Spaced`, `Forever`, `Exponential(base, factor, cap)`, `Recurs(n)`, `UpTo(s, limit)`, `Jitter(s, low, high, seed)`, `And`, `Or`, and the pure `Decide(s, runs, elapsed)`, which gives `Continue{After}` or `Stop`. `tasks.Retry(s) { … }` runs a block until it gives a value or the schedule stops, and `tasks.Repeat(s) { … }` runs it again while the schedule continues; both read the context's `time.Clock` and sleep on its `Scheduler`, so they run in virtual time under a `testing.VirtualClock`. Seven laws.
- A pure run of a declared machine is a direct loop (MU8; [runtime](docs/spec/runtime.md#machines-and-actors) 8): `machines.Run(X{}, signals)` and `machines.From(X{}, s, signals)` hold the state as a Go value and switch on its variant, so a run allocates twice in all where it allocated twice per signal, and a transition of effect-machine's "simulate" counter costs about 1.4 ns instead of 68 ns. Runs and their results are unchanged. The lowering through std's loop is selectable with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.machineLowering=interface`.
- A machine's signal union is a tag and its variants' records, not a Go interface, where it is small and the program's own (MU8b; [runtime](docs/spec/runtime.md#machines-and-actors) 8, Flat signals): a match on a signal switches on a byte, and a pure run checks for a stop once every 256 signals. Values, `==`, matches and runs are unchanged. The interface form is selectable with `-ldflags=-X=ergo.local/prototype/internal/sketch/lower.unionLowering=interface`.
- `time.Advance(m, d)` on a `time.Manual` returns only once the tasks it woke wait again (fua-b, batch 13; [stdlib](docs/spec/stdlib.md#time) 6, [runtime](docs/spec/runtime.md#machines-and-actors) 11.16). `NewManual` makes the calling task the first member of the clock's domain, as `testing.NewVirtualClock` does, and `Advance` moves one deadline at a time, waiting after each until every other member waits on a wait the clock sees. So a test on a Manual reads an actor's state, or a task's result, right after `Advance`, with no loop on `Sleepers` or `State`. An actor's waits (its inbox, `Send`, `Ask`, `State`, `Changes`, `ExitOf`, `Host.Get`) are now seen by both clocks, so a `VirtualClock` moves while an actor waits for a signal. A member that waits on something no clock sees (the host's input, a file) keeps `Advance` waiting until that wait ends.
- A machine actor gives an `Emit`'s or a `Done`'s output to its `sink` first, before it acts on the decision (fua-a, batch 13; [runtime](docs/spec/runtime.md#machines-and-actors) 11.15). Before, it showed the `Emit`'s new state to `Changes`, `State` and `WaitFor` and only then called the sink, so a driver that saw the state and then read what the sink kept could miss the output. Now an observer that sees a state has every output of the commits up to it, and the same holds for a child's outputs in its parent's inbox. A timer whose `In` is not positive now raises after the `Emit`'s output.
- New `tasks.Set` (runtime.md G4, batch 13 tasks-set; [stdlib](docs/spec/stdlib.md#tasks) 11-17): `tasks.NewSet[E](policy)` owns any number of tasks, `tasks.Go(set, body)` starts one, and a member that ends is dropped. The frame that made the Set owns it by the Task rule: its end stops every member, a return moves the Set to the caller, and a Set in a field, an element or a capture is S108 "a tasks.Set leaves its function only by return; stop it or return it". The policy is `tasks.FailFast` (the first failure or defect closes the Set and stops the rest; `Wait` gives it), `tasks.LogFailures` (written to standard error and dropped) or `tasks.Restart{Limit}` (a defect runs the body again, up to `Limit` times). `Wait`, `Stop` and `Len`; `Go` on a closed Set fails `tasks.Closed`. Laws `NoMemberOutlivesItsFrame`, `FinishedAreDropped`, `FailFastStopsTheRest`, `RestartRunsAgain` and `Set.StopEndsEveryMember`.
- Supervised machine actors (MU7, batch 13; [runtime](docs/spec/runtime.md#machines-and-actors) 18, [stdlib](docs/spec/stdlib.md#actors) 9): `actor.Supervise(m, capacity, sink, tasks.Restart{Limit})` restarts an actor after a defect, at most `Limit` times, each time in `m`'s initial state, and `actor.SuperviseDurable(…, recover, save)` in the state `recover` gives; the `Ask` in the crashed step and the queued ones get `actor.Stopped`, queued `Send`s are dropped, and `Done`, `Stop`, `Drain` and a typed failure end the actor for good. `actor.Restarts(a)` counts the restarts. The example `sign-in` names its send failure `PhoneUnreachable`, since `Unreachable` is a prelude name.
- Durations as text and numbers: std `time` gains `ParseDuration(s) duration fails ParseError` (Go's grammar and messages), `DurationText(d)` (Go's `Duration.String`), `Times(d, n)`, saturated where Go's product wraps, `Divide(d, n)` and `Count(d, unit)` (Go's `int(d / unit)`); std `flag` gains `flag.Duration(name, def, usage)`. A program writes `time.Times(1ms, n)` for `n` milliseconds (std-duration; [stdlib](docs/spec/stdlib.md#time) 8). Four new laws. `flag.Flag` has a fifth variant, `DurationFlag`.
- Encodings and digests in std (G3 std-digest; [stdlib](docs/spec/stdlib.md#encodings-and-digests)): `hex.Encode`, `hex.Decode`; `base64.Encode(e, s)` and `base64.Decode(e, s)` with `e` the union `base64.Encoding` of `StdEncoding` and `URLEncoding`; `sha256.Sum` (32 raw bytes); `crc32.Checksum` and `crc32.Update`. They work on strings, which hold bytes, and give Go's answers on any bytes. A decoder fails `hex.Malformed` or `base64.Malformed` with the `Offset` of the first bad byte. `encoding/hex`, `encoding/base64`, `crypto/sha256` and `hash/crc32` join the pure allowlist, so a user `extern go encoding/hex.…` now checks. Seven new laws.
- Runes, numbers and bits in std: `utf8.DecodeRuneInString(s)` gives the record `utf8.Decoded { Rune, Size }`, an invalid byte `(U+FFFD, 1)` as in Go; `utf8.RuneText(r)` (Go's `string(r)`), `AppendRune`, `ValidString`, `ValidRune`, `RuneLen`; `strings.ToValidUTF8`; `strconv.FormatInt(n, base)`. Two new std packages over Go's own functions: `math` (`Abs`, `Ceil`, `Floor`, `Trunc`, `Round`, `Sqrt`, `Pow`, `Mod`, `Inf`, `NaN`, `IsNaN`, `IsInf`, and `MaxInt64()`, `MinInt64()`, `MaxInt()`, `MinInt()` as functions) and `bits` (`OnesCount`, `LeadingZeros`, `TrailingZeros`, `Len`, their `64` forms, `RotateLeft32`, `RotateLeft64`). Every body is pure. `math/bits` joins the pure allowlist, so a user `extern go math/bits.…` now checks (std-text-runes; [stdlib](docs/spec/stdlib.md#math-and-bits); [strings and strconv](docs/spec/stdlib.md#strings-and-strconv) 8). Twelve new laws.
- New in std `slices`: `Clone`, `Concat(a, b)`, `Repeat(xs, n)` and `Slice(xs, i, j)`, Go's full slice expression `xs[i:j:j]`, so an `Append` to a slice of `xs` never writes `xs`; `Len(a)` and `At(a, i)` on an `Ascending`. New in std `maps`: `Clone`, `GetOr(m, k, def)` and `Update(m, k, f)`, an upsert whose callback sees `Some` of the old value or `None`, may fail, and returns the new Map, leaving `m` unchanged as `Delete` does under the value rule (std-slices-maps; [stdlib](docs/spec/stdlib.md#slices-maps-and-cmp) 9, 10). Nine new laws.
- New `tasks.Race(blocks)` (batch 12 C4; [stdlib](docs/spec/stdlib.md#tasks) 7-10): each block runs on a task of its own, and the first to end decides, with its value or its failure. The other blocks are stopped, and `Race` returns only after they have ended, their exit actions included. Blocks that end at the same instant tie, and the earliest in the slice wins. Ergo has no `select`: a race of two queue `Pop`s can drop a value, so a task that waits on several sources reads one queue of a union instead (the inbox pattern). Laws `EarliestWins` and `LosersStopped`.
- A stop ends a read of standard input (batch 12 C3; [stdlib, io](docs/spec/stdlib.md#io) 3; decision O15). A task that waits in `io.Stdin.Lines()` or `ReadAll()` of `io.Host` stops at once when it is stopped, where it used to wait until the input had a line or closed: `task.Stop()` of a reader with the input open now returns in milliseconds. No input is lost: the line read after the stop, and the text a stopped `ReadAll` had read, stay for the next read.
- New std `tasks` with `tasks.Transform(xs, limit, f)`, the concurrent form of `slices.Transform` (batch 12 C2; [stdlib](docs/spec/stdlib.md#tasks)): each call of `f` runs on a task of its own, at most `limit` at once, and the results keep the order of `xs`. The first failure stops the calls still running, waits for them and is the result; no call starts after it. Every task has ended when `Transform` returns. A `limit` below 1 is a defect. It is not named `Map`, because `Map` is the prelude's type. Laws `TransformEqualsLoop`, `TransformKeepsOrder` and `LimitHolds`.
- New std `testing` with `testing.VirtualClock`, a test `time.Clock` and `Scheduler` whose time moves on its own when every task of the test waits (batch 12 C1; [stdlib](docs/spec/stdlib.md#testing)). `let c = testing.NewVirtualClock(0)` then `with context { time.Clock: c, Scheduler: c } { … }`: a sleep of hours takes no wall time, and a test needs no loop on `Sleepers()` before it advances. The time moves only when every task started below the clock's maker is parked in a sleep, a queue wait, a task's `Wait` or `Stop`, or `timeout.After`, and then to the earliest deadline; a host wait, such as a read of standard input, keeps it still. Laws `SleepAdvancesExactly` and `IdleOnlyAdvance`.
- Durable machine actors (MU9; [runtime](docs/spec/runtime.md#machines-and-actors) 17): `actor.StartDurable(m, capacity, sink, recover, save)` starts from the recovered state and saves each committed transition before the actor commits, publishes or answers it; a failed save is a defect. New std `journal` (`Journal[S, E]` and `Codec[T]` with laws, `journal.Start(m, j, every, capacity, sink)`, which replays the journal with the pure step and snapshots every `every` saves, failing `Diverged` when the journal does not fit the machine), with the providers `journal/memory` and `journal/file`. A machine given to a durable runner must have a pure step: S108 names the step's first impure call.
- Name a child before it runs (mu-host; [runtime](docs/spec/runtime.md#machines-and-actors) 16): a step puts `actor.NewHost[A]()` in the state it enters, that entry's work fills it with `actor.ChildIn(send, host, m, capacity, toParent)`, and any task reads it with `host.Get()`, which waits for the fill and fails `Stopped` once the entry ended. The entry is shown to observers only after its work filled its hosts, waited or ended, so a reader that sees the entry needs no settle loop. A `ChildIn` on a host of another entry is a defect.
- Feed a machine actor from a source, and ask whether it can take a signal (MU10; [runtime](docs/spec/runtime.md#machines-and-actors) 15): `actor.Feed(a, cards)` gives `a` each value of the `Seq` `cards` as a signal, in order, on a task the actor owns; when the actor ends, the source's next value is not sent and a waiting source is stopped, so no source runs once `Stop`, `Drain` or `ExitOf` returns. A `Feed` on an ended actor fails `Stopped`. `machines.Can(step, s, e)` is whether a pure step takes `e` in `s` (not `Ignore` or `Reject`), and `actor.Can(a, step, e)` asks it in the actor's state and is `false` once the actor has ended, with no step run.
- A traced machine actor reports each step of its runner (MU15; [runtime](docs/spec/runtime.md#machines-and-actors) 15): with `ERGO_TRACE=trace.jsonl`, a program writes its trace as JSON Lines, and each actor's lines say `start`, `signal`, `timer-armed`, `timer-fired`, `dropped` (a stale signal), `decide` (with the decision, the next state and the `file:line` of the step's arm), `fail`, `work-started`/`ended`/`failed`/`interrupted`, `child-started`/`stopped`, `stop` and `exit`. Untraced, each hook is one load and compare.
- Machine actors are faster (MU18; [runtime](docs/spec/runtime.md#host-and-lowering-notes), Actors): a Send costs about 1.8x less and an Ask about 1.65x less than before, a start and stop about 2.6x less, and an idle actor about 1.6 KB less. Against a hand-written goroutine with a channel, measured interleaved: Send about 1.4x, Ask about 1.5x (parity when the hand code's waits also wake on a stop, as an actor's do), spawn and stop about 1.85x, an idle actor about 670 B more. Every actor rule holds as before; the old inbox stays as the reference the tests compare against.
- A machine's entry may own child actors (MU5; [runtime](docs/spec/runtime.md#machines-and-actors) 14): in a state's work, `actor.Child(send, Editor{}, 1, func(n int) Signal { Saved{N: n} })` starts a machine owned by that entry and returns its `Actor`. Its `Emit` and `Done` outputs come back as the entry's signals, and one that arrives after the entry ended is dropped. The entry's children stop, the last started first, before the entry's timer and work and before the next entry opens; a child's defect ends its parent. The checker accepts `actor.Child` only with the `send` of the Listen work that encloses the call; anywhere else it is S108 (mu5b).
- A machine state may own one piece of work (MU4; [runtime](docs/spec/runtime.md#machines-and-actors) 12): `type Finder machine[Phase, Signal] { initial: start, step: step, work: find }` with `func find(s Phase) Option[machines.Work[Signal, Catalog]]`. The live actor starts the work after the commit that opens the entry and before observers see the state, stops it and waits for it when the entry ends (an interrupted work sends nothing), drops a result of an ended entry and counts it in `Dropped()`, and ends on a work's defect. `machines.Work{Run: f, OnSuccess: g, OnFailure: h}` makes the result of `f` a signal, and `machines.Work{Listen: f, OnFailure: h}` sends as it goes. The checker requires `OnSuccess` unless the result is a signal and `OnFailure` unless every failure is one, and its S108 names the missing map and the function to write; a map that is never called is S108 too. The work's capability row is charged to the machine. `Work` is std `machines.Work`, not a prelude name, so a program may still declare its own `Work`. A `Machine` or `InputMachine` built from parts sets the new field `Work func(s S) Option[func(send func(e E)) needs R]`, `None` for no work.
- Observe and end a machine actor (MU12; [runtime](docs/spec/runtime.md#machines-and-actors) 13): `a.Drain()` closes admission, steps every queued signal and ends; `actor.WaitFor(a, pred)` and `actor.SendAndWait(a, e, pred)` wait for the first matching state from the state at the call, and fail `Stopped` when the actor ends first; `actor.ExitOf(a)` waits for `Finished{State, Output} | Halted{State} | Defected`, or fails with the step's failure that ended the actor, the same for every caller and for `Stop`; `actor.Latest(a)` is the last step's decision; `actor.Select(a.Changes(), f)` drops consecutive equal values. - A program can write files: std `fs` declares a second capability, `fs.Writes`, with `WriteFile(path, text) fails NotFound | Denied | Failed` and `MkdirAll(path) fails Denied | Failed`, and `fs.Host` provides it (batch 9 G4b; [stdlib](docs/spec/stdlib.md#fs) 8-10). `WriteFile` writes a new file beside the target and renames it over the target, so a reader never sees a part; a new file has mode 0666 less the umask and a file that was there keeps its mode. - A program can read files: the new std package `fs` declares the capability `fs.Files` with `ReadFile(path) string`, `ReadDir(path) []string` (sorted names) and `Stat(path) Info`, and its host provider `fs.Host` (std-1 G4; [stdlib.md, fs](docs/spec/stdlib.md#fs)). - `main` can end with a status and a message of its own: the failure `os.Exit { Code int, Message string }` of the new std package `os` (std-1 G2; [runtime.md, Exit causes](docs/spec/runtime.md#exit-causes) 8). - A stop no longer drops a value that a loop or a capability call has already received (#199 stage 5a, [runtime.md I1](docs/spec/runtime.md#i1-interruption-points) rule 2). The rule: an interruption point the compiler inserts never separates a step that delivers a value from the first statement that receives it. A loop's check now ends each iteration, and a `continue` jumps to it; before, it headed the body, so `for v in q.Values() { return v }` could take a value from the queue, see a stop at the body's first line, and lose the value. A capability call's check now comes before its operands; before, it came after them, so `Sink.Put(try q.Pop())` could pop a value and then stop before `Put` received it. A stop that arrives after the delivery stays pending for the next check. The number of checks is unchanged; only their positions move.
- A defect report now names the task where the defect happened, its exact Ergo site, its fork ancestry and the context in force there (#199 stage 4b, [runtime.md G2](docs/spec/runtime.md#g2-fork-tree-defects)). The rule: a defect is recorded once, on the failing task's goroutine, with that task's stack, its chain of tasks (at most 32) and a snapshot of its context values, and the record travels whole through `Wait`, `Stop`, releases and an owner's drain until main reports it. So a report never shows the waiter's frames or the parent's later context, and a dropped typed failure never takes a defect with it. Each task's site is now `FUNC calls task.Go at FILE:LINE:COL`, the form of a call frame, and it stays with a `Task` that moves. After `panic: VALUE` and the failing task's Ergo frames, the report lists the chain from the failing task to `main`, and under the failing task a `context` line such as `trace.span="ingest" log.region="eu"`. Before, the chain came before the frames, the task's Go closure appeared as a synthetic frame, and no context was written. The Go closure around an exit action's block is no longer counted as a repeat (`(2 times)`). A traced run writes the same report, and a `catch` still handles typed failures only. `runtime/rt` adds `Task.Values`, which walks the context bindings in force, inherited ones included, so the snapshot can list keys that no reader names.
- A `with` now builds each provider and registers its release in one masked step (#199 stage 3c, R7 and R8; [resources.md, Context ownership as built](docs/spec/resources.md#context-ownership-as-built) 8). In a `with` that acquires a provider with a `Close`, a constructor that returns a value after a stop arrived still registers it, and its `Close` runs; the stop is observed after the registration. A constructor that fails with a typed error, panics or is stopped registers nothing, and the providers built before it close, last built first, before the `with` ends. A stop that arrives while one provider is built is observed before the next constructor runs. A nested mask of the caller stays in force. An inline context whose entries are explicit provider expressions, `with context { A: openA(), B: try openB() } { … }`, now runs through the same step and the same acquisition facts as a named context; lowering refused every inline context before. Its provider expressions run in the enclosing function, so a `try` failure, `return`, `break` or `continue` there leaves the `with` after closing the providers built so far. A `with`'s footprint now counts each provider it builds, whatever the context's spelling ([rows.md, Footprints](docs/spec/rows.md#footprints)): `with context { W }` counts each provider of W it builds, as `with W` does, so a loop after it keeps its interruption point. It also counts the `Close` of each provider it releases, in every spelling: a function whose only effect is the release of a provider whose `Close` calls a capability now keeps the interruption point of a later loop (it lost it since stage 3b for `with W`). A `with` that acquires no resource builds its providers unmasked, as before. `runtime/v1`'s `Scope.WithClose` is no longer exported: `WithAcquire` is the one registration.
- A resource provider call now requires a checked constructor freshness fact (#199 stage 3b). A function that returns an existing value gets S109 naming #197, and so does a call of a bodiless extern, std or user, since no declaration says what it returns; fresh recursive constructors and fallible constructor results keep their freshness. An exit action may use a plain provider from its `with` when that provider has no acquired resource dependency.
- A `with` now releases the providers it builds when its block ends (#199 stage 3b, [resources.md, Context ownership as built](docs/spec/resources.md#context-ownership-as-built)). The checker records, for each `with`, the providers it acquires in build order, and the checked `Close` of each; an entry shared by several capabilities is one acquisition, and an overridden or unreached entry is not built. Releases run in the environment outside the `with`, so the needs of each `Close` are charged at the `with` and widen no row (S102 when nothing provides them). New errors: calling a capability's `Close` (S108, R24), since its `with` releases it; a resource provider that names an existing value (S109, #197); an exit action inside the block that needs an acquired resource provider of the `with` or one that uses it (S108); a `with` whose value holds a `Task` (S108).
- A written `Close` now runs masked, from its first instruction to its last, on every dispatch path (#199 stage 3a, [runtime.md, Release masks as built](docs/spec/runtime.md#release-masks-as-built)). The checker records which `Close` is a release (R1, R2), and a same-shaped method with another name, or a `Close` with another parameter, stays an ordinary interruptible call. A `Close` with a failure row is a type error. A stop before or during a `Close` or an exit action does not cut it short: its sleeps and queue waits wait uninterruptibly, and the caller sees the stop at its next interruption point after the release. A defect in a release joins the earlier exit and never replaces it. Exit actions and checked `Close` bodies share one mask boundary in `runtime/v1`, which restores the caller's mask depth on every path.
- Blocking runtime calls use one lowering owner and a catalog of waiting policies (#199 stage 2). `LiveScheduler.Sleep` now observes the running task's stop before and during its timer wait. `Wait` retains its owning task after a frame transfer; queue waits use the caller's task, and `Values` binds that task when iterated. `Stop` still drains uninterruptibly. Interruption stays outside typed failures, and these bindings add no extra call-site poll.
- A stop now reaches impure loops and recursion (#199 stage 1, [runtime.md I1](docs/spec/runtime.md#i1-interruption-points)). The checker infers each frame's footprint, what it runs rather than what its row names ([rows.md, Footprints](docs/spec/rows.md#footprints)). An impure frame checks its own task before each capability call and once in each loop iteration, including every `continue` path (stage 5a moved the loop check to the end of the iteration and the call check before the operands). A host call such as `xs.Append(1)` counts as opaque for now. A nonrecursive impure frame with a transparent footprint has no entry check. Pure frames have no checks, so their loops and recursion cannot be stopped until they end.

- Latch handoff now means the same on Go and JavaScript under `ef test` and the Go `TestScheduler`, and in every JavaScript execution (#142). `Sync.signal` makes every parked waiter runnable and returns, and the signaller keeps its turn; each waiter resumes later on its own turn. On JavaScript the waiter used to run inside the signaller's `signal` call, so interrupting the signaller right after its signal interrupted it mid-signal, and a waiter had already run before the signaller could interrupt it. On Go a scope close (a `scope` block, a fiber's exit or layer shutdown) handed off the turn before it cancelled the scope's children, so a child already woken by a signal could occasionally run and act after its owner began closing; the close now cancels while it still holds the turn. Now interrupting the signaller after `signal` returns cannot affect a waiter it does not own, and a signalled waiter interrupted before it runs, directly or by its owner's close, ends interrupted. Live Go, without the test scheduler, has no turns: a waiter runs on its own goroutine, possibly in parallel with the signaller, and an interrupt sent after `signal` races with it. The JavaScript `Latch` is now Effect's `Latch`, whose `open` resumes waiters from a dispatcher task; under the `ef test` harness on Bun the measured cost is within noise.
- `Scheduler.awaitRegistration()` under `ef test` now returns at quiescence, with the same meaning on Go and JavaScript: no managed fiber is running or runnable, and a fiber that has been signalled, fired or cancelled but has not run again is not idle. It used to wait for a timer registered since the last barrier. JavaScript then hung when forked work finished before its timeout timer started, and both targets hung after a fork that registers no timer, such as a pure value. On Go it could also return as soon as one fork registered a timer, before sibling forks had run. Forked work that already completed now passes the barrier, as does work whose timeout timer was cancelled. Interrupting a fiber parked at the barrier is an ordinary interruption on both targets, and when several fibers wait at once their release order is unspecified.
- `Scheduler.advance` selects each deadline at the same quiescence. On JavaScript, advancing straight after a worker signals readiness used to commit the target before the worker registered its next sleep, so that sleep never fired. On Go, a sleeper or latch waiter woken by an interrupt or a scope close was briefly invisible to adjustment and to the barrier.
- The Go and JavaScript layer runtimes share build-owned layer entries: one producer per selected node, and dependents and waiters observe one terminal outcome. Cancelling a waiter abandons only its own wait; it never interrupts the producer (unlike Effect's `MemoMap`, whose first requester owns the build, which the conformance table lists as a difference). Dependent-first shutdown attempts every finalizer.
- The HTTP transport enforces explicit body, read-header, read-body, idle and admission limits. It answers 413 for declared and chunked oversize bodies, 400 for malformed framing, 503 for admission and shutdown, and an empty 500 for failure, defect, cleanup failure or an invalid response (Content-Type outside visible ASCII, space and tab). Each request runs in a scope linked to client disconnect and server cancellation, and the response is written only after that scope closes. Shutdown stops admission, cancels and joins request scopes, then gives responses still being written the idle timeout before aborting them. Admission rejects at the cap and never waits, so a sequential client may observe 503 while its previous response is still being handed off ([runtime](docs/runtime.md)).
- On JavaScript a malformed request's connection is closed once its 400 or 431 is written, so a client that keeps its side open cannot hold shutdown open on Node or Bun. A parser error preempts an unwritten pipelined response (a documented host limit).

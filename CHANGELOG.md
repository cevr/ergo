# Changelog

Entries describe user-visible changes and are true at the commit that carries them. The layout follows Gleam's: one `## Unreleased` section with headed groups, newest work first within a group. Codes such as EF111 are compiler diagnostics.

## Unreleased

### Breaking changes

- Only code whose row holds the new prelude capability `Ambient` makes a host provider, and only the entry provides `Ambient` (host-authority H1; [stdlib](docs/spec/stdlib.md#host-packages)). `fs.Host` and `os.Host` were zero-field records, so any function made one and read the disk or the environment with an empty row: `fs.ReadFile(fs.Host, p)`, `with context { fs.Files: fs.Host } { … }`, and a `test` that did the same all checked and ran. Each host provider now has an unexported field, and its package exports one constructor, `func NewHost() Host needs Ambient`. `fs.Host` as a value, `fs.Host{}`, `let h fs.Host` and a record update of it are S114 "fs.Host has an unexported field, so only package fs builds it; use fs.NewHost". A call of `fs.NewHost()` where no row holds `Ambient` is S102: in an exported function or `main` that does not list it, in a `test`, a package-level `let` and a named context; an unexported helper's inferred row carries it to its callers. `Ambient`'s one operation is unexported, so `with context { Ambient: Fake } { … }` is S106. A program writes `func main() needs Console | Ambient { with context { fs.Files: fs.NewHost(), os.Process: os.NewHost() } { run() } }`; a package-level `let Live = context { fs.Files: fs.Host }` becomes a local context in `main`. A function that takes a host provider or a capability value as a parameter needs nothing. The entry's S109 for another capability in `main`'s row now reads "the host provides only Console and Ambient". The prelude's `LiveScheduler` follows in H2.
- A user `extern go` binds only a package of the pure allowlist: `math`, `slices`, `sort`, `strconv`, `strings` and `unicode/utf8`, by exact import path (wave std-1, G9; [grammar](docs/spec/grammar.md#declarations), Extern). Any other Go package may reach the host, and an extern has no `needs` row, so `extern go os.Getenv func Getenv(k string) string` built and ran with a hidden effect. It is now S109 at the declaration: "extern go os.Getenv reaches the host; wait for std os.Process or #202" (std `os.Process` is the coming host capability, wave std-1 G2). `time.Sleep`, `fmt.Print`, `math/rand/v2.IntN`, `runtime.GC` and pure packages outside the list such as `math/bits`, `unicode` and `cmp` get the same S109. Std's own externs are not under the rule. The list is the one that std's purity fact (G5b) uses for the imports of a pure Go body.
- A law stands at top level, beside `test`: `law AddCommutes(a Money, b Money) { add(a, b) == add(b, a) }` is checked with a member law's rules and its parameters, then the package, in scope, and no build contains it (law-top; [types](docs/spec/types.md#laws)). A type with laws and no operations is S108 "T has laws and no operations; write it as a top-level law: law X(…) { … }"; a top-level law with type parameters is S001; top-level laws and tests share one namespace.
- A capability row is written with `|`, as an error row is (196n; [#196](https://github.com/cevr/ergo/issues/196)): `func Checkout(id string) Receipt fails NotFound | Declined needs Orders | Payments { … }` and `let Live = context provides Orders | Payments { … }`. The same row needs no parentheses inside a parameter list: `func g(h func() needs A | B)`. A comma between the names is S001 at the comma, "a capability row separates its names with |: write needs A | B", and a parenthesised row is S001 at the `(`. `with E, F`, a context entry's keys, type arguments and parameters keep their commas. The checker prints rows in messages with `|` too, error rows included (`{NotFound | Declined}`).

- The construct that binds services to providers is spelled `context` (196w; [#196](https://github.com/cevr/ergo/issues/196), [preview](docs/previews/2026-11-02-wire-to-context.md)): `with context { Store: Mem{} } { … }` and `let Live = context provides Orders needs Config { … }`. `context` is a reserved keyword in place of `wire`, which is now an ordinary identifier: an old `wire { … }` gets the plain diagnostic any stray name gets, with no rename hint. Go's `context` package is imported under another name, `import go gocontext context`; `import go context` is S108, "context is a keyword; import the package under another name: import go gocontext context". The glossary terms are Context, Context exposure, Inline context and Named context; a context value keeps its name and is a value in the context. The network sense of wire (wire formats, wire keys of a codec) is unchanged.
- Std calls run under `ergo run` (check-v1 stage D3b; [#196](https://github.com/cevr/ergo/issues/196)):
  - `task.Go`, `Wait`, `Stop`, `scope.OnExit`, `queue.New`, `Push`, `Pop`, `Close`, `Values` and `slice.WithCapacity` call their `runtime/v1` bodies with the hidden frame scope, call site and task. `Push`, `Pop` and `Values` take the caller's task, so a stop reaches a task waiting on `Pop`; a `catch` arm `case queue.Closed:` matches the queue's failure, and exit actions run after the body in reverse order.
  - A function that returns a `Task` moves it to its caller's scope, through a direct call and through a function value. A result that holds a `Task` inside another type, or a `Task` passed as a type argument, is refused at build with S109 naming check-v1 stage E.
  - Every lowered function takes the environment, which carries the running task; the shared empty environment is gone. An operation of a capability or of the program's operation type takes the task first.
  - `"\(v)"` runs for a value of a basic type (string, bool, the integer and float types, duration) and prints it as Go's `%v` does; a value of any other type is refused at build with S109 naming check-v1 stage E.
  - An operation called through a borrow of an operation type, `p.Close()` with `p *queue.Queue[int]`, is S108 "an operation type is already a reference; call it on the value".
  - A method value of an operation, such as `q.Push` of a `queue.Queue` or `s.Area` of the program's operation type, runs: it evaluates its receiver once, where it is made, and calls the operation with the task of the code that calls it. A Seq from `q.Values()` waits with the task that iterates it, so stopping that task ends the wait even when another task made the Seq. The block of `task.Go` is bound once, where `task.Go` is called.
  - Operands run left to right, each once, also when a later operand takes a method value or a later part of `"\(…)"` calls: `use(10 / zero, ss[0].Area)` and `"\(10 / zero) \(f(ss[0]))"` fail with integer divide by zero, not with the later index out of range. A generated test puts each kind of expression that runs code (method value, call, Task wait, interpolation, try, catch, if, match) after a failing operand in call arguments, record, tuple, slice and Map literals, `+` operands and interpolation parts.
  - A block with no value runs as a type argument: `task.Go() { work() }` starts, and `t.Wait()` returns nothing. A declared generic function called with such a block runs too. A no-value type argument in any other position, such as a declared generic type, is refused at build with S109 naming check-v1 stage E.
  - `timeout.After` is still refused at build with S109, now naming lower-v1 (a `runtime/v1` body for `timeout.After`): its Go body is in `runtime/rt` and takes a timer factory, not the Ergo `Scheduler`.

- The checker enforces stage D3a of the v1 checker, and every form it admits that holds no std call runs under `ergo run` ([#196](https://github.com/cevr/ergo/issues/196); check-v1):
  - A refused defined type stays invalid at every use, including capability and failure rows, capability selectors, context entry keys, constraints and match patterns. An unused refused import alias adds no unused-import diagnostic. A Task assignment that also lacks an operation names that operation first. A refused entry of a list, such as a `needs` or `fails` row, type arguments, a tuple type, union variants, a context header, parameters or record fields, stands as invalid and the valid entries stay: `needs DStore | Log` then `Log.Put()` reports the definition only, and a written row that holds a refused entry accepts what escapes from or is charged to it. A `catch` arm whose type test names a refused type proves nothing, so it adds no totality error. A two-element tuple call returned into a tuple needing element conversions names a destructure-and-return repair with unbound names, `let (m, n) = pair(); return (m, n)`, with the call's source copied byte for byte; the exact text checks in place of the body. There is no repair for `return try pairF()`, for other arities, or for a call written over more than one line. The Task use rules now state transparent wrappers, dot-call arguments and the two refused examples (reassignment and capture by an immediately called literal); generic type-parameter arguments remain a stage E carry.
  - The prelude's `Append`, `Get` and `Delete` are functions on slice and Map types: `xs.Append(x)` takes one element, `m.Get(k)` returns `Option[V]`, `m.Delete(k)` returns the Map. They are reached only by the dot form on a value of exactly an unnamed slice or Map type; the bare call `Append(xs, x)` is S104 naming the dot form. A defined slice reaches `Append` after assignment, `let raw []int = xs`, then `raw.Append(1)`; a defined Map follows the same rule. The suggested repair uses an unbound name (`raw`, then `raw2`, …) and checks clean. They are names in no scope, so a package declares its own `Get`.
  - Which value goes where is one relation, Assignability, with Go's clauses in Go's order: identical types; identical underlying types when at least one side has no name (a basic type and a type parameter have one); an operation type the value implements; a union that lists the value's variant or row; a function type whose rows are no wider, when one side has no name. So `let raw []int = named` and `let named Ints = raw` cross without a conversion, a `Count` defined over `int` that implements `Store` assigns to `Store`, and two distinct named types over one type, `Count` and `int` included, cross by no clause. Each clause names the implicit conversion it makes, which `Info.Implicit` records at the value and the new `Info.ImplicitElems` records per element of a multi-name `let` (additive); the lowering reads that fact and derives none. A diagnostic names a conversion only where one exists, in the package's own spelling, and each repair it names checks clean when written back. A conversion of an invalid operand adds no diagnostic.
  - A defined type is over a basic, slice, Map, function, tuple or record type (a record instance and a variant are records). One over an operation type (`Task` and the std operation types included), a union or an instance of a generic union is one S108 at the definition, naming the type to use directly; its uses add none.
  - A literal of a defined slice or Map type, `Ints{1, 2}`, elided element literals included, lowers as Go writes it; the build refused it as "not a record literal". A generated test checks every pair of 44 kinds of types at 26 sites (assignments, writes, aggregates, joins, a pattern's written type, the operands of `==` and `!=`, and a context literal): each admitted pair runs, each refused pair has one diagnostic on its line, and an admitted context literal meets the one lowering refusal that waits for stage E. Its model of Assignability includes clause 5's needs row.
  - A dot call `x.f(…)` of a generic function whose first parameter `x` binds some type parameters runs: `Info.Calls` holds every type argument, the receiver-bound ones included, and no longer produces `CallPrelude`.
  - An import alias is only for a name clash: `import t timeout` with no other `timeout` in the file or package is S108 "an import alias is only for a name clash; write import timeout"; `_` follows the same rule. An unaliased clash with a package-level declaration is one S108 naming the alias to write. An alias that itself clashes with a package declaration gets one S108 naming another alias. A duplicate import binding adds no alias-rule or unknown-name cascade.
  - A `Task` leaves its function only by return, with S108 "a Task leaves its function only by return; wait on it or return it". A type holds a `Task` when one is in its structure (a type argument, a declared body, an element, a field or a variant); recursive types terminate, and the walk is linear in the declared types, so recursive generic types whose arguments grow at each level reach the S108 instantiation-cycle diagnostic. A Task-holding type is only the whole type of a local, a parameter or a result: as a slice or Map element or key, a tuple element (several results included), a pointer's element, a record or variant field, a defined type's base or a package `let`'s type it is refused. A Task-holding value is only bound by a local `let`, returned, passed as an argument, or the receiver of a called `Wait` or `Stop`: a discarded one, `_ = t`, `let _ = t`, a reassignment, a method value `t.Wait`, a borrow, a composite literal's part and an assignment into an operation type are refused, and so is a read of a Task-holding local from another frame, a function literal, a trailing block or the block of `task.Go`. A refused type covers the values assigned to it: one mistake, one diagnostic. `Info.TaskResults` names each function whose result holds a `Task` (additive).
- The checker enforces stage D2 of the v1 checker, and every form it admits runs under `ergo run` ([#196](https://github.com/cevr/ergo/issues/196), one `for`; check-v1):
  - `for` iterates four domains: a slice, a `Map` (one name binds the value, two the key and the value), the prelude's new `Range[T]` and the prelude's new `Seq[T]` (one name each). A string, an integer, a pointer or any other domain is S108 with the Ergo form to write, such as `for i in 0..len(s)` or `for x in *p`.
  - `a..b` is a `Range[T]` value for one integer type `T`, also outside a `for`; non-integer operands are S108.
  - `Seq[T]` is `func(yield func(v T) bool)`: convert a function to it, `Seq[int](f)`, and loop over it; a `break` makes `yield` return false. The std `Queue` gains `Values() Seq[T]`.
  - A single-name `for` binder follows the one binder rule of `let`, with the same message. A refused binder or domain is one diagnostic: its names add no S110.
  - A `for` over a `Map` that the body changes follows Go: each entry present at the start is visited at most once, an inserted entry may or may not be visited, and a deleted entry not yet reached is not visited.
  - A Map read `m[k]` is S108 "a Map read may miss; write m.Get(k), which returns an Option"; a Map write `m[k] = v` runs.
  - The default of a `Map` is an empty, writable `Map`: a `let` with a `Map` type and no value, a field a record literal omits, and a `Map` inside a defaulted record or tuple, named or not, a generic instance included, at any depth. A write to it runs; the lowering never writes Go's nil map. Each defined type or instance whose default holds a `Map` gets one generated Go function that builds it, so a deep or shared record graph costs work and output linear in its types, and two defaults never share a `Map`.
  - `len` is the only built-in function; it takes a slice, a `Map` or a string, and neither `len` nor an index sees through a pointer: write `len(*p)`, `(*p)[i]`.
- The checker enforces stage D1 of the v1 checker, and every form it admits runs under `ergo run` ([#196](https://github.com/cevr/ergo/issues/196), 196v; check-v1):
  - An assignment `x = e` or `x op= e` needs a target rooted at a `let mut` local, directly or through fields and indexes; a target rooted at a call's result or a literal is S108. A parameter, a `let`, a pattern, `as`, `case err:` or loop binding and a package-level `let` are immutable (S108, "declare x with let mut"). A borrow `&x`, or a call `x.f()` of a function that takes `*T`, needs a `let mut` root too; a write through a pointer does not. A `let mut` that is never reassigned is S110 "n is never reassigned; write let n"; a reassignment inside a refused literal (a struct field value that elides its type) still counts. A struct literal's value never elides its type: an elided literal there is refused on every route (a field, an extra positional value, an unknown field, a key that is not a name, a field set twice, a generic record whose type arguments cannot be inferred), and names inside it are not resolved.
  - `let x` with neither a type nor a value is S108; a package-level `let mut` and `let mut` over a pattern are S108.
  - No shadowing: a binder that reuses a name bound in an enclosing scope of the same function is S108 at the inner binder. Sibling scopes may reuse a name.
  - A prelude name (`int`, `len`, `Map`, `ordered`, `Option`, `Clock`, `Console`, …) cannot be redeclared at any scope: S108 "X is a prelude name, which cannot be redeclared; choose another name".
  - A call, from a later component, of a function the checker refused for its pinned row (class G) keeps its written signature, so an arity or argument mistake is reported. Each inferred row its body exceeded is unknown; a written row, and an inferred row that stayed empty, keep their value, so a function refused only for its capability row still has its written error row checked at every call. An unknown row also accepts any row assigned, joined or passed into it, also nested in a parameter or result type, with no diagnostic, and an `if` join, a generic argument or a trailing block keeps the failures and capabilities the other value is known to have. An unknown row makes every row it reaches unknown, through calls, locals, generic instances, catches and inferred rows. The checks that hold only when a row lacks something (try or catch on an expression that cannot fail, a type not in the caught row, an unreachable rest arm, a bare generic arm with no instance, a return of no value) add no follow-on there, and the checks that an error is present (an unhandled failure, a catch that does not handle a type, a type caught twice, a row a declared row does not list) still report on the rest of the row. A function literal or trailing block that calls it makes only a call of the literal unknown: the checks on the call the literal is passed to still report, and a written error row stays definite.
  - Same-named functions on a type declared twice: the group's verdict does not depend on which declaration comes first.
- The checker enforces stage C of the v1 checker, and every form it admits runs under `ergo run` ([#196](https://github.com/cevr/ergo/issues/196), 196r; check-v1):
  - A body yields its last expression: a function, an `if` or `match` arm, a `catch` arm and a trailing block; `return e` leaves early and means the same. A fallible tail's failure escapes, as `return f()` does. A body that needs a value and ends in a statement is S107 at its closing brace.
  - `if` and `match` are expressions: `let s = if c { 1 } else { 2 }`, `1 + match p { … }`, an argument, a tail. With an expected type every branch takes it; without one the branches have the first branch's type and never join into a union. A value `if` without `else` is S108. A branch that ends in `return`, `break` or `continue` joins any type.
  - One `catch`: arms are match arms over the failure. `case Declined{Reason: r}:` handles a type only when it matches every value of it; `case err:` binds the row value of the failures the earlier arms leave, which can be returned, matched or assigned to a declared union that lists each of them; `case _` handles the rest. An arm after `case err:` or `case _` is S108.
  - `try` covers the whole expression to its right: `try a() + b()` propagates both failures. A `try` over a catch that handles the whole row, with nothing inside it that propagates, is a redundant `try`, S108.
  - One statement-position rule, for a statement and for the tail of every body with no result (an `if` or `match` arm, a `with` block, a trailing block, a `catch` arm): a call, `try`, `catch` or `with` has its result discarded whatever its type; a pure value (a literal, a name, an operator or a conversion, by any spelling of its type: `int8(n)`, `N[int](n)`, `pkg.T(x)`) is S110 "this value is not used". An arm with no work is empty. A `with` whose value is used reports a path without a value as S107 at that path. A fallible tail of an `if` or `match` branch in value position passes its failure to the enclosing `catch` or `try`, as a `with` block does.
  - `break` and `continue` inside a `match` act on the enclosing `for`; outside a `for` they are S108.
  - Comparability is structural: a union compares only when every variant does, and a row value or an operation-type value never compares. `==`, tuples, record fields, `comparable` constraints and map keys all follow it, so a checked program never panics with "comparing uncomparable type". `Map[any, …]` is S108.
  - The lowering now runs every stage B form: record, nested, constant, tuple, `as` and several-subject patterns, `let` destructuring (package-level too: the initializer runs once, before every binding), tuples and defined types (a defined error type has its own `Error` text; a constant of a defined `bool` or `string` type keeps its type). Unnamed parameters (`func M(S, int)`), and every operations conversion lower too: from a record, an instance of a generic record (`G[int]`) or a pointer to either, to an operation type or an instance of a generic one (`A[int]`, `B[int, string]`). A total match whose value Go needs has a default arm that panics with a named defect, never a zero value. Each call of the source keeps its Ergo identity in the program's call table, `ergoCalls` (#230); a defect that escapes `main` is reported with its Ergo call chain from that table (`pick at main.ergo:2`, `middle calls pick at main.ergo:7:2`), never Go frames; only Go's fatal errors (a stack overflow, out of memory, concurrent map writes) still print Go's own report. Every program registers its declaration and call tables, even with no call; package-level `let` initializers run inside the root task in Go's initialization order, so a defect in one is reported the same way. The frame that panicked is always written `F at file:line`, even when its line holds a call or it recurses, and every reported line is exact: operations that can panic carry an inline `/*line*/` directive and each Go line repeats its statement's directive.
- The checker enforces stage B of the v1 checker ([#196](https://github.com/cevr/ergo/issues/196), 196p and 196t; check-v1):
  - A record with no fields is written bare: `return Pending`, `Runner.Each(f)`. `Pending{}` is S108 "a record with no fields is written bare: Pending", and a bare name of a record with fields is S108.
  - A type's members decide its kind. A union's variants are records of the package, named bare or declared inline (`type Payment = Pending | Declined{ Reason string }`); an inline variant of a generic union takes the union's parameters its fields mention. A variant from another package is S109 naming 196b. `type Celsius float64` defines a nominal type.
  - `match` takes a subject of any type and checks the full pattern language: names that bind, constants, type tests, nested record patterns, tuples and `as`. A match must be total over a union's variants (nested), `bool`'s constants and tuples, and constants of other types never cover (S103 names one missing pattern). A case the cases before it cover is S108. `case A as e, B as e:` is S108: every pattern of a case binds each name with one type.
  - Unreachable cases include a final `case _`; duplicate constant arms name the earlier pattern. Pattern proofs share a deterministic budget for work and allocated cells, proportional to written pattern nodes and subjects. Unwritten fields are implicit wildcards; sparse rows and memo keys keep them implicit. A proof over its budget stops with S103.
  - `let` and `for` destructure with irrefutable patterns; a partial one is S103 ("use match"). A single-name `let` follows the binder rule: it may reuse a package function or value, a known type still tests, and prelude names remain protected (`let true = false` is S108). A refused pattern name still binds a placeholder, so later uses add no diagnostic. A type test may name the subject's own union type.
  - Tuples are values and types: `func DivMod(a, b int) (int, int)`, `return (q, r)`, `let (q, r) = DivMod(7, 2)`. A call is one value, so `f(g())` no longer spreads `g`'s results.
  - `T(x)` converts only between numeric types, between `duration` and `int64`, and between a defined type and its base. `string(65)` is S108 with the fix `"\(n)"`; two defined types convert through their base.
- The checker enforces stage A of the v1 checker ([#196](https://github.com/cevr/ergo/issues/196), 196u; check-v1):
  - Ergo has no untyped constants. A literal takes the type its context expects (a written `let` type, a parameter, a result, a field, an element, the other operand, an assignment's target), else its default: `int`, `float64`, `rune`, `string` or `bool`. An integer literal may take an integer or float type, a float literal only a float type. `let c int = 2.0` and `1 + 2.5` are S108 (write `1.0 + 2.5`). A named constant has one type and never converts by itself (write `int8(Limit)`). A constant expression is evaluated exactly, and an overflow of its typed result is S108 (`let y int8 = 200 - 100` is S108 at `200`): each typed step must fit. A literal fits its type after its sign, in parentheses or not (`-(128)` is an `int8`).
  - A conversion gives a literal operand no expected type, so `float64(1 << n)` shifts an `int`. A shift's left literal takes an integer context, else `int`; a float context is S108, which says to write `int(1) << n` and convert the result. Go's untyped shift rule is gone.
  - Go's built-in functions that Ergo drops (`append`, `delete`, `make`, `new`, `cap`, `copy`, `close`, `clear`, `print`, `println`, `min`, `max`, `panic`, `recover`, `complex`, `real`, `imag`) are S104, each with the Ergo form to write, such as `xs.Append(x)`.
  - Diagnostics speak the decided language: `fails` rows (never `error[…]`), `let` (never `var`), `match` and `case _` (never `switch` or `default`), `Map[K, V]`, records `{ F T }` and unions `A | B`. A recursive group's message names the row to write: "write its error row: func f(…) T fails …", or its capability row with `needs`.
  - A node the decided parser never builds is S109 "not produced by the decided parser", never a panic.
  - A call of a constant, `1()`, `""()` or `K()` with `let K = 1`, is S108 "cannot call …". The checker accepted it before.
  - `s == m`, where `s` holds an operation type and `m` is a record that satisfies it through its functions, is S108 "cannot compare …". The checker accepted it before.
  - A removed built-in reports one S104: `new(int)` no longer adds "int is a type, not a value".
  - Two own entries for one capability in one context are S111 even when they are `replace` entries: `context { replace Store: a, replace Store: b, Base }` reports "Store has a second entry in this context, entry 2; the first is entry 1". The checker accepted two replaces before and bound the first. A capability written twice in one entry, `context { Store, Store: Mem{} }`, names its two keys: "Store is listed twice in entry 1, as its keys 1 and 2".
- Sources use the decided syntax of [#196](https://github.com/cevr/ergo/issues/196) and end in `.ergo` ([#221](https://github.com/cevr/ergo/issues/221)). Every command refuses any other extension, `.ef` included, with `source file must have .ergo extension`. The grammar is [docs/spec/grammar.md](docs/spec/grammar.md). What stopped parsing:
  - The Go spellings: the package clause, grouped and quoted imports, `:=`, `var`, `const`, `struct`, `interface`, receivers, `(T, error)` results, `switch` and type switches, `default:`, `go`, `defer`, channels, `select`, `map[K]V`, `++` and `--`, three-clause and `range` loops, variadic parameters, fixed arrays, labels, `goto` and `fallthrough`. Each is S001 with a message that names the Ergo form (`let`, `type Name { … }`, `T fails E`, `match`, `case _:`, `task.Go`, `scope.OnExit`, `Map[K, V]`, `for x in xs`, …).
  - The old Ergo spellings: `error[…]` rows, `wire Name { A = x }`, `catch e { … }`, bodiless functions with `//ef:go`, `uses` and `try` in operand position. Each is the plain S001. Tests are `test Name { … }`, laws `law Name(…) { … }` and contexts `let W = context { A: x }`.
  - Record members and context entries are separated by commas, which a line break does not replace. In a context, a comma run of names ended by `:` is one entry's key list on one line or several, so an embedded context is written after the entries. `ergo fmt` writes `with (W) { … }` as `with W { … }`. Its identity (`formatterVersion` in `ergo fmt --json`) is `ergo-2026/formatter-2`.
  - `scripts/migrate196` translates one old-syntax file into the decided syntax. It is a one-off and goes after v1.

  - `ergo build --receipt` and its application receipt are removed.

- The language is renamed Ergo (owner, 2026-10-27; [#218](https://github.com/cevr/ergo/issues/218)). The CLI is `ergo` (`cmd/ergo`, built as `bin/ergo`), the manifest is `ergo.json` (formerly `effra.json`), the Go module is `ergo.local/prototype`, edition and tool identities are `ergo-…` (formerly `effra-2026/formatter-1` and the like), bundled modules are `ergo/…`, the runtime package is `runtime/ergo`, the MCP server and LSP language id are `ergo`, environment variables are `ERGO_*`, the lint suppression directive is `ergo-lint-disable-next-line`, and links point at `github.com/cevr/ergo`. The `.ef` extension, `//ef:go`, and the `EF` and `EFMT_` codes keep their spelling until #205. Entries below describe their changes under the old name.

Both header clauses parse and format; the bridge refuses them with S109 until #196 checks them. The language has 28 keywords. The legacy edition keeps `uses { … }`.

The JavaScript emitter, `--entry`, running programs and tests with Bun or Node, the JavaScript receipt, and the `js` target in the CLI, MCP, LSP and lint manifests are removed. `--target js` is now the EF110 diagnostic `unsupported target js; the only target is go`. - The repository no longer has a Node toolchain: the root `package.json`, `bun.lock` and `node_modules` are gone, and the gate needs only Go and Git. The pinned Effect upstream checkout (`conformance/upstream/effect`, `.gitmodules`, `scripts/init_upstream.sh`, the manifest and the `import` step) and `conformance/framework-ports/` are removed; there is no exact Bun version requirement. `conformance/effect-cases.json` keeps each case's upstream file, line and label as provenance text, and `go run ./scripts/conformance check` validates it without a checkout, with Go-only evidence tests. - `enter`, `stay`, `ignore`, `reject` and `done` are reserved for machine decision forms. A function, parameter, local or declaration with one of these names is now an EF002 parse diagnostic that names the decision form; rename it. They stay legal as explicit field labels (`done: bool`, `Todo { done: true }`, `todo.done`), so wire keys such as `"done"` keep working, and as qualified host members (`sdk.done`); only shorthand `{ done }` is refused.
- An unhandled failure at `main` now writes the same entry failure report on Go and JavaScript: one stderr line per cause reason, such as `failure: AssertionFailed { message: "expected \"b\"; received \"a\"" }`, `defect: "..."` or `interrupt`. Go used to print only the failure tags, and JavaScript printed a host object dump that kept only the first reason. The exit status is 130 when every reason is an interruption, including a SIGINT or SIGTERM, and 1 otherwise. `ef run` forwards those signals and passes the program's report and status through without adding `exit status N`. Payloads are rendered from the checked types of `main`'s failure row, so the report is identical for every failure in that row that both targets can raise, including built-in, codec and HTTP listener failures. The one exception is an unclassified HTTP listener failure, which keeps the host's text. A record field named `_tag` stays ordinary data. A Go `Timeout` failure no longer carries a payload, which matches JavaScript. Built-in diagnostics now read the same on both targets: `Assert.equalText` quotes both sides with the report's string rule on Go and JavaScript (Go used `%q`, JavaScript `JSON.stringify`), and using `TestClock` or `TestScheduler` outside `ef test` raises one defect message on both, such as `test clock requires the ef test harness`. The full grammar is in [the design](docs/design.md#entry-failure-report).
- `Http.listen` checks its address before the host sees it, and reports listener failures in Effra's words on both targets. An address must be `host:port` with a decimal port from 0 to 65535 and a bracketed IPv6 host. Go used to accept service names such as `:http` and an empty port, and JavaScript raised a defect for an address without a colon. Both now fail with `IoError`, such as `invalid HTTP address "bad": missing port`. A failed listen reads `HTTP listen on "ADDRESS": address in use` (or `address not available`, `permission denied`, `host lookup failed`); any other listener failure keeps the host's text. The rules are in [the runtime guide](docs/runtime.md#http-server).
- A declared Go import the generated program cannot import is now refused by `ef check` with EF111 at its import declaration, whether or not any call uses it. The rule is the Go command's: a `main` package, a vendored package (any non-final `vendor` element; a package whose path merely ends in `vendor` is an ordinary package), and an `internal` package whose parent tree does not contain the generated main package. Every standard-library `internal` package is refused. Such imports used to pass `ef check` and fail later in `ef build` with a raw Go error.

An explicit Go import declares a runtime initialization dependency as well as host declarations, so the package's `init` functions and variables run before `main` or the test harness. Pruning still removes unreachable callers, bindings and helpers, never that initialization. Delete the import to drop the initialization. `ef check` and MCP `project.check` report each mode's `goInitialization` packages and whether they lower as a named or blank import.
- `GoHttp` is now `LiveHttp`.
- `Http.serve(address, handler)` and the `Handler` shorthand are removed. Use `Http.listen(address, HttpLimits, handler)` with an effectful `HttpRequest -> HttpReply` handler (`HttpHandler`). `Handler` is an ordinary user name again, and a call to `Http.serve` is EF102 on Go and JS. Paths keep their percent-encoding and failure bodies are empty.
- A declaration named like a builtin Http type (`HttpRequest`, `HttpResponse`, `HttpReply`, `HttpLimits`, `HttpHandler`) is EF101 once the program refers to the global `Http` or `LiveHttp`. Until then every one of these names is free for your own data and an ordinary type on Go and JavaScript, including `HttpHandler` (a `record HttpHandler` is declared, used in fields and signatures, constructed and built like any record). Without a declaration of your own, `fn f(h: HttpHandler)` is EF102 (unknown type) until the program refers to Http. A local value or row parameter named `Http` or `LiveHttp` is not a reference.
- Every generated JavaScript executable entry now interrupts `main` on SIGINT and SIGTERM, including programs that do not use Http. An interrupted run reports the interruption on stderr instead of dying from the signal. Library emission installs no handlers.
- `effra.bindings.json` is validated strictly. Each contract key must be the go/types full name of an exported function or method in the package it names (that package is loaded for the check even when the source does not import it), otherwise EF111, one diagnostic per key, sorted, with near misses from the same package. A key for an unnamed interface's method (`(interface).M`), which Go spells identically for unrelated declarations, is refused as ambiguous, and so is a package pattern such as `std`, `./...` or `all`. A refused key is never applied to a binding. Keys that used to be silently ignored now fail the check.

### Language and compiler

- A named context that embeds a context of an imported package now has the footprint it would have if that context were declared in its own package (batch-9 C4; [rows](docs/spec/rows.md#footprints)): the imported context's recorded footprint, or, when a `replace` hides some of its entries, the footprint of each entry it still runs, read with its own package's facts. Before, such a context was opaque, so each `with` of it placed more interruption points than needed.
- A function is pure by its own package's facts wherever it is declared (batch-9 C3; [stdlib](docs/spec/stdlib.md#pure-bodies)). A std function with an Ergo body, such as `strings.Cut`, and a function of an imported user package now compile to plain Go functions with no hidden environment argument when their bodies are pure, and so do their callers: `func halves(s string) string` calls `strings.Cut` with no environment. Before, any call of a function of another package kept the environment. A function that calls an impure function of another package, at any depth of the import chain, keeps it.
- An importer may wrap the `*check.ImportError` it returns (`fmt.Errorf` with `%w`, `errors.Join`, at any depth), and the S104 "unknown package" diagnostic still carries its reason (batch-9 C2). Before, only an unwrapped `*ImportError` gave the reason. The search ends on a custom `Unwrap` with a cycle.
- `check.Check` lists the diagnostics of a package of several files in one order, whatever order the caller lists the files in: by the canonical order of the files (name, then key, then text; `check/canon.go`), then offset, length, code and message (batch-9 C1). Before, the list followed the caller's index of each file, and two diagnostics at one offset were not ordered by length. Each diagnostic still names the caller's index of its file. `ergo check` and `ergo diagnostics` give the same output as before, since the loader lists files by name and the report sorts again.
- A program value now converts to a std operation type that no std extern returns (wave std-1, G2; [stdlib.md, os](docs/spec/stdlib.md#os) 5). Before, every std operation type outside the prelude was sealed, so `context { os.Process: os.Host }` was S109 "it is a sealed std protocol". The rule is now one predicate, `check.SealedStd`, that the checker and the lowering share: a std operation type is sealed only when the result of a std extern names it. `queue.Queue` (from `queue.New`) and the prelude's `Task` (from `task.Go`) stay sealed, with the same S109; `os.Process` is open like `Console` and lowers as an interface of the program.
- A function whose only calls are calls of pure std bodies (`strings.ToUpper`, `strconv.Itoa`, a caught `strconv.Atoi`) is now a pure function: it compiles to a plain Go function with no hidden environment argument, as `func shout(s string) string`, and its callers pass none (fu-lower; [stdlib](docs/spec/stdlib.md#pure-bodies)). It kept the environment before, though its footprint was already empty. A call of a std function with an Ergo body, such as `strings.Cut`, and of a user `extern go` still keeps the environment. A std extern whose `runtime/v1` body `v1.BodyOf` cannot read now stops the build with an internal compiler error that carries BodyOf's error.
- A context of an imported package can be embedded and built (196b U4; [rows](docs/spec/rows.md#context)). `context { lib.W }` embeds the exported named context `W` of the imported package `lib`, as a bare name embeds a context of the package, and a `replace` may override what it binds: `let Declining = context { Live, replace payments.Payments: memory.Decliner }`. An unexported or a missing context of `lib` is S104 "lib.w is not an exported context of package lib"; before, every qualified embedding was S104 "unknown context lib.W", and its import also got S110. `with lib.W`, and a named, an inline or a local context that embeds an imported one, now build and run: the build no longer refuses them with S109 naming 196b, and each `with` releases the imported resource providers it built. `examples/checkout`, the README's opening program, is now a program of packages (`payments`, `memory`, `cmd/checkout`), and its `Payments` contract states the law `Receipted`.
- A program can hold packages (196b U3; [grammar](docs/spec/grammar.md#source-files) rule 1). A package is a folder of `.ergo` files; `ergo.mod` (`module NAME`) marks the module root, and a local package is imported by its module path, `import tidewalk/walk`. An import cycle is S108 "import cycle: a imports b imports a". An import path whose last element is not a name, such as `app/okra-repo`, needs an alias (S108). A union variant from another package is now S108 for good, with the wrap form, in place of the S109 placeholder.
- A std extern whose `runtime/v1` Go body is marked `//ergo:pure` is transparent in footprints (wave std-1, unit G5b; [stdlib](docs/spec/stdlib.md#pure-bodies)). A function that calls `strings.TrimSpace`, `strings.Cut` or `strconv.Atoi` now has the footprint of one that calls nothing, so it gets no interruption point. Every `strings` and `strconv` body is marked. `v1.BodyOf` refuses the mark on a method, on a body whose file imports outside `strings`, `strconv`, `unicode/utf8`, `slices`, `sort` and `math`, on a hidden argument or a function parameter, and on a body that names package state or another body, starts a goroutine or uses a channel. A user `extern go` gets no purity: its call stays opaque.
- lower-v1 stage 5 ([#196](https://github.com/cevr/ergo/issues/196)): one compiler path, and exact support.
  - A pure function compiles to a plain Go function with no hidden environment argument, and its callers pass none: `func Fold(n int) int`. A function is pure when it has no `fails`, no `needs`, no row parameter and no `Task` result, has no interruption point, and calls only pure functions ([runtime](docs/spec/runtime.md#host-and-lowering-notes)). A pure function used as a value keeps the one Go shape of a function value through an adapter. No source name changes purity: a pure function that lowers to a Go method meeting a Go protocol exactly (`String() string`, `Error() string`, `GoString() string`, or a canonical method of go vet's stdmethods check) keeps the environment, so its type joins no Go interface by accident, and a pure Go method with a protocol's name and another signature is renamed with an underscore (`Seek_`), so go vet and Go's fmt never read it.

The new [support table](docs/spec/support.md) lists each family of construct with its status and owner, generated from the lowering's inventory, and [docs/testing.md](docs/testing.md) documents `ergo test`.
- lower-v1 stage 4 ([#196](https://github.com/cevr/ergo/issues/196)): more checked programs build and run.
  - A machine declaration lowers to a plan value: `Initial` is evaluated once at start, as a package `let` is, and a pure `Step` takes no environment and allocates nothing more than a direct call. There is no runner yet (#57).
  - A refuted property prints its seed and each argument as an Ergo literal (`Point{X: 1, Y: 6}`, `"a\nb"`, `[]int{1, 2}`), which pasted into a test checks and fails the same way.

  - A `with` releases a provider whose `Close` is an operation, a generic function or takes a pointer (C29). A generic `Close` whose type parameter has operations is still S109 naming [#197](https://github.com/cevr/ergo/issues/197).

The lowering appends each number with `strconv` into a stack buffer that Go's concatenation reads in place, so `"n=\(n) f=\(f) s=\(s)"` makes one allocation, as hand-written Go does; it calls no `fmt`.

- A user `extern go` binding of Go's `unsafe` package (such as `extern go unsafe.Sizeof func Size(x int64) uintptr`) is S108 at the declaration: "Ergo has no unsafe; unsafe stays at the FFI edge" ([grammar.md](docs/spec/grammar.md), Extern). So no Go built-in is the target of a user extern.
- A user `extern go` binding runs (check-v1 stage E4, 196x; [runtime.md](docs/spec/runtime.md)): a call of an extern whose signature has only basic types and whose target is in Go's standard library lowers to a direct call of the Go function, with no wrapper, and `go build` reports a target that does not match the written signature at the Ergo call's line. Before, `ergo run` refused every user extern with S109. A host call is not an interruption point. The context values of a std package are now keyed by its identity, so a defect report's `context` line writes `std:trace.span="…"` and `std:log.KEY="…"`, and a program package checked under a std path never shares std's keys.

A package value (a `let` or a function) and a named context of one name are S108 at the later declaration; a type and a context may still share a name. Context keys are private to the package that declares the binding's type. - A `with` now binds a context value for its block (#199 stage 4a, [runtime.md G1](docs/spec/runtime.md#g1-context-through-with)). `with log.Annotate("request", id) { … }` and `with trace.Span("load") { … }` bind a value that `log.Annotation(key)` and `trace.Current()` read inside the block and in every task the block starts, and the caller's values come back on the normal end, a typed failure, a defect and a stop. A task keeps the values it started with: a later binding in its parent never reaches it. A user type becomes a context value by declaring the two unexported protocol functions `contextKey` and `contextText` in its package; the checker admits a `with` operand only through that checked protocol, never by package name. The operand is evaluated once, before the region opens, and is checked as an ordinary argument; the region discharges no need and starts no task. Context values are strings at run time, and a context read is effectful: it counts as opaque in the frame's footprint, so a loop that reads one keeps its interruption point. New errors: a `with` operand that is neither a context nor a context value (S108), and a `with` of a local non-context value or of several operands (S109, #196).

An import of them was S109. Each signature is an `extern go` declaration bound to its Go body in `runtime/v1`; a body's hidden arguments (the caller's frame, the call's site, the caller's task) are named by their Go types ([stdlib.md](docs/spec/stdlib.md#v1-packages-task-scope-queue-and-slice), Hidden arguments). Not yet: `ergo build` refuses a call of them with S109 until check-v1 stage D lowers them, and `q.Values()` waits for the prelude's `Seq[T]`.
- A lexical error after a construct the 2026-edition parser reads ahead over is a located S001, not a crash or a hang ([#226](https://github.com/cevr/ergo/issues/226)). `func A(){match A{"` crashed `ergo check` and `ergo fmt` with a slice out of range, and `func A(){for "` or `type A{F["` never returned. The scanner now ends its token stream with EOF after the error, and its error token never lies behind a token already read. When a reading reaches the lexical error, the error is reported, not an earlier parser error from a fallback reading: `for i, x in xs` with a pasted no-break space before `in` names the U+00A0, not the comma.
- `machine Name { initial S.V {}; step f }` declares a state machine over ordinary named functions: `step` is a pure or effect `(S, E) -> decision<S, O>`, `initial` is a literal constructor of `S`, and a `stay` must keep the current variant (EF139). Decisions are syntax: the predeclared `decision<S, O>` and the forms `enter e`, `stay e`, `ignore`, `reject` and `done e` (bare `done` for a void output), matched with the same words; the five words are reserved as names but stay legal as explicit field labels (so a derived codec can carry the wire key `"done"`), and a form where no decision is expected, or a decision a statement discards, is EF143. Plan transitions and graph edges publish the same words (`enter`, `stay`, `ignore`, `reject`, `done`). Checking publishes one inspectable plan per declaration (states, possible transitions, function contracts and terminal output) through `ef check`, MCP and `ef graph --kind machine`; contract violations are EF140, unadmitted forms EF141, and every analysis is bounded, refusing with EF142 rather than admitting what it did not inspect. A module admits at most 256 declarations; each has a 65,536-unit analysis budget, of which a fixed 171 units pay for its own state, and all of them share one 1,048,576-unit budget per module. `enter`, `complete` and the runtime are specified, not built. The formatter identity is `effra/formatter-16`, which also admits `machine` declarations and decision forms. See [state machines](docs/specs/state-machines.md).
- Three checker passes whose cost was quadratic in the program's declarations now look names up in an index. Resolving a data type by name used to copy and scan every record and enum: a program of 20,000 one-field records plus one record naming them all took a median 7.6 s in `ef check` and allocated 13.4 GB, and now takes 0.39 s and allocates 0.31 GB, between 329 and 388 bytes per source byte from 2,500 to 80,000 records. Publishing generic data declarations used to search every published declaration for each one, and checking a callable's `uses` row used to scan every service for each label. Checked results are unchanged.
- `derive w = Json.codec<T>(..., decode: f, encode: g) with w1, w2` declares a transformed codec witness: ordinary functions convert to and from a structurally derived representation, rows are direction-specific, and decoding validates the whole structure before any transformation runs. A transformed domain must be plain data (EF138 for a resource, function or runtime value), checked under a 4096-unit layout work budget (EF127). Encoding writes as it transforms and retains nothing beyond `maxBodyBytes`; on Go it runs a writer generated per plan that reads the value in place, without reflection, and calls each witness's encode function directly with its typed domain value, matching a hand-written Go encoder of the same contract in retained and allocated memory.
- `derive e = Http.endpoint(method:, path:, input:, handler:, output:, status:) raises { Failure: status witness }` and `derive api = Http.routes(...)` declare typed JSON endpoints served by `Http.listen`; `derive w = Json.codec<SomeError>(...)` is a failure witness that encodes a mapped failure's body. Every reachable named failure must be mapped (EF107); the endpoint's row keeps the mapped failures, which a compound cause propagates. The formatter identity is `effra/formatter-16`.
- Service operations and implementation methods may declare row parameters (`E: raises`, `R: uses`), so a callback operation can state that its result rows follow the callback's rows. An operation's `uses` may name only its row parameters (a fixed label is still EF103), type parameters on operations and implementation methods are EF125, and an implementation conforms up to row-parameter renaming (arity or kind mismatch is EF104). An Effra implementation body cannot catch an abstract row (EF125). The JavaScript declarations of the service and provider carry the generic row variables. An implementation method body may use only its declared `uses` row plus the constructor's captured services; a callback requirement it does not declare is EF108.
- `Http.listen` and `Http.text`, with the builtin types `HttpRequest`, `HttpResponse`, `HttpReply`, `HttpLimits` and `HttpHandler`, provide bounded buffered HTTP/1.1 on Go and on server JavaScript. JavaScript programs can use Http (previously rejected); only Go imports still require the Go target (EF110).
- Admission of the Http contract follows lexically resolved references. Value and row bindings are resolved once, before checking, and the checker, lint and dependency ordering read that single resolution.
- The JavaScript library surface exports `LiveHttp` only where checked code selects it: a module function that provides it, or a provided layer. A library that only requires the `Http` interface exports the service tag and embeds no transport.
- Imported Go declarations are checked as canonical host types identified by package path and name: `string`, `bool`, `int64` and `[]byte` keep their Effra primitives, native `int` and `uintptr` keep their own width, and exported non-generic named types, pointers, slices and maps are nominal host values. Unsupported widths, generics, variadics and unimportable types diagnose with their reason.
- Nullable native results adapt through bundled `Option` (nil is `None`; every other value, including an interface holding a nil dynamic pointer, is `Some`). A nullable parameter receives only a present value. There is still no nil in source.
- Every result component of an imported function is retained: several results form a tuple with positional fields `v0`..`vN`, and a trailing `error` yields `GoResult` with `.value`, `.hasError` (Go's `err != nil`, so a typed-nil error is an error) and `.error` as `Option<error>` holding the original native error. `.orFail()` preserves the whole partial value.
- A source declaration may share a name with a predeclared Go annotation (`record int` beside `i64(n)`): the program builds, because the generated alias for the native `int` lives in its own `efHostType_` namespace.
- Source can annotate native types with Go's own spelling: `*sdk.Client`, `[]string`, `map[string]int`, and `error`, `any`, `int`, `uintptr` in programs that import Go.
- Go method calls follow Go's method sets on any executed receiver, such as `(run sdk.Open()).Close()`. A call is a lazy `Foreign` recipe that evaluates its receiver once. Pointer-receiver methods need a pointer; native fields and method values are not admitted. Universe methods such as `error.Error` work.
- A concrete host value reaches a native interface parameter with Go's assignment rule, so `io.Copy` keeps `WriterTo`/`ReaderFrom` dispatch. `value.as<T>()` is Go's comma-ok assertion, returning `(Option<T>, bool)`. `i64(n)` widens a native `int` and `int(x)` narrows to `Option<int>`.
- Checked Go I/O: `Read`, `ReadAt` and `Write` on `io.Reader`, `io.ReaderAt` and `io.Writer` implementations follow those interfaces' contracts (data returned with `io.EOF` stays beside the error; a short write is reported as `io.ErrShortWrite`), and `fs.FS` values keep `ReadDirFS`/`ReadDirFile` dispatch.
- `effra.bindings.json` contracts are keyed by the go/types full name, so methods can carry context-forwarding and cancellation contracts, and a promoted method (including from an embedded generic instance) carries the contract of the method it promotes. To give a method of an unnamed interface a contract, pass an explicit `context.Context` or declare a named Go interface with the method in your module.
- Native bindings are keyed by canonical identity (`go:<package path>.<name>` for a function, the actual receiver type and method for a method), so two receivers that display alike no longer share a binding. Inspection reports both the display symbol and the identity.

### Runtime

- A program can write files: std `fs` declares a second capability, `fs.Writes`, with `WriteFile(path, text) fails NotFound | Denied | Failed` and `MkdirAll(path) fails Denied | Failed`, and `fs.Host` provides it (batch 9 G4b; [stdlib](docs/spec/stdlib.md#fs) 8-10). `WriteFile` writes a new file beside the target and renames it over the target, so a reader never sees a part; a new file has mode 0666 less the umask and a file that was there keeps its mode. A symbolic link at the path is followed, as for Go's `os.WriteFile`. `fs.Files` stays read only. `main` binds `context { fs.Files: fs.NewHost(), fs.Writes: fs.NewHost() }`.
- A program can read files: the new std package `fs` declares the capability `fs.Files` with `ReadFile(path) string`, `ReadDir(path) []string` (sorted names) and `Stat(path) Info`, and its host provider `fs.Host` (std-1 G4; [stdlib.md, fs](docs/spec/stdlib.md#fs)). Each operation fails `fs.NotFound { Path }`, `fs.Denied { Path }` or `fs.Failed { Path, Reason }`, so a `catch` over the three is exhaustive, and an uncaught one is written as `error: fs.NotFound{Path:missing.md}` with status 1. A program binds it with `let Live = context { fs.Files: fs.Host }`. `fs.Files` is open as `os.Process` is, so a test binds its own provider, such as a `memory.Files` over a Map of paths to text. The set is read only; writes come later.
- `main` can end with a status and a message of its own: the failure `os.Exit { Code int, Message string }` of the new std package `os` (std-1 G2; [runtime.md, Exit causes](docs/spec/runtime.md#exit-causes) 8). When it is `main`'s only reason, the program writes `Message` verbatim on standard error and exits with `Code`, after every exit action has run. A `Code` outside 1..125 adds the line `error: os.Exit code N is outside 1..125` and exits 1; a defect beside it still exits 2; beside any other reason it is written as `error: os.Exit{Code:N Message:TEXT}` and the status is 1. Std `os` also declares the capability `os.Process` (`Args`, `Getenv` with `Option[string]`) and its host provider `os.Host` ([stdlib.md, os](docs/spec/stdlib.md#os)). A program binds it with `let Live = context { os.Process: os.Host }` and `with Live { … }`, and a test binds its own provider the same way, such as a `FakeEnv` record with `Args` and `Getenv` functions.
- A stop no longer drops a value that a loop or a capability call has already received (#199 stage 5a, [runtime.md I1](docs/spec/runtime.md#i1-interruption-points) rule 2). The rule: an interruption point the compiler inserts never separates a step that delivers a value from the first statement that receives it. A loop's check now ends each iteration, and a `continue` jumps to it; before, it headed the body, so `for v in q.Values() { return v }` could take a value from the queue, see a stop at the body's first line, and lose the value. A capability call's check now comes before its operands; before, it came after them, so `Sink.Put(try q.Pop())` could pop a value and then stop before `Put` received it. A stop that arrives after the delivery stays pending for the next check. The number of checks is unchanged; only their positions move.
- A defect report now names the task where the defect happened, its exact Ergo site, its fork ancestry and the context in force there (#199 stage 4b, [runtime.md G2](docs/spec/runtime.md#g2-fork-tree-defects)). The rule: a defect is recorded once, on the failing task's goroutine, with that task's stack, its chain of tasks (at most 32) and a snapshot of its context values, and the record travels whole through `Wait`, `Stop`, releases and an owner's drain until main reports it. So a report never shows the waiter's frames or the parent's later context, and a dropped typed failure never takes a defect with it. Each task's site is now `FUNC calls task.Go at FILE:LINE:COL`, the form of a call frame, and it stays with a `Task` that moves. After `panic: VALUE` and the failing task's Ergo frames, the report lists the chain from the failing task to `main`, and under the failing task a `context` line such as `trace.span="ingest" log.region="eu"`. Before, the chain came before the frames, the task's Go closure appeared as a synthetic frame, and no context was written. The Go closure around an exit action's block is no longer counted as a repeat (`(2 times)`). A traced run writes the same report, and a `catch` still handles typed failures only. `runtime/rt` adds `Task.Values`, which walks the context bindings in force, inherited ones included, so the snapshot can list keys that no reader names.
- A `with` now builds each provider and registers its release in one masked step (#199 stage 3c, R7 and R8; [resources.md, Context ownership as built](docs/spec/resources.md#context-ownership-as-built) 8). In a `with` that acquires a provider with a `Close`, a constructor that returns a value after a stop arrived still registers it, and its `Close` runs; the stop is observed after the registration. A constructor that fails with a typed error, panics or is stopped registers nothing, and the providers built before it close, last built first, before the `with` ends. A stop that arrives while one provider is built is observed before the next constructor runs. A nested mask of the caller stays in force. An inline context whose entries are explicit provider expressions, `with context { A: openA(), B: try openB() } { … }`, now runs through the same step and the same acquisition facts as a named context; lowering refused every inline context before. Its provider expressions run in the enclosing function, so a `try` failure, `return`, `break` or `continue` there leaves the `with` after closing the providers built so far. A `with`'s footprint now counts each provider it builds, whatever the context's spelling ([rows.md, Footprints](docs/spec/rows.md#footprints)): `with context { W }` counts each provider of W it builds, as `with W` does, so a loop after it keeps its interruption point. It also counts the `Close` of each provider it releases, in every spelling: a function whose only effect is the release of a provider whose `Close` calls a capability now keeps the interruption point of a later loop (it lost it since stage 3b for `with W`). A `with` that acquires no resource builds its providers unmasked, as before. `runtime/v1`'s `Scope.WithClose` is no longer exported: `WithAcquire` is the one registration.
- A resource provider call now requires a checked constructor freshness fact (#199 stage 3b). A function that returns an existing value gets S109 naming #197, and so does a call of a bodiless extern, std or user, since no declaration says what it returns; fresh recursive constructors and fallible constructor results keep their freshness. An exit action may use a plain provider from its `with` when that provider has no acquired resource dependency.
- A `with` now releases the providers it builds when its block ends (#199 stage 3b, [resources.md, Context ownership as built](docs/spec/resources.md#context-ownership-as-built)). The checker records, for each `with`, the providers it acquires in build order, and the checked `Close` of each; an entry shared by several capabilities is one acquisition, and an overridden or unreached entry is not built. Each provider with a `Close` is released once, in reverse acquisition order, on the normal end, a typed failure, a defect and a stop, after the tasks the block started have drained; a release defect never stops the later releases, and every cause is kept. Releases run in the environment outside the `with`, so the needs of each `Close` are charged at the `with` and widen no row (S102 when nothing provides them). New errors: calling a capability's `Close` (S108, R24), since its `with` releases it; a resource provider that names an existing value (S109, #197); an exit action inside the block that needs an acquired resource provider of the `with` or one that uses it (S108); a `with` whose value holds a `Task` (S108).
- A written `Close` now runs masked, from its first instruction to its last, on every dispatch path (#199 stage 3a, [runtime.md, Release masks as built](docs/spec/runtime.md#release-masks-as-built)). The checker records which `Close` is a release (R1, R2), and a same-shaped method with another name, or a `Close` with another parameter, stays an ordinary interruptible call. A `Close` with a failure row is a type error. A stop before or during a `Close` or an exit action does not cut it short: its sleeps and queue waits wait uninterruptibly, and the caller sees the stop at its next interruption point after the release. A defect in a release joins the earlier exit and never replaces it. Exit actions and checked `Close` bodies share one mask boundary in `runtime/v1`, which restores the caller's mask depth on every path.
- Blocking runtime calls use one lowering owner and a catalog of waiting policies (#199 stage 2). `LiveScheduler.Sleep` now observes the running task's stop before and during its timer wait. `Wait` retains its owning task after a frame transfer; queue waits use the caller's task, and `Values` binds that task when iterated. `Stop` still drains uninterruptibly. Interruption stays outside typed failures, and these bindings add no extra call-site poll.
- A stop now reaches impure loops and recursion (#199 stage 1, [runtime.md I1](docs/spec/runtime.md#i1-interruption-points)). The checker infers each frame's footprint, what it runs rather than what its row names ([rows.md, Footprints](docs/spec/rows.md#footprints)). An impure frame checks its own task before each capability call and once in each loop iteration, including every `continue` path (stage 5a moved the loop check to the end of the iteration and the call check before the operands). It also checks once at entry if its call-graph component has several members or a self-edge, or its footprint is opaque because unknown code may re-enter it. A host call such as `xs.Append(1)` counts as opaque for now. A nonrecursive impure frame with a transparent footprint has no entry check. Pure frames have no checks, so their loops and recursion cannot be stopped until they end.
- The HTTP admission test waits for an admitted `/after` response with a bounded retry of empty 503 responses (#232). Reading `/hold`'s response can precede the handler's deferred admission release. The test still requires immediate rejection at the cap and an exact successful response after release; the transport's admission rule is unchanged.
- On a traced tree, the releases of a `runtime/v1` frame (exit actions and the drains of tasks it still owns) raise release events, and a panic in one closes only the calls it opened, as `runtime/rt` scopes do (lower-v1 stage 3b-runtime, #230). `runtime/rt` adds one hook for this, `rt.Release`. Traced and untraced runs have the same exit.
- A stop now reaches a task that waits in `Push`, `Pop` or a `Values` loop of a `queue.Queue` (lower-v1 stage 3b-runtime): the operations take the caller's task (the lowering passes it), and a waiting one ends with an interruption, not `queue.Closed`. A stopped `Push`'s value never enters the queue. So a frame that ends while its producer waits on a full queue stops and drains the producer, as in `poller.ergo`, instead of waiting for ever.
- `runtime/v1` has the Go bodies of the v1 std packages `task`, `scope`, `queue` and `slice` (lower-v1 stage 3a), over `runtime/rt`; their signatures and lowering are stage 3b, so an import of them stays S109. The contract is in [runtime.md](docs/spec/runtime.md): `task.Go` starts a child of the calling task, and the calling function stops and drains a task it did not consume; a `Task` leaves its function only by a direct return, which moves it into the caller's frame, passed as a hidden destination (`Task.Move`), and a `Wait` on one returned without the move is a named defect; a frame holds only the tasks it still owns; an exit action's block, at any depth, owns the tasks it starts and the actions it registers; `Wait` returns a lone typed failure and raises a defect (with the task chain and the Go stack at the panic) or an interruption; `scope.OnExit` registers on the innermost function, masked, last in first out with that function's tasks, and keeps every defect. `queue.Queue[T]` is a FIFO with a capacity (0 is a rendezvous); `Push` waits while it is full; `Close` ends admission; a `Push` on a closed queue and a `Pop` on a closed, empty queue fail with the typed failure `queue.Closed`, not an interruption; `Values()` is a `Seq[T]` that drains it. The section "Channels" is now "Queues": Ergo has no channels. Not yet: a stop does not reach a task waiting in `Push` or `Pop` (#199). The laws R1 to R15 that apply run as tests under `-race`.

- Latch handoff now means the same on Go and JavaScript under `ef test` and the Go `TestScheduler`, and in every JavaScript execution (#142). `Sync.signal` makes every parked waiter runnable and returns, and the signaller keeps its turn; each waiter resumes later on its own turn. On JavaScript the waiter used to run inside the signaller's `signal` call, so interrupting the signaller right after its signal interrupted it mid-signal, and a waiter had already run before the signaller could interrupt it. On Go a scope close (a `scope` block, a fiber's exit or layer shutdown) handed off the turn before it cancelled the scope's children, so a child already woken by a signal could occasionally run and act after its owner began closing; the close now cancels while it still holds the turn. Now interrupting the signaller after `signal` returns cannot affect a waiter it does not own, and a signalled waiter interrupted before it runs, directly or by its owner's close, ends interrupted. Live Go, without the test scheduler, has no turns: a waiter runs on its own goroutine, possibly in parallel with the signaller, and an interrupt sent after `signal` races with it. The JavaScript `Latch` is now Effect's `Latch`, whose `open` resumes waiters from a dispatcher task; under the `ef test` harness on Bun the measured cost is within noise.
- `Scheduler.awaitRegistration()` under `ef test` now returns at quiescence, with the same meaning on Go and JavaScript: no managed fiber is running or runnable, and a fiber that has been signalled, fired or cancelled but has not run again is not idle. It used to wait for a timer registered since the last barrier. JavaScript then hung when forked work finished before its timeout timer started, and both targets hung after a fork that registers no timer, such as a pure value. On Go it could also return as soon as one fork registered a timer, before sibling forks had run. Forked work that already completed now passes the barrier, as does work whose timeout timer was cancelled. Interrupting a fiber parked at the barrier is an ordinary interruption on both targets, and when several fibers wait at once their release order is unspecified.
- `Scheduler.advance` selects each deadline at the same quiescence. On JavaScript, advancing straight after a worker signals readiness used to commit the target before the worker registered its next sleep, so that sleep never fired. On Go, a sleeper or latch waiter woken by an interrupt or a scope close was briefly invisible to adjustment and to the barrier.
- The Go and JavaScript layer runtimes share build-owned layer entries: one producer per selected node, and dependents and waiters observe one terminal outcome. Cancelling a waiter abandons only its own wait; it never interrupts the producer (unlike Effect's `MemoMap`, whose first requester owns the build, which the conformance table lists as a difference). Dependent-first shutdown attempts every finalizer.
- The HTTP transport enforces explicit body, read-header, read-body, idle and admission limits. It answers 413 for declared and chunked oversize bodies, 400 for malformed framing, 503 for admission and shutdown, and an empty 500 for failure, defect, cleanup failure or an invalid response (Content-Type outside visible ASCII, space and tab). Each request runs in a scope linked to client disconnect and server cancellation, and the response is written only after that scope closes. Shutdown stops admission, cancels and joins request scopes, then gives responses still being written the idle timeout before aborting them. Admission rejects at the cap and never waits, so a sequential client may observe 503 while its previous response is still being handed off ([runtime](docs/runtime.md)).
- On JavaScript a malformed request's connection is closed once its 400 or 431 is written, so a client that keeps its side open cannot hold shutdown open on Node or Bun. A parser error preempts an unwritten pipelined response (a documented host limit).

- In identity mode (the closure sweep), the test observer no longer makes the last close of its inotify descriptor: a holder process of the same test binary (`ERGO_TESTINPUTS_WATCH_HOLDER`) keeps a second descriptor and closes it after the observer is done. - A gate stopped by `SIGINT`, `SIGTERM` or `SIGHUP` stops every process it started before it exits, in both tiers ([stop](docs/tooling.md#merge-gate)). It starts no new step or command, kills each running step whole (its cgroup in the systemd scope, its process group under the RSS watch, the merge tier's sandboxed processes included) and each running command (`git`, a tool query, `go list`) with its process group, waits until each has ended, closes the merge sandbox, and in its scope kills what is left in its own leaf. Then it exits with 128 plus the signal's number, and says only what it proved: `gate: stopped by SIGTERM; every process it started has ended` when its scope's leaf reads back empty; under the RSS watch `…; every step and command it started has ended, with its process group`; and `…; not every process it started has ended: <reason>` when a cleanup fails. A second signal during a stop exits at once with `gate: stopped by SIGINT, then SIGTERM before the stop ended; processes it started may remain`. Before, a `SIGTERM` left the steps of a scoped gate running with ppid 1 and still holding the caller's `flock` of `gate.lock`. A signal the gate was started ignoring (`nohup`) stays ignored. `go run` does not pass on `SIGTERM`, so signal the gate's process or its process group, not only `scripts/gate.sh`.
- In its systemd scope the gate sets up its cgroups before it runs `git` or `go list` ([scope setup](docs/tooling.md#merge-gate)). Before, the telemetry sidecar that `go list` can leave stayed in the scope's own cgroup, so the kernel refused the controllers (`EBUSY`) and the gate exited 2 before any step.
- The gate uses at most its CPU budget, not every CPU of the host ([CPU budget](docs/tooling.md#merge-gate)). `ERGO_GATE_CPUS` sets it; the default is half of the usable CPUs (the affinity mask lowered to the cgroup's `cpu.max`), at least 2. The budget bounds the steps at once, the shards of `cmd/ergo`, the host packages' `-parallel`, and the `GOMAXPROCS` of the gate and of every step's Go processes, so each test binary's `-parallel` follows it. The gate also appends `-p=<at most the budget>` to every step's `GOFLAGS`, after the caller's flags, so a caller's `GOFLAGS=-p=16` cannot raise the go command's packages at once. In the systemd scope the kernel enforces it: the scope has `CPUQuota=<budget × 100>%`, each step's cgroup has `cpu.max` at the budget, and the gate fails with `gate: cpu budget: systemd scope … does not enforce the CPU budget: …` when the scope's `cpu.max` does not read back. The gate prints `gate: cpu budget: …` after the memory budget line. An invalid value fails the gate with one line. The whole-gate key and every step's receipt key hold the budget, so a gate does not replay a verdict, or promote a step's pass, recorded under another budget. Before, steps ran `max(2, CPUs)` at once and each Go process took every CPU.
- An incremental gate no longer replays two passes that a fresh run fails ([merge gate](docs/tooling.md#merge-gate)). The provenance analyzer's controls read main-module sources from their own module, `tools/provenance`, and Go's test cache rechecks only files inside a package's module, so a field removed from a syntax source replayed their pass; they now run with `-count=1`. The Effect mapping check refuses an evidence file Git does not track, but its step receipt keyed file contents and not the index, so untracking an evidence file replayed its pass; the step now has no receipt and runs on every whole-gate miss (about 0.15 s, less than the receipt lookup). The gate's go tests are now uncached by default and cached only by declared exception: every step runs with `-count=1` added to `GOFLAGS`, which each `go test` it starts inherits through any shell, `go run -exec`, `-toolexec` or `-vettool`, and only the hermetic gate packages' step keeps Go's test cache; so a real gate run reruns the tests Go used to replay, and a whole-gate replay is unchanged. The guard covers an accidental gap: `TestTestCommandsHaveCacheCoverage` checks the environment the gate builds for every step, and a step that sets `GOFLAGS` or another `-count` on purpose is out of scope but fails a literal tripwire, so it shows in review. Steps still start only allowlisted programs, set only allowlisted variables and run only reviewed shell scripts (`scripts/gate/reviewed.go`). `TestGateCacheParityModel` checks on a fixture checkout, against a reference model, that incremental and fresh verdicts agree after gates, merge-tier runs, source and index edits and cache sweeps. That default is hygiene: a tool that gives its child its own environment can still replay a stale pass from a host cache, so only `--merge` gives a merge verdict, and its uncached run now runs in a bubblewrap sandbox with no persistent state: an export of the head commit by its hash, every writable path (HOME, the temporary directories, GOCACHE, XDG_CACHE_HOME, the module cache, the checkout) bound from a new empty directory removed after the run, a module cache filled only with archives the gate builds from module file contents that match the tracked `go.sum` (members sorted and stored with fixed fields, no comment or extra bytes, so no byte of the host's ZIP container and no host `.info` or `.ziphash` reaches the run), and only `/usr` and GOROOT bound read-only, each by its resolved identity: the gate follows every symbolic link in the declared path, checks the tree it reaches, and binds that tree at the declared path, so a tree declared through a link is the tree checked; a link inside a tree whose target leaves both trees is bound empty at its target. Steps run with `GOWORK=off` and `-mod=readonly` last in `GOFLAGS`, and a `go.work` in the commit fails closed. At the start of each run the gate checks those two trees: a path this user could have written or a Go cache in `/usr` is bound empty, and one in GOROOT, at a tree's root or above a program the steps run makes `--merge` fail closed; so no byte a process of this user could write before the run is visible in it, except the commit and module file contents verified against the commit's go.sum. Without the sandbox (off Linux, no bwrap, no user namespaces, a dirty checkout, a refused input, a module that does not match `go.sum`) `--merge` exits 2 with one line and gives no verdict. The sandboxed run starts with an empty build cache: measured at a load of 13 to 31, its uncached run took 334 to 335 s against 265 to 277 s before, and `go test (other packages)` peaked at 6.4 to 7.1G of its 8G step budget against 2.4G. The input check takes about 0.7 s and the export about 1.5 s per run (measured at a load of 17).

- The emission cache (`$XDG_CACHE_HOME/ergo`) trims itself, as Go's build cache does ([runtime](docs/spec/runtime.md), emission cache). A build marks the entry it reuses at most once per hour, and starts a bounded trim at most once per hour (`ergo/trim.txt`, which replaces `ergo/private/.swept`). The trim removes entries no build used for 24 hours, staging directories older than one hour (a crashed builder's, a moved-aside corrupt entry) and private roots older than 24 hours. A build holds a shared `flock` on its module's directory until its link ends, and the trim removes a directory only when it takes its lock exclusively without waiting, after it renames the directory aside, so it never removes a module a build links and never leaves a half entry. Before, published entries and staging were never removed. Where `flock` does not exist, nothing is removed.
- The parser enforces the unquoted import-path element grammar: each slash- or dot-separated element starts with a letter or `_`, followed by letters, digits, `_` or `-` ([grammar](docs/spec/grammar.md#literals), #231). `import 0//0` is S001 at the leading digit. Comments follow the same rule after a path as after any other token: `import strings// note` and `import strings/* c */` are valid, and formatting keeps the comment with a separating space. The independent formatter test lexer now ends path tokens at `//` and `/*`, as the scanner does. The fuzz corpus retains the invalid numeric-path input and valid comment-boundary regressions.
- The emission cache keys on the compiler's producer identity (`internal/producer`), the same identity check envelopes report, acquired once when the cache first needs a key. A compiler copied or renamed over its own path during a build can no longer make the old process publish modules under the new compiler's key: Linux names the running image, and on darwin the replacement fails the kernel's cdhash check. On darwin the identity is the authenticated code: SHA-256 over the domain tag `ergo-producer-darwin-code-1` and the bytes the code signature's page hashes cover, so two files with one cdhash share it, whatever their signature container or trailing bytes hold; a universal file, or a code directory without full SHA-256 page hashes, gets a process-scoped identity. Linux keeps the digest of the whole executing file. A process-scoped identity (no kernel record, or a failed check) builds the module in a private root of the process and never publishes it. A build holds a `flock` lease on its root from the moment it takes the root until its link ends, also when it fails, so a long-lived host holds nothing between builds. A sweep of private roots starts at most once per 24 hours per cache and runs in bounded passes, one process at a time; a pass that hits its bound or is killed leaves the sweep due, so the next build continues it until it completes; a pass removes a root only when it is older than 24 hours and no build holds its lease. Compilation, emission and raw `fmt --stdin` still acquire no identity.
- On darwin/arm64, `ergo check`, `ergo diagnostics` and `ergo fmt --json` report a content identity for the compiler (`strength: executing-artifact`, `reuseScope: artifact`), as on Linux, rather than a process-scoped one ([#227](https://github.com/cevr/ergo/issues/227)). ### Upcoming (reviewed, not on this branch)

These land with later integrations and are listed so their migration notes are not lost. Do not rely on them yet.

- **Breaking:** `ef lint` invocation errors exit with status 2, and `ef lint rules` reports `rule` where it reported `name`.
- **Breaking:** call arguments written with labels bind to the parameter they name instead of by position. A call whose labels are out of parameter order changes what it computes. A label that names no parameter, repeats, collides with a positional argument, or is written on a callable value or Go function is an EF106 error instead of being ignored. Positional arguments must precede labels, and arguments still evaluate in source order.
